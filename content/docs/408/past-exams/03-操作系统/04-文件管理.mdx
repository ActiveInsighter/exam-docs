# 第 4 章 文件管理

## 4.1 文件

<Question id="408-47a2a6-001" type="single" tags="来源:2009考研408">

文件系统中, 文件访问控制信息存储的合理位置是（ ）。

<Option correct>文件控制块</Option>
<Option>文件分配表</Option>
<Option>用户口令表</Option>
<Option>系统注册表</Option>

<Solution>

**【解析】** ① A 正确 ✓：文件控制块（FCB）是操作系统为每个文件维护的数据结构，专门存储文件的元信息，用于管理、控制和按名存取文件，其中包含了全部文件属性。

② B 错误 ×：文件分配表（FAT）是一种用于管理磁盘存储空间分配的数据结构，记录磁盘上每个簇（或块）的使用情况，以及文件数据在磁盘上的链式存储位置。

③ C 错误 ×：用户口令表用于存储用户身份认证信息（例如，密码），与单个文件的访问控制无关。

④ D 错误 ×：系统注册表是 Windows 系统的配置数据库，用于集中存储系统、硬件、应用程序和用户账户的配置信息，从而实现系统配置的集中管理、高效检索与权限控制。故选 A。

**【点评】** 常规题。D 选项可能考生比较陌生，但本题 A 选项应该是很常见的。

</Solution>

</Question>

<Question id="408-47a2a6-002" type="single" tags="来源:2009考研408">

下列文件物理结构中, 适合随机访问且易于文件扩展的是（ ）。

<Option>连续结构</Option>
<Option correct>索引结构</Option>
<Option>链式结构且磁盘块定长</Option>
<Option>链式结构且磁盘块变长</Option>

<Solution>

**【解析】** ① A 选项：连续结构适合随机访问，但文件扩展时需要移动大量数据，扩展困难。

② B 选项：索引结构通过索引表可直接定位数据块，支持高效随机访问；同时新增数据块只需更新索引表，易于文件扩展。

③ C 选项和 D 选项中，链式结构由于文件分配的多个不连续的盘块通过链接指针构成一个链表，支持顺序访问，不适合随机访问。

**【点评】** 概念题。本题考查文件的各种物理结构。

</Solution>

</Question>

<Question id="408-47a2a6-003" type="single" tags="来源:2010考研408">

设文件索引节点中有 7 个地址项, 其中 4 个地址项是直接地址索引,2 个地址项是一级间接地址索引, 1 个地址项是二级间接地址索引,每个地址项大小为 4B。若磁盘索引块和磁盘数据块大小均为 256B, 则可表示的单个文件最大长度是（ ）。

<Option>33KB</Option>
<Option>519KB</Option>
<Option correct>1057KB</Option>
<Option>16513KB</Option>

<Solution>

**【解析】** 索引块大小为 256B，单个地址项大小为 4B，单个索引块可存放 $\frac{256\mathrm{B}}{4\mathrm{B}}=64$ 个索引项。再分类计算：① 直接地址索引（4 个）：直接地址索引直接指向磁盘数据块，4 个直接地址地址项对应 4 个磁盘数据块。② 一级间接地址索引（2 个）：1 个一级间接地址索引项指向一个索引块（该索引块里都是直接地址索引项），2 个一级间接地址索引项可指向 $2\times64=128$ 个磁盘数据块。③ 二级间接地址索引（1 个）：1 个二级间接地址索引项指向一个索引块（该索引块里都是一级间接地址索引项），可指向 $1\times64\times64=4096$ 个磁盘数据块。

7 个地址项可指向 $4+128+4096=4228$ 个磁盘数据块，每个磁盘数据块 256B，可表示的数据大小为 $4228\times256\mathrm{B}=1057\mathrm{KB}$。

**【点评】** 常规题。本题考查混合索引的相关计算，是高频考点。题目中说有 2 个一级间接地址索引，不要算漏了，错按 1 个一级间接地址索引来算了。

</Solution>

</Question>

<Question id="408-47a2a6-004" type="single" tags="来源:2012考研408">

若一个用户进程通过 read 系统调用读取一个磁盘文件中的数据,则下列关于此过程的叙述中, 正确的是（ ）。 I. 若该文件的数据不在内存中,则该进程进入睡眠等待状态 II. 请求 read 系统调用会导致 CPU 从用户态切换到核心态 III. read 系统调用的参数应包含文件的名称

<Option correct>仅 I、 II</Option>
<Option>仅 I、 III</Option>
<Option>仅 II、 III</Option>
<Option>I、 II、 III</Option>

<Solution>

**【解析】** ① Ⅰ正确 ✓：当调用 read 读取磁盘文件时，如果数据不在内存的页缓存中，会触发缺页中断，进程会进入阻塞（睡眠等待）状态，直到磁盘 I/O 完成数据加载到内存后才被唤醒。

② Ⅱ正确 ✓：read 是操作系统提供的系统调用，用户进程调用系统调用时，必须通过陷入指令（trap）让 CPU 从用户态切换到内核态，由操作系统内核来执行对应的操作。

③ Ⅲ错误 ×：read 系统调用的原型是 `read(int fd, void *buf, size_t count)`，它的参数是文件描述符（fd）、缓冲区地址和读取字节数，而不是文件名。文件名是在 open 系统调用中使用的，open 会返回文件描述符（fd）供后续 read 使用。文件描述符（fd）是进程打开文件后，内核维护的文件表的索引，用户进程后续的读写操作都通过 fd 来引用文件，而不是直接使用文件名，这样可以避免每次都去查找文件路径，提升效率。

| 系统调用 | 函数原型 | 函数参数 |
| --- | --- | --- |
| open | `open(pathname, flags, mode)` | pathname 指文件名；flags 指打开模式（只读、只写、读写等）；mode 参数仅在创建新文件时生效，作用是指定新文件的访问权限位（文件权限，例如：所有者读、所有者写、所有者执行等）。如果只是打开已存在的文件，mode 参数会被直接忽略。 |
| read | `read(fd, buf, count)` | fd 指文件描述符，是 open 返回的句柄，非文件名；buf 指缓冲区地址；count 指期望读取的最大字节数 |
| write | `write(fd, buf, count)` | fd 指文件描述符，是 open 返回的句柄，非文件名；buf 指缓冲区地址；count 指期望写入的最大字节数 |
| close | `close(fd)` | fd 指待关闭的文件描述符 |

**【点评】** 概念题。其中Ⅰ、Ⅱ为常规考点，Ⅲ比较生僻。举一反三：考生需了解常见系统调用的调用过程、调用参数等。

</Solution>

</Question>

<Question id="408-47a2a6-005" type="single" tags="来源:2013考研408">

用户在删除某文件的过程中, 操作系统不可能执行的操作是（ ）。

<Option correct>删除此文件所在的目录</Option>
<Option>删除与此文件关联的目录项</Option>
<Option>删除与此文件对应的文件控制块</Option>
<Option>释放与此文件关联的内存缓冲区</Option>

<Solution>

**【解析】** 删除文件的完整流程（按底层执行顺序），以类 Unix 系统（inode 机制）为例，同时覆盖 Windows 的通用逻辑，概括介绍每一步：

① 第一步：权限与状态校验。这一步是前置条件，不满足则直接报错，后续流程不执行。

- 检查当前用户是否对文件有删除权限（修改目录需要写权限）。
- 检查文件是否被其他进程打开占用（如果是独占打开，部分系统会拒绝删除，或标记为“待删除”，进程退出后再执行）。
- 检查文件的引用计数/链接数（是否有硬链接指向该文件）。

② 第二步：删除/修改目录项。目录本质上是一个“文件”，里面存储了文件名 → 文件元数据标识的映射（Unix 中是文件名 → inode 号，Windows 中是文件名 → 文件记录号）。

- 操作系统会在文件所在的目录中，移除该文件对应的目录项。
- 效果：从用户视角看，文件在目录里“消失”了，无法再通过文件名找到它。

③ 第三步：处理文件控制块（inode/文件记录）。文件控制块（Unix 的 inode、Windows 的 MFT 记录）存储了文件的核心元数据：大小、权限、磁盘块指针、引用计数等。

- 系统会将文件的引用计数（链接数）减 1。
- 若引用计数变为 0（没有其他硬链接指向该文件）：标记该文件控制块为“空闲”，等待后续回收；回收文件占用的磁盘数据块（将磁盘块标记为可用，写入新数据时会覆盖）。
- 若引用计数仍大于 0：文件的元数据和磁盘块不会被回收，只有当前的目录项被删除，其他硬链接仍可访问文件。

④ 第四步：释放内存缓冲区。如果该文件之前被进程读写过，操作系统可能在内存中缓存了文件的数据块（页缓存、缓冲区）。

- 删除文件时，系统会将缓存中未写入磁盘的脏数据刷盘，然后释放对应的内存缓冲区。
- 避免内存泄漏，同时确保磁盘数据的一致性。

**【提示】** ★ 为什么删除文件 ≠ 擦除数据？

- 操作系统删除文件时，只是修改了目录项、文件控制块和磁盘块的标记，并未物理擦除磁盘上的原始数据。
- 只要磁盘块没有被新数据覆盖，就可以通过数据恢复工具找回文件。
- 只有“格式化”、“磁盘擦除”或多次覆写，才会真正销毁数据。

**【点评】** 常规题。命题人在设计此题时“考虑不周”，选 A 太明显了，导致此题区分度极低，丧失了考查的意义。稍有计算机常识就知道，删除一个文件，是不可能将文件所在目录删除。

</Solution>

</Question>

<Question id="408-47a2a6-006" type="single" tags="来源:2013考研408">

为支持 CD - ROM 中视频文件的快速随机播放, 播放性能最好的文件数据块组织方式是（ ）。

<Option correct>连续结构</Option>
<Option>链式结构</Option>
<Option>直接索引结构</Option>
<Option>多级索引结构</Option>

<Solution>

**【解析】** ① 连续结构（顺序文件）：文件的数据块连续存放。优点：随机访问性能最好。知道文件起始地址和偏移量，就能直接算出目标数据块的物理地址，一次定位就能读取，没有额外开销。缺点：容易产生外部碎片，文件扩展困难。对于 CD-ROM 上的视频播放来说，连续存放能保证读取时磁头几乎不用移动，快速随机跳转（例如：拖进度条）时效率极高。故选 A。

② 链式结构：文件的数据块通过指针链接在一起，每个块包含下一个块的地址。缺点：无法高效随机访问。要找到第 $n$ 个块，必须从头开始依次读取 $n$ 次，跳转效率极低，完全不适合随机访问需求。

③ 直接索引结构：文件控制块（FCB）中包含一张索引表，记录了每个数据块的地址。缺点：索引表本身需要额外的 I/O 读取，随机访问时需要先读索引再读数据，两次访问的开销比连续结构大得多，在 CD-ROM 这种机械存储设备上，延迟会很明显。

④ 多级索引结构：索引表再分级（例如：一级、二级、三级索引），是对直接索引的扩展。缺点：随机访问需要多次读取索引块（例如：二级索引需要读索引目录块 → 一级索引块 → 数据块），访问次数更多，延迟更大，性能远不如连续结构。

**【提示】** 如今，CD-ROM 在主流消费市场已经被彻底淘汰。如今的 408 考试中，应该不会再考类似 CD-ROM 这种过时被淘汰的技术了（如今的主流存储介质是 SSD，所以最新的 408 考试中，考过几次 SSD）。本题是 2013 年的 408 考试真题，在 2013 年左右的时候，CD-ROM 尚未完全淘汰。尤其在 2010 年的时候，CD-ROM 仍是主流的存储介质，当时台式机和绝大多数笔记本出厂默认内置 DVD/CD 光驱。

**【点评】** 概念题。考查常见的几种文件物理存储结构。CD-ROM 的概念在 2011 年 408 第 14 题 B 选项中出现过。这里再次提醒各位考生，只要是 408 考试中出现的概念，都应该了解，还有可能再次考到。

</Solution>

</Question>

<Question id="408-47a2a6-007" type="single" tags="来源:2013考研408">

若某文件系统索引结点 (inode) 中有直接地址项和间接地址项, 则下列选项中, 与单个文件长度无关的因素是（ ）。

<Option correct>索引结点的总数</Option>
<Option>间接地址索引的级数</Option>
<Option>地址项的个数</Option>
<Option>文件块大小</Option>

<Solution>

**【解析】** ① A 选项：一个文件唯一对应一个索引节点，即文件和索引节点是一一对应关系。文件系统的容量上限决定了索引节点的总数，索引节点总数和单个文件的长度没有任何关系。

② B 选项：每个直接地址项都直接指向一个数据块，一级索引块里存放的都是直接地址项，二级索引块里存放的都是一级索引块地址项。间接地址索引的级数越多，能表示的文件越大。

③ C 选项：地址项个数越多（直接地址项或间接地址项），能直接或间接寻址的数据块数量就越多，能表示的文件越大。

④ D 选项：文件块越大，每个地址项指向的空间就越大，文件最大长度也就越大。

**【点评】** 概念题。考查文件索引节点相关的综合题，选 A 是很明显的。

</Solution>

<Question id="408-47a2a6-008" type="single" tags="来源:2014考研408">

在一个文件被用户进程首次打开的过程中, 操作系统需做的是（ ）。

<Option>将文件内容读到内存中</Option>
<Option correct>将文件控制块读到内存中</Option>
<Option>修改文件控制块中的读写权限</Option>
<Option>将文件的数据缓冲区首指针返回给用户进程</Option>

<Solution>

**【解析】** 因为此类题经常考，为了让考生对文件的打开过程有更全面的了解，这里先概要介绍文件打开的完整流程（★ 这个过程考生必须熟练掌握），再逐个分析各个选项。

▷ ① 文件 open 打开操作完整流程如下：

1. 检索目录，定位 FCB：
    - 根据传入的文件路径，逐层查找目录项，在外存找到目标文件对应的文件控制块 FCB（或 inode 索引节点）。
2. 读入 FCB 到内存：
    - 把外存上存储文件元数据的 FCB 加载到内存，生成内存 FCB，这就是本题 B 选项对应的操作。FCB 保存文件名、文件大小、磁盘块地址、读写权限、创建 / 修改时间、链接计数等文件元数据信息。
3. 权限校验：
    - 对比进程当前身份与 FCB 内读写权限，判断是否允许本次打开模式（只读 / 只写 / 读写）；若当前进程无打开文件的权限，则直接返回文件打开失败。
4. 创建进程私有打开文件表项：
    - 在进程 PCB 的打开文件表中新建表项，记录：指向内存 FCB 的指针、文件当前读写偏移量（初始为 0）、本次打开的访问模式（只读 / 可写等）。
5. 分配并返回文件描述符 fd：
    - 将上一步在进程 PCB 的打开文件表中，新建表项的下标（即：文件描述符 fd）返回给用户进程，进程后续再次操作该文件（read / write / close 等）都通过 fd 进行。文件描述符 fd 是进程私有打开文件表的数组下标。在 Linux 中，“一切皆文件”，进程所有 I/O 资源（普通文件、管道、socket、终端、设备等）全部统一用文件描述符 fd 标识。

▷ ② 再逐个分析各个选项：

A 错误×：首次打开文件时，不需要立刻把整个文件内容读到内存，只有后续进行读写操作（read 和 write 系统调用）时才会按需加载文件数据。

B 正确√：文件控制块（FCB）存放着文件的元数据（文件名、位置、权限、大小等），文件首次打开时，操作系统必须先把外存上的 FCB 读入内存，才能获取文件的管理信息、完成合法性校验等打开流程。

C 错误×：打开文件不会修改文件控制块的读写权限，权限是文件创建或专门修改权限时设置的，打开操作只会校验权限。修改权限需要单独系统调用 `chmod()`，`open()` 仅校验权限，不修改。

D 错误×：打开文件会返回文件描述符 fd，不会直接把数据缓冲区首指针返回给进程，缓冲区由操作系统内核管理。

**【点评】** 难题。文件的打开和读取等操作是 408 中的重难点，也是高频考点。2012 年 408 第 28 题考查“read 系统调用”、本题其实是考“open 系统调用”，考生可结合竞成写的这两题的解析，对比学习。

</Solution>

</Question>

<Question id="408-47a2a6-009" type="single" tags="来源:2015考研408">

在文件的索引节点中存放直接索引指针 10 个, 一级和二级索引指针各 1 个。磁盘块大小为 1KB, 每个索引指针占 4 个字节。若某文件的索引节点已在内存中, 则把该文件偏移量 (按字节编址) 为 1234 和 307400 处所在的磁盘块读入内存, 需访问的磁盘块个数分别是（ ）。

<Option>1,2</Option>
<Option correct>1,3</Option>
<Option>2,3</Option>
<Option>2,4</Option>

<Solution>

**【解析】** 先分析各级索引对应的地址范围：

- 直接索引：10 个指针 × 1KB = 10KB（偏移量 0～10239）
- 每个磁盘块可存放索引指针数 = 1KB ÷ 4B = 256 个
- 一级索引：256 × 1KB = 256KB（偏移量 10240～10240 + 256K = 272383）
- 二级索引：256 × 256 × 1KB = 64MB（偏移量 272384～272384 + 64M = 67381247）

① 偏移量 $1234<10240$，属于直接索引范围。索引节点已在内存中，直接从直接索引指针获得磁盘块地址，访盘 1 次读取数据。

② 偏移量 307400：$272384<307400<67381247$，属于二级索引范围。故需要访盘 3 次。故选 B。

- 第 1 次访盘：读取二级索引块（一级索引表所在块）
- 第 2 次访盘：读取一级索引块（数据块地址表所在块）
- 第 3 次访盘：读取目标数据块

**【点评】** 常规题。考查多级索引相关计算。此类题是 408 中的高频考点，考生需熟练掌握。本题的计算量也比较大，但只需大致估计范围即可做出本题。

<Question id="408-47a2a6-031" type="single" tags="来源:2023考研408">

某系统采用页式存储管理, 用位图管理空闲页框。若页大小为 4KB, 物理内存大小为 16GB,则位图所占空间的大小是（ ）。

<Option>128B</Option>
<Option>128KB</Option>
<Option correct>512KB</Option>
<Option>4MB</Option>

<Solution>

**【解析】** 物理内存大小为 16 GB，每页大小为 4 KB，因此物理内存总共包含的页框数为：$(16\text{GB})/(4\text{KB})=2^{34}/2^{12}=2^{22}$。位图需要管理每个页框的空闲状态，因此位图的位数应该等于物理内存中页框的数量。每个位表示一个页框的空闲状态，所以位图所占空间大小应为（位图所占位数）/8 = $(2^{22})/8=2^{19}\text{B}=512\text{KB}$。故选 C。

**【点评】** 常规题。基本概念的综合题。只要了解“位图”的概念，这题应该就能做对。

</Solution>

<Question id="408-47a2a6-032" type="single" tags="来源:2024考研408">

文件系统需占用部分外存空间记录空闲块位置,下列方法中,占用外存空间的大小与当前空闲块数量无关的是（ ）。

<Option correct>位图法</Option>
<Option>空闲表法</Option>
<Option>成组链接法</Option>
<Option>空闲链表法</Option>

<Solution>

**【解析】** **空闲表法**需要用额外的一张表来记录所有空闲的磁盘块，而**空闲链表法**需要将空闲磁盘块连接在一起，因此这两种方法都是空闲块越多需要的额外空间越多。**成组链接法**把空闲块分为若干组，每 100 个空闲块为一组，每组的第一个空闲块记录了空闲块总数和下一组物理空闲块的物理盘块号。因此空闲块越多所需空间越大。**位示图**用一个二进制位表示一个磁盘块是否空闲，因此无论磁盘块是否空闲都要占用空间，其大小仅取决于磁盘的总块数。

**【点评】** 常规题。考查基本概念。

</Solution>
