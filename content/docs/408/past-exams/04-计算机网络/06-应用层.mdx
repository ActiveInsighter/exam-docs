# 第 6 章 应用层

## 6.1 网络应用模型

<Question id="408-53633f-001" type="single" tags="来源:2019考研408">

下列关于网络应用模型的叙述中,错误的是（ ）。

<Option>在 P2P 模型中,结点之间具有对等关系</Option>
<Option correct>在客户 / 服务器 (C/S) 模型中, 客户与客户之间可以直接通信</Option>
<Option>在 C/S 模型中,主动发起通信的是客户,被动通信的是服务器</Option>
<Option>在向多用户分发一个文件时, P2P 模型通常比 C/S 模型所需的时间短</Option>

<Solution>

**【解析】** 网络应用模型主要分两种：

① P2P 模型，每个节点既当服务器也可作为客户，互相之间平等，故 A 正确。

② C/S 模型，存在少部分节点作为服务器为大多数的客户提供服务，客户需要先将信息发送给服务器，再由服务器来转发给需要通信的客户，无法直接通信。例如，在微信中和联系人交流，信息会先发送给微信服务器，服务器再转发给对方，而 P2P 模型中各个结点可以直接通信，故 B 错误，C 正确。当向多用户分发一个文件时，P2P 模型可以将任务分配给多个节点，用户可请求最近速率快的节点服务器，所以需要的时间更短，故 D 正确。故选 B。

**【点评】** 常规题。考查 P2P 模型和 C/S 模型的基本概念。

</Solution>

</Question>

## 6.2 域名系统 (DNS)

<Question id="408-53633f-002" type="single" number={2} tags="来源:2010考研408">

如果本地域名服务器无缓存, 当采用递归方法解析另一网络某主机域名时, 用户主机、 本地域名服务器发送的域名请求消息数分别为（ ）。

<Option correct>一条、一条</Option>
<Option>一条、多条</Option>
<Option>多条、一条</Option>
<Option>多条、多条</Option>

<Solution>

**【解析】** 如下图所示，DNS 查询方式主要有两种：

① **递归查询：** 请求方只发起一次 DNS 查询，若接收方查找不到对应的映射地址，则接收方将以请求者的身份发起新的 DNS 查询，递归地执行下去，直至遇到能处理请求的接收方后，将域名映射结果依次返回给最初的请求方。

② **迭代查询：** 请求方发出 DNS 查询后，若接收方查找不到对应的映射地址，则接收方将指示请求方寻找其他接收方获取结果，请求方则根据指示发送新的请求，如此反复，直到获取最终结果。故选 A。

![递归查询和迭代查询](/img/2010-q40-solution.svg)

**【点评】** 常规题。考查递归查询的概念。

</Solution>

</Question>

<Question id="408-53633f-003" type="single" tags="来源:2016考研408">

假设所有域名服务器均采用迭代查询方式进行域名解析。当 H4 访问规范域名为 www.abc.xyz.com 的网站时,域名服务器 201.1.1.1 在完成该域名解析过程中,可能发出 DNS 查询的最少和最多次数分别是（ ）。

<Option>1,3</Option>
<Option>0,3</Option>
<Option correct>0,4</Option>
<Option>1,4</Option>

<Solution>

**【解析】** ① 最少发起 0 次 DNS 查询：若本地域名服务器缓存中已有 www.abc.xyz.com 的解析结果，直接应答，一次对外查询都不用发。

② 最多发起 4 次 DNS 查询：若本地域名服务器缓存中不包含域名映射时，本地域名服务器依次向根域名服务器 → 顶级域名服务器（.com）→ 权限域名服务器（xyz.com）→ 权限域名服务器（abc.xyz.com）各发一次查询。故选 C。

<Question id="408-53633f-004" type="single" tags="来源:2020考研408">

假设下图所示网络中的本地域名服务器只提供递归查询服务, 其他域名服务器均只提供迭代查询服务；局域网内主机访问 Internet 上各服务器的往返时间 (RTT) 均为 10ms, 忽略其他各种时延。若主机 H 通过超链接 http://www.abc.com/index.html 请求浏览纯文本 Web 页 index.html, 则从点击超链接开始到浏览器接收 index.html 页面为止, 所需的最短时间与最长时间分别是（ ）。

![第 6 章 应用层 6.2 第3题：网络拓扑图，见原 PDF 第59页附近](/img/questions/408/computer-network-6-2-q3.svg)

<Option>10ms、 40ms</Option>
<Option>10ms、 50ms</Option>
<Option>20ms、 40ms</Option>
<Option correct>20ms、 50ms</Option>

<Solution>

**【解析】** ① 最短时间：当主机 H 本地存在 www.abc.com 域名对应的 IP 地址映射记录时，直接通过 IP 地址访问 Internet 上的服务器即可。通过 HTTP 协议访问资源时需要先耗费1个 RTT 来建立 TCP 连接，请求 index.html 并收到服务器响应，耗时1个 RTT，即最短需要消耗2个 RTT 的时延（第三次握手可以携带对 index.html 的请求），即20ms。

② 最长时间：当主机 H 本地不存在 www.abc.com 域名到 IP 地址的映射记录时，主机需要先向本地域名服务器发起 DNS 查询（此时延被忽略），接着本地域名服务器通过迭代查询向根域名服务器、com 顶级域名服务器、abc.com 权限域名服务器发起 DNS 查询，共需要3个 RTT。主机获取到 IP 地址后，同样地，需要建立 TCP 连接（耗时1个 RTT）、请求 index.html 并收到服务器响应（耗时1个 RTT），所以最长时间需要 $3+2=5$ 个 RTT，即50ms。故选 D。

**【点评】** 综合题。综合考查了域名解析过程和 TCP 连接建立过程。

</Solution>

</Question>

## 6.3 文件传输协议 (FTP)

<Question id="408-53633f-005" type="single" number={5} tags="来源:2009考研408">

FTP 客户和服务器间传递 FTP 命令时, 使用的连接是（ ）。

<Option correct>建立在 TCP 之上的控制连接</Option>
<Option>建立在 TCP 之上的数据连接</Option>
<Option>建立在 UDP 之上的数据连接</Option>
<Option>建立在 UDP 之上的控制连接</Option>

<Solution>

**【解析】** FTP 协议使用两个独立的 TCP 连接：① 控制连接：使用 21 号端口，在整个会话期间一直保持，用于在客户端和服务器之间传递 FTP 命令。② 数据连接：数据传输过程中临时建立，数据传输完成后断开。主动模式下使用 20 号，被动模式下使用随机端口。故选 A。

**【点评】** 概念题。本题考查 FTP 协议的基本概念。

</Solution>

</Question>

<Question id="408-53633f-006" type="single" tags="来源:2017考研408">

下列关于 FTP 协议的叙述中,错误的是（ ）。

<Option>数据连接在每次数据传输完毕后就关闭</Option>
<Option>控制连接在整个会话期间保持打开状态</Option>
<Option correct>服务器与客户端的 TCP20 端口建立数据连接</Option>
<Option>客户端与服务器的 TCP21 端口建立控制连接</Option>

<Solution>

**【解析】** FTP 使用两条并行的 TCP 连接：

- 控制连接：传送命令与响应。客户端使用随机端口去连接服务器的 21 号端口，整个会话期间保持打开。故选项 B 和选项 D 正确 ✓。
- 数据连接：实际传输文件数据，每次传输单独建立，传输完毕即关闭。故选项 A 正确 ✓。

FTP 协议的数据连接分为主动模式（PORT）和被动模式（PASV）：

- 主动模式（PORT）：服务器使用固定端口 20，主动连接客户端。
- 被动模式（PASV）：客户端主动连接服务器，服务器随机分配临时端口。

C 错误 ×：无论是主动模式还是被动模式，FTP 数据连接中客户端使用的都是临时端口（随机端口）。故选 C。

**【点评】** 概念题。考查 FTP 协议的基础内容。本题 C 选项极具迷惑性：FTP 协议中，20 和 21 号端口都是服务端使用的，客户端使用的都是随机端口。

</Solution>

</Question>

## 6.4 电子邮件

<Question id="408-53633f-007" type="single" number={7} tags="来源:2012考研408">

若用户 1 与用户 2 之间发送和接收电子邮件的过程如下图所示, 则图中①、②、③阶段分别使用的应用层协议可以是（ ）。

![第 6 章 应用层 6.4 第1题：图表，见原 PDF 第60页附近](/img/questions/408/computer-network-6-4-q1.svg)

<Option>SMTP、 SMTP、 SMTP</Option>
<Option>POP3、 SMTP、 POP3</Option>
<Option>POP3、 SMTP、 SMTP</Option>
<Option correct>SMTP、 SMTP、 POP3</Option>

<Solution>

**【解析】** ① SMTP 是发邮件专用协议，负责邮件的发送与服务器间转发，采用“推”模式，主动将邮件推送给下一跳服务器。明文发送时默认使用 25 号端口，加密发送时默认使用 465 或 587 号端口。② POP3 是收邮件专用协议，负责从邮件服务器下载邮件到本地。采用“下载并删除”模式：邮件下载到本地后，服务器默认会删除副本。明文接收时默认使用 110 号端口，加密接收时默认使用 995 号端口。③ IMAP（Internet Message Access Protocol，互联网消息访问协议）是一种邮件接收协议，专门用于用户客户端从邮件服务器上远程管理和读取邮件。POP3 正逐渐被 IMAP 取代。IMAP 明文接收时默认使用 143 号端口，加密接收时默认使用 993 号端口。IMAP 核心功能如下：

- 支持服务器同步管理：邮件默认保留在服务器上，所有操作（读信、标记、删除、建文件夹）都会同步到服务器。
- 支持远程操作：可以直接在客户端上创建文件夹、移动邮件、标记已读/未读、删除邮件，这些操作都会同步到服务器，无需把邮件下载到本地。
- 支持部分下载：可以只下载邮件的标题、正文，不下载附件，节省流量和本地空间，适合移动设备使用。

这里以用户 Alice 给用户 Bob 发送一封邮件为例，相关协议如下图所示。故选 D。

![Alice 给 Bob 发送邮件](/img/2012-q40-solution.svg)

**【点评】** 概念题。考查电子邮件相关协议。记忆性内容。

</Solution>

</Question>

<Question id="408-53633f-008" type="single" tags="来源:2013考研408">

下列关于 SMTP 协议的叙述中, 正确的是（ ）。 I. 只支持传输 7 比特 ASCII 码内容 II. 支持在邮件服务器之间发送邮件 III. 支持从用户代理向邮件服务器发送邮件 IV. 支持从邮件服务器向用户代理发送邮件

<Option correct>仅 I、 II 和 III</Option>
<Option>仅 I、 II 和 IV</Option>
<Option>仅 I、 III 和 IV</Option>
<Option>仅 II、 III 和 IV</Option>

<Solution>

**【解析】** ① I 正确√：SMTP 协议设计之初，规定邮件内容只能是 7 位 ASCII 码文本。如果要传输非 ASCII 内容（例如，中文、图片），需要通过 MIME 协议编码为 ASCII 格式再发送。

② II 正确√：SMTP 是邮件传输协议，核心功能之一就是邮件服务器之间的中继转发，将邮件从发件人服务器送到收件人服务器。

③ III 正确√：用户写好邮件后，客户端（用户代理）通过 SMTP 协议将邮件发送到自己的发件服务器，这是 SMTP 的典型应用场景。

④ IV 错误×：邮件服务器向用户代理发送邮件（也就是“收邮件”），使用的是 POP3 或 IMAP 协议，而非 SMTP。SMTP 只发不收（用户 → 服务器、服务器 → 服务器）、POP3/IMAP 只收不发（服务器 → 用户）。I、II、III 正确，故选 A。

**【提示】** ★ ① SMTP 是互联网上最成功、生命力最强的协议之一，自 1981 首次发布，通过持续的扩展和安全升级，至今依然牢牢占据着电子邮件传输的核心位置，是电子邮件的“通用语言”。根据 408 命题趋势，偏好考这种“经久不衰、至今仍是主流”的概念和技术。考生应重视。② SMTP 基于 C/S 模型，使用 TCP 连接（默认端口 25）。

**【点评】** 概念题。2012 年 408 第 40 题考过 SMTP 协议，本题又专门单一考查 SMTP 协议，这种“死记硬背”的考法（综合性、灵活性），如今的 408 考试中考的很少了。

</Solution>

</Question>

<Question id="408-53633f-010" type="single" tags="来源:2018考研408">

无须转换即可由 SMTP 协议直接传输的内容是（ ）。

<Option>JPEG 图像</Option>
<Option>MPEG 视频</Option>
<Option>EXE 文件</Option>
<Option correct>ASCII 文本</Option>

<Solution>

**【解析】** SMTP 最初设计只能传输 7 位 ASCII 码文本（NVT ASCII）。对于非 ASCII 数据（二进制文件、图像、视频、可执行程序、非英文字符等），必须先经 MIME（多用途互联网邮件扩展）进行编码转换（例如，base64、quoted-printable），将其转换为 ASCII 文本形式后才能由 SMTP 传输，接收方再解码还原。

JPEG 图像和 MPEG 视频都是二进制数据、EXE 文件是可执行二进制文件，都需要经 MIME 编码转换才能由 SMTP 传输。题目问“无须转换即可直接传输”，只有 ASCII 文本。故选 D。

**【点评】** 常规题。本题考查 SMTP 协议。记住结论：SMTP 只认 7 位 ASCII；一切非 ASCII 内容（图像、音频、视频、可执行文件、中文等非 ASCII 字符）都必须经 MIME 转换。

</Solution>

</Question>

## 6.5 万维网 (www)

<Question id="408-53633f-011" type="single" number={11} tags="来源:2014考研408">

使用浏览器访问某大学 Web 网站主页时, 不可能使用到的协议是（ ）。

<Option>PPP</Option>
<Option>ARP</Option>
<Option>UDP</Option>
<Option correct>SMTP</Option>

<Solution>

**【解析】** ① A 正确√：访问网站前需接入互联网。目前，在家庭宽带和校园网中广泛使用的“PPPoE 拨号”，其底层使用 PPP 协议完成身份认证和 IP 地址分配。这是访问网页的必要前置步骤，因此该过程可能涉及 PPP 协议。

**【提示】** PPPoE（PPP over Ethernet）拨号指在以太网上用 PPP 协议完成身份认证并接入互联网的整个过程，具体过程是：输入账号密码 → 身份认证 → 获取 IP 地址 → 上网。“拨号”一词源自早期电话拨号上网，虽然现代宽带不再真的“拨打电话号码”，但将“输入账号密码进行认证连接”这个操作仍称为拨号。

② B 正确√：ARP 协议一定会用到。数据帧在数据链路层传输时都需要目的 MAC 地址，ARP 协议将 IP 地址解析为 MAC 地址。

③ C 正确√：访问网页前需要做 DNS 域名解析，DNS 默认基于 UDP（53 号端口）传输数据，因此会用到 UDP。

④ D 错误×：SMTP 专门用于发送电子邮件。浏览器访问 Web 网站主页与邮件传输完全无关，不会用到 SMTP 协议。

**【拓展】** ★ PPP 协议是 408 中的冷门考点，从 2009～2026，这 18 年中，仅在 2012 年第 33 题 A 选项和 2014 年第 40 题 A 选项中出现过，需引起考生重视。这里对 PPPoE 协议进行补充介绍。

PPPoE（PPP over Ethernet）协议属于工作在数据链路层的封装型 / 隧道型协议：它不是凭空定义了一套全新的通信规则，而是把原本用于点对点链路的 PPP 协议，封装在以太网帧中进行传输。PPPoE 协议设计的初衷就是为了弥补以太网的接入管控短板。

- 以太网的局限：以太网是广播型多路访问网络，原生没有用户身份认证、独立链路隔离、按用户计费的能力，无法满足运营商级的接入管控需求。
- PPP 的优势：PPP 是经典的点对点链路层协议，自带完整的链路配置（LCP）、身份认证（PAP/CHAP）、网络参数协商（NCP/IPCP）和计费统计能力，但仅能运行在串行点对点线路上，无法直接在以太网上使用。
- PPPoE 的价值：它在以太网和 PPP 之间搭建了适配层，在共享的以太网物理链路上，为每个用户虚拟出一条独立的点对点逻辑隧道，既保留了以太网部署成本低的优势，又继承了 PPP 完善的用户管理能力。

在竞成《计算机网络考研复习全书》第 3 章第 3.7 节广域网部分，对 PPP 协议有较为详细的介绍，强烈建议考生去看下。这里限于篇幅，不再重复介绍。

**【点评】** 综合题。① 这类考题出题思路灵活，变式题目层出不穷，要求考生了解访问 Web 网页背后的底层交互流程。类似的题目是 408 的考查趋势。但做对本题其实不难，选 D 很明显，A 选项可能有些同学不熟悉导致不确定。

<Question id="408-53633f-012" type="single" tags="来源:2015考研408">

某浏览器发出的 HTTP 请求报文如下.下列叙述中,错误的是（ ）．

```http
GET /index.html HTTP/1.1
Host: www.test.edu.cn
Connection: Close
Cookie: 123456
```

<Option>该浏览器请求浏览 index.html</Option>
<Option>index.html 存放在 www.test.edu.cn 上</Option>
<Option correct>该浏览器请求使用持续连接</Option>
<Option>该浏览器曾经浏览过 www.test.edu.cn</Option>

<Solution>

**【解析】** ① A 正确 ✓。请求行“`GET /index.html HTTP/1.1`”表明：用 GET 方法请求服务器上的 index.html 文档对象，协议版本为 HTTP/1.1。

② B 正确 ✓。首部行“`Host: www.test.edu.cn`”指明目标主机是 www.test.edu.cn。HTTP/1.1 强制要求携带 Host 字：若无匹配的目的网络，则按照默认路由（0 同一个 IP 地址上托管多个域名，服务器必须靠 Host 字段才能区分你要访问哪一个网站。

{/* 原书此句夹杂默认路由文字，括号不完整，按原文保留。 */}

③ C 错误 ×。首部行“`Connection: Close`”表示：浏览器请求服务器在发完响应后关闭 TCP 连接，即使用非持续连接。虽然 HTTP/1.1 的默认行为是持续连接（keep-alive），但报文中显式给出的 Connection: Close 会覆盖默认值。

④ D 正确 ✓。Cookie 是浏览器首次访问某站点时，服务器在响应报文中通过 Set-Cookie 字段给该浏览器分配一个识别码，浏览器把它保存在本地的 Cookie 文件中，用于让无状态的 HTTP 协议能够“记住”用户，实现状态跟踪。因为 HTTP 是无状态协议：服务器默认无法区分两次请求是否来自同一个用户。但实际应用（例如，登录等场景）需要跨请求识别用户身份，Cookie 就是为此设计的。请求报文中已经携带着“`Cookie: 123456`”，说明该浏览器曾经访问过 www.test.edu.cn。

<Question id="408-53633f-014" type="single" tags="来源:2022考研408">

假设主机 H 通过 HTTP/1.1 请求浏览某 Web 服务器 S 上的 Web 页 news408.html, news408. html 引用了同目录下的 1 幅图像, news408.html 文件大小为 1MSS(最大段长), 图像文件大小为 3MSS, H 访问 S 的往返时间 RTT = 10ms, 忽略 HTTP 响应报文的首部开销和 TCP 段传输时延。若 H 已完成域名解析, 则从 H 请求与 S 建立 TCP 连接时刻起, 到接收到全部内容止, 所需的时间至少是（ ）。

<Option>30ms</Option>
<Option correct>40ms</Option>
<Option>50ms</Option>
<Option>60ms</Option>

<Solution>

**【解析】** 先明确 2 个概念：(1) HTTP/1.1 的默认模式是使用带流水线的持续连接。带流水线指在同一条 TCP 连接上连续的发出请求，不用等待响应返回后再发送请求。(2) 捎带确认指接收方接收到数据帧后不立即进行确认，而是等到自己给发送方发送数据时再捎带确认信息。本题求所需的最少时间，故不用考虑拥塞等情况，也不考虑传输时延。过程分析如下图所示：

![HTTP 请求过程](/img/2022-a40.svg)

① **第 1 个 RTT**：TCP 连接建立需要 3 次握手，前 2 次握手耗时 1 个 RTT；

② **第 2 个 RTT**：主机 H 发送第 3 次握手报文，并携带对 news408.html 文件的请求报文。初始时，采用慢开始算法，拥塞窗口大小 cwnd = 1MSS，服务器 S 向主机发送 1MSS 大小的 news408.html 文件，主机 H 收到 news408.html 文件。

③ **第 3 个 RTT**：主机 H 采用捎带确认发送对图像文件的请求报文。服务器 S 收到对 news408.html 文件的确认后，cwnd 变为 2MSS。服务器 S 发送大小为 2MSS 的部分图像文件给主机 H，主机 H 收到 2MSS 的图像文件。

④ **第 4 个 RTT**：主机 H 采用捎带确认发送对图像文件的请求报文。服务器 S 收到对 2MSS 图像文件的确认后，cwnd 变为 4MSS。服务器 S 将剩余 1MSS 的图像文件给主机 H，主机 H 收到 1MSS 文件。至此，主机 H 接受到全部内容。

**【点评】** 难题。本题综合性很强，综合考查了 HTTP/1.1 协议持续连接、捎带确认、TCP 连接建立、TCP 流量控制、TCP 拥塞控制等 408 核心考点。

</Solution>

<Question id="408-53633f-015" type="single" tags="来源:2024考研408">

若浏览器不支持并行 TCP 连接, 使用非持久的 HTTP/1.0 协议请求浏览 1 个 Web 页, 该页中引用同一个网站上 7 个小图像文件,则从浏览器为传输 Web 页请求建立 TCP 连接开始,到接收完所有内容为止, 所需要的往返时间 RTT 数至少是（ ）。

<Option>4</Option>
<Option>9</Option>
<Option>14</Option>
<Option correct>16</Option>

<Solution>

**【解析】** 非持续连接指每个请求或响应都是通过一个单独的 TCP 连接发送。因此每次请求一个新的网页或资源时，都会建立一个新的 TCP 连接。持续连接指 TCP 连接保持打开状态，可以发送多个请求或响应，而不需要为每个请求都建立新的连接。题目说采用非持久 HTTP，所以，每传送一个对象，需要建立一次 TCP 连接。TCP 连接建立时，前 2 次握手需要 1 个 RTT，第 3 次握手可以携带数据，服务器收到请求后进行响应，故每传输一个对象至少需要 2 个 RTT。请求 web 页面（HTML 文件）耗费 2 个 RTT，之后 7 个图像文件都需要建立 TCP 连接并发送请求，每次建立连接加传送图像文件需要 2 个 RTT，因此至少需要 $(1+7)\times2=16$ 个 RTT。

**【点评】** 常规题。高频考点，此前真题中考过类似的。

</Solution>
