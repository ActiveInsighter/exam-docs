# 第 5 章 传输层


## 5.1 UDP 协议

<Question id="408-ad3c14-001" type="single">

【2014】下列关于 UDP 协议的叙述中, 正确的是（ ）。 I. 提供无连接服务 II. 提供复用 / 分用服务 III. 通过差错校验, 保障可靠数据传输

<Option>仅 I</Option>
<Option correct>仅 I、 II</Option>
<Option>仅 II、 III</Option>
<Option>I、 II、 III</Option>

<Solution>

**【解析】** ① I 正确√：UDP 是无连接协议，发送数据前不需要建立连接，也没有连接状态维护，每个 UDP 数据报独立处理，无需维护连接上下文。

② II 正确√：UDP 通过端口号机制实现复用 / 分用，这是传输层的基本功能。

- 复用指发送方多个应用进程通过不同端口号共用 UDP 发送数据。
- 分用指接收方根据目的端口号将数据交付给对应的应用进程。

③ III 错误×：UDP 首部包含校验和字段（校验首部和数据部分），可选（非强制）的提供差错检测功能，但只能检测错误，不能纠正错误。而且检测到错误后直接丢弃，不会重传。也没有确认机制、没有重传机制、没有流量控制、没有拥塞控制。可靠数据传输需要：确认 + 重传 + 序号 + 计时器，这些都是 TCP 的特性，UDP 完全不提供。故选 B。

**【点评】** 概念题。考查 UDP 协议的特点。

</Solution>

</Question>

## 5.2 TCP 协议

<Question id="408-ad3c14-004" type="single" number={1}>

【2009】主机甲与主机乙之间已建立一个 TCP 连接, 主机甲向主机乙发送了两个连续的 TCP 段, 分别包含 300B 和 500B 的有效载荷, 第一个段的序列号为 200, 主机乙正确接收到两个段后, 发送给主机甲的确认序列号是（ ）。

<Option>500</Option>
<Option>700</Option>
<Option>800</Option>
<Option correct>1000</Option>

<Solution>

**【解析】** 如下图所示，TCP 序号是对数据部分进行编号，TCP 首部本身不占用序号。

TCP 段首部的序号字段指的当前报文段数据部分第一个字节的编号。

确认序号 = 期望收到的下一个字节的序号 = 已正确接收的最后一个字节的序号 + 1。

第一个 TCP 段的序列号为 200，长度为 300，则数据编号为 200～499；第二个 TCP 段的序列号为 499+1 = 500，长度为 300，则数据编号为 500～999。所以主机乙发送的确认号为 999+1 = 1000，故选 D。

**【点评】** 常规题。本题考查 TCP 段序列号的概念。

</Solution>

<Question id="408-ad3c14-005" type="single">

【2009】一个 TCP 连接总是以 1KB 的最大段长发送 TCP 段, 发送方有足够多的数据要发送。当拥塞窗口为 16KB 时发生了超时, 如果接下来的 4 个 RTT (往返时间) 时间内的 TCP 段的传输都是成功的,那么当第 4 个 RTT 时间内发送的所有 TCP 段都得到肯定应答时,拥塞窗口大小:（ ）

<Option>7KB</Option>
<Option>8KB</Option>
<Option correct>9KB</Option>
<Option>16KB</Option>

<Solution>

**【解析】** ① 根据 TCP 拥塞控制算法，当发生超时，慢开始门限 ssthresh 调整为当前 cwnd 的一半，即 $\mathrm{ssthresh}=\frac{16}{2}=8$。同时将 cwnd 重新设置为 1，重新开始执行慢开始算法。② 在接下来的 3 个 RTT 中，拥塞窗口指数增大：$1\to2\to4\to8$（拥塞窗口从 $1\to2$、$2\to4$、$4\to8$，各需要 1 个 RTT）。③ 在第 3 个 RTT 后，由于此时拥塞窗口 = 8，达到慢开始门限，所以开始执行拥塞避免算法，拥塞窗口线性增大（$8\to9$）。故在 4 个 RTT 后，拥塞窗口大小为 9 KB。故选 C。

**【点评】** 概念题。本题考查 TCP 的流量控制，基本每年必考。

</Solution>

<Question id="408-ad3c14-006" type="single">

【2010】主机甲和主机乙之间已建立了一个 TCP 连接, TCP 最大段长度为 1000B。若主机甲的当前拥塞窗口为 4000B, 在主机甲向主机乙连续发送两个最大段后, 成功收到主机乙发送的第一个段的确认段, 确认段中通告的接收窗口大小为 2000B, 则此时主机甲还可以向主机乙发送的最大字节数是（ ）。

<Option correct>1000</Option>
<Option>2000</Option>
<Option>3000</Option>
<Option>4000</Option>

<Solution>

**【解析】** TCP 的发送窗口上限，取拥塞窗口和接收窗口，这两者中的较小值。即发送窗口 $=\min\{\mathrm{cwnd},\mathrm{rwnd}\}=\min\{4000\mathrm{B},2000\mathrm{B}\}=2000\mathrm{B}$。由于此时只收到了第一个段的确认段，第二个段已发送但未被确认，所以此时主机甲还可以发送 $2000\mathrm{B}-1000\mathrm{B}=1000\mathrm{B}$。故选 A。

**【点评】** 常规题。TCP 拥塞控制的常规题型。

</Solution>

<Question id="408-ad3c14-007" type="single">

【2011】主机甲向主机乙发送一个 (SYN = 1, seq = 11220) 的 TCP 段, 期望与主机乙建立 TCP 连接,若主机乙接受该连接请求, 则主机乙向主机甲发送的正确的 TCP 段可能是（ ）。

<Option>`{SYN=0,ACK=0,seq=11221,ack=11221}`</Option>
<Option>(SYN = 1,ACK = 1,seq = 11220,ack = 11220)</Option>
<Option correct>(SYN = 1, ACK = 1, seq = 11221, ack = 11221)</Option>
<Option>`{SYN=0,ACK=0,seq=11220,ack=11220}`</Option>

<Solution>

**【解析】** ① 当主机甲向主机乙发送连接请求后，如果主机乙接受连接，则向主机甲发送确认报文段。确认报文段中 SYN=1（同意建立连接）和 ACK=1（确认收到请求）。

② 同时，虽然主机甲发送的连接请求报文段没有数据，但规定需要占用一个序号，所以主机乙确认报文段中的 $ack=11220+1=11221$。

③ 主机乙确认报文段的初始序号 seq 由主机乙的 TCP 进程独立确定，通常为随机值。它与主机甲发来的确认号、以及本次报文段中的 ack 字段，没有必然的数值关联。故选 C。

**【点评】** ★ 高频考点。主机乙确认报文段的初始序号 seq，这个点容易忽略出错。其他的都是常见考点。本题也可以通过排除法快速解题。

</Solution>

<Question id="408-ad3c14-008" type="single">

【2011】主机甲与主机乙之间已建立一个 TCP 连接,主机甲向主机乙发送了 3 个连续的 TCP 段, 分别包含 300B、 400B 和 500B 的有效载荷, 第 3 个段的序号为 900。若主机乙仅正确接收到第 1 和第 3 个段, 则主机乙发送给主机甲的确认序号是（ ）。

<Option>300</Option>
<Option correct>500</Option>
<Option>1200</Option>
<Option>1400</Option>

<Solution>

**【解析】** TCP 使用累积确认：接收方只会对“按序收到的连续数据”进行确认，确认号为“期望收到的下一个字节的序号”。由于主机乙仅接收到第 1 和第 3 个报文段，此时期望收到第 2 个报文段，主机乙期望接收第 1 个段的最后一个字节号的下一个字节号，即第 2 个段的第一个字节号。所以确认号应该为第 2 个报文段的第一个字节对应的序号，第 3 个段第一个字节的序号为 900，连续发送 3 个报文段，第 2 个报文段长度为 400B，可以推出第 2 个报文段的序号为 $900-400=500$。故选 B。

| 报文段 | 数据大小 | 起始序号 | 序号范围 | 接收状态 |
| --- | --- | --- | --- | --- |
| 第 1 个段 | 300B | 200 | 200～499 | 已接收 |
| 第 2 个段 | 400B | 500 | 500～899 | 丢失 |
| 第 3 个段 | 500B | 900 | 900～1399 | 已接收 |

| | 第 1 个段 | 第 2 个段 | 第 3 个段 |
| --- | --- | --- | --- |
| 有效载荷 | 300B | 400B | 500B |
| 序号范围 | 200～499 | 500～899 | 900～1399 |

**【点评】** 常规题。考查 TCP 序号 seq 相关计算。需要注意的是：seq 字段的值是本报文段所携带数据的第一个字节的序号，不包含 TCP 首部和 IP 首部。首部本身不占用序号空间。因此计算序号范围时，只需要按有效载荷的字节数来累加即可。

</Solution>

<Question id="408-ad3c14-009" type="single">

【2013】主机甲与主机乙之间已建立一个 TCP 连接, 双方持续有数据传输, 且数据无差错与丢失。若甲收到 1 个来自乙的 TCP 段,该段的序号为 1913、确认序号为 2046、有效载荷为 100 字节,则甲立即发送给乙的 TCP 段的序号和确认序号分别是（ ）。

<Option>2046、 2012</Option>
<Option correct>2046、 2013</Option>
<Option>2047、 2012</Option>
<Option>2047、 2013</Option>

<Solution>

**【解析】** TCP 序号（seq）指发送方本次数据段的起始编号。TCP 确认号（ack）指接收方期望收到对方下一个数据段的序号，TCP 确认号 = 收到的序号 + 收到的有效载荷字节数。

主机甲收到的报文段序号为 1913，有效载荷为 100B，则主机甲针对该报文段发送的确认号 ack = 1913 + 100 = 2013。主机甲收到的报文段确认号为 2046（主机乙期望收到下一个数据段的序号），则甲再发送的报文序号 seq = 2046。故选 B。

**【提示】** TCP 报文是按字节编号，TCP 的序号和确认号都是针对数据字节的，TCP 首部（以及选项部分）不参与编号。

**【点评】** 易错题。TCP 连接建立（3 次握手）和连接释放（4 次挥手）考查频率很高，类似本题这样考查 TCP 数据传输过程的序号和确认号，考查频率低，反而容易忽略。本题很容易混淆导致出错。考生可把本题当作典型例题理解记忆。

</Solution>

<Question id="408-ad3c14-010" type="single">

【2014】主机甲和主机乙已建立了 TCP 连接, 甲始终以 MSS = 1KB 大小的段发送数据, 并一直有数据发送；乙每收到一个数据段都会发出一个接收窗口为 10KB 的确认段。若甲在 t 时刻发生超时时拥塞窗口为 8KB, 则从 t 时刻起, 不再发生超时的情况下, 经过 10 个 RTT 后, 甲的发送窗口是（ ）。

<Option correct>10KB</Option>
<Option>12KB</Option>
<Option>14KB</Option>
<Option>15KB</Option>

<Solution>

**【解析】** ① 当 TCP 发生超时重传时，TCP 拥塞控制初始化规则如下：

- 将拥塞窗口 cwnd 重置为 1 个 MSS = 1KB。
- 将慢启动门限 ssthresh 更新为超时时刻拥塞窗口的一半，即：$\mathrm{ssthresh}=\frac{\mathrm{cwnd}}{2}=4\mathrm{KB}$。

② 当 cwnd ≤ ssthresh 时，是慢开始阶段：每经过一个 RTT，cwnd 翻倍（cwnd 指数增大）。拥塞窗口 cwnd 变化过程是：

$$
1\mathrm{KB}\xrightarrow{\text{第 1 个 RTT}}2\mathrm{KB}\xrightarrow{\text{第 2 个 RTT}}4\mathrm{KB}
$$

当经过 2 个 RTT 后，cwnd = ssthresh = 4KB，慢开始阶段结束。

③ 当 cwnd > ssthresh 时，进入拥塞避免阶段：每经过一个 RTT，cwnd 加一（cwnd 线性增大）。拥塞窗口 cwnd 变化过程是：

$$
\begin{aligned}
4\mathrm{KB}&\xrightarrow{\text{第 3 个 RTT}}5\mathrm{KB}\xrightarrow{\text{第 4 个 RTT}}6\mathrm{KB}\\
&\xrightarrow{\text{第 5 个 RTT}}7\mathrm{KB}\xrightarrow{\text{第 6 个 RTT}}8\mathrm{KB}\\
&\xrightarrow{\text{第 7 个 RTT}}9\mathrm{KB}\xrightarrow{\text{第 8 个 RTT}}10\mathrm{KB}\\
&\xrightarrow{\text{第 9 个 RTT}}11\mathrm{KB}\xrightarrow{\text{第 10 个 RTT}}12\mathrm{KB}
\end{aligned}
$$

经过 10 个 RTT 后，拥塞窗口 cwnd = 12KB。

④ 拥塞窗口是网络侧的承载上限，接收窗口是接收方的承载上限，发送窗口必须同时满足两个上限、取更小值，即：发送窗口 = min\{拥塞窗口 cwnd, 接收窗口 rwnd\} = min(12KB, 10KB) = 10KB。故选 A。

**【提示】** ① 题目已说明“接收窗口一直为 10KB”，根据发送窗口 = min\{拥塞窗口, 接收窗口\}，可知发送窗口 ≤ 接收窗口（10KB），则发送窗口不超过 10KB，只有 A 选项符合要求。这种解法可节省较多做题时间，无需分析慢开始和拥塞避免过程。猜测这里大概率应该是命题人考虑不周，选项设计欠妥当，导致考生“可钻空子”：设计几个小于 10KB 的选项即可避免。命题的本意应该还是要考 TCP 的拥塞控制过程的。

② 本题错选 B 的同学，挺可惜的，考点应该都会，但做题时“顾头不顾尾”，算了半天算出了拥塞窗口 = 12KB，漏了发送窗口要取拥塞窗口、接收窗口里更小的那个。这种“丢三落四”不是知识掌握的问题，可通过多做题增加熟练度、并总结专属自己的易错点来避免此类问题。

**【点评】** 常规题。TCP 连接的建立与释放、拥塞控制，是 408 中的高频考点。类似的题在 408 中多次考到。

</Solution>

</Question>

<Question id="408-ad3c14-011" type="single">

【2015】主机甲和主机乙新建一个 TCP 连接, 甲的拥塞控制初始阈值为 32KB, 甲向乙始终以 MSS = 1KB 大小的段发送数据, 并一直有数据发送; 乙为该连接分配 16KB 接收缓存, 并对每个数据段进行确认, 忽略段传输延迟。若乙收到的数据全部存入缓存, 不被取走, 则甲从连接建立成功时刻起, 未发生超时的情况下, 经过 4 个 RTT 后, 甲的发送窗口是（ ）。

<Option correct>1KB</Option>
<Option>8KB</Option>
<Option>16KB</Option>
<Option>32KB</Option>

<Solution>

**【解析】** ① 分析拥塞窗口 cwnd。TCP 连接建立后，拥塞窗口 cwnd 初始为 1KB，按指数增大。4 个 RTT 过后，拥塞窗口 cwnd 的变化过程为：

$$
1\text{KB}\xrightarrow{\text{第 1 个 RTT}}2\text{KB}\xrightarrow{\text{第 2 个 RTT}}4\text{KB}\xrightarrow{\text{第 3 个 RTT}}8\text{KB}\xrightarrow{\text{第 4 个 RTT}}16\text{KB}
$$

② 分析接收窗口 rwnd。乙收到的数据全部存在缓存中，4 个 RTT 过后乙的缓存中已经存储了 $(1+2+4+8)\text{KB}=15\text{KB}$，剩余缓存大小为 16KB − 15KB = 1KB。接收方（主机乙）的接收窗口 rwnd 由剩余缓存大小决定。此时接收方（主机乙）的接收窗口 rwnd 为 1KB，拥塞窗口为 16KB。

③ 发送窗口 = min(拥塞窗口 cwnd, 接收窗口 rwnd) = $\min\{16\text{KB},1\text{KB}\}$ = 1KB。故选 A。

**【点评】** 常规题。综合考查 TCP 流量控制和拥塞控制，此类题是 408 中的常考题。

</Solution>

</Question>

<Question id="408-ad3c14-012" type="single">

【2017】若甲向乙发起一个 TCP 连接, 最大段长 MSS = 1KB, RTT = 5ms, 乙开辟的接收缓存为 64KB, 则甲从连接建立成功至发送窗口达到 32KB, 需经过的时间至少是（ ）。

<Option correct>25ms</Option>
<Option>30ms</Option>
<Option>160ms</Option>
<Option>165ms</Option>

<Solution>

**【解析】** 慢开始阶段拥塞窗口 cwnd 初始为 1MSS = 1KB，每经过一个 RTT 拥塞窗口 cwnd 的大小会翻倍。

本题求至少需要的时间，所以考虑拥塞窗口从 1KB 开始一直指数增长的情况。拥塞窗口增长过程为

$$
1\mathrm{KB}\xrightarrow{\text{第1个RTT}}2\mathrm{KB}\xrightarrow{\text{第2个RTT}}4\mathrm{KB}\xrightarrow{\text{第3个RTT}}8\mathrm{KB}\xrightarrow{\text{第4个RTT}}16\mathrm{KB}\xrightarrow{\text{第5个RTT}}32\mathrm{KB}
$$

从连接建立成功到 cwnd 达到 32KB 需要 5 个 RTT，耗时 $5\times5\mathrm{ms}=25\mathrm{ms}$。接收窗口 rwnd 为 64KB，发送窗口 = $\min(\mathrm{cwnd},\mathrm{rwnd})=32\mathrm{KB}$，故接收窗口 rwnd 不构成限制。故选 A。

**【点评】** 常规题。考查 TCP 拥塞避免算法，本题是相对简单的一类考法。

</Solution>

**【拓展】** ★ TCP 首部中 SYN、ACK、FIN 取值，是 408 中高频考点，这里总结如下：

① 仅在 TCP 连接建立阶段，主动发起连接（第 1 次握手）和被动响应连接（第 2 次握手）这两个报文中，SYN = 1。后续任何阶段 SYN 均为 0（第 3 次握手阶段也是）。

② 在正常 TCP 通信中，除了第一次握手时 SYN 报文中 ACK = 0，所有后续报文的 ACK = 1。

③ 仅在 TCP 主动释放连接（第 1 次挥手和第 3 次挥手）时，FIN = 1。第 2 次和第 4 次挥手，FIN = 0。通俗的说：谁主动关闭连接，谁发的报文 FIN = 1；只做确认而不主动关闭连接，FIN = 0。

④ TCP 连接释放的四次挥手过程中，ACK 位均为 1。也就是说：除了 TCP 连接建立过程中第一次握手时 ACK 位为 0，TCP 连接建立后的所有报文，ACK 位均为 1。

【2016】假设下图中的 H3 访问 Web 服务器 S 时, S 为新建的 TCP 连接分配了 20KB(K = 1024)

![第 5 章 传输层 5.2 第21题：图表，见原 PDF 第56页附近](/img/questions/408/computer-network-5-2-q21.svg)

的接收缓存, 最大段长 MSS = 1KB, 平均往返时间 RTT = 200ms。 H3 建立连接时的初始序号为 100, 且持续以 MSS 大小的段向 S 发送数据, 拥塞窗口初始阈值为 32KB；S 对收到的每个段进行确认, 并通告新的接收窗口。假定 TCP 连接建立完成后, S 端的 TCP 接收缓存仅有数据存入而无数据取出。请回答下列问题:
   (1) 在 TCP 连接建立过程中, H3 收到的 S 发送过来的第二次握手 TCP 段的 SYN 和 ACK 标志位的值分别是多少？确认序号是多少？
   (2) H3 收到的第 8 个确认段所通告的接收窗口是多少？此时 H3 的拥塞窗口变为多少?H3 的发送窗口变为多少?
   (3) 当 H3 的发送窗口等于 0 时, 下一个待发送的数据段序号是多少？ H3 从发送第 1 个数据段到发送窗口等于 0 时刻为止,平均数据传输速率是多少 (忽略段的传输延时)?
   (4) 若 H3 与 S 之间通信已经结束, 在 t 时刻 H3 请求断开该连接, 则从 t 时刻起, S 释放该连接的最短时间是多少?

<Solution>

**【解析】**

(1) TCP 第二次握手的 SYN = 1，ACK = 1，因为 H3 建立连接时的初始序号为 100，且第一次握手的报文占用一个序号，所以第二次握手的确认号为 ack = 100 + 1 = 101。

(2) 因为 H3 收到 8 个确认段时，已经发送了 8 个数据段，所以接收窗口为 $20-8=12\mathrm{KB}$。当处于慢开始指数增长阶段时，H3 每发送一帧，拥塞窗口就增加 1，从传输轮次的尺度上来看每一个轮次拥塞窗口翻倍。因此收到第 8 个确认段后拥塞窗口增加 8 次，增长到 9 KB，H3 的发送窗口为接收窗口和拥塞窗口中的最小值，为 9 KB。

(3) 当接收缓存满后，H3 的发送窗口等于 0，即已经发送 20 KB = 20480 B，初始序号为 100，第一个数据字节序号为 101，所以已经发送了 101～20580 号字节，下一个待发送的序号为 20581。发送 20 KB 需要 5 个传输轮次（拥塞窗口为 $1\to 2\to 4\to 8\to 5$），所以总共用时 $5\mathrm{RTT}=1000\mathrm{ms}$，平均传输速率为：$20\mathrm{KB}\div 1000\mathrm{ms}=163.84\mathrm{kb/s}$。

(4) 连接释放最短时间的情况为：H3 发送了请求断开报文后，S 发回确认报文，同时 S 没有其他数据需要发送，所以立即发送请求断开报文，H3 收到请求断开报文后，发回确认，S 收到确认就可以断开。期间经过了 3 个单向传播时延，即 $1.5\mathrm{RTT}=300\mathrm{ms}$。

**【易错点】** 本题求的是 H3 发送断开请求到 S 接收到 H3 发送的断开确认的时间，注意画图，否则容易认为是 2RTT。

<Question id="408-ad3c14-025" type="essay">

【2023】(9 分) 某网络拓扑如下图所示, 主机 H 登录到 FTP 服务器后, 向服务器上传一个大小为 18000B 的文件 F。假设 H 为传输 F 建立数据连接时, 选择的初始序号为 100, MSS = 1000B, 拥塞控制的初始阈值是 4MSS,RTT = 10ms, 忽略 TCP 的传输时延；在 F 的传输过程中, H 均以 MSS 段向服务器发送数据, 且未发生差错、丢包和乱序现象。

![第 5 章 传输层 5.2 第22题：网络拓扑图，见原 PDF 第57页附近](/img/questions/408/computer-network-5-2-q22.svg)


请回答下列问题。
   (1)FTP 的控制连接是持久的还是非持久的？ FTP 的数据连接是持久的还是非持久的？ H 登录 FTP 服务器时, 建立的 TCP 连接是控制连接还是数据连接?
   (2) H 通过数据连接发送 F 时, F 的第一个字节序号是多少？在断开数据连接的过程中, FTP 服务器发送的第二次挥手 ACK 段的确认序号是多少?
   (3) H 通过数据连接发送 F 的过程中, 当 H 收到确认序号为 2101 的确认段时, H 的拥塞窗口调整为多少? 收到确认序号为 7101 的确认段时, H 的拥塞窗口调整为多少?
   (4) H 从请求建立数据连接开始, 到确认 F 已被服务全部接收为止, 至少需要多长时间? 在这期间应用层数据的平均发送速率是多少？

<Solution>

**【解析】**

（1）FTP 的控制连接是持久的，而 FTP 的数据连接是非持久的。控制连接在 FTP 会话期间一直保持开放状态，用于发送命令和控制信息，如登录验证、文件操作指令等。控制连接的持久性允许客户端和服务器之间进行多个命令的交互，直到会话结束或显式关闭控制连接。数据连接在 FTP 中用于传输文件内容。每当需要传输文件时，FTP 客户端和服务器之间会建立一个临时的数据连接，用于传输文件的实际数据。这个数据连接在文件传输完成后会关闭，因此是非持久的。在登录服务器时，建立的 TCP 连接是控制连接。登录操作涉及身份验证、发送命令等控制信息，因此使用的是控制连接。数据连接仅在需要传输文件时才会建立。

（2）FTP 使用 TCP 连接进行数据的传输，在 TCP 三次握手的过程中，需要消耗 1 个序号，所以 F 的第一个字节序号为 101。在断开数据连接的数据过程中，共传输了 18000B 的数据，数据的第一个序号为 101，数据的最后一个序号为 18100。在完成数据传输后，客户端发送的 seq 等于已传送过的数据最后一个字节的序号加 1，所以 seq = 18101，因为 TCP 规定，FIN 报文即使不携带数据，也消耗掉一个序号。所以服务器给客户端返回的 ack = 18102，代表已经收到了 seq = 18101 号数据，想要接收序号为 18102 的字节。所以 FTP 发送的第二次挥手的 ACK 序号为 18102。

（3）H 收到确认序号为 2101 的确认段时，H 的拥塞窗口调整为 3MSS。H 收到确认序号为 7101 的确认段时，H 的拥塞窗口调整为 5MSS。主机 H 发送数据的第一个字节为 101，MSS 为 1000B，代表每次可以发送的报文大小为 1000B。第一个报文段的序号为 101～1100，第二个报文段的序号为 1101～2100，以此类推。慢开始的门限值为 4MSS，在执行慢开始算法的时候，发送方每收到一个对新报文的确认 ACK，拥塞窗口值加 1。在本题中，接收到确认号为 2101，代表也接收到了确认号 1101，所以接收到了两个报文段的 ACK，这时候的窗口值因为还没有超过 4MSS，所以 H 的拥塞窗口值的大小为 3MSS。7101 代表的是对第 7 个报文段的确认，发送第一个报文段（101～1100），接收到第一个报文的确认，拥塞窗口调整为 2MSS，发送 2、3 报文段，接收到 2、3 报文段的确认，拥塞窗口调整为 4MSS，发送 4、5、6、7 报文段，并且接收到 4、5、6、7 报文段的确认，因为拥塞窗口值已经到达门限值 4MSS，采用拥塞避免，调整拥塞窗口值为 5MSS。

（4）H 从请求建立数据连接开始，到确认 F 已被服务器全部接收为止，至少需要 $6\mathrm{RTT}=60\mathrm{ms}$。在这期间应用层数据的平均发送速率为 $18000\mathrm{B}/60\mathrm{ms}=2.4\mathrm{Mbps}$。第 1 个 RTT：建立 TCP 连接。第 2 个 RTT 发送报文段 1，第 3 个 RTT 发送报文段 2～3，第 4 个 RTT 发送报文段 4～7，第 5 个 RTT 发送报文段 8～12，第六个 RTT 发送报文段 13～18。18 个报文段刚好为 18000B，所以传输文件 F 需要 6 个 RTT，平均传输速率为 $18000\mathrm{B}/60\mathrm{ms}=2.4\mathrm{Mbps}$。
