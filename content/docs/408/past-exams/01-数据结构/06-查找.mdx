<Question id="408-ada0b4-001" type="single">

【2010】已知一个长度为16 的顺序表L, 其元素按关键字有序排列。若采用折半查找法查找一个L 中不存在的元素，则关键字的比较次数最多的是（ ）。

<Option>4</Option>
<Option correct>5</Option>
<Option>6</Option>
<Option>7</Option>

<Solution>

**【解析】** 本题考查的是折半查找的比较次数。对于一个长度为 16 的顺序表，折半查找判定树高度为 $h=\lfloor\log_2 n\rfloor+1=5$，当查找的元素在折半查找判定树的最底层时，比较次数最多，需 5 次。故选 B。

**【点评】** 常规题。考查折半查找过程。

</Solution>

<Question id="408-ada0b4-003" type="single">

【2016】在有 $n(n>1000)$ 个元素的升序数组 A 中查找关键字 $x$。查找算法的伪代码如下所示:

```c
k = 0;
while (k < n and A[k] < x) k = k + 3;
if (k < n and A[k] == x) 查找成功;
else if (k - 1 < n and A[k - 1] == x) 查找成功;
else if (k - 2 < n and A[k - 2] == x) 查找成功;
else 查找失败;
```

本算法与折半查找算法相比, 有可能具有更少比较次数的情形是（ ）。

<Option>当x 不在数组中</Option>
<Option correct>当x 接近数组开头处</Option>
<Option>当x 接近数组结尾处</Option>
<Option>当x 位于数组中间位置</Option>

<Solution>

**【解析】** 本题的查找算法是在数组中从头开始往后查找，每三个为一组，当需要查找的关键字在数组中靠近开头的位置时，需要比较次数较少。而对于折半查找，在数组中靠近开头的位置时，要比较次数较多，具体所需的比较次数取决于元素所在折半查找判定树的层数。故选 B。

**【点评】** 常规题。本题出的有一定新意，需要理解题目给出的代码，并熟悉折半查找算法过程。

</Solution>

</Question>

<Question id="408-ada0b4-004" type="essay">

【2017】以下二叉树中, 可能成为折半查找判定树(不含外部结点) 的是（ ）。

![](/img/questions/408/data-structure-p062-01.svg)

<Solution>

**【解析】** 对于一个给定的有序查找表，其对应的折半查找判定树是唯一的。根据折半查找算法具体实现时，中间位置 mid 的取值，分为如下两种情况（这两种情况不可能同时存在）：

（1）若 $\mathrm{mid}=\lfloor(\mathrm{low}+\mathrm{high})/2\rfloor$（向下取整）。① 如果初始时查找表中的元素为 $2n+1$（奇数）个，那么树根的左右子树各有 $n$ 个结点；② 如果初始时查找表中的元素为 $2n$（偶数）个，那么树根的左子树中的结点个数为 $n-1$ 个，右子树中的结点个数为 $n$ 个。对于每一棵子树来说也是同样的情况。对于每一棵子树，其左子树的结点个数要么和右子树的结点个数一样，要么左子树中的结点个数比右子树中的结点个数少一个。

（2）若 $\mathrm{mid}=\lceil(\mathrm{low}+\mathrm{high})/2\rceil$（向上取整）。则对于树中每一个子树来说，其左子树中的结点个数要么和右子树中的结点个数一致，要么左子树中的结点比右子树中的结点多一个。

选项 A 有可能：因为树中每一棵子树其左子树都和其右子树中结点个数一致或者多一个。选项 B 不可能：以第 3 层中第 2 个（命名为子树 $a$）和第 3 个（命名为子树 $b$）结点为根的子树，子树 $a$ 中左子树比右子树多一个结点，子树 $b$ 中右子树比左子树多一个结点，这是不可能的。选项 C 和选项 B 的所错的地方一样，也还有其他矛盾的地方。选项 D 不可能：树根的左子树比右子树少一个结点。但以第 2 层第一个结点为根的子树，其左子树比右子树多一个结点，不一致。

**【点评】** 常规题。这题考的很细致，主要考查折半查找中间位置 mid 的取值。可以看出命题人出此题时颇费心思，考生初次遇到可能不知道如何下手。

</Solution>

</Question>

<Question id="408-ada0b4-005" type="single">

【2023】对含有600 个元素的有序顺序表进行折半查找, 关键字间的比较次数最多是（ ）。

<Option>9</Option>
<Option correct>10</Option>
<Option>30</Option>
<Option>300</Option>

<Solution>

**【解析】** 对含有 600 个元素的有序表进行折半查找，当要查找的目标元素不在表中时，其关键字比较次数最多。在这种情况下，折半查找会进行到最后一步，直到左边界和右边界相遇。在进行折半查找时，每次比较会将查找范围缩小一半，直到找到目标元素或确定目标元素不在表中。关键字比较次数最多不超过查找判定树的高度。对于 600 个元素的有序表，因为 $\lceil\log_2 600\rceil=10$，需要 10 次查找。故选 B。

**【点评】** 常规题。教材教辅中都有类似结论，在 2010 年 408 第 9 题中也有类似考查。

</Solution>

</Question>

<Question id="408-ada0b4-007" type="essay">

【2013】设包含4 个数据元素的集合 S = `{"do","for","repeat","while"}`，各元素的查找概率依次为:p1 = 0.35,p2 = 0.15,p3 = 0.15,p4 = 0.35。将S 保存在一个长度为4 的顺序表中，采用折半查找法,查找成功时的平均查找长度为2.2。请回答下列问题:
(1) 若采用顺序存储结构保存S, 且要求平均查找长度更短，则元素应如何排列？应使用何种查找方法? 查找成功时的平均查找长度是多少?
(2) 若采用链式存储结构保存S, 且要求平均查找长度更短，则元素应如何排列？应使用何种查找方法? 查找成功时的平均查找长度是多少?

<Solution>

**【解析】** 本题题意较难理解。首先分析题目条件：在顺序表中，采用折半查找，平均查找长度为 2.2，是怎么计算出来的，这有助于理解题意。通常字符串是按照字典序（26 个英文字母排列顺序）比较大小：从左到右逐字符比较 ASCII 编码值，首个不同字符决定整体大小；前缀完全相同时，短串更小。4 个数组元素 "do", "for", "repeat", "while" 的首字母分别为 'd'、'f'、'r'、'w'。按照字典序 `'d' < 'f' < 'r' < 'w'`，则 `"do" < "for" < "repeat" < "while"`。

折半查找只适用于有序的顺序表。采用折半查找的集合 $S$ 存储示意图如下。

| 查找概率 | 0.35 | 0.15 | 0.15 | 0.35 |
| --- | --- | --- | --- | --- |
| 数据元素 | do | for | repeat | while |
| 数组下标 | 0 | 1 | 2 | 3 |

折半查找过程如下：① 设置两个变量 left、high 分别指向数组开头和末尾，初始时：left = 0，high = 3。变量 mid 表示当前待比较元素。折半查找向上取整和向下取整均可，这里采用向下取整。② 第一次查找比较时，$\mathrm{mid}=\lfloor\frac{\mathrm{left}+\mathrm{high}}2\rfloor=\lfloor\frac{0+3}2\rfloor=1$。③ 第二次查找比较时，$\mathrm{mid}=\lfloor\frac{0+0}2\rfloor=0$ 或 $\mathrm{mid}=\lfloor\frac{2+3}2\rfloor=2$。④ 第三次查找比较时，$\mathrm{mid}=\lfloor\frac{3+3}2\rfloor=3$。折半查找判定树如下图所示。

![折半查找判定树](/img/2013-a42-1.svg)

{/* 原图 while 与 repeat 的结点标注互换，以下比较次数与计算式也存在对应关系问题，保留原文。 */}

如上图所示，采用折半查找，查找元素 "do", "for", "repeat", "while" 的比较分别为 2、1、3、2，平均查找长度 $\mathrm{ASL}=0.35\times2+0.15\times1+0.15\times2+0.35\times3=2.2$。再解答本题提出的问题：

(1) ① 采用顺序存储结构（顺序表），数据元素按其查找概率降序排列，如下图所示。

| 查找概率 | 0.35 | 0.35 | 0.15 | 0.15 |
| --- | --- | --- | --- | --- |
| 数据元素 | do | while | for | repeat |

② 采用顺序查找方法。

③ 查找成功时的平均查找长度 $=0.35\times1+0.35\times2+0.15\times3+0.15\times4=2.1$。

(2) **【答案一】**

① 采用链式存储结构，数据元素按其查找概率降序排列，构成单链表。

![单链表](/img/2013-a42-2.svg)

② 采用顺序查找方法。

③ 查找成功时的平均查找长度 $=0.35\times1+0.35\times2+0.15\times3+0.15\times4=2.1$。

**【答案二】**

① 采用二叉链表存储结构，构造二叉排序树，元素存储方式见下图。

![二叉排序树1和二叉排序树2](/img/2013-a42-3.svg)

② 采用二叉排序树的查找方法。

③ 查找成功时的平均查找长度 $=0.15\times1+0.35\times2+0.35\times2+0.15\times3=2.0$。

**【拓展】** ① 最优二叉排序树的定义：给定一组关键字，以及关键字对应的查找概率。用这组关键字构造的所有合法的二叉排序树中，平均查找长度最小的树，称为最优二叉排序树。其核心目标是：最小化平均查找长度，查找概率高的结点优先靠近根结点。② 最优二叉排序树和平衡二叉树、哈夫曼树对比：

- 平衡二叉树只看树的形态均衡，不考虑查找概率；
- 哈夫曼树是最优前缀码，不要求满足二叉排序树规则。

**【提示】** ★ 在官方给出的参考答案中，第 (2) 问给出了一种“采用二叉链表存储结构，构造二叉排序树”且 ASL = 2.0 的解法。关于这个二叉排序树是如何构造出来的？可能考生看到这个答案都会产生疑问，网上所有讲解这道题的博主，以及同类辅导书中，都没讲清楚，都是对着答案去“牵强”解释。其实，这是典型的“最优二叉排序树”问题。常见教材教辅中确实没介绍“最优二叉排序树”这部分内容，但很难说这部分内容属于 408 中的超纲内容：“最优二叉排序树”是一种特殊的二叉排序树，408 考纲中明确写了考查二叉排序树。

**【点评】** 难题。① 这道题的迷惑点在于：首先，题意不是很好理解，读题可能迷迷糊糊的没有思路。而且两问的最终答案看起来一样，进一步增加了迷惑性。整个题做起来给人一种“怪怪的”感觉，很难评价此题的好坏。② 另外，关于考生是否需要掌握“最优二叉排序树”？从第 (2) 问官方给出 ASL = 2.1 和 ASL = 2.0 两种答案，这 2 种答案都能得满分。从这点来推测，官方应该是不要求考生掌握“最优二叉排序树”，不然，ASL = 2.1 的解法直接判得 0 分，只有 ASL = 2.0 的解法才能得满分。所以，这题又引出了另外一个矛盾点：题目让求“平均查找长度更短”的解法，最优二叉排序树、ASL = 2.0 的解法是最短的，为什么 ASL = 2.1 的解法能得满分，这不是矛盾吗？这个题出的“欠妥当、考虑不周”。

</Solution>

</Question>

**【解析】**

(2) C++ 算法描述如下：

```cpp
// 中序遍历二叉树（中序遍历的标准模板）
void InOrder(SqBiTree tree,int InorderAns[],int &length,int root){
    if(-1 == tree.SqBiTNode[root]) return true; //遇到空树则返回true
    InOrder(tree, InorderAns, length, 2 * root + 1);
    InorderAns[length++] = tree.SqBiTNode[root];
    InOrder(tree, InorderAns, length, 2 * root + 2);
}

bool Jugdment(SqBiTree tree){ //验证是否为二叉搜索树
    //定义数组InorderAns存储中序遍历二叉树的结果；MAX_SIZE为题目中已定义的常量
    int InorderAns[MAX_SIZE], length = 0;
    InOrder(tree, InorderAns, length, 0); //根结点的数组下标为0
    for(int i = 0; i < length - 1; i++){
        //若下一个结点的值小于或等于当前结点，则不满足升序序列要求，返回false
        if(InorderAns[i + 1] <= InorderAns[i])
            return false;
    }
    return true; //程序顺利执行到这一步，说明是升序序列，则返回true
}
```

（2）① 关键字 14 的初始散列地址 $H_0=(14\times3)\%11=9$，散列地址 9 存储的关键字为 3，14 和 3 不相等，继续探查；② 再次探查的散列地址 $H_1=(9+1^2)\%11=10$，散列地址 10 存储的关键字为 18，14 和 18 不相等，继续探查；③ 再次探查的散列地址 $H_2=(9+2^2)\%11=2$，散列地址 2 存储的关键字为 14，相等，查找结束。故查找关键字 14 的关键字比较序列为：3，18，14。

（3）在散列表中查找关键字，当遍历到一个空位置时，认为查找失败。关键字 8 的初始散列地址 $H_0=(8\times3)\%11=2$，散列地址 2 不为空，继续探查；$H_1=(2+1^2)\%11=3$，散列地址 3 不为空，继续探查；$H_2=(2+2^2)\%11=6$，散列地址 6 不为空，继续探查；$H_3=(2+3^2)\%11=0$，散列地址 0 不为空，继续探查；$H_4=(2+4^2)\%11=7$，散列地址 7 为空，查找失败。

【2015】已知字符串s 为“abaabaabacacaabaabcc”, 模式串t 为“abaabc”。采用KMP算法进行匹配, 第一次出现“失配” (s[i] ≠t[ j]) 时, i = j = 5，则下次开始匹配时, i 和j 的值是（ ）。

<Option>i = 1,j = 0</Option>
<Option>i = 5,j = 0</Option>
<Option correct>i = 5,j = 2</Option>
<Option>i = 6,j = 2</Option>

<Solution>

**【解析】** 失配后，下一次匹配时，$j=next[j]$，$i$ 不变。即求 $next[5]$ 的值。对于模式串“abaabc”来说，即求“abaab”这个字符串最长相同前缀和后缀的长度。而最长公共子串为“ab”，即 $next[5]=2$，故 $i=5,j=2$。故选 C。

**【点评】** 常规题。考查 KMP 算法。KMP 算法是 408 中的高频考点，经常考选择题。

</Solution>
