## 二、DNS：域名解析的本质是逐级寻找答案

### 2.1 必须真正理解DNS的工作原理

DNS采用分布式、层次化的结构，最常见的功能是将域名解析为IP地址。

假设要访问 `www.abc.xyz.com`，按照题库采用的完整逐级委派模型，查询过程中涉及：

| 域名服务器                 | 主要作用                   |
| --------------------- | ---------------------- |
| 根域名服务器                | 告诉你去哪里查询 `.com`        |
| 顶级域名服务器               | 告诉你去哪里查询 `xyz.com`     |
| `xyz.com` 权限域名服务器     | 告诉你去哪里查询 `abc.xyz.com` |
| `abc.xyz.com` 权限域名服务器 | 返回目标域名的解析结果            |

注意，根域名服务器并不保存互联网中所有主机的IP地址。

**DNS的核心思想不是让某台服务器知道所有答案，而是让它知道应该去哪里寻找答案。**

### 2.2 递归查询与迭代查询

这是DNS最重要的选择题考点。

<Tabs items={['递归查询', '迭代查询']}>

<Tab value="递归查询">

```text
主机
  ↓
本地域名服务器
  ↓
根域名服务器
  ↓
顶级域名服务器
  ↓
权限域名服务器
```

查询结果沿原路径逐级返回。

请求者只需发出一次请求，后续查询由接收请求的服务器负责完成。

</Tab>

<Tab value="迭代查询">

```text
主机 → 本地域名服务器

本地域名服务器 ←→ 根域名服务器
本地域名服务器 ←→ 顶级域名服务器
本地域名服务器 ←→ 权限域名服务器

主机 ← 本地域名服务器
```

本地域名服务器不断根据上一次查询得到的信息，亲自寻找下一台服务器。

</Tab>

</Tabs>

| 比较项目         | 递归查询     | 迭代查询        |
| ------------ | -------- | ----------- |
| 找不到答案时       | 替请求者继续查  | 告诉请求者下一步去哪查 |
| 同一请求者发出的查询次数 | 通常一次     | 可能多次        |
| 后续查询的承担者     | 接收请求的服务器 | 原请求者        |
| 记忆方法         | 委托别人     | 自己跑腿        |

408常见的实际组合是：主机向本地域名服务器进行递归查询，本地域名服务器向其他域名服务器进行迭代查询。

A. 1，3

B. 0，3

C. 0，4

D. 1，4

**答案：C。**

</Accordion>

</Accordions>

### 确定计数对象

题目问的是本地域名服务器发出的查询，而不是主机发出的查询，也不是整个网络中的查询总数。

这是最容易被忽略的条件。

本地域名服务器可能已经缓存了该域名对应的IP地址。

$$

$$

| 第1次  | 根域名服务器        |
| 第2次  | `.com`        |
| 第3次  | `xyz.com`     |
| 第4次  | `abc.xyz.com` |

因此：

$$
N_{\max}=4
$$

注意，`www` 是目标主机名，不需要额外向所谓的 `www` 域名服务器查询。

</Step>

### 2.4 DNS必须记住的其他知识点

结合王道·卷三模拟题第2题，可以归纳出以下易错点。

| 常见说法               | 正误 | 原因            |
| ------------------ | -- | ------------- |
| DNS只能使用UDP         | 错  | 也可以使用TCP      |
| DNS默认服务端口为53       | 对  | TCP和UDP均可使用53 |
| DNS缓存可以减少网络中的查询报文  | 对  | 不必重复逐级查询      |
| DNS瘫痪后，即使知道IP也不能通信 | 错  | IP转发不依赖DNS    |
| 每次访问网站都必须进行DNS查询   | 错  | 可能已有缓存        |
| 根域名服务器保存所有域名的IP地址  | 错  | 采用分布式管理       |

其中最重要的是区分三个地址转换过程：

| 协议   | 解决的问题                |
| ---- | -------------------- |
| DNS  | 域名 → IP地址            |
| ARP  | 本链路下一跳IPv4地址 → MAC地址 |
| DHCP | 自动获得IP地址等网络配置        |

这三个协议经常出现在跨章节综合选择题中。

## 三、HTTP：本章最值得深入掌握的考点

HTTP的重点并不只是端口号，而是**对象、连接、请求、状态**这四个概念之间的关系。

### 3.1 一个网页不等于一个HTTP对象

例如，一个HTML网页引用了4张图片。

实际需要获取的对象有：

$$
N=1+4=5
$$

其中包括1个HTML文件和4个图片文件。

浏览器通常需要先获取HTML文件，解析其中的引用，才知道还需要请求哪些图片。

因此，不要把浏览一个网页理解为只发送一次HTTP请求。

这是HTTP时延计算的基础。

### 3.2 三种HTTP连接方式

假设一个网页包含1个HTML文件和 $n$ 个小图片文件，所有对象来自同一服务器，忽略发送时延、拥塞窗口限制和DNS查询时间，开始时没有建立TCP连接。

<Tabs items={['非持续串行', '持续非流水线', '持续流水线']}>

<Tab value="非持续串行">

每个对象都需要独立建立TCP连接。

每次获取对象需要：

$$
1\mathrm{RTT}\text{（建立连接）} +1\mathrm{RTT}\text{（请求与响应）}
$$

因此：

$$
\boxed{T=2(n+1)\mathrm{RTT}}
$$

</Tab>

<Tab value="持续非流水线">

所有对象复用同一条TCP连接，但是必须等待上一个对象返回之后，才能请求下一个对象。

$$
\boxed{T=(n+2)\mathrm{RTT}}
$$

其中1个RTT用于建立连接，剩余 $n+1$ 个RTT用于请求各对象。

</Tab>

<Tab value="持续流水线">

获得HTML文件之后，可以连续发送多个图片请求，不必等待前一个图片返回。

在理想条件下：

$$
\boxed{T=3\mathrm{RTT}}
$$

前提是至少存在一个引用对象，且所有后续对象可以在一个理想请求—响应轮次内传完。

</Tab>

</Tabs>

#### 三种方式的直观对比

假设网页引用4张小图片。

```text
非持续、非并行：

握手 HTML 握手 图1 握手 图2 握手 图3 握手 图4
 |    |    |    |    |    |    |    |    |    |
                  10 RTT

持续、非流水线：

握手 HTML 图1 图2 图3 图4
 |    |    |   |   |   |
          6 RTT

持续、流水线：

握手 HTML 图1、图2、图3、图4
 |    |           |
          3 RTT
```

| 连接方式    | TCP连接数    | 理想总时间                    |
| ------- | --------- | ------------------------ |
| 非持续、串行  | $n+1$ | $2(n+1)\mathrm{RTT}$ |
| 持续、非流水线 | 1         | $(n+2)\mathrm{RTT}$  |
| 持续、流水线  | 1         | $3\mathrm{RTT}$      |

<Callout type="info" title="连接与流水线">

**持续连接节省的是TCP握手时间，流水线方式节省的是逐个等待响应的时间。**

</Callout>

两者不是同一个概念。

### 3.3 代表题：2024年408真题

**来源：真题第15题。**

浏览器不支持并行TCP连接，使用非持久的HTTP/1.0协议访问一个网页，该网页引用同一网站上的7个小图像文件。

从请求建立TCP连接到接收全部内容，至少需要多少个RTT？

A. 4

B. 9

C. 14

D. 16

<Accordions>

<Accordion title="参考答案">

**答案：D。**

</Accordion>

</Accordions>

题目中的两个关键词决定了计算方法：

- 非持久：每个对象单独建立TCP连接。
- 不支持并行：各个连接的时间依次累加。

总对象数：

$$
N=1+7=8
$$

因此：

$$
T=2N\mathrm{RTT}
$$

$$
\boxed{T=16\mathrm{RTT}}
$$

#### 同一题目稍微修改条件

| 修改后的条件          | 所需时间   |
| --------------- | ------ |
| 非持续、不支持并行       | 16 RTT |
| 持续、非流水线         | 9 RTT  |
| 持续、流水线          | 3 RTT  |
| 非持续、7张图片可完全并行请求 | 4 RTT  |

最后一种情况下，先花2 RTT获取HTML，再花2 RTT并行获取全部图片。

题库中竞成·模拟三第8题，考查的正是持续、非流水线方式：1个HTML文件加4张图片，答案为6 RTT。

### 3.4 进阶：HTTP结合TCP拥塞窗口

**来源：2022年408真题，第14题。**

本题综合考查HTTP与TCP拥塞窗口。

题目条件为：

- HTTP/1.1。
- HTML文件大小为1 MSS。
- 网页引用1张大小为3 MSS的图片。
- RTT为10 ms。
- 已经完成DNS解析。
- 忽略TCP段传输时延。

从请求建立TCP连接到获得全部内容，至少需要多长时间？

题库答案：40 ms。

#### 为什么不是30 ms？

如果只考虑HTTP请求次数，很容易得到：

$$
T=1\mathrm{RTT}+1\mathrm{RTT}+1\mathrm{RTT}
$$

但题库的标准解析还考虑了TCP慢开始机制，采用初始拥塞窗口为1 MSS的传统考试模型。

| 时间轮次   | 拥塞窗口  | 实际过程         |
| ------ | ----- | ------------ |
| 第1 RTT | —     | TCP建立连接      |
| 第2 RTT | 1 MSS | 获得HTML文件     |
| 第3 RTT | 2 MSS | 获得图片的前2 MSS  |
| 第4 RTT | 4 MSS | 获得图片剩余的1 MSS |

因此：

$$
T=4\mathrm{RTT}
$$

$$
\boxed{T=40\mathrm{ms}}
$$

这里图片只需要发送一次HTTP请求，后续接收剩余数据只需要TCP层的确认和继续传输，不需要再次发送HTTP图片请求。

#### 这道题最值得学习的思想

**HTTP决定要请求什么对象，TCP决定这些对象的数据能以多快的速度传完。**

只要题目出现以下条件，就应该考虑是否需要结合第5章传输层的知识：

- MSS、拥塞窗口、慢开始。
- 接收窗口、发送窗口。
- 文件大小超过一次允许发送的数据量。

HTTP的简化时延公式并非在所有情况下都适用。

需要注意，2022年这道题的题干没有明确写出初始拥塞窗口为1 MSS，但题库解析采用了这一假设。40 ms是按该传统考试模型得出的结果，不能推广为任意实际TCP实现的必然结论。

## 四、DNS与HTTP综合计算：掌握统一时间线

### 4.1 代表题：2020年408真题

**来源：真题第4题。**

主机访问：

```text
http://www.abc.com/index.html
```

本地域名服务器向其他域名服务器进行迭代查询。局域网内主机访问Internet上各服务器的RTT均为10 ms，忽略其他时延。

求获得纯文本网页的最短时间和最长时间。

A. 10 ms，40 ms

B. 10 ms，50 ms

C. 20 ms，40 ms

D. 20 ms，50 ms

**答案：D。**

#### 最短时间

假设已经缓存域名对应的IP地址，不需要对外进行DNS查询。

| 操作        | 时间    |
| --------- | ----- |
| 建立TCP连接   | 10 ms |
| HTTP请求与响应 | 10 ms |

$$
T_{\min}=2\times10=20\mathrm{ms}
$$

#### 最长时间

假设没有可用缓存，需要完整进行域名解析。

| 操作                   | 时间    |
| -------------------- | ----- |
| 查询根域名服务器             | 10 ms |
| 查询 `.com` 顶级域名服务器    | 10 ms |
| 查询 `abc.com` 权限域名服务器 | 10 ms |
| 建立TCP连接              | 10 ms |
| HTTP请求与响应            | 10 ms |

$$
T_{\max}=5\times10=50\mathrm{ms}
$$

#### 提炼出的通用公式

在题目采用顺序访问、传统HTTP/TCP模型时，可以将时间拆解为：

$$
\boxed{ T_{\text{总}} = T_{\text{DNS}} + T_{\text{TCP连接}} + T_{\text{HTTP交互}} + T_{\text{额外传输}} }
$$

其中额外传输时间可能来自文件发送时延、TCP窗口限制等。

面对综合时延题，不要急着寻找一个公式直接代入，而是先写出完整的通信过程，再给每个阶段分配时间。

## 五、HTTP报文：理解每一行的真实含义

### 5.1 代表题：2015年408真题

**来源：真题第12题。**

浏览器发送以下HTTP请求：

```text
GET /index.html HTTP/1.1
Host: www.test.edu.cn
Connection: Close
Cookie: 123456
```

判断错误的说法。

A. 浏览器请求浏览 index.html

B. index.html位于www\.test.edu.cn上

C. 浏览器请求使用持续连接

D. 浏览器曾经浏览过该网站

<Accordions>

<Accordion title="参考答案">

**答案：C。**

</Accordion>

</Accordions>

这道题的陷阱在于HTTP/1.1默认使用持续连接，但报文中已经明确指定了 `Connection: Close`。

<Callout type="warn" title="HTTP默认行为">

**显式指定的条件优先于协议的默认行为。**

</Callout>

### 5.2 必须认识的HTTP报文字段

| 字段                       | 含义               |
| ------------------------ | ---------------- |
| `GET`                    | 请求获取指定资源         |
| `POST`                   | 向服务器提交数据，由服务器处理  |
| `Host`                   | 请求访问的目标主机及可选端口   |
| `Connection: keep-alive` | 希望保持连接           |
| `Connection: close`      | 响应完成后关闭连接        |
| `Cookie`                 | 向服务器携带保存的状态标识    |
| `Set-Cookie`             | 服务器指示浏览器保存Cookie |
| `HTTP/1.1`               | HTTP协议版本         |

特别注意：

`Host`不是客户端的主机名，而是目标服务器对应的网站名称。

POST也不是一定创建新资源，它的本质是提交数据供服务器处理。

### 5.3 无状态、无连接、持续连接的区别

这是模拟题中集中考查的一组易混概念。

| 概念       | 真正含义                |
| -------- | ------------------- |
| HTTP无状态  | 协议本身不自动维护跨请求的用户业务状态 |
| TCP面向连接  | 传输数据之前需要建立传输层连接     |
| HTTP持续连接 | 多个HTTP请求与响应复用同一底层连接 |
| Cookie   | 为应用提供跨请求的状态跟踪能力     |

例如，用户登录网站后继续访问购物车，服务器仍可识别用户身份。这不意味着HTTP本身变成了有状态协议，而是应用利用Cookie、Session或其他机制实现了状态管理。

同样，一条TCP连接持续存在，也不代表HTTP自动维护登录身份。

<Callout type="warn" title="状态与连接">

**状态是业务层面的问题，连接是通信层面的问题。**

</Callout>

#### 对应模拟题

竞成·模拟二第7题考查：

- HTTP是无状态协议。
- HTTP服务端默认端口80。
- HTTP/1.1默认持续连接。
- Host表示目标服务器。

竞成·模拟四第9题将GET改为POST，将Close改为keep-alive，再结合Cookie考查报文含义。

两道模拟题和2015年真题，本质上都是在考查HTTP报文语义及不同协议层次的职责。

补充一个考试用语的边界：部分教材称HTTP本身无连接，强调的是HTTP不负责建立传输层连接。不要由此推断HTTP/1.1不使用TCP连接，更不要将无连接和无状态视为同一个概念。

## 六、FTP：抓住双连接与端口所属方

### 6.1 FTP为什么需要两条连接？

FTP需要传输两种不同的信息：

一种是登录、上传、下载、切换目录等命令；另一种是真正的文件内容或目录列表。

FTP将它们放在两条独立的TCP连接中。

| 对比项目   | 控制连接   | 数据连接      |
| ------ | ------ | --------- |
| 传输内容   | 命令和响应  | 文件数据、目录列表 |
| 传输层协议  | TCP    | TCP       |
| 持续时间   | 整个会话期间 | 通常一次传输期间  |
| 服务器端口  | 21     | 主动模式通常为20 |
| 是否反复建立 | 通常不需要  | 通常需要      |

控制连接和数据连接分开，也称为带外控制。

### 6.2 主动模式和被动模式

<Tabs items={['主动模式', '被动模式']}>

<Tab value="主动模式">

```text
控制连接：

客户端临时端口 ───→ 服务器21端口

数据连接：

客户端协商端口 ←─── 服务器20端口
```

数据连接由服务器主动发起。

</Tab>

<Tab value="被动模式">

```text
控制连接：

客户端临时端口 ───→ 服务器21端口

数据连接：

客户端临时端口 ───→ 服务器协商端口
```

数据连接由客户端主动发起。

注意，主动和被动描述的是**数据连接的建立方式**，不是文件上传还是下载。

</Tab>

</Tabs>

### 6.3 代表题：2017年408真题

**来源：真题第6题。**

下列有关FTP的说法，错误的是哪一项？

A. 数据连接在每次数据传输结束后关闭

B. 控制连接在整个会话期间保持打开

C. 服务器与客户端的TCP 20端口建立数据连接

D. 客户端与服务器的TCP 21端口建立控制连接

<Accordions>

<Accordion title="参考答案">

**答案：C。**

</Accordion>

</Accordions>

这个选项非常有迷惑性，因为20确实是FTP常考端口，但是它属于经典主动模式下的服务器端，而不是客户端。

本题重点考查**这两个端口属于通信的哪一方**。

### 6.4 FTP常见陷阱

| 常见说法               | 正误 |
| ------------------ | -- |
| FTP使用UDP传输控制信息     | 错  |
| FTP控制连接与数据连接都是TCP  | 对  |
| FTP只能传输文本文件        | 错  |
| FTP支持ASCII和二进制传输模式 | 对  |
| FTP控制连接每传完一个文件就关闭  | 错  |
| FTP数据连接始终由服务器主动建立  | 错  |
| FTP数据连接始终使用20端口    | 错  |

## 七、电子邮件：不要死记协议，要理解通信方向

电子邮件题的核心是判断通信双方的身份及操作发起者。

### 7.1 一封邮件的完整传输过程

```text
发送方用户代理
      │
      │ SMTP
      ↓
发送方邮件服务器
      │
      │ SMTP
      ↓
接收方邮件服务器
      │
      │ POP3 / IMAP
      ↓
接收方用户代理
```

这里有一个特别重要的细节：

虽然最终邮件数据是从接收方邮件服务器流向接收方用户代理，但POP3连接和取信请求是由接收方用户代理主动发起的。

因此SMTP属于推送式邮件传输，POP3属于拉取式邮件访问。

| 协议   | 用途          | 传统服务端口  | 传输层       |
| ---- | ----------- | ------- | --------- |
| SMTP | 发送、中继邮件     | 25      | TCP       |
| POP3 | 下载、读取邮件     | 110     | TCP       |
| IMAP | 远程管理、同步邮件   | 143     | TCP       |
| MIME | 扩展邮件内容的表示形式 | 无独立传输端口 | 不独立建立传输连接 |

### 7.2 代表题：2013年408真题

**来源：真题第8题。**

关于SMTP协议，下列哪些说法正确？

I. 只支持传输7位ASCII码内容。

II. 支持邮件服务器之间发送邮件。

III. 支持用户代理向邮件服务器发送邮件。

IV. 支持邮件服务器向用户代理发送邮件。

答案为I、II、III，即A。

#### 为什么IV错误？

SMTP负责邮件发送与中继，而用户从自己的邮箱服务器取邮件，传统上使用POP3或IMAP。

#### 为什么I正确？

传统SMTP只能直接传输7位ASCII文本。

如果需要发送中文、图片、视频或者二进制文件，就需要利用MIME等机制编码转换。

2018年408真题第10题正是对这一知识点的直接考查：JPEG、MPEG、EXE、ASCII文本中，只有ASCII文本能够无须转换直接由传统SMTP传输。

现代SMTP存在8BITMIME等扩展能力，但408这两道原题按照基础SMTP模型作答。

### 7.3 POP3和IMAP的区别

| 比较项目   | POP3        | IMAP      |
| ------ | ----------- | --------- |
| 主要思想   | 下载邮件到本地     | 远程访问服务器邮件 |
| 邮件副本   | 可下载后删除，也可保留 | 通常保留在服务器  |
| 多设备同步  | 能力相对有限      | 支持        |
| 远程管理邮件 | 能力相对有限      | 支持        |
| 传输层协议  | TCP         | TCP       |

2015年408真题第9题问POP3使用什么类型的传输层服务。

因为POP3基于TCP，所以答案是面向连接、可靠的数据传输服务。

如果是通过浏览器使用网页版邮箱，浏览器与Web服务器之间还可以使用HTTP或HTTPS。不要简单认为只要涉及邮件，所有通信阶段就一定使用SMTP。

## 八、C/S与P2P：理解资源供给方式

### 8.1 两种网络应用模型

```text
C/S模型：

客户端A ──┐
客户端B ──┼── 服务器
客户端C ──┘

P2P模型：

节点A ←──→ 节点B
  ↕          ↕
节点C ←──→ 节点D
```

| 比较项目    | C/S         | P2P          |
| ------- | ----------- | ------------ |
| 节点角色    | 客户端和服务器相对固定 | 可以同时是客户端和服务器 |
| 通信方式    | 典型业务通过服务器提供 | 对等节点可以直接通信   |
| 资源提供者   | 主要是服务器      | 多个对等节点       |
| 扩展能力    | 可能受服务器能力限制  | 可聚合各节点资源     |
| 管理方式    | 相对集中        | 相对分散         |
| 安全性和稳定性 | 不具有绝对优势     | 也不具有绝对优势     |

### 8.2 代表题：2019年408真题

**来源：真题第1题。**

下列说法错误的是：

A. P2P模型中的结点具有对等关系。

B. C/S模型中，客户与客户之间可以直接通信。

C. C/S模型中，主动发起通信的是客户。

D. 向多用户分发文件时，P2P通常比C/S所需时间短。

<Accordions>

<Accordion title="参考答案">

**答案：B。**

</Accordion>

</Accordions>

按照408的典型C/S应用模型，客户之间的业务通信通过服务器进行协调或转发。

当然，这并不意味着现实中的两台客户端主机在网络层面永远不能建立其他直接连接。题目判断的是应用模型本身。

### 8.3 P2P为什么适合文件分发？

假设一个大小为 $F$ 的文件，需要发送给 $N$ 个用户，服务器上传速率为 $u_s$。

在传统C/S模型中，服务器至少需要提供 $N$ 份文件的数据：

$$
T_{\mathrm{C/S}}\geq\frac{NF}{u_s}
$$

而在P2P模型中，某个节点下载到一部分文件之后，可以继续向其他节点上传。

因此，参与者不仅消耗资源，也贡献资源。

这才是P2P扩展能力强的本质，而不是因为P2P一定更安全或者一定更稳定。

竞成·模拟七第1题就是利用“P2P比C/S更加安全和稳定”这一错误说法设置陷阱。

## 九、跨章节综合题：从开机到访问网页

2014年408真题第11题和王道·卷七模拟题第4题，考查了访问网络服务时可能使用哪些协议。

本类题考查跨层协议的协作。

### 9.1 一次典型的网站访问过程

假设计算机连接以太网，采用自动配置方式获取网络参数，目标网站位于其他网络，且相关缓存最初为空。

```text
开机接入网络
      ↓
DHCP获取IP地址、掩码、网关、DNS服务器地址
      ↓
根据目标地址和路由选择下一跳
      ↓
ARP获得所需的下一跳MAC地址
      ↓
DNS解析目标域名
      ↓
根据目标IP选择下一跳（必要时再次ARP）
      ↓
TCP建立连接
      ↓
HTTP发送网页请求
      ↓
服务器返回网页
```

各个协议解决的是不同阶段的问题。

| 协议   | 作用           | 访问网页时是否可能使用 |
| ---- | ------------ | ----------- |
| DHCP | 获取网络配置       | 可能          |
| ARP  | 获取下一跳MAC地址   | 可能          |
| DNS  | 解析域名         | 可能          |
| UDP  | 承载普通DNS查询等   | 可能          |
| TCP  | 提供传统HTTP传输服务 | 是           |
| IP   | 分组寻址与转发      | 是           |
| PPP  | 点对点链路通信、宽带接入 | 可能          |
| ICMP | 差错报告、网络诊断    | 可能，但不必发生    |
| SMTP | 邮件发送         | 普通网页访问不需要   |

### 9.2 代表题：2014年408真题

使用浏览器访问某大学Web网站主页时，不可能使用到的协议是：

A. PPP

B. ARP

C. UDP

D. SMTP

<Accordions>

<Accordion title="参考答案">

**答案：D。**

</Accordion>

</Accordions>

最容易误选的是UDP，因为HTTP使用TCP。

但网页访问可能先通过DNS解析域名，而普通DNS查询通常使用UDP。

所以不能因为HTTP使用TCP，就认为整个访问网页的过程中不会使用UDP。

<Callout type="idea" title="跨章节分析">

**做这种题时，必须考虑整个业务过程，而不是只考虑最终使用的应用层协议。**

</Callout>

另外，王道·卷七模拟题第4题考查从开机到FTP连接建立过程中，哪个协议可能未用到，题库答案为ICMP。它隐含了校园网采用自动配置、正常ARP解析等条件。严格来说，如果使用静态IP配置或者已有ARP映射，DHCP和ARP也并非逻辑上必然使用。

## 十一、本章最重要的选择题解题方法

### 方法一：确定谁在执行操作

很多题目的陷阱是偷换通信主体。

例如DNS查询次数，必须看是主机、本地域名服务器，还是所有域名服务器的总次数。

例如FTP端口，必须看20端口究竟属于客户端还是服务器。

看到协议题，第一反应应该是：**谁向谁发送了什么？**

### 方法二：区分应用层语义与传输层机制

| 应用层          | 传输层           |
| ------------ | ------------- |
| HTTP请求网页     | TCP负责可靠传输     |
| SMTP发送邮件     | TCP负责传送邮件数据   |
| DNS查询域名      | UDP或TCP承载查询报文 |
| Cookie跟踪业务状态 | TCP维护连接状态     |

无状态不等于无连接，发起连接不等于只能发送请求，使用TCP也不等于整个业务过程不会出现UDP。

### 方法三：计算时延先画过程，再数RTT

按照以下顺序检查：

DNS是否已经解析？

TCP是否已经建立连接？

有多少个独立对象？

使用持续连接还是非持续连接？

支持流水线或者并行连接吗？

TCP窗口是否限制发送数据量？

这六个问题判断正确，绝大多数HTTP时延计算题就可以解决。

### 方法四：区分默认、可能与必然

本章有很多选择题利用绝对化的表达制造错误选项。

| 错误表达              | 正确理解             |
| ----------------- | ---------------- |
| DNS只能使用UDP        | 通常使用UDP，也能使用TCP  |
| FTP数据连接一定使用20端口   | 主动模式下通常使用20      |
| HTTP/1.1一定使用持续连接  | 默认持续，但可显式关闭      |
| P2P一定比C/S安全       | 不具有必然性           |
| 访问网站一定进行DNS查询     | 可能存在缓存           |
| HTTP/1.1默认一定启用流水线 | 默认持续连接不等于一定启用流水线 |

理解成立条件，比单纯背诵结论重要得多。
