## 二、核心考点一：网络分层的本质

这是本章真题最重要的考点。

### 1. 七层模型及各层职责

应该理解每一层为什么存在，以及它究竟解决什么问题。

| 层次 | OSI参考模型 | 核心职责         | 关键词          |
| -- | ------- | ------------ | ------------ |
| 7  | 应用层     | 为网络应用提供服务    | HTTP、DNS、FTP |
| 6  | 表示层     | 解决数据表示差异     | 格式转换、压缩、加密   |
| 5  | 会话层     | 管理通信会话       | 对话管理、同步      |
| 4  | 传输层     | 实现进程之间的通信    | 端口、TCP、UDP   |
| 3  | 网络层     | 实现跨网络的主机通信   | IP地址、路由、转发   |
| 2  | 数据链路层   | 实现相邻结点间的数据传输 | MAC地址、帧      |
| 1  | 物理层     | 在物理介质上传输比特   | 电信号、光信号      |

最重要的是理解下面三个层次的区别。

```text
主机A             路由器             主机B
  进程A                               进程B
    │                                   │
    ├────── 传输层：进程到进程 ─────────┤
    │                                   │
    ├────── 网络层：主机到主机 ─────────┤
    │                                   │
    ├─ 数据链路层 ──┤── 数据链路层 ─────┤
         第一跳             第二跳
```

数据链路层解决的是**当前这一跳怎么传**。

网络层解决的是**经过哪些结点才能到达目的主机**。

传输层解决的是**怎样把数据交给目的主机中的正确进程，以及是否提供可靠、有序的端到端传输服务**。

这三个层次不是重复劳动，而是在不同的通信范围内解决不同的问题。

### 2. 代表真题：2009年408——端到端服务

**题目：** 在OSI参考模型中，自下而上第一个提供端到端服务的层次是（ ）。

A. 数据链路层\
B. 传输层\
C. 会话层\
D. 应用层

**答案：B。**

#### 解题本质

首先要明确，408教材语境下的端到端服务，通常指源主机和目的主机中应用进程之间的通信服务。

网络层可以将数据送到目的主机，但是一台计算机可能同时运行浏览器、邮件客户端、聊天软件等多个应用程序。

仅凭IP地址，无法确定数据应该交给哪个应用进程。

因此，需要传输层通过端口号实现进程之间的通信。

传输层才是自下而上第一个提供这种端到端服务的层次。

#### 迁移到2022年408真题

题目问：实现两个相邻结点间流量控制功能的是哪一层？

答案是数据链路层。

这里真正考查的不是“流量控制”四个字，而是**流量控制发生的范围**。

| 题目中的描述          | 对应层次  |
| --------------- | ----- |
| 相邻结点之间的流量控制     | 数据链路层 |
| 源进程与目的进程之间的流量控制 | 传输层   |
| 路由选择、跨网络分组转发    | 网络层   |
| 比特流的传输          | 物理层   |

<Callout type="warn" title="按通信范围判断">

**不要看到流量控制就直接选择传输层，也不要看到差错控制就直接选择数据链路层。**

</Callout>

多个层次可以具有相似的功能，区别在于这些功能针对的对象和范围。

### 3. 根据设备判断其工作层次

2016年408真题考查路由器、交换机、集线器实现的最高功能层。

| 网络设备       | 最高工作层次 | 判断依据        |
| ---------- | ------ | ----------- |
| 中继器、集线器    | 物理层    | 不识别MAC或IP地址 |
| 网桥、普通二层交换机 | 数据链路层  | 根据MAC地址转发帧  |
| 路由器        | 网络层    | 根据网络层地址转发分组 |

因此答案是3、2、1。

真正需要掌握的规律是：

**判断设备能理解和处理哪一层的协议控制信息，而不是判断它传输的物理内容是什么。**

路由器同样需要发送比特，也需要处理帧，但它能够进一步处理IP分组，因此最高工作在网络层。

注意，题目中的普通交换机是指二层交换机，实际网络中还存在三层交换机。

## 三、核心考点二：OSI与TCP/IP模型的区别

### 1. 三种模型的对应关系

| OSI七层模型 | TCP/IP四层模型 | 教学五层模型 |
| ------- | ---------- | ------ |
| 应用层     | 应用层        | 应用层    |
| 表示层     | 应用层        | 应用层    |
| 会话层     | 应用层        | 应用层    |
| 传输层     | 传输层        | 传输层    |
| 网络层     | 网际层        | 网络层    |
| 数据链路层   | 网络接口层      | 数据链路层  |
| 物理层     | 网络接口层      | 物理层    |

这张表能够直接解决资料中的2013年、2014年、2019年、2021年真题，以及模拟题第24题。

经典TCP/IP模型没有单独设置会话层和表示层，但不意味着这些功能消失了，而是由应用层协议或应用程序承担。

### 2. 面向连接与可靠传输是两个独立概念

| 概念    | 实际含义               |
| ----- | ------------------ |
| 面向连接  | 通信前需要建立逻辑连接        |
| 无连接   | 不需要预先建立逻辑连接        |
| 可靠传输  | 提供相应的数据正确交付保证      |
| 不可靠传输 | 不保证数据一定正确、完整、有序地到达 |

<Callout type="warn" title="连接与可靠性">

**面向连接不一定可靠，无连接也不必然意味着无法实现可靠传输。**

</Callout>

连接解决的是通信状态问题。

可靠性解决的是数据交付问题。

### 3. 代表真题：2011年408

TCP/IP参考模型的网络层提供的是什么服务？

答案：**无连接、不可靠的数据报服务。**

这是因为IP协议不需要提前建立连接，也不保证分组一定送达或者按序到达。

那么，为什么建立在IP之上的TCP可以提供可靠传输？

因为TCP自己实现了序号、确认、重传等机制。

```text
TCP：面向连接、可靠传输
          ↓ 使用
IP：无连接、尽最大努力交付
          ↓ 使用
底层网络
```

这个例子可以直接反驳模拟题第17题、第22题中的错误说法：

上下相邻层必须提供相同性质的服务——错误。

面向连接的服务一定可靠——错误。

下层不可靠，上层就不能可靠——错误。

#### 两种模型的服务类型

按照408常用教材的对比口径：

| 参考模型   | 网络层      | 传输层      |
| ------ | -------- | -------- |
| OSI    | 面向连接、无连接 | 面向连接     |
| TCP/IP | 无连接      | 面向连接、无连接 |

其中TCP和UDP正好对应TCP/IP传输层的两种服务类型。

OSI这一行应按照考试教材的经典对比方式理解，不应将其扩大为对所有实际协议实现的绝对限制。

## 四、核心考点三：协议、服务、接口的本质

### 1. 横向是协议，纵向是服务

```text
主机A                          主机B

第n+1层                         第n+1层
   ↑                               ↑
 服务与接口                      服务与接口
   │                               │
 第n层  ←────── 第n层协议 ──────→ 第n层
   ↑                               ↑
 服务与接口                      服务与接口
   │                               │
第n-1层                         第n-1层
```

| 概念 | 关系        | 本质            |
| -- | --------- | ------------- |
| 协议 | 不同结点的对等实体 | 通信双方遵守的规则     |
| 服务 | 同一结点的相邻层  | 下层能够为上层提供什么能力 |
| 接口 | 同一结点的相邻层  | 上层如何使用下层服务    |

对于第 $n$ 层：

- 它是第 $n-1$ 层的服务用户。
- 它是第 $n+1$ 层的服务提供者。
- 它与其他结点的第 $n$ 层实体遵循第 $n$ 层协议。

### 2. 网络体系结构不规定具体实现细节

2010年408真题问：下列哪一项不属于网络体系结构所描述的内容？

答案是协议的内部实现细节。

网络体系结构规定层次、协议、功能以及相应的层间关系。

但是，它不规定某个协议必须用C语言实现，必须使用哪种数据结构，或者必须使用哪种芯片。

这就是分层能够提高系统灵活性的根本原因。

<Callout type="info" title="分层的独立性">

**只要对外提供的服务和接口保持一致，内部实现就可以改变。**

</Callout>

### 3. 协议三要素：语法、语义、时序

| 要素 | 本质           | TCP协议中的例子    |
| -- | ------------ | ------------ |
| 语法 | 怎么写          | 首部字段长度、排列格式  |
| 语义 | 什么意思、应该做什么   | SYN、ACK标志的含义 |
| 时序 | 什么时候做、按什么顺序做 | 三次握手的先后关系    |

#### 代表真题：2020年408

原题配图展示了发送方和接收方随时间推进，依次发送、应答信息的过程。

问该图描述了哪种协议要素。

答案：**时序。**

因为图中没有规定报文结构，也没有明确解释报文各字段的含义，只体现通信动作发生的先后顺序。

#### 对照模拟题第20题

HTTP服务器收到GET请求后执行相应操作，属于哪个协议要素？

答案：**语义。**

这里虽然有一个“收到请求后”的时间描述，但题目关注的是收到请求应该执行什么操作，而不是通信的先后顺序。

这是出题人很喜欢设置的陷阱。

**判断协议三要素时，要关注题目描述的重点，而不是寻找某一个表面关键词。**

## 五、核心考点四：数据封装与传输效率

### 1. 理解PDU、SDU、PCI

三个概念可以通过一个公式理解：

$$
\boxed{\mathrm{PDU}=\mathrm{SDU}+\mathrm{PCI}}
$$

其中：

| 概念  | 含义            |
| --- | ------------- |
| SDU | 上层交给本层处理的数据   |
| PCI | 本层添加的协议控制信息   |
| PDU | 本层处理形成的协议数据单元 |

在题目采用的不拆分、不合并的简化封装模型中：

$$
\mathrm{SDU}_n=\mathrm{PDU}_{n+1}
$$

也就是说，上层的PDU是下层的SDU。

```text
应用层      [应用数据]

传输层      [TCP首部][应用数据]

网络层      [IP首部][TCP首部][应用数据]

数据链路层  [帧头][IP首部][TCP首部][应用数据][帧尾]

物理层      010101101001010...
```

每向下一层传递一次，本层就可以把上层传来的数据整体视为自己的载荷，并附加相应的控制信息。

### 2. 各层的数据单位

| 层次    | 本层PDU的常见名称  | 本层SDU的示意名称 |
| ----- | ----------- | ---------- |
| 传输层   | 报文段、用户数据报   | 应用数据       |
| 网络层   | 分组、IP数据报    | 报文段        |
| 数据链路层 | 帧           | 分组         |
| 物理层   | 比特流（教学惯用称呼） | 帧          |

模拟题第19题就是故意将PDU改成SDU进行考查。

物理层、数据链路层、网络层的SDU分别是什么？

答案是数据帧、数据分组、报文段。

### 3. 代表真题：2017年408——封装效率

OSI参考模型的应用层发送400B数据，不拆分。除物理层和应用层外，其他各层均引入20B额外开销。

求应用层数据传输效率。

<Steps>

<Step>

### 确定开销层数

OSI共7层，题目排除了2层。

因此增加开销的是5层。

</Step>

<Step>

### 计算总长度

$$
L_{\text{总}}=400+5\times20=500\mathrm{B}
$$

</Step>

<Step>

### 计算效率

$$
\eta=\frac{400}{500}=80\%
$$

答案为A。

</Step>

</Steps>

#### 通用解题公式

$$
\boxed{ \eta_{\text{封装}} =\frac{\text{有效载荷长度}}{\text{实际传输总长度}} }
$$

进一步推广，如果将报文拆分成多个分组，则每个分组可能都需要独立添加首部。

假设原始数据为 $M$，共拆成 $n$ 个分组，每个分组首部为 $h$，忽略其他开销：

$$
\eta=\frac{M}{M+nh}
$$

**封装效率取决于传输内容中有多少是真正需要的数据，而不是链路速度有多快。**

注意，封装效率和后面的信道利用率不是同一个概念。

## 六、核心考点五：发送时延与传播时延

这是整个计算机网络计算题最重要的基础。

发送与传播时延也是物理层、数据链路层及TCP的计算基础。

### 1. 四种时延

| 时延   | 公式或含义         | 决定因素      |
| ---- | ------------- | --------- |
| 发送时延 | $T_s=L/R$ | 数据长度、发送速率 |
| 传播时延 | $T_p=d/v$ | 传播距离、传播速度 |
| 处理时延 | 结点处理分组的时间     | 设备处理能力    |
| 排队时延 | 分组等待发送的时间     | 网络拥塞程度    |

$$
T_{\text{总}} =T_s+T_p+T_{\text{处理}}+T_{\text{排队}}
$$

其中最容易混淆的是发送时延和传播时延。

<Tabs items={['发送时延', '传播时延']}>

<Tab value="发送时延">

发送方将整个分组的所有比特推入链路需要多长时间。

$$
T_s=\frac{L}{R}
$$

</Tab>

<Tab value="传播时延">

某一个比特从链路的一端传播到另一端需要多长时间。

$$
T_p=\frac{d}{v}
$$

发送速率越高，表示单位时间可以向链路注入更多比特。

但并不意味着单个比特在链路中传播得更快。

</Tab>

</Tabs>

### 2. 建立最重要的时间线

假设在 $t=0$ 时开始发送一个分组。

| 事件          | 时刻            |
| ----------- | ------------- |
| 第一个比特开始发送   | $0$       |
| 最后一个比特发送完成  | $T_s$     |
| 第一个比特到达接收端  | $T_p$     |
| 最后一个比特到达接收端 | $T_s+T_p$ |

无论题目如何变化，只要能够确定它问的是哪一个事件，就能确定正确的时延。

### 3. RTT不等于两倍传播时延

模拟题第10题考查的是：如果请求和应答分组非常短，可以忽略发送时延，那么RTT与往返传播时延是什么关系？

答案是大于或等于。

在路径对称的情况下：

$$
RTT=2T_p+T_{\text{额外开销}}
$$

由于额外开销非负：

$$
\boxed{RTT\geq 2T_p}
$$

只有在忽略其他开销的理想模型下，才有：

$$
RTT=2T_p
$$

做题时不能看到RTT就无条件除以2，当作单向传播时延。

## 七、核心考点六：带宽时延积

带宽时延积是一个非常重要、但容易被死记硬背的概念。

### 1. 本质：链路能够容纳多少在途比特

$$
\boxed{\mathrm{BDP}=R\times T_p}
$$

进一步代入传播时延：

$$
\mathrm{BDP}=R\frac{d}{v}
$$

可以把链路想象成一根传输比特的管道：

```text
发送方                                  接收方
  A  → [1][0][1][1][0][0][1][0][1] →  B

        ← 链路中同时存在的比特 →
```

发送速率决定比特进入管道的速度。

传播时延决定比特在管道中停留的时间。

二者相乘，就是管道被充分利用时能够容纳的比特数量。

如果仅连续发送一个长度为 $L$ 的文件，那么链路上同时存在的最大比特数为：

$$
\boxed{ N_{\max}=\min(L,RT_p) }
$$

这里假设发送速率恒定，不考虑其他数据流。

### 2. 代表模拟题：王道卷一，第8题

题目给出：

信道长度1km，频带宽度160MHz，信号功率0.6W，噪声功率0.0193W，信号传播速度200000km/s，发送6000bit文件。

求链路上的最大在途比特数量。

<Steps>

<Step>

### 计算信道容量

由香农公式：

$$
C=W\log_2\left(1+\frac{S}{N}\right)
$$

由于：

$$
1+\frac{0.6}{0.0193}\approx32
$$

所以：

$$
C\approx160\times10^6\times5
$$

$$
C\approx8\times10^8\mathrm{bit/s}
$$

</Step>

<Step>

### 计算传播时延

$$
T_p=\frac{1}{200000} =5\times10^{-6}\mathrm{s}
$$

</Step>

<Step>

### 计算在途比特数

$$
\mathrm{BDP} =8\times10^8\times5\times10^{-6} =4000\mathrm{bit}
$$

文件大小为6000bit，超过链路能够同时容纳的4000bit，因此答案为4000bit，选D。

</Step>

</Steps>

#### 这道题真正重要的地方

题目中的三个物理量完全不同。

| 物理量    | 单位    |
| ------ | ----- |
| 信道频带宽度 | Hz    |
| 数据传输速率 | bit/s |
| 带宽时延积  | bit   |

计算机网络中有很多题目，只要通过单位分析，就可以判断公式是否使用正确。

## 八、核心考点七：电路交换、报文交换与分组交换

这是模拟题中非常重要的计算题型。

### 1. 三种交换方式的本质区别

| 特点         | 电路交换         | 报文交换   | 分组交换 |
| ---------- | ------------ | ------ | ---- |
| 是否预先建立专用电路 | 是            | 否      | 不一定  |
| 是否存储转发     | 通常不需要整报文存储转发 | 是      | 是    |
| 存储转发单位     | 不适用          | 整条报文   | 分组   |
| 能否形成分组流水   | 不涉及分组流水      | 单个报文不能 | 能    |
| 中间结点缓存需求   | 通常较低         | 较大     | 相对较小 |

分组交换的核心优势，不只是把报文拆小了，而是：

**拆分之后，不同链路能够同时传输不同分组，从而形成流水线。**

### 2. 彻底理解分组流水线

假设有3个分组，每个分组通过一段链路需要1秒，路径共有3段链路，忽略传播时延。

| 时间   | 链路1 | 链路2 | 链路3 |
| ---- | --- | --- | --- |
| 0～1s | 分组1 | —   | —   |
| 1～2s | 分组2 | 分组1 | —   |
| 2～3s | 分组3 | 分组2 | 分组1 |
| 3～4s | —   | 分组3 | 分组2 |
| 4～5s | —   | —   | 分组3 |

全部分组传输完成需要5秒，而不是9秒。

设分组数为 $n$，链路数为 $k$，每个分组发送时延为 $T_s$。

第一个分组到达终点需要：

$$
kT_s
$$

后续 $n-1$ 个分组陆续到达，需要：

$$
(n-1)T_s
$$

因此：

$$
\boxed{T=(n+k-1)T_s}
$$

如果每段链路传播时延均为 $T_p$，则：

$$
\boxed{T=(n+k-1)T_s+kT_p}
$$

适用条件是等长分组、等速率链路、存储转发，并忽略排队和处理等其他开销。

### 3. 代表模拟题：王道卷一，第2题

报文长度为 $x$ bit，经过 $k$ 段链路，每段传播时延为 $d$，传输速率为 $b$，电路建立时间为 $c$，分组长度为 $p$。

问满足什么条件时，分组交换比电路交换更快。

<Tabs items={['电路交换', '分组交换']}>

<Tab value="电路交换">

先建立电路，再发送整个报文。

$$
T_c=c+\frac{x}{b}+kd
$$

</Tab>

<Tab value="分组交换">

分组数：

$$
n=\frac{x}{p}
$$

利用流水线公式：

$$
T_f=(n+k-1)\frac{p}{b}+kd
$$

整理得到：

$$
T_f=\frac{x}{b}+(k-1)\frac{p}{b}+kd
$$

</Tab>

</Tabs>

#### 比较二者

要求：

$$
T_f<T_c
$$

消去共同部分：

$$
\boxed{(k-1)\frac{p}{b}<c}
$$

答案为A。

这道题不应该只记住最后的公式，而应该理解：

电路交换额外付出的代价是建立连接。

分组交换额外付出的代价是中间结点存储转发产生的流水线尾部开销。

谁的额外开销更小，谁就更快。

### 4. 三种交换方式的统一计算公式

设报文长度为 $M$ bit，每个分组长度为 $P$ bit，链路数为 $k$，链路速率为 $R$，每段传播时延为 $d$，电路建立时间为 $c$。

忽略分组首部、排队和处理等额外开销：

| 交换方式 | 总时延                                     |
| ---- | --------------------------------------- |
| 电路交换 | $c+\dfrac{M}{R}+kd$                 |
| 报文交换 | $k\dfrac{M}{R}+kd$                  |
| 分组交换 | $\dfrac{M}{R}+(k-1)\dfrac{P}{R}+kd$ |

这三个公式能够统一解决模拟题第2、5、7题。

但是不建议机械背诵。最好能够随时根据第一个分组和最后一个分组的时间线重新推导。

### 5. 进阶：为什么分组不是越小越好？

模拟题第4题进一步考查了最优分组长度。

假设报文有效长度为 $M$，每个分组的数据载荷为 $x$，首部长度为 $h$，经过两段链路，发送速率为 $s$。

总时延为：

$$
T(x)=\left(\frac{M}{x}+1\right)\frac{x+h}{s}
$$

展开：

$$
T(x)=\frac{1}{s} \left(M+h+\frac{Mh}{x}+x\right)
$$

只需要考虑其中随 $x$ 变化的部分：

$$
f(x)=\frac{Mh}{x}+x
$$

利用基本不等式：

$$
\frac{Mh}{x}+x\geq2\sqrt{Mh}
$$

等号成立时：

$$
\boxed{x=\sqrt{Mh}}
$$

所以原题给出0.2MB报文和20B首部，最优载荷约为2048B，选B。

这道题的精髓是理解两种相互制约的代价：

分组越小，首部数量越多，额外开销越大。

分组越大，存储转发等待时间越长，流水线优势越不明显。

因此存在最优分组长度。

原题中的0.2MB与严格整除条件并不完全严谨，所以这里采用题目要求的近似优化结果。

## 九、核心考点八：数据报与虚电路

这两种方式都属于分组交换。

它们最重要的区别是：**是否在数据传输之前建立一条逻辑路径，以及中间结点是否保存相应的连接状态。**

| 比较项目     | 数据报      | 虚电路              |
| -------- | -------- | ---------------- |
| 是否预先建立连接 | 否        | 是                |
| 转发依据     | 目的地址     | 虚电路号             |
| 分组路径     | 可以不同     | 通常相同             |
| 到达顺序     | 可能乱序     | 教材模型下按序          |
| 中间结点故障   | 后续分组可能绕路 | 原虚电路可能失效，需要恢复或重建 |
| 是否独占物理线路 | 否        | 通常也不独占           |

最重要的易错点：

<Callout type="warn" title="逻辑路径与独占电路">

**虚电路交换不等于电路交换。**

</Callout>

电路交换为通信建立专用电路或预留相应资源。

虚电路只是建立一条逻辑路径，仍然以分组为单位进行存储转发，多条虚电路可以共享同一物理链路。

模拟题第6题的错误选项，就是声称数据报和虚电路在中间结点故障时都能直接重新选择路径继续传输。

数据报可以在路由更新后让后续分组走其他路径；虚电路的原有连接状态则可能被破坏，通常需要额外的恢复机制。

### 容易混淆的分组排序与分片重组

模拟题第3题非常值得理解。

| 操作                | 所属层次 |
| ----------------- | ---- |
| TCP对乱序数据进行排序      | 传输层  |
| IPv4根据MTU进行分片     | 网络层  |
| 目的主机重组同一个IP数据报的分片 | 网络层  |

为什么不是同一层完成？

因为TCP排序的对象是传输层字节流。

IP分片重组的对象是某一个原始IP数据报。

两者解决的问题完全不同。

## 十、核心考点九：停止等待协议与信道利用率

这部分虽然主要属于后续数据链路层，但题库将多道相关模拟题归入本章，应提前掌握其共同的时延原理。

### 1. 停止等待协议为什么效率低？

发送方每发送一个数据帧，就必须等待确认到达，才能发送下一个数据帧。

```text
发送方                       接收方
   │                           │
   │ ─────── DATA ───────────→ │
   │                           │
   │        等待确认           │
   │ ←────── ACK ───────────── │
   │                           │
   │ ─────── DATA ───────────→ │
```

在等待期间，即使链路具有很大的带宽，发送方也无法继续发送新的数据帧。

所以：

<Callout type="warn" title="信道利用率">

**链路带宽很高，不代表实际吞吐量很高。**

</Callout>

### 2. 通用公式

设数据帧发送时延为 $T_s$，单向传播时延为 $T_p$，确认帧发送时延为 $T_a$。

忽略处理、排队及重传等开销：

$$
T_{\text{周期}}=T_s+2T_p+T_a
$$

发送方的数据帧发送时间占比为：

$$
\boxed{ U=\frac{T_s}{T_s+2T_p+T_a} }
$$

如果确认帧长度忽略不计：

$$
\boxed{ U=\frac{T_s}{T_s+2T_p} }
$$

如果数据帧中真正的有效数据为 $L_{\text{有效}}$，则有效数据率为：

$$
\boxed{ R_{\text{有效}}= \frac{L_{\text{有效}}}{T_{\text{周期}}} }
$$

### 3. 代表模拟题：王道卷七，第1题

链路数据率为2Mb/s，线路长度1km，传播速度为20m/ms，分组大小100B，确认帧大小忽略。

求停止等待协议的实际数据率。

#### 计算发送时延

$$
T_s=\frac{100\times8}{2\times10^6} =0.4\mathrm{ms}
$$

#### 计算传播时延

$$
T_p=\frac{1000}{20}=50\mathrm{ms}
$$

注意，必须使用题目给出的特殊传播速度，不能自行代入常用的光纤传播速度。

#### 计算完整周期

$$
T_{\text{周期}}=0.4+2\times50 =100.4\mathrm{ms}
$$

#### 计算实际数据率

$$
R_{\text{有效}}=\frac{800}{0.1004} \approx7968\mathrm{bit/s}
$$

即：

$$
\boxed{R_{\text{有效}}\approx8\mathrm{kb/s}}
$$

答案选C。

虽然链路带宽为2Mb/s，但大量时间被用于等待确认，实际数据率只有约8kb/s。

这就是滑动窗口协议存在的重要原因：让多个分组同时处于尚未确认的状态，减少发送方的空闲等待。

### 4. 反向求最小帧长

模拟题第12题要求根据目标信道利用率反推最小帧长。

设：

$$
U=\frac{L/R}{L/R+2T_p}
$$

整理得到：

$$
\boxed{ L=\frac{2RT_pU}{1-U} }
$$

当要求信道利用率达到50%时：

$$
L\geq 2RT_p
$$

特别值得理解：

当发送时延等于往返传播时延时，发送方一半时间用于发送，一半时间用于等待，利用率恰好为50%。

### 5. 区分三种效率指标

| 指标    | 分子          | 分母        |
| ----- | ----------- | --------- |
| 封装效率  | 有效数据长度      | 实际传输的数据长度 |
| 信道利用率 | 有效占用信道的发送时间 | 完整通信周期    |
| 有效数据率 | 有效数据比特数     | 完整通信周期    |

在无差错、恒定链路速率的简化模型下：

$$
R_{\text{有效}} =R\times U\times\eta_{\text{封装}}
$$

这个关系可以统一理解后续很多综合计算题。

## 十一、其他模拟题考点：掌握共同原理即可

资料中还有一些实际属于物理层、数据链路层或传输层的模拟题。这里不逐题展开，但应该掌握其核心方法。

### 1. 奈奎斯特定理与香农定理

分别解决有限码元状态数和信道噪声对数据率的限制。

奈奎斯特公式：

$$
C_N=2W\log_2 M
$$

香农公式：

$$
C_S=W\log_2\left(1+\frac SN\right)
$$

信噪比转换：

$$
\frac SN=10^{\mathrm{SNR_{dB}}/10}
$$

如果题目同时给出码元状态数和信噪比，则两个上限都需要检查：

$$
\boxed{C_{\max}=\min(C_N,C_S)}
$$

模拟题第13题给出4种信号状态、30dB信噪比、极限速率8kb/s。

奈奎斯特限制为 $4W$，香农限制约为 $9.97W$。

显然前者限制更严格，因此带宽为2kHz。

本质是：**系统同时受到多个条件约束时，性能取决于最严格的那个约束。**

### 2. CSMA/CD碰撞检测

核心思想是：发送方必须在发送完最短帧之前，有机会检测到最远端产生的碰撞。

$$
\boxed{ \frac{L_{\min}}{R}\geq2T_p }
$$

如果路径上还有集线器等设备的固定延迟，则必须计入往返过程。

这就是模拟题第9题的核心。

值得注意的是，它和停止等待协议中出现的 $2T_p$ 虽然数学形式相同，但物理含义不同。

停止等待是为了等待确认。

CSMA/CD是为了等待可能返回的碰撞信号。

### 3. CSMA/CA中的NAV

模拟题第14题考查CTS帧中的NAV。

关键不在于记住一个长公式，而在于画出时间线：

```text
DIFS → RTS → SIFS → CTS → SIFS → DATA → SIFS → ACK
                       ↑
                   CTS发送完成
```

CTS中的NAV表示CTS发送完成后，本次通信还需要占用多长时间。

因此：

$$
NAV_{\text{CTS}} =2T_{\text{SIFS}}+T_{\text{DATA}}+T_{\text{ACK}}
$$

已经发生的时间不应该重复计入。

### 4. 序号回绕问题

模拟题第11题考查的是旧数据还可能存在时，能否重复使用相同序号。

对于按字节编号的协议，若最大数据单元生存时间为 $T$，数据率为 $R$ bit/s，序号字段长度为 $w$ bit，则在题目采用的简化模型下：

$$
\boxed{2^w\geq\frac{RT}{8}}
$$

从而：

$$
w_{\min}= \left\lceil\log_2\frac{RT}{8}\right\rceil
$$

这道题需要特别注意序号是按字节编号还是按分组编号。

## 十二、本章最值得掌握的选择题解题思维

### 方法一：看到某种功能，先判断通信范围

不要直接通过“流量控制”“可靠传输”“差错控制”等关键词确定层次。

先判断它涉及相邻结点、不同主机，还是不同主机中的应用进程。

这是网络分层题最重要的判断依据。

### 方法二：看到时延题，先确定起点和终点

题目问的是发送完成、首比特到达、末比特到达、确认到达，还是所有分组传输完成？

只要事件定义不同，计算结果就可能不同。

### 方法三：看到多段链路，先判断能否流水

电路交换、报文交换、分组交换不能使用完全相同的计算公式。

尤其是分组交换，不要直接将每个分组经过所有链路的时间相加。

### 方法四：看到效率题，明确分子和分母

数据长度除以时间，得到的是数据率。

数据长度除以数据长度，得到的是数据占比。

时间除以时间，得到的是时间利用率。

### 方法五：看到绝对化表述，尝试构造反例

| 常见错误表述         | 反例或原因          |
| -------------- | -------------- |
| 下层不可靠，上层也不可靠   | TCP建立在IP之上     |
| 面向连接一定可靠       | 连接与可靠性是不同属性    |
| 带宽越大，传播时延越小    | 传播时延由距离和传播速度决定 |
| 所有网络体系结构都有相同层数 | OSI与TCP/IP不同   |
| 分组越小，传输效率一定越高  | 分组首部开销会增加      |
| RTT一定等于往返传播时延  | 还可能存在处理、排队等开销  |
| 虚电路就是电路交换      | 虚电路仍然属于分组交换    |
| 捎带确认可以忽略确认发送时间 | 反向数据帧也需要发送时间   |

7. 为什么虚电路交换不属于电路交换？
8. 为什么IP分片重组和TCP乱序排序属于不同层次？
9. 为什么某一层的SDU通常对应上一层的PDU？
10. 为什么只知道RTT，不能直接确定传播距离？

## 核心思维模型

计算机网络第1章最不应该采用的学习方法，就是孤立背诵每一层的功能，以及大量记忆时延计算公式。

真正应该在脑中建立的是两个模型：

<Cards>

<Card title="空间模型">

 数据从源进程出发，经过传输层、网络层、数据链路层和物理层，在网络中逐跳传输，最终交付给目的进程。

</Card>

<Card title="时间模型">

 数据需要经过发送、传播、存储转发、等待和确认，每一种协议都在这些时间开销之间进行权衡。

</Card>

</Cards>

这两个模型不仅可以解决第一章的选择题，也是后续学习以太网、滑动窗口、IP分片、TCP可靠传输和拥塞控制的共同基础。
