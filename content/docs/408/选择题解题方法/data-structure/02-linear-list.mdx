**本章最重要的能力，不是背诵链表操作的代码，而是在脑中准确维护结点之间的指向关系。**

绝大多数题目都可以归结为五个问题：

1. 当前指针究竟指向谁？
2. 修改指针后，哪些连接发生了变化？
3. 原来的连接是否会丢失？
4. 操作完成后，链表结构是否合法？
5. 为了完成操作，需要访问多少个结点？

掌握这五个问题，很多看起来复杂的代码选择题，实际上只是基础操作的组合。

## 二、核心考点1：真正理解单链表的插入与删除

### 2.1 首先理解指针赋值的本质

假设当前链表为：

```text
p
↓
A ──→ B ──→ C ──→ NULL
```

这里：

| 表达式             | 含义     |
| --------------- | ------ |
| `p`             | A结点的地址 |
| `p->data`       | A结点的数据 |
| `p->next`       | B结点的地址 |
| `p->next->next` | C结点的地址 |

特别注意下面两条语句的区别：

```c
p = p->next;
```

改变的是指针变量 `p`，让它指向B。链表结构没有发生任何变化。

```c
p->next = p->next->next;
```

改变的是A结点内部的指针域，让A直接指向C。链表结构发生变化。

<Callout type="warn" title="指针赋值与结构修改">

**修改指针变量，不等于修改链表；修改结点的链接域，才可能改变链表结构。**

</Callout>

这是理解整个链表章节的基础。

### 2.2 插入结点：先保存旧连接，再建立新连接

假设要在A和B之间插入新结点X。

```text
插入前：

A ──────────→ B      X

插入后：

A ──→ X ──→ B
```

设 `p` 指向A，`s` 指向X。

正确代码：

```c
s->next = p->next;
p->next = s;
```

第一步让X指向B，第二步让A指向X。

如果交换两条语句：

```c
p->next = s;
s->next = p->next;
```

第一条语句已经让 `p->next` 变成了 `s`，因此第二条实际上等于：

```c
s->next = s;
```

X指向自己，形成自环，同时丢失原来的后继连接。

### 代表题：王道·卷七

题目要求：在带头结点的单链表中，让插入的先后顺序与结点在链中的顺序相反，应该采用什么操作？

答案是头插法：

```c
p->next = L->next;
L->next = p;
```

假设依次插入1、2、3：

```text
插入1：L → 1
插入2：L → 2 → 1
插入3：L → 3 → 2 → 1
```

最终顺序是3、2、1。

由此得到一个非常重要的结论：

| 建表方式 | 最终结点顺序  |
| ---- | ------- |
| 头插法  | 与插入顺序相反 |
| 尾插法  | 与插入顺序相同 |

头插法不仅可以建表，还能用于链表逆序、有序链表降序合并等问题。

<Callout type="idea" title="保护旧连接">

**解题原则：凡是即将被覆盖、但后面仍然需要使用的指针，都必须提前使用或保存。**

</Callout>

### 2.3 删除结点：让前驱绕过待删除结点

假设删除B。

```text
删除前：

A ──→ B ──→ C

删除后：

A ─────────→ C
```

已知 `p` 指向A：

```c
q = p->next;
p->next = q->next;
free(q);
```

整个操作可以理解为：保存待删结点、绕过待删结点、释放待删结点。

这里必须区分两件事：

- 将结点从链表中摘除。
- 将结点占用的内存释放。

摘除不一定意味着释放。例如将一个结点移动到其他位置，就只能摘除，不能释放。

### 2.4 代表真题：2024年408——结点移动

这道题非常值得掌握，因为它将单链表的删除和插入组合起来考查。

已知 `h` 为带头结点单链表的头指针，`p` 指向非首且非尾结点，执行：

```c
q = p->next;
p->next = q->next;
q->next = h->next;
h->next = q;
```

问执行结果是什么？

#### 第一步：构造一个简单实例

```text
        p
        ↓
h → A → B → C → D → NULL
```

执行：

```c
q = p->next;
```

此时 `q` 指向C。

执行：

```c
p->next = q->next;
```

```text
h → A → B → D → NULL

        q → C → D
```

C已经从主链表中摘除，但没有被释放。

执行：

```c
q->next = h->next;
```

让C指向原来的首元结点A。

最后：

```c
h->next = q;
```

```text
h → C → A → B → D → NULL
```

因此，答案为 **D：将q所指结点移动到头结点之后。**

#### 这道题真正需要掌握什么？

不要将四条代码当成一个陌生算法，而应当识别两个基本操作：

```c
// 摘除 p 的后继结点
q = p->next;
p->next = q->next;

// 将 q 头插到链表中
q->next = h->next;
h->next = q;
```

即：

**结点移动 = 摘除结点 + 重新插入结点。**

以后遇到链表逆置、结点交换、链表重组等题目，都可以尝试拆解为这些基本操作。

## 三、核心考点2：双链表操作——用连接关系代替死记代码

双链表与单链表的本质区别在于：每个结点除了知道自己的后继，还知道自己的前驱。

```c
typedef struct DNode {
    int data;
    struct DNode *prev;
    struct DNode *next;
} DNode;
```

因此对于相邻结点A和B，必须同时满足：

```c
A->next == B
B->prev == A
```

这就是双链表的双向一致性。

### 3.1 双链表插入：必须建立四条连接

假设在A、B之间插入X。

```text
插入前：

A ⇄ B

插入后：

A ⇄ X ⇄ B
```

需要建立的四条连接如下：

| 指针域       | 应当指向 |
| --------- | ---- |
| `A->next` | X    |
| `X->prev` | A    |
| `X->next` | B    |
| `B->prev` | X    |

只要最后四个关系全部正确，插入就成功。

假设 `p` 指向A，`s` 指向X，且A存在后继：

```c
s->next = p->next;
s->prev = p;
p->next->prev = s;
p->next = s;
```

不必死记唯一的语句顺序。只要没有提前覆盖仍需使用的旧指针，就可能存在多种正确的语句排列。

### 3.2 代表真题：2023年408——补全双链表插入操作

这道题很有代表性，因为命题人故意使用了看起来复杂的指针表达式。

已知在非尾结点 `p` 后插入新结点 `s`，已经执行：

```c
s->next = p->next;
p->next = s;
```

问还需要执行哪些语句？

正确选项C：

```c
s->prev = s->next->prev;
s->next->prev = s;
```

#### 解题过程

给结点取固定名称，设原来的结构为：

```text
p                   q
↓                   ↓
A        ⇄          B

         X
         ↑
         s
```

前两条代码执行后：

```text
next方向：A ──→ X ──→ B

prev方向：A ←──────── B

X的prev尚未设置
```

现在缺少两个连接：

```c
s->prev = p;
s->next->prev = s;
```

但选项写的是：

```c
s->prev = s->next->prev;
```

分析右侧表达式：

- `s` 指向X。
- `s->next` 指向B。
- `s->next->prev` 此时仍然指向A。

因此这条语句等价于：

```c
s->prev = p;
```

再执行：

```c
s->next->prev = s;
```

让B的前驱变成X，完成插入。

这里原题库解析有一处容易误导的表述：在 `p->next=s` 执行之后，`p->next` 与 `s->next` 已经不是同一个结点，不能再将两者直接等同。正确的方法是按照当前指向逐级求值。

#### 为什么这道题重要？

核心考查的是指针表达式的动态语义，而非背诵插入代码：

**同一个指针表达式，在不同语句执行之后，可能代表完全不同的结点。**

因此，做指针题时千万不能一直使用初始状态分析后续语句。

### 3.3 双链表删除：恢复前驱与后继的双向连接

假设删除X：

```text
删除前：

A ⇄ X ⇄ B

删除后：

A ⇄ B
```

如果 `p` 指向X，只需要：

```c
p->prev->next = p->next;
p->next->prev = p->prev;
free(p);
```

这也是**2016年408双向循环链表删除题**的核心知识。

理解方式：

第一条让A的后继指向B。

第二条让B的前驱指向A。

最后释放X。

| 操作    | 核心连接数量   |
| ----- | -------- |
| 单链表插入 | 建立2条连接   |
| 单链表删除 | 修改1条原有连接 |
| 双链表插入 | 建立4条连接   |
| 双链表删除 | 修改2条原有连接 |

不包含头尾指针维护等额外操作。

**双链表的最佳解题方法：先画出目标结构，再检查每个选项是否能够建立正确的双向连接。**

竟成·模拟七的双向循环链表前插题也是这个考点，只是需要特别注意不能提前覆盖 `p->prev`。

## 四、核心考点3：循环链表——用极端情况破解选择题

循环链表并没有产生新的插入、删除原理，真正增加的难点是边界条件，以及首尾连接关系的维护。

### 4.1 必须掌握的空表与非空表特征

| 链表类型（带头结点） | 空表判断                            | 非空表尾结点特征             |
| ---------- | ------------------------------- | -------------------- |
| 普通单链表      | `h->next == NULL`               | `tail->next == NULL` |
| 单向循环链表     | `h->next == h`                  | `tail->next == h`    |
| 双向循环链表     | `h->next == h` 且 `h->prev == h` | `tail->next == h`    |

带头结点的双向循环链表还有一个重要特性：

```c
h->next   // 首元结点
h->prev   // 尾结点
```

因此即使没有单独设置尾指针，也可以在常数时间内找到尾结点。

注意：**头结点与首元结点不是同一个概念。** 头结点通常不存储有效的线性表元素。

### 4.2 代表真题：2021年408——删除循环链表第一个元素

已知一个带头结点的非空单向循环链表，头指针为 `h`，尾指针为 `p`，删除第一个元素。

正确选项D：

```c
q = h->next;
h->next = q->next;
if (p == q)
    p = h;
free(q);
```

这道题为什么不能只使用普通的单链表删除操作？

因为删除的可能是整个链表中唯一的数据结点。

<Tabs items={["多个数据结点", "只有一个数据结点"]}>
<Tab value="多个数据结点">

```text
      q         p
      ↓         ↓
h ──→ A ──→ B ──→ C
↑                 │
└─────────────────┘
```

删除A之后，尾指针仍然指向C，不需要修改。

</Tab>
<Tab value="只有一个数据结点">

```text
       p、q
         ↓
h ─────→ A
↑        │
└────────┘
```

此时删除A，链表应该变成：

```text
h、p
 ↓
[头结点] ──┐
   ↑      │
   └──────┘
```

必须执行：

```c
p = h;
```

否则尾指针仍然指向已经被释放的结点，成为悬空指针。

判断条件就是：

```text
p == q
```

即待删除结点恰好是尾结点。

</Tab>
</Tabs>

#### 从这道题提炼出的重要方法：极端情况检验法

链表选择题中出现“非空”“首结点”“尾结点”“循环链表”等条件时，优先考虑以下情况：

| 题目条件 | 优先测试             |
| ---- | ---------------- |
| 非空链表 | 只有一个数据结点         |
| 插入结点 | 空表、表头、表尾         |
| 删除结点 | 删除唯一结点、首元结点、尾结点  |
| 循环链表 | 操作后是否仍能形成闭环      |
| 带尾指针 | 原尾结点发生变化时是否更新尾指针 |

尤其是题目说“非空”时，不要默认链表有很多结点。

<Callout type="warn" title="边界条件">

**非空意味着至少有一个元素，并不意味着至少有两个元素。**

</Callout>

极端情况往往就是命题人设置错误选项的地方。

## 五、核心考点4：逻辑顺序与物理地址必须彻底区分

这是线性表中非常基础、但又容易被忽略的知识。

线性表描述的是元素之间的一对一逻辑关系，并不要求它们在内存中连续存放。

- 顺序表：通过存储位置体现逻辑关系。
- 链表：通过链接域体现逻辑关系。
- 静态链表：通过数组下标形式的链接域体现逻辑关系。

### 5.1 代表真题：2016年408——链表地址追踪

这道题和竟成·模拟五使用了相同的初始链表，分别考查插入与删除，特别适合结合起来学习。

原始存储状态：

| 内存地址  | 元素 | 链接地址  |
| ----- | -- | ----- |
| 1000H | a  | 1010H |
| 1004H | b  | 100CH |
| 1008H | c  | 1000H |
| 100CH | d  | NULL  |
| 1010H | e  | 1004H |
| 1014H | 空闲 | —     |

已知表头元素为c。

第一件事不是按照地址大小排序，而是沿着链接域恢复逻辑顺序：

```text
c ──→ a ──→ e ──→ b ──→ d ──→ NULL

1008H  1000H  1010H  1004H  100CH
```

真题要求在a与e之间插入f，f的地址为1014H。

插入后：

```text
c → a → f → e → b → d → NULL
```

所以：

| 元素 | 新的链接地址 |
| -- | ------ |
| a  | 1014H  |
| e  | 1004H  |
| f  | 1010H  |

答案D。

#### 模拟题的变式：删除a

竟成·模拟五要求从原链表中删除a。

```text
删除前：c → a → e → b → d

删除后：c ───→ e → b → d
```

因此c的链接地址变为1010H，e的链接地址保持1004H不变。

答案A。

#### 这类题的通用解法

先根据链接域画出原逻辑序列，再完成插入或删除，最后将结点名称转换为地址。

不要在地址表格中直接凭感觉寻找物理相邻的结点。

**结点的链接地址是后继结点的地址，不是当前结点自己的地址。**

## 六、核心考点5：静态链表——用数组实现的链表

静态链表很容易令人误以为它就是顺序表，因为它们都使用数组。

但本质上，静态链表仍然是链表。

```c
typedef struct {
    int data;
    int link;
} SListNode;
```

动态链表用指针记录后继地址，静态链表用整数记录后继所在的数组下标。

### 6.1 逻辑序号与数组下标

王道·卷六考查了一个非常典型的知识点：

若逻辑上第 $k$ 个结点的数组下标为 $i$，那么逻辑上第 $k+1$ 个结点的数据是什么？

答案：

```c
S[S[i].link].data
```

将这个表达式拆开即可理解：

```c
S[i]                 // 当前结点
S[i].link            // 后继结点的数组下标
S[S[i].link]         // 后继结点
S[S[i].link].data    // 后继结点的数据
```

为什么不能使用 `S[i+1].data`？

因为逻辑上的后继，不一定在数组中的下一个位置。

举例：

| 数组下标 | data | link |
| ---- | ---- | ---- |
| 0    | 头结点  | 3    |
| 1    | B    | 4    |
| 2    | D    | -1   |
| 3    | A    | 1    |
| 4    | C    | 2    |

实际逻辑顺序为：

```text
0 → 3 → 1 → 4 → 2 → -1

    A → B → C → D
```

如果当前结点是A，它的数组下标为3，而后继B的下标是1，并不是4。

**数组提供了随机访问物理位置的能力，但没有自动提供随机访问逻辑序号的能力。**

### 6.2 静态链表删除与空闲空间回收

竟成·模拟一考查了静态链表中更进一步的知识：删除一个结点之后，需要将其下标回收到空闲链表中。

可以把静态链表想象为同时维护两条链：

```text
有效数据链：

head → A → X → B → ...

空闲位置链：

avail → C → D → ...
```

删除X之后：

```text
有效数据链：

head → A → B → ...

空闲位置链：

avail → X → C → D → ...
```

假设 `a` 是待删结点的前驱下标，`x` 是待删结点下标，`avail` 是空闲链表头结点下标：

```c
S[a].link = S[x].link;

S[x].link = S[avail].link;
S[avail].link = x;
```

本质上仍然是：

**从有效链表中摘除结点，再将其头插到空闲链表。**

和前面的2024年408真题属于相同的操作思想。

值得注意的是，资料中这道模拟题原始表格的下标9的 `next` 值缺失。需要补充假设 `next[9]=4`，才能完整推导出题库给出的答案B。这是题目数据本身的问题，此条件缺失时不能唯一推出原答案。

## 七、核心考点6：时间复杂度——区分定位成本与修改成本

这是本章最容易形成错误认知的知识点之一。

很多同学认为：

> 顺序表插入和删除是 $O(n)$，链表插入和删除是 $O(1)$。

这个说法不够严谨。

真正应该掌握的是：

$$
T_{\text{操作}}= T_{\text{定位}}+T_{\text{修改}}
$$

链表修改指针本身通常很快，但找到正确的结点可能很慢。

### 7.1 顺序表与链表的复杂度比较

设线性表长度为 $n$，顺序表容量足够，普通链表默认只有头指针。

| 操作             | 顺序表       | 单链表       | 双链表    |
| -------------- | --------- | --------- | ------ |
| 按序号访问第 $i$ 个元素 | $O(1)$    | $O(n)$    | $O(n)$ |
| 无序表按值查找        | $O(n)$    | $O(n)$    | $O(n)$ |
| 在表头插入          | $O(n)$    | $O(1)$    | $O(1)$ |
| 在表尾插入          | $O(1)$    | $O(n)$    | $O(n)$ |
| 删除首元结点         | $O(n)$    | $O(1)$    | $O(1)$ |
| 已知结点，在其后插入     | 最坏 $O(n)$ | $O(1)$    | $O(1)$ |
| 已知非头数据结点，删除该结点 | 最坏 $O(n)$ | 一般 $O(n)$ | $O(1)$ |
| 已知结点，寻找前驱      | $O(1)$    | 一般 $O(n)$ | $O(1)$ |

表格按照常规实现和一般最坏情况判断，假定双链表删除时可直接访问需要的相邻结点，不涉及额外尾指针更新等特殊限制。

特别注意单链表的几个例外：

- 如果有尾指针，尾插可以是 $O(1)$。
- 如果已知待删结点的前驱，删除可以是 $O(1)$。
- 如果只知道待删结点自身，一般需要寻找其前驱，因此为 $O(n)$。

还有一种特殊技巧：对于非尾结点，可以复制后继的数据，再删除后继，从而在 $O(1)$ 时间内实现逻辑上的元素删除。但它并不是真正释放原待删结点，且不适用于尾结点，必须注意题目语义。

### 7.2 代表模拟题：竟成·模拟三

题目问下列哪种操作能在 $O(1)$ 时间内完成？

A. 删除单链表的 $k$ 个元素。

B. 在单链表末尾添加一个元素。

C. 删除单向循环链表的头结点。

D. 删除双向循环链表的头结点。

按照题库默认的常规实现条件，答案为D。

原因在于双向循环链表能够直接获得前驱和后继，从而不需要遍历链表寻找需要修改的相邻结点。

这道模拟题的题干不够严谨：“头结点”与“首元结点”需要区分，而且如果B额外提供尾指针，也能在常数时间完成。因此真正应该掌握的是操作依赖的条件，而不是记住答案D。

**做复杂度选择题，先找题目已经提供了哪些指针，再判断是否需要遍历。**

### 7.3 代表真题：2013年408——有序链表合并

已知两个长度分别为 $m$ 和 $n$ 的升序链表，将它们合并为一个长度为 $m+n$ 的降序链表，求最坏情况下的时间复杂度。

选项为：

A. $O(n)$

B. $O(mn)$

C. $O(\min(m,n))$

D. $O(\max(m,n))$

#### 解题思路

两个原始链表：

```text
L1：1 → 3 → 5

L2：2 → 4 → 6
```

每次比较两个链表当前的首元结点，取较小者，采用头插法插入结果链表。

| 取出的元素 | 结果链表                  |
| ----- | --------------------- |
| 1     | 1                     |
| 2     | 2 → 1                 |
| 3     | 3 → 2 → 1             |
| 4     | 4 → 3 → 2 → 1         |
| 5     | 5 → 4 → 3 → 2 → 1     |
| 6     | 6 → 5 → 4 → 3 → 2 → 1 |

最终得到降序链表。

因为每个结点只需要处理一次，而每次头插为 $O(1)$，所以时间复杂度为：

$$
T(m,n)=\Theta$m+n$
$$

又因为：

$$
\max(m,n)\leq m+n\leq 2\max(m,n)
$$

因此：

$$
\Theta$m+n$=\Theta(\max(m,n))
$$

选择 **D**。

#### 这道题考查了三个可以迁移的重要知识

第一，有序序列合并不需要每个元素与另一个序列的所有元素比较，可以使用双指针思想。

第二，按照升序取出元素，再使用头插法，就可以得到降序链表。

第三，两个输入规模相加时，渐进复杂度等价于取它们的最大值。

$$
O$m+n$=O(\max(m,n))
$$

但不能随意将其写成 $O(n)$，因为题目没有说明 $m$ 与 $n$ 的大小关系。

## 八、补充基础：顺序表的移动次数

这12道题主要集中在链式存储，因此顺序表移动次数没有被独立考查。但它属于第2章的重要基础知识，值得补充掌握。

### 8.1 顺序表插入元素

长度为 $n$ 的顺序表，在第 $i$ 个位置插入元素，其中：

$$
1\leq i\leq n+1
$$

需要移动原来的第 $i$ 至第 $n$ 个元素。

移动次数：

$$
M=n-i+1
$$

| 插入位置      | 移动次数    |
| --------- | ------- |
| 第一个位置     | $n$     |
| 最后一个位置    | $0$     |
| 第 $i$ 个位置 | $n-i+1$ |

若每个合法插入位置等概率出现，则平均移动次数为：

$$
E_{\text{insert}} =\frac{1}{n+1}\sum_{i=1}^{n+1}$n-i+1$ =\frac n2
$$

### 8.2 顺序表删除元素

删除第 $i$ 个元素，需要将其后面的所有元素向前移动。

移动次数：

$$
M=n-i
$$

若每个删除位置等概率出现，则平均移动次数为：

$$
E_{\text{delete}} =\frac1n\sum_{i=1}^{n}$n-i$ =\frac{n-1}{2}
$$

因此，顺序表任意位置插入、删除的平均时间复杂度均为：

$$
O$n$
$$

不必机械地记忆公式。只需要问自己：**操作位置后面有多少个必须移动的元素？**

## 九、本章选择题的统一解题方法

### 方法一：固定结点名称，动态更新指向

适用于所有指针代码题。

不要在草稿纸上只写 `p->next->next` 之类的表达式，而是给真实结点命名为A、B、C、D。

例如：

```text
初始：

p → A → B → C

执行 p->next = p->next->next 后：

p → A ───→ C
```

每执行一条语句，就更新一次指向关系。

尤其注意 `p->next` 是否已经被前面的语句改变。

### 方法二：先确定目标结构，再反推代码

适用于链表插入、删除题。

```text
单链表插入：A → X → B

单链表删除：A → B

双链表插入：A ⇄ X ⇄ B

双链表删除：A ⇄ B
```

不需要先读懂所有复杂选项，只需要确定最终哪些指针应该指向谁，再检查选项是否满足。

### 方法三：极端情况排除法

适用于循环链表、头尾指针维护题。

只含一个结点、空表、删除最后一个结点等极端情况，经常能够直接排除错误选项。

一个算法在普通情况下正确，并不代表它在题目允许的所有情况下都正确。

### 方法四：定位与修改分离

适用于时间复杂度题。

$$
T=T_{\text{定位}}+T_{\text{修改}}
$$

先判断是否需要遍历，再判断具体需要修改或移动多少元素。

### 方法五：识别基本操作的组合

适用于多行链表代码。

看到：

```c
q = p->next;
p->next = q->next;
```

识别为摘除后继。

看到：

```c
q->next = h->next;
h->next = q;
```

识别为头插。

两者组合就是移动结点。

复杂算法往往是简单操作的组合，学会识别这些基本操作，就不容易被长代码迷惑。

## 十、必须避免的高频错误认知

| 错误认知                   | 正确理解                |
| ---------------------- | ------------------- |
| 链表插入、删除一定是 $O(1)$      | 还需要考虑定位成本           |
| 链表有尾指针，就能快速删除尾结点       | 单链表仍可能需要寻找尾结点的前驱    |
| 静态链表使用数组，所以能够按逻辑序号随机访问 | 仍然需要沿链接域查找          |
| 头结点就是第一个数据结点           | 头结点通常不属于有效数据元素      |
| 非空链表至少有两个元素            | 可能只有一个元素            |
| 修改指针变量就是修改链表           | 修改结点的链接域才可能改变结构     |
| 指针赋值语句可以随意交换           | 交换可能覆盖旧连接，产生断链或自环   |
| 从链表中删除结点必须立即释放         | 如果要移动结点，则不应释放       |
| 循环链表的尾结点指向NULL         | 带头结点的循环链表尾结点指向头结点   |
| 双链表的插入与删除需要维护的连接数量相同   | 插入建立四条连接，删除通常修改两条连接 |

## 十二、最后浓缩：真正需要记在脑子里的知识

复习本章时，优先回顾以下八条结论：

1. 顺序表靠位置体现逻辑关系，链表靠链接体现逻辑关系。
2. 插入结点时，必须保护仍然需要使用的旧连接。
3. 删除结点的本质是让前驱绕过待删结点。
4. 双链表必须同时维护前驱和后继关系。
5. 头插逆序，尾插保序。
6. 循环链表尤其要注意空表、唯一结点和尾指针。
7. 静态链表的数组下标相当于动态链表中的地址。
8. 操作的时间复杂度取决于定位成本和修改成本。

**最值得反复研究的三道真题，是2023年408双链表插入、2021年408循环链表删除、2024年408单链表结点移动。**

它们分别训练了动态指针追踪、边界条件分析、基本操作组合这三种核心能力。
