## 第1套试卷 · 第45题

<Question id="wd408-2027-s01-q45" type="essay" number={45} points={8} tags="王道8套卷, 第1套, 操作系统, 进程与线程, 考点:生产者消费者问题, 考点:信号量P-V操作, 考点:有界生产量差约束">

两个生产者进程 A、B 和一个销售者进程 C 共享一个**容量无限**的仓库。A、B 每次循环各生产一件相应类型产品并入库；C 每次循环从仓库取出一件产品销售。任何时刻都**不允许两个入库操作同时执行**，也不允许入库与出库同时执行。自程序开始至当前时刻，**累计生产**的 A、B 产品件数满足

$$
-n\le N_A-N_B\le m,
$$

其中 $m,n$ 均为正整数。**该约束仅针对累计生产量**，不针对仓库当前剩余的 A、B 产品数量。请用信号量机制写出 A、B、C 三个进程的循环工作流程，并说明信号量初值与作用。

<Solution>

### 参考答案

设置四个信号量：

| 信号量 | 初值 | 作用 |
| --- | :---: | --- |
| `allowA` | $m$ | A 继续生产所能使用的差额许可，防止 $N_A-N_B>m$ |
| `allowB` | $n$ | B 继续生产所能使用的差额许可，防止 $N_B-N_A>n$ |
| `mutex` | 1 | 仓库入库／出库操作的互斥 |
| `products` | 0 | 当前仓库**已有产品**的数量，保证 C 不会取空 |

**P、V 伪代码：**`P(s)` 为等待/申请，`V(s)` 为释放/通知；`warehouse.put()` 和 `warehouse.take()` 仅操作共享仓库。

```c
semaphore allowA = m;
semaphore allowB = n;
semaphore mutex = 1;
semaphore products = 0;

process A {
    while (true) {
        P(allowA);             // 先取得 A 生产许可
        item x = produceA();  // 累计生产量 N_A 增加 1
        P(mutex);
        warehouse.put(x);
        V(mutex);
        V(products);           // 入库完成后才通知消费者
        V(allowB);             // A 每生产一件，B 的差额上限放宽 1
    }
}

process B {
    while (true) {
        P(allowB);
        item x = produceB();  // 累计生产量 N_B 增加 1
        P(mutex);
        warehouse.put(x);
        V(mutex);
        V(products);
        V(allowA);             // B 每生产一件，A 的差额上限放宽 1
    }
}

process C {
    while (true) {
        P(products);          // 仓库有产品才允许出库
        P(mutex);
        item x = warehouse.take();
        V(mutex);
        sell(x);
    }
}
```

**正确性说明：**

- `allowA=m`：A 最多可以**先于 B**生产 $m$ 件；每次 B 生产完一件就释放一个 A 的许可，因此 A 与 B 的生产差额不会超过 $m$。
- 对称地，`allowB=n` 保证 B 不会比 A 多生产超过 $n$ 件。两方生产时都在正式生产前取得许可，因此即使生产与入库并发也不会突破边界。
- `mutex` 只负责**真正读写共享仓库**时的互斥，不必把 `produceA()`、`produceB()` 或 `sell()` 放入临界区，避免不必要的串行化。
- `products` 初始为 0。入库后才 `V(products)`，消费者出库前先 `P(products)`，故不会卖出不存在的产品；无限仓库**不需要**表示空闲库位的计数信号量。

**边界验算：**若 $m=2,n=1$，A 已连续生产两件，则 `allowA=0`，第三次 A 生产必须等待 B 生产一件并 `V(allowA)`；若 B 比 A 多生产一件，则 B 也必须等待 A。即保持

$$
\boxed{-n\le N_A-N_B\le m}.
$$

**易错点：**生产量差的许可**不能**通过 C 的出售动作来释放；C 改变的是仓库库存量，不改变 A、B 的**累计生产量**。也不能在持有仓库互斥锁时等待 `products`，否则可能阻止生产者入库。

</Solution>
</Question>

## 第2套试卷 · 第45题

<Question id="wd408-2027-s02-q45" type="essay" number={45} points={7} tags="王道8套卷, 第2套, 操作系统, 进程与线程, 考点:多生产者装配同步, 考点:计数信号量, 考点:有限缓冲区互斥">

一个产品由 **1 件零件 A 和 3 件零件 B** 装配组成。有 5 条并行生产线：1 条生产 A，3 条生产 B，1 条负责装配。装配线的待装配暂存区最多容纳 **1 件 A** 和 **3 件 B**。如果 A 已有 1 件待装配，则 A 生产线须等待；B 已有 3 件待装配，则 B 生产线须等待。装配线凑足 1 件 A 和 3 件 B 后完成一次组装，再允许等待的生产线继续进入下一轮。

试用 P、V 操作描述零件生产线和装配线的同步互斥。假设 A、B 暂存区的数据结构及零件搬运均受同一个互斥锁保护。

<Solution>

### 参考答案

**先建立两个容量不同的有限缓冲区：**

- A 暂存区：空位 `emptyA=1`；已就绪零件 `fullA=0`。
- B 暂存区：空位 `emptyB=3`；已就绪零件 `fullB=0`。
- `mutex=1`：互斥访问两类共享暂存区。

```c
semaphore emptyA = 1, fullA = 0;
semaphore emptyB = 3, fullB = 0;
semaphore mutex = 1;

process ProduceA {             // 仅一条 A 生产线
    while (true) {
        P(emptyA);              // 留出 A 的 1 个待装配位置
        item a = makeA();
        P(mutex);
        bufferA.put(a);
        V(mutex);
        V(fullA);               // A 已备好
    }
}

process ProduceB {             // 下面过程有 3 个并行实例
    while (true) {
        P(emptyB);              // B 总共只能存 3 件
        item b = makeB();
        P(mutex);
        bufferB.put(b);
        V(mutex);
        V(fullB);               // 又有 1 件 B 已备好
    }
}

process Assemble {
    while (true) {
        P(fullA);               // 等到 1 件 A
        P(fullB);               // 等到第 1 件 B
        P(fullB);               // 等到第 2 件 B
        P(fullB);               // 等到第 3 件 B

        P(mutex);
        item a = bufferA.take();
        item b1 = bufferB.take();
        item b2 = bufferB.take();
        item b3 = bufferB.take();
        V(mutex);

        assemble(a, b1, b2, b3); // 每轮恰好消耗 1A + 3B

        V(emptyA);              // 本轮装配完成，释放 A 位置
        V(emptyB);              // 释放 B 的 3 个位置
        V(emptyB);
        V(emptyB);
    }
}
```

**正确性与活性：**

1. A 生产线第一次取得 `emptyA` 后，在装配完成以前不能取得第二个 A 空位，因此不会预存 2 件 A；B 的三个并行实例合计最多取得 3 个 B 空位，因而不超过暂存区容量。
2. 装配线只有取得 `fullA` 和**三个** `fullB` 许可后才开始装配，故每次消耗比例严格为 $1:3$。
3. 在获取 `fullA`、`fullB` 时**不持有 `mutex`**，否则装配线可能拿着互斥锁等待零件、生产线却无法入库，导致死锁。
4. 把 `V(emptyA/B)` 放在 `assemble()` **之后**，满足“完成组装再唤醒等待的生产线”的约定。若题目另约定零件被取走即释放空间，也可以在取出零件后、正式装配前通知空位，但那属于不同的暂存区占用规则。

**易错点：**三条 B 生产线共享**同一个** `emptyB/fullB` 计数信号量，而不是为每条 B 线各设 3 个空位；`fullB` 必须进行 3 次 P 操作，不能只等到 1 件 B 就装配。

</Solution>
</Question>

## 第3套试卷 · 第45题

<Question id="wd408-2027-s03-q45" type="essay" number={45} points={7} tags="王道8套卷, 第3套, 操作系统, 进程与线程, 考点:读者写者类同步, 考点:同向共享与异向互斥, 考点:饥饿控制">

猴子通过一根横跨峡谷、南北方向的绳索：**同方向**可以有多只猴子同时通过；如果南行猴子与北行猴子同时位于绳索上，则可能卡住而产生死锁。每只猴子在进入绳索前必须确认没有相反方向的猴子正在通过。

请使用 P、V 操作设计同步方案，使**任何时刻同一绳索上只存在一种行进方向**，同时允许同向并发通过。请说明若希望避免某一方向长期等待，可如何改进。

<Solution>

### 参考答案

此题的核心是**同方向类似多个读者共享资源、反方向类似互斥访问**。用计数变量记录当前已进入绳索的两种猴子的数量；仅方向中的**第一只**猴子需要申请绳索，**最后一只**离开时才释放绳索。

**推荐方案：加入公平入口 `turnstile`，抑制反方向饥饿。**

```c
semaphore rope = 1;            // 占有绳索的方向（只能有一个）
semaphore mutexN = 1;          // 北行计数器的锁
semaphore mutexS = 1;          // 南行计数器的锁
semaphore turnstile = 1;       // 控制新进入者的先后顺序
int north = 0, south = 0;

process GoNorth {               // 每只北行猴子执行
    P(turnstile);               // 先过公共入口闸机
    P(mutexN);
    north++;
    if (north == 1)
        P(rope);                // 本方向首只猴子取得绳索
    V(mutexN);
    V(turnstile);

    crossNorth();               // 同向多只猴子可并行

    P(mutexN);
    north--;
    if (north == 0)
        V(rope);                // 本方向最后一只离开
    V(mutexN);
}

process GoSouth {               // 每只南行猴子执行
    P(turnstile);
    P(mutexS);
    south++;
    if (south == 1)
        P(rope);
    V(mutexS);
    V(turnstile);

    crossSouth();

    P(mutexS);
    south--;
    if (south == 0)
        V(rope);
    V(mutexS);
}
```

**为何不会出现南北同时通过？**

- 如果已有北行猴子，那么 `rope=0`，南行方向的第一只猴子在 `P(rope)` 阻塞，不能进入绳索；反之亦然。
- 后续北行猴子只增加 `north` 计数，不再执行 `P(rope)`，因此北行可**多人并发**。只有最后一只北行猴子离开才会 `V(rope)`，使另一个方向有机会通过。
- 修改 `north/south` 计数时必须持有对应的 `mutexN/mutexS`，防止两只同向猴子同时误以为自己是“第一只”或“最后一只”。

**公平入口的作用：**在正常公平信号量唤醒假设下，如果有南行猴子开始等待北行队伍结束，它会占着 `turnstile` 等待 `rope`，后续新来的北行猴子便不能无限制地加入正在通行的北行队伍；现有北行猴子陆续离开后，南行最终可以获得绳索。若信号量不保证公平唤醒，则严格的有界等待还需要一个 FIFO 队列或票号机制，仅凭普通信号量不保证绝对公平。

**不加 `turnstile` 也可解决互斥**，只用 `rope/mutexN/mutexS` 和首进末出的计数模式即可，但持续不断涌入的某一方向可能造成另一方向**饥饿**。使用入口闸机属于为保证公平性增加的控制。

**易错点：**不能要求每只同向猴子各自取得 `rope`，否则会错误地强制单只通过；也不能只用一个方向布尔标志而不保护该标志的并发更新。

</Solution>
</Question>

## 第4套试卷 · 第45题

<Question id="wd408-2027-s04-q45" type="essay" number={45} points={7} tags="王道8套卷, 第4套, 操作系统, 进程与线程, 考点:最短剩余时间优先SRTF, 考点:内存首次适应与静态打印机分配, 考点:进程调度甘特图">

某多道程序设计系统供用户进程使用的内存共 **100 K**，打印机 **1 台**。内存采用**可变分区、首次适应算法**，优先分配低地址的连续空闲区域，**禁止移动已装入内存的进程**。打印机采用**静态分配**：进程获准进入内存参与调度时，如申请打印机，须同时获得它，并在整个进程执行期间占有，直到结束才释放。忽略 I/O 用时。CPU 使用**可抢占的最短剩余时间优先（SRTF）**，剩余时间相同者按先来先服务。调度可能发生在进程完成或新进程到达时；仅**已经获得所需内存及打印机的进程**能够参与 CPU 调度。

| 进程 | 到达时刻 | CPU 总执行时间 | 需求内存 | 需求打印机 |
| :---: | :---: | :---: | :---: | :---: |
| P1 | 0 | 8 | 15 K | 1 台 |
| P2 | 4 | 4 | 30 K | 1 台 |
| P3 | 10 | 1 | 60 K | 0 台 |
| P4 | 11 | 20 | 20 K | 1 台 |
| P5 | 16 | 14 | 10 K | 1 台 |

1. 给出 CPU 的**进程执行次序**及关键时刻的选择理由。
2. 计算从时刻 0 开始到全部进程结束的**总历时**。

<Solution>

### 参考答案

**（1）CPU 执行的进程序列为**

$$
\boxed{\mathrm{P1\to P2\to P3\to P2\to P4\to P5}}.
$$

**关键原则：进程“到达”不等于“具备运行资格”。**它必须同时取得所需的连续内存和打印机后才能进入就绪队列参与 SRTF 比较；被抢占但尚未结束的进程**继续占有内存和打印机**。

| 时刻 | 资源、进程状态与调度决定 |
| --- | --- |
| **0** | P1 获得 15 K 内存及唯一的打印机，开始运行。 |
| **4** | P2 到达，虽有足够内存，但**打印机仍被 P1 占用**，不能参与就绪调度；P1 继续。 |
| **8** | P1 完成并释放资源。P2 获得 30 K 内存和打印机，开始运行，尚需 4 时间单位。 |
| **10** | P3 到达，不需要打印机；P2 占用 30 K 内存，尚有 70 K 可用，可分配给 P3 的 60 K。P2 已运行 2 个单位，剩余 **2**；P3 仅需 **1**，所以 P3 **抢占** P2。P2 保留打印机。 |
| **11** | P3 完成释放 60 K。P4 到达但需打印机，**P2 尚未释放打印机**，P4 暂不能运行。P2 恢复运行，剩余 2。 |
| **13** | P2 完成，释放打印机和 30 K 内存；P4 随后获准装入内存并占有打印机，开始运行，需要 20。 |
| **16** | P5 到达，但打印机被 P4 持有，不能抢占 P4；P4 继续。 |
| **33** | P4 结束并释放资源；P5 获得 10 K 内存与打印机，开始运行，需要 14。 |
| **47** | P5 完成；所有进程结束。 |

**CPU 甘特图：**

```text
时间  0        8   10 11  13                  33             47
      |---P1---|P2--|P3|P2|---------P4---------|-----P5-------|
      0        8   10 11  13                  33             47
```

实际时间段：

| 时间区间 | 运行进程 | 本次实际运行时长 |
| --- | --- | ---: |
| $[0,8)$ | P1 | 8 |
| $[8,10)$ | P2 | 2 |
| $[10,11)$ | P3 | 1 |
| $[11,13)$ | P2 | 2 |
| $[13,33)$ | P4 | 20 |
| $[33,47)$ | P5 | 14 |

**（2）全部进程结束时间为 $\boxed{47}$。**

$$
T_{\rm total}=8+4+1+20+14=\boxed{47\text{ 个时间单位}}.
$$

在给定到达时刻与静态分配条件下，CPU 始终有能够运行的进程，所以这里没有空闲段，总历时等于各进程执行时长之和。

**资源与算法核对：**

- 时刻 10：仅 P2 与 P3 同时驻留主存，共 $30+60=90\ \mathrm{K}\le100\ \mathrm{K}$；P3 能装入并抢占 P2。
- 时刻 11：P4 即使有内存也**拿不到打印机**，不能以自己的 20 时间单位和 P2 剩余 2 比较。
- 时刻 16：P5 的执行时间 14 比 P4 当时剩余 17 更短，**但 P5 无打印机无法参与 SRTF**。若错误地忽略静态打印机占用，就会得到错误的调度次序。
- 首次适应与不移动条件在本题给定资源释放时序下不造成额外碎片阻塞，但仍应先判断内存能否连续分配，不能只比较 CPU 执行时间。

</Solution>
</Question>

## 第5套试卷 · 第45题

<Question id="wd408-2027-s05-q45" type="essay" number={45} points={8} tags="王道8套卷, 第5套, 操作系统, 进程与线程, 考点:多生产者多消费者广播缓冲区, 考点:计数信号量, 考点:缓冲区引用计数">

设有 $n_1$ 个发送进程 $A_1,\ldots,A_{n_1}$ 和 $n_2$ 个接收进程 $B_1,\ldots,B_{n_2}$，共享 $m$ 个消息缓冲区。要求：

1. 每个 $A_i$ 一次发送一条消息，写入一个缓冲区；缓冲区恰好能容纳一条消息。
2. **每一条消息必须被所有 $n_2$ 个 $B_j$ 分别接收且各接收一次**；所有接收者均读完后，该缓冲区才可重用。
3. 所有缓冲区均在使用时发送者等待；某接收者没有下一条未读消息时，该接收者等待。

试用 `wait` / `signal`（P / V）操作给出同步算法。设 $m,n_1,n_2\ge1$，且**每个接收者均按统一发送顺序读取消息**。

<Solution>

### 参考答案

本题**不是普通的“消费者拿走即删除”模型**，而是“一写多读”的广播模型。不能让某个接收者第一次读完就释放缓冲区；需要知道该消息还有多少个接收者尚未读取。

把 $m$ 个缓冲区组成环形队列。发送者统一按 `tail` 指针写入；每个接收者 $B_j$ 都有自己的 `head[j]`，表示**该接收者下一条待读消息的位置**。每个缓冲区记录尚未阅读它的接收者人数 `remain[k]`。

| 共享变量／信号量 | 初值 | 含义 |
| --- | --- | --- |
| `empty` | $m$ | **所有接收者均读过**、可供发送者重用的缓冲区数 |
| `ready[j]` | $0$（每个 $B_j$ 各一个） | 已发送、尚未被 $B_j$ 读取的消息数 |
| `mutex` | $1$ | 对环形缓冲区、`tail` 和 `remain` 的互斥访问 |
| `tail` | $0$ | 全体发送者的下一个写入位置 |
| `head[j]` | $0$（每个 $B_j$ 各一个） | $B_j$ 下一个读取位置 |
| `remain[k]` | $0$ | 第 $k$ 号缓冲区尚需阅读的接收者数量 |

**P / V 伪代码：**假设 `copy_to_local()` 将消息复制到该接收者的私有内存，`make_message()` 在临界区外生成消息。

```c
semaphore empty = m, mutex = 1;
semaphore ready[n2] = {0};
Message buffer[m];
int remain[m] = {0};
int tail = 0, head[n2] = {0};

process Sender(i) {                   // i=0,...,n1-1，多个实例
    while (true) {
        Message msg = make_message(i);
        wait(empty);                  // 没有完全释放的缓冲区则等待
        wait(mutex);
        buffer[tail] = msg;
        remain[tail] = n2;           // 本条消息要被 n2 人各读一次
        tail = (tail + 1) % m;
        for (int j = 0; j < n2; ++j)
            signal(ready[j]);        // 每个接收者各获得一次读取许可
        signal(mutex);
    }
}

process Receiver(j) {                 // j=0,...,n2-1，各运行一个实例
    while (true) {
        wait(ready[j]);              // 该接收者尚无未读消息则等待
        wait(mutex);
        int k = head[j];
        Message own = copy_to_local(buffer[k]);
        head[j] = (head[j] + 1) % m;
        remain[k]--;
        if (remain[k] == 0)
            signal(empty);           // 最后一位读者读完，才允许复用
        signal(mutex);
        process_message(j, own);     // 在临界区外处理私有副本
    }
}
```

**正确性：**

1. 每个发送进程写入前必须 `wait(empty)`，因此最多有 $m$ 条未被所有接收者读完的消息，占用数量不越界。发送者通过 `mutex` 串行更新 `tail`，形成**唯一的消息顺序**。
2. 每发送一条消息，就对每个 `ready[j]` 各进行一次 `signal`；每个 $B_j$ 每消费一次许可，只读自己 `head[j]` 所指的一条消息并前移一次，故每个接收者对每条消息**恰好读一次**。
3. 最后一个读者把 `remain[k]` 减到 0 时才 `signal(empty)`，此前生产者无法改写该槽位，不会出现“部分接收者尚未读完就覆盖”的错误。
4. 所有接收者按相同 FIFO 顺序前移。**能读完较后消息的每个读者，一定先读完较早消息**，因此缓冲区也按写入先后顺序完成全部阅读，环形 `tail` 不会覆盖仍在用的较早槽位。
5. `wait(empty)`、`wait(ready[j])` 均放在 `mutex` 外面；不会出现持锁等待另一方释放资源而导致的死锁。临界区里只进行无阻塞的 `signal` 操作及短暂的数据复制。

**易错点：**仅使用一对普通的 `full/empty` 信号量，无法保证同一条消息被**全部** $n_2$ 位接收者读到；若任何 $B_j$ 在第一次读取后就 `signal(empty)`，发送者可能过早覆盖该消息。这里 `ready[j]` 必须**各接收者独立**，`remain[k]` 必须**按缓冲区独立**。

</Solution>
</Question>

## 第7套试卷 · 第45题

<Question id="wd408-2027-s07-q45" type="essay" number={45} points={7} tags="王道8套卷, 第7套, 操作系统, 进程与线程, 考点:三级流水线同步, 考点:双缓冲区, 考点:信号量P-V操作">

三个进程 PA、PB、PC 合作顺序打印文件：PA 每次从磁盘**读取一条记录**写入缓冲区 1；PB 每次将缓冲区 1 的一条记录**复制**到缓冲区 2；PC 每次打印缓冲区 2 中的一条记录。**两个缓冲区都恰好只能容纳一条记录**。使用 P、V 操作保证不覆盖尚未使用的数据、不读取空缓冲区，且输出记录顺序不变。

<Solution>

### 参考答案

两个缓冲区分别设置“空位”和“已有记录”信号量，每个缓冲区只能在空／满两态间切换：

| 信号量 | 初值 | 含义 |
| --- | :---: | --- |
| `empty1` | 1 | 缓冲区 1 可写入 |
| `full1` | 0 | 缓冲区 1 有待复制记录 |
| `empty2` | 1 | 缓冲区 2 可写入 |
| `full2` | 0 | 缓冲区 2 有待打印记录 |

**P / V 伪代码：**用结束标记 `EOF_TOKEN` 表示文件已读完；它和普通记录走同一条流水线，PC 收到后结束，从而避免最后一条记录丢失。

```c
semaphore empty1 = 1, full1 = 0;
semaphore empty2 = 1, full2 = 0;
Record buffer1, buffer2;

process PA {                           // 磁盘 -> 缓冲区1
    while (true) {
        Record r = disk_read_or_eof(); // 顺序读一条；EOF 返回特殊标记
        P(empty1);                     // 确保不会覆盖未复制数据
        buffer1 = r;
        V(full1);                      // 通知 PB 有记录可复制
        if (is_eof(r)) break;
    }
}

process PB {                           // 缓冲区1 -> 缓冲区2
    while (true) {
        P(full1);                      // 先确保缓冲区1有记录
        P(empty2);                     // 再确保缓冲区2可写
        Record r = buffer1;
        buffer2 = r;
        V(empty1);                     // 复制完即可释放缓冲区1
        V(full2);                      // 缓冲区2现可被 PC 读取
        if (is_eof(r)) break;
    }
}

process PC {                           // 缓冲区2 -> 打印机
    while (true) {
        P(full2);
        Record r = buffer2;
        if (!is_eof(r)) printer_print(r);
        V(empty2);                     // 打印完成后才释放缓冲区2
        if (is_eof(r)) break;
    }
}
```

**同步顺序：**

$$
\text{PA写缓冲1}\xrightarrow{V(full1)}
\text{PB复制缓冲1至2}\xrightarrow{V(full2)}
\text{PC打印缓冲2}.
$$

- PA 取得 `empty1` 才能覆盖缓冲区 1；PB 完成复制后才 `V(empty1)`。
- PB 取得 `empty2` 才能写缓冲区 2；PC **完成打印**后才 `V(empty2)`，避免打印中被覆盖。
- 只有一个 PA、一个 PB、一个 PC，且每个缓冲区只存在对应的单写者／单读者，使用各自一对计数信号量已经保证访问次序，**无需额外互斥锁**。
- 数据按 `PA → PB → PC` 的先后顺序逐条传递；不同记录可分别位于读取、复制、打印三个阶段，实现流水线并行。

**易错点：**`P(full1)`、`P(full2)` 必须在读取对应缓冲区之前；`V(empty1)` 必须在 PB 完成复制之后，`V(empty2)` 必须在 PC 完成打印之后；将它们提前会出现读空或数据覆盖。

</Solution>
