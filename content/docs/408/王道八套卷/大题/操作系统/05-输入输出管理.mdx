# 操作系统 · 第5章 输入输出管理

本章收录综合应用题 **2** 道，按第 1～8 套试卷的顺序排列；题号保留原试卷编号。


## 第2套试卷 · 第46题

<Question id="wd408-2027-s02-q46" type="essay" number={46} points={8} tags="来源:王道8套卷第2套, 考点:中断驱动I-O, 考点:终端输出队列, 考点:阻塞唤醒与上下文">

进程 `P` 在用户态执行 `putchar('X')`，系统通过**中断驱动**向终端输出字符。内核维护一个有容量上限的待发送队列 `outq`；设备寄存器 `DATA` 和状态位 `READY` 满足：`READY=1` 表示设备空闲，向 `DATA` 写一个字符可启动发送；字符发送完毕时硬件置 `READY=1` 并产生发送完成中断。字符被系统接收并入队、必要时启动发送后，`putchar/write` **可提前返回用户态**，无需等终端显示完成。

为避免“已启动发送的字符还留在队列、随后被重复发送”的原文歧义，约定：**③ 从 `outq` 队首取出一个字符并写 `DATA`；⑦ 也先检查 `outq` 是否非空，非空时取出队首字符写 `DATA`。已提交 `DATA` 的字符不再位于待发送队列中。**

操作编号（编号只标识操作，不表示发生顺序）：

| 编号 | 操作 |
| :---: | --- |
| ① | `P` 执行系统调用陷入内核态 |
| ② | 把 `X` 追加到 `outq`（队满则需等待空位） |
| ③ | 当 `READY=1` 且 `outq` 非空时，取出队首字符写入 `DATA`，启动发送 |
| ④ | `P` 从系统调用返回用户态 |
| ⑤ | 本次硬件发送完成并产生中断请求 |
| ⑥ | CPU 响应中断，进入中断处理程序 |
| ⑦ | ISR：若 `outq` 非空，取出下一字符写 `DATA`；否则结束此次数据提交 |
| ⑧ | `outq` 已满时将 `P` 加入阻塞队列 |
| ⑨ | ISR 发现 `outq` 出现可用位置时，唤醒 `P` 并置为就绪 |

1. 初始 `outq` 为空、`READY=1`，从 `putchar('X')` 到系统调用返回，再到随后一次发送完成中断处理，写出主要编号顺序。
2. 初始 `outq` 已满且设备正忙（`READY=0`），指出导致 `P` 阻塞及重新就绪的编号，并写出恢复执行直至返回用户态的关键链路。
3. 把操作①～⑨归为“进程上下文（系统调用路径）”“ISR／中断入口处理”“硬件事件”三类。
4. 执行⑥⑦时 `P` 可能处于哪些进程状态？此时 CPU 是内核态还是用户态？至少举两种场景。

<Solution>

### 参考答案

**（1）可写为：** `① → ② → ③ → ④ → ⑤ → ⑥ → ⑦`。

先由 `P` 陷入内核、入队，再由③取出 `X` 写入 `DATA`。由于字符已被成功提交给设备，`P` 可以先执行④返回；设备随后完成发送并产生中断⑤，CPU 进入 ISR⑥，执行⑦。此时队列若仍为空，⑦只检查队列并结束，不再次写 `X`。

**（2）阻塞操作为 `⑧`，唤醒操作为 `⑨`。**

初始调用后，若 `outq` 已满，`P` **不能执行②完成入队**，应先阻塞。关键事件顺序可以写成：`① → ⑧ → ⑤ → ⑥ → ⑦ → ⑨ → ② → ④`。

⑤⑥⑦代表设备先发送完成，然后 ISR 从满队列取走一个待发字符并提交到 `DATA`，使队列出现空位；⑨将 `P` 从阻塞队列转入就绪队列。**调度器重新选中 P 后**，`P` 才继续执行②，将 `X` 入队；若这时设备仍忙，不应再执行③。后续在 `READY=1` 时由 ISR 或系统调用路径启动待发数据。此顺序省略了与 `P` 无关的其他进程及调度细节。

**（3）操作归类：**

| 执行场景 | 编号 | 理由 |
| --- | --- | --- |
| `P` 的进程上下文／系统调用路径 | ①②③④⑧ | 系统调用、入队、启动发送、阻塞和返回都可在进程的内核执行路径中发生 |
| 中断入口与 ISR | ⑥⑦⑨ | CPU 中断入口、ISR 启动下一字符、唤醒被阻塞进程 |
| 硬件事件 | ⑤ | 发送完成后由控制器提出中断请求 |

注：⑥的中断**响应、现场保存**涉及 CPU 硬件与内核入口代码的协作；这里按题目要求归入 ISR／中断处理路径，而不误算成用户态执行。

**（4）执行⑥⑦时 CPU 一定处于** $\boxed{\text{内核态}}$（特权态），`P` 的状态**并不唯一**：

- **就绪／暂时中断的运行态**：`P` 可能此前已通过④返回用户态，然后恰好执行 `P` 时终端中断到来。中断入口令 CPU 转入内核态，返回后 `P` 可恢复执行。若其间 CPU 调度了别的进程，`P` 则可能在就绪队列等待。
- **阻塞态**：`P` 正因 `outq` 满执行⑧而等待。此时设备中断由正在运行的**其他进程**所在 CPU 响应，ISR 释放空位后通过⑨才可将 `P` 唤醒。

### 易错点

1. **中断到来不等于调用它的进程必在运行。** 中断与发起 I/O 的进程异步。
2. `putchar()` 的返回时刻不必等于字符实际输出完成时刻。
3. **排队字符与正在 DATA 中发送的字符不能重复计数。** 如果采用“队列包含正在发送的字符”的另一种实现，应相应修改出队时刻，而不是让③⑦重复发送相同数据。

</Solution>
</Question>

## 第6套试卷 · 第46题

<Question id="wd408-2027-s06-q46" type="essay" number={46} points={8} tags="来源:王道8套卷第6套, 考点:SSTF磁盘调度, 考点:SCAN与C-SCAN, 考点:磁臂黏着, 考点:磁盘访问时间与DMA">

磁盘 I/O 请求队列的柱面号依次为

`35, 58, 40, 28, 80, 160, 143, 38, 204`，

磁头初始位置为 `95`，**初始扫描方向为柱面号增大的方向**。

1. 用最短寻道时间优先（SSTF）算法，共移动多少个磁道？
2. 用 SCAN 算法，共移动多少个磁道？
3. 用 C-SCAN 算法，共移动多少个磁道？
4. 哪些常见调度算法可能发生“磁臂黏着”（某磁道频繁产生新请求，其他磁道长期得不到服务）？如何改善？
5. 一次磁盘读／写的时间包括哪些部分？磁盘调度算法主要优化哪一部分？通常用哪种 I/O 控制方式成批读写盘块？

**计算条件说明**：原题未提供磁盘的**最大柱面号**，因此严格按 SCAN/C-SCAN“到物理端点再返回”的定义，第（2）（3）问不能得出唯一具体数值。记柱面范围为 `0～M`（$M\ge204$）；返回路径的磁头移动也计入总磁道数。同时给出**若磁盘为 `0～299` 柱面**时的示例，以免将 LOOK/C-LOOK 的结果误充作 SCAN/C-SCAN。

<Solution>

### 参考答案

**（1）SSTF 总移动距离为 $\boxed{243}$ 个磁道。**

每步选择离当前柱面最近的**待处理请求**，顺序为：

`95 → 80 → 58 → 40 → 38 → 35 → 28 → 143 → 160 → 204`

$$
\begin{aligned}
D_{\rm SSTF}
&=15+22+18+2+3+7+115+17+44\\
&=\boxed{243}。
\end{aligned}
$$

**（2）SCAN：$\boxed{2M-123}$ 个磁道。**

沿增大方向先响应 `143,160,204`，然后仍到磁盘物理末端 `M` 才折返，下降方向响应 `80,58,40,38,35,28` 并在 `28` 结束：

$$
D_{\rm SCAN}=(M-95)+(M-28)=\boxed{2M-123}。
$$

若 $M=299$，则 $D_{\rm SCAN}=\boxed{475}$。

**（3）C-SCAN：$\boxed{2M-15}$ 个磁道。**

先在增大方向处理 `143,160,204` 并到 `M`；随后**不服务地回到柱面 `0`**，再沿增大方向处理 `28,35,38,40,58,80`，在 `80` 结束：

$$
\begin{aligned}
D_{\rm C\text{-}SCAN}
&=(M-95)+(M-0)+(80-0)\\
&=\boxed{2M-15}。
\end{aligned}
$$

若 $M=299$，则 $D_{\rm C\text{-}SCAN}=\boxed{583}$。

**与 LOOK／C-LOOK 的区别**：若未规定物理最大柱面并约定“只移到该方向最远请求就返回”，则实际上算的是：

$$
\begin{aligned}
D_{\rm LOOK}&=(204-95)+(204-28)=\boxed{285},\\
D_{\rm C\text{-}LOOK}&=(204-95)+(204-28)+(80-28)=\boxed{337}。
\end{aligned}
$$

**（4）SSTF、SCAN、C-SCAN 在允许新请求不断进入当前调度队列的实现下，都可能出现磁臂黏着**；FCFS 保证按到达先后服务，不会由后来的同一磁道请求持续插队。**可用 N-Step-SCAN 或 FSCAN**：处理当前被冻结的一批请求时，把新请求放进下一批，限制热点请求反复占用当前扫描。

说明：对一个**固定且有限、期间没有新到达请求**的队列，SCAN/C-SCAN 都会完成该批请求；“磁臂黏着”说的是持续有新请求插入的动态情形，不能与 SSTF 的静态算例混淆。

**（5）一次磁盘读／写的总时间**一般包括：

$$
T_{\rm disk}=T_{\rm seek}+T_{\rm rotation}+T_{\rm transfer}
$$

其中寻道时间是磁头移动到目标柱面的时间，旋转延迟是等待目标扇区转到磁头下方的时间，传输时间是数据实际从磁盘表面读写的时间。还可按具体系统计入控制器、排队及接口开销。

- **磁盘调度算法**主要减少磁头移动距离，从而优化**寻道时间**，不直接消除旋转延迟或数据传输时间。
- 磁盘块的**批量数据传输通常采用 DMA**（直接存储器访问）控制方式，完成后通过中断通知 CPU；不应理解为 CPU 为每个字节都执行程序查询搬运。

### 易错点

题目只给出**最大请求柱面 `204`**，并不意味着磁盘**最大可用柱面**就是 `204`。如果未提供 `M` 就武断给出 SCAN、C-SCAN 的单个数值，会将“真实扫到物理端点”和“只扫到最远请求”的两种算法定义混在一起。

</Solution>
</Question>
