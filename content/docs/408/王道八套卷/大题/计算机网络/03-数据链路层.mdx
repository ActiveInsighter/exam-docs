## 第1套试卷 · 第47题

某无线局域网采用 IEEE 802.11 DCF 工作方式，拓扑结构如下图所示。服务器 Host-S 通过 100Base-T 接口连接交换机 S，交换机通过 100Base-T 接口连接桥接模式接入点 AP；无线终端 STA1 和 STA2 关联到 AP。忽略 RTS/CTS，采用基本接入机制。TCP 连接已经建立，不讨论拥塞窗口的具体变化。

![](/images/27王道8套卷1025/p014-1.svg)

1. DCF 使用什么介质访问控制机制？与以太网 CSMA/CD 的主要区别是什么？
2. STA1 监听到信道忙后，信道转为空闲，发送普通数据帧前需要经历哪些等待／退避过程？为何 ACK 可以优先于新的竞争数据帧发送？
3. Host-S 向 STA1 发送 IP 分组，AP 在无线侧转发成一个 802.11 数据帧。STA1 接收的无线帧中，**地址 1、地址 2、地址 3** 分别是什么 MAC 地址？
4. STA1 通过 TCP 连续向 Host-S 发送多个数据段，**第一个 TCP 数据段在 STA1→AP 无线侧最终丢失（802.11 MAC 重试后仍未成功），而后续多个数据段到达 Host-S**。Host-S 随后的 TCP ACK 通常具有什么特征？在什么条件下 STA1 可进行快速重传？若条件不满足又会怎样？
5. STA1 与 STA2 均向 AP 发送数据，未启用 RTS/CTS 时仍可能遇到什么典型冲突问题？结合图说明出现条件。

### 参考答案

**（1）DCF 使用 CSMA/CA（载波监听多点接入／碰撞避免）。**

- **CSMA/CD（传统共享式半双工以太网）**：发送时仍监听介质，检测到碰撞便停止发送并进行退避；现代全双工交换以太网不再使用碰撞检测。
- **CSMA/CA（802.11 无线局域网）**：无线终端通常无法可靠地在自身发送过程中检测其他终端的碰撞，因此通过物理／虚拟载波监听、帧间间隔、随机退避以及**逐帧 ACK 与必要时重传**来降低并处理碰撞风险。不能理解为完全不会发生碰撞。

**（2）忙信道转空闲后的竞争发送步骤：**

1. 等待介质持续空闲达到 **DIFS**（常规 DCF 数据发送）；若恢复此前被冻结的退避，亦须先确认所需空闲间隔。
2. 使用或恢复随机退避计数器；信道在每个空闲时隙计数递减，遇忙即冻结，下一次空闲且满足 DIFS 后继续。
3. 计数减为 0 且介质保持空闲时发送数据帧；接收方成功校验后在 **SIFS** 之后发送链路层 ACK。

由于 $\mathrm{SIFS}<\mathrm{DIFS}$，接收方的 ACK 无需与等待 DIFS 的新数据帧竞争，因此具备优先发送机会。**802.11 的链路层 ACK 不是 TCP 的传输层 ACK。**

**（3）下行帧三地址：** AP→STA1 属于 `From DS = 1, To DS = 0` 的基础设施 BSS 数据帧。

| 802.11 字段 | 表示 | 按图得到的 MAC |
| --- | --- | --- |
| 地址 1 | 无线接收端／目的地址（RA/DA） | **STA1：`00-11-11-11-11-D1`** |
| 地址 2 | 发射端／BSSID（TA） | **AP：`00-11-11-11-11-C1`** |
| 地址 3 | 原始源地址（SA） | **Host-S：`00-11-11-11-11-88`** |

本图中 AP 是**桥**而非 IP 路由器，Host-S 发出的以太网帧转换为无线帧时，源端系统的 MAC 保留在地址 3 中；不能错误地把地址 3 写成 AP 的 MAC。

**（4）丢失后的 TCP 现象与重传：**

- Host-S 未收到首段时，累计确认号停留在**下一个期望接收的字节序号**。即使后续更高序号数据段乱序到达，接收端也通常反复发送**相同累计确认号的重复 ACK**，不因为收到后续段就越过缺口确认。
- 若 STA1 收到**3 个重复 ACK**，并且实现遵循经典 TCP 快速重传机制，则可以不等重传计时器期满，就重传首个未确认段。
- 如果后续段数量不足、重复 ACK 不足三个或相应机制未触发，则通过**重传超时 RTO**进行恢复。题干的“连续发送若干段”本身**不能保证**必定快速重传。
- 此题特意约定链路层重传后仍丢失：否则 802.11 MAC 自动重试成功时，TCP 可能**根本观察不到丢包**。

**（5）典型问题：隐藏终端（隐藏站）问题。**

若 STA1 和 STA2 均能与 AP 通信，但两终端因为距离／遮挡等原因**互相监听不到**对方，则两者都可能认为信道空闲而同时向 AP 发帧，在 AP 处碰撞。图中两站都与 AP 关联只提供这一问题的**可能拓扑**；若两站可以互相载波监听，就不能仅凭图断定它们一定是隐藏终端。RTS/CTS 在合适条件下可降低这种碰撞概率。

### 易错点

三种 ACK 必须区分：802.11 MAC ACK 确认**无线帧**，TCP ACK 确认**字节流**，二者可能经过不同次数的重传；普通 DCF 的优先发送由 **SIFS 与 DIFS 的长短关系**保证，而不是优先级队列。
