## 第6套试卷 · 第47题

<Question id="wd408-2027-s06-q47" type="essay" number={47} points={9} tags="来源:王道8套卷第6套, 考点:应用层, 考点:DNS解析时延, 考点:TCP握手RTT, 考点:HTTP持续连接, 考点:HTTP流水线与非流水线">

浏览器用户点击一个 URL，本地主机尚未缓存目标域名的 IP 地址，因此需要先进行 DNS 查询。假定按顺序共查询 $n$ 台 DNS 服务器，每次查询与应答耗时均为 $\mathrm{RTT}$；主机与 Web 服务器的往返时延为 $\mathrm{RTT}_w$。各次 TCP 连接均需要一次三次握手，忽略 DNS 之外的排队、计算处理时间以及小对象的实际发送时间；这里使用**明文 HTTP**，不计 TLS 等额外握手。

1. 若 Web 服务器上只需获取**一张很小的图片**，从用户点击 URL 到图片下载完成，总共经过多长时间？
2. 若目标资源换成一份 HTML 页面，并且该 HTML 页面另引用 **3 个很小的对象**，计算下列 HTTP 工作模式下，从用户点击 URL 到 HTML 与全部三个对象都收到为止的时间：
   1. **非持续 HTTP，顺序建立连接、非流水线**；
   2. **持续 HTTP，非流水线**；
   3. **持续 HTTP，流水线**。

计算约定：同一服务器提供 HTML 与其引用的三个对象；不启用并行 TCP 连接。必须先获取并解析 HTML 才能知道其中三个对象的 URL；在“流水线”模式下，浏览器获得 HTML 后可在同一持续连接中连续发出三个请求，而不必逐个等待响应。HTTP 的每次请求／首个响应按一个 $\mathrm{RTT}_w$ 计。

<Solution>

### 参考答案

**（1）只下载一张很小的图片：**

$$
\boxed{T_1=n\,\mathrm{RTT}+2\,\mathrm{RTT}_w}.
$$

**（2）获取 HTML 页面及其三个引用对象：**

| HTTP 模式 | TCP 建连 | 获取 HTML | 获取 3 个对象 | 总用时 |
| --- | --- | --- | --- | --- |
| 非持续、顺序非流水线 | $4\,\mathrm{RTT}_w$ | $1\,\mathrm{RTT}_w$ | $3\,\mathrm{RTT}_w$ | $\boxed{n\,\mathrm{RTT}+8\,\mathrm{RTT}_w}$ |
| 持续、非流水线 | $1\,\mathrm{RTT}_w$ | $1\,\mathrm{RTT}_w$ | $3\,\mathrm{RTT}_w$ | $\boxed{n\,\mathrm{RTT}+5\,\mathrm{RTT}_w}$ |
| 持续、流水线 | $1\,\mathrm{RTT}_w$ | $1\,\mathrm{RTT}_w$ | $1\,\mathrm{RTT}_w$ | $\boxed{n\,\mathrm{RTT}+3\,\mathrm{RTT}_w}$ |

### 分步解析

**步骤 1：域名解析。** 因为题设给定必须依次查询 $n$ 台 DNS 服务器，每次耗时 $\mathrm{RTT}$，故解析耗时

$$
T_{\mathrm{DNS}}=n\,\mathrm{RTT}.
$$

**步骤 2：单对象 HTTP 请求。** 先进行 TCP 三次握手，客户端发出 SYN、收到 SYN+ACK，再发出 ACK；在没有额外 TLS 往返及异常的理想模型下，握手计 **一个 $\mathrm{RTT}_w$**。随后发送 HTTP 请求并收到很小的响应数据，再计 **一个 $\mathrm{RTT}_w$**：

$$
T_1=T_{\mathrm{DNS}}+T_{\mathrm{TCP}}+T_{\mathrm{HTTP}}
=n\,\mathrm{RTT}+\mathrm{RTT}_w+\mathrm{RTT}_w.
$$

**步骤 3：HTML + 3 个引用对象，非持续 HTTP。**

非持续 HTTP 每获取一个对象都重新建立 TCP 连接。HTML 和三个引用资源是 **4 个对象**，顺序下载每个耗时 $2\,\mathrm{RTT}_w$：

$$
T_{\mathrm{NP}}=n\,\mathrm{RTT}+4\bigl(\mathrm{RTT}_w+\mathrm{RTT}_w\bigr)
=\boxed{n\,\mathrm{RTT}+8\,\mathrm{RTT}_w}.
$$

**步骤 4：HTML + 3 个引用对象，持续 HTTP、非流水线。**

只做一次 TCP 握手；HTML 要等一个请求—响应往返，三个引用对象各等一个往返，故

$$
T_{\mathrm{P,nonpipe}}=n\,\mathrm{RTT}+\underbrace{\mathrm{RTT}_w}_{\text{握手}}+\underbrace{\mathrm{RTT}_w}_{\text{HTML}}+\underbrace{3\,\mathrm{RTT}_w}_{\text{3 个顺序请求}}
=\boxed{n\,\mathrm{RTT}+5\,\mathrm{RTT}_w}.
$$

**步骤 5：HTML + 3 个引用对象，持续 HTTP、流水线。**

仍需在获取 HTML 后才能知道三个引用对象的地址；但随后三个 HTTP 请求可连续送入**同一条 TCP 连接**，无须逐一等待前一个对象的响应。忽略对象发送时间时，三个请求响应合计按一次 Web 往返计，因此

$$
T_{\mathrm{P,pipe}}=n\,\mathrm{RTT}+\underbrace{\mathrm{RTT}_w}_{\text{握手}}+\underbrace{\mathrm{RTT}_w}_{\text{HTML}}+\underbrace{\mathrm{RTT}_w}_{\text{3 个流水线对象}}
=\boxed{n\,\mathrm{RTT}+3\,\mathrm{RTT}_w}.
$$

### 易错点

1. **不能漏算 HTML 本身**：引用 3 个对象意味着要下载 $1+3=4$ 个对象，而不是 3 个。
2. **流水线并不能把 HTML 与它引用的资源放在同一轮请求中**：浏览器必须先拿到并解析 HTML，才能知道后续三个对象需要哪些 URL。
3. **非持续不等于不能并行建立多条连接**：本题专门限定“顺序建立、不并行”；若允许并行 TCP 连接，非持续模式会有不同用时。
4. **HTTP 持续连接不等于并发流水线**：持续但非流水线时仍需逐个等待三个引用对象的响应。
5. 不要把 $n\,\mathrm{RTT}$ 与 $\mathrm{RTT}_w$ 混为一谈；前者来自 DNS 查询，后者来自 Web 服务器通信。HTTPS 的额外 TLS 握手以及现代 HTTP/2、HTTP/3 的多路复用都**不属于本题计算模型**。
