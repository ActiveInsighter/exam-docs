## 2.5 运算方法和运算电路

<Question id="sim1127-wd408-2027-s02-q43" type="essay" tags="来源:27王道八套卷, 试卷:第2套·第43题, 科目:计算机组成原理, 章节:数据的表示和运算, 考点:无符号加减法与标志位" points={12}>

某计算机的字长为 **8 位**。$x$ 和 $y$ 均为**无符号整数**，$x=68$、$y=80$，分别存于寄存器 A、B。加/减法结果仅保留 8 位，且减法由加法器完成补码形式的 $x+(\sim y)+1$。各问结果尽量用十六进制表示。

1. 寄存器 A、B 中的内容分别是什么？
2. 将 $x+y$ 的结果存入寄存器 C。写出 C 的内容、结果是否能正确表示、最高位进位 $C_{out}$，以及 $\mathrm{ZF}$、$\mathrm{CF}$ 的值。
3. 将 $x-y$ 的结果存入寄存器 D。写出 D 的内容、结果是否能正确表示、最高位进位 $C_{out}$，以及 $\mathrm{ZF}$、$\mathrm{CF}$ 的值。
4. 对无符号数，加法与减法中 $C_{out}$ 分别表示什么？与 $\mathrm{CF}$ 的关系是什么？
5. 无符号数常用于哪些场景？为什么不能用**有符号溢出标志 OF**来判断无符号运算的越界？

<Solution>

### （1）将操作数写成 8 位机器数

无符号 8 位整数的范围为 $[0,2^8-1]=[0,255]$。十进制 68 等于 $4\times16+4$，80 等于 $5\times16$，所以：

| 寄存器 | 十进制值 | 二进制位模式 | 十六进制 |
| --- | ---: | --- | --- |
| A | 68 | `0100 0100` | `0x44` |
| B | 80 | `0101 0000` | `0x50` |

### （2）无符号加法

先计算完整的 9 位加法结果，再截取低 8 位，不能把结果的最高有效位直接当成进位标志。

```text
  0 0100 0100   (68)
+ 0 0101 0000   (80)
-------------
  0 1001 0100   (148)
```

数学结果为 $148$，未超过 255，因此寄存器 C 保存 `0x94`，无符号解释正确。第 9 位为 0，故 $C_{out}=0$；低 8 位不全为 0，ZF=0；按常用无符号加法标志定义，CF=$C_{out}=0$。

虽然 C 的最高位为 1，但这只是无符号数中的权值 128，不表示负数。若同样的位模式被解释为有符号补码，则 `0x94` 表示 -108，而两个正操作数的和 148 超出有符号范围，此时 OF=1。这恰好说明有符号溢出与无符号进位是两回事。

### （3）无符号减法

硬件通过 $x+\sim y+1$ 实现减法。8 位取反得到 $\sim\mathrm{0x50}=\mathrm{0xAF}$，即 175。

```text
  0 0100 0100   (68)
+ 0 1010 1111   (175)
+ 0 0000 0001   (1)
-------------
  0 1111 0100   (244)
```

D 的低 8 位为 `0xF4`，$C_{out}=0$。真实数学结果 $68-80=-12$ 不在无符号范围内；机器结果 $244=(-12)\bmod256$ 是回绕值，并不是无符号意义下正确的差。低 8 位不为零，故 ZF=0。按照考研常用的减法借位标志约定，CF=1（产生借位）。

### （4）为什么减法的 CF 与进位相反

对任意 8 位无符号 $x,y$，其按位取反值为 $255-y$，所以加法器完整结果为

$$
x+(255-y)+1=256+(x-y).
$$

- 若 $x\ge y$，完整结果至少为 256，最高位进位为 1，原减法没有借位。
- 若 $x<y$，完整结果不足 256，最高位进位为 0，原减法发生借位。

因此加法的 CF=$C_{out}$；减法若规定 CF=1 表示借位，则 CF=$1-C_{out}$。题干没有直接规定 CF 的借位语义，参考答案采用考研常见及 x86 风格的定义；某些体系结构的减法进位标志反而定义为无借位，此时标志取值不同，但加法器本身的 $C_{out}$ 不变。

| 运算 | 低 8 位 | 数学结果 | 无符号结果可表示？ | $C_{out}$ | ZF | CF（借位语义） |
| --- | --- | ---: | --- | ---: | ---: | ---: |
| $x+y$ | `0x94` | 148 | 是 | 0 | 0 | 0 |
| $x-y$ | `0xF4` | -12 | 否 | 0 | 0 | 1 |

### （5）应用和标志位的本质

无符号数常用于计数、数组长度、容量、地址及偏移量、位掩码等非负数据；同为 8 位时，无符号范围是 0～255，补码有符号范围是 -128～127。硬件的低 8 位运算结果相同，但数值解释与越界判据不同：

- ZF 只检查结果各位是否全为 0；SF 反映结果最高位，在有符号解释下对应符号。
- CF（按上述语义）用于判断无符号进位或借位。
- OF 判断有符号补码数学结果是否超出范围。加法可用进入符号位与移出符号位的进位异或判断；减法则可看两个操作数符号是否不同、结果符号是否与被减数不同。

本题加法的 OF=1 而 CF=0，减法的 OF=0 而 CF=1，正好给出两个相反的例子。因此无论哪一种解释，都必须选择与数值类型匹配的标志，不能把 OF 当成无符号越界标志。

</Solution>

</Question>

<Question id="sim1127-wd408-2027-s04-q43" type="essay" tags="来源:27王道八套卷, 试卷:第4套·第43题, 科目:计算机组成原理, 章节:数据的表示和运算, 考点:补码减法、标志位与IEEE754" points={11}>

某 32 位计算机以**小端方式**存储数据，`int` 为 32 位有符号补码整数，`float` 为 IEEE 754 **32 位单精度**浮点数。以下 C 语言程序片段中，初始有 `a[5] = 0x7FFFFFFF`、`b[5] = 0xFFFFFFFF`：

```c
int i, a[10], b[10];
float x = -15.25f;
for (i = 0; i < 10; i++)
    if (b[i] < a[i])
        b[i] = 1;
    else
        b[i] = 0;
```

1. 假设有符号比较 `b[i] < a[i]` 在该机上通过 `b[i] - a[i]` 及标志位实现。求 $i=5$ 时减法结果及 $\mathrm{CF}$、$\mathrm{OF}$、$\mathrm{ZF}$、$\mathrm{SF}$ 的值（规定减法的 CF=1 表示产生**无符号借位**）。
2. 执行该次循环后 `b[5]` 的值是多少？说明为何不能只检查 SF 就断定两个有符号整数的大小。
3. `x` 的首地址为 `0x12345670`。求地址 `0x12345670` 至 `0x12345673` 四个字节的内容。

<Solution>

### （1）先确定补码解释，再计算减法及标志位

题目已规定机器中的 32 位位模式。`0xFFFFFFFF` 在有符号补码下等于 -1，而 `0x7FFFFFFF` 等于 $2^{31}-1$。注意题目要求的是 `b[5] - a[5]`，不是反过来相减。

数学结果为

$$
-1-(2^{31}-1)=-2^{31}=-2147483648.
$$

其恰好是 32 位有符号补码的下界，可以正确表示。为了验证无符号借位，再把减法转换为 32 位加法器上的运算：

```text
   0xFFFFFFFF
 + 0x80000000     // 按位取反 0x7FFFFFFF
 + 0x00000001
-------------
  0x180000000    // 完整 33 位结果
```

截取低 32 位得到 `0x80000000`，最高位进位 $C_{out}=1$。各标志位必须根据各自定义独立求值：

| 标志 | 判断依据 | 值 |
| --- | --- | ---: |
| CF | 题设 1 表示借位；$1-C_{out}=0$ | 0 |
| OF | 数学差等于最小补码值，未超范围 | 0 |
| ZF | 低 32 位不全为零 | 0 |
| SF | 低 32 位的最高位为 1 | 1 |

因此结果为 $\boxed{\mathrm{0x80000000}}$，标志依次为 $(0,0,0,1)$。这里操作数异号并不意味着一定溢出；有符号减法溢出需同时满足被减数与减数异号、结果与被减数异号。本题被减数和结果都是负数，故 OF=0。

### （2）解释有符号比较如何利用标志位

有符号小于条件由 $SF\oplus OF$ 判断。若减法未溢出，结果符号反映真实差的符号；若发生溢出，截断后的符号恰好反转，需要 OF 修正。

本题 $SF\oplus OF=1\oplus0=1$，所以执行 `b[5] = 1`，最终该元素为 `0x00000001`。

以 8 位补码的反例理解为什么不能只检查 SF：比较 $127<-1$ 时，计算 $127-(-1)=128$，机器结果为 `0x80`，SF=1，但 OF=1，所以异或为 0，比较结果为假。CF 也不能用于该有符号条件；CF 描述的是相同位模式按无符号解释时的借位。

补充：有符号大于的条件是 ZF=0 且 $SF\oplus OF=0$，小于等于为 ZF=1 或 $SF\oplus OF=1$。硬件比较指令可用减法产生标志而不写回差值，不能据此认为 C 语言源代码必须实际执行可能溢出的有符号减法。

### （3）逐字段求 IEEE 754 编码，再转换为小端内存布局

首先转换绝对值：$15=8+4+2+1$，$0.25=2^{-2}$，故

$$
15.25=(1111.01)_2=(1.11101)_2\times2^3.
$$

对于规格化单精度数，数值为 $(-1)^s(1.f)_2\times2^{E-127}$，隐藏的最高位 1 不存入尾数字段。

| 字段 | 位宽 | 本题取值 |
| --- | ---: | --- |
| 符号位 $s$ | 1 | `1`（负数） |
| 阶码 $E$ | 8 | $3+127=130$，即 `10000010` |
| 尾数 $f$ | 23 | `11101` 后补 18 个 0 |

拼接后按每 4 位一组转换为十六进制：

```text
1 | 10000010 | 11101000000000000000000
1100 0001 0111 0100 0000 0000 0000 0000
   C    1    7    4    0    0    0    0
```

因此 32 位编码为 `0xC1740000`。反向校验：阶码还原为 3，尾数有效值为 $1+1/2+1/4+1/8+1/32=1.90625$，乘 $2^3$ 再取负即 -15.25，恰好精确表示，无须舍入。

小端方式将最低有效字节存放在最低地址，故最终答案如下：

| 地址 | 字节内容 |
| --- | --- |
| `0x12345670` | `0x00` |
| `0x12345671` | `0x00` |
| `0x12345672` | `0x74` |
| `0x12345673` | `0xC1` |

字节序只影响不同字节在内存中的位置，不改变字节内部的位顺序，也不改变 IEEE 754 的编码值。应先算出整个机器数 `C1 74 00 00`，再按题目指定的端序排列，切忌直接把整个二进制串倒过来。

</Solution>

</Question>
