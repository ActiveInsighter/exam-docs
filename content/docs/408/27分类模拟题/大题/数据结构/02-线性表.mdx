## 2.1 线性表的顺序存储

<Question id="sim1127-wd408-2027-s03-q42" type="essay" tags="来源:27王道八套卷, 试卷:第3套·第42题, 科目:数据结构, 章节:线性表, 考点:滑动窗口与连续子数组计数" points={13}>

给定一个由**正整数**组成的数组 `nums` 和一个整数 $k$，计算并返回所有满足“子数组内元素乘积严格小于 $k$”的**非空连续子数组**的总数。

示例 1：输入 `nums=[10,5,2,6]`，$k=100$；输出 8。满足条件的 8 个子数组为 $[10]$、$[5]$、$[2]$、$[6]$、$[10,5]$、$[5,2]$、$[2,6]$、$[5,2,6]$。注意 $[10,5,2]$ 的乘积为 100，不满足严格小于的条件。

示例 2：输入 `nums=[1,2,3]`，$k=0$；输出 0。

回答下列问题：

1. 给出算法设计思想。
2. 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释。
3. 分析所设计算法的时间复杂度和空间复杂度。

<Solution>

### （1）算法思想：滑动窗口

本题要求的是**连续子数组的数量**，而非最长子数组的长度。直接枚举左右端点会产生 $O(n^2)$ 个区间。关键条件是所有元素都是正整数，因此向窗口中加入元素，乘积不会减小；移除元素，乘积不会增大。这种单调性允许使用双指针。

如果 $k\leq 1$，由于非空子数组的乘积至少为 1，直接返回 0。否则依次枚举右端点 `r`，维护左端点 `l`，使当前窗口的乘积小于 $k$，并且 `l` 是以 `r` 为终点的合法区间的最小起点。

为什么只需要统计窗口长度？若 `[l,r]` 合法，则删除若干左侧元素后得到的 `[l+1,r]`、`[l+2,r]` 等仍然合法；任何更靠左的起点都会使乘积不小于 $k$。因此恰好新增 $r-l+1$ 个合法子数组。若窗口为空，`l=r+1`，新增数量恰好为 0。按右端点分类求和，每个非空子数组只被计数一次。

### （2）C 语言实现

下面先判断乘法是否会达到阈值，再真正执行乘法。因为各数都是正整数，`prod*x >= k` 等价于 `prod > (k-1)/x`（整数除法），所以无需先计算可能很大的乘积。

```c
long long countSubarrays(const int nums[], int n, int k) {
    if (n <= 0 || k <= 1) return 0;
    int l = 0;
    long long prod = 1, ans = 0;
    for (int r = 0; r < n; ++r) {
        int x = nums[r];
        // 单个 x 就不合法，任何包含它的窗口都不合法
        if (x >= k) {
            l = r + 1;
            prod = 1;
            continue;
        }
        // 当前 prod 对应 [l, r-1]，先收缩再乘入 x
        while (l < r && prod > (k - 1) / x) {
            prod /= nums[l++];
        }
        prod *= x; // 保证 prod < k，不发生乘积溢出
        ans += (long long)r - l + 1;
    }
    return ans;
}
```

在常见的 32 位 `int`、64 位 `long long` 环境下，也可以采用更直观的 `prod *= nums[r]` 再在 `prod >= k` 时除去左端元素的写法；因为上一轮乘积严格小于 `k`，本轮乘积不超过两个正 `int` 的最大值之积。上面的预判法不依赖这一乘积范围。

### （3）示例推演与复杂度

对于 `nums=[10,5,2,6]`、`k=100`：

| `r` | 加入元素 | 最终窗口 | 乘积 | 新增 | 累计 |
| --- | --- | --- | ---: | ---: | ---: |
| 0 | 10 | `[10]` | 10 | 1 | 1 |
| 1 | 5 | `[10,5]` | 50 | 2 | 3 |
| 2 | 2 | `[5,2]` | 10 | 2 | 5 |
| 3 | 6 | `[5,2,6]` | 60 | 3 | 8 |

第三轮若保留 10，乘积恰为 100，不满足严格小于，因此必须删掉 10。

- 时间复杂度为 $O(n)$：右指针扫描 $n$ 次，左指针只向右移动，总共不超过 $n$ 次，内层循环不是对每个右端点都重新扫描。
- 辅助空间复杂度为 $O(1)$：不建立任何额外数组。答案最多为 $n(n+1)/2$，因此在常见 32 位 `int` 环境下使用 `long long` 保存计数。

**易错点：** 条件是严格小于而不是小于等于；元素为正整数才保证上述乘积单调性，若含零、负数或小于 1 的实数，不能直接使用本算法。

</Solution>

</Question>

<Question id="sim1127-408-jingcheng-2027-05-41" type="essay" points={13} tags="来源:27竞成10套卷, 试卷:第5套·第41题, 科目:数据结构, 章节:线性表, 考点:顺序表枢轴元素">

给定一个含 $n$（$n\geq 1$）个整数的数组 $A[0\cdots n-1]$，若数组中某个元素 $A[i]$ 满足 $A[0],A[1],\cdots,A[i-1]\leq A[i]$ 且 $A[i]\leq A[i+1],A[i+2],\cdots,A[n-1]$，则称 $A[i]$ 为数组中的枢轴元素。例如，数组 $(3,2,4,6)$ 存在枢轴元素 4 和 6；数组 $(3,2,1,2)$ 不存在枢轴元素。请设计一个尽可能高效的算法，若存在枢轴元素，则输出所有枢轴元素的下标并返回枢轴元素的个数；若不存在，则输出 $-1$。要求：

(1) 给出算法的基本设计思想；

(2) 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；

(3) 说明你所设计算法的时间复杂度和空间复杂度。

<Solution>

### （1）算法思想：后缀最小值 + 前缀最大值

判断 $A[i]$ 是否为枢轴，必须比较整个左区间和整个右区间，而非仅比较相邻元素。定义

$$
L_i=\max(A[0],\ldots,A[i]),\qquad R_i=\min(A[i],\ldots,A[n-1]).
$$

则枢轴的充要条件是 $L_i=A[i]=R_i$。包含自身不会改变判定结果，却能让首尾元素和只有一个元素的数组自然适用，无需为不存在的左右区间设置特殊值。

先从右往左计算后缀最小值数组 `R`，其中 `R[n-1]=A[n-1]`，`R[i]=min(A[i],R[i+1])`。再从左往右扫描，利用一个变量维护前缀最大值 `mx`。每到一个位置，更新 `mx` 后判断它和 `R[i]` 是否都等于 `A[i]`，若成立就输出下标并计数。

### （2）C++ 语言实现

```cpp
#include <vector>
#include <algorithm>
#include <cstdio>

int FindPivot(const int A[], int n) {
    if (n <= 0) { // 防御性处理；题设保证 n >= 1
        std::printf("-1\n");
        return 0;
    }
    std::vector<int> R(n);
    R[n - 1] = A[n - 1];
    for (int i = n - 2; i >= 0; --i)
        R[i] = std::min(A[i], R[i + 1]);

    int mx = A[0], count = 0;
    for (int i = 0; i < n; ++i) {
        mx = std::max(mx, A[i]); // 当前前缀包含 A[i]
        if (mx == A[i] && R[i] == A[i]) {
            std::printf("%d ", i);
            ++count;
        }
    }
    if (count == 0) std::printf("-1");
    std::printf("\n");
    return count;
}
```

题干要求无枢轴时**输出** `-1`，而不是规定函数必须返回 `-1`；上述实现输出 `-1` 并返回实际个数 0。使用 C 语言也可动态申请一个长度为 `n` 的 `int` 数组，使用后释放。

### （3）示例、正确性与复杂度

以 `(3,2,4,6)` 为例：

| 下标 | 0 | 1 | 2 | 3 |
| --- | ---: | ---: | ---: | ---: |
| `A[i]` | 3 | 2 | 4 | 6 |
| 前缀最大值 | 3 | 3 | 4 | 6 |
| 后缀最小值 | 2 | 2 | 4 | 6 |
| 是否枢轴 | 否 | 否 | 是 | 是 |

因此输出下标 `2 3`，返回 2。对于 `(3,2,1,2)`，前缀最大值全为 3，后缀最小值依次为 1、1、1、2，没有任何位置满足条件。

正确性来自两次扫描的循环不变式：每个 `R[i]` 都是当前位置及其右侧最小值，`mx` 是当前位置及其左侧最大值。两者同时等于 `A[i]`，与题干两组不等式完全等价，因而不会误判或漏判。

时间复杂度 $O(n)$，辅助空间复杂度 $O(n)$。由于最坏情况下必须检查每个元素并输出 $n$ 个枢轴，下界为 $\Omega(n)$，时间复杂度已经达到最优。也可以同时建前缀最大值和后缀最小值两个数组，但只用一个后缀数组更节省空间；暴力枚举的时间为 $O(n^2)$，空间为 $O(1)$，不作为高效答案首选。

**易错点：** 题目使用非严格不等式，重复值不能被直接排除；例如 `(2,2,2)` 的三个位置都是枢轴。这里的枢轴也不同于快速排序任意选取的划分基准。

</Solution>

## 2.2 线性表的链式存储

<Question id="sim1127-wd408-2027-s08-q42" type="essay" tags="来源:27王道八套卷, 试卷:第8套·第42题, 科目:数据结构, 章节:线性表, 考点:快慢指针与原地反转判断回文链表" points={14}>

已知一个长度为 $n$（$n>1$）的单链表，其表头指针为 `L`，结点结构由 `data` 和 `next` 两个域构成，其中 `data` 域为字符型。试设计一个在时间和空间上都尽可能高效的算法，判断该单链表是否**中心对称**（如 `xyx`、`xyyx` 都是中心对称的）。要求：

1. 给出算法的基本设计思想。
2. 根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释。
3. 说明所设计算法的时间复杂度和空间复杂度。

<Solution>

### （1）算法思想：寻找中点、反转后半段、逐项比较

中心对称即回文，要求第一个字符与最后一个字符相同、第二个与倒数第二个相同，以此类推。单链表无法通过前驱指针向前访问，因此若反复从头找倒数位置，时间会达到 $O(n^2)$；借助栈可以线性时间比较，但要额外占用 $O(n)$ 空间。

更好的方法是原地反转链表的后半部分：

1. 快慢指针均从首个数据结点出发；快指针每次走两步，慢指针每次走一步。采用下面的循环条件，使慢指针最后停在前半段的末尾（奇数长度时停在中间结点）。
2. 反转慢指针之后的全部结点。偶数长度时两半等长，奇数长度时中间字符不参与比较。
3. 从原表开头和反转后的后半段同时出发，逐个比较字符，只需比较后半段的长度。
4. 将后半段再反转一次，接回原处。即使中途发现字符不相等，也必须恢复链表，然后返回结果。

### （2）C 语言实现

这里明确假设 `L` 指向首个数据结点；如果采用带头结点的链表，只需传入 `L->next`。

```c
#include <stddef.h>

typedef struct Node {
    char data;
    struct Node *next;
} Node;

static Node *reverse(Node *p) {
    Node *prev = NULL;
    while (p != NULL) {
        Node *next = p->next; // 先保存原后继
        p->next = prev;
        prev = p;
        p = next;
    }
    return prev;
}

int isPalindrome(Node *L) {
    if (L == NULL || L->next == NULL) return 1;
    Node *slow = L, *fast = L;
    while (fast->next != NULL && fast->next->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }
    Node *second = reverse(slow->next);
    slow->next = second;

    int ok = 1;
    Node *p = L, *q = second;
    while (q != NULL) { // 后半段较短或等长，以它为准
        if (p->data != q->data) {
            ok = 0;
            break;
        }
        p = p->next;
        q = q->next;
    }
    slow->next = reverse(second); // 无论成功或失败均恢复
    return ok;
}
```

### （3）过程与复杂度

对于偶数长度 `x → y → y → x`，慢指针最终停在第二个结点。后半段 `y → x` 反转为 `x → y`，于是与前两个结点依次比较 `x/x`、`y/y`，均相等。对于奇数长度 `x → y → x`，慢指针停在中央的 `y`，后半段仅有一个 `x`，只比较两端即可。长度为 2 时，慢指针停在第一个结点，算法仍正确。

若反转后的每一对对应结点都相等，就已经检查全部 $\lfloor n/2\rfloor$ 对对称字符，故返回真；任意一对不相等则必非回文。

寻找中点、两次反转和比较均为线性过程，合计时间复杂度 $O(n)$；所有操作只维护常数个指针和变量，辅助空间复杂度 $O(1)$。最坏情况下必须访问全部数据结点，因此时间复杂度已经最优。

**易错点：** 不要将带头结点的 `L` 当作数据参与比较，不要遗漏奇数长度的中间字符处理，也不要因为发现不匹配就直接返回而破坏原链表。

</Solution>

</Question>
