## 5.1 I/O 管理基础

<Question id="sim1127-wd408-2027-s02-q46" type="essay" tags="来源:27王道八套卷, 试卷:第2套·第46题, 科目:操作系统, 章节:输入输出管理, 考点:中断驱动与终端输出" points={8}>

进程 `P` 在用户态执行 `putchar('X')`，系统通过**中断驱动**向终端输出字符。内核维护一个有容量上限的待发送队列 `outq`；设备寄存器 `DATA` 和状态位 `READY` 满足：`READY=1` 表示设备空闲，向 `DATA` 写一个字符可启动发送；字符发送完毕时硬件置 `READY=1` 并产生发送完成中断。字符被系统接收并入队、必要时启动发送后，`putchar/write` **可提前返回用户态**，无需等终端显示完成。

为避免“已启动发送的字符还留在队列、随后被重复发送”的原文歧义，约定：**③ 从 `outq` 队首取出一个字符并写 `DATA`；⑦ 也先检查 `outq` 是否非空，非空时取出队首字符写 `DATA`。已提交 `DATA` 的字符不再位于待发送队列中。**

操作编号（编号只标识操作，不表示发生顺序）：

| 编号 | 操作 |
| :---: | --- |
| ① | `P` 执行系统调用陷入内核态 |
| ② | 把 `X` 追加到 `outq`（队满则需等待空位） |
| ③ | 当 `READY=1` 且 `outq` 非空时，取出队首字符写入 `DATA`，启动发送 |
| ④ | `P` 从系统调用返回用户态 |
| ⑤ | 本次硬件发送完成并产生中断请求 |
| ⑥ | CPU 响应中断，进入中断处理程序 |
| ⑦ | ISR：若 `outq` 非空，取出下一字符写 `DATA`；否则结束此次数据提交 |
| ⑧ | `outq` 已满时将 `P` 加入阻塞队列 |
| ⑨ | ISR 发现 `outq` 出现可用位置时，唤醒 `P` 并置为就绪 |

1. 初始 `outq` 为空、`READY=1`，从 `putchar('X')` 到系统调用返回，再到随后一次发送完成中断处理，写出主要编号顺序。
2. 初始 `outq` 已满且设备正忙（`READY=0`），指出导致 `P` 阻塞及重新就绪的编号，并写出恢复执行直至返回用户态的关键链路。
3. 把操作①～⑨归为“进程上下文（系统调用路径）”“ISR／中断入口处理”“硬件事件”三类。
4. 执行⑥⑦时 `P` 可能处于哪些进程状态？此时 CPU 是内核态还是用户态？至少举两种场景。

<Solution>

### （1）设备空闲时的执行顺序

**答案：① → ② → ③ → ④ → ⑤ → ⑥ → ⑦。**

理解这道题的关键是区分三个时刻：字符被内核接受、字符被提交给设备、设备完成物理发送。三者不必同时发生。

| 步骤 | 执行者 | 队列及设备状态 |
| --- | --- | --- |
| ① | 进程 P | 陷入内核，开始执行系统调用 |
| ② | 内核中的 P | 将 X 入队，`outq=[X]` |
| ③ | 内核中的 P | 设备空闲，取出 X 写入 DATA；队列为空，设备开始忙 |
| ④ | 进程 P | 系统调用成功返回，可继续执行用户程序 |
| ⑤ | 设备控制器 | X 发送完成，READY 置 1，产生中断请求 |
| ⑥ | CPU | 响应中断，转入中断处理路径 |
| ⑦ | ISR | 若此时无新字符，只检查空队列并结束 |

这里按题目要求给出**先返回、随后完成中断**的典型时序。真实系统中若设备很快，也可能在④之前完成发送并触发中断，题设不要求返回一定早于硬件完成。

### （2）队满时的阻塞与唤醒

**阻塞：⑧；重新就绪：⑨。** 典型顺序为：

`① → ⑧ → ⑤ → ⑥ → ⑦ → ⑨ → 调度 P → ② → ④`

- ①后检查发现待发队列已满，②暂时无法成功，故⑧将 P 放入等待空位的阻塞队列，P 让出 CPU。
- 正在发送的旧字符完成后，硬件发出⑤；CPU 执行⑥，ISR 在⑦从满队列中取出下一字符写 DATA。此时才释放一个**待发送队列的槽位**。
- ⑨唤醒 P，使其由阻塞变为就绪。就绪不等于立即运行；调度器选中 P 后，它才能重新检查队列条件并执行②。
- 若设备仍忙，P 无须执行③，成功入队即可④返回。若有其他发送者抢占了空槽，P 必须重新等待；若设备已空闲，则可再执行③启动发送。

实现时，检查队列条件、入队/出队以及睡眠与唤醒的衔接要受适当的同步保护，防止丢失唤醒或重复提交字符。

### （3）区分三类执行事件

| 类别 | 编号 | 判定依据 |
| --- | --- | --- |
| 进程上下文、系统调用路径 | ①②③④⑧ | 由 P 发起，内核代表 P 完成请求或将其阻塞 |
| 中断入口与 ISR | ⑥⑦⑨ | CPU 响应设备中断，服务程序推进发送并唤醒等待者 |
| 硬件事件 | ⑤ | 外设独立完成实际传输并发出中断 |

①、⑥本身都包含硬件控制转移与软件入口的配合；表中按题目所问的执行路径分类。不能因为⑥含硬件动作就把整个 ISR 当成硬件执行。

### （4）中断发生时 P 的状态与 CPU 模式

⑥完成中断入口后以及执行⑦时，CPU 在**内核态**。P 则可能处于以下不同状态：

| 场景 | P 的状态 |
| --- | --- |
| P 已返回用户态且正占用 CPU，此时发生中断 | 原运行进程被暂时打断；中断返回可继续运行 |
| P 已返回，但 CPU 正运行其他进程 | 就绪（也可能因其他事件阻塞） |
| P 因 outq 已满而睡眠 | 阻塞；直到⑨才转为就绪 |

**核心知识：** 中断处理程序不是 P 的一个普通用户函数，设备中断与进程调度异步；进入内核态也不必然意味着发生进程切换。题中的提前返回意味着「已接受输出请求」，不是「屏幕已经显示字符」。

用户在使用计算机时，通过键盘输入命令，使得用户程序执行 fread() 库函数，调用相关的系统调用，之后 CPU 执行 I/O 指令，从磁盘获取文件数据。磁盘与 CPU 之间采用 DMA 方式进行数据传输，DMA 控制器如下图所示。

![DMA 控制器](/images/exams/408-jingcheng-2027/09-46-question.svg)

请回答下列问题。

(1) 键盘输入命令采用什么 I/O 方式？程序在调用系统调用时，CPU 处于什么状态？I/O 指令属于特权指令还是非特权指令？

(2) 从磁盘获取数据时，DMA 控制器中 MAR 和 DC 的作用分别是什么？

(3) 通常把 I/O 软件组织成 4 个层次，分别为：用户层软件、与设备无关的 I/O 软件、设备驱动程序和中断处理程序。其中，将逻辑设备名映射成物理设备名的是哪一层次？计算数据所在磁盘的柱面号、磁头号、扇区号的是哪一层次？

<Solution>

### （1）I/O 控制方式、CPU 状态与指令权限

答案：**键盘通常采用中断驱动 I/O；用户程序发起系统调用前在用户态，陷入后在内核态；I/O 指令属于特权指令（本题教材模型）。**

键盘输入是低速、随机到达的字符流。若采用程序查询方式，CPU 需要不断检查设备是否有新字符，浪费处理能力；采用中断方式时，控制器在输入到达后通知 CPU，CPU 才运行相应处理程序。磁盘则通常按块批量传输，DMA 更合适。

![系统调用过程](/images/exams/408-jingcheng-2027/09-46-solution.svg)

结合图理解系统调用：用户态库函数 `fread()` 在需要内核读取数据时调用系统调用封装函数（如 `read`）；执行陷入指令使 CPU 进入内核态，内核检查参数、执行文件系统及设备驱动逻辑，最后返回用户态。库函数不是系统调用本身；若数据已经在用户缓冲区或内核页缓存中，也不一定实际启动磁盘 I/O。题目已指定发生磁盘访问，按该路径作答。

用户程序不能随意直接控制磁盘寄存器。教材将 I/O 指令作为特权指令；实际体系结构也可能借助受保护的内存映射 I/O 实现设备访问，权限仍由操作系统控制。

### （2）DMA 控制器的 MAR 和 DC

| 寄存器 | 含义 | 在磁盘读入内存时的作用 |
| --- | --- | --- |
| MAR | 内存地址寄存器 | CPU 初始化为目标缓冲区起始内存地址；DMA 传输过程中记录当前/下一传输地址，并按单位更新 |
| DC | 数据计数器 | CPU 初始化本次传输的数量；每完成一个传输单位更新计数，到达终止条件后结束此次传输 |
| DR | 数据寄存器 | 暂存设备与内存之间传送的数据 |
| CR | 控制寄存器 | 保存传输方向、控制命令等信息（具体位定义由硬件决定） |

以连续读入 $N$ 个字节、每次传送 1 字节为例：初始 `MAR=A, DC=N`。第一次传输将数据写入地址 A，然后 MAR 增加 1、DC 减少 1；第 N 次后计数为 0，控制器通常向 CPU 发出完成中断。实际硬件可能按字、总线突发或描述符计数，DC 的单位取决于实现。

DMA 的三个阶段是 CPU 初始化、DMA 自主搬运、完成中断。CPU 不逐字搬运数据，但 DMA 仍需获得总线或内存访问权限，可能与 CPU 产生访存竞争。

### （3）I/O 软件四层职责

**逻辑设备名到物理设备名的映射：与设备无关的 I/O 软件。** **柱面号、磁头号和扇区号的计算：设备驱动程序（传统教材磁盘模型）。**

| 层次（从上到下） | 主要职责 |
| --- | --- |
| 用户层软件 | 库函数接口、部分缓冲和格式处理 |
| 与设备无关的 I/O 软件 | 统一接口、设备命名、分配与释放、保护、通用缓冲等 |
| 设备驱动程序 | 将抽象 I/O 请求变成具体设备命令、地址和控制参数 |
| 中断处理程序 | 处理设备完成或异常中断，记录状态、唤醒等待者等 |

现代磁盘通常向主机提供逻辑块地址 LBA，真实物理位置的映射可由设备固件完成，因此不能把传统 CHS 地址换算当作所有现代驱动的必经步骤。考研题中按照所给四层模型判断即可。

</Solution>

## 5.2 设备独立软件

<Question id="sim1127-408-jingcheng-2027-05-46" type="essay" tags="来源:27竞成10套卷, 试卷:第5套·第46题, 科目:操作系统, 章节:输入输出管理, 考点:SPOOLing与同步互斥" points={7}>

某系统采用 SPOOLing 技术管理一台打印机。输出井由 $n$ 个磁盘块组成，每个打印文件恰好占用 1 个磁盘块；打印请求队列最多可存放 $m$ 个请求表项，每个请求表项记录一个待打印文件所在的磁盘块号。多个用户进程可并发提交打印请求，系统中只有一个假脱机输出进程，输出井空闲块表和打印请求队列均为共享数据结构。请回答下列问题：

(1) 对下列打印过程进行排序：

① 在磁盘输出井中申请空闲磁盘块

② 打印机空闲时，假脱机输出进程取队首请求并进行打印

③ 申请一张空白的打印请求表，填写打印要求后挂入打印请求队列

④ 用户进程提出打印请求

⑤ 将待打印数据送入所申请的磁盘块

(2) 请使用 `wait()`、`signal()` 操作描述用户进程和假脱机输出进程中的同步与互斥。题中已给出的部分信号量如下（若有需要可自行补充新的信号量，并说明所使用信号量的初值及含义）。

```c
semaphore empty = n;
semaphore qempty = m;
semaphore qfull = 0;
```

<Solution>

### （1）打印过程排序

**答案：④ → ① → ⑤ → ③ → ②。**

SPOOLing 的核心是将对独占设备的直接请求变为磁盘上的排队任务。用户进程先提出请求，在输出井取得一个空闲磁盘块，将完整文件写入该块后，才把记录该块号的请求表项放入队列。最后由唯一的假脱机输出进程按队列顺序使用打印机。

### （2）信号量设计与 PV 代码

本题有两种有限资源（磁盘块、队列表项），以及两个需要互斥访问的共享数据结构，不能只用一对 `empty/full` 简单套用普通生产者消费者模型。

| 信号量 | 初值 | 作用 |
| --- | ---: | --- |
| `empty` | n | 尚可申请的输出井空闲磁盘块数量 |
| `qempty` | m | 尚可申请的空闲请求表项数量 |
| `qfull` | 0 | 已发布且可供输出进程领取的请求数量 |
| `blockMutex` | 1 | 保护输出井空闲块表 |
| `queueMutex` | 1 | 保护打印请求队列 |

假定 n、m 为正整数，文件写入和打印正常完成；`wait`、`signal` 为原子操作。参考伪代码如下：

```text
User(file) {
    wait(empty);               // 预留一个磁盘块
    wait(blockMutex);
    b = allocate_free_block(); // b 是本进程的局部变量
    signal(blockMutex);

    write_file(b, file);        // 文件完整写入后才可以发布请求

    wait(qempty);              // 预留一个请求表项
    wait(queueMutex);
    enqueue(b);
    signal(queueMutex);
    signal(qfull);              // 通知输出进程有新请求
}

SpoolOut() {
    while (true) {
        wait(qfull);
        wait(queueMutex);
        b = dequeue();          // 取出队首块号，保存于局部变量
        signal(queueMutex);
        signal(qempty);         // 队列表项可以立即复用

        print_file(b);          // 等待打印所需的数据使用完毕

        wait(blockMutex);
        release_block(b);
        signal(blockMutex);
        signal(empty);          // 数据块此时才可复用
    }
}
```

### 正确性与死锁分析

- **不会重复分配磁盘块。** `wait(empty)`限制预留总数，空闲块表的删除、插入均由 `blockMutex` 保护；每个用户取得互不相同的块号。
- **不会读取未写完的文件。** 用户只有在写入完成、入队之后才发布 `qfull`；输出进程必须先成功执行 `wait(qfull)`。这是生产者与消费者的同步关系。
- **不会出现队列越界或打印数据被覆盖。** `qempty` 限制表项数量，`queueMutex` 保护队列；请求取出后只释放表项，磁盘块仍归输出进程使用，直到打印完成再释放。
- **不会因锁顺序造成死锁。** 任何可能阻塞的资源等待都不在互斥锁保护区内执行；用户等待 `qempty` 时虽然占有一个磁盘块，但如果队列已满，输出进程能够取走请求并释放表项，不需要先申请新的磁盘块。若队列空且所有块被用户占有，则至少有表项可供它们发布请求。假设 I/O 能结束且进程获得调度，系统能够继续推进。

两个互斥信号量也可用一个公共互斥信号量代替，但仍需在锁外等待资源、读写文件和打印。唯一输出进程已保证打印机不会被多个输出进程同时使用，故无需额外设置打印机互斥信号量。`qempty` 和 `empty` 的释放时刻不同，是本题最主要的易错点。

</Solution>

</Question>

## 5.3 外存管理

<Question id="sim1127-wd408-2027-s06-q46" type="essay" tags="来源:27王道八套卷, 试卷:第6套·第46题, 科目:操作系统, 章节:输入输出管理, 考点:磁盘调度与访问时间" points={8}>

磁盘 I/O 请求队列的柱面号依次为

`35, 58, 40, 28, 80, 160, 143, 38, 204`，

磁头初始位置为 `95`，**初始扫描方向为柱面号增大的方向**。

1. 用最短寻道时间优先（SSTF）算法，共移动多少个磁道？
2. 用 SCAN 算法，共移动多少个磁道？
3. 用 C-SCAN 算法，共移动多少个磁道？
4. 哪些常见调度算法可能发生“磁臂黏着”（某磁道频繁产生新请求，其他磁道长期得不到服务）？如何改善？
5. 一次磁盘读／写的时间包括哪些部分？磁盘调度算法主要优化哪一部分？通常用哪种 I/O 控制方式成批读写盘块？

**计算条件说明**：原题未提供磁盘的**最大柱面号**，因此严格按 SCAN/C-SCAN“到物理端点再返回”的定义，第（2）（3）问不能得出唯一具体数值。记柱面范围为 `0～M`（$M\ge204$）；返回路径的磁头移动也计入总磁道数。同时给出**若磁盘为 `0～299` 柱面**时的示例，以免将 LOOK/C-LOOK 的结果误充作 SCAN/C-SCAN。

<Solution>

### （1）SSTF：每次选择距离最近的待访问柱面

磁头从 95 出发，最初离它最近的是 80（距离 15），而不是队列首部的 35。随后每次重新选择最近请求：

| 当前柱面 | 下一柱面 | 移动距离 |
| ---: | ---: | ---: |
| 95 | 80 | 15 |
| 80 | 58 | 22 |
| 58 | 40 | 18 |
| 40 | 38 | 2 |
| 38 | 35 | 3 |
| 35 | 28 | 7 |
| 28 | 143 | 115 |
| 143 | 160 | 17 |
| 160 | 204 | 44 |

$$D_{\mathrm{SSTF}}=15+22+18+2+3+7+115+17+44=\boxed{243}$$

### （2）SCAN：先沿原方向扫到端点，再反向服务

按初始方向将请求分组：向上为 143、160、204，向下为 80、58、40、38、35、28。最大柱面号为 M（题目未给定数值），访问路径为：

`95 → 143 → 160 → 204 → M → 80 → 58 → 40 → 38 → 35 → 28`

到达最后一个请求即停止计量，所以两段距离分别是 $M-95$ 和 $M-28$：

$$D_{\mathrm{SCAN}}=(M-95)+(M-28)=\boxed{2M-123}$$

若 M=299，则移动 475 个柱面。若题目要求继续扫描至下端点 0 才停止计量，还需额外加 28；这里计算完成所有请求所需移动距离。

### （3）C-SCAN：始终沿同一方向服务

`95 → 143 → 160 → 204 → M → 0 → 28 → 35 → 38 → 40 → 58 → 80`

从 M 回到 0 的途中不服务请求，但发生了实际磁头移动，必须计入距离：

$$D_{\mathrm{C-SCAN}}=(M-95)+M+80=\boxed{2M-15}$$

若 M=299，则移动 583 个柱面。由于原题未给出 M，以上两问严格而言没有唯一的数值答案。

| 算法 | 折返/回卷位置 | 总移动距离 |
| --- | --- | ---: |
| SCAN | 物理端点 M | $2M-123$ |
| C-SCAN | M 回到 0 | $2M-15$ |
| LOOK | 最远请求 204 | $(204-95)+(204-28)=285$ |
| C-LOOK | 204 回到 28 | $(204-95)+(204-28)+(80-28)=337$ |

**不要把最大请求号 204 直接当作物理端点 M。** 若教材将只扫描至最远请求的变体也称为 SCAN，应注明采用的定义。

### （4）磁臂黏着及改善方法

磁臂黏着是动态到达请求下的一种现象：某个磁道或很小的区域不断产生请求，使磁头长时间停留在该处，远处的请求得不到服务。

SSTF 最容易因新近请求持续插队而使远处请求饥饿。传统 SCAN/C-SCAN 若允许同一柱面不断到达的请求无限加入当前扫描，也可能出现黏着；若实现保证扫描持续前进或采用冻结队列，则不会有这种无限停留。FCFS 按到达顺序处理，不会因后来同柱面请求持续插队而饿死先到请求。

可使用 **N-Step-SCAN**（按固定上限将请求分批扫描）或 **FSCAN**（两个队列，当前扫描队列冻结，新请求加入另一队列），让本批请求在有限时间内完成。对本题给出的静态有限请求序列不存在持续插入问题。

### （5）磁盘访问时间与 DMA

$$T_{\mathrm{disk}}=T_{\mathrm{seek}}+T_{\mathrm{rotation}}+T_{\mathrm{transfer}}$$

- 寻道时间：移动磁头到目标柱面，磁盘调度主要优化这一项。
- 旋转延迟：等待目标扇区转到磁头下方。若转速为 r RPM 且目标扇区相位均匀分布，平均旋转延迟为 $30/r$ 秒。
- 传输时间：数据真正读出或写入所需时间，与数据量及传输速率有关。具体系统还可能有排队、控制器等附加开销。

成批盘块传输通常采用 **DMA**，CPU 负责设置参数，DMA 在设备和内存之间搬运数据，完成后由中断通知 CPU。不要把 DMA 与程序查询 I/O 混淆。
