## 6.5 万维网 (www)

<Question id="sim1127-wd408-2027-s06-q47" type="essay" points={9} tags="来源:27王道八套卷, 试卷:第6套·第47题, 科目:计算机网络, 章节:应用层, 考点:DNS解析时延、HTTP连接与流水线">

浏览器用户点击一个 URL，本地主机尚未缓存目标域名的 IP 地址，因此需要先进行 DNS 查询。假定按顺序共查询 $n$ 台 DNS 服务器，每次查询与应答耗时均为 $\mathrm{RTT}$；主机与 Web 服务器的往返时延为 $\mathrm{RTT}_w$。各次 TCP 连接均需要一次三次握手，忽略 DNS 之外的排队、计算处理时间以及小对象的实际发送时间；这里使用**明文 HTTP**，不计 TLS 等额外握手。

1. 若 Web 服务器上只需获取**一张很小的图片**，从用户点击 URL 到图片下载完成，总共经过多长时间？
2. 若目标资源换成一份 HTML 页面，并且该 HTML 页面另引用 **3 个很小的对象**，计算下列 HTTP 工作模式下，从用户点击 URL 到 HTML 与全部三个对象都收到为止的时间：
   1. **非持续 HTTP，顺序建立连接、非流水线**；
   2. **持续 HTTP，非流水线**；
   3. **持续 HTTP，流水线**。

计算约定：同一服务器提供 HTML 与其引用的三个对象；不启用并行 TCP 连接。必须先获取并解析 HTML 才能知道其中三个对象的 URL；在“流水线”模式下，浏览器获得 HTML 后可在同一持续连接中连续发出三个请求，而不必逐个等待响应。HTTP 的每次请求／首个响应按一个 $\mathrm{RTT}_w$ 计。

<Solution>

### 参考答案

| 情形 | 总时延 |
| --- | --- |
| （1）单张图片 | $n\,\mathrm{RTT}+2\,\mathrm{RTT}_w$ |
| （2）① 非持续、顺序非流水线 | $n\,\mathrm{RTT}+8\,\mathrm{RTT}_w$ |
| （2）② 持续、非流水线 | $n\,\mathrm{RTT}+5\,\mathrm{RTT}_w$ |
| （2）③ 持续、流水线 | $n\,\mathrm{RTT}+3\,\mathrm{RTT}_w$ |

### 一、先建立计算模型：每个 RTT 到底花在哪里？

RTT 是一次往返传播所需的时间。在本题忽略小对象发送时间、额外处理时间及 TLS 握手的前提下，整个过程可以拆成三种开销：

- **DNS 查询**：依次查询 $n$ 台服务器，每台查询和应答耗时一个 $\mathrm{RTT}$，所以总耗时为 $T_{\mathrm{DNS}}=n\,\mathrm{RTT}$。这是题目给定的完整 DNS 查询开销，不再额外增加一次本地域名服务器往返。
- **TCP 建立连接**：客户端发送 SYN，收到 SYN+ACK 后即可发送第三次握手的 ACK，并开始发送 HTTP 请求。由客户端视角看，开始发送请求前等待的是一个 $\mathrm{RTT}_w$，而不是三个 RTT。
- **HTTP 请求及响应**：客户端发出 GET 请求，服务器返回很小的对象。由于忽略实际发送时间，一轮请求—响应耗时一个 $\mathrm{RTT}_w$。

因此，只要数清楚关键路径上有几次 TCP 建连、几轮 HTTP 请求，就能完成本题。连接释放不计入耗时，因为题目要求计算到全部对象接收完毕，而非 TCP 完全关闭。

### 二、（1）只获取一张很小的图片

DNS 解析结束后，浏览器已知 Web 服务器 IP 地址。它先建立一条 TCP 连接，再通过这条连接发送一个 HTTP 请求。

| 阶段 | 操作 | 耗时 |
| --- | --- | --- |
| DNS | 查询 $n$ 台 DNS 服务器 | $n\,\mathrm{RTT}$ |
| TCP | SYN → SYN+ACK，发送最终 ACK | $\mathrm{RTT}_w$ |
| HTTP | GET 图片 → 收到图片 | $\mathrm{RTT}_w$ |

故总时延为

$$
T_1=n\,\mathrm{RTT}+\mathrm{RTT}_w+\mathrm{RTT}_w
=\boxed{n\,\mathrm{RTT}+2\,\mathrm{RTT}_w}.
$$

### 三、（2）获取 HTML 和三个引用对象

先明确依赖关系：一份 HTML 加三个引用对象共 **4 个对象**，而且只有 HTML 接收并解析完毕，浏览器才知道三个引用对象的 URL。四个对象均位于同一服务器，所以初次 DNS 解析可以复用，不需要再解析三次。

下面以 DNS 完成时为计时起点，每格代表一个 $\mathrm{RTT}_w$。记 H 为 HTML，A、B、C 为三个引用对象。

| 时间区间（单位：$\mathrm{RTT}_w$） | 非持续、顺序 | 持续、非流水线 | 持续、流水线 |
| --- | --- | --- | --- |
| 0～1 | TCP 1 建连 | TCP 建连 | TCP 建连 |
| 1～2 | 请求并接收 H | 请求并接收 H | 请求并接收 H |
| 2～3 | TCP 2 建连 | 请求并接收 A | 连续请求 A、B、C 并接收全部响应 |
| 3～4 | 请求并接收 A | 请求并接收 B | 已完成 |
| 4～5 | TCP 3 建连 | 请求并接收 C | 已完成 |
| 5～6 | 请求并接收 B | 已完成 | 已完成 |
| 6～7 | TCP 4 建连 | 已完成 | 已完成 |
| 7～8 | 请求并接收 C | 已完成 | 已完成 |

**① 非持续 HTTP，顺序建立连接、非流水线。**

每个对象都独立使用一条 TCP 连接；题目排除了并行建连，所以前一个对象下载结束后，才能开始下一个对象的建连和下载。四次建连和四次 HTTP 请求都在关键路径上。

$$
T_{\mathrm{nonpersistent}}=n\,\mathrm{RTT}+4\times(1+1)\mathrm{RTT}_w
=\boxed{n\,\mathrm{RTT}+8\,\mathrm{RTT}_w}.
$$

**② 持续 HTTP，非流水线。**

TCP 连接只建立一次，但每次必须等当前 HTTP 响应接收完毕才能发出下一请求。H、A、B、C 共四轮请求—响应，因此

$$
T_{\mathrm{persistent}}=n\,\mathrm{RTT}+(1+4)\mathrm{RTT}_w
=\boxed{n\,\mathrm{RTT}+5\,\mathrm{RTT}_w}.
$$

**③ 持续 HTTP，流水线。**

TCP 连接只建立一次；首先独立请求 HTML，待其返回后，再在同一条连接上连续发出 A、B、C 的三个 GET 请求，不必等待前一个响应。HTTP/1.1 流水线仍要求服务器按请求顺序返回响应，但在本题忽略发送与处理时间的理想条件下，三个小对象的响应可以在同一轮往返内全部收到。

$$
T_{\mathrm{pipeline}}=n\,\mathrm{RTT}+(1+1+1)\mathrm{RTT}_w
=\boxed{n\,\mathrm{RTT}+3\,\mathrm{RTT}_w}.
$$

不能把三个引用对象与 HTML 一起在第一次请求时发出，因为此时浏览器尚不知道它们的 URL。也不能认为流水线只发一个 GET 请求；这里实际仍有四个 GET 请求，只是后面三个的等待时间发生重叠。

### 四、举一反三：HTML 引用 m 个小对象

在同一服务器、顺序建连、无缓存命中且 DNS 开销仍为 $n\,\mathrm{RTT}$ 的相同模型下，设 $m\ge 1$，总对象数是 $m+1$：

| 模式 | Web 服务器往返次数 | 总时延 |
| --- | --- | --- |
| 非持续 HTTP，串行 | $2(m+1)$ | $n\,\mathrm{RTT}+2(m+1)\mathrm{RTT}_w$ |
| 持续 HTTP，非流水线 | $m+2$ | $n\,\mathrm{RTT}+(m+2)\mathrm{RTT}_w$ |
| 持续 HTTP，流水线 | $3$ | $n\,\mathrm{RTT}+3\,\mathrm{RTT}_w$ |

若 $m=0$，没有第二批引用对象，三种方式均只需要两个 Web RTT。若允许非持续 HTTP 在 HTML 下载完成后并行建立足够多的连接，全部引用对象可在另外两个 Web RTT 内下载完毕，合计四个 Web RTT（$m\ge 1$）；这与本题禁止并行的条件不同。

**关联知识与易错点：** 持续连接减少的是 TCP 建连次数，流水线减少的是等待 HTTP 响应的轮次，二者不是同一个概念。若对象分布于不同服务器，需要另行判断 DNS 缓存、连接复用和并行关系；若对象较大，应计入数据发送时间以及可能的 TCP 窗口限制。实际 HTTP/1.1 流水线还可能受到队头阻塞影响，HTTP/2、HTTP/3 多路复用及 HTTPS 握手也不属于本题简化模型。
