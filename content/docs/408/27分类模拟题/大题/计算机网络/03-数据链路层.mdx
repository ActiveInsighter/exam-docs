## 3.3 介质访问控制

<Question id="sim1127-wd408-2027-s01-q47" type="essay" tags="来源:27王道八套卷, 试卷:第1套·第47题, 科目:计算机网络, 章节:数据链路层, 考点:802.11 DCF与CSMA/CA" points={9}>

某无线局域网采用 IEEE 802.11 DCF 工作方式，拓扑结构如下图所示。服务器 Host-S 通过 100Base-T 接口连接交换机 S，交换机通过 100Base-T 接口连接桥接模式接入点 AP；无线终端 STA1 和 STA2 关联到 AP。忽略 RTS/CTS，采用基本接入机制。TCP 连接已经建立，不讨论拥塞窗口的具体变化。

![](/images/27王道8套卷1025/p014-1.svg)

1. DCF 使用什么介质访问控制机制？与以太网 CSMA/CD 的主要区别是什么？
2. STA1 监听到信道忙后，信道转为空闲，发送普通数据帧前需要经历哪些等待／退避过程？为何 ACK 可以优先于新的竞争数据帧发送？
3. Host-S 向 STA1 发送 IP 分组，AP 在无线侧转发成一个 802.11 数据帧。STA1 接收的无线帧中，**地址 1、地址 2、地址 3** 分别是什么 MAC 地址？
4. STA1 通过 TCP 连续向 Host-S 发送多个数据段，**第一个 TCP 数据段在 STA1→AP 无线侧最终丢失（802.11 MAC 重试后仍未成功），而后续多个数据段到达 Host-S**。Host-S 随后的 TCP ACK 通常具有什么特征？在什么条件下 STA1 可进行快速重传？若条件不满足又会怎样？
5. STA1 与 STA2 均向 AP 发送数据，未启用 RTS/CTS 时仍可能遇到什么典型冲突问题？结合图说明出现条件。

<Solution>

### （1）DCF 的介质访问机制

**答案：CSMA/CA（载波监听多点接入/碰撞避免）。**

| 比较维度 | CSMA/CD | CSMA/CA |
| --- | --- | --- |
| 典型场景 | 传统半双工共享以太网 | 802.11 DCF 无线局域网 |
| 发送前 | 监听介质 | 载波监听、帧间间隔、随机退避 |
| 发送时 | 检测碰撞，可停止发送 | 无线发送端通常难以同时可靠地检测碰撞 |
| 发送后 | 碰撞后退避重传 | 单播帧通常以 MAC ACK 确认，未确认则按重试规则处理 |

现代全双工交换以太网没有共享半双工冲突域，不再需要 CSMA/CD。CSMA/CA 是降低碰撞概率，并非保证零碰撞。

### （2）忙转空闲后的竞争发送流程

1. STA1 发现信道忙，延期发送；若已有退避计数器则冻结它。
2. 信道持续空闲满 DIFS（正常 DCF 竞争条件）后，开始随机退避或继续未完成的退避。
3. 每经过一个空闲时隙，退避计数减 1；期间若其他站发送，则再次冻结，待空闲满足 DIFS 后恢复。
4. 退避计数为 0 时发送数据帧；接收端正确收到需要确认的单播数据帧后，等待 SIFS，发送 MAC ACK。

由于 $\mathrm{SIFS}<\mathrm{DIFS}$，ACK 可以在新竞争者完成 DIFS 等待之前发出，无须再执行普通竞争退避。这是在同一无线介质的正常载波监听条件下建立的优先顺序，并不意味着隐藏终端永远不会造成干扰。

### （3）AP 向 STA1 转发时的三地址

先按图确定：服务器与 STA1 属于同一桥接网络，AP 只是链路层转发设备。下行无线帧从分布式系统进入 BSS，因此 `To DS=0, From DS=1`。

| 地址字段 | 角色 | MAC 地址 |
| --- | --- | --- |
| 地址 1 | 无线接收端 RA，同时是最终目的 DA | STA1：`00-11-11-11-11-D1` |
| 地址 2 | 无线发射端 TA，即 AP 的 BSSID | AP：`00-11-11-11-11-C1` |
| 地址 3 | 原始源 SA | Host-S：`00-11-11-11-11-88` |

记忆方法：地址 1/2 总是首先定位当前无线跳的收、发双方；地址 3 用于补足桥接网络中的另一端地址。上行 `To DS=1` 时，地址 3 反而是最终目的地址。

### （4）首个 TCP 数据段丢失后的 ACK 与重传

设缺失数据段的第一个字节序号为 x，接收方此前已经连续收到 x 之前的所有数据。TCP 累计确认机制规定 ACK 号表示下一个期望字节。

| 到达 Host-S 的数据 | 累计 ACK |
| --- | --- |
| 首段丢失 | 仍期望 x |
| 后续第一个乱序段 | ACK=x |
| 后续第二个乱序段 | ACK=x |
| 后续第三个乱序段 | ACK=x |
| 缺失段重传成功 | 若后续数据已缓存且连续，ACK 可一次前进至整个连续区间末尾的下一字节 |

经典 TCP 快速重传在发送方收到 **3 个重复 ACK** 时触发（这里假设此前已有相同累计 ACK 的基准确认，且后续 ACK 符合重复 ACK 的判定条件），无需等待 RTO。若重复 ACK 不足或没有触发其他丢包恢复机制，则通常依靠重传超时恢复。启用 SACK 的实现还可报告乱序收到的字节区间，但累计 ACK 不会跨越缺口。

题设已明确 802.11 重试最终失败，这是必要前提：若链路层重试成功，TCP 不一定观察到此次无线丢帧。

### （5）隐藏终端问题

若 STA1、STA2 都位于 AP 的通信范围内，但因距离、障碍物或信号强度限制而不能互相监听，两者可能同时判断信道空闲并向 AP 发送，最终在 AP 的接收端发生碰撞。这就是**隐藏终端问题**。图只说明两个终端均关联 AP，不能据此确定彼此是否可监听。

RTS/CTS 可让听不到发送站但能收到 AP 的 CTS 的站点设置网络分配向量 NAV 并推迟发送，从而减少此类冲突；它仍不能保证消除所有碰撞。考研中要区分链路层 MAC ACK（确认帧）和传输层 TCP ACK（确认字节流），不要将二者混为一谈。

</Solution>

## 3.4 局域网

<Question id="sim1127-408-jingcheng-2027-05-47" type="essay" tags="来源:27竞成10套卷, 试卷:第5套·第47题, 科目:计算机网络, 章节:数据链路层, 考点:VLAN与802.11帧转发" points={9}>

某网络拓扑如下图所示，R 为路由器，S1、S2 为支持 VLAN 的以太网交换机，AP1 为 802.11 接入点，仅 S1 与 S2 之间为干线链路，其他均为普通链路。网络中划分两个 VLAN：VLAN-10 的网络地址为 192.168.10.0/24，VLAN-20 的网络地址为 192.168.20.0/24。路由器 R 通过两个接口分别接入 VLAN-10 和 VLAN-20，其中 VLAN-10 对应接口 IP 地址为 192.168.10.1/24，MAC 地址为 00-11-11-11-11-A1；VLAN-20 对应接口 IP 地址为 192.168.20.1/24，MAC 地址为 00-11-11-11-11-A2。DHCP 服务器和 H1 接在交换机 S1 上，AP1 接在 S2 上，无线主机 H4 通过 AP1 接入网络，均属于 VLAN-10；H2 接在 S1 上，H3 接在 S2 上，均属于 VLAN-20。各设备的 IP 地址和 MAC 地址如下图所示。假设各交换机端口已正确划入相应 VLAN，不考虑传输差错。

![网络拓扑](/images/exams/408-jingcheng-2027/05-47-topology.svg)

请回答下列问题：

(1) 在 VLAN-20 中，网络地址为 192.168.20.0/24，其中 192.168.20.1 已分配给路由器 R 在 VLAN-20 中的接口，192.168.20.2、192.168.20.3 已分别分配给主机 H2、H3，则 VLAN-20 中还可分配的 IP 地址数量是多少？

(2) 假设 H1 和 H3 的 ARP 表均已建立，现 H1 向 H3 发送一个 IP 数据报，则该 IP 数据报封装成的 MAC 帧在 H1 到 H3 的过程中目的 MAC 地址是否有变化，请说明理由。

(3) H4 首次接入 AP1 时通过 DHCP 动态获取 IP 地址，在发送 DHCP 请求报文时发往 AP1 的 MAC 帧中的地址 3 是什么？封装成的 IP 数据报目的 IP 地址是什么？从 H4 到 DHCP 服务器之间 MAC 帧头共经过几次变化？请详细说明。

<Solution>

### （1）VLAN-20 的剩余可分配 IPv4 地址数

`192.168.20.0/24` 的主机号占 8 位，总地址数为 $2^8=256$。网络地址 `.0` 与定向广播地址 `.255` 不可作为本题中的普通单播接口地址；可用地址为 `.1` 至 `.254`，共 254 个。

已占用 `.1`（R 的接口）、`.2`（H2）、`.3`（H3），因此：

$$N=2^{32-24}-2-3=\boxed{251}$$

易错点：默认网关本身也占用一个主机地址，不能只减去两台主机。

### （2）H1 到 H3 的帧首部变化

**目的 MAC 地址会变化。** H1 的 IP 为 `192.168.10.3/24`，H3 为 `192.168.20.3/24`。对两个 IP 分别与掩码 `255.255.255.0` 按位与，得到不同的网络地址，故 H1 必须把数据交给默认网关 R，而非直接 ARP H3。

| 链路阶段 | 源 MAC | 目的 MAC |
| --- | --- | --- |
| H1 → S1 → R 的 VLAN-10 接口 | `00-11-11-11-11-C1` | `00-11-11-11-11-A1` |
| R 的 VLAN-20 接口 → S1 → S2 → H3 | `00-11-11-11-11-A2` | `00-11-11-11-11-D2` |

R 收到第一跳的帧，去掉旧链路层首部，查路由表，确定 VLAN-20 为直连网络，再查询或使用缓存中的 H3 的 MAC，重新封装第二跳的帧。虽然题目仅明确 H1 与 H3 的 ARP 表已建立，并未保证 R 已缓存 H3，R 若无缓存仍可先发 ARP 请求获取其地址；不影响最终数据帧的目的 MAC。

交换机在同一 VLAN 内进行二层转发，不会将源、目的 MAC 改成自身地址；干线上的 VLAN 标签可以变化。无 NAT 条件下，IP 源/目的地址仍是 H1/H3，路由器则会递减 TTL 并更新 IPv4 首部校验和。

### （3）H4 初次 DHCP 获取地址与帧格式

**地址 3：`FF-FF-FF-FF-FF-FF`；目的 IP：`255.255.255.255`；帧首部发生 3 次格式变化（按题意，干线使用带标签的 VLAN-10 帧）。**

在初次分配地址的 SELECTING 阶段，DHCP 客户端通常广播 DHCPDISCOVER，收到 OFFER 后再广播 DHCPREQUEST，以便选中的服务器以及其他提供 OFFER 的服务器均能获知选择结果。此时源 IP 为 `0.0.0.0`，目的 IP 为受限广播 `255.255.255.255`，UDP 源/目的端口为 68/67。续租时的 DHCPREQUEST 可以单播，不能把首次申请的结论推广到所有 DHCP 报文。

H4 向 AP1 发送的是上行基础设施无线帧（To DS=1，From DS=0）：

| 802.11 字段 | 本题值 |
| --- | --- |
| 地址 1：RA/BSSID | `00-11-11-11-11-E1`（AP1） |
| 地址 2：TA/SA | `00-11-11-11-11-F1`（H4） |
| 地址 3：DA | `FF-FF-FF-FF-FF-FF`（广播） |

随后 AP1 桥接广播帧，交换机沿 VLAN-10 泛洪。按 H4 到 DHCP 服务器的实际链路依次追踪：

| 经过的设备或链路 | 帧类型及首部变化 |
| --- | --- |
| H4 → AP1 | 802.11 三地址数据帧 |
| AP1 → S2 | 第 1 次：转成无标签以太网帧，源 MAC 为 H4、目的 MAC 为广播 |
| S2 → S1 的 Trunk | 第 2 次：添加 VLAN-10 的 802.1Q 标签，增加 4 B |
| S1 → DHCP 服务器 | 第 3 次：去掉标签，恢复普通以太网帧，减少 4 B |

注意，802.11 转以太网时的精确长度差依赖具体无线首部、LLC/SNAP 等封装，题目不要求计算该差值。若真实 Trunk 将 VLAN-10 配置成不带标签的 native VLAN，后两处标签变化不发生；原题未另行指定 native VLAN，按通常考研模型采用带标签干线。广播只在 VLAN-10 内扩散，DHCP 服务器恰好位于该 VLAN，故不需要 DHCP 中继。

</Solution>

</Question>
