## 1.1 操作系统的发展历程

<Question id="sim1127-wd408-2027-s01-q23" type="single" tags="来源:27王道八套卷, 试卷:第1套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:操作系统资源虚拟化" points={2}>

操作系统可以管理计算机系统的各类资源，并对资源进行虚拟化。下列关于虚拟化的说法中，正确的是（ ）。

Ⅰ. 时间片轮转调度算法是一种对 CPU 资源的虚拟化

Ⅱ. 内存分区是一种对内存资源的虚拟化

Ⅲ. SPOOLing 是一种设备虚拟技术，采用了类似于脱机输入/输出的思想

Ⅳ. 虚拟机管理程序一定运行在内核态

<Option correct>I、II、III</Option>

<Option>I、II</Option>

<Option>II、III</Option>

<Option>I、II、III、IV</Option>

<Solution>

**结论：Ⅰ、Ⅱ、Ⅲ。** 广义的资源虚拟化是将有限的物理资源抽象为多个任务可分别使用的逻辑资源。常见实现思路有时间复用、空间复用和设备模拟。

- **Ⅰ 正确：**时间片轮转将 CPU 时间划分为若干片段，例如 A、B、C 三个进程依次轮流执行。每个进程都可以持续推进自己的任务，从逻辑上获得一个虚拟处理器。物理单核并没有同时执行三个进程，这是时间复用。
- **Ⅱ 正确（广义口径）：**分区管理把内存划分成多个区域分配给不同进程，使进程分别获得自己的内存区域，属于空间复用。这里的“虚拟化”不应狭义理解为请求分页、按需调入或扩大地址空间；单纯内存分区并不能实现通常所说的虚拟存储器。
- **Ⅲ 正确：**SPOOLing 通过磁盘上的输入井、输出井暂存数据，并由后台程序统一使用实际设备。例如多个进程把打印请求写入输出井，再由打印进程顺序输出，逻辑上都可以提交打印任务，物理打印机却仍是独占型设备。
- **Ⅳ 错误：**虚拟机管理存在不同实现方式。裸机型管理程序通常直接掌控硬件，而宿主型方案可以包含运行在用户态的管理进程，并由内核或硬件辅助完成特权操作。因此不能断言虚拟机管理程序的所有部分一定运行于内核态。

**归纳：**CPU 时间片体现时间复用，内存分区体现空间复用，SPOOLing 体现独占设备向虚拟共享设备的转换。

</Solution>

</Question>

<Question id="sim1127-wd408-2027-s05-q23" type="single" tags="来源:27王道八套卷, 试卷:第5套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:多道程序设计与中断机制" points={2}>

关于**典型采用中断驱动 I/O 的抢占式多道程序操作系统**，下列叙述正确的有（ ）。

Ⅰ. 时钟中断、I/O 完成中断等是触发操作系统重新调度并切换进程的重要机制。

Ⅱ. 中断驱动 I/O 使进程可以在设备工作期间让出 CPU，有利于 CPU 与 I/O 设备并行工作，提高处理机利用率。

Ⅲ. I/O 软件通常将中断处理程序置于靠近硬件的底层，用于响应设备发出的中断请求。

<Option>Ⅰ、Ⅱ</Option>
<Option>Ⅱ、Ⅲ</Option>
<Option>Ⅰ、Ⅲ</Option>
<Option correct>Ⅰ、Ⅱ、Ⅲ</Option>

<Solution>

**结论：Ⅰ、Ⅱ、Ⅲ。** 多道程序设计希望在一个进程等待 I/O 时，让另一个就绪进程使用 CPU；中断机制使 CPU 不必不断轮询设备是否完成。

**以一次磁盘读请求为例：**进程 A 发起读盘系统调用，操作系统启动设备并使 A 阻塞，然后调度进程 B 执行。磁盘在后台读数据，完成后发出中断；CPU 暂停 B 的执行进入中断处理程序，内核确认设备状态、唤醒 A，随后按调度策略决定返回 B 还是改为执行 A。

- Ⅰ 正确：时钟中断可以使抢占式调度器检查时间片，I/O 完成中断则可能使新的进程就绪。两者均是常见调度触发来源。
- Ⅱ 正确：上述过程中 B 的计算可与磁盘为 A 服务的过程重叠，减少 CPU 空闲或忙等的时间，提高利用率。
- Ⅲ 正确：典型 I/O 软件由上到下可分为用户层软件、设备独立性软件、设备驱动程序和中断处理程序。中断处理程序直接面对设备中断事件，是靠近硬件的一层。

**原题校订说明：**原先“没有中断就不可能实现多道程序”“并行必须有中断”等绝对措辞已在题干中限定为典型抢占式、中断驱动 I/O 系统。中断既不是所有多道程序实现的唯一手段，也不意味着每次中断都要切换进程；系统调用、主动让出 CPU、异常等同样可以触发调度。

</Solution>
</Question>

<Question id="sim1127-408-jingcheng-2027-08-23" type="single" tags="来源:27竞成10套卷, 试卷:第8套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:操作系统基本功能" points={2}>

下列关于操作系统功能的说法中，错误的是（ ）。

<Option>操作系统是一种系统软件，用于控制和管理计算机的各种硬件资源并为用户提供服务。</Option>
<Option>分时系统可以同时支持多个用户访问系统，而用户通常可以获得独立的计算资源。</Option>
<Option>操作系统允许将进程的逻辑地址空间映射到物理内存中的不连续区域。</Option>
<Option correct>作业调度是指操作系统如何分配 CPU 时间给不同的进程。</Option>

<Solution>

本题主要区分作业调度与进程调度，同时考查操作系统的资源管理和分时特性。

- **A 正确：**操作系统作为系统软件，管理 CPU、内存、文件和设备，并通过命令接口、系统调用等向上层提供服务。
- **B 正确（逻辑意义）：**分时系统通过时间片调度和资源隔离，让不同用户获得交互式、相对独立的使用体验，并不代表每个用户拥有一套独立的物理 CPU，也不保证用户之间完全没有性能影响。
- **C 正确：**分页管理将虚拟页映射到物理页框。虚拟地址连续的两个页可以分别存放在不相邻的物理页框中，因此逻辑空间连续不要求物理空间连续。
- **D 错误：**作业调度是从外存后备作业中选择作业，使其进入内存并建立进程；进程调度才是在就绪进程中选出下一运行者、分配 CPU。

| 调度层次 | 选择对象 | 主要目标 |
| --- | --- | --- |
| 高级调度（作业调度） | 后备作业 | 决定哪些作业进入系统运行 |
| 中级调度（内存调度） | 可挂起或重新激活的进程 | 调节内存压力与多道程度 |
| 低级调度（进程调度） | 就绪进程或线程 | 决定下一时刻 CPU 给谁使用 |

**记忆方法：**高级调度决定“能不能进来”，低级调度决定“现在轮到谁运行”。

</Solution>

</Question>

## 1.2 操作系统的运行环境

<Question id="sim1127-wd408-2027-s02-q25" type="single" tags="来源:27王道八套卷, 试卷:第2套·第25题, 科目:操作系统, 章节:操作系统概述, 考点:上下文切换与中断响应" points={2}>

在以下关于进程上下文切换机制与异常/中断机制比较的叙述中，错误的是（ ）。

<Option>进程上下文切换完成后，CPU 执行另一个进程的代码</Option>
<Option>异常/中断请求被响应后，CPU 执行内核程序的代码</Option>
<Option correct>进程上下文切换和异常/中断响应的全部操作均通过执行内核程序实现，不需要硬件参与</Option>
<Option>进程上下文切换和异常/中断响应均会引起执行路径（运行进程/处理流程）的改变</Option>

<Solution>

关键是把异常/中断的**硬件响应**与进入内核后的**软件处理**分开，同时区分执行路径改变和进程切换。

以用户进程 P 执行时发生外部中断为例，典型流程如下：

1. CPU 硬件检测到可响应的中断，按体系结构规则保存必要的断点和状态，切换到相应特权级，并转入中断入口。
2. 内核中断处理程序进一步保存现场、处理设备事件，必要时唤醒进程。
3. 如果不需要调度，恢复 P 的现场并返回；如果决定调度 Q，则保存 P 的运行上下文并恢复 Q 的上下文。

A 正确：真正发生从 P 到 Q 的进程上下文切换后，将继续执行 Q 的指令。B 正确：在通常的操作系统模型中，响应异常或中断后执行相应内核处理程序。C 错误：第一步必须由硬件机制参与完成，不能由尚未获得控制权的软件自行完成全部响应。D 正确：二者都会改变当前执行路径，但中断可以处理后返回同一进程，而进程切换则改变运行主体。

**原文校订说明：**原 C 项容易把硬件“响应”和软件“处理”混为一谈，现有题干已经明确为“全部操作、不需要硬件参与”。进程切换一般由内核代码控制，也可能需要硬件支持的寄存器操作。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s03-q23" type="single" tags="来源:27王道八套卷, 试卷:第3套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:用户态与内核态转换" points={2}>

关于 CPU 的内核态与用户态，下列说法正确的有（ ）。

I. 当 CPU **响应**外设发出的 I/O 完成中断时，若原来处于用户态，则将切换至内核态执行中断处理。

II. 采用虚拟存储管理时，地址转换发现访问页号超出该进程合法页号范围，会产生异常并进入内核态处理。

III. 采用请求分页管理时，访问的合法页面不在内存会引发缺页异常，需要进入内核态处理。

IV. CPU 响应并处理中断时，一定同时发生进程切换。

<Option correct>I、II、III</Option>
<Option>I、II</Option>
<Option>II、III</Option>
<Option>I、II、III、IV</Option>

<Solution>

**结论：I、II、III。** 判断是否需要进入内核态，首先看事件是否需要操作系统以特权权限处理，而不是看是否换了进程。

- **I 正确：**外设完成 I/O 后发出外中断。CPU 真正响应中断时，如果原先在用户态，通常会进入内核态执行相应的处理程序。发出请求和 CPU 响应请求是两个时刻，中间可能因为屏蔽或优先级而延迟。
- **II 正确：**虚拟地址超出进程合法地址范围，属于地址越界或保护异常。它不是简单的“页面暂时不在内存”，不能直接通过把某个页面调入内存来修复；通常由内核判定并报告非法访问。
- **III 正确：**访问合法虚拟页，但该页未驻留内存，触发缺页异常。内核查找后备存储或分配页面，更新页表等信息，随后通常重新执行引发缺页的指令。
- **IV 错误：**进入内核态可以仍然为原进程服务。中断处理结束后，完全可能恢复原进程的现场，而不发生进程切换。

| 事件 | 产生原因 | 常见处理结果 |
| --- | --- | --- |
| I/O 外中断 | 外部设备完成操作 | 确认事件、唤醒等待者 |
| 越界或保护异常 | 地址非法或权限不足 | 报告错误或终止进程 |
| 普通缺页异常 | 合法页尚未驻留 | 调页或分配页面后重试 |

**易错点：**题干已经把原转写的“立即”修订为“响应时”。模式切换改变 CPU 权限，进程切换改变运行主体，二者不等价。

</Solution>
</Question>

<Question id="sim1127-408-jingcheng-2027-01-23" type="single" tags="来源:27竞成10套卷, 试卷:第1套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:系统调用与故障断点" points={2}>

用户态进程因执行系统调用而转入内核态，与因直接非法访问内核空间而转入内核态相比，下列叙述中正确的是（ ）。

<Option>前者属于指令引起的异常，后者属于硬件触发的外部中断</Option>
<Option>前者执行的是非特权指令，后者执行的是特权指令</Option>
<Option correct>前者硬件保存的断点为下一条指令地址，后者为当前指令地址</Option>
<Option>前者进入内核态时需要更新页表基址寄存器，后者不需要</Option>

<Solution>

按 408 通常使用的陷入（Trap）与故障（Fault）分类，主动系统调用和非法访存都属于执行指令时引发的内部异常，但返回断点不同。

假设地址 `0x1000` 处的指令是系统调用指令，其下一条指令位于 `0x1004`。系统调用已经按程序意图发起，服务完成后通常应继续执行 `0x1004`，因此体系结构需要保存或形成下一条指令对应的返回地址。若 `0x1000` 处是一条访问受保护内核地址的普通 load 指令，则指令在完成前因权限检查失败而产生故障；故障现场对应 `0x1000`，便于定位出错指令，或在可恢复的故障中重新执行。

- A 错误：非法访存不是设备发起的外部中断，而是执行当前指令触发的内部异常。
- B 错误：系统调用指令必须允许用户态发起；非法访存也可能由普通读写指令引起，错误在于访问地址或权限，而非指令本身属于特权指令。
- C 正确：按题目采用的教材模型，Trap 保存下一条指令地址，Fault 保存当前指令地址。
- D 错误：模式切换本身不必更换进程地址空间，不能据此断言系统调用必须更新页表基址而故障不需要。现实中采用内核页表隔离等机制的系统可能在两类入口都切换页表。

**边界：**不同 ISA 的异常返回地址寄存器定义可能不同，有的由软件调整保存的 PC；非法访问也未必能恢复执行。考研按题设的典型断点语义判断，不应把它当作所有处理器的绝对规则。

</Solution>

</Question>

系统在用户态下运行时，以下说法正确的有（ ）。

I. 可以执行访管指令

II. 可以执行命令解释程序

III. 可以设置时钟寄存器

IV. 不可以执行缺页处理程序

<Option>I、II、III</Option>
<Option correct>I、II、IV</Option>
<Option>I、III、IV</Option>
<Option>II、III、IV</Option>

<Solution>

**结论：I、II、IV。** 用户态可以执行普通应用指令，也可以主动发起系统调用；但不能自行执行会改变系统全局控制状态的特权操作。

I 正确：访管指令（如系统调用或 Trap 指令）允许在用户态执行。它通过硬件规定的受控入口使 CPU 转入内核态，由内核检查请求参数和权限。若访管指令只能在内核态执行，用户程序反而无法正常请求系统服务。

II 正确：命令解释程序（Shell）通常是普通用户态程序，负责读取、解释命令并启动其他程序。它执行文件访问、创建进程等需要内核帮助的工作时，会调用系统调用，而不是一直运行于内核态。

III 错误：题目中的设置时钟寄存器指设置用于系统时钟中断等的受保护硬件寄存器。这关系到抢占调度和 CPU 时间分配，通常仅允许内核执行，不能和用户态读取时间或通过系统调用设置定时器混同。

IV 正确：缺页处理程序需要检查页表、分配物理页框、执行必要的 I/O 并更新映射，这些属于内核内存管理的职责。用户态普通访存可以引发缺页异常，但内核缺页处理程序必须以适当特权运行。

**记忆方法：**发起请求可以在用户态，执行受保护的资源管理操作要在内核态。

</Solution>

</Question>

<Question id="sim1127-408-jingcheng-2027-06-23" type="single" tags="来源:27竞成10套卷, 试卷:第6套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:用户态可执行指令" points={2}>

下列操作中，可以在用户态执行的有（ ）。

I. 执行除法指令

II. 初始化中断向量表

III. 执行 Trap 指令

IV. 从内存中取数

V. 改变程序计数器（PC）的值

VI. 关闭中断允许位

<Option>2 种</Option>
<Option>3 种</Option>
<Option correct>4 种</Option>
<Option>5 种</Option>

<Solution>

**结论：4 种，即 I、III、IV、V。** 判断指令能否在用户态执行，不是看它是否会改变硬件寄存器，而是看它是否绕过权限限制或直接控制系统关键资源。

| 操作 | 用户态是否允许 | 原因 |
| --- | --- | --- |
| I 执行除法 | 是 | 普通算术运算；除零时才可能产生异常 |
| II 初始化中断向量表 | 否 | 涉及系统中断入口及受保护的控制状态 |
| III 执行 Trap | 是 | 用户态请求内核服务的受控入口 |
| IV 从内存取数 | 是 | 可以读取合法且有权限的地址 |
| V 改变 PC | 是 | 普通跳转、分支和函数调用都会改变 PC |
| VI 关闭中断允许位 | 否 | 普通用户程序不能禁止系统处理硬件中断 |

例如，用户态循环中的条件分支可以改变 PC，但不能通过跳转把 CPU 自行提升为内核态；普通 load 指令可以读取用户内存，但访问没有权限的地址会触发异常。类似地，执行 Trap 指令本身合法，不代表用户可以任意执行陷入之后的内核特权指令。

**注意：**这里 VI 指全局硬件中断允许状态，不是用户程序屏蔽自己的软件信号。

</Solution>

## 1.3 操作系统结构

<Question id="sim1127-408-jingcheng-2027-05-23" type="single" tags="来源:27竞成10套卷, 试卷:第5套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:分层模块宏内核微内核外核" points={2}>

下列关于操作系统结构的叙述，正确的是（ ）。

I. 分层法中每层通常只调用其低层提供的功能和服务，因此不便于系统调试和验证

II. 模块化结构中各模块相对独立，可通过明确接口相互协作，也可支持内核模块的动态装入

III. 宏内核将主要系统服务放在内核态运行，各管理模块之间可直接相互调用

IV. 微内核基于客户/服务器模式，用户态服务之间可通过消息传递机制进行通信，能提供高性能的系统服务

V. 外核主要负责硬件资源的分配、回收和保护，将资源管理策略更多交给上层库操作系统或应用程序实现

<Option>I、II</Option>
<Option>III、V</Option>
<Option>I、III、IV</Option>
<Option correct>II、III、V</Option>

<Solution>

**结论：II、III、V。** 操作系统结构的核心差别是系统服务放在哪里、模块之间如何调用，以及硬件资源的管理机制与策略由谁负责。

| 结构 | 基本特点 | 典型取舍 |
| --- | --- | --- |
| 分层法 | 上层依赖下层规定的接口 | 便于逐层验证，但跨层调用可能增加开销 |
| 模块化 | 相对独立模块通过接口协作 | 易扩展；需要管理模块依赖 |
| 宏内核 | 大部分系统服务在内核态 | 直接调用通常开销较小，但故障隔离较弱 |
| 微内核 | 将尽可能多的服务移到用户态 | 隔离和可维护性较好，IPC 可能带来额外开销 |
| 外核 | 内核主要负责安全复用硬件 | 资源管理策略更多交给库操作系统或应用 |

I 错误：明确的层次与接口使得下层可以先验证，再逐步测试上层，通常便于调试而不是不便于调试。II 正确：模块化支持明确接口，且可以实现可加载模块。III 正确：宏内核中的主要服务能够通过内核函数直接协作，减少跨保护域通信。IV 按教材命题口径错误：前半句描述微内核基本结构正确，但相比宏内核，消息传递和保护域切换通常引入额外开销，不能直接把高性能作为该结构的必然优势。V 正确：外核倾向于提供保护与安全资源复用机制，由应用或库操作系统决定更高层的管理策略。

**题设边界：**IV 的“能提供高性能”如果仅表示有可能达到高性能，并非严格错误；现代微内核可以通过优化 IPC 获得高性能。按本题选项和教材比较口径，应理解为“微内核结构天然带来性能优势”，因此选 D。

</Solution>

</Question>

<Question id="sim1127-408-jingcheng-2027-09-23" type="single" tags="来源:27竞成10套卷, 试卷:第9套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:内核架构与操作系统接口" points={2}>

下列说法中，正确的有（ ）个。

I. 配备了虚拟存储器的多道程序环境中，运行的进程越多，CPU 利用率越高。

II. 外核是不同于微内核和宏内核的一种操作系统内核架构。

III. 操作系统提供的接口包括联机接口和脱机接口。图形用户界面（GUI）是一种脱机接口。

IV. 内存映射文件技术结合了虚拟内存管理技术与文件管理技术，方便易用，节省空间。

<Option>1</Option>
<Option correct>2</Option>
<Option>3</Option>
<Option>4</Option>

<Solution>

**结论：2 项，即 II、IV。** 本题将多道程序的负载、内核结构、用户接口和内存映射放在一起考查，要分别判断，不能只凭熟悉的关键词选择。

I 错误：适当增加进程数可以利用其他进程等待 I/O 的时间，提高 CPU 利用率；但当各进程工作集需要的物理页框超过可用内存时，会频繁缺页、换入换出，发生抖动。此时继续增加进程反而可能降低 CPU 利用率。多道程度和 CPU 利用率不是单调递增关系。

II 正确：外核是另一种内核结构思路，主要提供硬件资源保护及安全复用，将较高级的抽象及策略交给库操作系统或应用，与宏内核、微内核的服务组织方式不同。

III 错误：联机接口强调用户与系统直接交互，既包括命令行，也包括 GUI；脱机接口通常指预先编写作业控制信息、提交批处理作业，不要求执行中持续交互。“图形”不代表“脱机”。

IV 正确：文件可映射到进程虚拟地址空间，之后以普通内存读写访问文件内容。共享映射还可以使多个进程复用同一物理文件页，减少重复缓冲和拷贝；按需调页使未访问部分不必全部装入内存。

**注意：**内存映射并非任何场景都保证节省空间。题目中的“节省空间”指共享页、按需加载等带来的典型收益，而不是所有实现和访问模式的绝对结论。

</Solution>

## 1.4 操作系统引导

<Question id="sim1127-wd408-2027-s08-q23" type="single" tags="来源:27王道八套卷, 试卷:第8套·第23题, 科目:操作系统, 章节:操作系统概述, 考点:BIOS 与 MBR 引导流程" points={2}>

在传统 BIOS + MBR 分区表的磁盘引导方式下，CPU 依次执行的程序顺序是（ ）。这里的“分区引导程序”指活动分区的引导扇区代码，忽略额外的第二阶段引导管理器。

<Option>ROM 引导程序 → 分区引导程序 → 硬盘主引导程序 → 操作系统初始化程序</Option>
<Option>硬盘主引导程序 → 分区引导程序 → ROM 引导程序 → 操作系统初始化程序</Option>
<Option correct>ROM 引导程序 → 硬盘主引导程序 → 分区引导程序 → 操作系统初始化程序</Option>
<Option>ROM 引导程序 → 硬盘主引导程序 → 操作系统初始化程序 → 分区引导程序</Option>

<Solution>

传统 BIOS/MBR 启动过程本质上是一层层寻找并装入更完整的引导程序，先执行的程序必须已经位于 CPU 能访问的位置。

| 次序 | 当前执行的程序 | 主要任务 |
| --- | --- | --- |
| 1 | ROM 引导程序（BIOS 固件） | 上电后自检、初始化基本硬件，选择启动磁盘，读取 MBR |
| 2 | 硬盘主引导程序（MBR 中的代码） | 根据分区表找到活动分区，加载分区引导扇区并转交控制权 |
| 3 | 分区引导程序 | 从该分区继续加载操作系统引导代码或内核 |
| 4 | 操作系统初始化程序 | 初始化内存、调度、设备、文件系统等内核功能 |

因此必须先由 ROM 固件寻找硬盘的主引导记录，再由主引导程序找到活动分区，不能颠倒两个磁盘引导程序的位置，也不能在引导程序找到并加载操作系统前先执行系统初始化。

**易错点：**MBR 是磁盘级的主引导记录，分区引导记录是分区级的引导记录。这里已明确忽略额外的第二阶段引导管理器，且采用传统 BIOS+MBR；现代 UEFI 通常从 EFI 系统分区加载 EFI 程序，并不必然遵循上述 MBR 链式路径。

</Solution>
</Question>
