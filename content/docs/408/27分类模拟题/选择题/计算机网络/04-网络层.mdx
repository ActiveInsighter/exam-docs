## 4.1 网络层的功能 (SDN 基本概念)

<Question id="sim1127-408-jingcheng-2027-04-37" type="single" tags="来源:27竞成10套卷, 试卷:第4套·第37题, 科目:计算机网络, 章节:网络层, 考点:OpenFlow流表匹配" points={2}>

下列与 OpenFlow 1.0 交换机中流表的匹配字段设计相关的网络层次是（ ）。

I. 应用层

II. 运输层

III. 网络层

IV. 链路层

<Option>

I、II、III

</Option>
<Option correct>

II、III、IV

</Option>
<Option>

II、III

</Option>
<Option>

III、IV

</Option>

<Solution>

**结论：II、III、IV。** OpenFlow 的流表将分组转发抽象为“匹配首部字段，再执行相应动作”。OpenFlow 1.0 的典型匹配字段跨越链路层、网络层和运输层，但不深入 HTTP 等应用层报文内容。

| 层次 | 可匹配字段示例 |
| --- | --- |
| 链路层 | 源/目的 MAC、EtherType、VLAN ID、VLAN 优先级 |
| 网络层 | 源/目的 IPv4 地址、IP 协议号、ToS 字段 |
| 运输层 | TCP/UDP 源端口、目的端口（还可用于表示 ICMP 类型和代码） |
| 设备元数据 | 入端口，不属于上述四层的协议首部 |

例如可匹配目的 IP 为指定网段、协议为 TCP、目的端口为 80 的分组，然后执行转发或丢弃。这不是读取 HTTP 请求的 URL，所以即使端口号暗示应用类型，也不等同于匹配应用层字段。

一条流表项通常包含匹配字段、计数器和动作等；题目问的是匹配字段涉及的层次，故不选 I。

</Solution>

</Question>

## 4.2 IPv4

<Question id="sim1127-wd408-2027-s02-q37" type="single" tags="来源:27王道八套卷, 试卷:第2套·第37题, 科目:计算机网络, 章节:网络层, 考点:CIDR子块划分" points={2}>

若将一个 IPv4 **/17 地址块完整划分**为恰好 9 个互不重叠的、符合 CIDR 规则的地址子块（允许子块大小不等，且不保留未划分地址），则最小的子块可能包含的 IP 地址数量为（ ）。

<Option>126</Option>
<Option correct>128</Option>
<Option>2046</Option>
<Option>2048</Option>

<Solution>

**结论：128 个地址。** CIDR 地址块的大小必须为 2 的整数次幂，并且网络起始地址按该块大小对齐。完整划分时，可以把原地址块看作二叉树的根，每次二分将一个块替换为两个等大、前缀长增加 1 的子块。

原 `/17` 块有 $2^{15}=32768$ 个地址。一次二分使块数增加 1；要恰好得到 9 块，需要 8 次二分。任意子块深度最多为 8，否则其每一级的另一支都至少贡献一个子块，总数会超过 9。

为了让最小块达到这个下界，可连续 8 次只拆分同一支。最终前缀分别为 `/18`、`/19`、`/20`、`/21`、`/22`、`/23`、`/24`、`/25`、`/25`，共 9 块，且完全覆盖原块。最小块为 `/25`，包含

$$
2^{32-(17+8)}=128
$$

个 IP 地址。题目不是问可分配给主机的地址数，所以不减去网络地址和广播地址；126 是常规 `/25` 的可用主机数。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s02-q38" type="single" tags="来源:27王道八套卷, 试卷:第2套·第38题, 科目:计算机网络, 章节:网络层, 考点:移动IP与隧道封装" points={2}>

如图，移动主机 A 的永久 IP 地址为 `218.75.230.16`，当前漫游到外地网络，从外地代理获得的转交地址为 `175.1.1.1`。固定主机 B 向 A 发送 IP 数据报。则 **B 发出的原始 IP 数据报**的目的地址，以及**归属代理发出的封装后外层 IP 数据报**的目的地址分别为（ ）。

![](/images/27王道8套卷1025/p022-1.svg)

<Option correct>`218.75.230.16`，`175.1.1.1`</Option>
<Option>`175.1.1.1`，`218.75.230.16`</Option>
<Option>`218.75.230.16`，`0.0.0.0`</Option>
<Option>`255.255.255.255`，`218.75.230.16`</Option>

<Solution>

移动 IPv4 通过永久地址标识移动主机，通过转交地址标识其当前所处位置。两者的用途不同，不能简单用后者替换前者。

| 传送阶段 | IP 目的地址 | 说明 |
| --- | --- | --- |
| B 发出原始 IP 数据报 | `218.75.230.16` | B 按 A 的永久地址通信 |
| 归属代理截获并封装 | 外层 `175.1.1.1` | 外层数据报沿隧道路由至转交地址 |
| 外地代理解封装 | 内层 `218.75.230.16` | 去掉外层首部，交付原数据报 |

图中 A 原归属网络为 `218.75.230.0/24`，漫游至 `175.1.0.0/16`。归属代理根据登记的转交地址完成隧道封装。以 IP-in-IP 为例，原数据报作为外层 IP 的载荷，内部目的地址一直保持为永久地址。

考点是区分原始首部与封装首部，而不是询问链路层下一跳 MAC；若将内层目的地址直接改成转交地址，就失去了原数据报的移动主机标识。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s04-q37" type="single" tags="来源:27王道八套卷, 试卷:第4套·第37题, 科目:计算机网络, 章节:网络层, 考点:IPv4分片与片偏移" points={2}>

某 TCP 报文段长 $3200\,\mathrm{bit}$，交给 IPv4 层后附加 $160\,\mathrm{bit}$ 的 IP 首部，得到总长 $3360\,\mathrm{bit}$ 的 IPv4 数据报。经路由器转发到下一个局域网时，该局域网可承载的**每个 IP 数据报（分片）最大总长度为 $1200\,\mathrm{bit}$**（包括 IP 首部）；每个分片的 IP 首部仍为 $160\,\mathrm{bit}$，按 IPv4 片偏移的 $8$ 字节单位分片，且允许分片。则这个局域网交给上层 IP 的**全部分片总长度**为（ ）。

<Option>$3160\,\mathrm{bit}$</Option>
<Option correct>$3840\,\mathrm{bit}$</Option>
<Option>$4240\,\mathrm{bit}$</Option>
<Option>$3200\,\mathrm{bit}$</Option>

<Solution>

**结论：3840 bit。** 先统一使用字节计算：IP 负载为 $3200/8=400$ B，首部为 20 B，链路 MTU 为 $1200/8=150$ B。

每个分片最多携带 $150-20=130$ B 负载。但 IPv4 片偏移以 8 B 为单位，因此除最后一片外，负载长度必须为 8 B 的整数倍。最大合法非末片负载为 $\lfloor130/8\rfloor\times8=128$ B。

| 分片 | 负载（B） | 总长度（B） | 片偏移 | MF |
| --- | ---: | ---: | ---: | ---: |
| 1 | 128 | 148 | 0 | 1 |
| 2 | 128 | 148 | 16 | 1 |
| 3 | 128 | 148 | 32 | 1 |
| 4 | 16 | 36 | 48 | 0 |

总负载仍为 400 B，但 IP 首部从 1 份增至 4 份，故全部分片的 IP 总长度是 $(400+4\times20)\times8=3840$ bit。

分片发生在 IP 层，TCP 首部已包含在 400 B 负载中，无须给每片增加 TCP 首部；本题也不计局域网帧首部等链路层开销。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s06-q37" type="single" tags="来源:27王道八套卷, 试卷:第6套·第37题, 科目:计算机网络, 章节:网络层, 考点:IPv4首部校验和" points={2}>

IPv4 数据报首部采用**16 位反码求和再取反**的检验和，而非 CRC。下列对这种设计的原因理解最恰当的是（ ）。

<Option>反码求和校验一定比 CRC 具有更强的检错能力。</Option>
<Option correct>反码求和计算与更新较简单，适合路由器在转发时迅速校验并更新首部检验和。</Option>
<Option>IP 首部太长，因而完全不能使用 CRC 检验。</Option>
<Option>CRC 只支持固定长度消息，而 IPv4 首部长度可变。</Option>

<Solution>

IPv4 使用 16 位反码和校验首部：发送端将校验和字段置零，把首部按 16 位字分组，进行带回卷进位的加法，再对结果按位取反；接收端对包含校验和的首部重新求和，正确时应为全 1。

路由器逐跳转发时会改变 TTL，必要时也会修改其他首部字段，因此首部校验和必须更新。反码加法便于快速计算，也可根据变化前后的字段增量更新。若原校验和为 $HC$、旧 16 位字为 $m$、新字为 $m'$，可用反码运算表达为 $HC'=\sim(\sim HC+\sim m+m')$，其中加法含回卷进位。

A 错：反码和并不一定比 CRC 检错能力强。C、D 错：CRC 能处理多种长度的报文，不是因为 IP 首部太长或长度可变才不能使用。B 才说明该设计有利于逐跳更新的原因。

IPv4 校验和只覆盖首部；TCP/UDP 校验和另行保护传输层数据，以太网 FCS 则通常采用 CRC。IPv6 基本首部取消了首部校验和字段。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s07-q38" type="single" tags="来源:27王道八套卷, 试卷:第7套·第38题, 科目:计算机网络, 章节:网络层, 考点:IGMPv2多播组" points={2}>

**按照 IGMPv2 的主机加入多播组过程**，下列说法正确的是（ ）。

<Option>IGMP 能精确获知各局域网每个多播组的成员总数</Option>
<Option>IGMP 在整个因特网范围内逐一管理所有组播接收者</Option>
<Option correct>主机加入一个多播组时，可向该组的多播地址发送 IGMPv2 成员关系报告</Option>
<Option>多播组的成员关系一旦确定就不能再变化</Option>

<Solution>

IGMP 是 IPv4 主机与本地组播路由器之间维护组成员关系的协议，解决的是“这个链路上是否存在某个组的接收者”，不是为整个 Internet 建立全局成员名单。

按 IGMPv2，主机加入组 G 时，可以主动向组 G 的多播地址发送 Membership Report；组播路由器通过查询和报告维持接口上的成员关系。主机离组时可发送 Leave Group，路由器再通过特定组查询判断是否仍有接收者。

- A 错：成员报告存在抑制机制，路由器一般并不精确统计组内主机数量。
- B 错：IGMP 的作用范围是本地链路；跨路由器的组播分发需要组播路由机制。
- C 对：IGMPv2 成员报告的 IP 目的地址为所报告的组地址。
- D 错：成员可动态加入和离开。

版本区分：IGMPv3 的成员关系报告发往 `224.0.0.22`，不能把 IGMPv2 的目的地址规则无条件推广到其他版本。原题已明确 IGMPv2，以消除版本歧义。

</Solution>
</Question>

<Question id="sim1127-wd408-2027-s07-q40" type="single" tags="来源:27王道八套卷, 试卷:第7套·第40题, 科目:计算机网络, 章节:网络层, 考点:ARP、DHCP与ICMP" points={2}>

某计算机刚接入校园**IPv4 以太网**，按题设采用 **DHCP 自动获取 IP 配置**，并通过 **ARP 动态解析缺省网关的 MAC 地址**；随后用 `ftp` 连接校园网外的文件服务器 `202.38.70.25`。假设网络畅通、没有额外诊断或差错报告报文。在上述过程中，**可能完全不需要使用**的是（ ）。

<Option>IP</Option>
<Option correct>ICMP</Option>
<Option>ARP</Option>
<Option>DHCP</Option>

<Solution>

**结论：ICMP。** 按题设的网络初始化及 FTP 访问过程，可以把协议按发生阶段排列：

| 阶段 | 协议 | 本题是否必须 |
| --- | --- | --- |
| 获取 IP 地址、掩码及网关 | DHCP（基于 UDP/IP） | 是，题干明确指定 |
| 获取默认网关 MAC | ARP | 是，题干明确动态解析 |
| 向校外服务器建立 FTP 连接并通信 | TCP/IP | 是，FTP 依赖 TCP/IP |
| 诊断或差错报告 | ICMP | 否，正常通信可不触发 |

主机根据掩码判断服务器在远端网络，所以以太网帧的目的 MAC 是下一跳网关，而 IP 目的地址仍为服务器 `202.38.70.25`。FTP 的 TCP 建连使用 SYN 等 TCP 报文，不要求事先 ping 服务器。

ICMP 在 IPv4 中用于差错报告及网络诊断等，题设排除这些额外事件，因此可能完全没有 ICMP 报文。另因服务器直接以 IP 地址给出，也不需要为了该地址进行 DNS 域名解析（不是本题选项）。若取消 DHCP/ARP 的明确前提，静态配置或已有邻居缓存也可能让相应协议不出现；原题已补充条件。

</Solution>
</Question>

<Question id="sim1127-408-jingcheng-2027-02-36" type="single" tags="来源:27竞成10套卷, 试卷:第2套·第36题, 科目:计算机网络, 章节:网络层, 考点:IPv4特殊地址" points={2}>

下列 IP 地址中，只能作为 IP 分组的目的地址而不能作为源地址的是（ ）。

<Option>0.0.0.0</Option>
<Option>223.255.255.250</Option>
<Option>192.168.101.1</Option>
<Option correct>230.1.1.1</Option>

<Solution>

| 选项 | 地址类别及用途 | 判断 |
| --- | --- | --- |
| A | `0.0.0.0`：未指定地址，如主机尚未获知自己的地址时 | 特定初始化场景可作源地址，不是普通目的地址 |
| B | `223.255.255.250`：普通单播地址范围内 | 在适当子网配置下可作源和目的 |

组播范围首字节为 224–239，传统分类称 D 类地址；看到 230 即可判断。私有地址不允许直接在公共 Internet 中路由，并不等于不能作为 IP 数据报的目的地址。B 的具体网络地址或广播地址属性仍取决于子网掩码，题中没有指定特殊前缀。

</Solution>

</Question>

<Question id="sim1127-408-jingcheng-2027-05-37" type="single" tags="来源:27竞成10套卷, 试卷:第5套·第37题, 科目:计算机网络, 章节:网络层, 考点:IPv4多播与ICMP" points={2}>

某主机 H 向 IPv4 多播组 239.192.1.2 发送 UDP 数据报，该数据报封装成以太网帧后在局域网中发送，经过某路由器转发时 TTL 减为 0。下列说法正确的是（ ）。

<Option>目的 MAC 地址应为 01-00-5E-40-01-02，且路由器应向 H 发送 ICMP 时间超过报文</Option>
<Option correct>目的 MAC 地址应为 01-00-5E-40-01-02，但路由器不应向 H 发送 ICMP 差错报告报文</Option>
<Option>目的 MAC 地址应为 01-00-5E-C0-01-02，且路由器应向 H 发送 ICMP 时间超过报文</Option>
<Option>目的 MAC 地址应为 FF-FF-FF-FF-FF-FF，但路由器不应向 H 发送 ICMP 差错报告报文</Option>

<Solution>

本题分别考查 IPv4 组播地址到以太网 MAC 的映射，以及 ICMP 差错报文的发送限制。

IPv4 组播 MAC 的固定高 25 位对应 `01-00-5E` 加下一字节最高位 0，低 23 位来自 IPv4 地址的低 23 位。将 `239.192.1.2` 的后 3 个字节写成十六进制 `C0-01-02`，再将 `C0` 的最高位清零：`C0 AND 7F = 40`。因此目的 MAC 为 `01-00-5E-40-01-02`，不是 `...-C0-01-02`，也不是全 F 广播地址。

路由器发现 TTL 耗尽应丢弃数据报；一般单播数据报可能触发 ICMP Time Exceeded，但 IPv4 规则禁止对目的地址为 IP 组播的数据报生成此类 ICMP 差错报告，以避免大量响应造成拥塞。因此本题不发送 ICMP 时间超过报文。

补充：IPv4 组播地址有效组号有 28 位，而映射仅保留低 23 位，故多个 IP 组播地址可能映射到同一个组播 MAC，需要网络层进一步过滤。

</Solution>

<Question id="sim1127-wd408-2027-s03-q37" type="single" tags="来源:27王道八套卷, 试卷:第3套·第37题, 科目:计算机网络, 章节:网络层, 考点:RIP距离向量" points={2}>

| :---: | :---: |

<Option>$0,4,4$</Option>

<Solution>

**结论：距离依次为 0、5、4。** RIP 是距离向量协议，邻居通告的是它自己到目的网络的距离，不是本路由器经该邻居到目的网络的距离。

**第一步：计算候选距离。** 本题规定相邻路由器间增加 1 跳，故 R1 经 R2 到网络 $N$ 的候选距离为 $d(N)=1+d_{R2}(N)$，三个候选值依次为 4、5、4，候选下一跳均为 R2。

**第二步：比较当前表项并更新。**

| 目的网络 | 旧距离 | 旧下一跳 | 候选距离 | 更新理由 | 最终距离 |
| --- | ---: | --- | ---: | --- | ---: |
| 10.0.0.0 | 0 | 直连 | 4 | 直连更优，保留旧路由 | 0 |

本题明确采用直连距离为 0 的教学约定；不要混入实际 RIP 实现中直连网络度量通常为 1 的口径。

</Solution>

- A 错误：eBGP 用于不同 AS，iBGP 用于同一 AS 内部的 BGP 路由传播，所以不能说 BGP 只能在 AS 之间使用。
- B 错误：BGP 不依赖周期性发送完整路由表来维护路由；正常情况下使用 UPDATE 宣告新增、变更或撤销的路由。RIP 可周期发送路由信息，但也受水平分割等规则影响。两者优化目标也不同，不能用同一个全局最短路径概念判断。
- C 错误：OSPF 直接封装在 IP 中（协议号 89），但其洪泛的是链路状态通告 LSA，不是路由表变化部分，而且 LSA 即使未变化也有周期刷新。各路由器基于链路状态数据库自行运行最短路径算法。
- D 正确：OSPF Hello 用于发现、维护邻居，BGP 在 TCP（端口 179）上通过 KEEPALIVE 等维持会话。

</Solution>

## 4.5 网络层设备

<Question id="sim1127-wd408-2027-s03-q38" type="single" tags="来源:27王道八套卷, 试卷:第3套·第38题, 科目:计算机网络, 章节:网络层, 考点:默认网关选择" points={2}>

一台主机的 IP 地址为 $11.1.1.100$，子网掩码为 $255.0.0.0$。现要从以下与主机所在链路相关的路由器接口中选择一个**同子网可直接到达的下一跳地址**作为默认网关：

I. $11.1.1.1/8$　II. $11.1.2.1/8$　III. $12.1.1.1/8$　IV. $13.1.2.1/8$

可能作为该主机默认网关的是（ ）。

<Option correct>I 和 II</Option>
<Option>I 和 III</Option>
<Option>I、III 和 IV</Option>
<Option>III 和 IV</Option>

<Solution>

**结论：I、II。** 判断默认网关能否直接到达，应使用本机子网掩码计算网络地址，而不是凭 IP 的前几段是否相似。

$255.0.0.0$ 的二进制为 `11111111.00000000.00000000.00000000`，即 /8。主机地址与掩码按位与得到 `11.0.0.0`，所以其直连子网为 `11.0.0.0/8`。

| 候选接口地址 | 与 /8 掩码按位与 | 是否属于本地子网 |
| --- | --- | --- |
| 11.1.1.1 | 11.0.0.0 | 是 |
| 11.1.2.1 | 11.0.0.0 | 是 |
| 12.1.1.1 | 12.0.0.0 | 否 |
| 13.1.2.1 | 13.0.0.0 | 否 |

主机向异地网络发送数据时，IP 分组的目的 IP 仍为远端目标，链路层帧的目的 MAC 则通常为默认网关接口的 MAC。为了通过 ARP 获取这个 MAC，网关必须是本地链路可达的下一跳。题目已经限定相关路由器接口与主机链路有关，因此 I、II 均可能作为默认网关；实际配置中仅同子网还不足以保证对方真能提供转发服务。

</Solution>
