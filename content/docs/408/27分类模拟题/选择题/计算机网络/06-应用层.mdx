## 6.1 网络应用模型

<Question id="sim1127-wd408-2027-s05-q40" type="single" points={2} tags="来源:27王道八套卷, 试卷:第5套·第40题, 科目:计算机网络, 章节:应用层, 考点:客户服务器模型与端口">

关于客户端／服务器（C/S）模型，下列说法**错误**的有（ ）。

Ⅰ. 客户端和服务器端都必须在连接建立**之前**知道对方的网络地址。

Ⅱ. 使用 HTTP 明文默认端口时，客户端和服务器端的本地 TCP 端口号都必须是 $80$。

Ⅲ. 在典型的浏览器访问网页场景中，网页使用的 HTML 等资源可以来自 Web 服务器。

Ⅳ. 客户端发起连接之后，服务器端也不能主动向客户端发送任何数据。

<Option>Ⅰ、Ⅳ</Option>
<Option>Ⅱ、Ⅳ</Option>
<Option correct>Ⅰ、Ⅱ、Ⅳ</Option>
<Option>仅Ⅳ</Option>

<Solution>

**结论：Ⅰ、Ⅱ、Ⅳ错误。** C/S 模型的核心是服务器提供服务并等待请求，客户端主动发起服务访问；双方并非只能按一个固定方向传输数据。

- Ⅰ 错误：客户端主动连接时通常需要知道服务器的 IP 与服务端口，可以先通过 DNS 解析域名。服务器可以在收到连接请求时获知客户端地址和源端口，不要求连接建立前就掌握所有客户端地址。
- Ⅱ 错误：HTTP 明文默认服务端口为 TCP 80，客户端通常使用系统分配的临时端口。例如客户端 `192.0.2.20:51000` 连接服务器 `192.0.2.10:80`。客户端源端口并不必须为 80。
- Ⅲ 正确：HTML、CSS、图片等网页资源可以由 Web 服务器返回，浏览器也可以使用本地缓存或执行脚本生成内容。题目使用“可以”而非“必须”，所以成立。
- Ⅳ 错误：客户端发起 TCP 连接后，TCP 是全双工的，服务器当然可以发送数据。普通 HTTP 服务器会返回响应；在 WebSocket 等允许双向消息的应用协议中，服务器还能主动发送应用层消息。不能将 C/S 的连接发起角色与后续数据传输方向混为一谈。

**关联考点：** C/S 与 P2P 的主要区别是服务提供和组织方式，而不是 TCP 是否全双工。P2P 节点可同时承担客户端和服务器角色，C/S 服务器也能并发服务多个客户端。

</Solution>
</Question>

## 6.2 域名系统 (DNS)

<Question id="sim1127-wd408-2027-s03-q40" type="single" points={2} tags="来源:27王道八套卷, 试卷:第3套·第40题, 科目:计算机网络, 章节:应用层, 考点:DNS缓存、递归与迭代查询">

关于 DNS（域名系统）的说法中，**正确**的是（ ）。

<Option>如果整个互联网的 DNS 服务都不可用，即使知道目标主机 IP 地址，也无法向它发送 IP 数据报</Option>
<Option correct>DNS 解析过程中广泛使用高速缓存，可减少重复查询、缩短解析时间，并减轻上级和根域名服务器负荷</Option>
<Option>DNS 只能基于 TCP 传输，目的是提供可靠交付</Option>
<Option>查询到某个权威域名服务器后，如果它不能直接给出最终答案，DNS 必须立即判定整个查询失败</Option>

<Solution>

DNS 负责域名与资源记录之间的映射，IP 层负责按目的 IP 地址转发数据报。两者处在不同层次，不能混淆。

**逐项判断：**

- A 错误：若发送方已知目的 IP 地址，网络层便可以根据路由表选择下一跳，并在相应链路上发送数据报，无须再做域名解析。DNS 不可用会使依赖域名的访问受阻，但并不意味着 IP 层停止工作；直接使用 IP 也不保证所有应用都能正常使用，例如依赖主机名的虚拟主机服务。
- B 正确：本地递归解析器可以缓存已经取得的地址记录（A、AAAA）以及域名服务器记录（NS）等。在记录的 TTL（生存时间）未到期时，重复查询可以直接命中缓存，或者从已缓存的较低层域名服务器继续查询，减少解析时延和上级服务器负荷。
- C 错误：传统 DNS 可以使用 UDP 和 TCP，服务器端通常使用 53 号端口。一般查询常用 UDP；响应被截断时可以改用 TCP，区域传送也通常使用 TCP。可靠性并不意味着 DNS 只能使用 TCP。
- D 错误：权威服务器不一定负责目标名称所在的最终子区。如果目标处于它委派出去的子区，它可以返回子区的 NS 记录及必要的地址信息，解析器继续向下查询即可。只有根据相应响应和查询过程确定名称不存在或无法获得结果时，才作相应处理，不能将转介直接视为失败。

**关联考点：** 主机通常向本地解析器发起递归查询，由本地解析器向根、顶级域及权威服务器进行迭代查询。递归强调由被请求方负责取得最终结果，迭代强调返回现有答案或下一步查询线索。缓存不仅保存最终 IP，还可以保存中间委派信息。

</Solution>
</Question>

<Question id="sim1127-408-jingcheng-2027-01-40" type="single" points={2} tags="来源:27竞成10套卷, 试卷:第1套·第40题, 科目:计算机网络, 章节:应用层, 考点:DNS迭代查询与缓存">

第 33～40 题、第 47 题均依据下图作答。图中 R1、R2、R3 为路由器，SW0、SW1 为链路层交换机，AP 为无线接入点，S1、S2、S3 分别为 DNS 服务器、DHCP 服务器、CODE 服务器，H1、H2、H3、H4 为主机。SW0 支持 VLAN 划分，按端口划分了 VLAN-10 基础服务区、VLAN-20 有线网络区、VLAN-30 无线网络区，R1 配置了各 VLAN 的网关和 DHCP 中继代理。

![网络拓扑图](/images/exams/408-jingcheng-2027/01-33-47-topology.svg)

S1 采用迭代查询方式进行域名解析，初始缓存为空。现 H1 访问 www.abc.com.cn，S1 成功解析并缓存了相关记录。接下来 H2 访问 www.abc.com，若在此期间无缓存过期，则 S1 最先发出的 DNS 查询请求的目标是（ ）。

<Option correct>根域名服务器</Option>
<Option>.com 顶级域名服务器</Option>
<Option>.cn 顶级域名服务器</Option>
<Option>.abc.com 权限域名服务器</Option>

<Solution>

**结论：根域名服务器。** 本题考查的是 DNS 域名层次与缓存复用，而不是 VLAN 或路由路径。图中 H1、H2 均使用 S1 作为题设中的 DNS 解析器，因此可以复用 S1 的缓存。

**第一步：确定两个域名的层次。** DNS 域名从右向左识别层次，最右侧省略的点表示根域。

| 待解析域名 | 从根向下的名称层次 | 顶级域 |
| --- | --- | --- |
| `www.abc.com.cn` | 根 → `cn` → `com.cn` → `abc.com.cn` → `www.abc.com.cn` | `.cn` |
| `www.abc.com` | 根 → `com` → `abc.com` → `www.abc.com` | `.com` |

**第二步：分析第一次查询留下的缓存。** 初始缓存为空，S1 从根域开始迭代查询，取得 `.cn` 下相关的委派记录和 `www.abc.com.cn` 的最终解析结果。实际 DNS 的区域切分不必与每一层标签一一对应，因此并非一定分别访问 `com.cn` 和 `abc.com.cn` 两台服务器，但正常解析不会因此取得 `.com` 顶级域的委派记录。

**第三步：判断第二次查询的起点。** `www.abc.com` 与第一次解析的名称分属不同顶级域。`com.cn` 中出现 `com` 字样，并不代表它属于 `.com`；S1 不能把 `.cn` 下的服务器当成 `.com` 的权威服务器。在题设的空缓存起点、只缓存正常查询所得记录的模型下，第二次查询仍需先访问根域名服务器，取得 `.com` 的委派信息，再逐层向下解析。

所以 B、C、D 均不是本次最先查询的目标，选 A。

**易错点：** 判断能否复用中间缓存，应比较域名右侧的共同后缀，而不是共同前缀或中间出现的单词。比如解析完 `www.abc.com.cn` 后再解析 `mail.abc.com.cn`，就可能利用已有的权威服务器缓存跳过根与顶级域查询。

</Solution>

</Question>

## 6.3 文件传输协议 (FTP)

<Question id="sim1127-408-jingcheng-2027-07-40" type="single" points={2} tags="来源:27竞成10套卷, 试卷:第7套·第40题, 科目:计算机网络, 章节:应用层, 考点:FTP主动与被动模式">

下列有关 FTP 的叙述中，错误的是（ ）。

<Option>FTP 基于 C/S 模式进行设计</Option>
<Option>主动模式下服务器默认使用 20 号端口进行数据连接，21 号端口进行控制连接</Option>
<Option correct>FTP 不允许客户指明文件的类型和格式</Option>
<Option>控制连接用于传输控制信息，在传输过程中长期保持开启状态</Option>

<Solution>

**结论：题目要求选错误项。** FTP 是应用层文件传输协议，使用 TCP 实现可靠的控制信息与文件数据传输。它的典型特点是将控制连接和数据连接分开，而不是通过一条 TCP 连接混合传输所有内容。

**逐项判断：**

- A 正确：FTP 采用客户/服务器模型，客户端发起登录、列目录、上传或下载请求，服务器提供文件传输服务。
- B 正确：在教材所述的默认主动模式中，客户端先连接服务器的 TCP 21 号端口建立控制连接；需要数据传输时，服务器通常从 TCP 20 号端口主动连接客户端指定的数据端口。注意 20 和 21 都是此处的服务器端默认端口。
- C 错误：FTP 允许客户端通过命令协商传输表示类型、文件结构和传输模式。例如 `TYPE A` 表示 ASCII 类型，`TYPE I` 表示 Image（二进制）类型。客户端可以选择适当的传输方式，并非只能按服务器固定的文件表示类型传输。
- D 正确：控制连接一般在整个 FTP 会话期间保持，用于传递命令及服务器响应；数据连接通常按一次文件传输或目录列表操作建立和释放（教材常见流模式）。二者的生命周期不同。

**主动模式与被动模式对比：**

| 比较项目 | 主动模式（PORT/EPRT） | 被动模式（PASV/EPSV） |
| --- | --- | --- |
| 控制连接发起方 | 客户端 | 客户端 |
| 服务器控制端口 | 默认 21 | 默认 21 |
| 数据连接发起方 | 服务器 | 客户端 |
| 服务器数据端口 | 教材默认 20 | 服务器选定的监听端口，不固定为 20 |

**易错点：** 主动与被动是针对数据连接建立方向而言，不是针对文件上传与下载方向，也不是针对控制连接的建立方向。被动模式通常更容易适应客户端位于 NAT 或防火墙之后的场景。

</Solution>

</Question>

## 6.5 万维网 (www)

<Question id="sim1127-wd408-2027-s01-q40" type="single" points={2} tags="来源:27王道八套卷, 试卷:第1套·第40题, 科目:计算机网络, 章节:应用层, 考点:HTTP持续连接、请求与响应">

下列关于 HTTP 的说法中，正确的是（ ）。

Ⅰ. 当用户点击某个包含1个文本文件和3张图片的网页时，如果 HTTP 使用持续连接，那么只需发送1个请求报文就能收到4个响应报文

Ⅱ. 可以使用同一个 HTTP/1.1 持续连接传输对 x.com/1.html 和 x.com/2.html 的请求和响应

Ⅲ. 当 HTTP 使用非持续连接时，一个 TCP 报文段也可装入两个不同的请求报文

Ⅳ. 响应报文中的实体主体部分永远不会是空的

<Option>Ⅰ、Ⅱ</Option>

<Option correct>仅 Ⅱ</Option>

<Option>Ⅲ、Ⅳ</Option>

<Option>Ⅱ、Ⅳ</Option>

<Solution>

**结论：仅Ⅱ正确。** HTTP 的持续连接与非持续连接，讨论的是多个 HTTP 请求/响应能否复用同一条 TCP 连接，不是一个请求可以获得多少个独立资源，也不是 TCP 报文段和 HTTP 报文之间的边界关系。

- Ⅰ 错误：在题设的普通网页访问模型下，基础 HTML 文件和 3 张独立图片是 4 个资源，需要分别请求，通常对应 4 个 HTTP 请求和 4 个响应。持续连接允许这些请求复用一条 TCP 连接，但不会把 4 次资源请求自动合并为 1 次。这里假设无缓存命中、图片没有内嵌到 HTML 中。
- Ⅱ 正确：两个资源均位于 `x.com`。在协议、服务器端口等连接复用条件相同且连接尚未关闭时，HTTP/1.1 可以在同一条持久 TCP 连接上传输多个请求和响应，不必每请求一个文件就重新建立连接。
- Ⅲ 错误：按考研教材的非持续 HTTP 模型，一条 TCP 连接只用于一次 HTTP 请求/响应交换，所以不在同一条连接中发送两个独立的请求。TCP 本身是字节流协议，并不禁止一个报文段承载多个应用层报文的字节，但这种传输层能力不能推翻题设的非持续 HTTP 使用约定；不能把两条连接的数据装进同一个 TCP 报文段。
- Ⅳ 错误：HTTP 响应允许没有消息体。例如 `HEAD` 请求对应的响应没有消息体，`204 No Content` 和 `304 Not Modified` 响应也不携带消息体。

**关联考点：HTTP 时延模型。** 设有 $n$ 个小对象位于同一服务器，忽略传输时间、DNS、连接释放与并行连接，且采用普通 TCP 三次握手：

| 方式 | 获取这 $n$ 个对象的时间（均已知 URL，从无 TCP 连接开始） |
| --- | --- |
| 非持续、逐个请求 | $2n\,RTT$ |
| 持续、非流水线 | $(n+1)RTT$ |
| 持续、流水线 | $2RTT$ |

其中建连需要一个 RTT；流水线方式允许在收到前一个响应之前就继续发送后续请求。如果对象 URL 必须在收到基础 HTML 后才能知道，则还要计入取得基础 HTML 所花的时间。

</Solution>

</Question>

<Question id="sim1127-408-jingcheng-2027-05-40" type="single" points={2} tags="来源:27竞成10套卷, 试卷:第5套·第40题, 科目:计算机网络, 章节:应用层, 考点:DNS缓存与HTTP流水线时延">

主机通过超链接 `http://www.jc408.com/index.html` 请求浏览页面 `index.html`，该页面引用 6 个小图像，其中 3 个在 `img.a.com`，3 个在 `static.b.com`。H 收到页面后才得知图像所在域名。本地 DNS 缓存为空，本地域名服务器递归查询，其他域名服务器迭代查询，本地域名服务器可缓存解析过程中获得的中间记录且可并行解析多个新域名。各 DNS 查询/响应 RTT 均为 50 ms，Web 服务器的 RTT 均为 50 ms，忽略其他各种时延，浏览器采用 HTTP/1.1 持久流水线连接。则从点击超链接开始，直到收到完整页面的最短用时为（ ）。

<Option>450 ms</Option>
<Option>500 ms</Option>
<Option correct>550 ms</Option>
<Option>600 ms</Option>

<Solution>

**结论：550 ms。** 本题的核心是将 DNS 查询、TCP 建连、HTTP 请求分阶段，并确定哪些阶段存在先后依赖、哪些能够并行。题设每个 DNS 和 Web RTT 均为 50 ms，忽略数据传输等其他时延。

**第一步：解析基础页面域名 `www.jc408.com`。**

本地 DNS 缓存为空。按题设的教材模型，H 向本地 DNS 服务器发起递归请求，本地服务器向其他 DNS 服务器迭代查询。查询链路依次为：

1. H 与本地 DNS 服务器：1 RTT（这里计入请求和最终应答在这段链路上的往返传播时间）。
2. 本地 DNS 与根域名服务器：1 RTT，取得 `.com` 顶级域服务器的委派记录。
3. 本地 DNS 与 `.com` 顶级域服务器：1 RTT，取得 `jc408.com` 权威服务器的委派记录。
4. 本地 DNS 与 `jc408.com` 权威服务器：1 RTT，取得目标地址。

因此 DNS 解析耗时 $T_1=4RTT=200\text{ ms}$。本地 DNS 同时缓存了可供后续使用的 `.com` 委派信息。

**第二步：下载基础 HTML。** 新建到 `www.jc408.com` 的 TCP 连接需 1 RTT，发送 GET 请求到收到 HTML 需 1 RTT，因此 $T_2=2RTT=100\text{ ms}$。此时距离点击链接已经过去 300 ms，浏览器才得知图片 URL。

**第三步：并行解析两个图片域名。** 两个新域名均属于 `.com`，可利用缓存中的顶级域服务器信息，跳过根域名服务器查询。每个域名需要 H 与本地 DNS、本地 DNS 与 `.com` 服务器、本地 DNS 与相应权威服务器各 1 RTT。两条查询链可以并行，因而不是将两个域名的耗时相加，而是取较长者：

$$
T_3=\max(3RTT,3RTT)=150\text{ ms}
$$

**第四步：并行下载六张图片。** 两台图片服务器各需要一条 TCP 连接，建连各花 1 RTT；同一服务器的 3 个图片请求使用持久流水线方式发送，在题设忽略对象发送时延的模型下，全部响应再花 1 RTT。为取得最短用时，两台服务器的建连和下载过程并行执行，因此 $T_4=2RTT=100\text{ ms}$。

| 阶段 | RTT 数 | 耗时 | 累计时刻 |
| --- | --- | --- | --- |
| 基础域名 DNS 解析 | 4 | 200 ms | 200 ms |
| 基础 HTML 建连及下载 | 2 | 100 ms | 300 ms |
| 两个图片域名并行解析 | 3 | 150 ms | 450 ms |
| 两台服务器并行下载图片 | 2 | 100 ms | 550 ms |

总耗时为

$$
T=T_1+T_2+T_3+T_4=(4+2+3+2)\times50=550\text{ ms}
$$

**易错点：** 持久连接不等于整个网页只建立一条 TCP 连接；不同服务器通常分别建连。并行操作取最大耗时，具有因果依赖的阶段才顺序相加。本题还默认各域按教材所示的委派层次解析、目标服务器需要分别建立新连接、无预连接或其他可用缓存；实际 DNS 区域结构和浏览器连接策略可能使时延有所不同。

</Solution>

</Question>
