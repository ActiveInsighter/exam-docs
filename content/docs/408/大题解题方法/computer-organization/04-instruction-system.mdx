## 二、核心知识一：指令格式、机器码编码与译码

**代表题：2010 年、2021 年、2024 年真题。**

### 1. 指令格式的本质

机器指令就是一串按照事先约定划分的二进制位。

例如2010年真题给出如下16位指令：

| OP  | Ms    | Rs     | Md     | Rd      |
| --- | ----- | ------ | ------ | ------- |
| 4 位 | 3 位   | 3 位    | 3 位    | 3 位     |
| 操作码 | 源寻址方式 | 源寄存器编号 | 目的寻址方式 | 目的寄存器编号 |

CPU 读取这些字段后就知道应该：

- 执行什么运算；
- 到哪里获取源操作数；
- 到哪里获取目的操作数；
- 将运算结果保存在哪里。

因此，**不要把机器码当作一个需要整体理解的十六进制数，而要把它看成多个具有独立含义的字段。**

### 2. 硬件位数类问题的统一方法

| 所求对象       | 决定因素         |
| ---------- | ------------ |
| 最多多少种操作    | 操作码的有效编码空间   |
| 最多多少个通用寄存器 | 寄存器编号字段的位数   |
| 通用寄存器宽度    | 通常由机器字长决定    |
| ALU 宽度     | 题设中通常与机器字长一致 |
| IR 位数      | 所需保存的指令长度    |
| MAR 位数     | 需要表示的主存地址位数  |
| MDR 位数     | 题设的存储器数据传送宽度 |

如果某个寄存器编号字段占 $n$ 位，则最多可以表示：

$$
N=2^n
$$

个寄存器。

注意：**寄存器编号的位数和寄存器本身的宽度完全是两回事。**

例如32位计算机有32个通用寄存器，那么寄存器编号只需要5位，而每个通用寄存器通常是32位。

#### MAR 的计算

$$
\text{可寻址单元数} =\frac{\text{主存地址空间大小}}{\text{每个编址单元的大小}}
$$

$$
\text{MAR位数} =\left\lceil\log_2\text{可寻址单元数}\right\rceil
$$

2010年真题中，主存地址空间为128KB，字长16位，按字编址。

一个字为2B，因此：

$$
\frac{128\times 2^{10}}{2}=2^{16}
$$

所以 MAR 为16位。

而2021年真题中，字长为16位，但数据总线为8位，按题设的数据传送宽度，MDR 为8位。

这说明不能机械地认为所有寄存器宽度都等于机器字长。

### 3. 代表题精讲：2021 年真题

本题同时考查操作码、译码、补码运算和寻址。

题目规定16位指令具有三种格式：

| 格式  | 高6位    | 剩余10位        |
| --- | ------ | ------------ |
| R 型 | 000000 | rs、rt、rd、op1 |
| I 型 | op2    | rs、rt、imm    |
| J 型 | op3    | target       |

其中 R 型的 op1 占4位，各寄存器编号占2位。

#### 第一问：最多定义多少种操作？

R 型：

$$
2^4=16
$$

I 型和 J 型共同使用高6位操作码，但是其中的 `000000` 已经用于识别 R 型指令。

因此：

$$
2^6-1=63
$$

即 I 型和 J 型合计最多63种操作。

**这个题的本质是编码空间不能重复占用。**

不要分别计算两个64种操作再相加。遇到扩展操作码问题，也应该从编码空间的分配角度理解。

#### 第二问：机器码 01B2H 的功能是什么？

首先转成完整的16位二进制：

```text
0000 0001 1011 0010
```

然后按照题目规定的字段边界重新划分：

```text
000000 | 01 | 10 | 11 | 0010
  OP     rs   rt   rd    op1
```

| 字段         | 含义      |
| ---------- | ------- |
| 000000     | R 型指令   |
| rs = 01    | 寄存器 R1  |
| rt = 10    | 寄存器 R2  |
| rd = 11    | 寄存器 R3  |
| op1 = 0010 | 带符号整数减法 |

于是这条机器指令的功能就是：

$$
R[3]\leftarrow R[1]-R[2]
$$

如果将机器码改为01B3H，只有最后的功能码改变，因此变成：

$$
R[3]\leftarrow R[1]\times R[2]
$$

#### 第三问：执行结果是否溢出？

题目给定：

$$
R[1]=\mathrm{B052H},\quad R[2]=\mathrm{0008H}
$$

B052H 是一个16位负数补码，其真值为：

$$
45138-65536=-20398
$$

执行减法：

$$
-20398-8=-20406
$$

仍然处于16位带符号整数范围：

$$
[-32768,32767]
$$

因此结果为 B04AH，不溢出。

执行乘法：

$$
-20398\times8=-163184
$$

已经超出16位带符号整数范围。

截取低16位后得到8290H，但发生溢出。

**真正重要的是：机器数计算结果与数学真实结果不是同一个概念。**

即使截断后的机器数看起来仍是负数，也不代表没有溢出。

### 4. 机器码题的固定解题模板

以后遇到任何机器码题，都使用以下顺序：

1. 补齐指令的完整二进制位数。
2. 根据题设划分字段。
3. 判断指令类型与具体操作。
4. 确定源操作数和目的操作数。
5. 写出指令功能表达式。
6. 计算执行结果，必要时判断溢出。

反过来，汇编转机器码，只需要将各个字段编码后按照顺序拼接即可。

不需要背诵大量真实处理器的操作码，考试通常会给出必要的编码格式。

## 三、核心知识二：数据寻址——彻底区分地址和数据

**代表题：2010 年真题。**

### 1. 寻址方式的本质

设：

- $A$ 为指令中的形式地址或立即数字段。
- $R[r]$ 为寄存器 $r$ 的内容。
- $M[x]$ 为内存地址 $x$ 中存放的内容。
- $EA$ 为有效地址。

常见寻址方式可以统一成下表。

| 寻址方式  | 地址或操作数计算        | 本质           |
| ----- | --------------- | ------------ |
| 立即寻址  | 操作数为 $A$    | 数据就在指令里      |
| 直接寻址  | $M[A]$      | 指令给出内存地址     |
| 间接寻址  | $M[M[A]]$   | 先从内存取地址      |
| 寄存器直接 | $R[r]$      | 数据就在寄存器里     |
| 寄存器间接 | $M[R[r]]$   | 寄存器保存地址      |
| 基址寻址  | $M[R[b]+A]$ | 基址加偏移        |
| 变址寻址  | $M[A+R[i]]$ | 地址随下标变化      |
| 相对寻址  | $EA=PC+A$   | 以规定的 PC 值为基准 |

这里的相对寻址公式只是基本形式，实际题目还可能涉及 PC 自增和偏移量缩放，后面会重点讲解。

最重要的区别是：

$$
R[r]\ne M[R[r]]
$$

一个是寄存器中的内容，另一个是以该内容为地址访问内存得到的数据。

### 2. 代表题精讲：2010 年真题

题目给出：

| 对象        | 内容    |
| --------- | ----- |
| R4        | 1234H |
| R5        | 5678H |
| 内存地址1234H | 5678H |
| 内存地址5678H | 1234H |

执行指令：

```asm
add (R4), (R5)+
```

题设规定逗号前为源操作数，逗号后为目的操作数。

这里的 `(R4)` 表示寄存器间接寻址，`(R5)+` 表示寄存器间接、自增寻址。

<Steps>

<Step>

### 确定操作数

源操作数：

$$
M[R[4]]=M[\mathrm{1234H}] =\mathrm{5678H}
$$

目的操作数：

$$
M[R[5]]=M[\mathrm{5678H}] =\mathrm{1234H}
$$

</Step>

<Step>

### 运算写回

$$
\mathrm{5678H}+\mathrm{1234H} =\mathrm{68ACH}
$$

结果应该写回目的操作数所在的内存单元：

$$
M[\mathrm{5678H}]\leftarrow\mathrm{68ACH}
$$

</Step>

<Step>

### 自增副作用

题设规定按字编址，自增量为1，因此：

$$
R[5]\leftarrow\mathrm{5679H}
$$

最终状态如下：

| 对象      | 执行前   | 执行后   |
| ------- | ----- | ----- |
| R4      | 1234H | 1234H |
| R5      | 5678H | 5679H |
| 内存1234H | 5678H | 5678H |
| 内存5678H | 1234H | 68ACH |

</Step>

<Step>

### 指令编码

根据题设的操作码、寻址方式编码和寄存器编号：

```text
0010 | 001 | 100 | 010 | 101
 OP     Ms    Rs    Md    Rd
```

拼接后得到：

$$
\boxed{\mathrm{2315H}}
$$

</Step>

</Steps>

### 3. 寻址与副作用

<Callout type="warn" title="寻址三要素">

**操作数的地址、操作数的值、结果的写回位置，是三个不同的概念。**

</Callout>

特别是自增、自减寻址，要注意地址修改发生在取操作数之前还是之后。

例如：

- 后自增：先使用旧地址，再增加寄存器内容。
- 前自减：先减少寄存器内容，再使用新地址。

自增量也不能永远背成1。应当依据题设规定、编址单位以及操作数长度确定。

## 四、核心知识三：相对寻址与转移指令（极其重要）

**代表题：2013 年、2019 年、2023 年真题，模拟卷第7套。**

不同处理器和指令格式下的相对寻址具有统一的数学模型。

### 1. 相对寻址的统一公式

题库中常见的相对转移指令以顺序执行的下一条指令地址为基准。

设当前指令地址为 $P$，指令占用 $L$ 个地址单元，偏移字段的有符号真值为 $D$，偏移量缩放系数为 $s$。

则：

$$
\boxed{PC_{\text{next}}=P+L}
$$

$$
\boxed{EA=P+L+sD}
$$

反过来，如果要求计算指令中的偏移量：

$$
\boxed{D=\frac{EA-(P+L)}{s}}
$$

这个公式几乎可以统一解决题库中的相对寻址计算题。

| 指令类型            | 基准地址       | 偏移量缩放 |
| --------------- | ---------- | ----- |
| 2013年真题的16位指令   | $PC+2$ | 乘2    |
| x86 风格 jmp      | 下一条指令地址    | 乘1    |
| x86 风格 call     | 下一条指令地址    | 乘1    |
| 模拟题 MIPS 风格 bne | $PC+4$ | 乘4    |

注意，不同指令系统规定可能不同，最终必须以题设的 PC 定义和寻址公式为准。

### 2. 代表题精讲：2019 年真题

题目给出递归调用函数的机器指令：

```text
00401025    E8 D6 FF FF FF    call f1(00401000)
```

要求计算下一条指令的地址、偏移量，并判断大小端。

<Steps>

<Step>

### 下一条指令地址

一条机器指令共有5个字节：

```text
E8 D6 FF FF FF
```

所以：

$$
PC_{\text{next}} =\mathrm{00401025H}+5 =\mathrm{0040102AH}
$$

</Step>

<Step>

### 计算偏移量

$$
\begin{aligned} D&=\mathrm{00401000H}-\mathrm{0040102AH}\\ &=-\mathrm{2AH}\\ &=-42 \end{aligned}
$$

</Step>

<Step>

### 补码编码

$$
[-42]_{\text{补}}=2^{32}-42
$$

对应的十六进制机器数：

$$
\boxed{\mathrm{FFFFFFD6H}}
$$

</Step>

<Step>

### 判断字节序

偏移量的正常十六进制表示为：

```text
FF FF FF D6
```

但机器代码中按地址递增顺序存放的是：

```text
D6 FF FF FF
```

最低有效字节 D6 位于低地址，因此采用小端存储。

本题综合考查指令长度、PC 相对寻址、补码和大小端。

</Step>

</Steps>

### 3. 模拟卷第7套：同一个模型如何迁移？

题目给出的 MIPS 分支指令：

```text
地址：0x301C
机器码：1480FFF9H
指令：bne R4,R0,loop
```

已知偏移量是最低16位补码，并且以指令字为单位。

首先：

$$
[\mathrm{FFF9H}]_{\text{补}}=-7
$$

因为每条指令占4B：

$$
\begin{aligned} EA&=\mathrm{301CH}+4+4\times(-7)\\ &=\mathrm{3020H}-\mathrm{1CH}\\ &=\boxed{\mathrm{3004H}} \end{aligned}
$$

与2019年真题的唯一区别就是偏移量多乘了4。

<Callout type="warn" title="偏移量单位">

**做题时不要只看到偏移量为负7，就直接把地址减7。必须先确定偏移量的单位。**

</Callout>

### 4. 相对寻址范围的经典陷阱

2013年真题规定：

$$
EA=PC+2+2\times OFFSET
$$

OFFSET 占8位，采用补码。

所以：

$$
-128\le OFFSET\le127
$$

当 OFFSET 最小时：

$$
EA_{\min}=PC+2-256=PC-254
$$

每条指令占2B。

相对于当前指令，最多向低地址方向跳转：

$$
\frac{254}{2}=\boxed{127\text{条}}
$$

而不是128条。

完整范围如下：

| OFFSET | 相对于当前指令的位置 |
| ------ | ---------- |
| -128   | 向低地址方向127条 |
| -1     | 当前指令       |
| 0      | 下一条指令      |
| 1      | 向高地址方向2条   |
| 127    | 向高地址方向128条 |

原因就是偏移量基准为下一条指令，而不是当前指令。

从这一点可以看出，背诵偏移量的补码范围并不足以做对题，必须把偏移量放到实际的地址公式中理解。

## 五、核心知识四：高级语言与汇编代码的对应

**代表题：2023 年、2024 年真题，模拟卷第7套和第8套。**

考试通常给出机器级代码，要求分析每条指令的作用，并结合数组、寄存器、循环或存储系统进行计算。

### 1. 必须熟悉的常见汇编指令

以下功能按题库常见的 MIPS 风格和 RISC 风格表示。不同汇编语法的操作数排列顺序可能不同。

| 指令         | 基本功能          |
| ---------- | ------------- |
| add        | 加法            |
| sub        | 减法            |
| addi       | 寄存器内容加立即数     |
| sll / slli | 逻辑左移          |
| lw         | 从内存读取一个字到寄存器  |
| sw         | 将寄存器内容写入内存    |
| mov        | 数据传送          |
| cmp        | 比较并更新标志位      |
| slti       | 小于立即数则置1，否则置0 |
| beq        | 相等则转移         |
| bne        | 不相等则转移        |
| jmp / j    | 无条件转移         |
| call       | 调用函数          |
| ret        | 函数返回          |
| push / pop | 入栈、出栈         |

不用背诵所有指令的二进制编码，但必须看到这些指令就能理解它们对寄存器、内存和 PC 的影响。

### 2. 数组访问的本质是地址计算

对于一维数组：

$$
\boxed{\operatorname{Addr}(a[i]) =\operatorname{Base}(a)+i\times w}
$$

对于按行优先存放、每行有 $n$ 个元素的二维数组：

$$
\boxed{\operatorname{Addr}(a[i][j]) =\operatorname{Base}(a)+(in+j)w}
$$

其中 $w$ 为按字节编址时每个元素的字节数。

| 数据类型（题库常见设定） | 元素大小 | 下标对应偏移量        |
| ------------ | ---- | -------------- |
| char         | 1B   | $i$        |
| short        | 2B   | $i\times2$ |
| int          | 4B   | $i\times4$ |
| double       | 8B   | $i\times8$ |

具体类型大小仍以题设为准。

因为：

$$
i\times2^k=i\ll k
$$

所以汇编代码访问数组时，经常先执行移位指令。

这不是在对数组元素的值进行乘法，而是在计算数组元素的地址偏移量。

### 3. 代表题精讲：2024 年真题

C 语言语句：

```c
sum += a[i];
```

对应汇编代码：

```asm
slli r4, r2, 2
add  r4, r3, r4
lw   r5, 0(r4)
add  r1, r1, r5
```

<Steps>

<Step>

### 指令语义

| 指令             | 执行后的结果                               |
| -------------- | ------------------------------------ |
| `slli r4,r2,2` | $R[4]=4i$                        |
| `add r4,r3,r4` | $R[4]=\operatorname{Base}(a)+4i$ |
| `lw r5,0(r4)`  | $R[5]=a[i]$                      |
| `add r1,r1,r5` | $R[1]=sum+a[i]$                  |

由此立即可以判断：

| 寄存器 | 保存的内容          |
| --- | -------------- |
| r1  | sum            |
| r2  | i              |
| r3  | 数组首地址          |
| r4  | 临时偏移量、随后保存元素地址 |
| r5  | 数组元素的值         |

这里最关键的是 r4 和 r5 的区别。

r4 是地址，r5 才是真正的数据。

## 六、核心知识五：立即数的符号扩展与零扩展

**代表题：2021 年真题、模拟卷第2套第44题。**

本题通过 MIPS 风格指令考查立即数扩展。

### 1. 扩展的本质是保持原有数值

假设16位立即数需要扩展到32位。

| 原始立即数 | 零扩展       | 符号扩展      |
| ----- | --------- | --------- |
| 1234H | 00001234H | 00001234H |
| 8000H | 00008000H | FFFF8000H |
| FFFFH | 0000FFFFH | FFFFFFFFH |
| FFF9H | 0000FFF9H | FFFFFFF9H |

零扩展在高位补0，保持原来的无符号数值。

符号扩展在高位复制符号位，保持原来的补码真值。

当最高位为0时，两种扩展结果相同；当最高位为1时，两种扩展结果不同。

例如 FFFFH：

$$
\operatorname{zext}(\mathrm{FFFFH})=65535
$$

$$
\operatorname{sext}(\mathrm{FFFFH})=-1
$$

<Callout type="idea" title="立即数扩展规则">

**选择哪种扩展，取决于指令如何解释该字段，而不是取决于它看起来像正数还是负数。**

</Callout>

### 2. 代表题精讲：模拟卷第2套

题目要求通过 MIPS 风格指令读取任意32位对齐地址 $A$ 中的数据。

设地址：

$$
A=\mathrm{1234F234H}
$$

将它拆分为高、低16位：

$$
A_{\text{upper}}=\mathrm{1234H}
$$

$$
A_{\text{lower}}=\mathrm{F234H}
$$

题目给出两种方案。

<Tabs items={['LUI + ORI + LW', 'LUI + LW']}>

<Tab value="LUI + ORI + LW">

```asm
lui t0, 0x1234
ori t0, t0, 0xF234
lw  s0, 0(t0)
```

第一条指令 LUI 将立即数放到高16位，低16位补0：

```text
t0 = 1234 0000H
```

第二条指令 ORI 对立即数零扩展：

```text
1234 0000
0000 F234
--------- 按位或
1234 F234
```

于是得到正确的完整地址。

最后 LW 读取这个地址中的数据。

这里使用按位或，是因为两个字段互不重叠：

$$
A=(A_{\text{upper}}\ll16) \mathbin{|}\operatorname{zext}(A_{\text{lower}})
$$

</Tab>

<Tab value="LUI + LW">

能不能省略 ORI，直接把低16位作为 LW 的偏移量？

```asm
lui t0, 0x1234
lw  s0, 0xF234(t0)
```

乍看似乎正确，但实际上地址算错了。

因为 LW 的立即数采用符号扩展：

$$
[\mathrm{F234H}]_{\text{补}} =\mathrm{F234H}-2^{16} =-\mathrm{0DCCH}
$$

计算出的有效地址为：

$$
\begin{aligned} EA&=\mathrm{12340000H}-\mathrm{0DCCH}\\ &=\mathrm{1233F234H} \end{aligned}
$$

与目标地址相比少了：

$$
2^{16}=\mathrm{10000H}
$$

怎么办？

将 LUI 中的高16位加1即可：

```asm
lui t0, 0x1235
lw  s0, 0xF234(t0)
```

此时：

$$
\mathrm{12350000H}-\mathrm{0DCCH} =\boxed{\mathrm{1234F234H}}
$$

</Tab>

</Tabs>

#### 为什么高16位必须加1？

令地址的高16位为 $H$，低16位为 $L$。

原地址：

$$
A=H\times2^{16}+L
$$

如果低16位最高位为1，符号扩展后的数值为：

$$
L-2^{16}
$$

要保持原地址不变，就必须满足：

$$
H'\times2^{16}+L-2^{16} =H\times2^{16}+L
$$

化简：

$$
H'=H+1
$$

因此修正公式为：

$$
\boxed{ H'= \begin{cases} H,&0\le L<2^{15}\\ (H+1)\bmod 2^{16},&2^{15}\le L<2^{16} \end{cases} }
$$

### 3. 高低位补偿的通用规律

不需要死记 LUI 加 ORI 的组合。

真正需要掌握的是：**当低位字段由无符号数改为带符号补码解释时，它的数值可能减少 $2^n$，于是高位必须补偿这部分差值。**

这个思想可以迁移到任何高低位拼接、立即数扩展和地址偏移问题。

## 七、核心知识六：条件转移与运算标志位

**代表题：2013 年、2017 年、2019 年真题。**

这一部分是计组第2章数据运算和第4章指令系统的结合。

### 1. CMP 指令的本质

比较两个数 $A$ 和 $B$，在题库常见的处理器模型中，本质上是执行：

$$
A-B
$$

但是不保存减法结果，而是根据结果设置标志位。

| 标志位     | 含义          |
| ------- | ----------- |
| ZF      | 运算结果是否为0    |
| SF / NF | 运算结果最高位是否为1 |
| CF      | 无符号数进位或借位标志 |
| OF      | 带符号整数运算是否溢出 |

对于条件跳转，CPU 根据这些标志位决定是否修改 PC。

### 2. 无符号比较和有符号比较必须分开

在题库采用的减法借位时 CF 为1的约定下，执行 $A-B$ 后：

| 比较关系 | 无符号数判断条件        | 有符号数判断条件                        |
| ---- | --------------- | ------------------------------- |
| 等于   | ZF = 1          | ZF = 1                          |
| 不等于  | ZF = 0          | ZF = 0                          |
| 小于   | CF = 1          | SF $\oplus$ OF = 1          |
| 小于等于 | CF = 1 或 ZF = 1 | SF $\oplus$ OF = 1 或 ZF = 1 |
| 大于   | CF = 0 且 ZF = 0 | SF = OF 且 ZF = 0                |
| 大于等于 | CF = 0          | SF = OF                         |

不同体系结构对减法进位标志的定义可能相反，考试应当按照题设约定。

**无符号比较主要看借位，有符号比较需要考虑溢出对符号位的影响。**

为什么不能仅凭 SF 判断有符号数大小？

例如8位带符号整数：

$$
127-(-1)=128
$$

真实结果是正数，但128无法用8位补码正确表示，截断后的机器数为：

$$
10000000
$$

所以：

$$
SF=1,\quad OF=1
$$

如果仅看 SF，会错误地认为127小于-1。

而：

$$
SF\oplus OF=1\oplus1=0
$$

能够正确判断127不小于-1。

### 3. 2013年真题的条件转移模型

题目设计了三个检测位 C、Z、N，规定只要某个被选中的标志位为1，就执行转移。

可以写成逻辑表达式：

$$
\boxed{ TakeBranch= (C\land CF)\lor (Z\land ZF)\lor (N\land NF) }
$$

如果要实现无符号数小于等于时转移，只需检测 CF 或 ZF。

所以：

$$
\boxed{C=1,\quad Z=1,\quad N=0}
$$

这种写法比逐个背诵检测位的取值更容易理解。

### 4. 2017年真题：无符号数减法陷阱

题目中 $i,n$ 都是32位无符号数。

当：

$$
i=0,\quad n=0
$$

执行比较：

$$
i-(n-1)
$$

注意，$n-1$ 并不是带符号意义上的-1，而是：

$$
n-1=2^{32}-1 =\mathrm{FFFFFFFFH}
$$

因此实际进行无符号数减法：

$$
\mathrm{00000000H}-\mathrm{FFFFFFFFH}
$$

被减数小于减数，产生借位：

$$
\boxed{CF=1}
$$

截取低32位后的结果却是：

$$
\mathrm{00000001H}
$$

所以不能看到结果为正数，就认为没有发生借位。

### 5. 2019年真题：乘法溢出

两个32位带符号整数相乘，完整乘积可以用64位表示。

假设只保留低32位作为结果。

那么不溢出的充要条件是：

**完整乘积的高32位，必须恰好是低32位符号位的扩展。**

| 低32位符号位 | 不溢出时的高32位 |
| ------- | --------- |
| 0       | 全0        |
| 1       | 全1        |

也就是完整乘积的最高33位必须全0或者全1。

否则：

$$
OF=1
$$

这就是2019年真题中 imul 指令判断溢出的依据。

对于递归计算阶乘的程序，13! 超过32位 int 的表示范围，应该优先将函数返回值改成足够宽的整数类型，例如 long long，使递归乘法也按照足够宽的类型计算。

## 八、核心知识七：函数调用、指令长度与大小端

这几个考点通常不会单独构成一道大题，而是作为汇编综合题中的小问出现。

### 1. 指令长度的计算

假设程序首条指令地址为 $A$，末条指令首地址为 $B$，末条指令长度为 $L$，且程序机器代码连续存放。

则：

$$
\boxed{\text{机器代码总长度}=B-A+L}
$$

2017年真题中：

- 首条指令地址为00401020H。
- 最后一条指令地址为0040107FH。
- 最后一条 ret 指令为1B。

因此：

$$
\begin{aligned} S&=\mathrm{0040107FH}-\mathrm{00401020H}+1\\ &=\mathrm{60H}\\ &=\boxed{96\mathrm B} \end{aligned}
$$

不能把公式一律记成末地址减首地址再加1，因为最后一条指令未必只有一个字节。

### 2. 大端、小端的本质

假设32位数据为12345678H，从地址 $A$ 开始存放。

| 地址        | 大端存储 | 小端存储 |
| --------- | ---- | ---- |
| $A$   | 12   | 78   |
| $A+1$ | 34   | 56   |
| $A+2$ | 56   | 34   |
| $A+3$ | 78   | 12   |

大小端改变的是**多字节数据的存储顺序**，不改变数据本身的数值。

也不是把每个字节内部的二进制位反过来排列。

在机器指令中判断大小端时，应该找到明确的多字节立即数、地址字段或偏移量进行比较，而不是把整条机器指令全部反转。

### 3. 函数调用与普通跳转的区别

| 指令              | 是否改变程序执行位置 | 特殊作用        |
| --------------- | ---------- | ----------- |
| jmp             | 是          | 无条件跳转       |
| jle / jge / bne | 条件成立时      | 根据比较结果跳转    |
| call            | 是          | 同时保存返回地址    |
| ret             | 是          | 根据保存的返回地址返回 |

call 的本质可以理解为：

$$
\text{保存下一条指令地址}
$$

$$
PC\leftarrow\text{被调用函数入口地址}
$$

ret 则将保存的返回地址恢复给 PC。

返回地址可以保存在栈中或专用链接寄存器中，具体取决于指令系统。

2019年真题要求计算递归函数 f1(10) 的调用次数。

调用过程是：

$$
f_1(10)\to f_1(9)\to\cdots\to f_1(1)
$$

所以总共调用10次，其中函数内部发生递归调用9次。

注意区分总调用次数和递归调用指令执行次数。

### 4. RISC 和 CISC 的判断

| 特征    | RISC 典型设计         | CISC 典型设计   |
| ----- | ----------------- | ----------- |
| 指令格式  | 较规整、通常定长          | 较复杂、通常变长    |
| 寻址方式  | 较少                | 较多          |
| 访存    | 主要由 Load/Store 完成 | 许多指令可直接访问内存 |
| 译码    | 相对简单              | 相对复杂        |
| 流水线实现 | 较容易规整化            | 可能需要更复杂的处理  |

2017年真题给出的机器代码具有明显的变长指令特征，结合其 x86 风格指令，可以判断为 CISC。

但是在一般情况下，RISC 与 CISC 的区别不应被绝对化为所有 RISC 指令都必须定长。

## 九、核心知识八：循环汇编与流水线综合题

**代表题：模拟卷第7套、第8套第44题。**

这两道模拟题实际上是第4章指令系统、第1章性能计算和第5章流水线的综合。

题库把它们归入本章是合理的，因为理解汇编语义是后续所有计算的前提。

### 1. 静态指令数与动态指令数

静态指令数是程序中写了多少条机器指令。

动态指令数是实际运行过程中执行了多少次机器指令。

例如模拟卷第7套：

```c
for(i=0; i<5; i++)
    j=j+B[i];
```

对应汇编：

```asm
1   add  R1,R0,R0
2   sll  R5,R1,2
3   add  R5,R5,R3
4   lw   R6,0(R5)
5   add  R2,R2,R6
6   addi R1,R1,1
7   slti R4,R1,5
8   bne  R4,R0,loop
```

第1条只执行一次，后面第2～8条每轮执行一次，共执行5轮。

所以：

$$
N=1+7\times5=36
$$

而不是8条，也不是40条。

最后一轮的分支虽然不跳转，但仍然执行了分支指令。

### 2. CPI、MIPS、执行时间

根据题设给出的每类指令周期数，得到：

| 指令类别 | 动态指令数 | CPI | 总周期数 |
| ---- | ----- | --- | ---- |
| 运算指令 | 26    | 4   | 104  |
| 访存指令 | 5     | 5   | 25   |
| 分支指令 | 5     | 3   | 15   |
| 合计   | 36    | —   | 144  |

平均 CPI：

$$
\overline{CPI} =\frac{\sum N_iCPI_i}{\sum N_i} =\frac{144}{36}=4
$$

主频为100MHz，所以：

$$
MIPS=\frac{f}{\overline{CPI}\times10^6} =\frac{100}{4}=25
$$

执行时间：

$$
T=\frac{144}{100\times10^6} =\boxed{1.44\ \mu s}
$$

这一类题最重要的是统计动态指令数，公式本身并不难。

### 3. 如何快速判断 RAW 数据相关？

最可靠的方法是标记每条指令读什么寄存器、写什么寄存器。

模拟卷第8套的汇编：

```asm
1   sll  t1,s3,2
2   add  t1,t1,s6
3   lw   t0,0(t1)
4   bne  t0,s5,exit
5   addi s3,s3,1
6   j    loop
```

| 指令编号 | 读取寄存器 | 写入通用寄存器 |
| ---- | ----- | ------- |
| 1    | s3    | t1      |
| 2    | t1、s6 | t1      |
| 3    | t1    | t0      |
| 4    | t0、s5 | 无       |
| 5    | s3    | s3      |
| 6    | 无     | 无       |

因此存在以下主要数据依赖：

| 生产者 → 消费者 | 相关寄存器 |
| --- | --- |
| 指令1 → 指令2 | t1 |
| 指令2 → 指令3 | t1 |
| 指令3 → 指令4 | t0 |

此外，更新下标的指令5也会依赖上一轮指令5产生的 s3。

<Callout type="warn" title="相关不等于停顿">

注意，RAW 数据依赖不等于一定出现流水线停顿。

</Callout>

是否停顿取决于生产者什么时候产生结果，以及消费者什么时候需要该结果。

### 4. 为什么转发不能完全解决 load-use？

假设采用经典五级流水线：

$$
IF\to ID\to EX\to MEM\to WB
$$

对于普通 ALU 运算，结果在 EX 末尾产生。

但 lw 指令要在 MEM 末尾才能得到内存数据。

如果紧接着的 bne 在 EX 阶段就需要该数据，即使存在转发，数据也还没有准备好。

#### 不插入气泡时

| 指令  | 周期1 | 周期2 | 周期3 | 周期4 | 周期5 |
| --- | --- | --- | --- | --- | --- |
| lw  | IF  | ID  | EX  | MEM | WB  |
| bne | —   | IF  | ID  | EX  | MEM |

在周期4，bne 已经需要数据，但 lw 到周期4末尾才读出数据。

#### 插入一个气泡后

| 指令  | 周期1 | 周期2 | 周期3 | 周期4 | 周期5 | 周期6 |
| --- | --- | --- | --- | --- | --- | --- |
| lw  | IF  | ID  | EX  | MEM | WB  | —   |
| bne | —   | IF  | ID  | 等待  | EX  | MEM |

此时 bne 可以通过转发使用已经读出的数据。

所以在题设分支比较发生于 EX 阶段并支持转发的情况下：

$$
\boxed{\text{load-use额外停顿1周期}}
$$

### 5. 流水线总时间的计算

设流水线有 $k$ 级，共执行 $N$ 条动态指令。

理想情况下，从开始到所有指令完成：

$$
C_{\text{ideal}}=N+k-1
$$

考虑额外停顿：

$$
\boxed{ T=(N+k-1+C_{\text{stall}})T_{\text{clk}} }
$$

流水线时钟周期由最慢的流水段决定，而不是各段时间之和。

模拟卷第8套规定：

| 项目          | 数值    |
| ----------- | ----- |
| 时钟周期        | 200ps |
| 流水级数        | 5     |
| 动态指令数       | 48    |
| load-use 停顿 | 8周期   |
| 控制冒险停顿      | 11周期  |

因此：

$$
\begin{aligned} C&=48+4+8+11\\ &=71 \end{aligned}
$$

$$
T=71\times200\mathrm{ps} =\boxed{14.2\mathrm{ns}}
$$

如果忽略流水线启动与结束阶段，只计算稳定吞吐工作量，则是13.4ns。

**题库这里有明确的特殊计数口径**：不计循环最后一次失败的条件检测，并按最后一条指令完成五级流水过程计算。实际碰到 while 循环，必须检查是否需要额外执行最后一次条件判断，以及分支指令的完成阶段，不能直接照搬48条指令。

## 十、将本章所有大题统一成一套解题方法

虽然题目背景可能不同，但实际上可以归纳为六个步骤。

| 步骤        | 应当思考的问题            |
| --------- | ------------------ |
| 第一步：译码    | 这是什么指令？各字段代表什么？    |
| 第二步：寻址    | 操作数在寄存器、内存还是指令内部？  |
| 第三步：解释    | 立即数是有符号数还是无符号数？    |
| 第四步：运算    | 真值是多少？机器数是多少？是否溢出？ |
| 第五步：写回    | 哪些寄存器、存储单元和标志位改变？  |
| 第六步：更新 PC | 顺序执行、条件转移还是函数调用？   |

对于程序级综合题，则在此基础上继续考虑指令执行次数、访存地址、Cache、页面和流水线。

这就是指令系统与其他章节之间的联系。

第4章本身并没有特别多复杂的公式，但它经常承担连接其他章节的作用。这也是真题越来越喜欢通过机器级代码考查多个知识点的原因。

## 十二、必须牢记的核心公式

考前可以将下面这张表作为快速复习资料。

| 知识点      | 核心公式                                                      |
| -------- | --------------------------------------------------------- |
| 编码数量     | $N=2^n$                                               |
| 补码表示范围   | $[-2^{n-1},2^{n-1}-1]$                                |
| 无符号数范围   | $[0,2^n-1]$                                           |
| 负补码真值    | $X_{\text{unsigned}}-2^n$                            |
| 顺序执行地址   | $PC_{\text{next}}=PC+L$                              |
| 相对转移地址   | $EA=PC_{\text{next}}+sD$                             |
| 相对偏移量    | $D=(EA-PC_{\text{next}})/s$                          |
| 一维数组地址   | $A+iw$                                                |
| 二维数组地址   | $A+(in+j)w$                                           |
| 连续代码长度   | $A_{\text{last}}-A_{\text{first}}+L_{\text{last}}$ |
| 虚页号      | $\lfloor A/P\rfloor$                                  |
| 页内偏移量    | $A\bmod P$                                            |
| 平均 CPI   | $\sum N_iCPI_i/\sum N_i$                              |
| CPU 执行时间 | $N\times CPI/f$                                       |
| 流水线总时间   | $(N+k-1+C_{\text{stall}})T_{\text{clk}}$            |

公式可以记住，但一定要理解每个量的单位、取值来源和适用条件。

## 十四、自测：判断自己是否真正掌握

独立回答以下10个问题。

1. 为什么相对寻址通常要使用下一条指令地址，而不是当前指令地址？
2. 为什么8位补码偏移量最小为-128，但2013年真题最多向低地址方向跳转127条指令？
3. 为什么寄存器编号占5位，不代表寄存器宽度也是5位？
4. 为什么访问 int 数组时经常出现逻辑左移2位的指令？
5. 为什么寄存器间接寻址中，寄存器内容不是最终操作数？
6. 为什么 FFFFH 零扩展和符号扩展后代表的数值不同？
7. 为什么模拟题的 LUI + LW 组合，有时必须将地址的高16位加1？
8. 为什么无符号数比较需要看 CF，而有符号数比较需要考虑 OF？
9. 为什么一段循环程序的实际执行指令数不能直接根据汇编代码行数确定？
10. 为什么有数据转发的流水线仍然可能发生 load-use 停顿？

## 最后总结

计算机组成原理第4章最需要建立的是以下五种能力：

- **位级思维**：把机器指令拆成具有独立含义的字段。
- **地址思维**：严格区分地址、数据、偏移量和编址单位。
- **数值思维**：区分二进制机器数、真实数值以及有符号和无符号解释。
- **状态思维**：追踪每条指令对寄存器、内存、标志位和 PC 的影响。
- **程序思维**：从指令序列中还原数组访问、循环、条件判断和函数调用。

学习本章最容易犯的错误，就是将大量汇编指令和寻址公式分别记忆，却没有理解它们之间的联系。

**指令系统的本质，是通过二进制编码描述数据从哪里来、如何处理、到哪里去，以及程序下一步执行什么。**
