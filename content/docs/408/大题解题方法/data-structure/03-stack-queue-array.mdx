## 二、队列的存储结构设计

### 1. 必须真正理解队列指针的含义

队列的逻辑特征是先进先出（FIFO），但是它的存储结构、判空条件、判满条件并不是固定不变的。

这些条件取决于 `front` 和 `rear` 的定义。

以牺牲一个存储单元的循环顺序队列为例：

| 项目      | 含义或操作                     |
| ------- | ------------------------- |
| `front` | 指向队头元素                    |
| `rear`  | 指向下一个可以插入的位置              |
| 队空      | `front == rear`           |
| 队满      | `(rear + 1) % M == front` |
| 入队      | 先写入，再移动 `rear`            |
| 出队      | 先读取，再移动 `front`           |

队列长度为：

$$
L=(rear-front+M)\bmod M
$$

其中 $M$ 是数组容量，实际最多存储 $M-1$ 个元素。

**最重要的知识不是记住这些公式，而是理解：rear 指向的是下一个空闲位置，并不是最后一个有效元素。**

只要改变指针定义，相应的公式和操作顺序也可能发生变化。

### 2. 代表真题：2019年408第42题

#### 题目核心要求

设计一个队列，满足：

1. 初始时队列为空。
2. 入队时允许增加队列占用空间。
3. 出队后，元素原来占用的空间可以重复使用，整个队列的空间只增不减。
4. 入队和出队的时间复杂度始终为 $O(1)$。

要求选择存储结构，画出初始状态及第一个元素入队后的状态，并给出判空、判满和基本操作过程。

<Steps>

<Step>

### 分析约束

先逐条分析约束。

| 题目要求       | 对数据结构的影响             |
| ---------- | -------------------- |
| 可以增加空间     | 需要支持动态扩容             |
| 空间可以重复使用   | 不能简单丢弃出队结点           |
| 空间只增不减     | 出队不能释放结点             |
| 始终为 $O(1)$ | 不能整体搬移元素，也不能遍历寻找空闲位置 |

普通顺序队列扩容时，可能需要复制全部元素，最坏时间复杂度为 $O(n)$。

普通链式队列虽然能够动态增加结点，但是通常会在出队时释放结点，不符合本题要求。

循环顺序队列可以重复利用空间，但是常规动态扩容仍然存在复制问题。

因此，将两种结构的优点结合起来：

**循环单链表 = 链表的动态扩容能力 + 循环队列的空间复用能力。**

</Step>

<Step>

### 设计指针状态

规定：

- `front` 指向第一个有效元素。
- `rear` 指向下一个空闲结点。
- 始终至少保留一个空闲结点。

初始状态只有一个结点，其 `next` 指向自身。

```text
 front、rear
      ↓
    [空闲]
      ↑  │
      └──┘
```

此时：

```text
front == rear
```

表示队列为空。

当第一个元素 `A` 入队时，先增加一个空闲结点，再将数据写入原结点。

```text
 front        rear
   ↓            ↓
  [A] ─────→ [空闲]
   ↑            │
   └────────────┘
```

此时 `front` 指向有效元素 `A`，`rear` 指向空闲结点。

判满条件为：

```text
rear->next == front
```

这里的“队满”表示当前已经没有额外可供使用的空闲结点，需要增加结点，并不是禁止继续入队。

注意：初始状态可以同时满足判空和当前存储空间已满的条件，因为唯一的结点是预留结点，实际可用容量为0。这并不矛盾。

</Step>

<Step>

### 分析入队与出队

假设依次入队 `A、B、C`。

```text
front                  rear
  ↓                      ↓
 [A] → [B] → [C] → [空闲]
  ↑                      │
  └──────────────────────┘
```

将 `A` 出队后，只移动 `front`，不删除结点。

```text
       front           rear
         ↓               ↓
 [空闲]→[B] → [C] → [空闲]
   ↑                     │
   └─────────────────────┘
```

原来存储 `A` 的结点进入空闲区域，以后可以重复利用。

<Callout type="info" title="逻辑删除与物理删除">

**物理结点仍然存在，只是它不再属于逻辑队列。**

</Callout>

</Step>

<Step>

### 实现核心代码

以下采用 C++ 风格描述，省略内存分配失败等工程性处理。

```cpp
struct Node {
    int data;
    Node *next;
};

struct Queue {
    Node *front;
    Node *rear;
};
```

初始化：

```cpp
void InitQueue(Queue &Q) {
    Node *p = new Node;
    p->next = p;

    Q.front = Q.rear = p;
}
```

入队：

```cpp
void EnQueue(Queue &Q, int x) {
    // 当前没有额外的空闲结点
    if (Q.rear->next == Q.front) {
        Node *p = new Node;

        p->next = Q.rear->next;
        Q.rear->next = p;
    }

    Q.rear->data = x;
    Q.rear = Q.rear->next;
}
```

出队：

```cpp
bool DeQueue(Queue &Q, int &x) {
    if (Q.front == Q.rear)
        return false;

    x = Q.front->data;
    Q.front = Q.front->next;

    return true;
}
```

复杂度分析：

$$
T_{\text{入队}}=O(1)
$$

$$
T_{\text{出队}}=O(1)
$$

在通常的算法分析模型下，每次操作至多增加一个结点、修改有限个指针，不需要整体搬移或者查找结点。

如果历史上队列最多同时容纳过 $k$ 个元素，那么该结构会保留 $k+1$ 个结点。

</Step>

</Steps>

#### 这道题真正应该学会什么？

**数据结构设计题，首先分析约束，其次定义状态，最后设计操作。**

尤其要区分：

- 逻辑删除与物理删除。
- 最坏时间复杂度与均摊时间复杂度。
- 有效元素与已经分配的存储空间。
- 指针的位置与指针所代表的逻辑意义。

这些知识不仅适用于队列，也适用于链表、内存管理、缓冲区等综合题目。

## 三、栈的本质：解决数据处理顺序相反的问题

### 1. 什么时候应该想到栈？

栈最重要的应用不是简单地存储数据，而是保存当前无法处理、需要以后逆序处理的信息。

| 题目特征        | 使用栈的原因           |
| ----------- | ---------------- |
| 逆序访问数据      | 后进先出             |
| 括号匹配        | 最近出现的左括号优先匹配     |
| 表达式求值       | 保存暂时无法计算的操作数或运算符 |
| 递归转非递归      | 保存尚未完成的函数状态      |
| 回文判断        | 将正向顺序转换为反向顺序     |
| 寻找最近尚未匹配的元素 | 优先处理最近进入栈的元素     |
| 高位在前的整数加法   | 从最低位开始计算进位       |

**如果数据能够访问的顺序与实际需要处理的顺序相反，就优先考虑栈。**

### 2. 代表模拟题：王道第2套第42题

#### 高位在前的单链表整数加法

两个单链表分别表示两个非负整数，每个结点存储一位数字，最高位在前。

例如：

```text
L1：7 → 2 → 4 → 3
L2：    5 → 6 → 4
```

要求返回一个新链表，表示两个整数之和。

```text
结果：7 → 8 → 0 → 7
```

即：

$$
7243+564=7807
$$

#### 为什么这道题应该想到栈？

普通链表的访问顺序是：

```text
最高位 → 最低位
```

但是整数加法的处理顺序是：

```text
最低位 → 最高位
```

因为高位的计算依赖低位产生的进位。

这就形成了访问顺序与处理顺序的矛盾。

如果直接从两个链表的头部开始同步相加，不仅位数对不齐，而且无法提前知道进位。

栈正好可以消除这种矛盾。

#### 算法设计

先将两个链表的数字分别压入两个栈。

```text
  栈 A         栈 B

   [3] ←栈顶    [4] ←栈顶
   [4]          [6]
   [2]          [5]
   [7]
```

依次弹出两个栈顶进行加法。

设当前两位数字分别为 $x,y$，上一位产生的进位为 $c$。

$$
s=x+y+c
$$

当前位结果：

$$
d=s\bmod 10
$$

新进位：

$$
c=\left\lfloor\frac{s}{10}\right\rfloor
$$

计算过程如下：

| 取出的数字 | 原进位 | 和  | 当前位 | 新进位 | 结果链表    |
| ----- | --- | -- | --- | --- | ------- |
| 3、4   | 0   | 7  | 7   | 0   | 7       |
| 4、6   | 0   | 10 | 0   | 1   | 0→7     |
| 2、5   | 1   | 8  | 8   | 0   | 8→0→7   |
| 7、0   | 0   | 7  | 7   | 0   | 7→8→0→7 |

为什么结果链表使用头插法？

因为我们生成结果的顺序是从低位到高位，但是最终链表需要从高位到低位。

所以实际上有两次逆序转换：

```text
输入链表
    ↓ 栈
低位到高位计算
    ↓ 头插法
高位到低位的结果链表
```

#### 核心算法代码

根据原题要求，两个链表长度均不超过100。

```cpp
ListNode* Add(ListNode *L1, ListNode *L2) {
    int A[100], B[100];
    int top1 = 0, top2 = 0;

    // 两个链表分别入栈
    for (ListNode *p = L1; p; p = p->next)
        A[top1++] = p->val;

    for (ListNode *p = L2; p; p = p->next)
        B[top2++] = p->val;

    int carry = 0;
    ListNode *head = nullptr;

    while (top1 > 0 || top2 > 0 || carry != 0) {
        int x = top1 > 0 ? A[--top1] : 0;
        int y = top2 > 0 ? B[--top2] : 0;

        int sum = x + y + carry;
        carry = sum / 10;

        // 头插法生成新链表
        ListNode *p = new ListNode;
        p->val = sum % 10;
        p->next = head;
        head = p;
    }

    return head;
}
```

设两个链表长度为 $m,n$，按一般输入规模分析：

$$
T(m,n)=O(m+n)
$$

$$
S(m,n)=O(m+n)
$$

#### 必须理解的三个细节

**第一，为什么使用 `||` 而不是 `&&`？**

因为两个整数的长度可能不同，只要有一个栈不为空，就应该继续计算。

**第二，为什么循环条件还要包含 `carry != 0`？**

例如：

$$
99+1=100
$$

即使两个栈已经为空，最高位仍然可能产生进位。

**第三，为什么不用整数变量直接存储整个数字？**

因为原题最多有100位数字，远远超过普通整型变量的表示范围。

必须逐位处理。

### 3. 重要迁移：栈不是逆序处理的唯一方法

题库中王道第8套第42题要求判断单链表是否中心对称，例如 `xyx`、`xyyx`。

最直接的做法是将链表元素全部压栈，然后重新遍历链表，与依次出栈的元素进行比较。

时间复杂度为 $O(n)$，辅助空间复杂度为 $O(n)$。

但是，如果允许临时修改链表，可以采用更高效的空间方案：

```text
快慢指针找到中点
        ↓
原地反转后半段链表
        ↓
逐个比较对应元素
        ↓
恢复原链表
```

例如：

```text
原链表：a → b → c → b → a

分成：  a → b    c    b → a
                      ↓反转
        a → b         a → b
```

比较两段即可。

| 方法    | 时间复杂度  | 辅助空间复杂度 | 特点          |
| ----- | ------ | ------- | ----------- |
| 辅助栈   | $O(n)$ | $O(n)$  | 不修改原链表      |
| 递归比较  | $O(n)$ | $O(n)$  | 使用系统调用栈     |
| 反转后半段 | $O(n)$ | $O(1)$  | 需要临时修改并恢复链表 |

如果题目强调空间尽可能高效，就要考虑利用原有结构实现逆序，而不是机械地分配辅助栈。

## 四、数组压缩存储：不要死记下标公式

### 1. 数组类大题的本质

数组压缩存储看起来公式很多，但实际上只需要掌握一个核心思想：

<Callout type="idea" title="压缩存储计数">

**目标元素的存储下标，就是在它之前已经存储的元素个数。**

</Callout>

所有对称矩阵、三角矩阵的压缩存储公式，都可以从这个思想推导出来。

假设数组下标从0开始。

$$
k=\text{目标元素之前的存储元素总数}
$$

如果还要求物理地址，则：

$$
LOC(a_{ij})=BASE+k\times L
$$

其中 $L$ 是每个元素占用的存储单元数。

### 2. 四种常见存储公式的统一推导

下面矩阵行列编号均从1开始，压缩数组下标从0开始，采用行优先存储。

<Tabs items={['下三角矩阵', '上三角矩阵']}>

<Tab value="下三角矩阵">

```text
×
× ×
× × ×
× × × ×
```

第 $i$ 行之前存储的元素数为：

$$
1+2+\cdots+(i-1)
=\frac{i(i-1)}{2}
$$

第 $i$ 行中，元素 $a_{ij}$ 前面还有 $j-1$ 个元素。

所以：

$$
\boxed{k=\frac{i(i-1)}{2}+j-1}
$$

适用于 $i\geq j$。

对于对称矩阵，如果只存储下三角区域，而 $i<j$，交换 $i,j$ 后再计算。

</Tab>

<Tab value="上三角矩阵">

```text
× × × ×
  × × ×
    × ×
      ×
```

第 $i$ 行之前的存储元素数为：

$$
n+(n-1)+\cdots+(n-i+2)
$$

第 $i$ 行内的偏移量为：

$$
j-i
$$

所以：

$$
\boxed{
k=\frac{(i-1)(2n-i+2)}{2}+j-i
}
$$

适用于 $i\leq j$。

</Tab>

</Tabs>

#### 常见情况总结

| 存储区域         | 存储元素总数             |
| ------------ | ------------------ |
| 下三角，包含对角线    | $\frac{n(n+1)}{2}$ |
| 上三角，包含对角线    | $\frac{n(n+1)}{2}$ |
| 严格下三角，不包含对角线 | $\frac{n(n-1)}{2}$ |
| 严格上三角，不包含对角线 | $\frac{n(n-1)}{2}$ |
| 三对角矩阵的带状区域   | $3n-2$             |

如果题目要求额外存储三角区域外的公共常数，则还需增加一个存储单元。

不要默认所有题目都有这个单元。

### 3. 代表真题：2011年408图的综合题

本题属于图的跨章节综合题，矩阵压缩存储是解题基础。

#### 题目核心

某有向带权图有6个顶点，其邻接矩阵为上三角矩阵，按行优先存储在如下数组中：

$$
4,6,\infty,\infty,\infty,5,\infty,\infty,
\infty,4,3,\infty,\infty,3,3
$$

要求还原邻接矩阵，并进一步计算关键路径。

#### 本题真正的难点

如果机械使用教材的上三角矩阵存储方式，应该有：

$$
\frac{6\times7}{2}=21
$$

个三角区域元素。

如果再保存公共常数，则为22个存储单元。

然而题目只提供了15个元素。

为什么？

因为：

$$
15=\frac{6\times5}{2}
$$

这正好是严格上三角区域的元素个数。

所以本题没有存储主对角线，也没有显式存储下三角区域的公共常数。

**遇到非常规压缩存储题，先数元素，再判断实际存储区域。**

#### 正确还原过程

| 行号 | 存储数量 | 对应内容                       |
| -- | ---- | -------------------------- |
| 0  | 5    | $4,6,\infty,\infty,\infty$ |
| 1  | 4    | $5,\infty,\infty,\infty$   |
| 2  | 3    | $4,3,\infty$               |
| 3  | 2    | $\infty,3$                 |
| 4  | 1    | $3$                        |
| 5  | 0    | 无                          |

恢复矩阵：

$$
A=
\begin{pmatrix}
0&4&6&\infty&\infty&\infty\\
\infty&0&5&\infty&\infty&\infty\\
\infty&\infty&0&4&3&\infty\\
\infty&\infty&\infty&0&\infty&3\\
\infty&\infty&\infty&\infty&0&3\\
\infty&\infty&\infty&\infty&\infty&0
\end{pmatrix}
$$

后续计算得到关键路径：

$$
0\rightarrow1\rightarrow2\rightarrow3\rightarrow5
$$

长度为：

$$
4+5+4+3=16
$$

后面的关键路径计算属于图的知识，本章重点是如何准确地还原数组。

#### 矩阵压缩存储大题的万能步骤

1. 明确矩阵下标从0还是1开始。
2. 判断行优先还是列优先。
3. 判断是否包含主对角线。
4. 利用元素数量验证实际存储区域。
5. 计算前面完整行或列的元素数量。
6. 加上当前行或列内部的偏移量。
7. 用第一个和最后一个元素验证公式。

**掌握计数推导法，比背诵十几个压缩存储公式更加可靠。**

## 五、数组算法：利用单调性消除重复计算

### 1. 代表模拟题：王道第3套第42题

给定一个由正整数组成的数组，统计乘积严格小于 $k$ 的所有非空连续子数组数量。

例如：

$$
A=[10,5,2,6],\qquad k=100
$$

正确答案为8。

本题原归类于线性表，可用于理解数组算法的优化思想。

#### 普通解法为什么效率低？

枚举所有子数组，一共有：

$$
\frac{n(n+1)}{2}
$$

个。

如果每次重新计算区间乘积，朴素算法可能需要 $O(n^3)$ 时间。

即使利用累积乘积，将每个区间的计算优化为常数时间，总时间通常仍为 $O(n^2)$。

如何进一步优化为 $O(n)$？

关键在于题目给出的特殊性质：

**所有元素都是正整数，即每个元素至少为1。**

因此，区间向右扩大时，乘积不会减小；区间向左缩小时，乘积不会增大。

这就具备了使用滑动窗口的条件。

### 2. 理解滑动窗口的本质

维护两个指针 `left` 和 `right`，以及当前窗口的乘积 `product`。

每次将右侧新元素加入窗口。

如果乘积不满足条件，就不断从左侧删除元素，直到：

$$
product<k
$$

此时，以 `right` 为右端点的合法连续子数组有：

$$
right-left+1
$$

个。

为什么？

假设当前合法窗口为：

$$
[5,2,6]
$$

那么以6结尾的合法子数组一定包括：

$$
[6],\quad[2,6],\quad[5,2,6]
$$

由于数组元素均至少为1，继续缩短这个窗口，乘积不可能增大。

所以不需要逐个计算这些子数组。

| 右端点元素 | 合法窗口    | 新增合法子数组数 | 累计 |
| ----- | ------- | -------- | -- |
| 10    | [10]    | 1        | 1  |
| 5     | [10,5]  | 2        | 3  |
| 2     | [5,2]   | 2        | 5  |
| 6     | [5,2,6] | 3        | 8  |

### 3. 核心代码

```cpp
long long Count(int A[], int n, int k) {
    if (k <= 1)
        return 0;

    int left = 0;
    long long product = 1;
    long long ans = 0;

    for (int right = 0; right < n; right++) {
        product *= A[right];

        while (product >= k) {
            product /= A[left];
            left++;
        }

        ans += right - left + 1;
    }

    return ans;
}
```

#### 为什么嵌套循环仍然是 $O(n)$？

不能看到 `for` 中嵌套 `while` 就认为复杂度是 $O(n^2)$。

整个算法中，右指针最多移动 $n$ 次，左指针最多移动 $n$ 次。

因此：

$$
T(n)=O(n+n)=O(n)
$$

只使用有限个辅助变量：

$$
S(n)=O(1)
$$

这是一种非常重要的复杂度分析方法：**统计整个算法中每个操作的总执行次数，而不是机械地计算循环嵌套层数。**

#### 可以迁移到哪些题目？

滑动窗口思想还可以用于满足一定单调性质的连续子数组问题，例如正整数数组的区间和、最长合法连续区间等。

但必须注意，如果原题允许负数或零，上述乘积窗口算法就不能直接套用。

<Callout type="warn" title="滑动窗口适用条件">

**不是所有连续子数组问题都可以使用滑动窗口，真正决定能否使用的是区间性质是否具有所需的单调性。**

</Callout>

## 六、栈与队列应用题必须掌握的补充思想

这些知识在所给题库中没有足够多的独立大题，但属于重要的算法基础，值得作为变式储备。

### 1. 括号匹配：保存尚未完成的任务

遇到左括号，将其入栈。

遇到右括号，与栈顶左括号匹配。

如果出现以下任意情况，则匹配失败：

- 遇到右括号时栈为空。
- 栈顶左括号与当前右括号类型不匹配。
- 扫描结束后栈仍然不为空。

例如：

```text
([{}])
```

可以匹配。

```text
([)]
```

不能匹配。

为什么不能使用队列？

因为嵌套结构必须优先完成最近开始的任务，而不是最早开始的任务。

这也是栈能够用于递归、表达式计算和深度优先搜索的根本原因。

### 2. 表达式求值：严格维护运算数顺序

以后缀表达式为例：

```text
8 2 3 * -
```

计算过程：

| 当前符号 | 操作            | 栈内元素（栈底到栈顶） |
| ---- | ------------- | ----------- |
| 8    | 入栈            | 8           |
| 2    | 入栈            | 8、2         |
| 3    | 入栈            | 8、2、3       |
| \*   | 计算 $2\times3$ | 8、6         |
| -    | 计算 $8-6$      | 2           |

最终结果：

<Accordions>

<Accordion title="参考答案与解析">

答案：

$$
8-2\times3=2
$$

核心代码：

```cpp
int b = Pop(S);
int a = Pop(S);

Push(S, Calculate(a, op, b));
```

<Callout type="warn" title="操作数顺序">

**先弹出右操作数，再弹出左操作数。**

</Callout>

对于减法和除法，顺序颠倒会直接导致答案错误。

2017年408的表达式树大题也体现了相同的核心问题：如何保持表达式正确的运算结构与顺序。不过该真题主要使用树的中序遍历和括号处理，而不是直接使用操作数栈。

### 3. 使用两个栈实现队列

一个栈负责入队，另一个栈负责出队。

```text
输入栈             输出栈

  [C]               [A]
  [B]               [B]
  [A]               [C]

     将元素依次弹出并压入
```

一次栈操作形成逆序，两次栈式处理实现先进先出。

关键规则：只有输出栈为空时，才把输入栈的全部元素转移到输出栈。

每个元素最多经历两次入栈、两次出栈。

所以均摊操作时间复杂度为：

$$
O(1)
$$

但单次出队的最坏时间复杂度为：

$$
O(n)
$$

因此，不能用这种常规方案直接满足2019年真题中每次入队和出队始终为 $O(1)$ 的要求。

## 七、第三章大题的通用解题思维

本章可归纳为以下五种解题模型。

| 思维方式   | 核心问题             | 代表题目        |
| ------ | ---------------- | ----------- |
| 约束反推   | 什么结构能够同时满足全部要求？  | 2019年队列设计   |

| 消除重复计算 | 已经计算的信息能否重复利用？   | 连续子数组滑动窗口   |

### 算法大题的标准答题框架

遇到要求设计数据结构或者算法的大题，可以统一按照以下顺序作答。

**第一步：写清楚算法思想。** 不要仅仅写“使用栈”或者“使用队列”，还要说明为什么选择该结构，它解决了什么问题。

**第二步：定义关键变量。** 例如指针指向有效元素还是空闲位置，栈顶表示最后一个元素还是元素数量，数组下标从哪里开始。

**第三步：写出核心操作。** 重点保证操作前后，数据结构仍然满足所规定的状态和性质。

**第四步：检查边界情况。** 空结构、只有一个元素、长度不同、奇偶长度、恰好达到容量上限、最后一次进位等。

**第五步：分析复杂度。** 不仅分析时间复杂度，还要区分辅助空间、输出空间、最坏复杂度和均摊复杂度。
