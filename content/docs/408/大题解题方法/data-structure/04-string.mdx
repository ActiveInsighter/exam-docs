## 三、KMP算法的本质：利用已经获得的信息

### 1. BF算法为什么效率低？

假设主串和模式串进行如下匹配：

```text
主串 S：a b a b a b a c
模式 P：a b a b a c
                  ↑
                 失配
```

前面5个字符已经匹配成功，但第6个字符失配了。

如果使用BF算法，就将模式串整体向右移动一位，重新从第一个字符开始比较。

问题在于：**此前成功匹配的5个字符包含大量有用信息，BF算法却直接丢弃了这些信息。**

BF算法发生失配时，采用0起始下标，其指针更新规则为：

$$
i=i-j+1
$$

$$
j=0
$$

主串指针发生回退。

最坏时间复杂度为：

$$
O(nm)
$$

其中 $n$ 为主串长度，$m$ 为模式串长度。

### 2. KMP如何利用已经匹配的信息？

仍然考虑刚才的例子。

```text
已匹配部分：a b a b a

最长相等前缀：a b a
最长相等后缀：    a b a
```

已匹配部分 `ababa` 的最长相等真前后缀为 `aba`，长度为3。

由于主串的这一段和模式串已经匹配成功，因此主串末尾的 `aba` 必然与模式串开头的 `aba` 相等。

这3个字符根本不需要再次比较。

```text
失配之前：

S：a b a b a b a c
P：a b a b a c
             ↑

调整之后：

S：a b a b a b a c
P：    a b a b a c
             ↑
```

主串指针保持不变，模式串指针从下标5回退到下标3。

> KMP不是简单地让模式串向右移动，而是利用已经匹配部分的最长相等真前后缀，确定下一次仍然可能匹配成功的位置。

### 3. 为什么一定选择最长相等前后缀？

因为选择最长相等真前后缀，意味着模式串向右移动的距离最小，同时保留的有效匹配信息最多。

假设已经成功匹配了 $j$ 个字符，最长相等真前后缀长度为 $k$，则模式串向右移动：

$$
j-k
$$

个位置。

更短的移动距离不满足前后缀相等的条件，可以直接排除；更长的移动距离则可能跳过有效答案。

这也是KMP不会漏掉匹配结果的根本原因。

## 四、代表题一：next数组的计算与推导

**题目来源：王道·卷七，第4题。原题为选择题，这里将其扩展为综合应用题。**

已知模式串：

```text
acaba
```

求其next数组，并解释每个元素的含义。

### 1. 先理解什么是相等真前后缀

真前缀是不包含整个字符串的前缀，真后缀是不包含整个字符串的后缀。

例如字符串 `ababa`：

| 真前缀  | 真后缀  |
| ---- | ---- |
| a    | a    |
| ab   | ba   |
| aba  | aba  |
| abab | baba |

最长相等真前后缀为 `aba`，长度为3。

注意，不能把整个 `ababa` 当成自己的相等真前后缀，否则失配时模式串就无法有效移动。

### 2. next数组的手算方法

原题采用从1开始编号、`next[1]=0` 的约定。

对于 $j\geq 2$：

$$
next[j]=k+1
$$

其中 $k$ 是模式串前 $j-1$ 个字符的最长相等真前后缀长度。

| 位置 $j$ | 当前字符 | 已匹配部分 | 最长相等真前后缀 | next值 |
| ---------- | ---- | ----- | -------- | ----- |
| 1          | a    | 空     | 特殊情况     | 0     |
| 2          | c    | a     | 无        | 1     |
| 3          | a    | ac    | 无        | 1     |
| 4          | b    | aca   | a        | 2     |
| 5          | a    | acab  | 无        | 1     |

所以：

$$
\boxed{next=[0,1,1,2,1]}
$$

### 3. 最容易犯的错误：把当前字符算进去

求 `next[4]` 时，研究的是 `aca`，不是 `acab`。

为什么？

因为 `next[4]` 表示模式串第4个字符失配后，应该回退到什么位置。

第4个字符既然还没有匹配成功，就不能将其作为已知的匹配信息。

### 4. 三种不同数组的区别

同一个模式串 `acaba`，不同教材可能采用不同定义。

| 数组类型                   | 数组结果           |
| ---------------------- | -------------- |
| 1起始，next首项为0           | 0, 1, 1, 2, 1  |
| 0起始，next首项为-1          | -1, 0, 0, 1, 0 |
| LPS数组（包含当前位置的最长真前后缀长度） | 0, 0, 1, 0, 1  |

它们的底层思想完全相同，但定义和下标不同。

**考试时一定要先确认题目采用哪种编号约定。**

</Callout>

## 五、代表题二：nextval数组为什么能够进一步优化？

**题目来源：王道·卷八，第4题。**

已知主串和模式串：

```text
S = aabaabcabc
P = aaabc
```

采用0起始下标的KMP算法，当 $i=2,j=2$ 时发生失配，求nextval数组及下一次真正进行字符比较的位置。

### 1. 先求普通next数组

| 下标 $j$ | 0  | 1 | 2 | 3 | 4 |
| ---------- | -- | - | - | - | - |
| 模式串        | a  | a | a | b | c |
| next       | -1 | 0 | 1 | 2 | 0 |

### 2. 普通next数组存在什么问题？

此时的匹配状态如下：

```text
S：a a b a a b c a b c
       ↑
P：a a a b c
       ↑
```

当前主串字符为 `b`，模式串字符为 `a`，显然失配。

按照普通KMP算法：

$$
j=next[2]=1
$$

但是模式串下标1对应的字符仍然是 `a`。

既然已经知道 `b` 不等于 `a`，为什么还要再比较一次？

即使再次回退到下标0，对应的字符依然是 `a`，仍然必然失败。

<Callout type="idea" title="nextval优化原理">

**nextval的本质就是提前跳过这种必然失败的字符比较。**

</Callout>

### 3. nextval的计算规则

令：

$$
k=next[j]
$$

那么对于 $j>0$，有：

$$
nextval[j]= \begin{cases} -1,& k=-1\\ k,& P[j]\ne P[k],\ k\geq0\\ nextval[k],& P[j]=P[k],\ k\geq0 \end{cases}
$$

初始条件：

$$
nextval[0]=-1
$$

本题计算结果如下：

| 下标      | 0  | 1  | 2  | 3 | 4 |
| ------- | -- | -- | -- | - | - |
| 模式串     | a  | a  | a  | b | c |
| next    | -1 | 0  | 1  | 2 | 0 |
| nextval | -1 | -1 | -1 | 2 | 0 |

### 4. 确定下一次比较的位置

失配后：

$$
j=nextval[2]=-1
$$

由于 $j=-1$ 是哨兵状态，并不对应真实字符，因此接下来执行：

$$
i=i+1=3
$$

$$
j=j+1=0
$$

最终答案：

$$
\boxed{(i,j)=(3,0)}
$$

### 5. 普通next与nextval的区别

| 对比            | next         | nextval      |
| ------------- | ------------ | ------------ |
| 利用已经匹配的信息     | 是            | 是            |
| 跳过不可能成功的对齐位置  | 是            | 是            |
| 跳过相同字符造成的重复失配 | 不一定          | 是            |
| 最坏时间复杂度       | $O(n+m)$ | $O(n+m)$ |

nextval不会改变KMP的时间复杂度数量级，但能够减少部分实际字符比较次数。

## 六、代表题三：完整KMP匹配过程与比较次数

**题目来源：竞成·模拟一，第8题。**

原题为选择题，以下扩展综合考查next、nextval、指针变化与字符比较次数。

已知：

```text
S = cbabababac
P = ababac
```

要求求出next和nextval数组，写出完整匹配过程，并求匹配成功位置及实际字符比较次数。

### 1. 求回退数组

采用0起始下标。

| 下标      | 0  | 1 | 2  | 3 | 4  | 5 |
| ------- | -- | - | -- | - | -- | - |
| 模式串     | a  | b | a  | b | a  | c |
| next    | -1 | 0 | 0  | 1 | 2  | 3 |
| nextval | -1 | 0 | -1 | 0 | -1 | 3 |

### 2. 完整匹配过程

| 比较次数 | $i$ | $j$ | 比较字符  | 比较结果 |
| ---- | ------- | ------- | ----- | ---- |
| 1    | 0       | 0       | c / a | 失配   |
| 2    | 1       | 0       | b / a | 失配   |
| 3    | 2       | 0       | a / a | 成功   |
| 4    | 3       | 1       | b / b | 成功   |
| 5    | 4       | 2       | a / a | 成功   |
| 6    | 5       | 3       | b / b | 成功   |
| 7    | 6       | 4       | a / a | 成功   |
| 8    | 7       | 5       | b / c | 失配   |
| 9    | 7       | 3       | b / b | 成功   |
| 10   | 8       | 4       | a / a | 成功   |
| 11   | 9       | 5       | c / c | 成功   |

最重要的是第8次比较。

```text
S：c b a b a b a b a c
                 ↑
P：    a b a b a c
                 ↑
```

发生失配后：

$$
j=nextval[5]=3
$$

主串指针 $i=7$ 保持不变。

```text
S：c b a b a b a b a c
                 ↑
P：        a b a b a c
                 ↑
```

前3个字符已经通过前后缀关系得到确认，不需要重新比较。

### 3. 最终答案

匹配成功时：

$$
i=10,\qquad j=6
$$

模式串长度为6，因此匹配起始下标为：

$$
i-j=10-6=4
$$

即从主串第5个字符开始匹配成功。

字符比较总次数为：

$$
\boxed{11}
$$

### 4. 比较次数类大题的通用方法

不要凭感觉数，也不要把模式串移动次数当作比较次数。

只需要按照下面的规则处理：

| 当前状态       | 指针操作                     | 字符比较次数 |
| ---------- | ------------------------ | ------ |
| 字符相等       | `i++，j++`                | 加1     |
| 字符不等       | `j=next[j]`或`nextval[j]` | 加1     |
| $j=-1$ | `i++，j++`                | 不增加    |

<Callout type="warn" title="字符比较计数">

**每真正比较一对字符，才增加一次字符比较次数。**

</Callout>

### 5. 题库中存在一个值得注意的计数陷阱

竞成·模拟六，第3题：

```text
S = abaacaadaafa
P = aada
```

题库标注答案为12次，但按照优化后的KMP算法进行严格统计：

- 实际字符比较次数：10次。
- 哨兵分支处理次数：2次。
- 主循环执行次数：12次。

因此，原题答案实际上采用了主循环执行次数的统计口径，而不是严格意义上的字符比较次数。

综合题中应明确字符比较次数与主循环执行次数的统计口径。

## 七、KMP算法代码：不要死记，要理解递推关系

以下为KMP相关算法的拓展代码模板。

下面统一采用0起始下标。

<Tabs items={['BF', 'next', 'nextval', 'KMP']}>

<Tab value="BF">

```c
int BF(char S[], char P[], int n, int m) {
    int i = 0, j = 0;

    while (i < n && j < m) {
        if (S[i] == P[j]) {
            i++;
            j++;
        } else {
            i = i - j + 1;
            j = 0;
        }
    }

    if (j == m)
        return i - j;

    return -1;
}
```

理解最重要的一行：

```c
i = i - j + 1;
```

其中 `i-j` 是本轮匹配的起始位置，加1表示从下一个位置重新开始。

</Tab>

<Tab value="next">

```c
void GetNext(char P[], int m, int next[]) {
    if (m == 0)
        return;

    int j = 0, k = -1;
    next[0] = -1;

    while (j < m - 1) {
        if (k == -1 || P[j] == P[k]) {
            j++;
            k++;
            next[j] = k;
        } else {
            k = next[k];
        }
    }
}
```

其中：

- `j` 表示当前正在处理的位置。
- `k` 表示当前已知的最长相等真前后缀长度。
- 当两个字符相等时，原有相等前后缀可以同时延长一位。
- 当两个字符不等时，通过 `next[k]` 寻找更短的候选前后缀。

#### 为什么失配时是 `k=next[k]`？

假设已知某段字符串的最长相等真前后缀为：

```text
aba
```

但继续扩展时失败了。

接下来要寻找更短的相等真前后缀，而 `aba` 自己的最长相等真前后缀恰好是 `a`。

因此可以直接利用以前已经计算好的next值，不必重新从头搜索。

**求next数组的过程，本质上也是模式串自己与自己进行模式匹配的过程。**

</Tab>

<Tab value="nextval">

```c
void GetNextVal(char P[], int m,
                int next[], int nextval[]) {
    if (m == 0)
        return;

    nextval[0] = -1;

    for (int j = 1; j < m; j++) {
        int k = next[j];

        if (k == -1 || P[j] != P[k])
            nextval[j] = k;
        else
            nextval[j] = nextval[k];
    }
}
```

这比直接编写优化版nextval生成算法更容易理解和检查。

</Tab>

<Tab value="KMP">

```c
int KMP(char S[], char P[], int n,
        int m, int next[]) {
    int i = 0, j = 0;

    while (i < n && j < m) {
        if (j == -1 || S[i] == P[j]) {
            i++;
            j++;
        } else {
            j = next[j];
        }
    }

    if (j == m)
        return i - j;

    return -1;
}
```

如果希望使用优化后的KMP，只需要传入nextval数组即可。

将BF算法和KMP算法放在一起比较：

```c
// BF失配处理
i = i - j + 1;
j = 0;

// KMP失配处理
j = next[j];
```

两者最核心的差别就在这里。

BF让主串回退并重新匹配，而KMP保留主串位置，只调整模式串指针。

</Tab>

## 八、为什么KMP的时间复杂度是线性的？

KMP的总复杂度包含预处理与匹配两个阶段。

### 1. 构建next数组

指针 `j` 单调向右移动，最多增长 $m$ 次。

指针 `k` 在匹配成功时增加，在失配时回退。它的回退次数受到此前增长次数的限制。

因此构建next数组的时间复杂度为：

$$
O(m)
$$

### 2. 匹配过程

主串指针 `i` 始终不会减小，最多增长 $n$ 次。

虽然模式串指针 `j` 可能反复回退，但每次正常增长都伴随着主串指针增长；每次失配回退至少减少1。

所以 `j` 的累计回退次数也受到累计增长次数的限制。

匹配过程时间复杂度为：

$$
O(n)
$$

加上预处理过程：

$$
\boxed{T(n,m)=O(n+m)}
$$

需要长度为 $m$ 的回退数组，因此辅助空间复杂度为：

$$
\boxed{S(m)=O(m)}
$$

这里实际上体现了一个很重要的算法分析思想：**单次操作可能比较复杂，但是所有操作累计起来仍然是线性的。** 这种分析方式也可以迁移到栈、双指针、滑动窗口等算法中。

## 九、与字符串有关的一道真正的408综合应用题

**题目来源：2020年408真题，题库将其归入树与二叉树章节，题目ID为 `408-67f846-040`。**

这道题讨论具有前缀特性的不等长二进制编码。要求设计存储结构、实现字符串译码，并判断编码是否具有前缀特性。

本题为前缀树的跨章节综合应用，不属于KMP题。

### 1. 什么是前缀特性？

任意一个字符的编码都不能是其他字符编码的前缀。

例如：

| 字符 | 合法编码方案 | 不合法编码方案 |
| -- | ------ | ------- |
| A  | 0      | 0       |
| B  | 10     | 01      |
| C  | 11     | 11      |

右侧不合法，因为A的编码 `0` 是B的编码 `01` 的前缀。

这可能导致译码时无法直接判断当前字符是否已经结束。

### 2. 如何存储和译码？

使用二叉前缀树，左分支表示0，右分支表示1，字符存储在叶结点。

```text
          root
         /    \
        0      1
        A     / \
             0   1
             B   C
```

对于编码：

```text
010110
```

从根结点出发，根据每一位选择左右孩子。每到一个叶结点就输出字符，再返回根结点继续译码。

```text
0 | 10 | 11 | 0
A    B    C   A
```

译码结果为 `ABCA`。

### 3. 如何判断是否具有前缀特性？

将每个编码依次插入二叉前缀树。

插入过程中主要检查三种冲突：

- 尚未读完整个新编码，就遇到已存储字符的结点，说明旧编码是新编码的前缀。
- 新编码读取完毕，但当前结点仍然有孩子，说明新编码是旧编码的前缀。
- 新编码读取完毕，发现该结点已经存储字符，说明编码重复。

所有编码都不存在上述冲突，则满足前缀特性。

### 4. 这道题可以迁移出什么思想？

KMP与二叉前缀树虽然是不同算法，但都在利用字符串的结构信息：

- KMP利用相等前后缀，消除重复比较。
- 二叉前缀树利用公共前缀，共享存储路径，并快速判断前缀关系。

<Callout type="warn" title="前缀编码与哈夫曼树">

需要注意，本题并没有要求构建哈夫曼树。具有前缀特性的编码不一定是最优编码。

</Callout>
