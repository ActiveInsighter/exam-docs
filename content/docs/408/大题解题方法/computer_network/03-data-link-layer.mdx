## 二、滑动窗口与可靠传输：本章最重要的综合计算模型

### 2.1 理解滑动窗口的真正含义

滑动窗口协议解决了两个问题：

- 可靠传输：如何处理帧丢失、出错、重复和失序。
- 传输效率：如何在等待确认期间继续发送数据，而不是让信道一直空闲。

发送方的序号空间可以分为四个区域。

```text
    已确认       已发送未确认       允许发送但未发送       暂不允许发送
  ──────────┬────────────────┬─────────────────┬──────────
            │                │                 │
           base           nextseqnum       base + W
            └───────── 发送窗口 W ────────────┘
```

其中：

$base$：最早尚未被确认的帧序号。

$nextseqnum$：下一次发送的新帧序号。

$W$：发送窗口大小。

因此，在不考虑序号回绕时：

$$
\boxed{\text{已发送未确认帧数}=nextseqnum-base}
$$

$$
\boxed{\text{还能发送帧数}=W-(nextseqnum-base)}
$$

如果序号发生回绕，设序号空间大小为 $M$，则应采用模运算：

$$
\text{已发送未确认帧数}
=(nextseqnum-base+M)\bmod M
$$

**滑动窗口题的核心是维护这些状态变量。**

### 2.2 GBN与SR的本质区别

设帧序号字段占 $n$ bit，序号空间大小为：

$$
M=2^n
$$

| 比较项目 | 停止等待  | GBN后退N帧             | SR选择重传            |
| ---- | ----- | ------------------- | ----------------- |
| 发送窗口 | 1     | 最大 $2^n-1$          | 等大窗口时最大 $2^{n-1}$ |
| 接收窗口 | 1     | 1                   | 可以大于1             |
| 失序帧  | 丢弃    | 丢弃                  | 窗口内可缓存            |
| 确认方式 | 逐帧确认  | 累计确认                | 选择性确认             |
| 超时重传 | 重传当前帧 | 重传最早未确认帧及其后已发送的未确认帧 | 重传相应超时帧           |

#### GBN最大发送窗口的来源

假设序号字段只有2位，则序号为：

$$
0,1,2,3
$$

如果发送窗口允许为4，发送方一次发完这4帧，而接收方全部正确接收，但确认帧全部丢失。

此时接收方期待的下一帧又是0号帧。

发送方超时后重新发送旧的0号帧，接收方却可能将它当作新一轮的0号帧。

这就产生了歧义。

因此必须保证：

$$
\boxed{W_T\leq 2^n-1}
$$

对于SR，为了避免新旧接收窗口的序号空间发生歧义，需要满足：

$$
W_T+W_R\leq 2^n
$$

当发送窗口与接收窗口大小相等时：

$$
\boxed{W_T=W_R\leq 2^{n-1}}
$$

窗口上限的依据是避免新旧帧的序号产生歧义。

### 2.3 代表性真题：2017年408 GBN综合大题

本题综合考查发送窗口、接收窗口、累计确认、捎带确认、超时重传和信道利用率。

#### 题目核心条件

甲乙双方采用GBN协议，持续进行双向数据传输，并始终采用捎带确认。

| 条件     | 数值         |
| ------ | ---------- |
| 数据帧长度  | 1000B      |
| 发送序号字段 | 3 bit      |
| 确认序号字段 | 3 bit      |
| 信道速率   | 100 Mbps   |
| RTT    | 0.96 ms    |
| 确认序号含义 | 期望收到的下一帧序号 |

题目使用 $S_{x,y}$ 表示甲发送的数据帧，其中：

$$
x=\text{甲方自己的发送序号}
$$

$$
y=\text{甲方期待乙方发送的下一帧序号}
$$

这是两个完全独立的状态。

<Callout type="idea" title="双向状态独立">

**做捎带确认题时，一定要把发送方向和接收方向分开分析。**

</Callout>

<Steps>

<Step>

### 确定已确认帧

题目图$a$中，甲方最后收到乙方发来的帧为：

$$
R_{3,3}
$$

第二个3表示乙方希望收到甲方的3号帧。

由于GBN采用累计确认，因此说明甲方的0、1、2号帧已经被正确接收。

答案为：

$$
\boxed{S_{0,0},S_{1,0},S_{2,0}}
$$

共3帧。

注意，不应该根据甲方发送了多少帧来判断乙方正确接收了多少帧，而应该根据乙方返回的累计确认号判断。

</Step>

<Step>

### 计算剩余窗口与捎带确认

序号字段为3 bit，因此：

$$
M=2^3=8
$$

GBN最大发送窗口为：

$$
W_T=8-1=7
$$

根据题目图$a$，甲方已发送0～4号帧，其中0～2号帧已经得到确认。

所以当前状态为：

$$
base=3,\qquad nextseqnum=5
$$

已发送未确认的帧有3号、4号，共2帧。

因此：

$$
\boxed{7-2=5\text{帧}}
$$

接下来可以发送的序号为：

$$
5,6,7,0,1
$$

那么捎带确认号是多少？

图$a$中甲正确接收了乙方0号和1号帧，但是缺少2号帧，虽然乙方3号帧到达了甲方，GBN仍然会将失序帧丢弃。

因此甲期待的仍然是2号帧。

接下来发送的5个帧分别为：

$$
S_{5,2},S_{6,2},S_{7,2},S_{0,2},S_{1,2}
$$

第一帧和最后一帧为：

$$
\boxed{S_{5,2},S_{1,2}}
$$

这道题最容易犯的错误，就是看到乙方的3号帧到达，误认为确认号应该变为4。

<Callout type="warn" title="GBN接收规则">

**GBN接收方只接受当前期待的帧，不会因为更大的序号到达而跳过缺失的帧。**

</Callout>

</Step>

<Step>

### 确定超时重传帧

根据图$b$，甲方已经发送0～4号帧，但乙方的累计确认号停留在2。

所以：

$$
base=2,\qquad nextseqnum=5
$$

需要重传：

$$
2,3,4
$$

共3帧。

同时，甲方已经按序收到了乙方0、1、2号帧，因此期待乙方的3号帧。

所以第一个重传帧为：

$$
\boxed{S_{2,3}}
$$

这里有一个非常重要的细节：**重传时可以携带当前最新的确认序号，不一定照搬原来发送时的确认号。**

原来的 $S_{2,0}$ 重传时变成 $S_{2,3}$，正是因为甲方接收方向的状态发生了变化。

</Step>

</Steps>

### 2.4 滑动窗口题的万能草稿模板

遇到类似题目，直接在草稿纸上写出这张状态表。

| 状态变量              | 图$a$ | 图$b$ |
| ----------------- | ---- | ---- |
| 最早未确认序号 base      | 3    | 2    |
| 下一新帧序号 nextseqnum | 5    | 5    |
| 期待对方的下一帧序号        | 2    | 3    |
| 已发送未确认帧数          | 2    | 3    |
| 最大发送窗口            | 7    | 7    |

这样既可以解决还能发送多少帧的问题，又可以解决重传哪些帧、捎带确认号是多少的问题。

分别维护发送状态与接收状态即可。

## 三、信道利用率与有效数据传输速率

这是贯穿物理层、数据链路层和传输层的通用计算模型。

### 3.1 先掌握三个基础时间

设数据帧长度为 $L$ bit，确认帧长度为 $L_{\mathrm{ACK}}$ bit，信道速率为 $R$，链路距离为 $d$，信号传播速度为 $v$。

数据帧发送时延：

$$
T_d=\frac{L}{R}
$$

确认帧发送时延：

$$
T_a=\frac{L_{\mathrm{ACK}}}{R}
$$

单向传播时延：

$$
\tau=\frac{d}{v}
$$

如果题目中的RTT仅表示往返传播时延，则：

$$
RTT=2\tau
$$

从发送方开始发送一帧，到完整收到该帧的确认，在忽略处理、排队等时延且接收方立即返回确认的条件下，需要经历：

```text
发送数据帧 → 数据帧传播 → 发送确认帧 → 确认帧传播
    Td           τ           Ta           τ
```

因此确认周期为：

$$
\boxed{T=T_d+T_a+2\tau}
$$

如果题目已经将数据帧或ACK的发送时延包含在RTT的定义中，就不能重复计算。一定要根据题意确定时间范围。

### 3.2 信道利用率通用公式

停止等待协议在一个确认周期内只能发送一帧：

$$
\boxed{U=\frac{T_d}{T_d+T_a+2\tau}}
$$

滑动窗口协议最多可以连续发送 $W$ 帧。在无差错、发送方始终有数据且确认及时返回的理想条件下：

$$
\boxed{
U=\min\left(1,\frac{WT_d}{T_d+T_a+2\tau}\right)
}
$$

当确认帧发送时延忽略不计时，可以简化为：

$$
\boxed{
U=\min\left(1,\frac{W}{1+2a}\right)
}
$$

其中：

$$
a=\frac{\tau}{T_d}
$$

#### 为什么要与1取最小值？

因为窗口足够大时，发送方可以不停地发送数据，信道达到满载。

但无论窗口再大，利用率都不可能超过100%。

达到满利用率的最小发送窗口为：

$$
\boxed{
W_{\min}=
\left\lceil
\frac{T_d+T_a+2\tau}{T_d}
\right\rceil
}
$$

### 3.3 继续分析2017年真题的第四问

题目给出：

$$
L=1000\times8=8000\text{ bit}
$$

$$
R=100\times10^6\text{ bit/s}
$$

数据帧发送时延为：

$$
T_d=\frac{8000}{100\times10^6}
=80\ \mu s
$$

题目采用捎带确认，双方的数据帧长度均为1000B。

因此携带确认信息的返回帧也需要完整的发送时间：

$$
T_a=80\ \mu s
$$

按照本题对RTT的计算口径：

$$
RTT=0.96\text{ ms}=960\ \mu s
$$

一个确认周期为：

$$
T=80+80+960=1120\ \mu s
$$

GBN发送窗口最大为7，因此：

$$
U=\frac{7\times80}{1120}
$$

$$
\boxed{U=50\%}
$$

#### 捎带确认的时间开销

捎带确认的返回帧也是完整的数据帧。

如果错误地忽略返回帧的发送时延，就会算错。

在相同条件下，不同发送窗口对应的理想利用率如下：

| 发送窗口 | 信道利用率  |
| ---- | ------ |
| 1    | 7.14%  |
| 4    | 28.57% |
| 7    | 50%    |
| 10   | 71.43% |
| 14   | 100%   |
| 15   | 100%   |

这里窗口大于7的情况仅用于说明窗口大小与利用率的关系，原题的3 bit GBN协议不允许这些窗口取值。

由此可以理解：**窗口的作用，本质上是利用等待确认的时间继续发送数据，从而填满链路。**

### 3.4 有效数据传输速率与信道利用率的区别

这是2010年真题考查的一个重要陷阱。

| 概念       | 计算方式              |
| -------- | ----------------- |
| 信道速率     | 物理链路每秒能够发送的比特数    |
| 信道利用率    | 用于发送所考查数据帧的时间占比   |
| 数据帧传输速率  | 单位时间成功传输的完整数据帧比特数 |
| 有效数据传输速率 | 单位时间成功传输的有效载荷比特数  |

标准无VLAN标签的以太网MAC帧格式为：

| 字段      | 长度       |
| ------- | -------- |
| 目的MAC地址 | 6B       |
| 源MAC地址  | 6B       |
| 类型/长度字段 | 2B       |
| 数据部分    | 46～1500B |
| FCS     | 4B       |

所以：

$$
\text{以太网帧开销}=18\text{B}
$$

$$
\text{最小帧长}=64\text{B}
$$

$$
\text{最大帧长}=1518\text{B}
$$

有效数据速率的通用计算方法为：

$$
\boxed{
R_{\text{有效}}=
\frac{\text{成功传输的有效数据量}}
{\text{实际消耗的总时间}}
}
$$

在简单无差错模型中，也可以写成：

$$
R_{\text{有效}}
=R\times U\times\frac{L_{\text{有效}}}{L}
$$

#### 代表性真题：2010年408第二问

题目条件：链路速率10 Mbps，单向传播时延10 $\mu s$，甲方发送1518B数据帧，乙方返回64B确认帧，甲收到确认后才能继续发送。

根据以太网帧格式：

$$
L_{\text{有效}}=1518-18=1500\text{B}
$$

数据帧发送时间：

$$
T_d=\frac{1518\times8}{10\times10^6}
=1214.4\ \mu s
$$

确认帧发送时间：

$$
T_a=\frac{64\times8}{10\times10^6}
=51.2\ \mu s
$$

按照原题参考解答采用的简化模型，一个周期为：

$$
T=1214.4+51.2+20
=1285.6\ \mu s
$$

有效数据传输速率：

$$
R_{\text{有效}}
=\frac{1500\times8}{1285.6\times10^{-6}}
$$

$$
\boxed{R_{\text{有效}}\approx9.33\text{ Mbps}}
$$

区分以下三个量：

- 1518B：实际发送的数据帧长度。
- 1500B：有效数据部分长度。
- 1285.6 $\mu s$：完成一次数据发送和确认的总时间。

原题按照简化模型没有额外计入帧间间隔；其他题目如果明确给出帧间间隔、前导码等开销，则应将其纳入总时间。

## 四、CSMA/CD：掌握碰撞检测的时间轴模型

### 4.1 为什么需要CSMA/CD？

在传统共享式半双工以太网中，多个站点共享同一传输介质。

由于信号传播需要时间，即使两个站点发送数据之前都监听到了空闲信道，它们仍然可能同时发送数据并产生碰撞。

CSMA/CD的核心过程是：

**先监听、空闲发送、边发边听、冲突停止、随机退避。**

最小帧长与最大传输距离均受碰撞检测时间约束。

### 4.2 最坏情况下的碰撞过程

设A、B分别位于共享链路的两端，单向传播时延为 $\tau$。

```text
时刻 0：
A 开始发送 ─────────────────────── B

时刻 τ−ε：
A ───────────────→ A的信号即将到达 B
                                  B 开始发送

时刻 τ 附近：
A ─────────────────────────────── B 检测到冲突

时刻 2τ 附近：
A 检测到冲突 ←─────────────────── B
```

A需要接近两倍的单向传播时延才能检测到这次碰撞。

如果A在碰撞信号返回之前就已经发送完毕，它便可能无法检测到碰撞。

因此必须满足：

$$
\boxed{T_d\geq2\tau}
$$

又因为：

$$
T_d=\frac{L}{R}
$$

所以：

$$
\boxed{L_{\min}\geq2\tau R}
$$

这就是以太网最小帧长公式的真正来源。

### 4.3 三种常见的逆向计算

| 题目要求   | 公式（无额外设备延迟时）                      |
| ------ | --------------------------------- |
| 最小帧长   | $L_{\min}=2\tau R$               |
| 最大传播距离 | $d_{\max}=\frac{L_{\min}v}{2R}$ |
| 最大信道速率 | $R_{\max}=\frac{L_{\min}v}{2d}$ |

这些并不是三个独立公式，而是同一个约束：

$$
\boxed{\frac{L}{R}\geq2\frac{d}{v}}
$$

#### 必须理解的反直觉现象

在最小帧长保持不变时，提高传输速率反而会缩短CSMA/CD网络允许的最大距离。

因为速率越高，一帧越快发送完毕，留给碰撞检测的时间也就越短。

### 4.4 代表性真题：2010年408第一问

题目给出甲乙之间距离为2 km，传播速度为200000 km/s。

单向传播时延为：

$$
\tau=\frac{2}{200000}
=10\ \mu s
$$

问题要求，从最早开始发送数据的时刻起，到两台主机都检测到碰撞为止，最短和最长需要多长时间。

<Tabs items={['最短情况：同时发送', '最长情况：临界时刻发送']}>

<Tab value="最短情况：同时发送">

碰撞发生在中间附近，两台主机都要经过一个单向传播时延才能检测到碰撞。

$$
\boxed{T_{\min}=\tau=10\ \mu s}
$$

</Tab>

<Tab value="最长情况：临界时刻发送">

最早开始发送的主机需要接近 $2\tau$ 才能检测到碰撞。

$$
\boxed{T_{\max}=2\tau=20\ \mu s}
$$

</Tab>

</Tabs>

最容易错的地方，是将碰撞发生的时间与主机检测到碰撞的时间混为一谈。

碰撞最早可以在两站同时发送后的 $\tau/2$ 时刻于链路中部发生，但两端主机都检测到碰撞仍需 $\tau$。

### 4.5 代表性真题：2022年408最大距离计算

题目给出：

$$
R=100\text{ Mbps}
$$

$$
L_{\min}=64\text{B}
$$

$$
v=2\times10^8\text{ m/s}
$$

经过集线器时存在额外单向延迟：

$$
T_h=1.51\ \mu s
$$

要求两主机之间的最大距离。

首先计算争用期：

$$
T_{\text{争用}}=
\frac{64\times8}{100\times10^6}
=5.12\ \mu s
$$

由于争用期是最远两站之间的往返传播时间：

$$
\tau_{\max}=\frac{5.12}{2}
=2.56\ \mu s
$$

扣除集线器延迟，真正用于物理链路传播的时间为：

$$
T_{\text{传播}}=2.56-1.51
=1.05\ \mu s
$$

所以：

$$
d_{\max}
=2\times10^8\times1.05\times10^{-6}
$$

$$
\boxed{d_{\max}=210\text{ m}}
$$

这类题最通用的公式是：

$$
\boxed{
\frac{L_{\min}}{R}
=2\left(\frac{d_{\max}}{v}+\sum T_{\text{设备}}\right)
}
$$

如果题目给的是单向设备延迟，就要随传播时间一起乘2；如果直接给出往返延迟，则不能再次乘2。

还要注意，210 m是依据题目给定参数求出的理论碰撞检测距离，并不是现实中100Base-T网线的标准布线长度。

### 4.6 二进制指数退避算法

虽然上述真题主要考查碰撞时间和距离，但二进制指数退避是这一模型的重要延伸。

第 $k$ 次碰撞后，令：

$$
m=\min(k,10)
$$

从以下整数中随机选取一个：

$$
r\in\{0,1,\ldots,2^m-1\}
$$

退避时间为：

$$
\boxed{T_{\mathrm{backoff}}=rT_{\text{争用}}}
$$

例如第三次碰撞后：

$$
r\in\{0,1,2,3,4,5,6,7\}
$$

最大退避时间是7个争用期，而不是8个。

传统以太网达到16次发送失败后放弃该帧的继续发送尝试，并报告错误。

## 五、网络拓扑、冲突域、广播域与交换机

这一部分通常不会涉及非常复杂的计算，但是容易与DHCP、ARP、IP地址和无线局域网结合考查。

### 5.1 从设备的工作层次推导功能

| 设备      | 工作层次  | 隔离冲突域 | 隔离广播域 |
| ------- | ----- | ----- | ----- |
| 中继器     | 物理层   | 否     | 否     |
| 集线器Hub  | 物理层   | 否     | 否     |
| 网桥      | 数据链路层 | 是     | 否     |
| 普通二层交换机 | 数据链路层 | 是     | 否     |
| 路由器     | 网络层   | 是     | 是     |

这里的广播域结论按照普通二层交换、不划分VLAN的模型理解。VLAN可以进一步划分广播域。

不同设备的转发机制：

**集线器转发的是物理信号，因此所有连接的站点仍共享传输介质。**

**交换机根据MAC地址转发数据帧，可以将不同端口的传输分离。**

**路由器根据IP地址进行分组转发，不会像普通二层交换机一样直接泛洪链路层广播帧。**

现代全双工交换以太网的点对点链路实际上不存在共享介质碰撞；考试中的冲突域划分通常沿用每个交换机端口隔离冲突域的传统模型。

### 5.2 代表性真题：2022年408网络拓扑题

题目规定：

H1与H2属于同一广播域，但不属于同一个冲突域。

H2与H3属于同一个冲突域。

根据原题拓扑，可以将相关部分简化为：

```text
                   设备1
                ┌─────────┐
                │ 交换机  │
                └─┬─────┬─┘
                  │     │
                 H1    设备2
                     ┌───────┐
                     │  Hub  │
                     └─┬───┬─┘
                       │   │
                      H2   H3
```

设备1需要隔离冲突域，但是不能隔离广播域，因此在给出的三种设备中选择交换机。

设备2不能隔离冲突域，因此选择集线器。

$$
\boxed{\text{设备1：交换机}}
$$

$$
\boxed{\text{设备2：集线器}}
$$

**做网络拓扑题时，先判断广播域，再判断冲突域，最后确定设备。**

### 5.3 交换机自学习算法

交换机的转发表记录的是：

$$
\text{MAC地址}\longrightarrow\text{端口}
$$

每当交换机接收到一个数据帧，它需要完成两件事：

第一，根据源MAC地址学习：发送该帧的主机位于哪个端口方向。

第二，根据目的MAC地址决定转发行为。

| 目的地址情况          | 处理方法                 |
| --------------- | -------------------- |
| 目的MAC已知，且位于其他端口 | 定向转发                 |
| 目的MAC已知，且与入端口相同 | 过滤，不向其他端口转发          |
| 目的MAC未知         | 向同一VLAN内除入端口外的相关端口泛洪 |
| 广播MAC地址         | 向同一VLAN内除入端口外的相关端口泛洪 |

<Callout type="idea" title="交换机自学习">

**最关键的记忆：根据源地址学习，根据目的地址转发。**

</Callout>

例如A从端口1发送给B，交换机最初不知道A和B的位置。

交换机先学习：

$$
A\longrightarrow1
$$

因为B未知，所以泛洪。

当B从端口2回复A时，交换机学习：

$$
B\longrightarrow2
$$

此时A已知，直接从端口1转发。

这个过程不需要交换机主动发送ARP请求来学习普通二层转发表。

### 5.4 DHCP与广播域的综合考查

2022年真题第三问考查H4通过DHCP获取IP地址。

DHCP的典型四步过程如下：

```text
客户端                              DHCP服务器
  │ ───────── Discover ──────────────→ │
  │ ←───────── Offer ───────────────── │
  │ ───────── Request ───────────────→ │
  │ ←────────── ACK ────────────────── │
```

客户端首次发送DHCP Discover时，还没有获得IP地址，也不知道DHCP服务器的具体地址，因此使用广播。

首次Discover的典型封装：

| 字段      | 内容                |
| ------- | ----------------- |
| 源IP地址   | 0.0.0.0           |
| 目的IP地址  | 255.255.255.255   |
| 源MAC地址  | 客户端MAC            |
| 目的MAC地址 | FF-FF-FF-FF-FF-FF |
| UDP源端口  | 68                |
| UDP目的端口 | 67                |

原题中路由器E0接口与H4位于同一个广播域，因此：

$$
\boxed{\text{E0接口可以收到该广播帧}}
$$

交换机向DHCP服务器转发时，目的MAC地址仍是：

$$
\boxed{\text{FF-FF-FF-FF-FF-FF}}
$$

这里有一个经典陷阱：

<Callout type="warn" title="广播域边界">

**路由器能够接收到广播帧，不代表路由器会把该广播帧转发到另一个广播域。**

</Callout>

若配置DHCP中继，可以通过中继机制联系其他网络中的DHCP服务器，但那不是普通二层广播帧的直接跨网转发。

## 六、无线局域网802.11：必须掌握的三地址模型

2022年真题和2027王道第1套第47题都考查了这个知识点，值得重点掌握。

### 6.1 为什么无线局域网需要三个MAC地址？

以太网普通数据帧只需要源MAC和目的MAC。

但无线局域网中，实际在无线链路上发送帧的设备，不一定是数据的原始发送者。

例如：

```text
Host-S ── 以太网交换机 ── AP ))) 无线链路 ))) STA1
  ↑                       ↑                   ↑
原始发送者            无线帧实际发送者        无线接收者
```

这个过程中有三个不同的角色：

| 缩写 | 含义             |
| -- | -------------- |
| SA | 数据的原始源地址       |
| DA | 数据的最终目的地址      |
| TA | 当前无线链路上的实际发送地址 |
| RA | 当前无线链路上的实际接收地址 |

在普通基础设施模式下，部分角色由同一个设备承担，因此使用三个地址字段即可。

### 6.2 上行帧与下行帧

普通基础设施模式的802.11数据帧：

| 传输方向    | To DS | From DS | 地址1          | 地址2         | 地址3      |
| ------- | ----- | ------- | ------------ | ----------- | -------- |
| 无线站点→AP | 1     | 0       | AP（RA）       | 无线源站（TA/SA） | 最终目的地址DA |
| AP→无线站点 | 0     | 1       | 无线目的站（RA/DA） | AP（TA）      | 原始源地址SA  |

地址字段的基本规律：

$$
\boxed{\text{地址1：无线链路实际接收方}}
$$

$$
\boxed{\text{地址2：无线链路实际发送方}}
$$

地址3则用于补充尚未表达的原始源地址或最终目的地址。

在上述基础设施模式数据帧中，AP的BSSID会出现在地址1或地址2。

### 6.3 代表性真题：2022年408第四问

H4向H5发送一个IP分组，两者均连接到同一个AP。

实际无线传输分两段：

```text
H4 ──────────→ AP ──────────→ H5
       上行帧             下行帧
```

第一段H4→AP：

| 字段  | 内容 |
| --- | -- |
| 地址1 | AP |
| 地址2 | H4 |
| 地址3 | H5 |

第二段AP→H5：

| 字段  | 内容 |
| --- | -- |
| 地址1 | H5 |
| 地址2 | AP |
| 地址3 | H4 |

题目问的是H5最终收到的802.11帧，所以分析第二段。

根据题目图中的MAC地址：

$$
\boxed{\text{地址1：00-11-11-11-11-E1}}
$$

$$
\boxed{\text{地址2：00-11-11-11-11-C1}}
$$

$$
\boxed{\text{地址3：00-11-11-11-11-D1}}
$$

### 6.4 模拟题变式：有线服务器向无线主机发送数据

2027王道第1套第47题给出的拓扑为：

```text
Host-S ── 交换机S ── AP
                     ├ ))) STA1
                     └ ))) STA2
```

Host-S向STA1发送IP分组。

AP工作在桥接模式，而非路由模式。

STA1最终收到的无线帧为：

| 字段  | 对应设备   | MAC地址             |
| --- | ------ | ----------------- |
| 地址1 | STA1   | 00-11-11-11-11-D1 |
| 地址2 | AP     | 00-11-11-11-11-C1 |
| 地址3 | Host-S | 00-11-11-11-11-88 |

与2022年真题相比，原始数据发送方从无线主机变成了有线服务器，但解题方法完全相同。

**先判断无线链路实际的发送方和接收方，再补上原始源地址或最终目的地址。**

还需要区分AP桥接与路由器转发：如果跨越了路由器，链路层封装会重新生成，此时应该从当前链路的帧源地址出发分析，而不能机械地追溯到最初发送IP分组的主机MAC地址。

## 七、CSMA/CA、DCF与隐藏终端

这一部分由2027王道模拟题重点考查，是本章重要的综合简答题模型。

### 7.1 为什么无线局域网不用CSMA/CD？

无线设备在发送信号时，自身的发送信号通常远强于接收到的其他站点的信号，难以可靠进行边发送边碰撞检测。

另外还存在隐藏终端等问题。

因此802.11无线局域网采用CSMA/CA碰撞避免机制。

| 对比项目      | CSMA/CD        | CSMA/CA     |
| --------- | -------------- | ----------- |
| 典型应用      | 传统共享式半双工以太网    | 802.11无线局域网 |
| 主要思想      | 发生碰撞后检测并处理     | 尽量避免碰撞      |
| 是否边发边检测碰撞 | 是              | 通常不进行       |
| 确认机制      | 普通以太网MAC无逐帧ACK | 普通单播采用ACK   |
| 退避机制      | 检测碰撞后随机退避      | 信道竞争中随机退避   |

注意，CSMA/CA只是降低碰撞概率，并不能彻底消除碰撞。

### 7.2 DCF机制：为什么ACK可以优先发送？

题目问STA1监听到信道忙，后来信道转为空闲时，发送普通数据帧需要经历什么过程。

标准的答题逻辑为：

```text
信道忙
   ↓
信道转为空闲
   ↓
持续空闲达到 DIFS
   ↓
随机退避计数
   ↓
空闲时计数递减，忙时冻结
   ↓
计数归零，发送数据帧
   ↓
接收方等待 SIFS
   ↓
发送 ACK
```

关键关系：

$$
\boxed{SIFS<DIFS}
$$

因为接收方返回ACK之前只需要等待SIFS，而其他竞争发送普通数据帧的站点至少需要等待DIFS，所以ACK具有优先发送机会。

#### 随机退避计数的细节

假设一个站点还剩5个退避时隙。

经历2个空闲时隙后，剩余3个时隙。此时其他站点开始发送数据，信道变忙。

该站点应该冻结计数器，等信道再次空闲达到DIFS后，从剩余3个时隙继续计数。

不是每次信道变忙都重新抽取一个随机数。

这属于特别容易考查的时序细节。

### 7.3 隐藏终端的本质

```text
  STA1  ))) )))      AP      ((( (((  STA2

  STA1  ←──── 无法互相监听 ────→  STA2

       两个站点都能够与 AP 通信
```

STA1正在向AP发送数据，但是STA2监听不到STA1。

STA2误认为信道空闲，也向AP发送数据。

两个信号在AP处产生冲突。

这就是隐藏终端问题。

本质在于：

$$
\boxed{\text{发送方监听到的信道状态，不一定代表接收方的信道状态}}
$$

#### RTS/CTS如何缓解隐藏终端问题？

```text
STA1                  AP                  STA2
  │ ───── RTS ───────→ │                     │
  │ ←──── CTS ──────── │ ───── CTS ────────→ │
  │ ───── DATA ──────→ │                  暂缓发送
  │ ←──── ACK ──────── │                     │
```

STA2虽然监听不到STA1的RTS，但能够收到AP发送的CTS，从而知道接下来一段时间信道将被占用。

其他站点可以利用帧中的持续时间信息设置NAV，进行虚拟载波监听。

因此RTS/CTS可以减少隐藏终端导致的数据帧碰撞，但会带来额外控制帧开销，而且不能保证完全消除碰撞。

模拟题特别强调，STA1和STA2都连接到同一个AP，并不能证明它们一定互为隐藏终端，还必须满足两者不能有效地相互载波监听。

## 八、数据链路层与TCP可靠传输的综合考查

2027王道第1套模拟题有一个非常有价值的跨层考点：无线链路中的数据帧丢失，如何影响TCP？

### 8.1 两种ACK必须区分

| 对比项目 | 802.11 MAC ACK | TCP ACK      |
| ---- | -------------- | ------------ |
| 所属层次 | 数据链路层          | 传输层          |
| 确认对象 | 无线MAC帧         | TCP字节流       |
| 作用范围 | 当前无线链路         | 端到端TCP连接     |
| 确认依据 | 无线帧是否成功接收      | 哪些连续字节已经收到   |
| 丢失恢复 | MAC层重试         | TCP快速重传或超时重传 |

一份TCP数据可以被封装进IP分组，再封装进802.11数据帧。

```text
TCP报文段
    ↓
IP数据报
    ↓
802.11 MAC帧
    ↓
无线信号
```

当无线帧传输出错时，802.11可以在本地链路进行重传。

如果MAC层重传成功，TCP层可能完全感知不到这次丢包。

如果MAC重试之后仍然失败，才可能需要TCP进行端到端恢复。

### 8.2 模拟题核心：第一个TCP报文段丢失

假设TCP连续发送以下四个报文段，每段1000B：

| 报文段 | 起始序号 | 接收情况 |
| --- | ---- | ---- |
| 第1段 | 1000 | 丢失   |
| 第2段 | 2000 | 到达   |
| 第3段 | 3000 | 到达   |
| 第4段 | 4000 | 到达   |

假设接收方原本期待1000号字节，并已发出相应的累计确认。

虽然之后的报文段已经到达，但由于第1000号开始的一段字节缺失，累计确认号仍然停留在：

$$
ACK=1000
$$

```text
发送方                              接收方

Seq=1000 ──────────×                 丢失

Seq=2000 ─────────────────────────→  失序
          ←──────────────────────── ACK=1000

Seq=3000 ─────────────────────────→  失序
          ←──────────────────────── ACK=1000

Seq=4000 ─────────────────────────→  失序
          ←──────────────────────── ACK=1000

Seq=1000 ─────────────────────────→  快速重传
          ←──────────────────────── ACK=5000
                         （若后续报文段均已缓存）
```

经典TCP快速重传的触发条件是：

$$
\boxed{\text{收到3个重复ACK}}
$$

如果没有达到快速重传的条件，则通常通过重传计时器超时进行恢复。

#### 本题最重要的三个结论

第一，MAC层ACK与TCP ACK完全不同，不能混淆。

第二，无线帧发生一次丢失，不一定导致TCP重传。

第三，TCP连续发送多个报文段，并不意味着一定可以触发快速重传，因为重复ACK数量可能不足。

此外，GBN和TCP虽然都可以采用累计确认，但二者接收失序数据和重传数据的机制不同，不能直接把TCP当成GBN协议处理。

## 九、其他必须掌握的基础计算：CRC与透明传输

CRC与透明传输是补充知识点，未在原题库本章四道大题中独立出现。

### 9.1 CRC循环冗余校验

CRC的本质是利用模2除法构造能够被生成多项式整除的码字。

假设生成多项式：

$$
G(x)=x^3+x+1
$$

对应二进制：

$$
G=1011
$$

需要注意：

$$
\boxed{\text{CRC位数}=\text{生成多项式最高次数}}
$$

这里生成多项式最高次数为3，所以CRC占3 bit。

假设原始数据为1101。

首先在数据末尾补3个0：

$$
1101000
$$

然后进行模2除法：

```text
1101000
1011000
─────── XOR
0110000
0101100
─────── XOR
0011100
0010110
─────── XOR
0001010
0001011
─────── XOR
0000001
```

余数为：

$$
FCS=001
$$

最终发送的数据为：

$$
\boxed{1101001}
$$

接收方用同一个生成多项式进行模2除法。

余数非零说明检测到差错，余数为零则说明没有检测到差错，但不能保证绝对无差错。

CRC只负责检错，并不自动完成纠错和重传。

### 9.2 零比特填充

在采用比特填充的HDLC、同步PPP等协议中，为了避免数据部分出现与帧定界标志相同的比特序列，发送方在数据部分每遇到连续5个1，就插入一个0。

例如：

```text
原始数据：01111110

填充之后：011111010
                 ↑
              插入的0
```

接收方执行相反操作，删除数据部分连续5个1之后填充的0。

注意，异步PPP使用的是字节填充，不能将所有PPP场景都看成比特填充。

## 十、本章大题最容易丢分的知识点

| 常见错误               | 正确理解                     |
| ------------------ | ------------------------ |
| 3 bit序号的GBN窗口为8    | 最大窗口为7                   |
| 收到ACK=3说明3号帧已确认    | 如果ACK表示下一期待序号，则确认的是此前连续帧 |
| GBN收到失序帧就缓存        | GBN接收窗口为1，丢弃失序帧          |
| GBN只重传发生丢失的一帧      | 超时后重传最早未确认帧及其后已发送的未确认帧   |
| 捎带确认号与发送序号有关       | 二者分别描述两个方向的状态            |
| 重传时必须沿用旧确认号        | 可以携带当前最新的确认号             |
| 信道利用率可以大于1         | 最大为100%                  |
| 捎带确认不需要发送时间        | 携带确认的数据帧本身也需要发送时间        |
| 1518B都是有效数据        | 标准最大有效载荷为1500B           |
| 碰撞发生就意味着发送方检测到碰撞   | 检测需要信号传播时间               |
| 最小帧长为 $\tau R$     | 最坏情况下需要 $2\tau R$        |
| 交换机隔离所有广播域         | 普通二层交换机不隔离同一VLAN的广播域     |
| 交换机根据目的MAC学习       | 根据源MAC学习                 |
| 路由器不能收到广播帧         | 可以收到本地广播，但通常不向其他网络转发     |
| 802.11地址2一定是原始发送主机 | 地址2是当前无线链路实际发送者          |
| CSMA/CA彻底避免碰撞      | 只能降低碰撞概率                 |
| DIFS比SIFS短         | SIFS比DIFS短               |
| 信道忙就重新随机退避         | 已有退避计数通常被冻结，随后恢复         |
| 无线帧丢失一定触发TCP重传     | MAC层可能先完成本地重传            |

## 十一、考场公式速查表

| 考点          | 公式                                |
| ----------- | --------------------------------- |
| 数据发送时延      | $T_d=L/R$                         |
| 单向传播时延      | $\tau=d/v$                        |
| 序号空间        | $M=2^n$                           |
| GBN最大窗口     | $W_T=2^n-1$                       |
| SR等大窗口上限    | $W_T=W_R=2^{n-1}$                 |
| 可继续发送帧数     | $W_T-\text{已发送未确认帧数}$             |
| 确认周期        | $T_d+T_a+2\tau$                   |
| 停止等待利用率     | $T_d/(T_d+T_a+2\tau)$             |
| 滑动窗口利用率     | $\min(1,WT_d/(T_d+T_a+2\tau))$    |
| 满利用率最小窗口    | $\lceil(T_d+T_a+2\tau)/T_d\rceil$ |
| 有效数据传输速率    | $L_{\text{有效}}/T$              |
| CSMA/CD争用期  | $2\tau$                           |
| 最小帧长        | $2\tau R$                         |
| 最大距离（无额外延迟） | $L_{\min}v/(2R)$                 |
| 二进制指数退避时间   | $rT_{\text{争用}}$               |
| CRC冗余位数     | 生成多项式最高次数                         |

## 十二、考前自测

独立解释以下10个问题。

- 为什么GBN发送窗口不能等于整个序号空间？
- 为什么SR等大发送、接收窗口最多只能占序号空间的一半？
- 为什么捎带确认题必须分别维护发送状态和接收状态？
- 为什么滑动窗口可以提高信道利用率？怎样计算达到满利用率的最小窗口？
- 为什么CSMA/CD最小帧长必须满足两倍传播时延的约束？
- 为什么传输速率越高，固定最小帧长下的最大碰撞检测距离反而越小？
- 为什么交换机可以隔离冲突域，却不能隔离同一VLAN中的广播域？
- 为什么802.11无线数据帧需要区分原始源地址与实际发送地址？
- 为什么SIFS比DIFS短？随机退避为什么要冻结？
- 为什么无线链路层的丢包不一定导致TCP重传？
