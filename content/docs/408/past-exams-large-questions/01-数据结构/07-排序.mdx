## 2016 年第 43 题

<Question
  id="408-ds-large-2016-43"
  type="essay"
  tags="来源:2016考研408, 科目:数据结构, 章节:排序, 考点:快速选择, 考点:双目标划分, 难度:综合"
>

已知有 $n$（$n\ge2$）个正整数构成集合

$$
A=\{a_k\mid 0\le k<n\}.
$$


现将其划分为两个不相交的子集 $A_1,A_2$，对应元素个数为 $n_1,n_2$，元素和为 $S_1,S_2$。设计尽可能高效的算法，使

$$
|n_1-n_2|\ \text{最小，且在此条件下}\ |S_1-S_2|\ \text{最大。}
$$


要求：

1. 给出算法的基本设计思想。
2. 用 C 或 C++ 描述算法。
3. 说明时间复杂度和空间复杂度。

<Solution>

### 参考答案

此题是**有优先级的双目标最优化**，不能把两个指标随意加权处理。

1. 首先令 $k=\lfloor n/2\rfloor$，将其中一组的元素个数固定为 $k$，另一组固定为 $n-k=\lceil n/2\rceil$，从而保证人数差最小（偶数为 $0$、奇数为 $1$）。
2. 正整数条件下，取**最小的 $k$ 个数**组成 $A_1$，其余全部构成 $A_2$，即可达到最大和差。若 $n$ 为奇数，元素较多的一组应接收较大的那一半元素。
3. 用 **Quickselect** 将第 $k$ 小与其余元素在数组中划开，无须将两组内部完全排序。末尾一次线性扫描分别求和。采用随机枢轴的迭代三路划分，**期望 $O(n)$ 时间**、**最坏 $O(n^2)$ 时间**、辅助空间 $O(1)$（不计随机数发生器状态），原数组会被重排。

### 推导：为什么一定是“小的一组取最小的 $k$ 个”？

<Steps>
  <Step>

  ### 第一步：先满足优先级更高的人数约束

  因为 $n_1+n_2=n$，显然

  $$
  \min|n_1-n_2|=\begin{cases}0,&n\text{ 为偶数},\\1,&n\text{ 为奇数}\end{cases}
  $$


  所以无需考虑更不均衡的划分，即使那样可以产生更大的和差也**不符合题意**。

  </Step>
  <Step>

  ### 第二步：设定有序边界，证明最优性

  将 $n$ 个数非降序记为 $b_1\le b_2\le\cdots\le b_n$。令 $k=\lfloor n/2\rfloor$，总和 $S=\sum_i b_i$。某组若恰有 $k$ 个元素、其和为 $x$，则两组和差为

  $$
  |S_1-S_2|=|S-2x|.
  $$


  由有序性，$k$ 元素子集的和必满足

  $$
  B=\sum_{i=1}^k b_i\ \le x\le\ L=\sum_{i=n-k+1}^n b_i.
  $$


  $|S-2x|$ 是 $x$ 的凸函数，因此在区间 $[B,L]$ 上的最大值必发生在端点。若 $n=2k$，取最小 $k$ 个或最大 $k$ 个本质只是交换组名，两端得到相同绝对和差。

  若 $n=2k+1$，设中间数为 $c=b_{k+1}>0$，有 $S=B+c+L$。由于 $L\ge B$，

  $$
  |S-2B|=L+c-B,\qquad |S-2L|=|B+c-L|\le L+c-B.
  $$


  所以**选最小 $k$ 个给人数较少的一组**最优。这个严格结论依赖 $c>0$；若允许负数，最后一步未必成立。

  </Step>
  <Step>

  ### 第三步：只划分边界，不完整排序

  若将所有数先排序，当然可以取前 $k$ 个，但成本通常是 $O(n\log n)$；题目只需知道“哪 $k$ 个最小”，不要求它们内部从小到大排列，因此可使用 Quickselect。

  三路划分每次以枢轴 $pivot$ 将当前区间变为

  $$
  [\text{小于 }pivot]\ [\text{等于 }pivot]\ [\text{大于 }pivot].
  $$


  根据第 $k$ 个位置与三段边界的关系，仅继续处理必要的一段。大量重复值时，三路划分还可一次跳过整段相等键。

  </Step>
</Steps>

### 完整 C 实现：随机枢轴 + 三路快速选择

```c title="将最小的 k 个数原地放到数组前部"
#include <stdlib.h>

static void SwapInt(int *x, int *y) {
    int t = *x; *x = *y; *y = t;
}

// 约定 n>=2、元素均为正整数、允许原地改变输入次序。
// 返回两组和的最大绝对差。
long long divideSet(int a[], int n) {
    if (a == NULL || n < 2) return -1;
    int k = n / 2;
    int left = 0, right = n - 1;

    while (left <= right) {
        // 随机枢轴减少固定输入对固定枢轴的对抗性。
        int pivot = a[left + rand() % (right - left + 1)];
        int lt = left, i = left, gt = right;
        while (i <= gt) {
            if (a[i] < pivot) SwapInt(&a[lt++], &a[i++]);
            else if (a[i] > pivot) SwapInt(&a[i], &a[gt--]);
            else ++i;
        }
        // [left,lt) <pivot；[lt,gt] ==pivot；(gt,right] >pivot。
        // 若 k 落在等值区域或紧贴其两侧，前 k 个元素已经是最小 k 个。
        if (k < lt) right = lt - 1;
        else if (k > gt + 1) left = gt + 1;
        else break;
    }

    long long smallSum = 0, largeSum = 0;
    for (int i = 0; i < k; ++i) smallSum += a[i];
    for (int i = k; i < n; ++i) largeSum += a[i];
    return largeSum - smallSum; // 全为正整数时该差非负
}
```

**代码关键处：**`k` 是“前半组含 $k$ 个元素”，不是从 $1$ 起的第 $k$ 小的下标。判定停止用分界位置 $k$，最终取 `a[0..k-1]` 作为 $A_1$；若 $k$ 落在与枢轴相等的区段，可任意拿足所需个数，交换结果值不影响目标。

### 手算样例与复杂度

若输入 $A=\{3,12,5,9,1,20,4\}$，排序后只是为了**核对**：

$$
1,3,4\mid 5,9,12,20.
$$


因此 $A_1=\{1,3,4\}$、$A_2=\{5,9,12,20\}$，$n_1=3,n_2=4$，$S_1=8,S_2=46$；最小人数差为 $1$，最大和差为 $\boxed{38}$。选最小四个数作为一组，只能得到 $|13-41|=28$，与最优值不同。

- **期望时间**：随机枢轴下，每轮划分当前区间需线性时间，期望总扫描量为 $O(n)$；最后求和 $O(n)$。
- **最坏时间**：若每轮有效规模只缩减 $1$，划分成本可能累计为 $O(n^2)$。**平均/期望线性不等于最坏线性**。
- **辅助空间**：以上为迭代实现，除有限个变量外不占额外存储，$O(1)$。若改成递归 Quickselect，需计入递归栈；如不允许修改输入，复制数组还需 $O(n)$ 空间。

<Callout type="info" title="与排序题、背包题的区别">

本题要**最大化**和差，且所有元素都是**正整数**，所以最优解在排序两端。若题目改成“最小化和差”，就可能成为具有组合约束的划分/子集和问题，不能照搬这道题的快选切分法。

</Callout>

</Solution>
</Question>

### 原创预测题 1｜奇数规模下，交换两组人数就一定等价吗？

给定严格为正的 $7$ 个整数 $\{3,12,5,9,1,20,4\}$，仍要求先最小化 $|n_1-n_2|$，再最大化 $|S_1-S_2|$。

1. 给出一组达到最大和差的划分，并列出两组人数、和以及两个优化目标值。
2. 若机械地将**最小的四个数**放进人数较多的组，和差变为多少？
3. 对一般 $n=2k+1$ 的正整数数组，用中位数 $c$ 和两侧的和 $B,L$ 解释为什么人数多的一组应接受**较大的元素**；允许重复关键字时结论是否改变？

<Solution>

### 参考答案

1. 可取 $A_1=\{1,3,4\}$、$A_2=\{5,9,12,20\}$，所以 $(n_1,n_2)=(3,4)$、$(S_1,S_2)=(8,46)$，两目标依次为 $\boxed{1}$ 与 $\boxed{38}$。
2. 若改取 $A_1=\{1,3,4,5\}$、$A_2=\{9,12,20\}$，两组和为 $13$ 与 $41$，和差 $\boxed{28}$，虽然人数差仍为 $1$，但**未达到第二目标最优**。
3. 令排序后两侧的 $k$ 个数之和为 $B,L$，中位数为 $c>0$。令大元素组含 $k+1$ 个数可得到 $L+c-B$，反过来让小元素组含 $k+1$ 个数最多得到 $|L-(B+c)|$；前者不小于后者。重复关键字不会影响交换与界限证明，但可能导致最优划分不唯一。

### 推导

因为排序后 $L\ge B$ 且 $c>0$，直接分两种情形验证：

- 若 $L\ge B+c$，则 $|L-B-c|=L-B-c<L-B+c$。
- 若 $L<B+c$，则 $|L-B-c|=B+c-L\le L+c-B$，最后一步利用 $L\ge B$。

这样无论数据分布如何，人数多的一组放较大一半始终**不劣于**反向分配。若数值存在重复，分界附近的相等数可以分配给不同位置，但人数与两组和仍满足同一最优目标。

<Callout type="warn" title="不要把“人数差最小”误解成“人数多的必定是第 1 组”">

题目只规定 $|n_1-n_2|$ 最小，并未指定是 $A_1$ 还是 $A_2$ 多一个人。若将标签交换，不影响目标；真正关键是**较大的那一组人数应对应较大的那一批正数**。

</Callout>

</Solution>
</Question>

### 原创预测题 2｜去掉正整数条件，如何修正最优策略？

现在允许数组中出现负数和 $0$，仍要求先使人数差最小，再使两组**和的绝对差**最大。给定

$$
A=\{-10,-9,-8,1,2\}.
$$


1. 按原题机械选取最小的 $\lfloor n/2\rfloor$ 个值为一组，结果是多少？是否最优？
2. 在人数差仍为 $1$ 的前提下，找出更优的划分与目标值。
3. 推导一般有符号整数的最优规则：若 $k=\lfloor n/2\rfloor$，为什么只需比较“最小 $k$ 个数”与“最大 $k$ 个数”的组和？给出排序法的时间与辅助空间复杂度。

<Solution>

### 参考答案

1. 取最小两数 $\{-10,-9\}$，组和为 $-19$；其余 $\{-8,1,2\}$ 的和为 $-5$，和差仅 $\boxed{14}$，**不是最优**。
2. 改取 $A_1=\{1,2\}$（和为 $3$），$A_2=\{-10,-9,-8\}$（和为 $-27$），和差为 $\boxed{30}$，人数差仍为 $1$。
3. 对任一人数最均衡的划分，取其中**恰有 $k$ 个元素**的一组，其和为 $x$；设整个数组和为 $S$，则和差为 $|S-2x|$。大小为 $k$ 的子集和一定落在 $[B,L]$，其中 $B$ 为最小 $k$ 个元素的和，$L$ 为最大 $k$ 个元素的和。凸函数 $|S-2x|$ 在区间上取最大值于端点，因此最优值一定是

   $$
   \boxed{\max\{|S-2B|,\ |S-2L|\}}.
   $$


   采用原地堆排序后双端求和，可保证最坏 $O(n\log n)$ 时间和 $O(1)$ 额外空间；若使用 Quickselect 求两端的 $k$ 元素和，也可达期望 $O(n)$，但要单独处理划分和重复键。

### 证明与反例意义

**不能直接把正整数策略推广。** 原题证明中使用了中位数 $c>0$ 以确定哪一个端点更优；在本题 $c=-8<0$，将其放到人数更多、数值更小的一组反而可能使和差进一步拉大。

对任一固定数量为 $k$ 的子集，最小和 $B$ 必由最小 $k$ 个元素取到，最大和 $L$ 必由最大 $k$ 个元素取到。对于任何 $x\in[B,L]$，绝对值函数不可能严格超过两端较大者：

$$
|S-2x|\le\max\{|S-2B|,|S-2L|\}.
$$


因此**无须枚举所有 $\binom nk$ 个子集**。本例 $S=-24$，$B=-19$，$L=3$：

$$
|S-2B|=|-24+38|=14,\qquad |S-2L|=|-24-6|=30.
$$


两端比较便得到正确答案 $30$。当 $n$ 为偶数时，两端分组互为补集，因此两个端点的结果其实相等；当 $n$ 为奇数且允许负数时，才更应警惕“正整数时首选最小 $k$ 个”的固定结论。

<Callout type="info" title="可迁移考点：带人数限制的极值子集问题">

只要一个目标可写成 $|S-2x|$，且组的大小固定，就应该先思考**子集和的上下界**与目标函数的形状，再决定是否需要动态规划或穷举。最大化绝对差只需两个端点；把目标改成**最小化**绝对差时，这个端点论证就不再适用。

</Callout>

</Solution>

## 2021 年第 42 题

<Question
  id="408-ds-large-2021-42"
  type="essay"
  tags="来源:2021考研408, 科目:数据结构, 章节:排序, 考点:比较计数排序, 考点:排序稳定性, 难度:中等"
>

已知排序算法如下，数组 `b` 具有足够空间，`a` 与 `b` 为不同数组：

```c
void cmpCountSort(int a[], int b[], int n)
{
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n);

    for (i = 0; i < n; i++)
        count[i] = 0;

    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j])
                count[j]++;
            else
                count[i]++;

    for (i = 0; i < n; i++)
        b[count[i]] = a[i];

    free(count);
}
```

已知：

```c
int a[] = {25, -10, 25, 10, 11, 19};
int b[6];
cmpCountSort(a, b, 6);
```

要求：

1. 写出调用后 `b` 的内容。
2. 若含有 $n$ 个元素，元素之间总共比较多少次？
3. 判断排序是否稳定；若不稳定，给出**最小改动**使其稳定，并解释理由。

<Solution>

### 参考答案

1. `count = {5,0,4,1,2,3}`，故 $\boxed{b=\{-10,10,11,19,25,25\}}$。注意：两个 `25` 在输出中的**原始身份已交换**。
2. 关键字比较次数固定为

   $$
   \boxed{C(n)=\sum_{i=0}^{n-2}(n-i-1)=\frac{n(n-1)}2}.
   $$


3. **原算法不稳定。** 将 `if (a[i] < a[j])` 改为 **`if (a[i] <= a[j])`** 即可稳定；其余循环、搬运语句不必改变。时间为 $\Theta(n^2)$，工作数组 `count` 为 $O(n)$ 额外空间，`b` 是另外提供的长度 $n$ 的输出数组。

### 解析一：读懂 `count` 的真正含义

这不是经典的“按关键字取值建桶”的计数排序：题目既没给关键字值域，也没有维护每个值的频次。它实际上是**两两比较来求元素名次的比较计数排序**。

<Steps>
  <Step>

  **每对元素恰好比较一次。** 对下标 $i<j$，若 $a[i]<a[j]$，给较大的 `a[j]` 的名次加 $1$；否则给 `a[i]` 的名次加 $1$。该计数代表“按本算法的排序规则，有多少记录排在我前面”，即最终目的下标。

  </Step>
  <Step>

  **不相等时，较小者排在前面。** $-10,10,11,19$ 四个关键字的目标下标依次为 $0,1,2,3$。两个 $25$ 都大于前四者，剩余目标下标是 $4,5$。

  </Step>
  <Step>

  **相等时，原程序把左边的元素排在后面。** 当 $i=0,j=2$、两值均为 $25$ 时，条件 `25 < 25` 为假，执行 `count[0]++`。因此原下标 $0$ 的 `25` 名次是 $5$，下标 $2$ 的 `25` 名次是 $4$。

  </Step>
</Steps>

| 原下标 $i$ | 原值 $a[i]$ | 比较得出的 `count[i]` | 输出到 `b` 下标 |
| ---: | ---: | ---: | ---: |
| 0 | 25 | 5 | 5 |
| 1 | -10 | 0 | 0 |
| 2 | 25 | 4 | 4 |
| 3 | 10 | 1 | 1 |
| 4 | 11 | 2 | 2 |
| 5 | 19 | 3 | 3 |

所以数值结果递增，但若记原下标为身份标记，两个相等元素的相对次序是 `25(下标2) → 25(下标0)`，与原输入相反。

### 解析二：为什么只改一个比较符就能修复？

改为 `<=` 后，对任意 $i<j$：

- 当 $a[i]<a[j]$ 时，较大元素 $a[j]$ 的计数增加。
- 当 $a[i]>a[j]$ 时，较大元素 $a[i]$ 的计数增加。
- **当 $a[i]=a[j]$ 时，较晚出现的 $a[j]$ 的计数增加**，即原先的顺序被保留下来。

因此稳定版实际上按有序对 $(a[i],i)$ 的**字典序**决定先后。对任一记录 $i$，其目标名次恰为

$$
\operatorname{rank}(i)
=\#\{j:a[j]<a[i]\}
 +\#\{j<i:a[j]=a[i]\}.
$$

不同记录的有序对不可能相等，所以所有目标名次恰好覆盖 $0,1,\ldots,n-1$，每个输出位置只会写一次；不会发生重叠写入或空洞。对于本例，稳定版 `count={4,0,5,1,2,3}`。

```c
#include <stdlib.h>
#include <stddef.h>

/* 0：失败；1：成功。要求 b 与 a 的存储区间不重叠。 */
int StableRankSort(const int a[], int b[], size_t n) {
    if (n == 0) return 1;
    if (a == NULL || b == NULL) return 0;
    int *rank = (int *)calloc(n, sizeof *rank);
    if (rank == NULL) return 0;

    for (size_t i = 0; i < n; ++i) {
        for (size_t j = i + 1; j < n; ++j) {
            if (a[i] <= a[j]) ++rank[j]; /* 相等时后出现者靠后 */
            else ++rank[i];
        }
    }
    for (size_t i = 0; i < n; ++i) b[rank[i]] = a[i];
    free(rank);
    return 1;
}
```

<Callout type="warn" title="稳定性≠最终关键字数值有序">

排序稳定性的定义是：**关键字相等的两条不同记录，排序后仍保持原先后关系**。题目仅展示 `int` 时，两个相同的 `25` 看起来完全一样；判断稳定性必须引入原始下标或其他身份标记。若将 `b` 直接指向 `a`，此实现还可能覆盖未读取的值，不能直接称为原地排序。

</Callout>

### 比较次数与复杂度

双层循环无论输入已排序、逆序或大量重复，都枚举所有 $i<j$，次数固定为 $\binom n2$，故最好、平均、最坏均为 $\Theta(n^2)$；初始化 `count` 和写 `b` 各为 $\Theta(n)$。作为实现本身，`count` 需要 $n$ 个整数，额外存储为 $\Theta(n)$；若将调用者提供的输出数组一并计入，则总共涉及两个长度 $n$ 的额外区域。

**考场答题重点：** 先写 `count`，再写 `b`；比较次数用组合数；最小修改只需把严格小于改成小于等于，并用相等关键字的原下标说明稳定性。

### 原创预测题 1｜三组重复关键字，能否不用排序算出稳定名次？

给定带身份的记录序列（括号内依次为关键字、记录编号）：

$$
[(5,A),(2,B),(5,C),(3,D),(5,E),(2,F)].
$$


1. 用原真题的 `<` 分支求 `count[0..5]`，给出输出记录序列。
2. 改用 `<=` 后重新计算 `count` 与输出记录序列。
3. 用数学表达式写出稳定名次，不借助完整两重循环说明它为何不会出现重复下标，并分析时间与空间复杂度。

<Solution>

### 参考答案

| 模式 | 按原输入位置的名次数组 `count` | 输出记录身份顺序 |
| --- | --- | --- |
| 原版 `<` | `[5,1,4,2,3,0]` | `F,B,D,E,C,A` |
| 稳定版 `<=` | `[3,0,4,2,5,1]` | `B,F,D,A,C,E` |

两个版本的关键字序列都为 $[2,2,3,5,5,5]$，但**原版将每组相等关键字的相对次序翻转**。

### 推导

对于原版，每一组相同关键字会被逆序排列：`2` 组是 $F,B$，`5` 组是 $E,C,A$。严格小于当前关键字的记录仍排在该组之前。因此从小到大写出全部身份为 $F,B,D,E,C,A$，其逆置映射给出原下标 $0$ 至 $5$ 的目标位置 $[5,1,4,2,3,0]$。

稳定版要让相等关键字按**原始下标从小到大**排列，直接得到 $B,F,D,A,C,E$，对应 `count=[3,0,4,2,5,1]`。

更本质的秩公式为

$$
\boxed{r_i=\sum_{j=0}^{n-1}[a_j<a_i]+\sum_{j=0}^{i-1}[a_j=a_i]},
$$

其中 $[P]$ 为条件 $P$ 成立时取 $1$、否则取 $0$ 的指示函数。第一项是全部更小关键字的数量；第二项是当前关键字**在相同关键字内部的先后位次**。它等价于对 $(a_i,i)$ 的字典序求秩，故严格全序下名次必然互不重复。

若逐条独立按公式统计，复杂度为 $O(n^2)$ 时间、$O(n)$ 名次存储；原真题的两两比较也达到相同量级，但只对每一对下标比较一次，常数因子通常更小。

<Callout type="tip" title="判断排序稳定性的最短路径">

不要只检验最终数字是否升序。将相等键标上 `A/B/C`，比较排序前后的身份先后关系，这比凭印象判断“算法名称是否稳定”更可靠。

</Callout>

### 原创预测题 2｜输出数组别名与线性时间稳定替代方案

某同学把稳定版 `cmpCountSort(a,b,n)` 的调用写为 `cmpCountSort(a,a,n)`，认为“目标名次互不重复，所以原地写回也不会出错”。现给数组 $a=[3,1,2]$。

1. 按原真题的**稳定版**算出名次，并模拟 `b[count[i]]=a[i]` 在 `b==a` 时实际写回的每一步，判断其结论是否正确。
2. 若关键字范围已知为 $0\sim U-1$，且每条记录有必须保留的身份，设计**真正 $O(n+U)$ 时间的稳定计数排序**（允许独立输出数组），说明为什么要从右往左放置记录。
3. 明确两种算法的时间与额外空间差异，并说明无已知紧凑值域时不能直接使用此线性计数方案。

<Solution>

### 参考答案

1. 稳定名次为 `count=[2,0,1]`。若 `b==a`，按 $i=0,1,2$ 写：第 0 步 `a[2]=a[0]=3`，数组变为 `[3,1,3]`；第 1 步 `a[0]=a[1]=1`，变为 `[1,1,3]`；第 2 步写 `a[1]=a[2]=3`，最终错误地得到 **`[1,3,3]`**，而不是 `[1,2,3]`。所以不能共享同一存储区间。
2. 用频数数组 `cnt[0..U-1]` 和前缀和确定每种键在输出中的右边界，**从右向左扫描原记录**；每放入一条记录便减少相应键的剩余末端下标，保证同关键字中靠后的记录先占靠后位置。
3. 比较计数排序：$\Theta(n^2)$ 时间、$\Theta(n)$ 工作名次；值域计数排序：$\Theta(n+U)$ 时间、$\Theta(n+U)$ 总额外存储（包括独立的输出数组）。若 $U$ 很大或关键字没有可直接寻址的整数范围，空间与初始化代价可能不可接受。

### 完整的记录版 C 实现

```c
#include <stdlib.h>

typedef struct {
    int key;
    int originalId;
} Record;

/* 要求 n>0、U>0，且 0<=in[i].key<U；in 与 out 不重叠。 */
int StableValueCountSort(const Record in[], Record out[], int n, int U) {
    if (!in || !out || n <= 0 || U <= 0) return 0;
    int *end = (int *)calloc((size_t)U, sizeof *end);
    if (!end) return 0;

    for (int i = 0; i < n; ++i) ++end[in[i].key];
    for (int x = 1; x < U; ++x) end[x] += end[x - 1];

    /* end[key]：该关键字的“当前未占用区间右端后一位”。 */
    for (int i = n - 1; i >= 0; --i) {
        int key = in[i].key;
        int target = --end[key];
        out[target] = in[i];
    }
    free(end);
    return 1;
}
```

### 为什么从右往左稳定？

在某一关键字的输出区间内，前缀和使 `end[key]` 初始指向该区间之后。对于两条相等关键字的记录 $i<j$，逆序扫描必先处理 $j$，把它放到该区间当前最右空位；随后处理 $i$，后者被放到更左边。所以输出中仍是 $i$ 在 $j$ 前。

<Callout type="warn" title="区别两种“计数排序”">

原真题的 `count[i]` 是**第 $i$ 条记录的名次**，必须比较元素对；此变式的 `end[x]` 是**值为 $x$ 的记录所属区间的边界**，其线性效率来自已知且可直接寻址的关键字范围。不要把它们当成同一种算法。

</Callout>

</Solution>

## 2022 年第 42 题

<Question
  id="408-ds-large-2022-42"
  type="essay"
  tags="来源:2022考研408, 科目:数据结构, 章节:排序, 考点:TopK问题, 考点:大根堆, 难度:中等"
>

现有 $n$ 个数保存在一维数组 $M$ 中，其中 $n>100000$。需要找出其中**最小的 $10$ 个数**。

要求：

1. 设计一种平均情况下比较次数尽可能少的算法；**只需描述算法思想，不要求编写程序**。
2. 给出算法在平均情况下的时间复杂度及空间复杂度。

<Solution>

### 参考答案

采用**容量固定为 10 的大根堆**维护当前最小的十个数：

1. 将前 $10$ 个数建立大根堆，其堆顶是当前十个候选中的**最大值**。
2. 对 $M[10],M[11],\ldots,M[n-1]$ 顺序扫描。若新数 $x\ge$ 堆顶，则它不比当前第十小的值更优，直接丢弃；若 $x<$ 堆顶，则用 $x$ 替换堆顶并向下调整恢复大根堆性质。
3. 扫描完毕，堆内恰为整个数组最小的十个数，**无需对这十个数再排序**。

建堆成本为 $O(10)$，每读一个新数先比较堆顶，只有触发替换时再执行 $O(\log10)$ 的堆调整；因此**平均及最坏总时间为 $O(n\log10)=O(n)$**，额外空间 $O(10)=O(1)$（将 $10$ 视作题设固定常数）。本题不要求实现代码，仅准确描述规则和复杂度即可得分。

### 为什么一定用大根堆？

<Steps>
  <Step>

  **把原问题转化成在线维护门槛。** 当我们已保留十个候选时，候选中最大的那个就是第十小的阈值 $t$。新来的 $x\ge t$ 不应挤掉比自己更小的元素；只有 $x<t$ 才应替换阈值。

  </Step>
  <Step>

  **大根堆让阈值始终位于堆顶。** 读新数只需一次堆顶比较；替换后调用 `siftDown` 将更新后的值放到合法位置。若错误地使用**小根堆**，堆顶是最小候选，无法立即判断谁是应被淘汰的“最大候选”。

  </Step>
  <Step>

  **用不变式证明全局正确。** 处理完前 $t\ge10$ 个元素后，堆中是这 $t$ 个元素的最小十个（重复值按出现次数计）。新数 $x$ 不小于堆顶时，旧候选仍可构成最小十个；小于堆顶时，替换旧候选中最大的一个即可形成新前缀的最小十个。对 $t$ 归纳得到最终结论。

  </Step>
</Steps>

### 比较次数为什么通常很少？

对每个后续元素，至少执行一次“与堆顶比较”；但绝大多数足够大的新元素无需参与堆内下沉。如果输入次序看作从 $n$ 个**不同值**中均匀随机排列，那么读入第 $t$ 个元素（$t>10$）时，它挤入当前前十的概率恰为 $10/t$。因而期望堆顶替换次数为

$$
\mathbb E[R]=\sum_{t=11}^{n}\frac{10}{t}
=10(H_n-H_{10})=O(10\log(n/10)).
$$

于是固定容量堆的期望比较成本接近 $n-10$ 次堆顶比较，再加少量 $O(\log10)$ 的下沉调整。这个分析依赖随机输入顺序，不能在任意特定输入上把上述期望替换次数当作确定次数；它也**不意味着已经证明大根堆具有所有比较模型下最小的精确常数**。

### 如需要实现：一个可核验的参考程序

以下仅用于理解算法，原题只要求设计思想。`heap` 是**额外的十个元素空间**，不修改输入数组。

```c
#include <stddef.h>

static void SiftDownMax(int h[], int size, int i) {
    while (2 * i + 1 < size) {
        int child = 2 * i + 1;
        if (child + 1 < size && h[child + 1] > h[child]) ++child;
        if (h[i] >= h[child]) break;
        int tmp = h[i]; h[i] = h[child]; h[child] = tmp;
        i = child;
    }
}

/* 要求 n>=10、M与heap非空，输出为无序的10个最小值。 */
void SmallestTen(const int M[], int n, int heap[10]) {
    for (int i = 0; i < 10; ++i) heap[i] = M[i];
    for (int i = 10 / 2 - 1; i >= 0; --i)
        SiftDownMax(heap, 10, i);

    for (int i = 10; i < n; ++i) {
        if (M[i] >= heap[0]) continue;
        heap[0] = M[i];
        SiftDownMax(heap, 10, 0);
    }
}
```

### 复杂度和方案选择

| 方法 | 时间复杂度 | 额外空间 | 是否可单遍在线处理 | 适用限制 |
| --- | --- | --- | --- | --- |
| 长度 10 大根堆 | 最坏 $O(n\log10)=O(n)$ | $O(10)$ | 是 | 不要求候选有序 |
| 整数组排序 | 比较排序一般 $O(n\log n)$ | 视实现而定 | 否 | 获得了本题不需要的完整顺序 |
| 逐次扫描求最小值十遍 | $O(10n)=O(n)$ | 可 $O(1)$ | 否 | 重复完整扫描，比较次数较多 |
| Quickselect | 期望 $O(n)$，常见实现最坏 $O(n^2)$ | 迭代原地版 $O(1)$ | 否 | 需可修改并随机访问全部数据 |

<Callout type="tip" title="从固定 10 推广到变量 k 时，空间结论必须改写">

若要求最小 $k$ 个数，则维护容量 $k$ 的大根堆，最坏时间为 $O(n\log(k+1))$、额外空间 $O(k)$。只有在本题 $k=10$ 固定的情况下，才能写空间 $O(1)$。如需输出升序十个数，可另对堆中的十个元素排序，但这是题目没有要求的附加工作。

/* 返回 a 是否比 b 更差：用于大根堆把最差者放在根 */
static bool Worse(Item a, Item b) {

           (a.key == b.key && a.index > b.index);

/* 堆已满时，仅当新记录“优于”根结点才替换 */

### 原创预测题 2｜离线选取：为什么 Quickselect 不适合流式 TopK？

原题改为：所有 $n$ 个元素都已经在**可修改的数组**中，允许改变元素原始顺序，只需将最小的 $k$ 个数放在数组前 $k$ 个位置、前后两部分**内部均无需排序**。$1\le k\le n$，关键字可能大量重复。

1. 使用三路划分 Quickselect 实现，说明停止条件。为什么简单的二路划分处理全部相等的输入可能退化？
2. 给出具有期望 $O(n)$ 时间和 $O(1)$ 额外空间的算法框架，并说明最坏复杂度。
3. 对比原题的大根堆：当输入变成无法回退的网络流，并要求随时查询最小 $k$ 个数时，应该选择哪种方案？

<Solution>

### 参考答案

离线可使用**随机枢轴的三路 Quickselect**：把当前区间划为严格小于枢轴、等于枢轴、严格大于枢轴三块，依据分界下标只进入**包含第 $k$ 小边界**的那一块；当数组下标 $k$ 落在两块的边界或相等块之内时即可结束。期望时间 $O(n)$，最坏 $O(n^2)$，迭代版本额外空间 $O(1)$。

### 可运行的 C 实现

```c
#include <stdlib.h>

static void SwapInt(int *x, int *y) {
    int temp = *x; *x = *y; *y = temp;
}

/* 结束后 A[0..k-1] 是全局最小的 k 个数，内部无序。
   前提：0<=k<=n、A有效；如需随机化，可由调用者先执行 srand。 */
void SelectSmallestK(int A[], int n, int k) {
    if (A == NULL || n <= 1 || k <= 0 || k >= n) return;
    int l = 0, r = n - 1;
    while (l <= r) {
        int pivot = A[l + rand() % (r - l + 1)];
        int lt = l, i = l, gt = r;
        while (i <= gt) {
            if (A[i] < pivot) SwapInt(&A[lt++], &A[i++]);
            else if (A[i] > pivot) SwapInt(&A[i], &A[gt--]);
            else ++i;
        }
        /* < pivot 在 [l,lt)，== pivot 在 [lt,gt] */
        if (k < lt) r = lt - 1;
        else if (k > gt + 1) l = gt + 1;
        else break;  /* 恰好边界或落在等值段：前 k 个已确定 */
    }
}
```

### 证明“分界正确”的关键

每轮结束时，小于枢轴的元素都在等值区左侧，大于枢轴的都在右侧。若 $k<lt$，前 $k$ 个必属于更小值区域，可丢弃其余；若 $k>gt+1$，小于和等于枢轴的全部属于前 $k$，只需要在右侧继续挑选；若 $lt\le k\le gt+1$，直接取前 $k$ 个便满足目标。

**大量重复元素**（尤其全部相等）时，三路划分可以一次处理完相等区间，而不用反复围绕同一个数执行近乎无收益的二路分区。随机枢轴带来平均线性复杂度，但最坏仍可能多次极端不平衡；若要求**确定性最坏 $O(n)$**，可采用中位数的中位数（BFPRT）选枢轴，代价是更高的实现与比较常数。

<Callout type="info" title="选择算法先看数据使用方式">

大根堆适合**无法回看历史记录的在线场景**，每步都保有当前最优候选，空间 $O(k)$；Quickselect 依赖已经完整持有、可随机访问且可改变的数组，是**离线选择**，不会自动提供每次读入之后的正确 TopK。两者同为选择算法，使用前提不同。

</Callout>

</Solution>
</Question>

## 2023 年第 42 题

<Question
  id="408-ds-large-2023-42"
  type="essay"
  tags="来源:2023考研408, 科目:数据结构, 章节:排序, 考点:置换选择, 考点:初始归并段, 难度:综合"
>

在对含 $n$ 条记录的文件进行外部排序时，采用**置换—选择排序**生成初始归并段。可使用一个容量至多保存 $m$ 条记录的工作区。

1. 若 $n=19$，记录按下列关键字顺序到达，工作区容量 $m=4$，问会生成**几个初始归并段**？分别写出每段的关键字。

   $$
   51,94,37,92,14,63,15,99,48,56,23,60,31,17,43,8,90,166,100.
   $$


2. 对任意 $n>m>0$，第一段长度可能达到的**最大值和最小值**分别是多少？请说明理由。

<Solution>

### 参考答案

共生成 **$\boxed{3}$ 个**初始归并段：

$$
\begin{aligned}
R_1&=(37,51,63,92,94,99),\\
R_2&=(14,15,23,31,48,56,60,90,166),\\
R_3&=(8,17,43,100).
\end{aligned}
$$

三段长度分别为 $6,9,4$，相加为 $19$，与原文件记录数一致。一般情况下，第一段长度满足

$$
\boxed{m\le |R_1|\le n},
$$


且下界 $m$ 与上界 $n$ **都能取到**。

### 原理：活动记录、冻结记录与读入指针

置换—选择排序的核心并不是“取 $m$ 个数排好、输出一段，然后再取下一批”。它允许输出一个值之后立即补充输入记录，因而一段**完全可以超过 $m$**。

<Steps>
  <Step>

  **初始填满工作区。** 第一次装入 $51,94,37,92$，它们全是当前归并段的**活动记录**。工作区内选出最小活动键 $37$ 并输出，把下一条输入 $14$ 补入刚腾出的位置。

  </Step>
  <Step>

  **补入数与刚输出数比较。** 若读入 $x\ge y$（刚输出为 $y$），仍可以放在当前非递减归并段后面，保持活动；若 $x<y$，则 $x$ 不可能进入本段，必须标记为**冻结**，留到下一段。被冻结的数仍占着工作区位置，不允许在本段继续被选择。

  </Step>
  <Step>

  **只在全部活动记录耗尽时结束本段。** 下一段开始时解冻所有记录，重新以最小活动记录开头。若磁盘输入已耗尽，则剩下的活动记录继续依次输出，直至工作区清空。输出中的段内顺序非递减，但**不同段之间不必有序**。

  </Step>
</Steps>

### 第 1 段：逐步跟踪

初始活动集为 $\{37,51,92,94\}$。

| 本次输出 | 新读入 | 是否可加入本段？ | 该步结束后的活动记录 |
| ---: | ---: | --- | --- |
| 37 | 14 | 否，$14<37$，冻结 | $51,92,94$ |
| 51 | 63 | 是，$63\ge51$ | $63,92,94$ |
| 63 | 15 | 否，冻结 | $92,94$ |
| 92 | 99 | 是 | $94,99$ |
| 94 | 48 | 否，冻结 | $99$ |
| 99 | 56 | 否，冻结 | 无，结束第 1 段 |

故

$$
R_1=(37,51,63,92,94,99).
$$


本段结束时冻结集合为 $\{14,15,48,56\}$，重新激活作为下一段的工作区；磁盘上下一条尚未读入的是 $23$。

### 第 2 段：重新激活冻结记录

| 本次输出 | 新读入 | 处理 | 该步结束后的活动记录 |
| ---: | ---: | --- | --- |
| 14 | 23 | 激活 | $15,23,48,56$ |
| 15 | 60 | 激活 | $23,48,56,60$ |
| 23 | 31 | 激活 | $31,48,56,60$ |
| 31 | 17 | 冻结 | $48,56,60$ |
| 48 | 43 | 冻结 | $56,60$ |
| 56 | 8 | 冻结 | $60$ |
| 60 | 90 | 激活 | $90$ |
| 90 | 166 | 激活 | $166$ |
| 166 | 100 | 冻结 | 无，结束第 2 段 |

故

$$
R_2=(14,15,23,31,48,56,60,90,166).
$$


这一段输出 $9$ 条记录，是工作区容量的两倍多；该例直接说明**不能按 $\lceil n/m\rceil$ 来确定归并段数**。

### 第 3 段和全过程验算

此时输入读取完毕，只剩冻结的 $17,43,8,100$。重新激活，按升序输出得到

$$
R_3=(8,17,43,100).
$$


检查：

- 每段内部都是非递减序列，跨段则不作有序性要求；
- 共有 $6+9+4=19$ 条记录，**无重复输出、无漏读**；
- 工作区始终至多占用 $4$ 条记录，冻结记录不是存到另一个无限大小的内存区。

### 首段长度上下界的严格证明

**下界 $m$。** 初始装入的 $m$ 条记录都属于第 1 段，因为它们均在第一次输出之前已经入工作区，且没有任何已输出值迫使它们冻结。以后从输入补入的记录可以被冻结，但初始 $m$ 条最终都会在第 1 段输出。故 $|R_1|\ge m$。

**上界 $n$。** 任何记录最多输出一次、共有 $n$ 条，故 $|R_1|\le n$。若输入序列严格递增，则新补入的值总大于刚输出值，没有冻结，第一段就包含全部 $n$ 条，达到 $n$。

**下界可达到。** 若输入严格递减，初始 $m$ 条构成活动集；在这 $m$ 条被输出时，随后读入的值均小于对应的输出值，因此全部被冻结。第一段恰有最初 $m$ 条，达到 $m$。

<Callout type="warn" title="三类常见错法">

1. **把新记录与“工作区最小值”比较：** 错。判冻结的基准是**刚输出的最后一个键**，以确保当前归并段非递减。
2. **把冻结记录立即丢弃：** 错。它仍占工作区，下一段还要恢复；否则记录总数守恒会失败。
3. **把相等数冻结：** 错。只要 $x=y$ 就仍可留在本段，因归并段允许非递减，而不要求严格递增。

</Callout>

### 复杂度及外部排序关系

借助能够区分“本段活动/已冻结”的选择树或堆，可以在工作区内以 $O(\log m)$ 代价选择并替换记录，生成初始归并段的整体时间为 $O(n\log m)$，工作区 $O(m)$。生成段之后再做多路归并；初始归并段长通常超过 $m$，能减少段数与归并趟数，但**真正的段长取决于输入排列**，不能保证固定为 $2m$。

</Solution>
</Question>

### 原创预测题 1｜同值能否留在本段？完整模拟冻结与解冻

工作区容量 $m=3$，文件的关键字按下列顺序依次输入：

$$
[4,4,3,4,2,5,1,5,0].
$$


1. 给出置换—选择排序的全部初始归并段及其长度。
2. 写出**第一段**逐次输出、新读入及冻结情况，特别说明读入的 $4$、$5$ 与刚输出值相等时如何处理。
3. 若错误地把冻结条件改为“新数小于或等于刚输出值”，会破坏哪一条规则？给出本输入上可能出现的差异。

<Solution>

### 参考答案

正确的冻结条件为 $x<y$，其中 $y$ 是本段最近一次输出的键。按此规则生成

$$
\boxed{R_1=(3,4,4,4,5,5),\qquad R_2=(0,1,2)}.
$$


共有 $2$ 段，长度 $6,3$。第一段结束时冻结的记录恰为 $2,1,0$，输入也已经全部读取；第二段解冻后直接输出 $0,1,2$。

### 第一段模拟

| 输出 $y$ | 新读入 $x$ | 处理 | 当前活动记录（排序展示） |
| ---: | ---: | --- | --- |
| 3 | 4 | $4\ge3$，加入当前段 | $4,4,4$ |
| 4 | 2 | $2<4$，冻结 | $4,4$ |
| 4 | 5 | $5\ge4$，加入当前段 | $4,5$ |
| 4 | 1 | $1<4$，冻结 | $5$ |
| 5 | 5 | **相等，仍激活** | $5$ |
| 5 | 0 | $0<5$，冻结 | 无，结束本段 |

在记录值相等的情形，非递减排序允许连续输出两个 `5`；若把 `x<=y` 都冻结，则第 5 步读入的 `5` 会被错误地推迟到下一段：本来属于第一段的后一个 `5` 无法继续参加本段，第一段变短，而且可能增加段数。更重要的是，这种改动使算法不再遵守“所有可合法续接本段的记录都保留活动资格”的标准置换—选择策略。

### 证明与检查

冻结记录只能在下一个归并段重新参与最小值选择。每条输入记录在其进入工作区后，始终处于“活动”或“冻结”之一；每次输出从当前活动集中删除恰好一条，并读取至多一条新记录。运行至所有记录输出，总数必是 $n=9$。最终 $6+3=9$，两段均有序。

每步只做三件事：**取当前活动最小值、读下一条、与刚输出值比较并标注活动/冻结**。把被冻结的数用单独记号列在表格旁，待活动集空时再全部解冻，不会串段。

</Callout>

### 原创预测题 2｜置换—选择之后，如何安排归并才能减少磁盘写入？

沿用本题生成的 $3$ 个初始归并段，长度分别为 $6,9,4$。假定只能执行**二路归并**，每次把两个非空有序段归并生成一个新段，并将新段的所有记录各写入一次；暂不计归并读取及最终文件的重复保存费用。

1. 为使归并过程中写入的总记录数最少，应如何安排两个归并轮次？计算最少写入次数。
2. 若先归并长度 $6,9$ 的两段，再与长度 $4$ 的段归并，写入次数是多少？比最佳方案多多少？
3. 为什么“初始归并段个数越少”与“归并阶段总写入量尽可能少”是相关但不同的问题？对于 $r$ 个归并段，给出具有复杂度保证的最佳二路合并调度方法。

<Solution>

### 参考答案

1. 应先合并**最短两段**：$4+6=10$，再把新段 $10$ 与余下长度 $9$ 的段合并为 $19$。累计写入次数

   $$
   \boxed{10+19=29}.
   $$


2. 错误次序：$6+9=15$，然后 $15+4=19$，写入量为 $15+19=34$，比最优方案多 $\boxed{5}$ 条记录的写入。
3. 对任意 $r$ 个不等长归并段，把段长作为最小堆中的权值，反复弹出**当前最小的两段**，归并后按新长度重新入堆，直至只剩一个段。这是哈夫曼式最优二路归并调度；调度本身需 $O(r\log r)$ 时间、$O(r)$ 堆空间。

### 为什么先并短段？

归并树每个叶子的权值是初始归并段长 $w_i$，深度 $d_i$ 等于该段的记录在后续归并中会被**重复写入的次数**，所以全部归并生成的新段写入总次数为

$$
W=\sum_{i=1}^{r}w_i d_i.
$$


在本题的最优树中，长度 $4$ 与 $6$ 的段深度都为 $2$，长度 $9$ 的段深度为 $1$，故

$$
W=4\times2+6\times2+9\times1=29.
$$


如果过早把长段 $9$ 与 $6$ 合并，长度 $9$ 的记录就会参与两次合并，重复写入更多，造成 $34$ 次写入。哈夫曼的交换论证指出，可以在某棵最优归并树中让两个最小权值成为最深层的一对兄弟，将它们合并后递归处理余下问题，因此每轮贪心取两最短段是安全的。

<Callout type="info" title="区分置换—选择与最优归并树的两个优化阶段">

**置换—选择**利用 $m$ 个工作区记录尽量产生较长的初始有序段，减少初始段数；**最优二路归并**针对已经产生的段长，决定哪些段应更早合并，以减少累计重复读写。两者优化对象不同，可以连续使用。若允许真正的三路及更高路归并，还必须重新考虑可用缓冲区、归并器路数与每轮的 I/O 代价，不能直接把二路公式照搬过去。

</Callout>
