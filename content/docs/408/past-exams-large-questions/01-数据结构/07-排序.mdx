<span id="question-2016-43" />

## 2016 年第 43 题

<ExamQuestion>

**16. 2016 年第 43 题**

已知由 $n\;(n\ge 2)$ 个正整数构成的集合

$$
A=\{a_k\mid 0\le k<n\}.
$$

将其划分为两个不相交的子集 $A_1$ 和 $A_2$，元素个数分别为 $n_1$ 和 $n_2$，元素之和分别为 $S_1$ 和 $S_2$。

设计一个尽可能高效的划分算法，使

$$
|n_1-n_2|
$$

最小，并在此基础上使

$$
|S_1-S_2|
$$

最大。

要求：

1. 给出算法的基本设计思想；
2. 用 C 或 C++ 描述算法；
3. 说明时间复杂度和空间复杂度。

<ExamSolution>

<ExamAnswer>

令 $k=\lfloor n/2\rfloor$。把集合中最小的 $k$ 个元素放入 $A_1$，其余 $n-k$ 个放入 $A_2$，即可先保证 $|n_1-n_2|$ 最小，再保证 $|S_1-S_2|$ 最大。用原地 Quickselect 定位第 $k$ 个元素，**平均时间 $O(n)$，最坏时间 $O(n^2)$，额外空间 $O(1)$（迭代版本）**。

</ExamAnswer>

<ExamExplanation>

### 一、两级优化目标必须按题目先后顺序处理

目标不是最小化和之差，而是**先让人数/元素数尽量接近，再让和之差尽量大**。设 $n_1+n_2=n$，则首先要求

$$
|n_1-n_2|\text{ 最小}\quad\Rightarrow\quad\{n_1,n_2\}=\left\{\left\lfloor\frac n2\right\rfloor,\left\lceil\frac n2\right\rceil\right\}.
$$

由于所有元素都是**正整数**，可不失一般性地让较小的 $k=\lfloor n/2\rfloor$ 个组成 $A_1$，剩下组成 $A_2$。这种划分使 $S_2>S_1$：当 $n$ 为偶数时有 $n/2$ 个大数与同数目的小数配对，每对大数均不小于小数；奇数时 $A_2$ 还额外有一个正数。因此最大化 $|S_2-S_1|$ 等价于最小化 $S_1$（总和固定）：

$$
S_2-S_1=S-2S_1.
$$

选出全体中最小的 $k$ 个元素，是使 $S_1$ 最小的必要充分方法（相等元素可任意选取）。**交换论证**：若 $A_1$ 含有一个大于 $A_2$ 中元素的值，交换二者能减小 $S_1$、增大 $S_2$，目标不变差，故最终大小两组必构成排序后的前 $k$ 与后 $n-k$ 个。

### 二、无需排序全部元素：原地快速选择

若完全排序，时间 $O(n\log n)$。实际上只需要确定“第 $k+1$ 小元素”的分界位置，把较小 $k$ 个放左边；不要求每组内部有序。因此使用 `partition` 把枢轴安放到最终位置，再仅对包含目标下标 $k$ 的一侧继续。

```c
#include <stddef.h>

static int split(int a[], int left, int right) {
    int pivot = a[left];
    int i = left, j = right;
    while (i < j) {
        while (i < j && a[j] >= pivot) --j;
        a[i] = a[j];
        while (i < j && a[i] <= pivot) ++i;
        a[j] = a[i];
    }
    a[i] = pivot;
    return i;
}

static void quickSelectK(int a[], int n, int k) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int p = split(a, left, right);
        if (p == k) return;
        if (p < k) left = p + 1;
        else right = p - 1;
    }
}

long long maxSumDifference(int a[], int n) {
    if (a == NULL || n < 2) return -1; // 不满足题设
    int k = n / 2;
    quickSelectK(a, n, k);
    long long loSum = 0, hiSum = 0;
    for (int i = 0; i < k; ++i) loSum += a[i];
    for (int i = k; i < n; ++i) hiSum += a[i];
    return hiSum - loSum;
}
```

输入 $a$ 在原地改变顺序，输出仅为最优差值；如需输出两个子集，划分后的区间 `$a[0..k-1]` 和 `$a[k..n-1]` 就是所求。使用 `long long` 存储和，避免 $n$ 个较大的 `int` 累加到 `int` 溢出。

### 三、复杂度要区分“平均”和“最坏”

一次 `split` 花费 $O(n)$，典型情况下后续只处理较短或较长的**一侧**，规模不断缩小，平均代价

$$
T(n)=n+\frac n2+\frac n4+\cdots=O(n).
$$

最坏情况是每次枢轴都偏向一端：$T(n)=n+(n-1)+\cdots+1=O(n^2)$。上述实现是迭代版，没有递归调用栈，除原数组外只使用常数个标量，故额外空间为 $O(1)$。如题目要求**严格最坏线性时间**，可选用中位数的中位数（BFPRT）保证枢轴质量；算法更复杂，不必在只求平均高效时强行使用。

### 四、样例、变式与坑点

对 $\{1,2,7,10,12\}$，$k=2$，$A_1=\{1,2\}$、$A_2=\{7,10,12\}$，两组元素数差 1，和差 $29-3=26$。不能用“让两组和尽量接近”的常见背包分组思路，目标刚好相反。

**正数条件很关键**：若元素允许负数且 $n$ 为奇数，“把最小 $k$ 个放小组”不一定最大化绝对和差；此时需要同时比较小组取最小 $k$ 个与最大 $k$ 个两种极端方案，见[原创题](#question-original-159)。若含重复值，划分可不唯一，但最大差值仍确定。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

现有五个整数 $[-100,-99,1,2,3]$，不再保证为正数。要求两组均非空：

1. 给出满足最优目标的划分及最大 $|S_1-S_2|$。
2. 证明对一般 $n\ge2$ 的整数集合，令 $k=\lfloor n/2\rfloor$，只比较**最小 $k$ 个**和**最大 $k$ 个**构成的小组，就能选出最优方案；
3. 给出 $O(n\log n)$ 的直接实现思路，并说明如何用选择算法进一步降低平均时间复杂度。

<ExamSolution>

<ExamAnswer>该例应取小组 $\{-100,-99\}$、大组 $\{1,2,3\}$，两组和为 $-199$ 与 6，绝对差为 **205**；若改成 $[-100,-99,1]$，最优小组反而选最大值 $\{1\}$。一般情形将组大小固定为 $k$ 后，分别比较该 $k$ 个元素之和的最小值与最大值对应的绝对差即可。排序实现 $O(n\log n)$ 时间；用两次选择算法可达平均 $O(n)$ 时间。</ExamAnswer>

<ExamExplanation>

令总和 $S=\sum_{i=1}^n a_i$，任取一个含 $k$ 个元素的小组，其和为 $x$，另一组和为 $S-x$，目标

$$
|S_1-S_2|=|x-(S-x)|=\boxed{|2x-S|}.
$$

在所有容量为 $k$ 的子集中，$x$ 的最小值为排序后前 $k$ 个的和 $x_{min}$；最大值为后 $k$ 个的和 $x_{max}$。函数 $f(x)=|2x-S|$ 是凸函数，在区间 $[x_{min},x_{max}]$ 内最大值必能在端点之一取得，所以只需计算

$$
\boxed{\max\bigl(|2x_{min}-S|,\ |2x_{max}-S|\bigr)}.
$$

本题排序为 $[-100,-99,1,2,3]$，$k=2$，$S=-193$。取最小两数时 $x_{min}=-199$，得到 $|-398+193|=205$；取最大两数 $x_{max}=5$，得到 $|10+193|=203$，故最大值 **205**。用 $[-100,-99,1]$ 则 $k=1$，$S=-198$，取最小值 $-100$ 得 $|-200+198|=2$，取最大值 $1$ 得 $|2+198|=200$；因此原题正数前提不可忽略。

直接实现：先排序，累计总和、前 $k$ 个及后 $k$ 个之和，比较两个目标即可，排序复杂度 $O(n\log n)$；若可原地修改数组，选用原地排序的额外空间取决于具体排序算法。对大规模输入，不必完全排序：两次原地选择分别划出最小、最大 $k$ 个并累计（或使用额外数组保护原数据），通常平均 $O(n)$，但必须说明选择算法的最坏界和可能改动原数组。计算 $2x-S$ 时建议以至少 64 位宽度存储和，数据范围更大时需检查 64 位是否足够。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2021 年第 42 题

<ExamQuestion>

**26. 2021 年第 42 题**

已知某排序算法如下：

```c
void cmpCountSort(int a[], int b[], int n)
{
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n);

    for (i = 0; i < n; i++)
        count[i] = 0;

    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j])
                count[j]++;
            else
                count[i]++;

    for (i = 0; i < n; i++)
        b[count[i]] = a[i];

    free(count);
}
```

请回答：

1. 若

```c
int a[] = {25, -10, 25, 10, 11, 19};
int b[6];
```

调用 `cmpCountSort(a, b, 6)` 后，数组 `b` 中的内容是什么？
2. 若 `a` 中含有 $n$ 个元素，则算法执行过程中元素之间的比较次数是多少？
3. 该算法是否稳定？若稳定，说明理由；若不稳定，将其修改为稳定排序算法。

<ExamSolution>

<ExamAnswer>

输出 `b` 为 `{-10, 10, 11, 19, 25, 25}`；元素之间总比较次数恰为 $n(n-1)/2$；原算法**不稳定**。将判断条件 `if (a[i] < a[j])` 改为 **`if (a[i] <= a[j])`**，使相等元素中后出现者的 `count` 增大，就变成稳定排序。时间复杂度 $\Theta(n^2)$，空间复杂度 $\Theta(n)$。

</ExamAnswer>

<ExamExplanation>

### 一、识别算法：比较计数排序（不是按键值范围统计的 Counting Sort）

两层循环对原数组下标 $i<j$ 的每一**无序位置对**只比较一次，并将 `count` 加在“应排在后面”的那个元素上。最终 `count[i]` 正好是元素 `a[i]` 在结果数组里的秩/下标（从 0 起）。由此无需交换 `a` 的元素，直接写 `b[count[i]]=a[i]`。

对于给定数组，逐对计算得到：

| 原下标 $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| $a[i]$ | 25 | -10 | 25 | 10 | 11 | 19 |
| 原代码 `count[i]` | 5 | 0 | 4 | 1 | 2 | 3 |

因此 `b[0..5]` 依次填入 $-10,10,11,19,25,25$。注意两个 25 在 `b` 中的**先后来源**被颠倒了：`a[2]` 占 `b[4]`，`a[0]` 占 `b[5]`。

### 二、严格计算次数：与输入是否有序完全无关

外层 $i$ 取 $0,1,\dots,n-2$，内层固定 $i$ 时迭代 $n-1-i$ 次：

$$
C(n)=\sum_{i=0}^{n-2}(n-1-i)=(n-1)+(n-2)+\cdots+1=\boxed{\frac{n(n-1)}2}.
$$

这个次数是**元素之间的关键字比较次数**，不包括循环条件判断、下标赋值，也不包括分配内存。无论输入本来排好序还是倒序，比较次数都不变，故最坏/最好/平均均为 $\Theta(n^2)$。`count` 需要 $n$ 个整数，`b` 也需要 $n$ 个输出位置；若把题设已给的输出数组视为必要输出，不再算入辅助空间，**额外 `count` 仍为 $\Theta(n)$**。

### 三、稳定性判断不要只看排完后“值是否有序”

稳定排序要求原来相等的关键字，排序后**对应记录的相对先后保持不变**。令两个 25 分别记为 $25_A$（下标 0）和 $25_C$（下标 2）。原条件 `a[i] < a[j]` 遇到相等值时为假，就给前者 `count[i]++`；因此 $25_A$ 被排到 $25_C$ 后，**不稳定**。两个键值相同看不出颠倒，必须用不同记录标记辅助判断。

将内层判断改成：

```c
if (a[i] <= a[j])
    count[j]++;           // 小于或等于：后者应排在后面
else
    count[i]++;           // 严格大于：前者应排在后面
```

改动后对相等的 $a[i]$、$a[j]$（$i<j$），把计数加给 $j$，保持先来的记录在前。更形式化地，稳定版本的 `count[i]` 恰为

$$
\#\{j\mid a[j]<a[i]\}+\#\{j<i\mid a[j]=a[i]\}.
$$

第一项是所有严格小于它的元素数，第二项是相等且比它早的元素数，于是不同记录的目标下标不会冲突，且排序稳定。**仅更改一处比较符号，无须更改写入数组的阶段。**

### 四、对比与延伸

- 比较计数排序用元素**两两比较**得到秩，时间 $O(n^2)$；通常所谓“计数排序”要求关键字范围适合数组统计，时间 $O(n+U)$、空间 $O(U)$，不是同一算法。
- 该算法比较次数固定，但即使改成稳定版，也不具有原地排序性质，因为它还用 `count` 和输出数组 `b`。
- 若题目扩展为“按成绩升序，成绩相同则保留原来输入顺序”，稳定性判断完全一样；把记录只当作裸整数值会掩盖稳定与否。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

输入四条记录 $(2,A),(1,B),(2,C),(1,D)$，其中整数为关键字，字母为原始记录标识。

1. 原 2021 年第 42 题的比较计数代码运行后，标识顺序是什么？稳定版本输出又是什么？
2. 分别写出四条记录的稳定版目标下标 `count[]`；
3. 证明对任意重复关键字，使用稳定规则不会有两条记录写入 `b` 的同一个下标，并分析复杂度。

<ExamSolution>

<ExamAnswer>原条件 `<` 得到 $(1,D),(1,B),(2,C),(2,A)$，不稳定；改为 `<=` 后得到 **$(1,B),(1,D),(2,A),(2,C)$**。稳定版各原记录的目标下标为 **$[2,0,3,1]$**，对应 `count[0..3]`。时间 $\Theta(n^2)$，额外 `count` 空间 $\Theta(n)$。</ExamAnswer>

<ExamExplanation>

稳定规则对任意一对位置 $i<j$：若 $a[i].key\le a[j].key$，说明 $i$ 记录应在 $j$ 前，让后者秩加 1；否则前者秩加 1。最终下标是按 **$(\text{key},\text{原始下标})$ 的字典序**排序的秩。

本题四条记录稳定版目标下标依次为 $[2,0,3,1]$：键为 1 的 $B,D$ 在前，其中 $B$ 原来比 $D$ 早；键为 2 的 $A,C$ 在后，其中 $A$ 比 $C$ 早。原版遇到相等时反转它们的顺序，所以输出 $D,B,C,A$（这里只列标识）。

为什么不会冲突？任取不同记录 $i,j$：总能按“关键字更小优先，同关键字原下标更小优先”的规则定出唯一相对次序。对每条记录，`count[i]` 正是排在它前面的记录个数。严格全序中的各记录秩恰好为 $0,1,\ldots,n-1$，故互不相同、无覆盖。

即便只有两个不同键，算法仍遍历所有 $n(n-1)/2$ 对，故比较次数不因数据分布变化。此排序不是依赖小范围键的计数排序；额外数组 `b` 的 $n$ 个位置是输出空间，不要与用于排秩的 `count` 混淆。

</ExamExplanation>

</ExamSolution>

## 2022 年第 42 题

<ExamQuestion>

**28. 2022 年第 42 题**

现有 $n$ 个数保存在一维数组 $M$ 中，其中

$$
n>100000.
$$

需要找出 $M$ 中最小的 10 个数。

请回答：

1. 设计一个完成上述任务的算法，要求平均情况下的比较次数尽可能少，只需描述算法思想，不需要程序实现；
2. 说明算法平均情况下的时间复杂度和空间复杂度。

<ExamSolution>

<ExamAnswer>

在数组前 10 个元素中建立**容量固定为 10 的大根堆**。顺序读取其余 $n-10$ 个值：若 $x\ge$ 堆顶，忽略；若 $x<$ 堆顶，用 $x$ 替换堆顶并向下调整。扫描完成后堆中的就是整个数组里最小的 10 个元素（**重复值按元素出现次数保留**）。总时间复杂度 $O(n\log10)=O(n)$，额外存储为 $O(10)=O(1)$；此界甚至是最坏情况下也成立的。

</ExamAnswer>

<ExamExplanation>

### 一、为什么保留“最大的那个候选”而不是最小的那个

目标是找出全局**最小的 10 个**，而不是找最小值一个。任何时刻，保存已扫描前缀中最小的 10 个元素；这些候选中最容易被淘汰的就是其中的**最大值**，因此选**大根堆**（堆顶最大），而不是小根堆。堆顶只占一个位置即可查看，常数次比较就能排除大部分不合格的新元素。

设当前候选多重集合 $H$ 的容量为 10。维护的不变式是：处理完前 $i\ge10$ 个输入后，$H$ 恰为这 $i$ 个元素中最小的 10 个（若第 10 位有多个相等元素，选其中任意满足数量的 10 个）。

- 读到 $x\ge\max(H)$：已有 10 个元素都不大于 $x$，所以无需替换，保持不变式；
- 读到 $x<\max(H)$：原堆顶是 10 个候选中最大者，替换它后得到新的最小 10 个；再下沉修复堆序即可。

完成整个数组扫描后，不变式直接给出全局正确性。**堆中十个值并不一定按升序存储**，若题目要求有序输出，最后对十个候选排序即可，其开销与 $n$ 无关。

### 二、算法步骤（考场可直接写）

1. 将 $M[0..9]$ 复制到辅助数组 $H[0..9]$；使用自底向上建堆形成大根堆，成本 $O(10)$。
2. 对 $i=10,11,\ldots,n-1$，先比较 $M[i]$ 与 $H[0]$。若 $M[i]<H[0]$，执行 `H[0]=M[i]` 并从堆顶向下调整；否则不处理。
3. 扫描结束时返回 $H$。若第 10 小恰好等于某个新值，可以选择不换，结果的**多重集合**仍正确。

例如 $M=[8,3,9,1,8,4,2,7,0,6,5,\ldots]$，前十个候选中最大者是 9。再读入 5 时，9 应被 5 替换；随着扫描进行，大根堆顶相当于动态维护“当前第 10 小”这个阈值。

### 三、复杂度、比较次数与其他候选方案

堆始终最多 10 个元素，维护堆的高度为 $\lfloor\log_2 10\rfloor$，因此一次更新 $O(\log10)$；对 $n-10$ 个新元素至少各有一次与堆顶的比较，总成本

$$
T(n)=O(10)+(n-10)\,O(1+\log10)=\boxed{O(n)}.
$$

建堆存储 10 个数需要 $O(10)=O(1)$ 额外空间。如果 10 改成输入参数 $k$，则复杂度为 $O(n\log k)$ 时间、$O(k)$ 额外空间；此时**不能仍写 $O(1)$ 空间**。因为 $n>100000$ 且 $k=10$ 极小，通常比先把整个 $n$ 个数排序更合适。

- **全排序**：$O(n\log n)$ 比较时间，得到远超所需的信息。
- **快速选择**：能在平均 $O(n)$ 时间、原地额外 $O(1)$ 空间内把最小 10 个移到前端，但可能需要多次遍历，且经典版本最坏 $O(n^2)$；若题目特别强调平均比较次数少，容量 10 的堆是一种很有效的实用选择。两种方法都可达渐近线性，不能在缺少具体概率模型时断言某个方法在**所有数据分布**下绝对比较次数最少。
- **反复找最小值 10 次**：约需 $10n$ 次比较，仍是 $O(n)$（10 固定），但常数较大。

### 四、易错条件

题目要的是 10 个**元素**，非“10 个不同关键字”。例如 $M$ 中 1 出现 20 次，那么最小 10 个元素都可以是 1。若要求 10 个**互异值**，必须加入去重规则；见[原创题](#question-original-161)。单纯“堆顶比较相同就跳过”并不是一般的去重方案。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

数据流依次为 $[5,1,3,1,2,2,9]$，只允许保存少量候选，取 $k=3$：

1. 找最小的 3 **个元素**（允许重复）与最小的 3 **个不同关键字**（需去重），各是什么？
2. 各设计一种流式维护算法。说明为什么仅比较新值与大根堆堆顶并不足以得到 3 个互异值；
3. 如果 $k$ 不是常数而是用户输入，分别给出算法时间与空间复杂度，并讨论找不到 $k$ 个互异值的情况。

<ExamSolution>

<ExamAnswer>按元素计，结果为 **$[1,1,2]$**；按互异值计，结果为 **$[1,2,3]$**。两种情形均可用大根堆保留 $k$ 个最小候选；互异版需额外通过候选集合判断键值是否已存在。常见实现：允许重复版 $O(n\log k)$ 时间、$O(k)$ 空间；互异版用大根堆和哈希集合，可得**期望** $O(n\log k)$ 时间、$O(k)$ 空间（正确同步删除/插入集合）。</ExamAnswer>

<ExamExplanation>

**按元素计**：扫描前缀时维护大小至多 3 的大根堆，堆满后只在 `x < heap.max` 时替换。第二个 1 是另一个合法元素，必须保留：最后堆中是多重集合 $\{1,1,2\}$。

**按互异值计**：如果只是忽略与**堆顶**相等的输入，无法过滤不在堆顶的重复值。例如堆中已有 $\{1,2,3\}$，再来 2，它并不等于堆顶 3，但并非新互异键。因此每次还须查询一个集合 `seen`（只包含**当前堆内**的互异键）：

1. 若 `x` 已在 `seen`，跳过；
2. 若当前候选不足 $k$，将新键放入堆，同时加入 `seen`；
3. 若已满且 `x < heap.max`，先从 `seen` 删除旧堆顶键，堆顶改成 $x$ 并下沉，再向 `seen` 加入 $x$；否则略过。

**为什么仅存“当前在堆中的”键已经足够？** 如果一个旧键已因过大而被淘汰，之后阈值（堆顶）只会不增，不可能因为未来重新遇到这个旧键就让它回到最小 $k$ 候选中；忽略与否不会破坏结论。因此不需要为输入中所有历史键维护一个 $O(n)$ 的全局去重集合。

**复杂度**：大根堆操作耗时 $O(\log k)$；哈希 `seen` 查询/更新均为期望 $O(1)$；故整体期望 $O(n\log k)$、空间 $O(k)$。若不希望使用哈希，可以在线性扫描最多 $k$ 个候选来判重，此时单次 $O(k)$、总时间 $O(nk)$（另计堆调整），额外空间仍 $O(k)$。若流中只有两个互异键而 $k=3$，不能凭空补出第三个，应返回实际找到的数量 2，或明确说明数据不足。

</ExamExplanation>

</ExamSolution>

## 2023 年第 42 题

<ExamQuestion>

**30. 2023 年第 42 题**

对含有 $n$ 个记录的文件进行外部排序。采用**置换—选择排序**生成初始归并段时，需要使用一个工作区，工作区中最多保存 $m$ 个记录。

请回答：

1. 若文件中有 19 个记录，其关键字依次为

$$
51,94,37,92,14,63,15,99,48,56,23,60,31,17,43,8,90,166,100,
$$

当 $m=4$ 时，可生成几个初始归并段？各是什么？
2. 对任意 $n$、$m$，其中 $n>m>0$，生成的第一个初始归并段的长度最大值和最小值分别是多少？

<ExamSolution>

<ExamAnswer>

工作区容量 $m=4$，依题设替换—选择（置换—选择）规则，生成 **3 个初始归并段**：

- $R_1=(37,51,63,92,94,99)$，长度 6；
- $R_2=(14,15,23,31,48,56,60,90,166)$，长度 9；
- $R_3=(8,17,43,100)$，长度 4。

对任意 $n>m>0$，第一个归并段满足 $\boxed{m\le L_1\le n}$，其最小长度为 $m$，最大长度为 $n$，均可构造输入达到。

</ExamAnswer>

<ExamExplanation>

### 一、先辨清“外部排序”和“初始归并段”

外部排序的数据主体不能全部装入内存，先把输入文件分为多个**内部有序的归并段**，再以多路归并将它们合并。初始段越长、段数越少，后续归并趟数和磁盘 I/O 通常越少。普通方法每次读取 $m$ 个记录、内部排序后写出，初始段长最多 $m$；置换—选择法则利用**不断补入新记录**，允许一个归并段长于工作区容量 $m$。

本题的关键是：**“有资格进入当前段”与“暂存等待下段”是两类状态**，不能只把所有工作区记录作为普通最小堆而不做标记。

### 二、工作区不变式及操作规则

工作区始终不超过 4 个记录，划分为 `ACTIVE`（仍属于当前归并段）和 `FROZEN`（已冻结、下一段才可输出）。

1. 最初将 $51,94,37,92$ 装入工作区，均为可输出状态；
2. 在 `ACTIVE` 中取关键字最小者 $v$ 输出到当前归并段；
3. 从输入文件再读一个关键字 $x$。若 $x\ge v$，将其标为 `ACTIVE`；否则冻结到下一段。**等于号可以进入同一段**，因为归并段要求的是非降序而不是严格升序；
4. 当 `ACTIVE` 为空时结束当前归并段，将冻结记录解冻，另开一个段；若输入已经结束，继续输出工作区内可用的记录直到完成。

注意：每条输出记录后只补入**一个**新记录；在工作区没有可输出记录前，不能提前抽取后面很多记录来绕过冻结条件。可用带冻结标志的选择树/堆实现；冻结者不能参加当前段的最小值竞争。

### 三、逐步手推：按输入指针填写“输出—补入—状态”

初始四个元素之后，后续输入依次是 $14,63,15,99,48,56,23,60,31,17,43,8,90,166,100$。

| 当前段 | 输出到磁盘的值 | 补入新值 | 新值状态 |
| --- | --- | --- | --- |
| $R_1$ | 37 | 14 | 冻结（$14<37$） |
| $R_1$ | 51 | 63 | 留在当前段 |
| $R_1$ | 63 | 15 | 冻结 |
| $R_1$ | 92 | 99 | 留在当前段 |
| $R_1$ | 94 | 48 | 冻结 |
| $R_1$ | 99 | 56 | 冻结，当前段结束 |
| $R_2$ | 14 | 23 | 留在当前段 |
| $R_2$ | 15 | 60 | 留在当前段 |
| $R_2$ | 23 | 31 | 留在当前段 |
| $R_2$ | 31 | 17 | 冻结 |
| $R_2$ | 48 | 43 | 冻结 |
| $R_2$ | 56 | 8 | 冻结 |
| $R_2$ | 60 | 90 | 留在当前段 |
| $R_2$ | 90 | 166 | 留在当前段 |
| $R_2$ | 166 | 100 | 冻结，当前段结束 |
| $R_3$ | 8、17、43、100 | 无后续输入 | 依次输出到文件末尾 |

从第一段结束时的冻结集合 $\{14,15,48,56\}$ 启动第二段；第二段结束时冻结集合是 $\{8,17,43,100\}$，构成第三段。检验：三段各自非降序，且元素总数 $6+9+4=19$，恰好覆盖原文件 19 个记录，多重集合无增删。

### 四、为什么第一个段最长 $n$、最短 $m$——构造证明

**下界 $L_1\ge m$**：最初放入的 $m$ 个记录全部为当前段有效记录。只要该段尚有一个有效记录，就可以输出它，且冻结的只能是之后新读入的记录。因此首批 $m$ 个初始记录均能在第一段内输出，至少有 $m$ 个。

**下界可达**：把整个输入按关键字**严格递减**排列。初始 $m$ 个值在第一段排序输出；每次补入的新值均小于刚输出的当前值，被冻结，首段输出完初始 $m$ 个记录即结束。所以 $L_1=m$。

**上界 $L_1\le n$**：一个段不可能包含多于全文件的 $n$ 条记录。按**非降序**给出整个输入，每次读入的新值都不小于上次输出，始终不冻结，故第一个段直接包含全部 $n$ 个记录，即 $L_1=n$。

特别提醒：随机输入下常引用“平均初始归并段长度约 $2m$”的经验结论，需要独立同分布等额外假设；**本题问的是严格极值，不是平均值**。

### 五、代码模型、复杂度与考场检查点

可分别用两个小根堆维护当前段与被冻结的记录，二者占用记录数**之和**始终不超过 $m$。每输出一个记录，最多插入一次（可能进入另一个堆），堆操作 $O(\log m)$，因此生成初始归并段的总计算时间为 $O(n\log m)$，工作区 $O(m)$；顺序读入/写出各 $n$ 条记录，外存 I/O 量为 $\Theta(n)$ 次记录传输（未计后续归并和块化因素）。如果采用选择树实现，多次输出同样可维持 $O(\log m)$ 的选择代价。

常见失分点：把冻结记录当成当前段的下一个最小值；在跨段时忘了解冻；把 $m$ 当成段长上限；漏掉文件读完后仍在工作区内的记录；只报段数而不写清每段内部顺序；没有用总计 19 条的守恒检查。

</ExamExplanation>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

输入记录顺序为 $[9,1,8,2,7,3,6,4,5,0,10]$，置换—选择工作区容量 $m=3$，关键字互异。

1. 求全部初始归并段，逐段写出关键字；
2. 指出第一段结束时的冻结记录，并解释为什么数字 $0$ 不能直接出现在第二段的中部；
3. 若下一阶段采用 **2 路归并**，在不考虑归并段长度差异、缓冲区以及败者树细节时，至少需要多少趟归并才能得到一个完整有序文件？每趟读写的数据量如何估算？

<ExamSolution>

<ExamAnswer>

初始归并段为 $R_1=(1,2,7,8,9)$、$R_2=(3,4,5,6,10)$、$R_3=(0)$；第一段结束时冻结的是 $3,4,6$（注意 $5,0,10$ 尚未被读入）；3 个初始段采用 2 路归并最少需要 **2 趟**。每趟完整归并约读取 $n$ 个记录并写出 $n$ 个记录，即 $2n$ 次记录级传输（实际磁盘按块 I/O）。

</ExamAnswer>

<ExamExplanation>

1. 装入 $[9,1,8]$。输出 1 补入 2（有效）；输出 2 补入 7（有效）；输出 7 补入 3（冻结）；输出 8 补入 6（冻结）；输出 9 补入 4（冻结）。因此第一段 $[1,2,7,8,9]$ 结束，**此时冻结的是 $\{3,6,4\}$**，而不是只有 $3,6$。
2. 解冻 $[3,4,6]$。输出 3 补入 5（有效）；输出 4 补入 0（冻结）；输出 5 补入 10（有效）；输出 6、10（文件已读完）。第二段为 $[3,4,5,6,10]$；数字 0 比第二段已经输出的 4 小，只能冻结到第三段，第三段 $[0]$。
3. 按 $k=2$ 路归并，每趟最多把段数降为向上取整的一半，$r=3$ 时 $3\to2\to1$，所以为 $\lceil\log_2 3\rceil=2$ 趟。假设每一趟都对全文件顺序读写一次，合计约 $2\times(2n)=4n$ 次记录传输；对 $n=11$ 即约 44 次记录级读写（并非 44 次磁盘块访问）。

**校正考点**：读入操作和当前段输出同步发生，必须在每次输出后补入下一个输入记录，因此第一段结束的冻结集合是 $\{3,4,6\}$。本题答案按这个严格过程计算，不要将尚未读取的记录加入冻结集合。

**注意**：对于长度不等的归并段，最优归并树（可通过 Huffman 思想安排归并）可以进一步降低总读写量；题问的是等价归并趟数的朴素方案，不应把“最少趟数”和“最少数据搬运量”混为一谈。

</ExamExplanation>

</ExamSolution>
