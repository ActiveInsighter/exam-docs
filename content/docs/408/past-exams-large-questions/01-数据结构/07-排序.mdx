## 2016 年第 43 题

<ExamQuestion>

**16. 2016 年第 43 题**

已知由 $n\;(n\ge 2)$ 个正整数构成的集合

$$
A=\{a_k\mid 0\le k<n\}.
$$

将其划分为两个不相交的子集 $A_1$ 和 $A_2$，元素个数分别为 $n_1$ 和 $n_2$，元素之和分别为 $S_1$ 和 $S_2$。

设计一个尽可能高效的划分算法，使

$$
|n_1-n_2|
$$

最小，并在此基础上使

$$
|S_1-S_2|
$$

最大。

要求：

1. 给出算法的基本设计思想；
2. 用 C 或 C++ 描述算法；
3. 说明时间复杂度和空间复杂度。

<ExamSolution>
<ExamAnswer>

1. 先固定 $k=\lfloor n/2\rfloor$，使 $|n_1-n_2|$ 最小；再选择最小的 $k$ 个数构成 $A_1$，其余较大的 $n-k$ 个数构成 $A_2$，使正整数条件下的 $|S_1-S_2|$ 最大。使用快速选择（Quickselect）无须将整个数组排序。
2. 下面采用原地迭代划分，结束时数组前 $k$ 个位置存最小的 $k$ 个数，返回两组和的差。

```c
#include <stddef.h>

static int partition(int a[], int l, int r) {
    int pivot = a[l];
    int i = l, j = r;
    while (i < j) {
        while (i < j && a[j] >= pivot) --j;
        a[i] = a[j];
        while (i < j && a[i] <= pivot) ++i;
        a[j] = a[i];
    }
    a[i] = pivot;
    return i;
}

long long divideSet(int a[], int n) { // 约定 n >= 2，原数组允许改动
    int k = n / 2;
    int l = 0, r = n - 1;
    while (l <= r) {
        int p = partition(a, l, r);
        if (p == k) break;
        if (p < k) l = p + 1;
        else r = p - 1;
    }
    long long s1 = 0, s2 = 0;
    for (int i = 0; i < k; ++i) s1 += a[i];
    for (int i = k; i < n; ++i) s2 += a[i];
    return s2 - s1;
}
```

3. Quickselect 平均时间复杂度为 $O(n)$，最坏时间复杂度为 $O(n^2)$；末尾两次求和为 $O(n)$，故总平均时间 $O(n)$、最坏 $O(n^2)$。该**迭代**实现的额外空间为 $O(1)$；若改用递归实现，需要额外计入递归栈。

</ExamAnswer>
<ExamExplanation>

1. **题目是二级优化，而非两个目标同时随意权衡。** 第一优先级是最小化 $|n_1-n_2|$：偶数 $n=2k$ 时两组各 $k$ 个；奇数 $n=2k+1$ 时分别为 $k$ 和 $k+1$ 个。只有满足此条件后才可考虑使 $|S_1-S_2|$ 最大。
2. **正整数条件决定最优方向。** 将数组由小到大记为 $b_1\le\cdots\le b_n$。选最小的 $k=\lfloor n/2\rfloor$ 个元素作为 $A_1$，其和取到可能的最小值 $S_1$；另一组包含余下元素（当 $n$ 为奇数时，多出的那个正整数放在较大元素组中），因此 $S_2\ge S_1$。若选择不同的 $k$ 个元素使较小组的和更大，$S_2-S_1=S-2S_1$ 只会减小。对于奇数情形，将更多正元素放进大和的一组，也比把更多元素放进小和的一组更优。
3. **交换论证（固定组大小）。** 假定当前 $A_1$ 中有 $x$，而 $A_2$ 中有 $y<x$；交换后 $A_1$ 和减少 $x-y$，$A_2$ 和增加 $x-y$，两组和差增加 $2(x-y)$。持续交换直至 $A_1$ 恰为最小的 $k$ 个元素，就得到最优划分；相等元素分到哪组均不影响目标值。
4. **为什么 Quickselect 比完整排序合适。** 排序会得到所有元素的全序，但题目仅需确定第 $k$ 小元素的分界。`partition` 将枢轴放到最终排序位置 $p$，并保证其左侧不大于枢轴、右侧不小于枢轴：若 $p=k$，前 $k$ 个位置即为需要的小数组；否则仅处理包含下标 $k$ 的一侧。
5. **下标约定易错。** `k=n/2` 是前一组的元素数量；下标 $k$ 对应第 $k+1$ 小的枢轴，故前一组用 `a[0]` 到 `a[k-1]`，后一组从 `a[k]` 起。千万不要把前 $k+1$ 个元素错误地划给较小组。
6. **时间与空间分开论证。** 每次划分只扫描当前区间，若枢轴平均较均衡，处理规模形成 $n+n/2+n/4+\cdots=O(n)$；一再选中最小/最大枢轴则变为 $n+(n-1)+\cdots=O(n^2)$。代码只保留常量个整数变量，因而额外空间 $O(1)$，但会修改输入数组；若必须保留原序列，通常先复制数组并计入 $O(n)$ 空间。
7. **常见陷阱。** 目标不是最小化两组和之差（那是另一种划分/背包问题）；也不能仅写“排序后各取一半，复杂度 $O(n)$”。复杂度声明应与实际代码算法相一致。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

<ExamQuestion>

正整数数组 $A=\{3,12,5,9,1,20,4\}$，按原题的先最小化人数差、再最大化和差的要求进行划分。

1. 给出最优两组（组内顺序不限），以及 $n_1,n_2,S_1,S_2$。
2. 计算目标值 $|n_1-n_2|$ 与 $|S_1-S_2|$。
3. 若错误地把最小的 $4$ 个数划为 $A_1$，将得到多大的和差？由此解释奇数长度下“多一个元素”应该放在较大元素组的原因。

<ExamSolution>
<ExamAnswer>

1. 排序为 $1,3,4,5,9,12,20$；可取 $A_1=\{1,3,4\}$、$A_2=\{5,9,12,20\}$，$n_1=3,n_2=4,S_1=8,S_2=46$。
2. 人数差为 $1$，和差为 $38$。
3. 若 $A_1=\{1,3,4,5\}$、$A_2=\{9,12,20\}$，和差为 $|13-41|=28<38$。

</ExamAnswer>
<ExamExplanation>

1. 奇数数组的最优人数差为 $1$，但并未指定哪组多一个元素。将人数较多的一组设为较大关键字组，可使较大组和进一步增大（正整数假设非常关键）。
2. 交换法即可证明：若小和组混入比大和组更大的元素，交换后人数组合不变而和差变大，因此最优分界必在排序后相邻的两部分之间。
3. 应按字典序优化目标：人数差相同为 $1$ 时，才有资格比较和差 $38$ 与 $28$。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

1. 若机械照搬原题，选最小的 $\lfloor n/2\rfloor=2$ 个数为 $A_1$，计算两组和差。

<ExamSolution>

1. 选 $A_1=\{-10,-9\}$，$S_1=-19$；$A_2=\{-8,1,2\}$，$S_2=-5$，和差 $14$。
2. 改为 $A_1=\{-10,-9,-8\}$，$S_1=-27$；$A_2=\{1,2\}$，$S_2=3$，和差 $30$（人数差仍为 $1$）。
3. 对一般整数须比较两种合法组大小 $\lfloor n/2\rfloor$、$\lceil n/2\rceil$，并考虑固定大小组取最小若干值、或取最大若干值所对应的绝对和差，取最大者；可由排序或双端选择辅助完成。

## 2021 年第 42 题

<ExamQuestion>

**26. 2021 年第 42 题**

已知某排序算法如下：

```c
void cmpCountSort(int a[], int b[], int n)
{
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n);

    for (i = 0; i < n; i++)
        count[i] = 0;

    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j])
                count[j]++;
            else
                count[i]++;

    for (i = 0; i < n; i++)
        b[count[i]] = a[i];

    free(count);
}
```

请回答：

1. 若

```c
int a[] = {25, -10, 25, 10, 11, 19};
int b[6];
```

调用 `cmpCountSort(a, b, 6)` 后，数组 `b` 中的内容是什么？
2. 若 `a` 中含有 $n$ 个元素，则算法执行过程中元素之间的比较次数是多少？
3. 该算法是否稳定？若稳定，说明理由；若不稳定，将其修改为稳定排序算法。

<ExamSolution>
<ExamAnswer>

1. 输出数组为 `{-10, 10, 11, 19, 25, 25}`。按原数组下标 $0$ 到 $5$，原版代码计算的计数是 `count = {5,0,4,1,2,3}`；两个相等的 $25$ 在输出时顺序颠倒。
2. 每一对不同位置的元素比较一次，次数是 $\binom n2=n(n-1)/2$。
3. 原算法**不稳定**。将 `if (a[i] < a[j])` 修改为 `if (a[i] <= a[j])`，使相等时**较早出现**的元素排在较前位置，即可实现稳定排序。时间复杂度 $O(n^2)$、计数数组与输出数组分别需要 $O(n)$ 存储。

</ExamAnswer>
<ExamExplanation>

1. **先识别算法的本质。** 这不是按数值频数开桶的计数排序，而是通过两两比较直接统计每个元素的**最终名次（秩）**，又常称比较计数排序、名次排序。`count[i]` 最终作为 `b[count[i]] = a[i]` 的输出地址。
2. **对不等元素的秩规律。** 一次比较 $a[i]$ 和 $a[j]$，较大者的 `count` 加一：最终每个元素的计数至少包括数组中严格小于它的元素数目。因此 $-10$ 的最终秩为 $0$，$10$ 为 $1$，$11$ 为 $2$，$19$ 为 $3$。
3. **对相等元素的秩规律及原版错误。** 由于原判断使用严格 `<`，当 $i<j$ 且 $a[i]=a[j]$ 时执行 `count[i]++`，较早出现的元素反而排在后面：原数组的第一个 $25$ 最终秩为 $5$，第二个 $25$ 秩为 $4$。仅看输出的数值序列无法发现不稳定，必须给相等记录加身份标签或追踪下标。
4. **稳定性修复。** 改用 `<=` 后，当 $i<j$ 且两数相等，执行 `count[j]++`；这相当于用“元素值 + 原下标”进行字典序比较，确保原下标较小的相等记录先输出。此时 `count` 为 `{4,0,5,1,2,3}`，输出的两个 $25$ 依然相邻，但原始顺序被保留。
5. **证明 `count` 无重复且覆盖 $0\sim n-1$。** 对任意两个输入位置，排序关系（值不同按数值比较、值相同按约定下标决胜）必给出先后次序。每次两两比较，都给排在后面的元素贡献一次计数；因此 `count[i]` 正是位于它前面的记录数，各计数恰好是 $0,1,\ldots,n-1$ 的一种排列，不会发生两个记录写到同一 `b` 槽位的问题。
6. **准确分析代价。** 内层执行次数为 $(n-1)+(n-2)+\cdots+1=n(n-1)/2$，无论原数组是否有序都一样，故最好、平均、最坏时间均为 $\Theta(n^2)$。`count` 需要 $n$ 个整数，`b` 需要 $n$ 个输出位置，辅助总空间为 $O(n)$（若输出数组作为调用方提供的目标存储，额外动态分配空间仅指 `count`）。
7. **实现易错点。** 不能把 `b` 和 `a` 指向同一块数组后继续使用此实现，因为最后写回可能覆盖尚未读出的输入值；`malloc` 结果在工程中应检查是否为空；并应保证 `n>=0` 和输出数组大小足够。修改判断只改变相等项先后次序，不影响递增排序结果。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

## 2022 年第 42 题

<ExamQuestion>

**28. 2022 年第 42 题**

现有 $n$ 个数保存在一维数组 $M$ 中，其中

$$
n>100000.
$$

需要找出 $M$ 中最小的 10 个数。

请回答：

1. 设计一个完成上述任务的算法，要求平均情况下的比较次数尽可能少，只需描述算法思想，不需要程序实现；
2. 说明算法平均情况下的时间复杂度和空间复杂度。

<ExamSolution>
<ExamAnswer>

1. 维护一个大小固定为 $10$ 的**大根堆**，保存截至当前扫描位置发现的最小 $10$ 个元素；堆顶就是候选集合中的最大值。初始化为前 $10$ 个数建堆；对其余每个数 $x$，若 $x\ge H[0]$ 则忽略，若 $x<H[0]$ 则替换堆顶并向下调整。扫描结束，堆中即是全局最小的 $10$ 个数（不要求这 $10$ 个数本身有序）。
2. 初次建堆 $O(10)$，后续至多 $n-10$ 次比较堆顶，必要时调整 $O(\log10)$，因此平均及最坏总时间都是 $O(n\log10)=O(n)$；额外堆空间 $O(10)=O(1)$。这里将 $10$ 视作题目固定常数，不能对任意增长的 $k$ 仍声称 $O(1)$ 空间。

</ExamAnswer>
<ExamExplanation>

1. **明确查询目标：只要最小十个数，不必完整排序。** 完整排序不仅比较额外的元素相对大小，而且至少需要 $\Omega(n\log n)$ 的比较（一般比较排序模型）。顺序扫描并始终保留十个候选即可满足题意。
2. **为什么选大根堆而非小根堆。** 当十个候选已经形成集合时，是否接受新元素只需与“候选中的最大值”比较：小于堆顶就有资格把它替换掉，否则不可能属于最小十个。大根堆可在 $O(1)$ 时间提供此阈值，并在 $O(\log10)$ 时间重新维护结构；小根堆仅能快速取得当前最小值，不能直接完成该筛选。
3. **算法不变式。** 处理完前 $t\ge10$ 个数时，堆中包含这些数的最小十个（按多重集合含义计数）。开始处理 $10$ 个数时显然成立。加入第 $t+1$ 个数 $x$：若 $x\ge$ 堆顶，新数不可能严格优于候选中的最大数，保持原堆正确；若 $x<$ 堆顶，新数进入最小十个并挤走原候选最大者，替换堆顶再下沉后不变式仍成立。由归纳法，到 $t=n$ 时正确。
4. **重复值和比较符号。** 若出现与堆顶相同的数，用 `x >= heap[0]` 可以忽略新来的那个；因为要求的是十个**数值**而非带身份的具体记录，结果按多重集不受影响。如题目要求重复记录按原下标择优，应为记录定义次级比较规则。
5. **比较次数为何少。** 大多数扫描值只和堆顶比较一次就被淘汰，只有真正更小的数才触发堆调整。若取 $k=10$ 为常数，每个被替换元素的向下调整层数最多 $\lfloor\log_2 10\rfloor$，因此最坏总体也为线性时间；“平均比较次数尽可能少”是算法设计动机，不意味着已经证明它在所有比较模型下具有绝对最小常数项。
6. **与其他方案对比。** 全排序 $O(n\log n)$，重复选最小十次 $O(10n)$，维护十元素有序表每次更新 $O(10)$，大根堆为 $O(n\log10)$；Quickselect 在平均情况下也可达 $O(n)$，但有最坏 $O(n^2)$ 的常见实现，并且对仅取十个数通常需要比“先和阈值比较”的堆方案进行更多分区比较，适用场景不同。
7. **推广 $k$ 的复杂度。** 若最小值个数改为输入参数 $k$，建堆 $O(k)$，扫描并调整总复杂度 $O(n\log k)$，存储 $O(k)$，当 $k$ 随输入增长时这不再是常数。若后续还要求输出从小到大的顺序，可在候选堆中再执行一次排序，额外 $O(k\log k)$。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

2. 对实时数据流需要维持不变式，使用大小固定的大根堆很自然；若等全部数据读完再执行 Quickselect，无法在中途随时报告正确的最小 $k$ 个数。
3. 有界内存和平均运行比较次数是不同的约束条件，答题时应说明是否允许改变原数组、是否必须在线处理、是否要求输出有序。

## 2023 年第 42 题

<ExamQuestion>

**30. 2023 年第 42 题**

对含有 $n$ 个记录的文件进行外部排序。采用**置换—选择排序**生成初始归并段时，需要使用一个工作区，工作区中最多保存 $m$ 个记录。

请回答：

1. 若文件中有 19 个记录，其关键字依次为

$$
51,94,37,92,14,63,15,99,48,56,23,60,31,17,43,8,90,166,100,
$$

当 $m=4$ 时，可生成几个初始归并段？各是什么？
2. 对任意 $n$、$m$，其中 $n>m>0$，生成的第一个初始归并段的长度最大值和最小值分别是多少？

<ExamSolution>
<ExamAnswer>

1. 当工作区容量 $m=4$ 时，生成 **$3$ 个初始归并段**（段内非递减）：

   - 第 $1$ 段：$37,51,63,92,94,99$；
   - 第 $2$ 段：$14,15,23,31,48,56,60,90,166$；
   - 第 $3$ 段：$8,17,43,100$。

2. 第一个归并段最长为 $n$，最短为 $m$，即 $m\le L_1\le n$；两种极值均能达到。

</ExamAnswer>
<ExamExplanation>

1. **理解置换—选择排序，不是简单把每 $m$ 个数排序后输出。** 工作区最初装入 $m$ 条记录；每次选择当前仍允许进入本归并段的最小记录输出，读取下一条输入记录替换腾出的工作区位置。若读入值 $x$ 不小于刚输出值 $y$，则 $x$ 仍可以进入当前非递减段；若 $x<y$，就将其**冻结**，留待下一段。只有当前工作区内不再有属于本段的活动记录时，才能结束本段。
2. **第 $1$ 段逐步模拟。** 初始工作区为 $51,94,37,92$。

   | 本段输出 | 读入下一个值 | 决定 | 输出后当前段仍可选的关键字 |
   | ---: | ---: | --- | --- |
   | $37$ | $14$ | $14<37$，冻结 | $51,92,94$ |
   | $51$ | $63$ | $63\ge51$，参加本段 | $63,92,94$ |
   | $63$ | $15$ | 冻结 | $92,94$ |
   | $92$ | $99$ | 参加本段 | $94,99$ |
   | $94$ | $48$ | 冻结 | $99$ |
   | $99$ | $56$ | 冻结 | 无，结束第 $1$ 段 |

   此时被冻结的记录为 $14,15,48,56$。第 $1$ 段共输出 $6$ 条记录，长度可以超过 $m=4$。
3. **第 $2$ 段逐步模拟。** 将冻结记录重新激活，从中选出最小者并继续读未处理的输入记录：

   | 本段输出 | 新读入 | 处理决定 |
   | ---: | ---: | --- |
   | $14$ | $23$ | 参加本段 |
   | $15$ | $60$ | 参加本段 |
   | $23$ | $31$ | 参加本段 |
   | $31$ | $17$ | 冻结 |
   | $48$ | $43$ | 冻结 |
   | $56$ | $8$ | 冻结 |
   | $60$ | $90$ | 参加本段 |
   | $90$ | $166$ | 参加本段 |
   | $166$ | $100$ | 冻结，结束本段 |

   因此第 $2$ 段为 $14,15,23,31,48,56,60,90,166$；冻结集合为 $17,43,8,100$。
4. **第 $3$ 段。** 输入已经读完，重新激活这 $4$ 条冻结记录，依次输出 $8,17,43,100$；全部输入恰好被输出一次。可用检查：三段长度 $6+9+4=19=n$，段内各自有序，但不同段之间不要求相互有序。
5. **长度界的证明。** 首次装入的 $m$ 条记录都属于第一段且不会被提前冻结：初始记录在工作区中可以被选择输出，它们不会因为后来读入更小的值而转去其他段。因此第一段至少包含最初的 $m$ 条，即 $L_1\ge m$。其余输入若总是符合本段的非递减要求，就无冻结而输出全部 $n$ 条，即 $L_1\le n$ 可达；若后续每条都严格小于当时刚输出的键，那么填入的均冻结，第一段仅输出初始 $m$ 条，可达最小 $m$。
6. **常见误区。** 冻结记录仍占工作区但**不得参加当前段最小值选择**；不能把它简单丢弃，也不能在当前段活动记录未空时提前解冻。若关键字相等，因非递减次序允许 $x=y$，应让其继续参加当前段。
7. **算法组织与性能。** 工作区可借助最小堆维护当前段可参与输出的记录，冻结标记影响选择资格；每次选择/替换在 $O(\log m)$ 时间内完成，处理 $n$ 条记录的生成过程通常为 $O(n\log m)$ 时间，工作区 $O(m)$。置换—选择的意义在于初始归并段长度通常可以超过工作区容量，以减少后续归并趟数，但具体长度依赖输入序列。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>
