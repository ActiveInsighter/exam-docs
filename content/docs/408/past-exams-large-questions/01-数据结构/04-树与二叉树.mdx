## 2012 年第 41 题

综合考点：最佳归并策略、哈夫曼树。

<ExamQuestion>

**7. 2012 年第 41 题**

有 6 个升序表 $A,B,C,D,E,F$，长度分别为

$$
10,35,40,50,60,200.
$$

要求通过 5 次两两合并，将这 6 个表最终合并成 1 个升序表，并使**最坏情况下的总比较次数最少**。

1. 给出完整合并过程，并求最坏情况下的总比较次数；
2. 根据上述过程，描述 $N$（$N\ge2$）个不等长升序表的最佳合并策略，并说明理由。

<ExamSolution>

<ExamAnswer>采用类似哈夫曼树的最佳归并策略：每次合并当前长度最小的两个表。最坏情况下总比较次数为 $825$。</ExamAnswer>

<ExamExplanation>

两个长度分别为 $m$、$n$ 的有序表进行归并，最坏情况下需要

$$
m+n-1
$$

次比较。因此，为使总比较次数最少，应让较小的表尽可能早地合并，避免较大的中间结果被反复参与后续归并。这正是**哈夫曼树 / 最佳归并树**的思想。

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2012-41-figure-001.svg" alt="2012 年第 41 题最佳归并树" />

具体过程：

1. $10+35=45$：合并 $A,B$，最坏比较 $44$ 次；
2. $40+45=85$：合并 $C,AB$，最坏比较 $84$ 次；
3. $50+60=110$：合并 $D,E$，最坏比较 $109$ 次；
4. $85+110=195$：最坏比较 $194$ 次；
5. $195+200=395$：最坏比较 $394$ 次。

总比较次数为

$$
44+84+109+194+394=825.
$$

对于一般的 $N$ 个不等长升序表，可把每个表的长度看作叶结点权值：

1. 每次从当前所有表中选择长度最小的两个表；
2. 将它们归并为一个新表；
3. 把新表重新放回候选集合；
4. 重复直到只剩一个表。

这样构造出的最佳归并树具有最小的带权路径长度，因此也使各次归并所产生的总比较代价最小。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2014 年第 41 题

<ExamQuestion>

**11. 2014 年第 41 题**

二叉树的带权路径长度（WPL）是二叉树中所有叶结点的带权路径长度之和。给定一棵二叉树 $T$，采用二叉链表存储，其中叶结点的 `weight` 域保存该结点的非负权值。设 `root` 为指向 $T$ 根结点的指针，请设计求 $T$ 的 WPL 的算法。

要求：

1. 给出算法的基本设计思想；
2. 使用 C 或 C++ 语言给出二叉树结点的数据类型定义；
3. 根据设计思想描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>采用递归遍历，同时把当前结点深度作为参数传递；遇到叶结点时累加“叶结点权值 × 深度”。</ExamAnswer>

<ExamExplanation>

### 基本思想

规定根结点深度为 $0$。遍历到结点 $p$ 时：

- 若 $p$ 为空，贡献为 $0$；
- 若 $p$ 是叶结点，则其对 WPL 的贡献为

$$
p\to weight\times depth;
$$

- 若 $p$ 是非叶结点，则递归计算左右子树，子结点深度均为当前深度加 $1$。

这样每个结点只访问一次，所有叶结点的贡献之和就是整棵树的 WPL。

### 结点定义与算法

```c
typedef struct BiTNode {
    int weight;
    struct BiTNode *lchild;
    struct BiTNode *rchild;
} BiTNode, *BiTree;

int WPLCore(BiTree root, int depth) {
    if (root == NULL) {
        return 0;
    }

    // 叶结点：累加该叶结点的带权路径长度
    if (root->lchild == NULL && root->rchild == NULL) {
        return root->weight * depth;
    }

    return WPLCore(root->lchild, depth + 1)
         + WPLCore(root->rchild, depth + 1);
}

int WPL(BiTree root) {
    return WPLCore(root, 0);
}
```

原整理中的代码同时使用了 `Node`、`BiTNode` 以及 `left/right`、`lchild/rchild` 两套命名，容易造成类型和成员名不一致；这里已统一为同一套二叉链表定义。

时间复杂度为 $O(n)$，其中 $n$ 为树的结点数；递归栈空间为 $O(h)$，其中 $h$ 为树高。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2016 年第 42 题

<ExamQuestion>

**15. 2016 年第 42 题**

若一棵非空 $k$ 叉树（$k\ge 2$）$T$ 中，每个非叶结点都有恰好 $k$ 个孩子，则称 $T$ 为**正则 $k$ 叉树**。

请回答并给出推导过程：

1. 若 $T$ 有 $m$ 个非叶结点，则 $T$ 中有多少个叶结点？
2. 若 $T$ 的高度为 $h$（单结点树的高度 $h=1$），则 $T$ 的结点数最多为多少？最少为多少？

<ExamSolution>

<ExamAnswer>

1. 叶结点数为

$$
(k-1)m+1.
$$

2. 高度为 $h$ 时，结点总数最大为

$$
\frac{k^h-1}{k-1},
$$

最小为

$$
1+k(h-1).
$$

</ExamAnswer>

<ExamExplanation>

### （1）叶结点数

设叶结点数为 $n_0$。正则 $k$ 叉树只有两类结点：叶结点和度为 $k$ 的非叶结点，因此总结点数为

$$
n=n_0+m.
$$

一棵含 $n$ 个结点的树共有

$$
n-1
$$

条边；另一方面，每个非叶结点都发出 $k$ 条父子边，共有

$$
km
$$

条边。因此

$$
n_0+m-1=km,
$$

整理得

$$
\boxed{n_0=(k-1)m+1}.
$$

### （2）高度固定时的最多结点数

要使结点数最多，第 $1$ 至第 $h-1$ 层的所有结点都必须是非叶结点，即形成满 $k$ 叉树。

第 $j$ 层有

$$
k^{j-1}
$$

个结点，因此

$$
N_{\max}
=1+k+k^2+\cdots+k^{h-1}
=\frac{k^h-1}{k-1}.
$$

### 高度固定时的最少结点数

要使树高仍为 $h$ 而结点数尽可能少，只需在每一层保留一个非叶结点继续向下一层延伸。每个非叶结点又必须恰有 $k$ 个孩子。

从根开始，每向下增加一层，就必须新增 $k$ 个结点。共需扩展 $h-1$ 次，因此

$$
N_{\min}=1+k(h-1).
$$

原整理中最大结点数求和式的上下标存在识别混乱，这里已按树高定义重新推导并统一修正。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2017 年第 41 题

<ExamQuestion>

**17. 2017 年第 41 题**

设计一个算法，将给定的表达式树（二叉树）转换为等价的中缀表达式，并通过括号正确反映操作符的计算次序。

例如，下列两棵表达式树：

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2017-41-figure-001.svg" alt="2017 年第 41 题表达式树" />

应分别输出：

```text
(a+b)*(c*(-d))
(a*b)+(-(c-d))
```

二叉树结点定义如下：

```c
typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;
```

要求：

1. 给出算法的基本设计思想；
2. 用 C 或 C++ 描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>对表达式树进行中序遍历；除根结点和叶结点外，每个分支结点所对应的子表达式外加一对括号。</ExamAnswer>

<ExamExplanation>

表达式树本质上把每个运算符的两个操作对象放在左右子树中，因此按

$$
\text{左子树}\to\text{根}\to\text{右子树}
$$

的中序次序输出，就能得到中缀形式。

但仅做普通中序遍历会丢失原表达式树规定的运算次序，因此需要加括号：

- 叶结点只是操作数，不加括号；
- 根结点代表整个表达式，最外层无需再加括号；
- 其余非叶结点代表一个子表达式，应在遍历其左子树前输出 `(`，遍历其右子树后输出 `)`。

该规则同样能处理图中的一元负号结点：当左孩子为空、右孩子为操作数或子表达式时，中序输出自然得到 `-d` 或 `-(c-d)`。

```c
#include <stdio.h>

typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;

void PrintExpr(BTree *root, int depth) {
    if (root == NULL) {
        return;
    }

    int isRoot = (depth == 0);
    int isLeaf = (root->left == NULL && root->right == NULL);

    // 非根的运算符结点所代表的子表达式需要括号
    if (!isRoot && !isLeaf) {
        printf("(");
    }

    PrintExpr(root->left, depth + 1);
    printf("%s", root->data);
    PrintExpr(root->right, depth + 1);

    if (!isRoot && !isLeaf) {
        printf(")");
    }
}

void Expression(BTree *root) {
    PrintExpr(root, 0);
}
```

原整理把该中序遍历函数命名为 `preorder`，容易与“先序遍历”混淆；这里已更正函数命名和说明。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2020 年第 42 题

<ExamQuestion>

**24. 2020 年第 42 题**

若任一字符的编码都不是其他字符编码的前缀，则称该编码集合具有**前缀特性**。

现有某字符集（字符个数不少于 2）的一组不等长编码，每个字符的编码均为二进制 0、1 序列，最长为 $L$ 位，并具有前缀特性。

请回答：

1. 哪种数据结构适合保存上述具有前缀特性的不等长编码？
2. 基于所设计的数据结构，简述从 0/1 串到字符串的译码过程；
3. 简述判定某字符集的一组不等长编码是否具有前缀特性的过程。

<ExamSolution>

<ExamAnswer>使用二叉树（前缀树）保存编码：0 对应左分支，1 对应右分支，字符只保存在编码终点的叶结点。译码时从根按位下行，到叶结点输出字符并回到根；判定前缀特性可在逐个插入编码构造前缀树的同时完成。</ExamAnswer>

<ExamExplanation>

### （1）数据结构

使用一棵**二叉前缀树**。

- 从根到某结点的一条路径表示一个二进制编码；
- 约定编码位 0 走左孩子，编码位 1 走右孩子；
- 一个合法字符编码的终点保存相应字符；
- 若整组编码具有前缀特性，则所有字符编码终点都应是叶结点。

### （2）译码过程

从输入 0/1 串的左端开始扫描，并令当前结点初始为根结点：

1. 当前位为 0，则走向左孩子；当前位为 1，则走向右孩子；
2. 到达保存字符的叶结点后，输出该字符；
3. 重新回到根结点，继续处理后续二进制位；
4. 扫描完整个 0/1 串后，译码结束。

由于编码具有前缀特性，到达一个字符对应叶结点时就可以唯一确定该字符，不需要向后试探。

### （3）判定是否具有前缀特性

可以在逐个插入编码、构造前缀树的过程中检查。

对每个编码 $C$，从根开始逐位处理：

1. 在尚未处理完 $C$ 时，若当前结点已经是某个已有字符编码的终点，则说明**已有较短编码是 $C$ 的前缀**，不具有前缀特性；
2. 根据当前位 0/1 进入相应孩子；若孩子不存在，则新建结点；
3. $C$ 的所有位处理完后：
   - 若当前结点已经是某个字符的编码终点，则出现重复编码，不合法；
   - 若当前结点已有左孩子或右孩子，则说明 **$C$ 是某个已有较长编码的前缀**，不具有前缀特性；
   - 否则把当前结点标记为该字符的编码终点。

所有编码都插入成功，才能判定整组编码具有前缀特性。

若所有编码总长度为 $M$，上述建树与检查只需 $O(M)$ 时间。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>
