## 2012 年第 41 题

<ExamQuestion>

**7. 2012 年第 41 题**

有 6 个升序表 $A,B,C,D,E,F$，长度分别为

$$
10,35,40,50,60,200.
$$

要求通过 5 次两两合并，将这 6 个表最终合并成 1 个升序表，并使**最坏情况下的总比较次数最少**。

1. 给出完整合并过程，并求最坏情况下的总比较次数；
2. 根据上述过程，描述 $N$（$N\ge2$）个不等长升序表的最佳合并策略，并说明理由。

<ExamSolution>

<ExamAnswer>每次选**当前长度最短的两个升序表**进行两路归并，再把合并结果作为新表放回候选集合。依次合并 $10+35=45$、$40+45=85$、$50+60=110$、$85+110=195$、$195+200=395$；比较次数分别为 $44,84,109,194,394$，总最坏比较次数 $\boxed{825}$。一般 $N$ 个表用小根堆维护长度即可实现最优归并，决策阶段 $O(N\log N)$。</ExamAnswer>

<ExamExplanation>

### 一、理解优化目标：不是合并次数，而是总比较次数

无论采用哪棵二叉归并树，把 $N$ 个表两两合并成 1 个总需要**恰好 $N-1$ 次归并**。区别是早期形成的中间表会在之后的归并中反复参加比较。长度分别为 $a,b$ 的两个非空有序表，标准两指针归并的最坏比较次数是

$$
a+b-1,
$$

因为至多在最后一个元素之前，两个表都仍有未归并元素。该界限可由交错排列达到。题目给的是**最坏情况比较次数**，不能把它误写为元素移动次数 $a+b$。

### 二、按照图中的最佳归并树操作

题面 SVG 展示了归并树。使用小根堆逐步取两个最小值：

| 次序 | 选中表长 | 新表长 | 最坏比较 |
| ---: | --- | ---: | ---: |
| 1 | $10,35$ | $45$ | $44$ |
| 2 | $40,45$ | $85$ | $84$ |
| 3 | $50,60$ | $110$ | $109$ |
| 4 | $85,110$ | $195$ | $194$ |
| 5 | $195,200$ | $395$ | $394$ |

所以 $44+84+109+194+394=825$。注意第 3 步的 `50,60` 比 `85` 小；如机械沿原 A,B,C,D,E,F 顺序合并，很容易错。

### 三、为什么哈夫曼贪心可以最优

把每个原始表看作叶结点，表长 $w_i$ 为叶权，叶到根的路径长度为 $d_i$（叶深度）。每次内部结点的“归并表长”是它所有后代叶权之和，故所有归并总表长之和等于带权路径长度：

$$
\sum_{v\in\text{内部结点}}w(v)=\sum_{i=1}^{N}w_i d_i=\operatorname{WPL}.
$$

每次归并的最坏比较次数比新表长少 1，一共做 $N-1$ 次，所以

$$
C_{\max}=\operatorname{WPL}-(N-1).
$$

$N$ 固定时只需最小化 WPL，这就转化为经典哈夫曼最优树问题。最深层的两个兄弟叶可以安排为**最轻的两个权值**（交换后 WPL 不增），将这两个叶压缩成权值之和的新叶，问题便缩减为 $N-1$ 叶；递归应用得到“每次合并两最小”的贪心策略。

此题 $\operatorname{WPL}=825+5=830$，即为交叉验算。整个归并结果表长为 $395$，**绝不能**把 $395$ 当作总比较次数。

### 四、一般算法、复杂度与修正模型

使用小根堆存长度：建堆 $O(N)$，每轮弹两次最小、计算合并代价、把和压回，重复 $N-1$ 轮。决策成本 $O(N\log N)$，堆空间 $O(N)$。若实际上还执行元素归并，复制/移动等数据处理开销与各表的 WPL 有关，不能说整次真实归并只需 $O(N\log N)$。

```cpp
#include <queue>
#include <vector>
#include <functional>
using namespace std;

long long MergeWorstComparisons(const vector<long long>& len) {
    priority_queue<long long, vector<long long>, greater<long long>> pq;
    for (long long x : len) pq.push(x);  // 题设保证 x > 0
    long long ans = 0;
    while (pq.size() > 1) {
        long long a = pq.top(); pq.pop();
        long long b = pq.top(); pq.pop();
        ans += a + b - 1;
        pq.push(a + b);
    }
    return ans;                         // 题设默认 64 位范围内
}
```

若每次合并还有固定启动代价 $c$，则总费用是 $\operatorname{WPL}-(N-1)+c(N-1)$；在每次都支付相同 $c$ 的条件下，最优合并顺序**不变**。若固定成本与表长或设备有关，不能再直接使用该结论。[原创题](#question-original-139)对此展开。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

五个非空升序表长分别为 $5,8,13,27,50$。每归并两个表，最坏关键字比较次数为 $a+b-1$，此外有固定启动开销 $c=4$（以相同比较成本单位计）。

1. 求使总费用最小的归并过程、总比较次数、总启动开销及总费用。
2. 证明固定开销不改变最佳归并次序。
3. 实现 `long long OptimalMergeCost(const vector<long long>& len, long long c)`，要求决策 $O(N\log N)$，并写出必要的输入与数值边界条件。

<ExamSolution>

<ExamAnswer>合并 `5+8=13`、`13+13=26`、`26+27=53`、`50+53=103`。最坏比较次数 $12+25+52+102=\boxed{191}$；共 $N-1=4$ 次启动，启动开销 $4\times4=16$；最小总费用 $\boxed{207}$。固定开销对所有二叉归并方案都是 $(N-1)c$，只改变总费用，不改变哈夫曼贪心选择。</ExamAnswer>

<ExamExplanation>

### 一、注意两个“13”来源不同

初始有长度 13 的原表，第一次归并 5 与 8 又生成长度 13 的新表，所以第二步应合并**两个 13**，而不是把 13 与 27 直接合并。

| 步 | 合并 | 新长度 | 最坏比较 | 启动费 |
| ---: | --- | ---: | ---: | ---: |
| 1 | $5+8$ | 13 | 12 | 4 |
| 2 | $13+13$ | 26 | 25 | 4 |
| 3 | $26+27$ | 53 | 52 | 4 |
| 4 | $50+53$ | 103 | 102 | 4 |

归并内部结点权值和（WPL）为 $13+26+53+103=195$，因此比较次数 $195-4=191$。所有元素总长度是 103，和比较次数 191 完全不是同一个量。

### 二、抽象证明与算法

任意两两归并形成一棵有 $N$ 个叶的满二叉归并树，内部结点数恒为 $N-1$。因此总费用必为

$$
\underbrace{\sum_{v\text{ 内部}}\bigl(w(v)-1\bigr)}_{\mathrm{WPL}-(N-1)}
+\underbrace{c(N-1)}_{\text{所有方案相同}}
=\mathrm{WPL}+(c-1)(N-1).
$$

$N$ 与 $c$ 已固定，最优性只取决于 WPL，于是每次取两最小权的哈夫曼算法仍然适用。

```cpp
#include <vector>
#include <queue>
#include <functional>
#include <stdexcept>
using namespace std;

long long OptimalMergeCost(const vector<long long>& len, long long c) {
    if (len.empty() || c < 0) throw invalid_argument("bad input");
    priority_queue<long long, vector<long long>, greater<long long>> pq;
    for (long long x : len) {
        if (x <= 0) throw invalid_argument("empty sorted table");
        pq.push(x);
    }
    long long ans = 0;
    while (pq.size() > 1) {
        long long a = pq.top(); pq.pop();
        long long b = pq.top(); pq.pop();
        long long merged = a + b;  // 题目保证和与费用不超 long long
        ans += merged - 1 + c;
        pq.push(merged);
    }
    return ans;
}
```

输入长度非空；长度都是正数（非空有序表）且常数费用非负；题目假定所有中间和及总费用适于 `long long`，通用库应增加溢出检查。若允许空表，`a+b-1` 不再是该合并最坏比较次数，必须单独定义空表归并规则。

### 三、何时不该用哈夫曼

当启动开销随着参与表的长度、存储位置或归并设备变化时，`c(N-1)` 不再是常数，最优策略可能改变；若要求**保持原输入顺序、只能合并相邻两段**，普通哈夫曼会破坏相邻性，需使用区间动态规划。看清“任取两个”还是“只能相邻”，是该模型的核心边界。

## 2014 年第 41 题

<ExamQuestion>

**11. 2014 年第 41 题**

二叉树的带权路径长度（WPL）是二叉树中所有叶结点的带权路径长度之和。给定一棵二叉树 $T$，采用二叉链表存储，其中叶结点的 `weight` 域保存该结点的非负权值。设 `root` 为指向 $T$ 根结点的指针，请设计求 $T$ 的 WPL 的算法。

要求：

1. 给出算法的基本设计思想；
2. 使用 C 或 C++ 语言给出二叉树结点的数据类型定义；
3. 根据设计思想描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>对二叉树做深度优先遍历并记录当前结点深度（根深度定义为 0）。只有叶结点才贡献 `weight × depth`；空树贡献 0，内部结点不直接计权。递归求出两棵子树之和即为 WPL，时间 $O(n)$、递归栈空间 $O(h)$。</ExamAnswer>

<ExamExplanation>

### 一、辨别路径长度、深度和权值

二叉树的带权路径长度定义为

$$
\operatorname{WPL}(T)=\sum_{v\text{ 为叶结点}} w(v)\,d(v),
$$

这里 $d(v)$ 是**从根到叶所经过的边数**：根深度为 0，根的左右孩子深度为 1。内部结点即使有 `weight` 字段也不计入这个公式，题目只保证叶结点的权值有意义。

例如根 `A` 的左孩子叶权为 5；其右孩子 `B` 的左孩子为叶权 2、右孩子 `C` 的左右叶权分别为 1、4，则深度依次是 $1,2,3,3$，

$$
\operatorname{WPL}=5\times1+2\times2+1\times3+4\times3=24.
$$

**单结点树**只有根叶，路径长度为 0，故无论权值多少 WPL 都是 0，而不是权值本身。

### 二、递归分解、统一类型的 C 代码

子问题定义 `WPLCore(p,d)` 为“以 `p` 为根所含叶结点，沿原树根计算的 WPL 贡献之和”。于是

$$
F(p,d)=\begin{cases}
0,&p=\mathrm{NULL},\\
w(p)d,&p\text{ 无孩子},\\
F(p.\mathrm{left},d+1)+F(p.\mathrm{right},d+1),&\text{否则}.
\end{cases}
$$

```c
#include <stddef.h>

typedef struct BiTNode {
    int weight;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

long long WPLCore(BiTree p, int depth) {
    if (p == NULL) return 0;
    if (p->lchild == NULL && p->rchild == NULL)
        return (long long)p->weight * depth;
    return WPLCore(p->lchild, depth + 1)
         + WPLCore(p->rchild, depth + 1);
}

long long WPL(BiTree root) {
    return WPLCore(root, 0);
}
```

`long long` 能减少 `int` 相乘或累计溢出风险，但**前提仍是最终结果在有符号 64 位范围内**；如果权值、规模极大，需使用更宽整数或溢出检查。类型名 `BiTNode`、成员 `lchild/rchild` 前后一致，避免“`left`/`lchild` 混用”的编译错误。

### 三、遍历不变量与正确性

对任意结点 `p`，函数遍历到 `p` 时参数 `depth` 恰是原根到 `p` 的边数。若 `p` 是叶，贡献正是 $w(p)\cdot depth$；否则所有叶被左右两棵子树不重不漏地划分，递归结果相加正好枚举整个以 `p` 为根的叶集合。对树结构做归纳即可证明。

每个结点只访问一次，耗时 $\Theta(n)$；递归活动记录数最多为树高 $h$，辅助空间 $O(h)$。平衡树高度 $O(\log n)$，极度退化的树高度 $O(n)$。原树本身不计辅助空间。

### 四、常考变式与易错点

- **用层序遍历求 WPL**：队列保存 `(node,depth)` 即可，时间 $O(n)$、队列空间 $O(w)$，$w$ 为最大层宽；见[原创题](#question-original-140)。
- **若根深度从 1 开始**：算出的不是题目通常定义的 WPL，而是标准 WPL 加上全部叶权之和，绝不能混用约定。
- **非叶结点也有权值**：题目明确只求叶结点带权路径长度，不能把内部结点计入。
- **与哈夫曼树联系**：已给定树时直接计算 WPL；要求在一组权值下求**最小可能 WPL**时才需要哈夫曼构造。这两个问题的任务不同。

</ExamExplanation>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

给定一棵普通二叉树，根 `A` 左孩子为叶 `B`（权值 5），右孩子是内部结点 `C`；`C` 的左孩子为叶 `D`（权值 2），右孩子为内部结点 `E`；`E` 的左右孩子分别为叶 `F`（权值 1）、`G`（权值 4）。根深度为 0。

1. 求 WPL。
2. 不使用递归，通过**层序遍历**计算任意非空二叉树 WPL，要求 C++17 代码、$O(n)$ 时间，并给出空间复杂度更精确的表达式。
3. 树退化为单链时，递归 DFS 与队列 BFS 分别使用多少辅助空间？单个根结点的树 WPL 如何计算？

<ExamSolution>

<ExamAnswer>四个叶权深度为 $(5,1),(2,2),(1,3),(4,3)$，WPL 为 $\boxed{24}$。层序队列存 `(结点指针, 深度)`，仅在弹出的结点为叶时累计贡献，时间 $O(n)$，队列额外空间 $O(w)$，其中 $w$ 为最大层宽。单链时 BFS 队列空间 $O(1)$，递归 DFS 调用栈 $O(n)$；单结点树 WPL 为 0。</ExamAnswer>

<ExamExplanation>

### 一、深度与权值只属于叶结点

```text
         A(d=0)
        /      \
    B:5(d=1)   C(d=1)
              /    \
         D:2(d=2) E(d=2)
                 /      \
             F:1(d=3) G:4(d=3)
```

按根到叶的**边数**计深度，故

$$
WPL=5\cdot1+2\cdot2+1\cdot3+4\cdot3=24.
$$

如果错把层数 1、2、3、4 当作深度，便会多算叶权之和 $5+2+1+4=12$，得出错误的 36。

### 二、队列算法与完整代码

```cpp
#include <queue>
#include <utility>
using namespace std;

struct Node {
    long long weight;
    Node *left, *right;
};

long long WPLBFS(const Node* root) {
    if (root == nullptr) return 0;
    queue<pair<const Node*, int>> q;
    q.push({root, 0});
    long long sum = 0;
    while (!q.empty()) {
        auto [p, d] = q.front();
        q.pop();
        if (p->left == nullptr && p->right == nullptr) {
            sum += p->weight * d; // 假设乘积及总和在 long long 范围内
        } else {
            if (p->left)  q.push({p->left, d + 1});
            if (p->right) q.push({p->right, d + 1});
        }
    }
    return sum;
}
```

`queue<pair<node,depth>>` 的深度字段不可以省略，除非另用“分层计数”方式在每层结束时增加深度。队列每次弹出 1 个结点，至多入队其 2 个孩子；每个结点恰好一次入队、出队，故时间 $\Theta(n)$。

### 三、空间与边界比较

DFS 递归版占用 $O(h)$ 调用栈，最坏 $O(n)$；BFS 层序版最多只存相邻一两层中的结点，故空间 $O(w)$，这里 $w$ 是**最大层宽**，严格地说队列同时可混存某层余量与下一层结点，数量仍与最大层宽同阶。

退化为链时 $h=n$ 但 $w=1$，DFS 需要 $O(n)$、BFS 仅 $O(1)$；完全二叉树时 $h=O(\log n)$、$w=\Theta(n)$，反过来 DFS 更省空间。只有根的树，根同时为叶且 $d=0$，结果始终为 $w(root)\cdot0=0$。

</ExamExplanation>

</ExamSolution>

## 2016 年第 42 题

<ExamQuestion>

**15. 2016 年第 42 题**

若一棵非空 $k$ 叉树（$k\ge 2$）$T$ 中，每个非叶结点都有恰好 $k$ 个孩子，则称 $T$ 为**正则 $k$ 叉树**。

请回答并给出推导过程：

1. 若 $T$ 有 $m$ 个非叶结点，则 $T$ 中有多少个叶结点？
2. 若 $T$ 的高度为 $h$（单结点树的高度 $h=1$），则 $T$ 的结点数最多为多少？最少为多少？

<ExamSolution>

<ExamAnswer>（1）有 $m$ 个非叶结点的正则 $k$ 叉树，叶结点数为 $\boxed{(k-1)m+1}$；（2）高度为 $h$（根所在层为第 1 层）时，最多结点数 $\boxed{(k^h-1)/(k-1)}$，最少结点数 $\boxed{1+k(h-1)}$。</ExamAnswer>

<ExamExplanation>

### 一、先审条件：正则与满树是两个概念

本题“正则 $k$ 叉树”只要求：**每个内部结点都恰有 $k$ 个孩子，叶结点有 0 个孩子**。并不要求所有叶都在最后一层，也不要求每层都是满的。无论树是否平衡，边数公式始终成立。

### 二、用“边的两种计数”求叶数

设 $n_0$ 为叶结点数、$m$ 为内部结点数，则总数 $n=n_0+m$。树有 $n-1$ 条边，这是不依赖孩子数量的性质。另一方面每个内部结点恰有 $k$ 个孩子，每条边都从某个内部结点发出，因此边总数为 $km$。联立：

$$
n_0+m-1=km\quad\Longrightarrow\quad
\boxed{n_0=(k-1)m+1}.
$$

**不把根单独再加一条边**，根没有父边。例：$k=2,m=3$，必有 $n_0=4$；$k=3,m=2$，必有 $n_0=5$。这也解释了满二叉树“叶数等于度为 2 的结点数加 1”的推广形式。

还可写出只用 $n$ 表示的关系：

$$
n=km+1,\qquad m=\frac{n-1}{k},\qquad
n_0=\frac{(k-1)n+1}{k}.
$$

由此知道任意正则 $k$ 叉树的总结点数都满足 $n\equiv1\pmod{k}$，可用于迅速排除不可能的数值。

### 三、高度为 $h$ 的最大规模

根在第 1 层，第 $i$ 层最多 $k^{i-1}$ 个结点。要让总数最大，就让所有非末层结点都产生 $k$ 个孩子：

$$
N_{\max}=\sum_{i=0}^{h-1}k^i
=\frac{k^h-1}{k-1}.
$$

**达到最大值**时，各层结点数是 $1,k,k^2,\ldots,k^{h-1}$，这比“正则”要求更强，是满 $k$ 叉树的形态。

### 四、高度为 $h$ 的最小规模：主干 + 旁支

必须有一条从根到第 $h$ 层的主干，共 $h-1$ 个在主干上的内部结点。每个这样的结点都必须产生**恰好 $k$ 个孩子**：其中 1 个继续向下，另外 $k-1$ 个可直接作为叶子停止展开。因此从单个根结点出发，每向下延伸一层，都被迫新增 $k$ 个孩子，总数为

$$
N_{\min}=1+k(h-1).
$$

例如 $k=3,h=4$，最小结点数 $1+3\times3=10$，最多 $1+3+9+27=40$。最小情况有 3 个内部结点、7 个叶结点；最大情况有 13 个内部结点、27 个叶结点，都满足上面的叶数公式。

### 五、边界、迁移与考场模板

- $h=1$ 时只有一个根兼叶，两个式子都给 1。
- 只有“**最多有 $k$ 个孩子**”时，最小可变为一条单链的 $h$ 个结点；题设的“非叶**恰有** $k$ 孩子”不能删掉。
- 若给出内部结点数 $m$ 反求可能树高，还需结合每层最多结点数与一条主干至少占 $h-1$ 个内部结点，可推出高度范围；见[原创题](#question-original-141)。
- 这种题先写“总边数 $n-1$”，再按出度求边数，比画很多示意图稳定得多。

</ExamExplanation>

</ExamSolution>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

某正则 $k$ 叉树中所有非叶结点都恰好有 $k\ge2$ 个孩子，根所在层为第 1 层，高度为 $h$。现已知 $k=3$ 且非叶结点数为 $m=6$。

1. 求叶结点数和总结点数。
2. 求该树可能达到的**最小高度和最大高度**，说明两端均可构造。
3. 推出一般 $m\ge0$、$k\ge2$ 时最小高度、最大高度公式（可以给出不依赖浮点对数的整数判定形式），并辨析“正则”与“每层全满”。

<ExamSolution>

<ExamAnswer>叶结点数 $L=(3-1)\cdot6+1=\boxed{13}$；总结点数 $n=3\cdot6+1=\boxed{19}$。最小高度 $\boxed{4}$，最大高度 $\boxed{7}$。一般情况下 $h_{\min}$ 是满足 $1+k+\cdots+k^{h-2}\ge m$ 的最小 $h$（$m=0$ 时 $h=1$），等价于 $1+\lceil\log_k((k-1)m+1)\rceil$；$h_{\max}=m+1$。</ExamAnswer>

<ExamExplanation>

### 一、结点数先用出度求和

有 6 个内部结点，每个都发出 3 条边，故总边数 $18$；树结点数 $18+1=19$，于是叶数 $19-6=13$：

$$
n=km+1=19,\qquad L=(k-1)m+1=13.
$$

这些数是**确定的**，不会随着不同树高而改变；变化的是内部结点在各层的分布。

### 二、最小高度：尽可能让内部结点铺满前面各层

若树高为 $h$，最底层（第 $h$ 层）不可能有内部结点，否则将产生第 $h+1$ 层。因此内部结点最多布置在第 1 至第 $h-1$ 层，其容量上界为

$$
m\le 1+k+k^2+\cdots+k^{h-2}
=\frac{k^{h-1}-1}{k-1}.
$$

本题 $k=3$，高度 $h=3$ 时只能容纳最多 $1+3=4$ 个内部结点，容不下 $m=6$。高度 $h=4$ 时内部结点容量是 $1+3+9=13$，容得下。构造举例：根 1 个内部结点；第 2 层的 3 个孩子全是内部结点；第 3 层的 9 个结点中任选 2 个作为内部结点并各长出 3 个孩子，其他保持叶。内部数 $1+3+2=6$，树高 4，叶数是 $13$，因而可实现。

最小高度的等价整数判定：从 $h=1$ 开始，不断乘 $k$ 累积可容纳的内部结点数，直到至少覆盖 $m$，避免浮点对数的舍入误差。

### 三、最大高度：所有内部结点沿一条主干排列

树高 $h$ 必须有一条从根走到最深叶的路径，路径上的前 $h-1$ 个结点都是内部结点，因此

$$
h-1\le m\quad\Longrightarrow\quad h\le m+1.
$$

让 6 个内部结点依次连成一条内部主干，每个主干结点除用于延伸主干的 1 个孩子外，另外两个孩子都直接做叶；最后一个内部结点的 3 个孩子全为叶。这时高度恰为 7，且满足“每个非叶恰有 3 个孩子”。

### 四、一般公式和失分点

当 $m\ge0$、$k\ge2$ 时，

$$
\boxed{h_{\min}=1+\left\lceil\log_k\bigl((k-1)m+1\bigr)\right\rceil},\qquad
\boxed{h_{\max}=m+1}.
$$

对 $m=0$，树仅根一个结点，两者均为 1。对 $m>0$，最小高度只要求内部结点尽可能靠近根结点，不要求整个树在末层填满；最大高度只要求有一条最长内部分支，其他分支尽早终止。

注意：如果把“正则”错认为“满 $k$ 叉树”（各层完全填满），会错误地要求高度固定，进而误判某些 $m$ 不可能出现。题目规定的只是**内部结点孩子个数**，而不是**叶子深度完全一致**。

</ExamExplanation>

</ExamSolution>

## 2017 年第 41 题

<ExamQuestion>

**17. 2017 年第 41 题**

设计一个算法，将给定的表达式树（二叉树）转换为等价的中缀表达式，并通过括号正确反映操作符的计算次序。

例如，下列两棵表达式树：

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2017-41-figure-001.svg" alt="2017 年第 41 题表达式树" />

应分别输出：

```text
(a+b)*(c*(-d))
(a*b)+(-(c-d))
```

二叉树结点定义如下：

```c
typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;
```

要求：

1. 给出算法的基本设计思想；
2. 用 C 或 C++ 描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>以**中序遍历**打印表达式树：先输出左子树，再输出本结点运算符（或操作数），最后输出右子树。对**不是整棵树根的非叶结点**，在其对应子表达式外补一对括号；叶结点与根结点无需外层括号。这样可得到题图中的 `(a+b)*(c*(-d))`、`(a*b)+(-(c-d))`。时间复杂度为 $O(n+S)$（$n$ 为结点数，$S$ 为输出字符总数），递归栈为 $O(h)$。</ExamAnswer>

<ExamExplanation>

### 一、为何“普通中序遍历”不够

表达式树的叶结点是操作数，内部结点是运算符；**树形结构本身**定义了计算的先后次序。二元结点 $op$ 对应的值是 `left op right`，因此应该使用“左—根—右”的中序遍历。但单纯串接词元会丢失分组信息：

- 根为 `*`，左孩子为 `+`（孩子为 `a,b`），右孩子为 `c`。直接中序得 `a+b*c`，通常按运算优先级解释为 $a+(b\times c)$；原树要求的是 $(a+b)\times c$。
- 根为 `-`，左叶为 `a`，右子树根为 `-`（叶 `b,c`）。省略括号会得到 `a-b-c`，而原树要求 $a-(b-c)$。即使两个运算符**优先级相同**，右子树上的结合次序也不能随便改变。
- 一元负号 `-` 只使用**右孩子**，表达 `-d` 或 `-(c-d)`；这种结点与二元减法不是一回事。

考试最稳妥的处理不是尝试记住每个运算符的优先级，而是直接给非根、非叶的子表达式加括号。多加的括号虽然可能不够简洁，但能够忠实反映树的计算顺序。

### 二、给出遍历不变量与伪代码

把根结点的深度设为 $0$。递归访问当前结点 `p`：

1. `p == NULL` 直接返回。对根调用时深度为 0。
2. 如果 `p` **不是根且不是叶**，先打印 `(`。
3. 递归打印左子树，接着打印 `p->data`，再递归打印右子树。
4. 与步骤 2 对应，必要时打印 `)`。

此处对任何**内部结点**都一律使用括号，不需要依据优先级判断；对只有右孩子的一元运算符，左递归为空，打印运算符后再打印右孩子，顺序自然正确。题目图中若一元负号的右孩子是叶 `d`，产生 `-d`；若右孩子是 `c-d` 子树，则产生 `-(c-d)`。

### 三、符合给定结点定义的 C 实现

```c
#include <stdio.h>

typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;

// depth == 0 仅在整棵树的根结点成立
void PrintInfix(const BTree *p, int depth) {
    if (p == NULL) return;
    int leaf = (p->left == NULL && p->right == NULL);
    int paren = (depth > 0 && !leaf);

    if (paren) putchar('(');
    PrintInfix(p->left, depth + 1);
    printf("%s", p->data);        // 必须使用 %s，data 是字符串而非单个字符
    PrintInfix(p->right, depth + 1);
    if (paren) putchar(')');
}

void Expression(const BTree *root) {
    PrintInfix(root, 0);
}
```

**手推树图**：第一棵根为 `*`，左子树得到 `(a+b)`，右子树 `c*(-d)` 为非根子表达式，得到 `(c*(-d))`，故完整结果为 `(a+b)*(c*(-d))`。第二棵根为 `+`，左右子树分别产生 `(a*b)`、`(-(c-d))`，故得到 `(a*b)+(-(c-d))`。

### 四、正确性证明和复杂度

归纳命题：`PrintInfix(p,depth)` 输出的文本表达式，其计算树与以 `p` 为根的子树相同；若此结点不是整棵树的根且是非叶，还会将整个子表达式括起来。

- 若 `p` 是叶，直接输出操作数字符串，成立。
- 若 `p` 是内部结点，递归假设保证左右子表达式各自保持原树运算次序，打印中间运算符恢复根结点的运算，必要时的成对括号保证父结点把整段视为一个操作数。

每个结点访问一次；若结点的运算符/操作数字符串长度总和为 $S_0$，输出字符量至多 $S_0+2n$，因此时间为 $O(n+S_0)$（固定长度 `data[10]` 时为 $O(n)$）。最大递归深度为树高 $h$，辅助空间 $O(h)$；不将输出流占用计入辅助空间。**不能写成前序遍历**；若题目改问“最少括号”，则需要引入优先级、结合性以及右子树减法/除法等特殊判断，本题并无此要求。

### 五、举一反三：一元与二元运算的结构约定

算法假定叶是合法操作数，内部结点是允许的运算符；一元负号由 `left==NULL`、`right!=NULL` 表示。若题目把负号统一存成二元减法，或允许右孩子为空的一元后缀操作符，则要先明确结点语义，再设计打印次序。对含负数的数字叶 `-12`，它作为**一个操作数 token** 与包含一元负号结点的表达式树结构也不相同。

</ExamExplanation>

$$
10-(6-2)=6,\qquad (10-6)-2=2.
$$

所以**同一优先级**的二元运算也不能总是丢弃右子树括号。左结合的 `a-b-c` 等价于 $(a-b)-c$，并不等价于 $a-(b-c)$。

$$
(-(7+2))\times3=-9\times3=-27.
$$

### 二、一元负号的建模前提

如果当前结点字符串是 `"-"`，只能靠孩子结构区分语义：两个非空孩子是二元减法，左空且右非空是一元负号。**不能只根据结点文本 `"-"` 判别元数**。真实编译器的 AST 往往另存专门的结点类型（例如 `NEG` 与 `SUB`），这比依赖“左孩子为空”更稳健。

### 三、最小括号是另一个难题

2017 真题要求“通过括号正确反映计算次序”，允许多余括号，因此统一包裹是充分方法。若改成“输出括号数最少”的优化目标，就必须考虑二元运算的优先级、结合性以及除法、减法的右侧子表达式，并且有的代数等价变换会改变浮点舍入结果；不能直接在通用表达式树上采用“优先级相同一律删括号”规则。

## 2020 年第 42 题

<ExamQuestion>

**24. 2020 年第 42 题**

若任一字符的编码都不是其他字符编码的前缀，则称该编码集合具有**前缀特性**。

现有某字符集（字符个数不少于 2）的一组不等长编码，每个字符的编码均为二进制 0、1 序列，最长为 $L$ 位，并具有前缀特性。

请回答：

1. 哪种数据结构适合保存上述具有前缀特性的不等长编码？
2. 基于所设计的数据结构，简述从 0/1 串到字符串的译码过程；
3. 简述判定某字符集的一组不等长编码是否具有前缀特性的过程。

<ExamSolution>

<ExamAnswer>使用**二叉前缀树（Trie/译码树）**。0 走左子树、1 走右子树，合法编码的终点结点保存字符且必须是叶。译码时逐位走树，到叶立即输出字符并返回根；扫描到不存在的边或输入在内部结点结束则报错。验证前缀特性时逐条插入：**中途遇已有编码终点、终点已有孩子、终点重复**都应拒绝。令总编码长度为 $M$，建树并判定时间 $O(M)$，空间 $O(M)$。</ExamAnswer>

<ExamExplanation>

### 一、概念辨析：前缀码、唯一可译码、哈夫曼码

前缀特性要求任意两个**不同字符**的编码 $x,y$，不存在“$x$ 是 $y$ 的真前缀”。例如 `{0,10,110,111}` 是前缀码，而 `{0,01,11}` 不是（`0` 是 `01` 的前缀）。由于每读到一个叶结点就能唯一识别一个字符，前缀码可以**即时译码**，无需试探后续比特。

- **前缀码一定唯一可译码**，但是唯一可译码的编码未必前缀无歧义。
- **哈夫曼编码是构造最小平均码长的典型前缀码方法**，本题并没有要求编码长度最优，不能把“必须用哈夫曼树”当作答案。
- 只按编码长度判断并不充分：即使满足 Kraft 不等式 $\sum_i2^{-l_i}\le 1$，**给定的具体码字**仍可能互为前缀，例如 `{0,01,11}` 的长度分别为 1、2、2，和恰为 1，却违反前缀特性。

### 二、数据结构与合法形态

二叉前缀树中根对应空前缀，向左（位 0）、向右（位 1）各增加一个比特。具有前缀特性的一组**互异非空码字**满足：

1. 仅在码字终点保存字符；该结点必须是叶；
2. 根和其它内部结点均不保存字符；
3. 某些分支可以不存在，并不要求二叉树是满二叉树或每层都有节点。

以 `A=0, B=10, C=110, D=111` 为例：根的左叶是 A；右分支（1）向左到 B，向右继续分出 C 和 D。最大深度即最长编码长度 $L=3$。

### 三、插入时判定所有三类冲突

按任意顺序逐条插入编码 `code`，从根开始：

- **未读完即遇已有终点**：旧码字是新码字前缀，例如先有 `0`，再插入 `01`。
- **读完后终点已经有孩子**：新码字是旧码字前缀，例如先有 `01`，再插入 `0`。
- **读完后终点本身已记录一个字符**：不同字符被赋予相同码字，同样无效。

若三个冲突都不存在，则在终点标记对应字符；不存在的中间结点按需创建。每位最多经过或创建一个结点，所有码字总长度为 $M$，时间为 $O(M)$，最多创建 $M+1$ 个结点，空间 $O(M)$。在第一个冲突处即可判定“否”，无需继续处理。题设字符种类不少于 2，故有效编码非空；若放宽为空码字，除只有一个字符外它必然是其他所有码字的前缀。

### 四、正确的译码流程（包括输入非法的情况）

```text
p = root
for bit in encoded_bits:
    if bit not in {'0','1'}: report invalid
    p = p.child[bit]
    if p == NULL: report invalid path
    if p.has_char:
        output(p.char)
        p = root
if p != root: report truncated / incomplete final codeword
else: success
```

**示例**：`0110111010` 按 `0 | 110 | 111 | 0 | 10` 唯一分割，译得 `ACDAB`。输入 `01101` 可先译出 `A、C`，末尾只剩 `1`（停在内部结点），应该报**末码字不完整**，不能把它默默丢弃。若编码流中出现 Trie 不存在的子边，要立即报“无效码字”。

### 五、为何判定正确；做题技巧

任何前缀冲突只能呈现三种位置关系：“旧串更短”“新串更短”或“等长且相同”；三项插入检查逐一覆盖，所以算法充要。译码的正确性可按已经完整译出的字符个数归纳：每次走到叶时，从上次重置位置至当前的比特恰等于一个码字，因为码字没有更短的合法前缀，所以读到叶就能无回溯地确定一个字符；下一段从根重复。

若编码总比特数为 $B$，译码时间为 $O(B)$、工作空间为 $O(1)$（不计预建的 Trie 与输出缓冲），单个码字的最长下行长度不超过 $L$。若问“最小平均码长”才考虑权值和哈夫曼树；若问“能否即时、唯一译码”，就优先从**前缀冲突 + 叶结点识别**切入。

</ExamExplanation>

</ExamSolution>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

字符 `A,B,C,D` 的二进制编码分别为 `0,10,110,111`。

1. 画出或文字描述其二叉译码树，判定是否有前缀特性；
2. 译码 `0110111010`，并判断 `01101` 能否构成**完整**的编码串；
3. 另一套码集为 `{0,01,11}`。计算其 Kraft 和 $\sum_i2^{-l_i}$，由此可以直接断言这套具体编码具有前缀特性吗？
4. 解释即使码字长度符合 Kraft 不等式，也不能跳过哪些检查。

<ExamSolution>

<ExamAnswer>第一套码集具有前缀特性：根左叶为 A，右侧先分出 B，再分出 C、D。`0110111010` 译码为 `ACDAB`；`01101` 是不完整编码串。第二套码集 Kraft 和为 $1/2+1/4+1/4=1$，但 `0` 是 `01` 的前缀，所以**不具有**前缀特性。</ExamAnswer>

<ExamExplanation>

### 一、逐位向树中插入的形态

```text
       root
       /  \\
      0    1
      A   / \\
         0   1
         B  / \\
            0   1
            C   D
```

这里图中 `0/1` 表示所走的边；可在实际结点里只存字符标记。A 的码字为 `0`，B 为 `10`，C 为 `110`，D 为 `111`，四个字符都在叶结点，因而互无前缀关系。注意根右孩子（路径 `1`）**不是字符 B**，B 对应 `10`；如果把 `1` 当成完整码字，就会导致 B、C、D 被同一个前缀截断。

### 二、按“到叶就输出并回根”推演

$$
0110111010=0\mid110\mid111\mid0\mid10,
$$

分别匹配 A、C、D、A、B，输出 `ACDAB`。而 `01101=0\mid110\mid1`，末尾 `1` 停在非叶节点；之前读出的 A、C 并不使整个输入合法，最后必须报“结束时仍在树内部”。

### 三、长度可行性不等于具体码字无冲突

长度 $1,2,2$ 的 Kraft 和为 $1$，说明存在一组**具有这些长度**的二进制前缀码，例如 `{0,10,11}`。但是给定的 `{0,01,11}` 中，`0` 本身和 `01` 互为真前缀，故它不是前缀码。Kraft 不等式是对“某组长度能否实现前缀码”的判据，**不是**对“任意指定码字均不存在前缀冲突”的直接判据。

### 四、通用检查清单

按每条码字建前缀树：走到中间若遇已有字符，表明旧码字是新码字前缀；新码字的终点若已有子节点，表明新码字是旧码字前缀；终点若已存字符，表明重复编码。三个条件均不触发才能成功。构造和检查总复杂度 $O(M)$，$M$ 是全部码字的总比特长度。

</ExamExplanation>
