## 2012 年第 41 题

<ExamQuestion>

**7. 2012 年第 41 题**

有 6 个升序表 $A,B,C,D,E,F$，长度分别为

$$
10,35,40,50,60,200.
$$

要求通过 5 次两两合并，将这 6 个表最终合并成 1 个升序表，并使**最坏情况下的总比较次数最少**。

1. 给出完整合并过程，并求最坏情况下的总比较次数；
2. 根据上述过程，描述 $N$（$N\ge2$）个不等长升序表的最佳合并策略，并说明理由。

<ExamSolution>

<ExamAnswer>

1. 每轮从当前升序表集合中取长度最短的两表合并，合并长度及最坏比较次数依次为：$45/44$、$85/84$、$110/109$、$195/194$、$395/394$，故最坏总比较次数是 $44+84+109+194+394=\boxed{825}$。
2. 对于 $N\ge 2$ 个表，使用**最小堆实现哈夫曼式最优二路归并**：反复取出两个最短表，归并，按合并后长度重新入堆。最小比较次数为最小带权外部路径长度减去 $N-1$。

</ExamAnswer>

<ExamExplanation>

1. **单次二路归并的比较次数为什么是 $m+n-1$？** 设两个非空升序表分别有 $m,n$ 个元素；每比较一次，至少有一个元素被放入结果表。当其中一个表先耗尽时，另一表剩余元素无需比较，直接复制即可。最坏情形直到总共剩一个元素才耗尽某表，于是比较 $m+n-1$ 次。注意这里计数的是**元素间关键字比较**，不是元素移动次数；若两表数据范围完全不交叠，实际比较次数可以少得多。
2. **逐步构造最优归并树。** 初始表长集合为 $\{10,35,40,50,60,200\}$；始终选两最小值，且合并后的新表须重新参与选择。

   | 步骤 | 被合并表长 | 合并后长度 | 本次最坏比较 | 下一轮候选长度 |
   | --- | --- | ---: | ---: | --- |
   | 1 | $10,35$ | $45$ | $44$ | $40,45,50,60,200$ |
   | 2 | $40,45$ | $85$ | $84$ | $50,60,85,200$ |
   | 3 | $50,60$ | $110$ | $109$ | $85,110,200$ |
   | 4 | $85,110$ | $195$ | $194$ | $195,200$ |
   | 5 | $195,200$ | $395$ | $394$ | $395$ |

   原题归并树示意：

   <img src="/img/408/past-exams-large-questions/01-数据结构/assets/2012-41-figure-001.svg" alt="2012 年最佳二路归并树" />

3. **从一次归并到整棵树的转化。** 把每张原始表作为权值等于表长的叶结点；每次合并是一个内部结点，结点权值等于两孩子权值之和。若叶结点 $i$ 深度（根到叶边数）为 $d_i$，则其全部元素会被重复读入、归并 $d_i$ 次，所以各次“合并后总长度”之和为 $\sum_i w_i d_i$，也就是 WPL。共有 $N-1$ 次二路归并，每次最坏比较数比合并后长度少 $1$，因而总最坏比较代价为

   $$
   C_{\max}=\sum_{i=1}^{N}w_i d_i-(N-1).
   $$

   本题 $\mathrm{WPL}=45+85+110+195+395=830$，故 $C_{\max}=830-5=825$。**不要把 830 当作比较次数，也不要误以为五轮只需减 1。**
4. **为什么每次选最短两表？** 在一棵最优二叉归并树中，可以交换叶结点的权值而不改变树形；把更小的权值放到更深位置不会增加 $\sum_iw_id_i$。最深层可以找到两个互为兄弟的叶结点，使最小的两个权值成为兄弟，再将其合并为权值之和的“新叶结点”。余下问题与原问题同型，递归应用这个交换论证即可得到哈夫曼贪心策略。注意不能据此推出“随手选当前两张任意表”也最优。
5. **实现与复杂度。** 初始将 $N$ 个长度建成最小堆，反复弹出两个最小值 $x,y$，令 `cost += x+y-1`，压回 $x+y$；只计算最佳比较次数的调度开销为 $O(N\log N)$ 时间、$O(N)$ 堆空间。若实际合并数据，处理元素的工作量需另按归并树各层累计计算，而非简单声称整题归并只要 $O(N\log N)$。
6. **答题陷阱与推广。** 归并过程中表长会改变，不能一开始把原表两两固定配对；出现相等长度时选择任意一对最小表仍可得到某种最优树；哈夫曼树强调的是**总加权路径长度**，未必是普通树高最低；若题目以“元素写入次数”为代价，则每次合并代价为 $x+y$，合计恰为 WPL，不需要减 $N-1$。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

有四个已排序顺序表，长度依次为 $5,7,9,20$，只允许进行两两合并。已知每次长度为 $m,n$ 的两个非空表合并时，最坏关键字比较次数为 $m+n-1$。

1. 写出比较次数最少的合并顺序，计算最坏总比较次数及累计元素写入次数（假定每次生成的新表全部写入一次）。
2. 有人先合并 $5$ 与 $20$、再合并 $7$ 与 $9$，最后合并两结果。计算其两种代价并评价。
3. 说明为什么“总比较次数”与“写入次数”恰差 $N-1$。

<ExamSolution>

<ExamAnswer>

1. 最优过程：$5+7=12$、$9+12=21$、$20+21=41$；最坏比较次数为 $11+20+40=\boxed{71}$，写入次数为 $12+21+41=\boxed{74}$。
2. 错误顺序：$5+20=25$、$7+9=16$、$25+16=41$；比较次数为 $24+15+40=\boxed{79}$，写入次数为 $25+16+41=\boxed{82}$，均较最优多 $8$。
3. 四张表完成归并恰有三次合并，每次最坏比较次数都比该次写入长度少 $1$。

</ExamAnswer>

<ExamExplanation>

1. 用最小堆或有序表维护当前长度，选 $5,7$ 之后必须把 $12$ 与剩下的 $9,20$ 再比较，所以第二步取 $9,12$，而不是机械地只配对最初输入顺序。
2. 合并代价若以写入次数计，实际上就是各内部结点权值之和，即 $\mathrm{WPL}$；若以最坏关键字比较计，则为 $\mathrm{WPL}-(N-1)$。本题 $N=4$，所以两者差 $3$。
3. 多花费的代价源于长度 $20$ 的大表过早参加了归并；它在错误策略中参与两轮，而最优策略中只参与最后一轮。一般要让较大的表位于更浅的叶层。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

五张非空升序表的长度为 $1,1,2,5,9$。要求最坏比较次数最少，同时关注哈夫曼归并树中叶子的深度。

1. 给出最优二路归并顺序、每轮合并代价以及总最坏比较次数。
2. 计算这棵归并树的带权路径长度（WPL），核对它与比较次数的关系。
3. 当存在相同长度时，是否必须选某一个固定编号的表？若改为“三路同时归并”，能否直接使用每轮 $m+n-1$ 的比较公式？

<ExamSolution>

<ExamAnswer>

1. 一种最优方案：$1+1=2$，$2+2=4$，$4+5=9$，$9+9=18$。四轮最坏比较分别为 $1,3,8,17$，合计 $\boxed{29}$。
2. $\mathrm{WPL}=2+4+9+18=\boxed{33}$，故 $33-(5-1)=29$。
3. 选取任意一组当前两个最小权值均可；三路合并过程的关键字比较算法不同，不能照搬二路归并的 $m+n-1$ 公式。

</ExamAnswer>

<ExamExplanation>

1. 两个长度为 $1$ 的表最先合并为 $2$；此时存在两张长度为 $2$ 的表（原表和新表），这两者正好是当前最短两张表，继续合并为 $4$。接下来候选为 $4,5,9$。
2. 虽然两个 $9$ 分别来自原表和中间表，但在最后一步只需把它们归并，且哈夫曼算法不需要规定同长度节点的固定先后。不同的合法平局选择可能得到不同形状的最优树，但总代价相同。
3. 原题给出的每轮最坏比较数上界，来自**两个**升序表的二路归并。三路归并会涉及选择三个表头中的最小者，代价模型必须重新声明，不能直接套用二路比较公式，也不能未经论证直接认为三路哈夫曼树一定同样最优。

</ExamExplanation>

</ExamSolution>

## 2014 年第 41 题

<ExamQuestion>

**11. 2014 年第 41 题**

二叉树的带权路径长度（WPL）是二叉树中所有叶结点的带权路径长度之和。给定一棵二叉树 $T$，采用二叉链表存储，其中叶结点的 `weight` 域保存该结点的非负权值。设 `root` 为指向 $T$ 根结点的指针，请设计求 $T$ 的 WPL 的算法。

要求：

1. 给出算法的基本设计思想；
2. 使用 C 或 C++ 语言给出二叉树结点的数据类型定义；
3. 根据设计思想描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>

1. 以根结点深度 $0$ 为起点，深度优先遍历二叉树；只在遇到叶结点时把 `weight * depth` 累加到结果中。
2. 用包含 `weight`、`lchild`、`rchild` 的二叉链表结点表示。
3. 可用带深度参数的递归函数计算，时间复杂度 $O(n)$、递归辅助空间 $O(h)$（$n$ 为结点数，$h$ 为根到最深叶结点的结点层数）。

</ExamAnswer>

<ExamExplanation>

1. **定义与深度约定。** 设叶结点集合为 $L$，叶结点 $v$ 的权值为 $w(v)$，根到它经过的**边数**为 $d(v)$。则二叉树的带权路径长度为

   $$
   \operatorname{WPL}(T)=\sum_{v\in L}w(v)d(v).
   $$

   因此根深度为 $0$；单结点树既是根又是叶，WPL 为 $w\times 0=0$。如果把根所在层记为“第 $1$ 层”，需要在程序里转化成深度 `level-1`，否则所有叶权之和会被错误地多加一次。
2. **从定义直接写递归。** ①空树没有叶贡献，返回 $0$；②叶结点贡献为 $w\times d$；③内部结点自己不计入 WPL，返回左右子树在深度 $d+1$ 下的贡献之和。这里题目只保证叶结点的 `weight` 域有意义，**绝不可把每个内部结点的权值也乘深度求和**。
3. **完整 C 实现。** 本实现统一使用 `BiTNode` 和 `lchild/rchild`，并把累加结果定义为 `long long`，减轻常见的 `int` 求和溢出风险（若输入更大仍要根据题意检查范围）。

```c
#include <stddef.h>

typedef struct BiTNode {
    int weight;
    struct BiTNode *lchild;
    struct BiTNode *rchild;
} BiTNode;

long long WPLCore(const BiTNode *p, int depth) {
    if (p == NULL) return 0;
    if (p->lchild == NULL && p->rchild == NULL)
        return (long long)p->weight * depth;
    return WPLCore(p->lchild, depth + 1)
         + WPLCore(p->rchild, depth + 1);
}

long long WPL(const BiTNode *root) {
    return WPLCore(root, 0);
}
```

4. **用实例验算。** 若根左孩子是权值 $2$ 的叶（深度 $1$），右孩子为内部结点，右子树两叶权值分别为 $3,5$（深度均为 $2$），则 $\operatorname{WPL}=2\times1+3\times2+5\times2=18$。代码恰好在访问这三个叶结点时相加。
5. **正确性说明。** 对子树高度做归纳：空子树无贡献；高度为 $1$ 的叶结点贡献是定义式中的唯一一项；对内部结点，左右叶集合不相交且并起来正好等于该子树的全部叶集合，子树中叶的全局深度由 `depth+1` 正确传递，因此左右递归和就是全树 WPL。
6. **复杂度与常见错误。** 每个结点被访问一次，故时间 $O(n)$。递归同时存在的栈帧数量与最大深度成正比，即 $O(h)$；最坏退化二叉树 $O(n)$，平衡二叉树 $O(\log n)$。关键错误有：根深度从 $1$ 开始；把单孩子结点误判为叶（正确条件是**两孩子都为空**）；在左右子树的空指针上访问域；把哈夫曼算法的“建最优树”混同于本题“给定树求 WPL”。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

给定二叉树：根结点 $R$ 的左孩子为权值 $2$ 的叶结点 $A$，右孩子为内部结点 $B$；$B$ 的左、右孩子分别为权值 $3$ 和 $5$ 的叶结点 $C,D$。规定深度为从根出发的边数。

1. 列出每个叶结点深度，计算 WPL。
2. 若把根的层号定义为 $1$，错误地用 `weight * level` 累加，得到什么结果？与正确 WPL 相差多少？

1. $d(A)=1$，$d(C)=d(D)=2$，故 $\boxed{\mathrm{WPL}=2+6+10=18}$。

<ExamQuestion>

有四个字符，其出现次数（权值）分别为 $2,3,5,7$。需要建立一棵二叉前缀编码树，使所有字符的带权路径长度最小。

1. 按哈夫曼算法给出每一步合并的权值。
2. 求最小 WPL，并给出其中一组合法的二进制前缀编码。
3. 为什么给定二叉树求 WPL 与构造最优哈夫曼树，是两个不同的算法问题？

<ExamSolution>

<ExamAnswer>

1. 合并 $2+3=5$、$5+5=10$、$7+10=17$。
2. 最小 WPL 为 $\boxed{5+10+17=32}$。例如权值 $7,5,2,3$ 可分别编码为 `0`、`10`、`110`、`111`。
3. 前者在已有树上遍历并累加，时间 $O(n)$；后者需要决定树的结构，让权值小的叶通常更深，可以用最小堆反复合并两个最小权值。

</ExamAnswer>

3. 考试容易把两个“哈夫曼”相关题混淆：若题目已经给出结点和左右孩子，直接 DFS/BFS 求和即可；若问“让 WPL 最小”，必须重新构造最优树。两者都用相同的 WPL 定义，但解决步骤不同。

</ExamExplanation>

## 2016 年第 42 题

<ExamQuestion>

**15. 2016 年第 42 题**

若一棵非空 $k$ 叉树（$k\ge 2$）$T$ 中，每个非叶结点都有恰好 $k$ 个孩子，则称 $T$ 为**正则 $k$ 叉树**。

请回答并给出推导过程：

1. 若 $T$ 有 $m$ 个非叶结点，则 $T$ 中有多少个叶结点？
2. 若 $T$ 的高度为 $h$（单结点树的高度 $h=1$），则 $T$ 的结点数最多为多少？最少为多少？

<ExamSolution>

<ExamAnswer>

1. 当非叶结点数为 $m$ 时，叶结点数为 $\boxed{(k-1)m+1}$，总结点数为 $km+1$。
2. 高度定义为根所在层为第 $1$ 层时，最多结点 $\boxed{\frac{k^h-1}{k-1}}$，最少结点 $\boxed{1+k(h-1)}$。$h=1$ 时两式均为 $1$。

</ExamAnswer>

<ExamExplanation>

1. **先用边数守恒建立基本恒等式。** 树的每个非根结点都恰有一条来自父亲的边，若结点数为 $n$，则边数 $e=n-1$；正则 $k$ 叉树每个非叶结点发出恰好 $k$ 条父子边，若有 $m$ 个非叶结点，则 $e=km$。由 $n=m+n_0$ 得

   $$
   m+n_0-1=km,\qquad n_0=(k-1)m+1,\qquad n=km+1.
   $$

   这里“非叶结点的孩子数恰等于 $k$”是不可省略的条件。一般的“最多 $k$ 个孩子”的 $k$ 叉树只能推出 $e\le km$，不能套用等式。
2. **最大规模。** 要达到高度 $h$ 且结点最多，层 $1,2,\dots,h$ 分别填满 $1,k,k^2,\dots,k^{h-1}$ 个结点，从而

   $$
   n_{\max}=1+k+\cdots+k^{h-1}=\frac{k^h-1}{k-1}.
   $$

   等号成立当且仅当 $1$ 至 $h-1$ 层的全部结点均恰有 $k$ 个孩子，形成满层结构。
3. **最小规模。** 高度要保持 $h$，至少要有一条长 $h-1$ 条边的根—叶路径；这条路径上的前 $h-1$ 个结点一定是非叶结点，并且每个必须生成**全部 $k$ 个孩子**。除一名孩子继续向下以外，另外 $k-1$ 名孩子都可立即成为叶，最省结点。共有 $h-1$ 次展开，每次净增加 $k$ 个结点，故

   $$
   n_{\min}=1+k(h-1).
   $$

   不能把答案误写成 $h$：一条简单链除非 $k=1$，否则不满足每个非叶结点都恰有 $k$ 个孩子。
4. **等价结论与边界条件。** 正则 $k$ 叉树的结点总数必满足 $n\equiv1\pmod{k}$；非叶数 $m=(n-1)/k$、叶数 $n_0=n-(n-1)/k$。反过来，当 $n=km+1$ 且 $m\ge0$ 时，可以构造一棵这样的树，但具体树形和高度不由 $n$ 唯一确定。
5. **从结点数反求高度范围。** 对允许构造的 $n=km+1$，由 $n\le(k^h-1)/(k-1)$ 得

   $$
   h\ge\left\lceil\log_k\big((k-1)n+1\big)\right\rceil;
   $$

   由 $n\ge1+k(h-1)$ 得 $h\le (n-1)/k+1=m+1$。最小高度对应尽量铺满每层，最大高度对应每层只有一个结点继续分叉；两界均可取到。
6. **三个高频错误。** ①把“高度为层数”错换成“边数”，造成差 $1$；②把普通 $k$ 叉树误当作正则 $k$ 叉树；③忘记 $h=1$ 的单根树，此时 $m=0,n_0=1$，与全部公式一致。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

**17. 2017 年第 41 题**

设计一个算法，将给定的表达式树（二叉树）转换为等价的中缀表达式，并通过括号正确反映操作符的计算次序。

例如，下列两棵表达式树：

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2017-41-figure-001.svg" alt="2017 年第 41 题表达式树" />

应分别输出：

```text
(a+b)*(c*(-d))
(a*b)+(-(c-d))
```

二叉树结点定义如下：

```c
typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;
```

要求：

1. 给出算法的基本设计思想；
2. 用 C 或 C++ 描述算法，并在关键位置给出注释。

<ExamSolution>

<ExamAnswer>

1. 使用**中序遍历**输出表达式：先递归左子树、输出本结点运算符，再递归右子树；只给**非根的非叶结点**对应的子表达式加一对括号，以不依赖运算符优先级的方式保留原树规定的计算顺序。
2. 对于一元负号，约定其结点左孩子为空、右孩子为操作数或子表达式，遍历时自然形成 `-d` 或 `-(c-d)`。输出结果对应题图的 `(a+b)*(c*(-d))` 与 `(a*b)+(-(c-d))`。

</ExamAnswer>

<ExamExplanation>

1. **为什么必须使用中序而不是先序/后序？** 表达式树的**叶结点**通常是操作数，**内部结点**是运算符：中序 `左—根—右` 生成中缀式；先序 `根—左—右` 生成前缀式；后序 `左—右—根` 生成后缀式。只有中序会把运算符放在相应操作数之间。
2. **为什么普通中序还不够？** 例如树的根为减号、左孩子 `a`、右子树为 `b-c`，简单中序得到 `a-b-c`；按通常左结合运算，这意味着 `(a-b)-c`，与树指定的 $a-(b-c)$ 不同。因此需要显式括号保存子树的结合关系。原题不要求“括号最少”，使用**给所有非根内部结点加括号**的统一方案最不容易漏判优先级、结合性。
3. **一元负号的结构约定是关键。** 题中的 `-d` 可用数据为 `"-"`、左孩子 `NULL`、右孩子 `"d"` 的结点表示；其自身不是叶结点。若负号结点不是根，先打印左括号，再因左孩子为空不输出，输出 `-` 与右子树，最后打印右括号，得到 `(-d)`。例如外面再套乘法得到 `c*(-d)`。**若程序输入采用不同的一元负号表示规则，必须相应调整。**
4. **C 算法（直接输出，不分配新表达式字符串）。** 使用题目给定的 `BTree` 结构，且可支持 `data[10]` 中的多字符操作数。

```c
#include <stdio.h>

typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;

static void PrintInfix(const BTree *p, int depth) {
    if (p == NULL) return;
    int isLeaf = (p->left == NULL && p->right == NULL);
    int needParen = (depth > 0 && !isLeaf);

    if (needParen) putchar('(');
    PrintInfix(p->left, depth + 1);
    fputs(p->data, stdout);       /* 叶：操作数；内部：运算符 */
    PrintInfix(p->right, depth + 1);
    if (needParen) putchar(')');
}

void Expression(const BTree *root) {
    PrintInfix(root, 0);       /* 根的最外层括号省略 */
}
```

5. **逐结点理解题图。** 第一棵树：根 `*` 不加最外括号；左侧 `a+b` 是非根运算子树，输出 `(a+b)`；右侧 `c*(-d)` 整体亦为非根运算子树，输出 `(c*(-d))`。拼接后恰得 `(a+b)*(c*(-d))`。第二棵同理得到 `(a*b)+(-(c-d))`。原图保留：<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2017-41-figure-001.svg" alt="2017 年表达式树图示" />
6. **正确性和复杂度。** 对任意子树归纳：叶只输出操作数；内部结点按中序拼出左表达式、当前运算符、右表达式，对非根内部结点加括号，使父结点把它作为整体操作数。因此输出与树等价。每个结点只访问一次，若每个 `data` 长度均为常数，则时间 $O(n)$，递归空间 $O(h)$；若允许任意长词法单元，时间应更准确写为 $O(n+S)$，其中 $S$ 为所有被输出的字符总数。
7. **考场易错点。** ①把函数命名为 `preorder` 却执行中序，会造成概念错误；②只按运算符优先级添加括号，容易遗漏右结合或一元运算的情况；③给每个叶结点都加括号虽然有时等价，但不符合题目示例中的简洁输出；④如果需要**完全还原相同的语法树**，不要随意利用加法交换律等代数化简删掉括号。

</ExamExplanation>

## 2020 年第 42 题

<ExamQuestion>

**24. 2020 年第 42 题**

若任一字符的编码都不是其他字符编码的前缀，则称该编码集合具有**前缀特性**。

现有某字符集（字符个数不少于 2）的一组不等长编码，每个字符的编码均为二进制 0、1 序列，最长为 $L$ 位，并具有前缀特性。

请回答：

1. 哪种数据结构适合保存上述具有前缀特性的不等长编码？
2. 基于所设计的数据结构，简述从 0/1 串到字符串的译码过程；
3. 简述判定某字符集的一组不等长编码是否具有前缀特性的过程。

<ExamSolution>

<ExamAnswer>

1. 用**二叉前缀树（Trie）**：从根出发，位 `0` 走左边，位 `1` 走右边；字符仅放在对应编码所到达的终止结点。满足前缀特性时所有字符终止结点均为叶。
2. 译码时逐位沿树向下，遇到字符终止结点立即输出并将指针重置为根；遇到不存在的边或扫完后仍停在非根内部结点，应报告编码串非法或不完整。
3. 逐条插入编码构造前缀树：途中若提前遇到已有字符终止结点，则“旧编码是新编码的前缀”；整条编码结束时，若当前结点已有终止标志或仍有孩子，则出现重复或“新编码是旧编码的前缀”。无冲突才符合前缀特性。

</ExamAnswer>

<ExamExplanation>

1. **前缀码、无歧义与即时译码。** “任一编码都不是另一不同字符编码的前缀”保证解码器不必预读未来比特：只要走到某字符的终止结点，这一字符就唯一确定。相比用定长数组列出所有可能二进制串，按前缀共享公共路径的二叉树更适合保存不等长码。注意“不同字符串可以解码成不同字符”不是充分定义：必须检查整组编码的前缀关系；编码为空串时（字符集至少两个字符）也不符合前缀特性。
2. **结点设计。** 每个结点包含 `child[2]` 和字符终止标志 `terminal`，终止标志为真时附带 `symbol`。不必假设所有内部结点都有两个孩子，**普通前缀码允许只有一个分支**；哈夫曼树是更特别的一种常见构造。
3. **伪代码（插入一组码字时即时校验）。**

```text
Insert(code, symbol):
    if code 为空: 报错
    p = root
    for bit in code:
        if p.terminal: 报错     // 旧码字是本码字前缀
        if p.child[bit] 不存在: 新建孩子
        p = p.child[bit]
    if p.terminal: 报错         // 完全重复的编码
    if p.child[0] 或 p.child[1] 存在: 报错 // 新码字是旧码字前缀
    p.terminal = true; p.symbol = symbol
```

   这里“途中”是指读取下一位**之前**检查已到达结点是否为终点。如果只检查最终结点，则会漏掉 `0` 与 `01` 的冲突；如果只检查途中，则会漏掉先插 `01` 后插 `0` 的冲突。
4. **译码伪代码与错误处理。**

```text
Decode(bits):
    p = root
    for bit in bits:
        if p.child[bit] 不存在: 报错（未知编码路径）
        p = p.child[bit]
        if p.terminal:
            输出 p.symbol
            p = root
    if p != root: 报错（最后一段不是完整字符）
```

   若输入 0/1 串由完整编码串拼接而成，则每输出一个字符就回到根；对“输入结束但尚未匹配完整码字”的情况不能强行输出一个字符。
5. **复杂度。** 设有 $r$ 个编码、最长编码长度为 $L$、所有编码长度之和为 $M$，插入与前缀校验总时间 $O(M)$，建立的树结点数至多 $M+1$，空间 $O(M)$。译码长度为 $B$ 的比特串需 $O(B)$ 时间（输出字符的成本另计），只需当前树指针以外的常数工作空间；树本身的存储开销不算临时工作空间。
6. **判定与构造的边界。** 若已有编码 `00` 再插入 `0`，最终停在已有子树的内部结点，冲突；若已有编码 `0` 再插 `00`，提前遇到终止结点，冲突；若两不同字符共享完全相同的编码，重复，也冲突。不要把“任何合法前缀码”误认为“必定是最优哈夫曼编码”；最优性还需结合字符频率。

</ExamExplanation>

</ExamSolution>

1. 具有前缀特性；四个编码均对应树的叶结点。
2. 分割为 `0|110|10|111|0`，译码结果为 $\boxed{ACBDA}$。
3. 可以先识别字符 $B$（前两位 `10`），末尾单独的 `1` 仅到达内部结点，仍缺少后续位，应报告**截断/码字未完成**；整串不能作为完整合法消息接受。

</ExamAnswer>

<ExamExplanation>

1. `0` 与所有以 `1` 起始的编码互不构成前缀；`10` 不会成为以 `11` 开始的码字的前缀；`110` 与 `111` 最后一位不同，因而无前缀冲突。
2. 解码遇到每个叶立刻回根，因此 `0110101110` 的解码顺序不能按固定码长分段；真正的分割完全由树给出。
3. 一旦读取完 `10` 就已到达 $B$ 的叶，随即回到根；接着读取 `1`，尚未到达 $C$ 或 $D$，所以剩余比特不足。当前已识别的前缀并不意味着完整报文有效。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

考虑两组拟采用的二进制码长：方案甲的三种字符码长为 $1,2,2$；方案乙的三种字符码长为 $1,3,3$。假设每个字符必须有不同且非空的二进制编码。

1. 分别计算两方案的 Kraft 和 $\sum_i 2^{-\ell_i}$，据此判断是否可能构造前缀码。
2. 为可行方案构造一组实际前缀编码，并用前缀树解释它为什么合法。
3. 对具体编码集合 `0`、`01`、`11`，指出冲突；再说明：仅通过 Kraft 和是否足以断言**已给定的具体码字**不存在前缀冲突？

<ExamSolution>

<ExamAnswer>

1. 甲：$2^{-1}+2^{-2}+2^{-2}=1$，可行；乙：$2^{-1}+2^{-3}+2^{-3}=3/4$，亦可行。
2. 甲可取 `0,10,11`；乙可取 `0,100,101`。这些编码均不存在一个码字作为另一码字前缀的情况。
3. `0` 是 `01` 的前缀，集合不合法；Kraft 和只用于给定**码长集合**的可构造性判断，不能替代对**具体码字**的前缀冲突检查。

</ExamAnswer>

<ExamExplanation>

1. 对二进制前缀码，Kraft 不等式 $\sum_i 2^{-\ell_i}\le1$ 是必要条件；对于给定码长的存在性问题，它也是充分条件。所以两组码长都允许某种前缀编码。注意甲的和恰为 $1$ 是可以的，不能误当作“必须严格小于 $1$”。
2. 从深度 $\ell$ 的叶出发，它在深度 $L$ 所占的后代位置数是 $2^{L-\ell}$；这些位置对不同前缀码不能重叠，除以 $2^L$ 就得到 Kraft 不等式的直观来源。
3. 具体集合 `0,01,11` 虽码长也是 $1,2,2$，Kraft 和为 $1$，但 `0` 已经是 `01` 的前缀，所以仍然无效。这一反例说明：**码长可能安排成前缀码，不等于任意按这些长度填写 0/1 就自动合法。**

</ExamExplanation>

</ExamSolution>
