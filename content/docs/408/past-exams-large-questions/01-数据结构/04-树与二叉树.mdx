# 第 4 章 树与二叉树

## 4.2 二叉树基础

<Question id="408-67f846-008" type="essay" tags="来源:2016考研408">

如果一棵非空 $k(k\ge2)$ 叉树T 中每个非叶结点都有k 个孩子，则称T 为正则k 叉树, 回答下列问题并给出推导过程:

(1) 若T 有m 个非叶结点，则T 中的叶结点有多少个？

(2) 若T 的高度为h(单结点的树h = 1)，则T 的结点数最多为多少个? 最少为多少个?

<Solution>

**【解析】**

(1) 由题意得结点总数 $n=n_0+n_k=n_0+m$。这里的 $n_0$ 指的是度为 0 的结点，也就是叶子结点；$n_k$ 为度为 $k$ 的结点，由题意得到非叶结点的度均为 $k$，所以 $m=n_k$。

根据树的结点总数与度的关系可得边数 $e=n-1=mk$。结点的度就是结点孩子的个数，每个孩子都通过一条边与父结点连接，即结点的度就是该结点连接孩子结点的边数。题目中“每个非叶结点都有 $k$ 个孩子”告诉我们每个结点都有 $k$ 条边来连接孩子结点。又有 $m$ 个非叶节点，所以树有 $mk$ 条边。由上述公式，可得叶结点个数：$n_0=(k-1)m+1$。

{/* 原文“每个结点都有 k 条边”应限于非叶结点，此处保留原文。 */}

(2) ① 结点数最多的情形：除第 $h$ 层外，其余层都是度为 $k$ 的结点，第 $h$ 层都是叶结点，也就是说树是一个满树，对应结点总数是 $(k^h-1)/(k-1)$。

② 结点数最少的情形：除根结点外，第 2 至 $h$ 层的每层结点数均为 $k$，对应的结点总数是 $1+(h-1)k$。

> **【点评】** 常规题。考查树的数学性质。根据二叉树的数学性质，类推到 $k$ 叉树。

</Solution>

</Question>

## 4.3 二叉树的遍历

<Question id="408-67f846-018" number={2} type="essay" tags="来源:2017考研408">

设计算法,将给定的表达式树(二叉树) 转换为等价的中缀表达式(通过括号反映操作符的计算次序) 并输出。例如, 当下列两棵表达式树作为输入时, 输出的等价中缀表达式分别为a+b* c* -d 和a*b + - c-d 。二叉树结点定义如下:

```c
typedef struct node {
    char data[10];          // 存储操作数或操作符
    struct node *left;      // 指向左子树
    struct node *right;     // 指向右子树
} BTree;
```

![](/img/questions/408/data-structure-p032-02.svg)

要求:

(1) 给出算法的基本设计思想。

(2) 根据设计思想，采用C 或C++ 语言描述算法，关键之处给出注释。

<Solution>

**【解析】**

(1) 算法思想：表达式树的中序遍历序列加上必要的括号，即为等价的中缀表达式。对二叉树进行中序遍历：访问叶结点时输出操作数；访问分支结点时，在其左右子树的遍历结果之间输出操作符。关键在于括号的添加规则：根结点对应的最外层表达式不加括号；每个非根分支结点所代表的子表达式在输出时用一对括号包裹，以反映其运算优先级。叶结点是操作数，不加括号。这样既能保证运算次序正确，又不会出现多余括号。

(2) 代码如下：

```cpp
void infix(BTree* root,int depth = 1) { //depth = 1，表示从根结点开始递归
    if (root == NULL) {
        return;
    }

    if (root -> left == NULL && root -> right == NULL) {
        cout << root -> data; //对于叶子结点，直接打印，不需要添加括号
    } else { //对子表达式先添加左括号
        if(depth > 1) cout << "("; //depth > 1表示表达式最外层不需要加上括号
        //递归方向：分解为对左子表达式 + 操作符 + 右子表达式的求解
        infix(root -> left, depth + 1);
        //非叶结点都是操作符。加括号的操作仅对子表达式进行，所以直接输出操作符
        cout << root -> data;
        infix(root -> right, depth + 1);
        if(depth > 1) cout << ")";
    }
}
```

> **【真题溯源】** 此题不是根据 LeetCode 上的题目改编而来，而是改编自经典教材的习题：《数据结构题集》（严蔚敏、吴伟民编）第 6 章“树和二叉树”，题号 6.51。

> **【点评】** 难题。综合考查二叉树的递归遍历框架改造。这是 408 考试中第 2 次考查二叉树遍历的算法题（2014 年 408 第 41 题是首次考查二叉树的算法题，但本题难度更大）难点主要在于：① 不知道在哪里加括号；② 难以理解递归思想。

</Solution>

</Question>

## 4.6 树与二叉树的应用

<Question id="408-67f846-038" number={3} type="essay" tags="来源:2012考研408">

设有6 个有序表A、B、C、D、E、F, 分别含有10、35、40、50、60 和200 个数据元素,各表中的元素按升序排列。要求通过5 次两两合并, 将6 个表最终合并成1 个升序表, 并在最坏情况下比较的总次数最小。请回答下列问题:

(1) 给出完整的合并过程, 并求出最坏情况下比较的总次数。

(2) 根据你的合并过程, 描述 $N(N\ge2)$ 个不等长升序表的合并策略, 并说明理由。

<Solution>

**【解析】**

(1) 合并长度分别为 $m$ 和 $n$ 的有序表，在最坏的情况下，需要比较 $m+n-1$ 次。最坏的情况对应的场景是：一个表中全部元素都比另一个表所有元素大。例如：可以用 $A=\{1,2,3\}$、$B=\{4,5,6,7\}$ 具体做验证。

{/* 原书此处对最坏情况的描述及例子有误，按原文保留。 */}

要让总比较次数最少，采用构建哈夫曼树的思路：每次合并当前元素个数最少的两个表，让元素个数少的表被合并的次数更多，减少元素个数多的表参与合并的次数，从而降低总比较次数。合并过程如下所示：

| 次数 | 合并过程 | 剩余待合并表（括号里数字指表长度） | 本次最坏比较次数 |
| --- | --- | --- | --- |
| 第 1 次 | 表 A 和表 B 合并 → 表 AB | C(40)、AB(45)、D(50)、E(60)、F(200) | $10+35-1=44$ |
| 第 2 次 | 表 C 和表 AB 合并 → 表 ABC | D(50)、E(60)、ABC(85)、F(200) | $40+45-1=84$ |
| 第 3 次 | 表 D 和表 E 合并 → 表 DE | ABC(85)、DE(110)、F(200) | $50+60-1=109$ |
| 第 4 次 | 表 ABC 和表 DE 合并 → 表 ABCDE | ABCDE(195)、F(200) | $85+110-1=194$ |
| 第 5 次 | 表 ABCDE 和表 F 合并 → 表 ABCDEF | 无 | $195+200-1=394$ |

![对应于合并过程的哈夫曼树](/img/2012-q41-solution.svg)

最坏情况下比较的总次数为：$44+84+109+194+394=825$。

(2) 对于 $n(n\geq 2)$ 个不等长有序表，应采用构建哈夫曼树的合并策略：

① 每次从当前待合并的表中，选取长度最小的两个表进行合并；

② 将合并后的新表放回待合并集合中，重复步骤①，直到只剩一个表为止。

理由是：哈夫曼树的核心思想是让权值（这里指表长）小的节点离根节点更远，权值大的节点离根节点更近。对应到合并中，就是让短表被合并次数更多，长表被合并次数更少，从而使所有合并的总比较次数最小。

**【拓展】** 若每次可以合并 3 个或 4 个有序表，则采用哪种合并策略可以使得总比较次数最少？答案：合并过程类似于外部排序的过程，类似于构建多叉哈夫曼树的思想，具体合并过程可以使用败者树减少比较次数。

**【点评】** 难题。本题其实是“二路归并排序和哈夫曼树”的综合题。命题人在设计此题时也是颇费心思的，出的挺巧妙。本题很容易得 0 分，区分度极高。考场上时间紧张，若考生第一反应想不到“两个有序表合并最坏的场景”，就想不到用哈夫曼树的思想解题。这种一眼看不出考的是哪个考点的题，灵活性很强，要么得 0 分，要么得满分。这种题在近些年的 408 考试中考的少，需要引起考生重视。平时应注意加强对类似题目的练习。在竞成《数据结构考研复习全书》最后一章“专题练习”中，专门设置了对此类题的专题练习，考生可针对性强化训练。

</Solution>

</Question>

<Question id="408-67f846-039" type="essay" tags="来源:2014考研408">

二叉树的带权路径长度(WPL) 是二叉树中所有叶结点的带权路径长度之和。给定一棵二叉树T，采用二叉链表存储, 其结点结构为 `|left|weight|right|`。其中叶结点的weight 域保存该结点的非负权值。设root 为指向T 的根结点的指针，请设计求T 的WPL 的算法, 要求:

(1) 给出算法的基本设计思想。

(2) 使用C 或C++ 语言, 给出二叉树结点的数据类型定义。

(3) 根据设计思想，采用C 或C++ 语言描述算法，关键之处给出注释。

<Solution>

**【解析】**

(1) 算法的基本设计思想：① 二叉树的带权路径长度（WPL）是树中所有叶结点的带权路径长度之和。叶结点的带权路径长度 = 该叶结点的权值 × 根结点到该叶结点的路径长度（路径上的边数），其中叶结点的权值存储在结点结构体的 weight 成员中。

② 求解时，可通过“任意一种二叉树的遍历算法”（本题采用中序遍历）统计每个叶结点的路径长度：遍历时维护一个变量 h，二叉树每向下一层深度 h 加 1，每回溯一层深度 h 减 1（如果用层序遍历算法则不用回溯）；遇到叶结点时，用其权值 weight 与当前深度 h 相乘并累加到总和 WPL 中。遍历完整棵二叉树即可求得 WPL。

(2) 二叉树结点的数据类型定义如下：

```c
typedef struct BiTNode {
    int weight;
    struct BiTNode *left, *right;
} BiTNode, *BiTree;
```

(3) C 语言算法代码实现如下：

```c
void InOrderCalWPL(BiTNode *T,int h,int *wpl) {
    if(T == NULL) {
        return ; // 空结点，递归直接返回
    }
    InOrderCalWPL(T->left,h+1,wpl); //递归遍历左子树，下层深度+1
    if(T->left == NULL && T->right == NULL) {
        *wpl += T->weight * h; // 计算叶结点的带权路径长度
    }
    InOrderCalWPL(T->right, h+1, wpl); //递归遍历右子树，下层深度+1
}

int GetTreeWPL(BiTree root) { //函数调用入口，输入根指针，返回树的WPL
    int wpl = 0; // 初始化wpl为0
    InOrderCalWPL(root,0,&wpl); // 根结点初始深度为0
    return wpl;
}
```

**【注意】** 在子函数 `InOrderCalWPL()` 中，形参 wpl 必须定义成指针，否则就是错的。或者通过引用传参也行。考生若不熟悉 C 语言函数的形参和实参，或者 C++ 中的引用，建议去看下竞成《数据结构考研复习全书》第 1 章【编程基础】部分（在该章 1.5 小节），该章对 408 考试中所需要的前置的编程基础知识进行了补充介绍，助力考生 0 基础入门 408。

**【提示】** ★ ① 408 算法题重在平时积累，难以临时突击速成。建议在学习过程中多总结积累常见代码模板，做到能够独立默写。从 408 算法题型特点来看：二叉树、链表、图的算法题套路性强，基本都是在经典算法代码基础上做一些改造。数组相关的算法题考的更灵活，最优解往往技巧性强难以想到，但暴力解法往往思路直观，容易想到，写出暴力解能拿一半分数左右。

② 本题考了“二叉树的带权路径长度”，类似考点还有：求二叉树高度或宽度、完全二叉树的判定、平衡二叉树的判定、完全二叉树父子结点之间的关系、求公共祖先等。这些考点建议考生在草稿纸上动手写一遍代码。

③ 本题还有层序遍历的解法，考生可自己动手写一遍，限于篇幅，这里不再列举更多解法。另外，官方公布的此题的评分标准答案中，还提供了一种“基于后序遍历、借用非叶结点的 weight 域保存孩子结点中 weight 域值之和”的解法，比较巧妙，建议考生去看看。教育部每年都会公布统考科目真题的标准答案，竞成将历年官方公布的 408 评分标准答案（2009～至今），整理在竞成《408 评分标准与官方答案》这本书中。

**【真题溯源】** LeetCode 上有道类似的题，建议考生动手练习：

**【点评】** 常规题。考查二叉树遍历算法的应用。本题无论用二叉树的先序遍历、中序遍历、后续遍历或层序遍历，任意一种均可。从如今备考 408 的视角来看，这个很基础、偏简单。但这是从 2009～2014，这 6 年来，408 中首次考查树的算法题。在此之前，408 算法题都是考查数组和链表操作。可能当年备考 408 的同学，408 算法题的备考重心都放在“数组和链表”上，忽略了对“树和图”相关算法题的准备，也会导致在这种基础的题目上失分。这里再次提醒各位备考 408 的同学，这十几年的 408 考试反复验证了，只要是 408 考纲上的内容，都有可能考查（考试是“抽查”），不要放弃对考纲上某些考点的学习。

<Question id="408-67f846-040" type="essay" tags="来源:2020考研408">

若任一字符的编码都不是其他字符编码的前缀，则称这种编码具有前缀特性,现有某字符集(字符个数≥2) 的不等长编码, 每个字符的编码均为二进制的0,1 序列, 最长为L 位, 且具有前缀特性。请回答下列问题:

(1) 哪种数据结构适宜保存上述具有前缀特性的不等长编码？

(2) 基于你所设计的数据结构, 简述从0/1 串到字符串的译码过程。

(3) 简述判定某字符集的不等长编码是否具有前缀特性的过程。

<Solution>

**【解析】**

(1) 适宜用二叉树保存上述具有前缀特性的不等长编码。用二叉树中的叶结点保存字符，字符编码规则为：从根结点开始，左分支路径记为 0，右分支路径记为 1，从根结点到叶结点路径上、由 0 和 1 组成的字符串，即为该叶结点保存字符的编码。

(2) 从左到右依次遍历 0/1 串中的各位。从二叉树的根结点开始，若 0/1 串中的当前位为 0，则查找左子树；若 0/1 串中的当前位为 1，则查找右子树，直到遍历到叶结点，输出叶结点中保存的字符，并从根结点开始重复此过程。直到遍历完整个 0/1 串，则译码完成。此过程中输出的字符串即为 0/1 串表示的字符串。

(3) 这个过程描述很繁杂，这里直接原文摘抄官方给出的参考答案：

二叉树既可用于保存各字符的编码，也可用于检测编码是否具有前缀特性。判定编码是否具有前缀特性的过程，同时也是构建二叉树的过程。初始时，二叉树中仅含有根结点，其左子指针和右子指针均为空。依次读入每个编码 C，建立 / 寻找从根开始对应于该编码的一条路径，过程如下：对每个编码，从左至右扫描 C 的各位，根据 C 当前位（0 或 1）沿结点的指针（左子指针或右子指针）向下移动。当遇到空指针时，创建新结点，让为空的指针指向该新结点并继续移动。沿指针移动过程中，可能遇到三种情况：

① 若遇到了叶结点（非根），则表明不具有前缀特性，返回；

② 若在处理 C 的所有位的过程中，均没有创建新结点，则表明不具有前缀特性，返回；

③ 若处理 C 的最后一个编码位时创建了新结点，则继续验证下一个编码。

若所有编码均通过验证，则编码具有前缀特性。

**【点评】** 创新题。这题考查前缀编码，在介绍哈夫曼编码时都会介绍这部分内容。第三小问的描述比较麻烦，比较难表达清楚。

</Solution>
