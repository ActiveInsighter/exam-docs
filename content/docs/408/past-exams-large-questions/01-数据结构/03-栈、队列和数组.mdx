## 2019 年第 42 题

<Question
  id="408-ds-large-2019-42"
  type="essay"
  tags="来源:2019考研408, 科目:数据结构, 章节:栈队列数组, 考点:循环链式队列, 难度:较难"
>

请设计一个队列，满足以下要求：

1. 初始时队列为空。
2. 入队时允许增加队列占用的空间。
3. 出队后，出队元素原来占用的空间可以重复使用，即整个队列已经申请的空间只增不减。
4. 入队和出队操作的时间复杂度始终为 $O(1)$。

请回答：

1. 应选择**链式存储结构**还是**顺序存储结构**？
2. 画出队列的初始状态，并给出**判队空**和「当前已分配空间已满」的条件。
3. 画出第一个元素入队后的状态。
4. 给出入队和出队操作的基本过程。

<Solution>

### 参考答案

**选择循环单链表**，所有已申请结点永久保留在环内（直到整个队列销毁时才释放）。约定：

- `front` 指向当前队头**数据结点**；
- `rear` 指向**下一次准备写入的空闲结点**，不是最后一个有效数据结点；
- 环中始终**至少留一个空闲结点**，因此容量为已申请结点数减 1。

在这组明确的指针语义下：

$$
\boxed{\text{队空}\iff front=rear},
$$

$$
\boxed{\text{现有空间已满，入队需扩容}\iff rear\!\to next=front}.
$$

初始只申请一个结点 $N_0$，令 `N0->next=N0`，`front=rear=N0`。首次入队必先申请 $N_1$，把 $N_1$ 接在 $N_0$ 后面；再将数据写入 $N_0$，令 `rear=N1`、`front=N0`。

### 关键过程：把「逻辑队列」和「物理环」分开

| 概念 | 表示什么 | 出队时的处理 |
| --- | --- | --- |
| 已申请结点 | 环中全部结点（数据区与空闲区） | **不释放**任何结点 |
| 逻辑有效元素 | 从 `front` 起沿 `next` 到 `rear` 前的所有结点 | 只把 `front` 后移 |
| 可复用空闲结点 | 从 `rear` 起到 `front` 前的结点，含 `rear` | 今后 `rear` 到达时可再次写入 |

<Steps>
  <Step>

  ### 初始化：一个结点自成环

  ```text
      +---------+
      |    N0   |---+
      +---------+   |
           ^________|
      front = rear = N0
  ```

  队空条件成立；由于只有一个空闲格，再入队前**必须增加结点**。初始状态与题图一对应。

  </Step>
  <Step>

  ### 第一次入队：先扩容再写入

  在 `rear` 后面插入一个新结点 `N1`：

  ```text
  front=N0 [数据 x]  -->  rear=N1 [空]  -->  N0
  ```

  此时环有两个结点，只有 `N0` 含有效元素；与题图二一致。

  </Step>
  <Step>

  ### 后续操作：始终复用空闲格

  - **入队**：若 `rear->next==front`，先在 `rear` 后新增一个结点；将新数据写入旧 `rear`，然后 `rear=rear->next`。
  - **出队**：若 `front==rear`，报告队空；否则输出 `front->data`，再执行 `front=front->next`，**不释放旧结点**。

  </Step>
</Steps>

### C 语言实现

```c title="循环链式队列：结点只扩容、不逐次释放" lineNumbers
#include <stdlib.h>

typedef struct QNode {
    int data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front;          // 首个有效数据位置；空时与 rear 相等
    QNode *rear;           // 下一空位置（常驻空闲格）
} CircleQueue;

int InitQueue(CircleQueue *q) {
    if (q == NULL) return 0;
    QNode *p = (QNode *)malloc(sizeof(QNode));
    if (p == NULL) return 0;
    p->next = p;
    q->front = q->rear = p;
    return 1;
}

int IsEmpty(const CircleQueue *q) {
    return q->front == q->rear;
}

int EnQueue(CircleQueue *q, int value) {
    if (q == NULL || q->front == NULL) return 0;
    if (q->rear->next == q->front) { // 满的是已申请容量，不是逻辑操作失败
        QNode *p = (QNode *)malloc(sizeof(QNode));
        if (p == NULL) return 0;
        p->next = q->rear->next;
        q->rear->next = p;           // 恰好插在 rear 后方
    }
    q->rear->data = value;
    q->rear = q->rear->next;
    return 1;
}

int DeQueue(CircleQueue *q, int *out) {
    if (q == NULL || out == NULL || q->front == NULL || IsEmpty(q))
        return 0;
    *out = q->front->data;
    q->front = q->front->next;       // 旧队头变成以后可复用的空格
    return 1;
}

void DestroyQueue(CircleQueue *q) {
    if (q == NULL || q->front == NULL) return;
    QNode *first = q->front, *p = first->next;
    while (p != first) {
        QNode *next = p->next;
        free(p);
        p = next;
    }
    free(first);
    q->front = q->rear = NULL;
}
```

### 不变量、正确性与复杂度

**环形分区不变量：**队列有效元素按 FIFO 顺序恰位于从 `front` 依 `next` 行至 `rear` 之前的结点中；`rear` 以及之后直到 `front` 前的结点均为空闲区。

- **入队无扩容**：把 `rear` 这个空结点改为有效元素，`rear` 顺移后仍指向空结点。
- **入队需扩容**：若 `rear->next==front`，当前只有 `rear` 一格空闲；先在它后面接新结点，写入旧 `rear`，新 `rear` 就有空格，不会覆盖队头。
- **出队**：移走的是有效序列的第一项，旧 `front` 留在环内，保证之后仍可复用并继续满足 FIFO。

每次入队最多新建一个结点、修改常数个指针；每次出队只改一次队头指针，因此**在通常考研链式结构分析中，把一次结点分配视为 $O(1)$，单次操作都是 $O(1)$**。若生命周期内逻辑队列最多同时有 $H$ 个元素，则恰至多申请 $H+1$ 个结点，整个销毁过程耗时 $O(H)$。

<Callout type="warn" title="必须声明指针定义">

这里 `rear` **不是尾数据结点**。如果换成「`rear` 指尾元素」的定义，空队列与满队列的判断式也会改变。不要把 `front==rear` 与 `rear->next==front` 不加说明地套在任意循环链队列上。

</Callout>

</Solution>
</Question>

### 原创强化训练 1 · 可复用队列的完整状态追踪

<Question
  id="408-ds-large-2019-42-ext1"
  type="essay"
  tags="来源:原创强化训练, 科目:数据结构, 考点:循环链队列模拟, 难度:中等"
>

采用真题队列：`front` 指队头，`rear` 指下一空结点；初始只有自环结点 `N0`，以后新增结点依次命名为 `N1,N2,...`。

按顺序执行：

```text
EnQueue(10), EnQueue(20), DeQueue(), EnQueue(30),
DeQueue(), DeQueue(), EnQueue(40)
```

要求：

1. 每步写出当前的 `front`、`rear`、有效队列内容及**历史累计申请结点数**。
2. 给出三次出队的返回值，并说明最后一次入队为何无需扩容。
3. 说明「队空」是否意味着「已申请空间已满」，并给出准确的判断。

<Solution>

### 参考答案

| 操作 | `front` | `rear` | 队列内容（从队头到队尾） | 累计结点数 |
| --- | --- | --- | --- | ---: |
| 初始 | `N0` | `N0` | `[]` | 1 |
| 入队 10 | `N0` | `N1` | `[10]` | 2 |
| 入队 20 | `N0` | `N2` | `[10,20]` | 3 |
| 出队 10 | `N1` | `N2` | `[20]` | 3 |
| 入队 30 | `N1` | `N0` | `[20,30]` | 3 |
| 出队 20 | `N2` | `N0` | `[30]` | 3 |
| 出队 30 | `N0` | `N0` | `[]` | 3 |
| 入队 40 | `N0` | `N1` | `[40]` | 3 |

三次出队值依次是 **10、20、30**；最终只保存 **40**，已申请结点仍为 **3 个**。

### 推理过程

**开始时**：物理环 `N0->N0`。第一次入队先在 `N0` 后分配 `N1`，随后原 `N0` 写入 10；第二次入队时仅剩 `N1` 空格，因此在 `N1` 后新建 `N2`，环成 `N0->N1->N2->N0`。

**中段复用**：出队 10 后，原结点 `N0` 没有释放，而是进入空闲区。入队 30 时 `rear=N2`，由于 `N2->next=N0` 与 `front=N1` 不相同，故直接在 `N2` 写入 30，然后令 `rear=N0`。

**最后入队 40**：虽然 `front==rear==N0`（队空），但 `rear->next==N1`，**并不等于 `front`**。这意味着环上还有其它可用空格，可直接写入 `N0`，前移尾指针为 `N1`。

<Callout type="idea" title="核心辨析">

初始只有 1 个结点时，可以同时满足队空与「需扩容」；申请到多个结点以后，**队空不意味着一定要扩容**。两种状态由不同条件描述，不能互相替换。

</Callout>

</Solution>
</Question>

### 原创预测训练 2 · 多队列共享回收结点池

<Question
  id="408-ds-large-2019-42-ext2"
  type="essay"
  tags="来源:原创预测训练, 科目:数据结构, 考点:空闲链表, 考点:存储复用, 难度:较难"
>

某系统维护两个 FIFO 队列 `Q1`、`Q2`，两者必须**共享同一个空闲结点池**。任何队列出队后，结点不得立即还给系统，而要放入空闲链表；任一队列入队时，优先从公共池取结点，池空时才新申请结点。

1. 设计队列及池的数据结构，列出内存所有权不变量。
2. 使用 C 实现入队、出队，要求每次操作仅修改常数个指针。
3. 若 `Q1` 曾入队 3 次后全部出队，紧接着 `Q2` 入队 3 次，最少总计申请多少个数据结点？说明时间复杂度和空间复杂度。

<Solution>

### 参考答案

每个队列维护 `first/last`，池维护单链表头指针 `freeList`。**每个物理结点在任何时刻恰好归属 `Q1`、`Q2`、`freeList` 之一**。入队优先从池首摘除再尾插，出队从队首摘除并插到池首，二者只需 $O(1)$ 指针操作。

```c title="两个队列共享结点池" lineNumbers
#include <stdlib.h>

typedef struct PoolNode {
    int data;
    struct PoolNode *next;
} PoolNode;

typedef struct {
    PoolNode *first, *last;
} PoolQueue;

typedef struct {
    PoolNode *freeList;
} Pool;

int PoolEnQueue(Pool *pool, PoolQueue *q, int value) {
    if (!pool || !q) return 0;
    PoolNode *p;
    if (pool->freeList) {
        p = pool->freeList;
        pool->freeList = p->next;
    } else {
        p = (PoolNode *)malloc(sizeof(PoolNode));
        if (!p) return 0;
    }
    p->data = value;
    p->next = NULL;
    if (q->last) q->last->next = p;
    else q->first = p;
    q->last = p;
    return 1;
}

int PoolDeQueue(Pool *pool, PoolQueue *q, int *out) {
    if (!pool || !q || !out || !q->first) return 0;
    PoolNode *p = q->first;
    *out = p->data;
    q->first = p->next;
    if (!q->first) q->last = NULL;
    p->next = pool->freeList;  // 从有效队列迁入公共池
    pool->freeList = p;
    return 1;
}
```

### 不变量证明

- `first` 始终是逻辑队头，`last` 始终是逻辑队尾，非空队列的 `last->next=NULL`；队空时二者均为 `NULL`。
- 从公共池取出结点后，先改写 `p->next=NULL` 再加入队尾，以免把池中剩余结点串进有效队列。
- 结点出队后在同一操作中**脱离旧队列并进入空闲池**，不存在一个结点被两条队列同时使用的情形。

样例先使 `Q1` 的有效占用达到 3，需分配 3 个结点；全数出队后这 3 个结点进入公共池，`Q2` 的 3 次入队直接复用它们，**历史总申请数仍为 3**。

若历史时刻两条队列有效结点数之和的最大值为 $H$，且公共池最初为空，则历史总申请结点数恰为 $H$；故占用空间 $O(H)$。每次入队出队均为 $O(1)$（单结点分配按算法抽象模型记 $O(1)$）。

<Callout type="warn" title="与真题结构的不同">

真题的单队列使用「整环结点不释放，头尾在环上绕行」；本题的两个队列使用**各自的线性有效链表 + 一个共享空闲链表**。二者都复用历史结点，但不能把真题 `front/rear` 的判空判满公式原样移植过来。

</Callout>

</Solution>
</Question>

## 2026 年第 42 题

<Question
  id="408-ds-large-2026-42"
  type="essay"
  tags="来源:2026考研408, 科目:数据结构, 章节:栈队列数组, 考点:出栈序列, 考点:卡特兰数, 难度:较难"
>

栈的基本操作有入栈和出栈。将序列

$$
1,2,3,\ldots,n
$$

依次入栈，回答下列问题：

1. 当 $n=9$ 时，可以得到出栈序列

   $$
   \{2,3,1,6,4,7,5,9,8\}
   $$

   吗？可以得到出栈序列

   $$
   \{2,3,1,5,6,7,4,9,8\}
   $$

   吗？
2. 假设 $1,2,\ldots,n$ 组成任意出栈序列 $P_1,P_2,\ldots,P_n$。若其中存在 $P_i,P_j,P_k$，且 $i<j<k$，使该出栈序列不能由栈得到，则这三个元素满足怎样的大小关系？
3. 若 $n=4$，则以 $2$ 开头的合法出栈序列共有多少个？
4. 若 $n=k-1$ 时合法出栈序列总数为 $M$。当 $n=k$ 时，以 $1$ 开头的合法出栈序列有多少个？以 $2$ 开头的有多少个？总数是多少？

<Solution>

### 参考答案

1. 第一组 $(2,3,1,6,4,7,5,9,8)$ **不合法**；第二组 $(2,3,1,5,6,7,4,9,8)$ **合法**。
2. 禁止出现按出栈先后顺序排列、满足

   $$
   \boxed{i<j<k,\quad P_j<P_k<P_i}
   $$

   的三个元素，通常称为 **312 型禁形**。一个升序输入的单栈出栈排列合法，当且仅当不存在这种禁形。
3. 当 $n=4$ 时，以 $2$ 开头的合法序列共 **5** 个。
4. 当 $k\ge2$ 且 $C_{k-1}=M$，首元素为 $1$ 的有 **$M$** 个，首元素为 $2$ 的也有 **$M$** 个；全部合法序列数为

   $$
   \boxed{C_k=\frac{2(2k-1)}{k+1}M},
   $$

   其中 $C_k=\frac{1}{k+1}\binom{2k}{k}$ 是第 $k$ 个卡特兰数。

### 第 1 问：用唯一可行的压栈过程作判定

**原则：**下一个要求输出的元素 $x$ 尚未入栈，就必须依次压入到 $x$；若 $x$ 已在栈内却不是栈顶，直接判失败。压入更多更大的数不可能把 $x$ 变到栈顶。

<Tabs items={['序列一：不合法', '序列二：合法']} defaultIndex={0}>
  <Tab value="序列一：不合法">

  目标是 `2,3,1,6,4,7,5,9,8`。先执行：

  ```text
  push 1, push 2, pop 2;
  push 3, pop 3, pop 1;
  push 4, push 5, push 6, pop 6.
  ```

  此时栈自底至顶为 `[4,5]`，下一个目标却是 `4`；**栈顶 5 挡在 4 上方**，不可能合法。前后还出现禁形 $(6,4,5)$，满足 $4<5<6$。

  </Tab>
  <Tab value="序列二：合法">

  目标是 `2,3,1,5,6,7,4,9,8`，下面是一条完整操作记录：

  ```text
  push 1, push 2, pop 2;
  push 3, pop 3, pop 1;
  push 4, push 5, pop 5;
  push 6, pop 6;
  push 7, pop 7, pop 4;
  push 8, push 9, pop 9, pop 8.
  ```

  全部 9 个输入恰好压入一次、弹出一次，输出顺序完全吻合，故合法。

  </Tab>
</Tabs>

### 第 2 问：312 禁形为什么恰好刻画不合法序列？

<Steps>
  <Step>

  ### 必要性：禁形出现，就无法从栈中取出

  假设输出依次出现 $a,b,c$，满足 $a>c>b$。为了先弹出 $a$，输入按 $1,2,\ldots,a$ 的顺序已全部压入过，因此较小的 $b,c$ 也早已入栈。由于 $b<c$，入栈时 $b$ 位于 $c$ 的**下面**。在输出 $b$ 之前没有弹出 $c$，所以栈顶方向仍被 $c$ 挡住，不可能完成。

  </Step>
  <Step>

  ### 充分性：模拟若失败，必可找出禁形

  假设贪心模拟第一次在待输出 $b$ 处失败，此时 $b$ 已入栈且上方有较大元素 $c>b$。由于该 $c$ 已压入而尚未弹出，说明此前某个已经输出的更大元素 $a>c$ 迫使输入先压到至少 $a$，但出栈时没有移走 $c$。于是按输出顺序存在 $a,b,c$，并满足 $a>c>b$。

  因此「模拟失败」必有 312 禁形；不存在这种禁形时一定可模拟成功。

  </Step>
</Steps>

<Callout type="warn" title="别把禁形写成按数值先后的位置关系">

这里的 $i<j<k$ 表示三个元素在**输出序列里出现的先后次序**。数值关系为 $P_j<P_k<P_i$，即第一项最大、第二项最小、第三项居中；不是数值下标的大小次序。

</Callout>

### 第 3 问：四个元素时以 2 开头的序列

首个输出若为 2，则头三个操作必为 `push 1, push 2, pop 2`，余下按合法操作枚举：

$$
\boxed{2134,\quad2143,\quad2314,\quad2341,\quad2431}.
$$

所以共有 **5** 种。比如 `2413` 不合法：弹出 4 后栈顶是 3，不能越过 3 先弹出 1。

### 第 4 问：利用卡特兰数计数

将一次 `push` 记为左括号、一次 `pop` 记为右括号，则合法操作序列满足：**任何前缀的出栈次数不超过入栈次数**。这样的长度为 $2n$、恰含 $n$ 对括号的序列数就是

$$
C_n=\binom{2n}{n}-\binom{2n}{n+1}=\frac{1}{n+1}\binom{2n}{n}.
$$

- **首项为 1**：强制 `push 1,pop 1`，剩余 $2,\ldots,k$ 构成同构的 $k-1$ 个元素问题，因此有 $C_{k-1}=M$ 种。
- **首项为 2**：强制 `push 1,push 2,pop 2`。此后栈中已有 1，剩余 `push 3,...,push k` 与 $k-1$ 次弹出组成一个从高度 1 出发再回到 0 的合法路径；它与规模 $k-1$ 的完整 Dyck 路径一一对应，所以仍有 $C_{k-1}=M$ 种。
- **总数**：

$$
\begin{aligned}
\frac{C_k}{C_{k-1}}
&=\frac{\dfrac{1}{k+1}\binom{2k}{k}}
{\dfrac{1}{k}\binom{2k-2}{k-1}}\\
&=\frac{k}{k+1}\cdot\frac{(2k)(2k-1)}{k^2}\\
&=\frac{2(2k-1)}{k+1}.
\end{aligned}
$$

故 $C_k=\frac{2(2k-1)}{k+1}M$。

### 复习要点

| 问题类型 | 首选工具 | 得分关键 |
| --- | --- | --- |
| 给定一个候选序列，判断可否出栈 | **显式栈模拟** | 按顺序压到目标，再检查栈顶 |
| 问为什么不合法 | **312 禁形 / 首次冲突** | 指出不能越过栈顶元素 |
| 计数所有合法操作序列 | **卡特兰数** | 所有操作前缀必须合法 |
| 限定第一出栈元素 | **强制前缀 + 剩余路径** | 先锁定压栈操作，再计数 |

### 原创强化训练 1 · 线性时间定位第一个出栈矛盾

<Question
  id="408-ds-large-2026-42-ext1"
  type="essay"
  tags="来源:原创强化训练, 科目:数据结构, 考点:栈模拟, 难度:较难"
>

输入顺序固定为 $1,2,\ldots,n$，只允许使用一个初始为空的栈。给出一个由 $1,2,\ldots,n$ 构成的排列 `P`。

1. 设计 $O(n)$ 时间的算法判断它是否为合法出栈序列，并在失败时报告**第一个无法完成输出的下标**。
2. 说明为何「目标元素已经入栈，却不在栈顶」可以立刻返回失败。
3. 判断下面两个 $n=8$ 的候选序列：

   $$
   P=(3,2,1,6,5,4,8,7),
   $$

   $$
   Q=(3,1,2,6,5,4,8,7).
   $$

<Solution>

### 参考答案

$P$ **合法**，$Q$ **不合法**，第一个失败位置是**第 2 个输出**（0-based 下标 1）。$Q$ 的开头 $(3,1,2)$ 已是典型的 312 禁形。

```c title="合法出栈序列判定 + 首次冲突位置" lineNumbers
#include <stdlib.h>

/* 返回 1=合法，0=不合法，-1=分配失败；badPos 为 0-based */
int CheckPopOrder(const int P[], int n, int *badPos) {
    if (!P || n < 0 || !badPos) return 0;
    *badPos = -1;
    int *stack = (int *)malloc((size_t)(n > 0 ? n : 1)
                               * sizeof(int));
    if (!stack) return -1;

    int next = 1, top = -1;
    for (int i = 0; i < n; ++i) {
        int x = P[i];
        if (x < 1 || x > n) {
            *badPos = i; free(stack); return 0;
        }
        while (next <= x) stack[++top] = next++;
        if (top < 0 || stack[top] != x) {
            *badPos = i; free(stack); return 0;
        }
        --top;
    }
    free(stack);
    return 1;
}
```

### 推导

**处理 `P`**：先压 $1,2,3$，再弹 $3,2,1$；压 $4,5,6$，弹 $6,5,4$；压 $7,8$，弹 $8,7$，整个过程合法。

**处理 `Q`**：先压 $1,2,3$ 后弹出 3，此时栈自底至顶为 $[1,2]$，第二个目标是 1，但栈顶为 2。此时压入 4、5 等只会使 1 更深，故可立即报告冲突；输出位置 2（从 1 开始计数）即为第一次失败。

每个值至多入栈一次、出栈一次，**总操作数最多 $2n$ 的数量级**，因此时间 $O(n)$；显式栈最多容纳 $n$ 个元素，额外空间 $O(n)$。

<Callout type="idea" title="从理论判定到可执行判定">

312 禁形提供「为什么不可能」的数学解释，**栈模拟提供最直接的线性算法**；不必真的枚举全部三元组来判定是否合法。

</Callout>

</Solution>

### 原创预测训练 2 · 限制栈容量的合法出栈序列计数

<Question
  id="408-ds-large-2026-42-ext2"
  type="essay"
  tags="来源:原创预测训练, 科目:数据结构, 考点:卡特兰数推广, 考点:动态规划, 难度:拔高"
>

向一个栈按 $1,2,\ldots,n$ 依次压入元素，允许入栈、出栈交错进行，但**栈容量最多为 $c$**（$1\le c\le n$）。一次压栈不得使当前栈高超过 $c$。

1. 设计动态规划，计算在此容量限制下不同的合法**出栈排列**数量，说明状态、转移、边界及复杂度。
2. 计算 $n=4,c=2$ 的答案，并与无容量限制的 $C_4$ 比较。
3. 证明对于 $c=2$，有 $n\ge1$ 时答案为 $2^{n-1}$；当 $c\ge n$ 时，结果为什么退化为普通卡特兰数？

<Solution>

### 参考答案

设 $f(p,q)$ 为已经执行 $p$ 次压栈、$q$ 次出栈时，所有合法操作前缀的数量。栈高为 $p-q$，仅允许

$$
0\le q\le p\le n,\qquad p-q\le c.
$$

初值 $f(0,0)=1$，每个状态尝试合法压栈或出栈：

$$
\begin{cases}
f(p+1,q)\mathrel{+}=f(p,q),&p<n,\ p-q<c;\\
f(p,q+1)\mathrel{+}=f(p,q),&q<p.
\end{cases}
$$

答案是 $f(n,n)$。状态只落在宽度为 $c+1$ 的对角带内，时间、表格空间均为 $O(n(c+1))$；还可以用对角带的滚动存储降低空间。$n=4,c=2$ 时答案为 **8**，而无容量限制的 $C_4=14$。

### 为什么动态规划正确

栈操作的每个合法前缀由两类动作之一扩展：

- **压栈**：输入还没压完，且当前高度小于容量上限，才可以从 $(p,q)$ 转移到 $(p+1,q)$；
- **出栈**：当前栈非空，才可以从 $(p,q)$ 转移到 $(p,q+1)$。

由于输入值的压栈顺序固定，**每个不同的合法压/弹操作序列都唯一确定一个出栈排列**，反过来一个可实现的出栈排列也唯一确定其合法压/弹操作次序，因此计算操作序列数与计算出栈排列数一致。

实现时可使用如下递推表：

```text
f[0][0] = 1
for p = 0..n:
    for q = max(0, p-c)..p:      // q 从小到大
        if p < n and p-q < c:
            f[p+1][q] += f[p][q]
        if q < p:
            f[p][q+1] += f[p][q]
return f[n][n]
```

因转移只向右或向下，按 `p` 递增、`q` 递增遍历可得到拓扑顺序。大规模输入需使用足够宽度的计数类型或高精度整数，避免卡特兰数增长造成溢出。

### $c=2$ 的闭式计数

把压栈记作 `(`、出栈记作 `)`，容量 $2$ 表示合法括号路径的高度始终不超过 2。任何一个**首次回到高度 0 的不可再分块**只能形如

$$
\underbrace{\texttt{(}\ \texttt{()}\ \texttt{()}\ \cdots\ \texttt{()}\ \texttt{)}}_{t+1\text{ 对括号}},\qquad t\ge0.
$$

这意味着：每个块可以有任意正整数数量的括号对，整个序列恰对应把 $n$ 拆成若干正整数的一个**有序拆分**。在 $n$ 个单位之间共有 $n-1$ 个间隙，每个间隙独立决定切分或不切分，因此

$$
\boxed{\text{容量为 2 时的数量}=2^{n-1}}.
$$

于是 $n=4$ 时为 $2^3=8$。若 $c\ge n$，全部 $n$ 个元素同时入栈也不超容，限制不再额外排除合法路径，因此退化为

$$
\boxed{C_n=\frac{1}{n+1}\binom{2n}{n}}.
$$

<Callout type="warn" title="计数模型的三层限制">

始终需要满足 $q\le p$（不能空栈出栈）、$p\le n$（不能压入超过输入数量的元素），并且额外满足 $p-q\le c$（不能超容量）。遗漏任何一条，都会把不合法的操作路径计入答案。

</Callout>

</Solution>
</Question>
