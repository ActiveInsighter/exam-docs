## 2019 年第 42 题

<Question
  id="408-ds-large-2019-42"
  type="essay"
  tags="来源:2019考研408, 考点:循环链式队列"
>

请设计一个队列，满足以下要求：

1. 初始时队列为空。
2. 入队时允许增加队列占用的空间。
3. 出队后，出队元素原来占用的空间可以重复使用，即整个队列已经申请的空间只增不减。
4. 入队和出队操作的时间复杂度始终为 $O(1)$。

请回答：

1. 应选择**链式存储结构**还是**顺序存储结构**？
2. 画出队列的初始状态，并给出**判队空**和「当前已分配空间已满」的条件。
3. 画出第一个元素入队后的状态。
4. 给出入队和出队操作的基本过程。

原题图（保留原路径）：

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2019-42-figure-001.svg" alt="2019 年第 42 题循环链式队列初始状态" />

<Solution>

### 答案速览

1. **选链式存储**，具体用**循环单链表**：结点只增不减，出队后的结点留在环中复用。顺序存储（数组）扩容需整体搬移，做不到「入队始终 $O(1)$」。
2. 约定 `front` 指向队头元素，`rear` 指向**下一个可写入的空闲结点**（环中始终至少留一个空结点）：
   - **队空**：`front == rear`；
   - **已分配空间已满**（再入队需申请新结点）：`rear->next == front`。
3. 初始只有一个结点 $N_0$ 自成环，`front = rear = N0`；第一个元素入队后环中有 $N_0$（存数据）、$N_1$（空），`front = N0`，`rear = N1`。
4. 入队：若满先在 `rear` 后插入新结点；把数据写入 `rear`，`rear = rear->next`。出队：若空则失败；取 `front->data`，`front = front->next`，**不释放结点**。

### 图解：初始状态与第一次入队

<AlgoFigure src="/img/408/past-exams-large-questions/01-数据结构/solutions/2019-42-1" w={740} h={300} alt="2019-42 循环链式队列的初始状态与第一个元素入队后的状态" caption="① 只有一个结点、front 与 rear 重合，此时既是队空也是「满」；② 先在 rear 后插入 N₁ 扩容，再把 x 写入旧 rear（N₀），rear 前进到 N₁" />

为什么要「永远留一个空结点」？如果允许环中结点全部存数据，`rear` 追上 `front` 时会出现 `front == rear`，就与队空的判断式冲突了。留一个空结点后：

- `front == rear` 只可能是「一个元素都没有」；
- `rear->next == front` 表示「只剩 `rear` 这一个空结点」，此时再入队必须先申请结点。

### 图解：一般状态与扩容

<AlgoFigure src="/img/408/past-exams-large-questions/01-数据结构/solutions/2019-42-2" w={740} h={360} alt="2019-42 循环链式队列的一般状态（数据区与空闲区）以及空间已满时在 rear 后插入新结点" caption="蓝色为有效数据（从 front 起到 rear 之前），灰色为可复用的空闲结点；④ 中虚线绿色是新申请并插在 rear 后面的结点" />

环被 `front`、`rear` 切成两段：**数据区**和**空闲区**。出队只是把 `front` 往前推，旧队头结点自动并入空闲区，以后 `rear` 绕回来时会再次写入——这就是「出队空间可重复使用」。

### 入队与出队过程

```c title="2019-42：循环链式队列（结点只增不减）" lineNumbers
#include <stdlib.h>

typedef struct QNode {
    int data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front;   // 队头元素
    QNode *rear;    // 下一个空闲结点
} Queue;

int InitQueue(Queue *q) {
    QNode *p = (QNode *)malloc(sizeof(QNode));
    if (p == NULL) return 0;
    p->next = p;                         // 自成环
    q->front = q->rear = p;
    return 1;
}

int EnQueue(Queue *q, int x) {
    if (q->rear->next == q->front) {     // 只剩 rear 一个空结点：扩容
        QNode *p = (QNode *)malloc(sizeof(QNode));
        if (p == NULL) return 0;
        p->next = q->rear->next;
        q->rear->next = p;               // 插在 rear 之后
    }
    q->rear->data = x;                   // 写入当前空结点
    q->rear = q->rear->next;
    return 1;
}

int DeQueue(Queue *q, int *x) {
    if (q->front == q->rear) return 0;   // 队空
    *x = q->front->data;
    q->front = q->front->next;           // 旧结点留在环中复用
    return 1;
}
```

### 正确性与复杂度

- **不变量**：从 `front` 沿 `next` 走到 `rear` 之前的结点恰好是队列元素（FIFO 顺序），`rear` 起到 `front` 之前都是空闲结点，且 `rear` 本身一定空闲。
- 入队需扩容时，新结点插在 `rear` 之后，写入旧 `rear` 后新的 `rear` 正是这个新结点，不会覆盖队头。
- 入队至多申请一个结点并改常数个指针，出队只改 `front`，二者都是 $O(1)$。若队列同时最多有 $H$ 个元素，整个生命周期最多申请 $H+1$ 个结点。

<Callout type="warn" title="必须先说清指针含义">

本解中 `rear` 指「下一个空闲结点」而不是「队尾元素」。若换成 `rear` 指队尾元素的约定，判空、判满条件都要随之改变，不能把 `front == rear`、`rear->next == front` 套到任何循环链队列上。

</Callout>

</Solution>

### 原创强化训练 1 · 可复用队列的完整状态追踪

<Question
  id="408-ds-large-2019-42-ext1"
  type="essay"
  tags="来源:原创强化训练, 考点:循环链队列模拟"
>

采用真题队列：`front` 指队头，`rear` 指下一空结点；初始只有自环结点 `N0`，以后新增结点依次命名为 `N1,N2,...`。

按顺序执行：

```text
EnQueue(10), EnQueue(20), DeQueue(), EnQueue(30),
DeQueue(), DeQueue(), EnQueue(40)
```

要求：

1. 每步写出当前的 `front`、`rear`、有效队列内容及**历史累计申请结点数**。
2. 给出三次出队的返回值，并说明最后一次入队为何无需扩容。
3. 说明「队空」是否意味着「已申请空间已满」，并给出准确的判断。

<Solution>

### 参考答案

| 操作 | `front` | `rear` | 队列内容（从队头到队尾） | 累计结点数 |
| --- | --- | --- | --- | ---: |
| 初始 | `N0` | `N0` | `[]` | 1 |
| 入队 10 | `N0` | `N1` | `[10]` | 2 |
| 入队 20 | `N0` | `N2` | `[10,20]` | 3 |
| 出队 10 | `N1` | `N2` | `[20]` | 3 |
| 入队 30 | `N1` | `N0` | `[20,30]` | 3 |
| 出队 20 | `N2` | `N0` | `[30]` | 3 |
| 出队 30 | `N0` | `N0` | `[]` | 3 |
| 入队 40 | `N0` | `N1` | `[40]` | 3 |

三次出队值依次是 **10、20、30**；最终只保存 **40**，已申请结点仍为 **3 个**。

### 推理过程

**开始时**：物理环 `N0->N0`。第一次入队先在 `N0` 后分配 `N1`，随后原 `N0` 写入 10；第二次入队时仅剩 `N1` 空格，因此在 `N1` 后新建 `N2`，环成 `N0->N1->N2->N0`。

**中段复用**：出队 10 后，原结点 `N0` 没有释放，而是进入空闲区。入队 30 时 `rear=N2`，由于 `N2->next=N0` 与 `front=N1` 不相同，故直接在 `N2` 写入 30，然后令 `rear=N0`。

**最后入队 40**：虽然 `front==rear==N0`（队空），但 `rear->next==N1`，**并不等于 `front`**。这意味着环上还有其它可用空格，可直接写入 `N0`，前移尾指针为 `N1`。

<Callout type="idea" title="核心辨析">

初始只有 1 个结点时，可以同时满足队空与「需扩容」；申请到多个结点以后，**队空不意味着一定要扩容**。两种状态由不同条件描述，不能互相替换。

</Callout>

</Solution>
</Question>

### 原创预测训练 2 · 多队列共享回收结点池

<Question
  id="408-ds-large-2019-42-ext2"
  type="essay"
  tags="来源:原创预测训练, 考点:空闲链表, 考点:存储复用"
>

某系统维护两个 FIFO 队列 `Q1`、`Q2`，两者必须**共享同一个空闲结点池**。任何队列出队后，结点不得立即还给系统，而要放入空闲链表；任一队列入队时，优先从公共池取结点，池空时才新申请结点。

1. 设计队列及池的数据结构，列出内存所有权不变量。
2. 使用 C 实现入队、出队，要求每次操作仅修改常数个指针。
3. 若 `Q1` 曾入队 3 次后全部出队，紧接着 `Q2` 入队 3 次，最少总计申请多少个数据结点？说明时间复杂度和空间复杂度。

<Solution>

### 参考答案

每个队列维护 `first/last`，池维护单链表头指针 `freeList`。**每个物理结点在任何时刻恰好归属 `Q1`、`Q2`、`freeList` 之一**。入队优先从池首摘除再尾插，出队从队首摘除并插到池首，二者只需 $O(1)$ 指针操作。

```c title="两个队列共享结点池" lineNumbers
#include <stdlib.h>

typedef struct PoolNode {
    int data;
    struct PoolNode *next;
} PoolNode;

typedef struct {
    PoolNode *first, *last;
} PoolQueue;

typedef struct {
    PoolNode *freeList;
} Pool;

int PoolEnQueue(Pool *pool, PoolQueue *q, int value) {
    if (!pool || !q) return 0;
    PoolNode *p;
    if (pool->freeList) {
        p = pool->freeList;
        pool->freeList = p->next;
    } else {
        p = (PoolNode *)malloc(sizeof(PoolNode));
        if (!p) return 0;
    }
    p->data = value;
    p->next = NULL;
    if (q->last) q->last->next = p;
    else q->first = p;
    q->last = p;
    return 1;
}

int PoolDeQueue(Pool *pool, PoolQueue *q, int *out) {
    if (!pool || !q || !out || !q->first) return 0;
    PoolNode *p = q->first;
    *out = p->data;
    q->first = p->next;
    if (!q->first) q->last = NULL;
    p->next = pool->freeList;  // 从有效队列迁入公共池
    pool->freeList = p;
    return 1;
}
```

### 不变量证明

- `first` 始终是逻辑队头，`last` 始终是逻辑队尾，非空队列的 `last->next=NULL`；队空时二者均为 `NULL`。
- 从公共池取出结点后，先改写 `p->next=NULL` 再加入队尾，以免把池中剩余结点串进有效队列。
- 结点出队后在同一操作中**脱离旧队列并进入空闲池**，不存在一个结点被两条队列同时使用的情形。

样例先使 `Q1` 的有效占用达到 3，需分配 3 个结点；全数出队后这 3 个结点进入公共池，`Q2` 的 3 次入队直接复用它们，**历史总申请数仍为 3**。

若历史时刻两条队列有效结点数之和的最大值为 $H$，且公共池最初为空，则历史总申请结点数恰为 $H$；故占用空间 $O(H)$。每次入队出队均为 $O(1)$（单结点分配按算法抽象模型记 $O(1)$）。

<Callout type="warn" title="与真题结构的不同">

真题的单队列使用「整环结点不释放，头尾在环上绕行」；本题的两个队列使用**各自的线性有效链表 + 一个共享空闲链表**。二者都复用历史结点，但不能把真题 `front/rear` 的判空判满公式原样移植过来。

</Callout>

</Solution>
</Question>

## 2026 年第 42 题

<Question
  id="408-ds-large-2026-42"
  type="essay"
  tags="来源:2026考研408, 考点:出栈序列, 考点:卡特兰数"
>

栈的基本操作有入栈和出栈。将序列

$$
1,2,3,\ldots,n
$$

依次入栈，回答下列问题：

1. 当 $n=9$ 时，可以得到出栈序列

   $$
   \{2,3,1,6,4,7,5,9,8\}
   $$

   吗？可以得到出栈序列

   $$
   \{2,3,1,5,6,7,4,9,8\}
   $$

   吗？
2. 假设 $1,2,\ldots,n$ 组成任意出栈序列 $P_1,P_2,\ldots,P_n$。若其中存在 $P_i,P_j,P_k$，且 $i<j<k$，使该出栈序列不能由栈得到，则这三个元素满足怎样的大小关系？
3. 若 $n=4$，则以 $2$ 开头的合法出栈序列共有多少个？
4. 若 $n=k-1$ 时合法出栈序列总数为 $M$。当 $n=k$ 时，以 $1$ 开头的合法出栈序列有多少个？以 $2$ 开头的有多少个？总数是多少？

<Solution>

### 答案速览

1. 序列 $\{2,3,1,6,4,7,5,9,8\}$ **不能**得到；序列 $\{2,3,1,5,6,7,4,9,8\}$ **能**得到。
2. 不能由栈得到，当且仅当存在 $i<j<k$ 使

   $$
   \boxed{P_j<P_k<P_i}
   $$

   即按出栈先后看：**先出最大、再出最小、最后出中间**（「312 型」）。
3. $n=4$ 时以 2 开头的合法序列有 **5** 个：$2134,2143,2314,2341,2431$。
4. 以 1 开头的有 $M$ 个，以 2 开头的也有 $M$ 个；总数为第 $k$ 个卡特兰数

   $$
   C_k=\frac{1}{k+1}\binom{2k}{k}=\frac{2(2k-1)}{k+1}\,M .
   $$

### 第 1 问图解：唯一可行的模拟

<AlgoFigure src="/img/408/past-exams-large-questions/01-数据结构/solutions/2026-42-1" w={760} h={470} alt="2026-42 两个出栈序列的栈模拟：序列一在输出 4 时被 5 挡住，序列二全部成功" caption="每一列是输出目标元素之后的栈（自底向上）。序列 ① 在要输出 4 时，4 被 5 压住" />

判定规则只有一条：**要输出 $x$ 时，若 $x$ 还没入栈，就按顺序一直压到 $x$ 再弹出；若 $x$ 已在栈中但不是栈顶，判失败。**（再压入更大的数只会把 $x$ 埋得更深，不可能补救。）

- 序列 ①：输出 6 时要依次压入 4、5、6 再弹出 6，栈中剩 `[4, 5]`；下一个要 4，但栈顶是 5，失败。
- 序列 ②：`push1 push2 pop | push3 pop | pop | push4 push5 pop | push6 pop | push7 pop | pop | push8 push9 pop | pop`，9 个数各进出一次，全部吻合。

### 第 2 问图解：312 禁形

<AlgoFigure src="/img/408/past-exams-large-questions/01-数据结构/solutions/2026-42-2" w={740} h={260} alt="2026-42 312 禁形：先出最大 a，再出最小 b，后出中间 c 时，c 压在 b 上无法取出 b" caption="出栈顺序 a → b → c，数值 a 最大、b 最小、c 居中：b 被 c 压在下面" />

- **必要性**（出现禁形 ⇒ 不合法）：设出栈顺序中 $a,b,c$ 依次出现且 $a>c>b$。弹出 $a$ 时，比它小的 $b,c$ 都已入栈；因 $b<c$，$b$ 先入栈，位于 $c$ 之下。$c$ 要在 $b$ 之后才出栈，所以轮到 $b$ 时 $c$ 仍挡在上面，矛盾。
- **充分性**（模拟失败 ⇒ 必有禁形）：模拟第一次失败时，待输出的 $b$ 在栈中且其上方有更大的 $c$；$c$ 之所以已入栈，是因为此前输出过某个更大的 $a$。于是 $a,b,c$ 构成禁形。

### 第 3 问图解：以 2 开头的序列

<AlgoFigure src="/img/408/past-exams-large-questions/01-数据结构/solutions/2026-42-3" w={720} h={326} alt="2026-42 n=4 时以 2 开头的合法出栈序列枚举树，共 5 种" caption="第一个输出 2 强制了 push 1、push 2、pop 2，此时栈中只有 1；再按第二个输出分三类" />

### 第 4 问：卡特兰数推导

把 `push` 看成「(」、`pop` 看成「)」，合法操作序列就是 $k$ 对括号的合法匹配（任何前缀中「)」不多于「(」），个数为卡特兰数

$$
C_k=\binom{2k}{k}-\binom{2k}{k+1}=\frac{1}{k+1}\binom{2k}{k}.
$$

- **以 1 开头**：强制 `push 1, pop 1`，剩下 $2,\ldots,k$ 是规模 $k-1$ 的同类问题，共 $C_{k-1}=M$ 个。
- **以 2 开头**：强制 `push 1, push 2, pop 2`，此后栈底留着 1，还剩 $k-2$ 次 push（元素 $3,\ldots,k$）和 $k-1$ 次 pop。在这些剩余操作前补上一个「push 1」，恰好得到元素 $1,3,4,\ldots,k$ 这 $k-1$ 个数的一个完整合法操作序列；反过来，规模 $k-1$ 的任何合法序列都以 push 开头，去掉它就还原回来。二者一一对应，所以也是 $M$ 个。（$k=4$ 时 $M=C_3=5$，与第 3 问吻合。）
- **总数**：

$$
\frac{C_k}{C_{k-1}}=\frac{\frac{1}{k+1}\binom{2k}{k}}{\frac{1}{k}\binom{2k-2}{k-1}}=\frac{2(2k-1)}{k+1}
\ \Longrightarrow\ 
C_k=\frac{2(2k-1)}{k+1}M .
$$

<Callout type="warn" title="易错点">

- 禁形中的 $i<j<k$ 指**出栈先后**，数值关系是 $P_j<P_k<P_i$（大、小、中），不要写反。
- 判断单个序列时用模拟最稳；说明「为什么不行」时指出被挡住的元素或 312 禁形。
- 以 2 开头的个数也是 $M$，不是 $M-1$ 或 $C_k-M$。

</Callout>

</Solution>
</Question>

### 原创强化训练 1 · 线性时间定位第一个出栈矛盾

<Question
  id="408-ds-large-2026-42-ext1"
  type="essay"
  tags="来源:原创强化训练, 考点:栈模拟"
>

输入顺序固定为 $1,2,\ldots,n$，只允许使用一个初始为空的栈。给出一个由 $1,2,\ldots,n$ 构成的排列 `P`。

1. 设计 $O(n)$ 时间的算法判断它是否为合法出栈序列，并在失败时报告**第一个无法完成输出的下标**。
2. 说明为何「目标元素已经入栈，却不在栈顶」可以立刻返回失败。
3. 判断下面两个 $n=8$ 的候选序列：

   $$
   P=(3,2,1,6,5,4,8,7),
   $$

   $$
   Q=(3,1,2,6,5,4,8,7).
   $$

<Solution>

### 参考答案

$P$ **合法**，$Q$ **不合法**，第一个失败位置是**第 2 个输出**（0-based 下标 1）。$Q$ 的开头 $(3,1,2)$ 已是典型的 312 禁形。

```c title="合法出栈序列判定 + 首次冲突位置" lineNumbers
#include <stdlib.h>

/* 返回 1=合法，0=不合法，-1=分配失败；badPos 为 0-based */
int CheckPopOrder(const int P[], int n, int *badPos) {
    if (!P || n < 0 || !badPos) return 0;
    *badPos = -1;
    int *stack = (int *)malloc((size_t)(n > 0 ? n : 1)
                               * sizeof(int));
    if (!stack) return -1;

    int next = 1, top = -1;
    for (int i = 0; i < n; ++i) {
        int x = P[i];
        if (x < 1 || x > n) {
            *badPos = i; free(stack); return 0;
        }
        while (next <= x) stack[++top] = next++;
        if (top < 0 || stack[top] != x) {
            *badPos = i; free(stack); return 0;
        }
        --top;
    }
    free(stack);
    return 1;
}
```

### 推导

**处理 `P`**：先压 $1,2,3$，再弹 $3,2,1$；压 $4,5,6$，弹 $6,5,4$；压 $7,8$，弹 $8,7$，整个过程合法。

**处理 `Q`**：先压 $1,2,3$ 后弹出 3，此时栈自底至顶为 $[1,2]$，第二个目标是 1，但栈顶为 2。此时压入 4、5 等只会使 1 更深，故可立即报告冲突；输出位置 2（从 1 开始计数）即为第一次失败。

每个值至多入栈一次、出栈一次，**总操作数最多 $2n$ 的数量级**，因此时间 $O(n)$；显式栈最多容纳 $n$ 个元素，额外空间 $O(n)$。

312 禁形提供「为什么不可能」的数学解释，**栈模拟提供最直接的线性算法**；不必真的枚举全部三元组来判定是否合法。

</Callout>

### 原创预测训练 2 · 限制栈容量的合法出栈序列计数

<Question
  id="408-ds-large-2026-42-ext2"
  type="essay"
  tags="来源:原创预测训练, 考点:卡特兰数推广, 考点:动态规划"
>

向一个栈按 $1,2,\ldots,n$ 依次压入元素，允许入栈、出栈交错进行，但**栈容量最多为 $c$**（$1\le c\le n$）。一次压栈不得使当前栈高超过 $c$。

1. 设计动态规划，计算在此容量限制下不同的合法**出栈排列**数量，说明状态、转移、边界及复杂度。
2. 计算 $n=4,c=2$ 的答案，并与无容量限制的 $C_4$ 比较。
3. 证明对于 $c=2$，有 $n\ge1$ 时答案为 $2^{n-1}$；当 $c\ge n$ 时，结果为什么退化为普通卡特兰数？

<Solution>

### 参考答案

设 $f(p,q)$ 为已经执行 $p$ 次压栈、$q$ 次出栈时，所有合法操作前缀的数量。栈高为 $p-q$，仅允许

$$
0\le q\le p\le n,\qquad p-q\le c.
$$

初值 $f(0,0)=1$，每个状态尝试合法压栈或出栈：

$$
\begin{cases}
f(p+1,q)\mathrel{+}=f(p,q),&p<n,\ p-q<c;\\
f(p,q+1)\mathrel{+}=f(p,q),&q<p.
\end{cases}
$$

答案是 $f(n,n)$。状态只落在宽度为 $c+1$ 的对角带内，时间、表格空间均为 $O(n(c+1))$；还可以用对角带的滚动存储降低空间。$n=4,c=2$ 时答案为 **8**，而无容量限制的 $C_4=14$。

### 为什么动态规划正确

栈操作的每个合法前缀由两类动作之一扩展：

- **压栈**：输入还没压完，且当前高度小于容量上限，才可以从 $(p,q)$ 转移到 $(p+1,q)$；
- **出栈**：当前栈非空，才可以从 $(p,q)$ 转移到 $(p,q+1)$。

由于输入值的压栈顺序固定，**每个不同的合法压/弹操作序列都唯一确定一个出栈排列**，反过来一个可实现的出栈排列也唯一确定其合法压/弹操作次序，因此计算操作序列数与计算出栈排列数一致。

实现时可使用如下递推表：

```text
f[0][0] = 1
for p = 0..n:
    for q = max(0, p-c)..p:      // q 从小到大
        if p < n and p-q < c:
            f[p+1][q] += f[p][q]
        if q < p:
            f[p][q+1] += f[p][q]
return f[n][n]
```

因转移只向右或向下，按 `p` 递增、`q` 递增遍历可得到拓扑顺序。大规模输入需使用足够宽度的计数类型或高精度整数，避免卡特兰数增长造成溢出。

### $c=2$ 的闭式计数

把压栈记作 `(`、出栈记作 `)`，容量 $2$ 表示合法括号路径的高度始终不超过 2。任何一个**首次回到高度 0 的不可再分块**只能形如

$$
\underbrace{\texttt{(}\ \texttt{()}\ \texttt{()}\ \cdots\ \texttt{()}\ \texttt{)}}_{t+1\text{ 对括号}},\qquad t\ge0.
$$

这意味着：每个块可以有任意正整数数量的括号对，整个序列恰对应把 $n$ 拆成若干正整数的一个**有序拆分**。在 $n$ 个单位之间共有 $n-1$ 个间隙，每个间隙独立决定切分或不切分，因此

$$
\boxed{\text{容量为 2 时的数量}=2^{n-1}}.
$$

于是 $n=4$ 时为 $2^3=8$。若 $c\ge n$，全部 $n$ 个元素同时入栈也不超容，限制不再额外排除合法路径，因此退化为

$$
\boxed{C_n=\frac{1}{n+1}\binom{2n}{n}}.
$$

<Callout type="warn" title="计数模型的三层限制">

始终需要满足 $q\le p$（不能空栈出栈）、$p\le n$（不能压入超过输入数量的元素），并且额外满足 $p-q\le c$（不能超容量）。遗漏任何一条，都会把不合法的操作路径计入答案。

</Callout>

</Solution>
