# 408 历年大题整理 · 数据结构（第 21–30 题）

<ExamQuestion>

**21. 2019 年第 41 题**

设线性表

$$
L=(a_1,a_2,a_3,\ldots,a_{n-1},a_n)
$$

采用带头结点的单链表保存，结点定义如下：

```c
typedef struct node {
    int data;
    struct node *next;
} NODE;
```

请设计一个额外空间复杂度为 $O(1)$、时间上尽可能高效的算法，重新排列 $L$ 中的各结点，使其变为

$$
L'=(a_1,a_n,a_2,a_{n-1},a_3,a_{n-2},\ldots).
$$

要求：

1. 给出算法的基本设计思想；
2. 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；
3. 说明算法的时间复杂度。

<ExamSolution>

<ExamAnswer>先找中点，将后半段原地逆置，再把前、后两段交替合并。时间复杂度为 $O(n)$，额外空间复杂度为 $O(1)$。</ExamAnswer>

<ExamExplanation>

### 基本思想

目标序列需要依次取

$$
a_1,a_n,a_2,a_{n-1},a_3,a_{n-2},\ldots
$$

因此，若每次都从单链表尾部寻找结点，会造成反复遍历，时间复杂度上升到 $O(n^2)$。

更高效的做法分三步：

1. 使用快慢指针找到链表中点，把链表分成前、后两段；
2. 将后半段链表**原地逆置**，于是后半段的结点顺序变为 $a_n,a_{n-1},a_{n-2},\ldots$；
3. 将前半段与逆置后的后半段交替连接。

### C 语言实现

```c
void Rearrange(NODE *head) {
    if (head == NULL || head->next == NULL || head->next->next == NULL) {
        return;
    }

    /* 第 1 步：找到前半段的最后一个结点 */
    NODE *slow = head->next;
    NODE *fast = head->next;
    while (fast->next != NULL && fast->next->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }

    /* 将前、后两段断开 */
    NODE *second = slow->next;
    slow->next = NULL;

    /* 第 2 步：原地逆置后半段 */
    NODE *prev = NULL;
    NODE *cur = second;
    while (cur != NULL) {
        NODE *next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    second = prev;

    /* 第 3 步：交替合并两段 */
    NODE *first = head->next;
    while (second != NULL) {
        NODE *next1 = first->next;
        NODE *next2 = second->next;

        first->next = second;
        second->next = next1;

        first = next1;
        second = next2;
    }
}
```

以偶数个结点为例，若原链表为

$$
a_1\to a_2\to a_3\to a_4\to a_5\to a_6,
$$

则分段后为

$$
a_1\to a_2\to a_3,
\qquad
 a_4\to a_5\to a_6,
$$

后半段逆置为

$$
a_6\to a_5\to a_4,
$$

交替合并即可得到

$$
a_1\to a_6\to a_2\to a_5\to a_3\to a_4.
$$

找中点、逆置和合并都只需线性扫描，因此总时间复杂度为

$$
O(n),
$$

只使用常数个指针变量，额外空间复杂度为

$$
O(1).
$$

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**22. 2019 年第 42 题**

请设计一个队列，满足以下要求：

1. 初始时队列为空；
2. 入队时允许增加队列占用的空间；
3. 出队后，出队元素原来占用的空间可以重复使用，即整个队列已经申请的空间只增不减；
4. 入队和出队操作的时间复杂度始终为 $O(1)$。

请回答：

1. 应选择链式存储结构还是顺序存储结构？
2. 画出队列的初始状态，并给出判队空和“当前已分配空间已满”的条件；
3. 画出第一个元素入队后的状态；
4. 给出入队和出队操作的基本过程。

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2019-42-figure-001.svg" alt="2019 年第 42 题循环链式队列初始状态" />

<img src="/img/408/past-exams-large-questions/01-数据结构/assets/2019-42-figure-002.svg" alt="2019 年第 42 题第一个元素入队后的状态" />

<ExamSolution>

<ExamAnswer>采用带 `front`、`rear` 指针的循环单链表。队空条件为 `front == rear`；当 `rear->next == front` 时，表示当前已分配结点没有可直接继续使用的空闲位置，下一次入队前需扩充一个结点。</ExamAnswer>

<ExamExplanation>

### （1）存储结构选择

应采用**链式存储结构**。

顺序存储结构若需要动态扩容，通常要重新申请连续空间并搬移已有元素，不能保证每次入队都严格为 $O(1)$；而链表可在 $O(1)$ 时间内申请并接入新结点。

为了让已经出队的结点以后还能再次使用，可把所有已申请结点组织成**循环单链表**。

约定：

- `front` 指向当前队头元素所在位置；
- `rear` 指向下一次入队要写入的位置；
- 始终保留一个位置用于区分队空与“当前环已满”。

### （2）初始状态及判定条件

初始时只申请一个空闲结点，并令

```c
front = rear;
rear->next = front;
```

因此队空条件为

```c
front == rear
```

当

```c
rear->next == front
```

时，说明当前循环链表中已没有能够在不混淆队空状态的前提下直接继续使用的空闲位置。此时并不意味着入队失败，而是应先在 `rear` 后插入一个新结点，再完成入队。

### （3）第一个元素入队

初始时同时满足 `front == rear` 和 `rear->next == front`，所以第一次入队前先增加一个结点，然后把元素写入原 `rear` 所指结点，再令 `rear = rear->next`。

### （4）入队与出队过程

**入队：**

```text
若 rear->next == front：
    在 rear 后插入一个新的空闲结点，并保持循环链表；
将新元素写入 rear 所指结点；
rear = rear->next；
```

**出队：**

```text
若 front == rear：
    队空，出队失败；
否则：
    取出 front 所指结点中的元素；
    front = front->next；
```

出队时不释放结点。随着 `front` 向前移动，原来出队结点仍保留在循环链表中，之后会再次成为可复用空间。

链表尾部插入新结点、移动 `front`、移动 `rear` 都只涉及常数次指针操作，因此每次入队和出队均为 $O(1)$。

</ExamExplanation>

</ExamSolution>

**23. 2020 年第 41 题**

定义整数三元组 $(a,b,c)$ 的距离为

$$
D(a,b,c)=|a-b|+|b-c|+|c-a|.
$$

给定 3 个非空整数集合 $S_1,S_2,S_3$，各集合中的元素已按升序分别存放在 3 个数组中。请设计一个尽可能高效的算法，计算并输出所有可能三元组

$$
(a,b,c),\qquad a\in S_1,\ b\in S_2,\ c\in S_3
$$

中的最小距离。

例如：

$$
S_1=\{-1,0,9\},
$$

$$
S_2=\{-25,-10,10,11\},
$$

$$
S_3=\{2,9,17,30,41\},
$$

则最小距离为 $2$，相应的三元组可以取 $(9,10,9)$。

要求：

1. 给出算法的基本设计思想；
2. 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；
3. 说明算法的时间复杂度和空间复杂度。

<ExamSolution>

<ExamAnswer>三个数组各设一个指针，每次计算当前三元组的距离，然后只将三个当前元素中的最小者对应的指针后移。若 $n=|S_1|+|S_2|+|S_3|$，时间复杂度为 $O(n)$，额外空间复杂度为 $O(1)$。</ExamAnswer>

<ExamExplanation>

### 关键性质

设当前三个数按大小排列为

$$
x\le y\le z.
$$

则

$$
|x-y|+|y-z|+|z-x|
=(y-x)+(z-y)+(z-x)
=2(z-x).
$$

所以三元组距离只由其中的**最大值与最小值之差**决定：

$$
D=2(\max-\min).
$$

若当前最小值不变，仅增大中间值或最大值，不可能缩小当前的最大最小差；因此，要寻找更小的距离，下一步应推进**当前最小元素所在数组的指针**。

### 算法

```c
#include <limits.h>
#include <stdlib.h>

int Min3Distance(int A[], int n1,
                 int B[], int n2,
                 int C[], int n3) {
    int i = 0, j = 0, k = 0;
    int dmin = INT_MAX;

    while (i < n1 && j < n2 && k < n3) {
        int a = A[i];
        int b = B[j];
        int c = C[k];

        int d = abs(a - b) + abs(b - c) + abs(c - a);
        if (d < dmin) {
            dmin = d;
        }

        // 已达到理论最小值，不可能继续改进
        if (dmin == 0) {
            break;
        }

        // 只推进当前三个元素中的最小者
        if (a <= b && a <= c) {
            ++i;
        } else if (b <= a && b <= c) {
            ++j;
        } else {
            ++k;
        }
    }

    return dmin;
}
```

原整理中有多处下标识别错误，例如把 $C[k]$ 写成了 $C[j]$、把三个集合长度条件写成了错误的符号；这里已按三指针算法统一修正。

三个指针都只会单调向后移动，每个数组元素最多被访问常数次。若

$$
n=|S_1|+|S_2|+|S_3|,
$$

则时间复杂度为

$$
O(n),
$$

额外空间复杂度为

$$
O(1).
$$

</ExamExplanation>

</ExamSolution>

**24. 2020 年第 42 题**

若任一字符的编码都不是其他字符编码的前缀，则称该编码集合具有**前缀特性**。

现有某字符集（字符个数不少于 2）的一组不等长编码，每个字符的编码均为二进制 0、1 序列，最长为 $L$ 位，并具有前缀特性。

请回答：

1. 哪种数据结构适合保存上述具有前缀特性的不等长编码？
2. 基于所设计的数据结构，简述从 0/1 串到字符串的译码过程；
3. 简述判定某字符集的一组不等长编码是否具有前缀特性的过程。

<ExamSolution>

<ExamAnswer>使用二叉树（前缀树）保存编码：0 对应左分支，1 对应右分支，字符只保存在编码终点的叶结点。译码时从根按位下行，到叶结点输出字符并回到根；判定前缀特性可在逐个插入编码构造前缀树的同时完成。</ExamAnswer>

<ExamExplanation>

### （1）数据结构

使用一棵**二叉前缀树**。

- 从根到某结点的一条路径表示一个二进制编码；
- 约定编码位 0 走左孩子，编码位 1 走右孩子；
- 一个合法字符编码的终点保存相应字符；
- 若整组编码具有前缀特性，则所有字符编码终点都应是叶结点。

### （2）译码过程

从输入 0/1 串的左端开始扫描，并令当前结点初始为根结点：

1. 当前位为 0，则走向左孩子；当前位为 1，则走向右孩子；
2. 到达保存字符的叶结点后，输出该字符；
3. 重新回到根结点，继续处理后续二进制位；
4. 扫描完整个 0/1 串后，译码结束。

由于编码具有前缀特性，到达一个字符对应叶结点时就可以唯一确定该字符，不需要向后试探。

### （3）判定是否具有前缀特性

可以在逐个插入编码、构造前缀树的过程中检查。

对每个编码 $C$，从根开始逐位处理：

1. 在尚未处理完 $C$ 时，若当前结点已经是某个已有字符编码的终点，则说明**已有较短编码是 $C$ 的前缀**，不具有前缀特性；
2. 根据当前位 0/1 进入相应孩子；若孩子不存在，则新建结点；
3. $C$ 的所有位处理完后：
   - 若当前结点已经是某个字符的编码终点，则出现重复编码，不合法；
   - 若当前结点已有左孩子或右孩子，则说明 **$C$ 是某个已有较长编码的前缀**，不具有前缀特性；
   - 否则把当前结点标记为该字符的编码终点。

所有编码都插入成功，才能判定整组编码具有前缀特性。

若所有编码总长度为 $M$，上述建树与检查只需 $O(M)$ 时间。

</ExamExplanation>

</ExamSolution>

**25. 2021 年第 41 题**

已知无向连通图 $G$ 由顶点集 $V$ 和边集 $E$ 组成，且 $|E|>0$。当 $G$ 中度为奇数的顶点个数为不大于 2 的偶数时，$G$ 存在一条包含所有边且长度为 $|E|$ 的路径，称为 EL 路径。

图 $G$ 采用邻接矩阵存储，类型定义如下：

```c
typedef struct {
    int numVertices, numEdges;
    char VerticesList[MAXV];
    int Edge[MAXV][MAXV];
} MGraph;
```

请设计算法

```c
int IsExistEL(MGraph G)
```

判断 $G$ 是否存在 EL 路径。存在则返回 1，否则返回 0。

要求：

1. 给出算法的基本设计思想；
2. 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；
3. 说明算法的时间复杂度和空间复杂度。

<ExamSolution>

<ExamAnswer>统计图中奇度顶点的个数。由于题目已保证图连通且 $|E|>0$，奇度顶点数为 0 或 2 时存在 EL 路径，否则不存在。时间复杂度 $O(|V|^2)$，额外空间复杂度 $O(1)$。</ExamAnswer>

<ExamExplanation>

### 基本思想

对于无向图的邻接矩阵，第 $i$ 行非零元素的个数就是顶点 $i$ 的度。

因此逐个计算每个顶点的度，并统计奇度顶点的数量 `odd`：

- `odd == 0`：存在欧拉回路，因此当然存在 EL 路径；
- `odd == 2`：存在以两个奇度顶点为端点的欧拉路径；
- 其他情况：不存在 EL 路径。

### C 语言实现

```c
int IsExistEL(MGraph G) {
    int odd = 0;

    for (int i = 0; i < G.numVertices; ++i) {
        int degree = 0;

        for (int j = 0; j < G.numVertices; ++j) {
            if (G.Edge[i][j] != 0) {
                ++degree;
            }
        }

        if (degree % 2 != 0) {
            ++odd;
            if (odd > 2) {
                return 0;
            }
        }
    }

    return (odd == 0 || odd == 2) ? 1 : 0;
}
```

原整理中的内层循环错误地使用了 `numEdges` 作为邻接矩阵的列数。邻接矩阵是

$$
|V|\times |V|
$$

矩阵，因此行、列都必须遍历 `G.numVertices`。

最坏情况下需检查整个邻接矩阵，时间复杂度为

$$
O(|V|^2),
$$

额外只使用常数个变量，空间复杂度为

$$
O(1).
$$

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**26. 2021 年第 42 题**

已知某排序算法如下：

```c
void cmpCountSort(int a[], int b[], int n)
{
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n);

    for (i = 0; i < n; i++)
        count[i] = 0;

    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j])
                count[j]++;
            else
                count[i]++;

    for (i = 0; i < n; i++)
        b[count[i]] = a[i];

    free(count);
}
```

请回答：

1. 若

```c
int a[] = {25, -10, 25, 10, 11, 19};
int b[6];
```

调用 `cmpCountSort(a, b, 6)` 后，数组 `b` 中的内容是什么？
2. 若 `a` 中含有 $n$ 个元素，则算法执行过程中元素之间的比较次数是多少？
3. 该算法是否稳定？若稳定，说明理由；若不稳定，将其修改为稳定排序算法。

<ExamSolution>

<ExamAnswer>

排序结果为

```text
{-10, 10, 11, 19, 25, 25}
```

元素比较次数为

$$
\frac{n(n-1)}{2}.
$$

原算法不稳定。把判断改为 `if (a[i] <= a[j]) count[j]++; else count[i]++;` 后可保持相等元素的原相对次序。

</ExamAnswer>

<ExamExplanation>

### （1）排序结果

对任意元素 `a[i]`，`count[i]` 最终表示该元素在输出数组中的目标下标。

原算法会得到

```text
b = {-10, 10, 11, 19, 25, 25}
```

即按非递减次序排列。

### （2）比较次数

双重循环使每一对不同位置的元素恰好比较一次，因此比较次数为

$$
(n-1)+(n-2)+\cdots+1
=\frac{n(n-1)}{2}.
$$

### （3）稳定性

原算法**不稳定**。

设 $i<j$ 且

$$
a[i]=a[j].
$$

原条件 `a[i] < a[j]` 为假，于是执行

```c
count[i]++;
```

这会使原本位于前面的 `a[i]` 获得更大的输出下标，排到原本位于后面的 `a[j]` 之后，从而破坏稳定性。

应修改为：

```c
if (a[i] <= a[j])
    count[j]++;
else
    count[i]++;
```

当两个元素相等时，增加后一个元素 `a[j]` 的计数，使后出现的相等元素仍排在后面，因此排序变为稳定排序。

若使用 C++ 动态数组写法 `new int[n]`，释放时相应应使用 `delete[] count`。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

$T$ 中不存在的结点在数组 `SqBiTNode` 中用 `-1` 表示。

例如，下图给出了两棵非空二叉树 $T_1$ 和 $T_2$ 及其顺序存储示意。

请设计一个尽可能高效的算法，判定一棵采用这种方式存储的二叉树是否为二叉搜索树。若是返回 `true`，否则返回 `false`。

要求：

2. 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释。

<ExamSolution>

<ExamAnswer>对顺序存储的二叉树进行中序遍历，并检查访问到的有效结点值是否严格递增；若出现当前值小于等于前一个访问值，则不是二叉搜索树。</ExamAnswer>

<ExamExplanation>

### 基本思想

若结点存放在下标 $i$ 处，则其左右孩子下标分别为

$$
2i+1,
\qquad
2i+2.
$$

二叉搜索树的一个等价判定条件是：**中序遍历所得关键字序列严格递增**。

因此可以用变量 `prev` 保存中序遍历过程中上一个有效结点的值：

1. 递归检查左子树；
2. 访问当前结点，要求当前值严格大于 `prev`；
3. 更新 `prev`；
4. 递归检查右子树。

由于题目规定有效结点值均为正整数，可令 `prev` 初值为 0。

### C 语言实现

```c
bool InOrderCheck(SqBiTree *T, int i, int *prev) {
    // 超出实际存储范围，或当前位置为空结点
    if (i >= T->ElemNum || T->SqBiTNode[i] == -1) {
        return true;
    }

    // 检查左子树
    if (!InOrderCheck(T, 2 * i + 1, prev)) {
        return false;
    }

    // 中序序列必须严格递增
    if (T->SqBiTNode[i] <= *prev) {
        return false;
    }
    *prev = T->SqBiTNode[i];

    // 检查右子树
    return InOrderCheck(T, 2 * i + 2, prev);
}

bool IsBST(SqBiTree *T) {
    int prev = 0;   // 题目保证有效结点值均为正整数
    return InOrderCheck(T, 0, &prev);
}
```

原整理中的代码先递归访问了某位置的左孩子，之后才判断当前位置是否为 `-1`。对于顺序存储的空结点，应当**先判断当前位置是否为空，再决定是否访问其孩子**；这里已修正这一顺序。

每个实际访问到的数组位置只处理常数次，最坏时间复杂度为 $O(\text{ElemNum})$；递归栈空间与树高有关，为 $O(h)$。

</ExamExplanation>

</ExamSolution>

**28. 2022 年第 42 题**

现有 $n$ 个数保存在一维数组 $M$ 中，其中

$$
n>100000.
$$

需要找出 $M$ 中最小的 10 个数。

请回答：

1. 设计一个完成上述任务的算法，要求平均情况下的比较次数尽可能少，只需描述算法思想，不需要程序实现；
2. 说明算法平均情况下的时间复杂度和空间复杂度。

<ExamSolution>

<ExamAnswer>维护一个只含 10 个元素的大根堆。堆顶始终是当前候选的 10 个最小数中的最大者；扫描其余元素，只有当新元素小于堆顶时才替换堆顶并向下调整。因 10 为常数，平均时间复杂度为 $O(n)$，额外空间复杂度为 $O(1)$。</ExamAnswer>

<ExamExplanation>

### 算法思想

1. 取数组 $M$ 的前 10 个元素，建立一个大小为 10 的**大根堆** $H$；
2. 对 $M$ 中剩余的每个元素 $x$：
   - 先与堆顶 $H[0]$ 比较；
   - 若

$$
x\ge H[0],
$$

则 $x$ 不可能属于当前最小的 10 个数，直接忽略；
   - 若

$$
x<H[0],
$$

则用 $x$ 替换堆顶，再对堆顶执行一次向下调整，恢复大根堆；
3. 全部扫描结束后，堆中的 10 个元素就是整个数组中最小的 10 个数。

之所以使用**大根堆**，是因为只需 $O(1)$ 时间就能取得这 10 个候选值中的最大者，从而快速判断一个新元素是否值得进入候选集合。

### 复杂度

堆大小固定为 10，所以每次堆调整的代价为

$$
O(\log 10)=O(1).
$$

扫描 $n$ 个元素的总时间复杂度为

$$
O(n).
$$

辅助堆只有 10 个元素，因此若以 $n$ 为规模衡量，额外空间复杂度为

$$
O(1).
$$

若把“10”推广为一般的 $k$，则对应复杂度为 $O(n\log k)$ 时间和 $O(k)$ 额外空间。

</ExamExplanation>

- 第 $v$ 行中的非零元素个数等于顶点 $v$ 的出度；
- 第 $v$ 列中的非零元素个数等于顶点 $v$ 的入度。

int printVertices(MGraph G) {

    for (int v = 0; v < G.numVertices; ++v) {
        int indegree = 0;
        int outdegree = 0;

        for (int i = 0; i < G.numVertices; ++i) {
            if (G.Edge[v][i] != 0) {
                ++outdegree;
            }
            if (G.Edge[i][v] != 0) {
                ++indegree;
            }
        }

        if (outdegree > indegree) {
            printf("%c ", G.VerticesList[v]);
            ++count;
        }
    }

    return count;
}

额外空间复杂度为

$$
O(1).

**30. 2023 年第 42 题**

对含有 $n$ 个记录的文件进行外部排序。采用**置换—选择排序**生成初始归并段时，需要使用一个工作区，工作区中最多保存 $m$ 个记录。

请回答：

1. 若文件中有 19 个记录，其关键字依次为

$$
51,94,37,92,14,63,15,99,48,56,23,60,31,17,43,8,90,166,100,
$$

当 $m=4$ 时，可生成几个初始归并段？各是什么？
2. 对任意 $n$、$m$，其中 $n>m>0$，生成的第一个初始归并段的长度最大值和最小值分别是多少？

<ExamSolution>

<ExamAnswer>

当 $m=4$ 时，共生成 3 个初始归并段：

1. $37,51,63,92,94,99$
2. $14,15,23,31,48,56,60,90,166$
3. $8,17,43,100$

第一个初始归并段长度的最大值为 $n$，最小值为 $m$。

</ExamAnswer>

<ExamExplanation>

### （1）置换—选择过程

初始把前 4 个关键字装入工作区：

$$
51,94,37,92.
$$

每次从当前仍属于本归并段的记录中选择最小者输出，再读入一个新的输入记录：

- 若新记录关键字不小于刚输出的关键字，则它仍可参加当前归并段；
- 若新记录关键字更小，则将它“冻结”，留待下一归并段。

按照这一规则，第一段依次输出

$$
37,51,63,92,94,99.
$$

第一段结束时被冻结的记录进入第二段，继续执行同样过程，可得到

$$
14,15,23,31,48,56,60,90,166.
$$

剩余被冻结记录构成第三段：

$$
8,17,43,100.
$$

因此共生成 3 个初始归并段。

### （2）第一个归并段长度的上下界

工作区初始装入 $m$ 个记录，这 $m$ 个记录最终都必须在第一个归并段中被输出，因此第一个归并段长度不可能小于

$$
m.
$$

若后续读入的每个记录都不小于当前刚输出的记录，则没有任何记录被冻结，整个文件的 $n$ 个记录都可以落入第一个归并段，因此最大长度为

$$
n.
$$

所以第一个初始归并段长度满足

$$
m\le L_1\le n.
$$

</ExamExplanation>
