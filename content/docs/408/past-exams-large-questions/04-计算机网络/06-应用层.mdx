## 2011 年第 47 题

<ExamQuestion>

**111. 2011 年第 47 题**

某主机的 MAC 地址为 `00-15-C5-C1-5E-28`，IP 地址为 `10.2.128.100`（私有地址）。题图给出了网络拓扑，以及该主机进行 Web 请求时一个以太网数据帧前 80B 的十六进制内容。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2011-47-figure-001.svg" alt="2011 年第 47 题网络拓扑、以太网帧内容及报文格式" />

1. Web 服务器的 IP 地址是什么？该主机默认网关的 MAC 地址是什么？
2. 该主机在构造图中数据帧时，使用什么协议确定目的 MAC 地址？封装该协议请求报文的以太网帧目的 MAC 地址是什么？
3. 假设 HTTP/1.1 采用持续、非流水线方式，一次请求—响应耗时为一个 RTT，`rfc.html` 页面还引用 5 个 JPEG 小图像。从发出图中的 Web 请求开始，到浏览器收到全部内容，共需多少个 RTT？
4. 该帧封装的 IP 分组经过路由器 R 转发时，需要修改 IP 首部中的哪些字段？

<ExamSolution>

<ExamAnswer>

1. Web 服务器地址 **`64.170.98.32`**；默认网关 MAC 地址 **`00-21-27-21-51-EE`**。
2. **ARP**；查询帧目的 MAC 为 **`FF-FF-FF-FF-FF-FF`**。
3. 按题设“从 HTTP 请求已经发出开始、持久非流水线、一问一答各 1RTT”，需要 **6 RTT**。
4. 按题图 R 具有源 NAT 功能，修改 **源 IPv4 地址、TTL、IPv4 首部校验和**；若 R 同时修改 TCP 源端口，还必须更新 TCP 校验和（该问专问 IP 首部，TCP 端口不在其内）。

</ExamAnswer>

<ExamExplanation>

### 一、十六进制帧解码：先算好帧头 14B

给出的前 80B 为以太网帧内容。标准以太网 II 帧头：前 6B 目的 MAC、后 6B 源 MAC、再后 2B EtherType，**因此 IPv4 头的第 1B 在整帧偏移 14B 处（从 0 起）**。题图中：

- 第 1～6B 目的 MAC 是 `00-21-27-21-51-EE`；
- 源主机 MAC 是 `00-15-C5-C1-5E-28`；
- EtherType 若为 `0x0800` 表示 IPv4，`0x0806` 表示 ARP；
- IP 目的地址在 IPv4 首部的第 17～20B，即帧第 31～34B，对应十六进制 `40 AA 62 20`。

按每个字节换算十进制：

$$
\mathtt{0x40}=64,\quad\mathtt{0xAA}=170,
\quad\mathtt{0x62}=98,\quad\mathtt{0x20}=32.
$$

所以最终服务器 IPv4 地址为 **`64.170.98.32`**。

主机自己是私网 `10.2.128.100`，服务器是外网，首次发往外网的以太网帧的**目的 MAC 是第一跳网关的 MAC**，不是远端服务器的 MAC。题图帧头的 `00-21-27-21-51-EE` 因而正是 R 在该局域网一侧的 MAC。

### 二、ARP 查找的是“下一跳”地址

**先用 IP 与掩码判断目的是否属于本子网**。异网时选择默认路由的下一跳 IP；若没有下一跳 IP→MAC 缓存条目，先广播 ARP 请求：

$$
\text{ARP 请求帧目的 MAC} = \mathtt{FF-FF-FF-FF-FF-FF}.
$$

ARP 应答一般单播返回查询者，随后主机才有条件构造题图中目的 MAC 为网关 MAC 的**业务数据帧**。注意 ARP 不是使用 UDP/TCP 的应用层协议，不应把 ARP 当成 DNS。即使 HTTP 最终目的仍为 `64.170.98.32`，本地二层只需解决到 R 的封装问题。

### 三、HTTP/1.1 持久但非流水线：一张时间表就够

HTTP/1.1 持久连接允许多个 HTTP 请求复用同一 TCP 连接；**非流水线**要求前一响应完成后再发下一请求。题目已指定**从题图 Web 请求发出时起**，因此不能把已经建立 TCP 连接的 1RTT 再算进去。

| 顺序 | 请求资源 | 消耗 |
| --- | --- | ---: |
| 1 | `rfc.html` HTML 主文档 | 1 RTT |
| 2～6 | HTML 引用的 JPEG 图像 1～5 | 5 RTT |
| **合计** | **6 个 HTTP 请求—响应** | **6 RTT** |

$$
T_{\mathrm{HTTP}}=(1+5)RTT=\boxed{6RTT}.
$$

**对照变式**：如果题设从“发起全新 TCP 连接”开始计时，且 DNS 解析已完成，则还需额外 **1RTT 建连**，总计 7RTT；如果有并行多个连接、HTTP/2 多路复用或服务端推送，就不能直接沿用 6RTT。

### 四、R 转发并 NAT 时 IPv4 首部和 TCP 首部谁会变

此题 NAT 路由器 R 把内网源 IP `10.2.128.100` 转换为自己的公网源 IP `101.12.123.15`；转发使 **TTL 减 1**；IPv4 首部改变后必须**重新计算 IPv4 首部校验和**。题图 IP 总长 `01EFH=495B`，不超过下一跳 MTU=1500B，题设没有导致分片的条件：

| 字段 | 是否变动 | 原因 |
| --- | --- | --- |
| 源 IPv4 地址 | **变** | R 执行源 NAT |
| TTL | **变** | 每经过三层路由跳减 1 |
| IPv4 首部校验和 | **变** | 首部内容变化必须重新计算 |
| 目的 IPv4 | 不变（本题） | 目标仍是公网 Web 服务器 |
| IP 总长度、标识、片偏移 | 不需要因该次转发改变 | 无分片的题设情形 |
| TCP 校验和 | 可能需要改变 | TCP 伪首部含源/目的 IP；若 NAT 还改端口，也需重新计算/增量更新 |

**重要区分**：纯路由转发通常只改变 TTL 和 IPv4 首部校验和；题中 **因为还有 NAT** 才改变源 IP。若附加有目的 NAT、隧道、分片或可变 IP 选项，则会改动更多字段，不能把本题三项当成所有路由器的通用不变清单。

### 五、实战速查

- 帧头先 6B+6B+2B，IP 源/目的位置从 IP 首部算，不要将帧偏移和 IP 偏移混淆。
- 远端目标 IP 与本地帧的目的 MAC 常属于**不同节点**；ARP 的查询对象是下一跳 IP。
- HTTP RTT 题先圈出计时起点：DNS/TCP 握手是否算在内，再按是否持续、并行、流水线来累加。
- NAT 修改 IP 地址还涉及**TCP/UDP 校验和伪首部**；问“IP 首部”时不用把 TCP 校验和混进去。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

主机 H=`192.168.50.20/24`，本地 DNS 服务器=`192.168.50.53/24`，默认网关 R 的内网 IP/MAC 分别为 `192.168.50.1`、`02-50-00-00-00-01`。R 将 H 的源 IP 转换成公网 `198.51.100.5`（可同时转换源端口）；Web 服务器是 `203.0.113.40`。浏览器从发起域名 `study.example` 的 DNS 查询时开始计时，DNS 查询与应答共需 1 RTT，然后新建 TCP 连接耗时 1 RTT，再利用 HTTP/1.1 **持续、非流水线**连接获取 1 份 HTML 和其中引用的 4 张小图片；每个 HTTP 请求—响应耗时 1 RTT。忽略 ARP 耗时、发送时间和服务器处理时间。开始时 H 的 ARP 表为空。

1. 最少共需多少个 RTT？若改为从已经发出第一条 HTTP GET 开始计时，又是多少个 RTT？
2. 为询问同网段 DNS 服务器的 MAC，H 首个 ARP 帧目的 MAC 是什么？发往异网 Web 服务器的首个 TCP SYN 帧的下一跳目的 MAC 是什么？
3. 在 H 发 SYN 时，SYN 所在 IP 分组的目的 IP 是什么？经过 R 的源 IP 变成什么？R 对该分组的哪些 IP 首部字段必须做相应变化？
4. 假设 NAT **还修改 TCP 源端口**，只修改 IPv4 首部校验和而不处理 TCP 校验和，是否正确？

<ExamSolution>

<ExamAnswer>

1. $1\mathrm{RTT}$ DNS + $1\mathrm{RTT}$ TCP + $5\mathrm{RTT}$ HTTP = **7 RTT**；若从首条 HTTP GET 已发出开始，则是 **5 RTT**。
2. 首个 ARP 查询的 MAC 为 **`FF-FF-FF-FF-FF-FF`**；发往外网 SYN 的下一跳目的 MAC 为 **`02-50-00-00-00-01`**。
3. SYN 目的 IP 仍为 **`203.0.113.40`**；R 做源 NAT 后源 IP 为 **`198.51.100.5`**；IPv4 源 IP、TTL、IP 首部校验和均需按实际转发重新处理。
4. **不正确**。源 IP 和 TCP 源端口改变后必须更新 TCP 校验和（其覆盖伪首部及 TCP 首部/数据），不能只改 IPv4 首部校验和。

</ExamAnswer>

<ExamExplanation>

### （1）时间分段：DNS 与 TCP 建连并非 HTTP 请求

此题的计时起点是“开始域名解析”：

| 阶段 | 服务 | RTT 数 |
| --- | --- | ---: |
| DNS | 向本地域名服务器解析 `study.example` | 1 |
| TCP | 和 Web 服务器建立新 TCP 连接 | 1 |
| HTTP | 请求 HTML | 1 |
| HTTP | 顺次请求 4 张 JPEG（非流水线） | 4 |
| **合计** | | **7** |

如果题目从“第一条 GET 已发出”开始，前两行不再计时，只是 $1+4=5RTT$。若题目换成并行连接、HTTP/2 多路复用、缓存命中或额外 DNS 链式查询，应依新条件重新建模。

### （2）先判本地/异网，再寻找下一跳 MAC

DNS 地址 `192.168.50.53` 与 H 同为 `192.168.50.0/24`，H 可直接 ARP 查询 DNS 的 MAC。ARP 表空，查询请求的**目的 MAC 为广播**。随后 TCP 连接发往公网目标 `203.0.113.40`，应交给默认网关 `192.168.50.1`：ARP 得到 R 的 MAC 后，**真正承载 SYN 的帧**目的 MAC 是 R；而 SYN 的 **IP 目的仍为外网 Web 服务器**。

### （3）NAT 前后的字段表

| 分层字段 | 在 H 发出时 | 经 R 出公网后 |
| --- | --- | --- |
| 源 IPv4 | `192.168.50.20` | `198.51.100.5` |
| 目的 IPv4 | `203.0.113.40` | `203.0.113.40` |
| TTL | $n$ | 典型变为 $n-1$ |
| IPv4 首部校验和 | 原首部校验值 | 依据新首部更新 |
| 以太网目的 MAC | R 内网 MAC | 下一跳设备 MAC（视公网链路而定） |

TCP 校验和覆盖 **IPv4 伪首部**（源/目的 IP、协议号、TCP 长度）、TCP 首部以及数据；所以即使只改源 IP、不改端口，校验和也需要随之更新，除非采用具备等价校验和补偿的特殊处理。R 如还映射源端口，更不可能只更新 IPv4 头部校验和。IPv4 首部校验和**只覆盖 IPv4 首部**，不能代替 TCP 校验和。

</ExamExplanation>

</ExamSolution>

## 2021 年第 47 题

<ExamQuestion>

**121. 2021 年第 47 题**

某网络拓扑如下图所示。以太网交换机 S 通过路由器 R 与 Internet 互联。路由器部分接口、本地域名服务器、H1、H2 的 IP 地址和 MAC 地址如图所示。

在 $t_0$ 时刻，H1 的 ARP 表和 S 的交换表均为空。H1 从 $t_0$ 时刻开始使用浏览器通过域名 `www.abc.com` 请求访问 Web 服务器；在 $t_1$ 时刻（$t_1>t_0$），S 第一次收到封装 HTTP 请求报文的以太网帧。假设从 $t_0$ 到 $t_1$ 期间，网络中没有发生任何与此次 Web 访问无关的通信。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2021-47-figure-001.svg" alt="2021 年第 47 题网络拓扑" />

1. 从 $t_0$ 到 $t_1$ 期间，H1 除了 HTTP 之外还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文依次通过哪些协议进行封装？
2. 若 S 的交换表表项结构为 `<MAC 地址, 端口>`，则在 $t_1$ 时刻，S 的交换表中有哪些表项？
3. 从 $t_0$ 到 $t_1$ 期间，H2 至少会接收到几个与此次 Web 访问相关的帧？这些帧是什么帧？其目的 MAC 地址是什么？

<ExamSolution>

<ExamAnswer>

1. 还运行 **DNS**；通常按 **DNS→UDP→IPv4→以太网帧** 封装。
2. 交换机 S 已学习三个**实际发过帧**的源地址：`<00-11-22-33-44-cc,4>`、`<00-11-22-33-44-bb,1>`、`<00-11-22-33-44-aa,2>`。
3. H2 至少收到 **2 个广播 ARP 请求帧**，二者目的 MAC 均为 **`FF-FF-FF-FF-FF-FF`**。

</ExamAnswer>

<ExamExplanation>

### 一、访问网页不只是 HTTP：先解析域名，后连接网站

H1 输入 `www.abc.com` 而不是直接输入 IP，必须取得服务端 IP 才能据此发起连接。题目已给本地 DNS 服务端，因此从 $t_0$ 到第一次 HTTP 请求发出之间，存在 DNS 查询/应答：

$$
\text{DNS 应用数据}\to
\text{UDP 段}\to
\text{IPv4 分组}\to
\text{以太网帧}.
$$

典型 DNS 查询用 UDP 目的端口 53；若响应超长、需要可靠传送或特殊操作，也可使用 TCP。**本题问常见 DNS 查询封装，应答 UDP，不表示 DNS 永远只用 UDP**。ARP 是用于 IPv4→MAC 的**链路层相关机制**，尽管也会运行，却不是本小问的“还运行了哪个应用层协议”。

访问顺序可以画成：

1. H1 要向同子网 DNS 服务器查询 `www.abc.com` 的 IP，但本地 ARP 表为空；
2. H1 通过 ARP 请求得到 DNS 服务器的 MAC，再发送 UDP/DNS 查询；
3. DNS 服务器应答解析结果，H1 得到 Web 服务器的 IP；
4. Web 服务端在互联网，H1 要把 TCP 三次握手和 HTTP 请求交默认网关 R；
5. 若 H1 还不知道 R 的 MAC，再广播 ARP 请求，收到 R 的 ARP 应答后进行 TCP/HTTP 通信。

### 二、交换机只“学源 MAC”，不因泛洪而自动学目的地址

题目假设交换表在 $t_0$ 为空。以太网学习交换机的典型算法：帧从某端口进入时，记下 **`<源 MAC, 入端口>`**，然后按目的地址决定单播转发或广播/未知单播泛洪。不能“看到图上有设备”就预先填入所有设备，更不能因为 H2 收到广播就认为 H2 的 MAC 被学习。

| 发生事件 | 收帧端口 | 帧的源设备/MAC | S 新增/刷新表项 |
| --- | ---: | --- | --- |
| H1 询问 DNS MAC 的 ARP 请求 | 4 | H1 `00-11-22-33-44-cc` | `<00-11-22-33-44-cc,4>` |
| DNS 主机回复 ARP / DNS 应答 | 1 | DNS `00-11-22-33-44-bb` | `<00-11-22-33-44-bb,1>` |
| H1 询问网关 MAC，R 回复 | 2（R 发送响应） | R `00-11-22-33-44-aa` | `<00-11-22-33-44-aa,2>` |

$t_1$ 时 S 第一次收到 HTTP 请求的帧，H1 本身的 MAC 和端口仍会被确认学习；在没有无关通信且不考虑学习老化到期的题设中，表里就有这三项。**H2 的 MAC 不在表中**，因为 H2 没有发出帧。

### 三、H2 为什么能“至少收到”两个帧

H1 的 ARP 表一开始为空，至少需要两次不同下一跳的硬件地址解析：

- **第一次广播**：查询同网段本地 DNS 服务器的 MAC；
- **第二次广播**：DNS 解析出外网目标后，查询默认网关 R 的 MAC。

二者的以太网目的 MAC 都是

$$
\boxed{\mathtt{FF-FF-FF-FF-FF-FF}}.
$$

交换机对广播帧向同 VLAN 其他端口泛洪，所以连接 S 的 H2 至少收到两帧；但两次 ARP 查询的 **ARP 目标 IP 不一样**。发给 DNS 服务器或 R 的 **ARP 应答**通常是单播给 H1，并不要求 H2 都收到；TCP 三次握手及 HTTP 请求同样是发给网关或相应节点的单播帧，不应无条件加到 H2 的“至少两帧”之中。

### 四、为何这个题的最小值不能想当然加上 DHCP/DNS 广播

题设 H1 已有 IP、网关和本地 DNS 配置，并未说它刚接入网络等待 DHCP 配置，因此无需再计 DHCP DORA 四步。向本地域名服务器发送的 DNS 查询也是 UDP/IP 的**定向单播**（通过其 MAC），不应因为 DNS 是“域名解析”就认为 DNS 请求必然二层广播。

特别注意：交换机可能因**未知单播**泛洪某些帧，使 H2 在特定实际网络里收到更多帧；题问“**至少**”且没有无关通信，应答的是**必然发生的两次 ARP 广播**，不能把未知单播等不确定事件当作必然。若开启 VLAN 隔离、代理 ARP、ARP 缓存预置或 DNS 与网关同设备，结果可能变化；本题明确 ARP 表为空及原图设备分置。

### 五、流程题答题模板

1. IP 配好了吗？若没有，考虑 DHCP；有域名吗？有则考虑 DNS。
2. 目标 IP 与本机掩码按位与后同子网吗？同网 ARP 目标主机，异网 ARP 网关。
3. 交换机表项只从**收到帧的源 MAC/端口**学习；绝不根据目的 MAC 反向猜学习项。
4. H2 到底收到什么？区分广播、未知目的单播泛洪和已知目的单播；明确“**至少**”的口径。
5. 所有层次字段要分别写：应用层 DNS、运输层 UDP、网络层 IP、链路层 Ethernet / ARP。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

同一 VLAN 的二层交换机 S 上连接 H1（MAC `02-00-00-00-00-11`，端口 1，IP `10.1.1.10/24`）、H2（MAC `02-00-00-00-00-22`，端口 2，IP `10.1.1.20/24`）、网关 G（MAC `02-00-00-00-00-33`，端口 3，IP `10.1.1.1/24`）及本地 DNS D（MAC `02-00-00-00-00-44`，端口 4，IP `10.1.1.53/24`）。H1 的 ARP 缓存和 S 的转发表初始为空，H2 不主动发送任何帧；无其它通信、无端口隔离，ARP 应答均为单播。

1. H1 解析外网域名并建立 TCP 连接，直到第一次 HTTP 请求帧到达交换机之前，H1 至少需要发几个不同目标 IP 的 ARP 查询？H2 至少接收几帧？目的 MAC 是什么？
2. 此时 S 的 MAC 学习表至少有哪几个条目？为什么不包括 H2？
3. 若把 D 改为外网 DNS `8.8.8.8`，且 H1 已预先配置这个 DNS 地址、DNS 解析只由 G 路由转发，H1 仍无 ARP 缓存，则在相同窗口内 H1 至少需要发几个 ARP 查询？H2 至少接收几个与此次访问相关的广播 ARP 帧？S 还能否从本次交换学习到 DNS D 的 MAC？
4. 若题目改成“H2 也主动回复一个 ARP 请求”，会对 S 表项有何影响？

<ExamSolution>

<ExamAnswer>

1. 需要查询 DNS D 的 MAC 和网关 G 的 MAC，**2 个不同目标的 ARP 请求**；H2 至少收到 **2 个广播帧**，目的 MAC 均为 **`FF-FF-FF-FF-FF-FF`**。
2. **`<02-00-00-00-00-11,1>`（H1）、`<02-00-00-00-00-44,4>`（D）、`<02-00-00-00-00-33,3>`（G）**，不包括未发帧的 H2。
3. 只有 **1 个**本地 ARP 查询：询问 G 的 MAC；H2 至少收到 **1 个**广播 ARP 帧。S **学不到公网 DNS 的 MAC**，只看得到本地链路的 H1 和 G；外网 DNS 不在这个二层广播域。
4. H2 发出任何帧并经端口 2 被 S 收到时，S 会学习/刷新 **`<02-00-00-00-00-22,2>`**。

</ExamAnswer>

<ExamExplanation>

### （1）本地 DNS 与异网 Web：H1 会问两个“下一跳”

H1 与 D 都在 `10.1.1.0/24`，解析域名的 DNS 查询需要发给 D，自身 ARP 表空，故先广播 `Who has 10.1.1.53?`。解析出外网 Web IP 后，外网目标不属于本地 `/24`，H1 再向默认网关 G 查询 `Who has 10.1.1.1?`。两个 ARP 请求**目标 IP 不同**，在同一 VLAN 都是以太网广播帧，因此 H2 至少收到两帧。

注意 DNS 查询自身不是二层广播，它通过已解析的 D MAC **单播**；也不能把第二个查询说成“对 Web IP 直接 ARP”，因为目的 Web 在外网，H1 只需解析下一跳 G 的 MAC。

### （2）S 只能从入站帧的源地址学习

- S 从端口 1 收到 H1 首个 ARP 广播，学到 H1 MAC→1；
- S 从端口 4 收到 D 的 ARP 回复（或后续 DNS 响应），学到 D MAC→4；
- S 从端口 3 收到 G 的 ARP 回复，学到 G MAC→3；
- H2 仅被动收到泛洪广播，并未从端口 2 发送帧，因此 S **没有足够的源 MAC 证据** 学到 H2 MAC→2。

这体现“交换机学习**源 MAC+入端口**，不是目的 MAC+出端口”的根本机制。

### （3）DNS 移到异网：所有发往 DNS/Web 的包都经同一个网关

当 DNS 为 `8.8.8.8`，DNS 与外网 Web 都不在 H1 的 `/24`。只需通过一次 ARP 得到 G 的 MAC，便可把两种业务的 IP 包均装入目的 MAC 为 G 的以太网帧。域名解析对外网 DNS 仍需应用层 DNS 查询，但**不需要对 8.8.8.8 发本地 ARP**，也不需要单独为 Web 目标 IP 发本地 ARP。

交换机 S 不会学习位于其他子网的 DNS 服务器的物理 MAC：它只能见到由 G 在本地 VLAN 发送进来的帧，源 MAC 为 G 的本地接口。IP 包源地址可能是 8.8.8.8，**不能直接拿 IP 源地址推断以太网源 MAC**。

### （4）最小收到帧数与额外通信

ARP 回复一般定向单播给 H1，不保证 H2 接收；未知单播泛洪、重试 ARP、广播 DNS、设备附加控制协议可能增加帧数，但题目问“至少”且未声明额外通信，因此只算必然的 2 帧或 1 帧。如果 H2 主动回复或发送任意以太网帧，经端口 2 入 S，学习表才新增长久或临时的 H2 项。

</ExamExplanation>
