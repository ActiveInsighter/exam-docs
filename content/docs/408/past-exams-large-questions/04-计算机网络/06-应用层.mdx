## 2011 年第 47 题｜以太网抓包、ARP、HTTP 时延与 NAT

<Question
  id="408-net-large-2011-47"
  type="essay"
  tags="来源:2011考研408, 科目:计算机网络, 章节:应用层, 考点:以太网抓包, 考点:ARP与NAT, 考点:HTTP持续连接, 难度:综合"
>

某主机的 MAC 地址为 `00-15-C5-C1-5E-28`，IP 地址为 `10.2.128.100`（私有地址）。题图给出了网络拓扑，以及该主机进行 Web 请求时一个以太网数据帧前 80B 的十六进制内容。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2011-47-figure-001.svg" alt="2011 年第 47 题网络拓扑、以太网帧内容及报文格式" />

1. Web 服务器的 IP 地址是什么？该主机默认网关的 MAC 地址是什么？
2. 该主机在构造图中数据帧时，使用什么协议确定目的 MAC 地址？封装该协议请求报文的以太网帧目的 MAC 地址是什么？
3. 假设 HTTP/1.1 采用持续、非流水线方式，一次请求—响应耗时为一个 RTT，`rfc.html` 页面还引用 5 个 JPEG 小图像。从发出图中的 Web 请求开始，到浏览器收到全部内容，共需多少个 RTT？
4. 该帧封装的 IP 分组经过路由器 R 转发时，需要修改 IP 首部中的哪些字段？

<Solution>

### 参考答案

1. Web 服务器 IP 为 **`64.170.98.32`**；默认网关 MAC 为 **`00-21-27-21-51-EE`**。
2. 使用 **ARP 地址解析协议**查询下一跳 MAC；ARP 请求以太网帧目的 MAC 为广播 **`FF-FF-FF-FF-FF-FF`**。
3. 题目从**首个 HTTP 请求已经发出**开始计时，HTML 1 RTT + 5 张小图各 1 RTT，合计 **6 RTT**。
4. 由于图中 R 是公网出口并执行 NAT，转发时**源 IP**由 `10.2.128.100` 改为 `101.12.123.15`，**TTL 减 1**，相应地**重新计算 IPv4 首部校验和**；本题没有分片，不必改变总长度和片偏移。

### 解题过程

<Steps>
  <Step>

  **第一步：从以太网首部中读 MAC，再从 IP 首部读目的 IP，不能错开 14B。** 题图给的是**以太网帧**的前 80B，而不是从 IP 首字节起的 80B。以太网首部最前面的 6B 是目的 MAC，接下来的 6B 是源 MAC，最后 2B 是协议类型（本题为 IPv4）。

  | 以太网帧中按 1 起始的字节位置 | 字段 | 本题结果 |
  | --- | --- | --- |
  | 1～6 | 目的 MAC | `00-21-27-21-51-EE` |
  | 7～12 | 源 MAC | `00-15-C5-C1-5E-28` |
  | 13～14 | 类型 | IPv4（`0800H`） |
  | 27～30 | IP 源地址（IPv4 首部第 13～16B） | `10.2.128.100` |
  | 31～34 | IP 目的地址（IPv4 首部第 17～20B） | `40 AA 62 20`（十六进制） |

  把 `40H`、`AAH`、`62H`、`20H` 各自转为十进制：$64$、$170$、$98$、$32$，故远端 Web 服务器 IP 为 **`64.170.98.32`**。题目主机地址 `10.2.128.100` 是私有地址，访问 Internet 服务器必须经本地默认网关，因而本链路的帧目的 MAC **是网关的 MAC**，不是远端服务器的 MAC。

  </Step>
  <Step>

  **第二步：ARP 查询的是本地下一跳的 MAC，ARP 请求是广播。**

  发送前，主机根据其地址和子网掩码判断目标 Web 服务器不在本子网，便在路由表中选定默认网关作为下一跳；然后查询网关 IP 到网关 MAC 的映射：

  $$
  \underbrace{\text{目的 IP}=64.170.98.32}_{\text{整个 IP 端到端目标}}
  \quad\longrightarrow\quad
  \underbrace{\text{帧目的 MAC}=\text{默认网关 MAC}}_{\text{当前以太网链路的接收者}}.
  $$

  若缓存没有此映射，先发送 ARP 请求，目的 MAC 全部为 1，即 `FF-FF-FF-FF-FF-FF`。收到网关应答并建立 ARP 表项后，才向网关 MAC 单播发送图中的 Web 请求帧。这里还须区分**ARP（解析本地 IPv4 下一跳）**和**DNS（解析域名到 IP）**，二者解决的问题不同。

  </Step>
  <Step>

  **第三步：HTTP 时延先圈出计时起点，再判断是否能流水发送。** HTTP/1.1 的持续连接允许多次请求共用一条 TCP 连接，但“持续”不表示“流水线”。本题**非流水线**，即同一连接上必须等前一个对象的响应完成，才能请求下一个对象。

  | 动作 | 额外耗时 | 能否并行 |
  | --- | ---: | --- |
  | 请求并接收 `rfc.html` | 1 RTT | 必须先得到 HTML 才获知图片引用 |
  | 请求并接收图像 1 | 1 RTT | 不可以流水线 |
  | 请求并接收图像 2～5 | 4 RTT | 仍按顺序逐个请求 |
  | 合计 | **6 RTT** | — |

  **不再添加 TCP 握手 RTT**，因为题目已经明确从抓到的**Web 请求发出**时刻计时。若题目改为“从发起 TCP 建连开始”，在忽略其他处理时延的通常模型下才另加 1 RTT。不要把 5 个图像按同一页自动合并成一次请求。

  </Step>
  <Step>

  **第四步：把一般 IP 路由转发与本题的 NAT 区分开。** 一般 IPv4 路由器转发时必须减少 TTL，并根据修改后的首部重新校验首部；路由器通常还要在下一个链路上**重新生成以太网首部**，但链路层 MAC 不是 IPv4 首部字段。由于本题 R 位于私网到公网出口，还做源地址转换，故额外改写 IPv4 源地址：

  $$
  \texttt{10.2.128.100}\longrightarrow\texttt{101.12.123.15}.
  $$

  图中 IP 总长度是 `01EFH`，即 $1\times256+239=495\text{B}$，小于输出链路 MTU=1500B，故不发生分片。题目没有提供修改后的完整 IP 首部字节，不需要数值计算新校验和，只需指出**必须更新首部校验和**。

  </Step>
</Steps>

<Callout type="warn" title="这题最容易连续错三步">① 从帧头读 IPv4 字段要先跳过 **14B 以太网首部**；② **远端目标 IP 不等于本跳以太网帧的目的 MAC**；③ “HTTP 请求已发出”不包括先前的 DNS/ARP/TCP 建连时间。NAT 改写源地址属于额外功能，不能误说所有路由器必定 NAT。</Callout>

</Solution>
</Question>

### 原创强化题 1｜抓包字段、ARP 下一跳与 NAT 的联合判定

<Question
  id="408-net-large-2011-47-ext1"
  type="essay"
  tags="来源:原创预测题, 科目:计算机网络, 章节:应用层, 考点:以太网和IPv4字段, 考点:ARP与NAT, 难度:较难"
>

主机 A 的地址为 `10.10.1.10/24`，MAC 为 `02-00-00-00-00-0A`；默认网关 G 的内网 IP 为 `10.10.1.1`，MAC 为 `02-00-00-00-00-01`。A 的 ARP 缓存最初为空，要给远端 Web 服务器 `203.0.113.90` 发送一个**只有 IPv4 首部 20B 和 TCP 首部 20B、没有应用负载**的报文段。IP 层初始 TTL 为 64。G 的公网侧源 NAT 地址是 `198.51.100.5`；该 IP 数据报还需经过公网侧两台路由器才到达服务器，均无分片。

1. A 发出的第一条 ARP 请求帧目的 MAC 是什么？ARP 查询的目标 IPv4 地址是什么？
2. A 随后发送 TCP/IP 段时，该以太网帧的目的 MAC、IPv4 目的 IP 分别是什么？
3. IP 总长度是多少？是否需要满足 46B 最小以太网数据字段而增加填充？填充多少？
4. G 转发后源 IP、TTL 分别是多少？假定之后两台路由器各只使 TTL 减 1，服务器收到的 TTL 为多少？

<Solution>

### 参考答案

1. **广播 MAC `FF-FF-FF-FF-FF-FF`**；ARP 的目标 IPv4 地址是**下一跳 `10.10.1.1`**。
2. 二层目的 MAC 为 G 的 **`02-00-00-00-00-01`**；IPv4 目的地址始终是服务器 **`203.0.113.90`**。
3. IPv4 总长度 **40B**；需要在以太网载荷区补 **6B**，填充不计入 IP 总长度。
4. G 转发后源 IP 变为 **`198.51.100.5`**，TTL 为 **63**；此后再经过两台路由器，服务器收到 TTL 为 **61**。

### 解题过程

<Steps>
  <Step>

  **先用掩码决定下一跳。** A 的 `/24` 子网为 `10.10.1.0/24`，远端 `203.0.113.90` 不在本子网。A 必须先解析 `10.10.1.1` 的 MAC。ARP 请求封装为二层广播帧，并不是对远端 Web 服务器直接 ARP。

  </Step>
  <Step>

  **普通单播发出的两层目的地址不同。** ARP 完成后，以太网帧交给网关 MAC `02-00-00-00-00-01`；其内部 IPv4 数据报仍以 `203.0.113.90` 为目的，路由器继续依目的 IP 查路由转发。

  </Step>
  <Step>

  **分别统计 IP 总长度与以太网补齐量。** $L_{IP}=20+20+0=40\text{B}$，以太网数据区至少 46B，因此需要填充 $46-40=6\text{B}$。从 IP 层观察总长字段仍是 40；从以太网观察该段数据区已被补到 46B，外层还另有以太网首部和 FCS。

  </Step>
  <Step>

  **NAT 与 TTL 按经过的路由器数分别更新。** 先过 G：源地址由 `10.10.1.10` 变公网 `198.51.100.5`，TTL $64\to63$，并更新校验和；再过两个公网路由器：$63\to62\to61$。中途二层交换设备不减 TTL。

  </Step>
</Steps>

<Callout type="info" title="考点迁移">遇到“抓包 + 地址转换 + 帧长”的大题，优先列 **MAC 目的、IP 目的、IP 源、IP 总长度、TTL** 五栏，每层字段分开写，能防止多问连锁出错。</Callout>

</Solution>
</Question>

### 原创强化题 2｜DNS、建连与 HTTP 流水线的 RTT 预算

<Question
  id="408-net-large-2011-47-ext2"
  type="essay"
  tags="来源:原创强化题, 科目:计算机网络, 章节:应用层, 考点:HTTP持久连接, 考点:DNS与RTT, 难度:综合"
>

浏览器准备访问一个网页，其中 HTML 文档还引用 **6 张小图片**。初始没有 DNS 缓存，也尚未建立到服务器的 TCP 连接；为简化计算，DNS 查询恰好耗费 **1 RTT**，TCP 三次握手耗费 **1 RTT**。收到完整 HTML 之后才知道图片 URL。假设 DNS、网页请求和响应的 RTT 数值相同，各对象传输时间与服务器处理时间均可忽略，而且没有重传、TLS 握手及其他请求。

1. 若使用 HTTP/1.1 **持续、非流水线**连接，从发出 DNS 查询到全部 7 个对象收到，至少需要几个 RTT？
2. 若改用理想 **HTTP/1.1 流水线**，HTML 到达后立即流水发送 6 个图片请求，至少需要几个 RTT？为什么不是 1 RTT？
3. 若起点改为**TCP 已经建立、DNS 也已经解析、即将发出 HTML GET**，两种方式分别需要几个 RTT？
4. 如果 HTTP 连接是持续连接，却不允许流水线，能否仅凭“持续”就把图片的 6 个 RTT 合并为 1 个？

<Solution>

### 参考答案

1. **$1+1+1+6=9\text{ RTT}$**。
2. **$1+1+1+1=4\text{ RTT}$**：DNS、建连、HTML、流水图片请求各一轮。
3. 从 HTML GET 开始，**非流水线 7 RTT**、**流水线 2 RTT**。
4. **不能**；持续连接指复用 TCP，非流水线仍需等前一个响应后再发下一个请求。

### 解题过程

<Steps>
  <Step>

  **分清必需的前置环节。** 要访问域名，先 DNS 解析出目标 IP，消耗 1 RTT；要在新 TCP 上使用 HTTP/1.1，先建连 1 RTT。题设起点早于二者，所以两轮都需计入，不能当作每张图像各重新执行一次。

  </Step>
  <Step>

  **HTML 和图片存在依赖关系。** HTML 必须先取回才能发现 6 个 URL，故任何不预知图片地址的策略都至少经历“HTML 请求/响应”与“图片请求/响应”**两阶段**。流水线不能把第二阶段提前到 HTML 阶段之前。

  </Step>
  <Step>

  **非流水线与流水线分别算请求轮数。** 持续非流水线：1 个 HTML + 6 个依次请求的图片 = 7 RTT，合计加上前置 2 RTT 为 9 RTT。理想流水线：HTML 1 RTT，之后 6 个图片请求连续发出，忽略带宽与处理时间时响应能在同一轮 RTT 内陆续返回，应用层共 2 RTT，加前置 2 RTT 为 4 RTT。

  </Step>
  <Step>

  **改变计时起点就移除已发生的操作。** 若明确 TCP 与 DNS 都已就绪，那么不再计其 2 RTT，两者分别是 7 RTT 与 2 RTT。不能把“对象数 ×（DNS + TCP + HTTP）”机械套用。

  </Step>
</Steps>

<Callout type="warn" title="模型适用范围">此处是按题设的理想 HTTP/1.1 串行与流水线比较。HTTP/2 多路复用、连接并行、TLS、服务器推送、缓存或对象传输时延都会改变实际时间线；不可直接套 9 或 4 RTT。</Callout>

</Solution>
</Question>

## 2021 年第 47 题｜DNS、ARP 与交换机的 MAC 地址自学习

<Question
  id="408-net-large-2021-47"
  type="essay"
  tags="来源:2021考研408, 科目:计算机网络, 章节:应用层, 考点:DNS报文封装, 考点:ARP广播, 考点:交换机自学习, 难度:综合"
>

某网络拓扑如下图所示。以太网交换机 S 通过路由器 R 与 Internet 互联。路由器部分接口、本地域名服务器、H1、H2 的 IP 地址和 MAC 地址如图所示。

在 $t_0$ 时刻，H1 的 ARP 表和 S 的交换表均为空。H1 从 $t_0$ 时刻开始使用浏览器通过域名 `www.abc.com` 请求访问 Web 服务器；在 $t_1$ 时刻（$t_1>t_0$），S 第一次收到封装 HTTP 请求报文的以太网帧。假设从 $t_0$ 到 $t_1$ 期间，网络中没有发生任何与此次 Web 访问无关的通信。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2021-47-figure-001.svg" alt="2021 年第 47 题网络拓扑" />

1. 从 $t_0$ 到 $t_1$ 期间，H1 除了 HTTP 之外还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文依次通过哪些协议进行封装？
2. 若 S 的交换表表项结构为 `<MAC 地址, 端口>`，则在 $t_1$ 时刻，S 的交换表中有哪些表项？
3. 从 $t_0$ 到 $t_1$ 期间，H2 至少会接收到几个与此次 Web 访问相关的帧？这些帧是什么帧？其目的 MAC 地址是什么？

<Solution>

### 参考答案

1. H1 还需运行 **DNS**。按题设的普通 UDP DNS 查询，封装层次为 **DNS 报文 → UDP 数据报 → IPv4 数据报 → 以太网帧**。
2. 在 $t_1$ 时刻，S 至少学到下列 **3 个** `<MAC, 端口>` 表项：

   | 设备 | MAC | 交换机端口 |
   | --- | --- | ---: |
   | H1 | `00-11-22-33-44-cc` | **4** |
   | 本地 DNS 服务器 | `00-11-22-33-44-bb` | **1** |
   | 默认网关 R | `00-11-22-33-44-aa` | **2** |

3. H2 至少接收到 **2 个广播以太网帧**：H1 为解析**本地 DNS 服务器 MAC** 发出的 ARP 请求、H1 为解析**默认网关 MAC** 发出的 ARP 请求；两帧目的 MAC 均是 **`FF-FF-FF-FF-FF-FF`**。

### 解题过程

<Steps>
  <Step>

  **第一步：从域名开始逆向列前置操作，不能直接跳到 HTTP。** 浏览器只知道 `www.abc.com` 域名，先通过 DNS 获得 Web 服务器的 IP。题图本地域名服务器为 `192.168.1.126/25`，和 H1 在同一个 `/25` 子网，H1 可直接通过以太网向它发送 DNS 请求。

  一次普通 DNS 查询按协议层次封装为：

  $$
  \boxed{\text{DNS 应用报文}\to\text{UDP}\to\text{IP}\to\text{Ethernet}}.
  $$

  DNS 传统查询通常使用 UDP 53；若响应过大触发截断、执行区域传送等情况可使用 TCP。本题按普通查询答 UDP 即可。**ARP 不属于应用层协议**，虽然接下来的地址解析也会发生，但不能用 ARP 取代第一问的 DNS。

  </Step>
  <Step>

  **第二步：按时序重现“ARP → DNS → ARP → TCP → HTTP”，解释为什么有两次 ARP。**

  | 事件顺序 | H1 想通信的对象 | 二层地址处理 | S 可学习的入站帧源 MAC |
  | --- | --- | --- | --- |
  | ① ARP 查询本地 DNS | `192.168.1.126` | H1 向同一广播域广播请求 | H1 的 MAC，从端口 4 收入 |
  | ② DNS 服务器回答 ARP | H1 | DNS 服务器向 H1 单播应答 | DNS MAC，从端口 1 收入 |
  | ③ DNS 查询与应答 | 本地 DNS 服务器 | 可直接使用已获 MAC，不必再 ARP | 已有 H1、DNS 对应表项 |
  | ④ H1 ARP 查询默认网关 | 路由器 R | 远端 Web 不在本子网，需解析网关 MAC | H1 表项仍是端口 4 |
  | ⑤ R 回 ARP 应答 | H1 | R 将自身接口 MAC 单播给 H1 | R MAC，从端口 2 收入 |
  | ⑥ TCP 握手并发送 HTTP 请求 | 远端 Web 服务器 | 本地以太网帧目的 MAC 为 R 接口 | 使用已学到的 H1、R 表项 |

  **同一 IP 主机执行 DNS 与 HTTP，不意味着二者都把帧直接发送给相同设备。** 本地 DNS 查询交给本地 DNS 服务器；访问 Internet Web 服务器交给默认网关。因为 H1 在 $t_0$ 时 ARP 表为空，至少需要解析这两个不同的本地下一跳地址。

  </Step>
  <Step>

  **第三步：交换机只通过入站帧源 MAC 学习，不根据谁收到广播来学习。**

  每当 S 从某个物理端口接收以太网帧，它记录帧的**源 MAC → 入端口**。因此 H1 的第一次 ARP 广播便使 S 学到 `<00-11-22-33-44-cc,4>`；DNS 服务器的应答使 S 学到 `<00-11-22-33-44-bb,1>`；默认网关的应答使 S 学到 `<00-11-22-33-44-aa,2>`。

  H2 在题设期间没有主动发帧，S 即使把多个广播帧转发给 H2，**也不能据此生成 H2 的 MAC 地址表项**。交换机表项不是通过“查询每台机器是否在线”获得的。

  </Step>
  <Step>

  **第四步：判断 H2 能看见哪些帧，必须先区分广播与已知单播。**

  H1 发出的两次 ARP 请求，其以太网目的 MAC 都是 `FF-FF-FF-FF-FF-FF`，交换机在同一个二层广播域向除入端口外的端口洪泛，因此 H2 至少看见 2 帧。

  DNS 和路由器发给 H1 的 ARP 应答是单播，并且此时 S 已从 H1 的 ARP 请求学到 H1 的端口 4，所以应答可直接送往端口 4，不要求复制给 H2。即使有未知单播、额外 ARP 或其他现实实现行为，题目问的是**至少**收到几个，不能把未经保证的额外帧算进去。

  </Step>
</Steps>

<Callout type="warn" title="三条高频判题规则">① **DNS 解析域名，ARP 解析本地下一跳的 MAC**；② 交换机只用入站的**源 MAC + 入端口**学习，广播被转发的接收方不会被自动学习；③ “收到 2 个广播”是题设的最小保证，不能把 TCP/HTTP 的普通单播帧也机械加入 H2 的必收数量。</Callout>

</Solution>
</Question>

### 原创强化题 1｜远程 DNS 与本地 DNS 对 ARP 次数的影响

<Question
  id="408-net-large-2021-47-ext1"
  type="essay"
  tags="来源:原创强化题, 科目:计算机网络, 章节:应用层, 考点:跨网段ARP, 考点:交换表学习, 难度:较难"
>

二层交换机 S 的端口 1 连接主机 H，端口 2 连接静默主机 Q，端口 3 连接路由器 G，端口 4 连接一台**本地 DNS 服务器 L**。四个端口处于同一广播域。H=`192.168.10.10/24`，G 的 LAN 地址为 `192.168.10.1`，L=`192.168.10.53`；另有**远端** DNS 服务器 D=`192.168.20.53`，Web 服务器 W=`203.0.113.20`。初始 H 的 ARP 缓存和 S 的交换表都为空，其他设备按需正常回复，Q 从不发送任何帧。忽略其他无关通信。

1. 如果 H 配置的 DNS 是**远端 D**，在发出针对 W 的第一次 HTTP 请求之前，H **至少**需要为哪些 IP 发出 ARP 请求？Q 至少收到几个来自 H 的广播帧？
2. 该场景中第一次 HTTP 请求到达 S 时，S 至少会有哪两类设备的 MAC 学习表项？是否必然存在 L 的表项？
3. 如果把 H 配置的 DNS 改成**本地 L**，且其它条件不变，H 至少会为哪些 IP 发出 ARP 请求？Q 至少收到几个来自 H 的广播帧？
4. 对远端 D 发出的 DNS 查询，H 的 IP 分组**目的 IP**与本链路以太网帧**目的 MAC 所属设备**分别是什么？

<Solution>

### 参考答案

1. 只需 ARP 查询 **网关 G=`192.168.10.1`**，H2/Q 至少接收 **1 个** H 发出的广播 ARP 帧。
2. 至少学到 **H（端口 1）和 G（端口 3）** 的 MAC；**不必然**出现未参与通信的本地 DNS 服务器 L 的表项。
3. 至少 ARP 查询 **L=`192.168.10.53`** 与 **G=`192.168.10.1`**，Q 至少接收到 **2 个**广播 ARP 帧。
4. IPv4 目的 IP 为 **`192.168.20.53`（D）**；二层目的 MAC 属于**网关 G**，不是 D。

### 解题过程

<Steps>
  <Step>

  **是否 ARP DNS 主机，要先对 DNS 地址和本机做掩码计算。** H 所在 `/24` 是 `192.168.10.0/24`。D 的第三字节 20，与本机第三字节 10 不同，故需要经网关 G 转发。因此 H 首先广播 ARP 查询 `192.168.10.1` 的 MAC，而不是查询 `192.168.20.53` 的 MAC。

  </Step>
  <Step>

  **DNS 回复后的 Web 通信沿用相同下一跳。** W=`203.0.113.20` 同样在网外，H 已在 DNS 阶段得到 G 的 MAC，可直接复用缓存。若缓存未过期且网关不变，不需要再发第二次 ARP。S 因 H 的请求和 G 的回复学到 H→1 与 G→3；L 未发送任何帧，不必出现在学习表中。

  </Step>
  <Step>

  **切换到本地 DNS 才需要两次解析。** L=`192.168.10.53` 属于同一个 `/24`，H 首先 ARP 查询 L 并直接交换 DNS 查询/响应；之后远端 W 仍要求 ARP 查询 G。S 此时又可通过 L 的应答学到 L→4；处于同一广播域的 Q 能看见 H 发出的两个 ARP 广播。

  </Step>
  <Step>

  **两层目的地址保留各自语义。** 发往 D 的 IPv4 目的字段必须是 `192.168.20.53`，因为 DNS 请求的终点为 D；同一帧在 H 所在以太网上交给路由器 G 的 MAC。远端 DNS 的 MAC 地址不会被普通本地 ARP 所解析。

  </Step>
</Steps>

<Callout type="info" title="推理模板">先做 `目的IP AND 子网掩码`；同子网则 ARP 目的主机，异子网则 ARP 路由下一跳。**应用层访问对象相同，不代表需要相同次数的 ARP 广播**：DNS 服务器是否本地直接影响次数。</Callout>

</Solution>
</Question>

### 原创强化题 2｜VLAN 隔离下的广播可见性与交换机学习

<Question
  id="408-net-large-2021-47-ext2"
  type="essay"
  tags="来源:原创预测题, 科目:计算机网络, 章节:应用层, 考点:VLAN广播域, 考点:ARP与DNS, 考点:交换机MAC学习, 难度:综合"
>

一台支持 VLAN 的交换机 S 各端口连接如下：

| 端口 | 设备 | VLAN | 地址 |
| --- | --- | --- | --- |
| 1 | H1 | VLAN 10 | `10.10.10.10/24` |
| 2 | 本地 DNS 服务器 D | VLAN 10 | `10.10.10.53/24` |
| 3 | 网关路由器 G 的接口 | VLAN 10 | `10.10.10.1/24` |
| 4 | 静默主机 H2 | VLAN 20 | `10.10.20.20/24` |

初始 H1 的 ARP 表及 S 的 MAC 学习表为空。H1 已配置 D 为 DNS 服务器，需通过域名访问远端 Web 服务器；H2 在此期间从不发帧。D 与 G 都能正常单播返回 ARP 应答；不发生其它无关通信。二层交换机不启用 VLAN 间路由。

1. H1 为完成 DNS 查询和连接远端 Web 服务器，至少需要向哪些本地 IP 发出 ARP 请求？这些 ARP 请求的以太网帧目的 MAC 分别是什么？
2. S 是否应把这两条 ARP 广播帧复制到 H2 所在的端口 4？H2 必然接收到几个这样的广播帧？
3. S 至少能从哪些设备学到 `<MAC, VLAN, 端口>` 关联？是否能仅通过接收过的广播帧学习出 H2 的 MAC？
4. 若管理员希望 VLAN 20 中的 H2 访问 VLAN 10 中的 D，需要二层交换机默认就会做的“广播洪泛”，还是应配置**三层路由能力**？说明原因。

<Solution>

### 参考答案

1. H1 至少 ARP 查询 **D=`10.10.10.53`**、**G=`10.10.10.1`**；两次请求目的 MAC 均是 **`FF-FF-FF-FF-FF-FF`**。
2. **不应**洪泛到 VLAN 20 的端口 4；H2 因这两次请求而必然收到的广播帧数为 **0**。
3. 至少学到 **H1→(VLAN10,端口1)**、**D→(VLAN10,端口2)**、**G→(VLAN10,端口3)**；不会凭广播的接收者自动学到静默 H2 的 MAC。
4. 需要启用并正确配置**VLAN 间三层转发**（如路由器或三层交换机的 SVI 接口及相应策略），普通二层广播洪泛不能跨 VLAN 解决连通问题。

### 解题过程

<Steps>
  <Step>

  **先定位广播域。** VLAN 10 与 VLAN 20 在二层逻辑上是不同广播域，虽然它们接在**同一台物理交换机**上，二层广播依然只在所属 VLAN 内洪泛。这里 H1、D、G 都属于 VLAN 10，H2 属于 VLAN 20。

  </Step>
  <Step>

  **H1 的两次 ARP 对象不同。** D=`10.10.10.53/24` 位于 H1 本地子网，H1 需要解析 D 的 MAC 以直接查询 DNS；远端 Web 在网外，H1 需要解析 G=`10.10.10.1` 的 MAC。两次 ARP 请求均使用广播 MAC，但它们只会在 VLAN 10 内传播。

  </Step>
  <Step>

  **学习表项来自入站帧的源 MAC，并带 VLAN 作用域。** H1 在端口 1 发广播 → 学到 H1；D 从端口 2 回 ARP 应答 → 学到 D；G 从端口 3 回应 → 学到 G。因此至少有三个 VLAN10 内的学习关联。H2 只收不发，且不在广播 VLAN 内，所以不可能通过这次通信学到 H2 的 MAC。

  </Step>
  <Step>

  **跨 VLAN 通信不能靠洪泛替代路由。** 若 H2 要访问 D，`10.10.20.20/24` 与 `10.10.10.53/24` 不在同一 IP 网段，H2 要将分组交给 VLAN20 的三层网关，再由具备到 VLAN10 路由及回程路径的设备转发。仅仅把 VLAN10 的广播复制到 VLAN20，不会建立正确的 IP 子网路由。

  </Step>
</Steps>

<Callout type="warn" title="跨章节综合题的判分重点">**一台交换机不必等于一个广播域。** 无 VLAN 的普通交换机默认端口属于同一广播域；启用 VLAN 后，广播帧被限制在所属 VLAN 内。交换机自学习仍只看**入站帧的源 MAC**，不会凭“谁收到了广播”推知其 MAC。</Callout>

</Solution>
</Question>
