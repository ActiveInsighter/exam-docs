## 2011 年第 47 题

<ExamQuestion>

**111. 2011 年第 47 题**

某主机的 MAC 地址为 `00-15-C5-C1-5E-28`，IP 地址为 `10.2.128.100`（私有地址）。题图给出了网络拓扑，以及该主机进行 Web 请求时一个以太网数据帧前 80B 的十六进制内容。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2011-47-figure-001.svg" alt="2011 年第 47 题网络拓扑、以太网帧内容及报文格式" />

1. Web 服务器的 IP 地址是什么？该主机默认网关的 MAC 地址是什么？
2. 该主机在构造图中数据帧时，使用什么协议确定目的 MAC 地址？封装该协议请求报文的以太网帧目的 MAC 地址是什么？
3. 假设 HTTP/1.1 采用持续、非流水线方式，一次请求—响应耗时为一个 RTT，`rfc.html` 页面还引用 5 个 JPEG 小图像。从发出图中的 Web 请求开始，到浏览器收到全部内容，共需多少个 RTT？
4. 该帧封装的 IP 分组经过路由器 R 转发时，需要修改 IP 首部中的哪些字段？

<ExamSolution>

<ExamAnswer>

1. Web 服务器 IP 地址为 `64.170.98.32`；默认网关 MAC 地址为 `00-21-27-21-51-EE`。
2. 使用 ARP；ARP 请求帧的目的 MAC 地址为 `FF-FF-FF-FF-FF-FF`。
3. 共需 $6$ 个 RTT。
4. 本题中应修改：源 IP 地址、TTL、首部校验和。源 IP 地址由 `10.2.128.100` 转换为 `101.12.123.15`，TTL 减 1，并重新计算 IP 首部校验和。

</ExamAnswer>

<ExamExplanation>

### （1）由帧内容确定目的 IP 和默认网关 MAC

以太网首部长度为

$$
6+6+2=14\text{ B}.
$$

IPv4 首部中的目的 IP 地址位于首部第 17～20 字节，因此在以太网帧中从第 31 字节开始。图中对应的 4 个字节为

$$
\texttt{40 AA 62 20}_{16},
$$

换成十进制即

$$
64.170.98.32.
$$

以太网帧最前面的 6B 是**目的 MAC 地址**，图中为 `00-21-27-21-51-EE`。由于 Web 服务器不在本地私有网络内，主机应把帧交给默认网关，因此该目的 MAC 就是默认网关接口的 MAC 地址。

### （2）ARP

主机已知下一跳默认网关的 IP 地址，需要通过 ARP 得到其 MAC 地址。若本机 ARP 缓存中没有对应项，则先广播 ARP 请求，因此以太网目的地址为

$$
\texttt{FF-FF-FF-FF-FF-FF}.
$$

### （3）持续非流水线 HTTP

持续连接只建立一次 TCP 连接；本问从题图中的 Web 请求已经发出开始计时，因此只计算 HTTP 请求—响应 RTT。

- 获取 `rfc.html`：$1$ RTT；
- 页面引用 5 个 JPEG，小图像必须依次请求，每个再用 $1$ RTT。

故总时间为

$$
1+5=\boxed{6\text{ RTT}}.
$$

### （4）路由器转发时的首部变化

路由器 R 同时承担 NAT。源地址 `10.2.128.100` 是私有地址，出 Internet 时被转换为 R 的公网地址 `101.12.123.15`。每经过一个路由器，TTL 还要减 1；因为 IP 首部发生变化，所以必须重新计算首部校验和。

题图中该 IP 分组总长度字段为 `01EFH`，即 495B，小于输出链路 MTU 1500B，因此本题不会发生 IP 分片，总长度、标志和片偏移无需改变。



### 十六进制抓包题的通用审题清单

1. **先标记首部边界。** 以太网首部 14B：目的 MAC（6B）｜源 MAC（6B）｜类型（2B）；若类型为 `0800`，后面是 IPv4。IPv4 首部中总长度在第 3～4B，TTL 在第 9B，协议字段在第 10B，源/目的 IP 分别在第 13～16B 与 17～20B。做地址题先确认“给的是以太网帧还是 IP 分组”，否则所有偏移都会错 14B。
2. **远端目标 MAC 不在当前以太帧里。** H 到异网段服务器通信时，IP 目的仍为服务器 `64.170.98.32`，但当前链路帧的目的 MAC 是默认网关的接口 MAC；通过 ARP 查询的是**下一跳** IP 的 MAC，而不是远端 Web 服务器 MAC。ARP 请求广播，ARP 应答通常单播。
3. **题中 R 具有 NAT 功能，不能只答 TTL。** IPv4 路由转发的一般变化是 TTL 减 1，IPv4 首部校验和相应更新；本题出公网时还做源地址 NAT，将私网源 IP 改为 R 的公网 IP。若执行 PAT，还可能同时改源端口并更新运输层校验和，但题目问 IPv4 首部、且未给出端口映射，不能强行添加一条未知端口结论。
4. **HTTP 时延从“请求已经发出”开始。** 初始 TCP 建连、DNS 解析等已不在本问计时区间。HTTP/1.1 持续、非流水线：一个 HTML 响应用 1 RTT，解析后 5 个小图像顺序请求再用 5 RTT，合计 6 RTT（题设将每次请求响应近似为 1 RTT，且忽略发送/处理时延）。如果从建立连接前算，且 DNS 已知，还须再加 1 RTT 建连。
5. **NAT、路由转发、二层封装是三个不同层次的动作。** 路由器读取目的 IP 决定下一跳；重新封装新链路的源/目的 MAC；NAT 只在配置且命中规则时改 IP/端口字段。题设 IP 总长 495B、小于 1500B 的 MTU，因此无需给出分片的 MF/offset 改变。

</ExamExplanation>

<ExamQuestion>
一台主机的地址是 `10.0.0.12/24`，默认网关为 `10.0.0.1`，网关接口 MAC 为 `02-AA-00-00-00-01`。用户访问远端 Web 服务器 `203.0.113.80`，出口路由器进行源地址 NAT，公网地址为 `198.51.100.9`。浏览器已获得服务器 IP，DNS 与 ARP 耗时忽略；HTTP/1.1 使用同一条持续连接且不支持流水线，HTML 首页含 3 张图片，传输/处理时延忽略。

1. 主机发出的请求 IP 分组的目的 IP 是什么？封装其以太网帧时目的 MAC 应是什么？
2. 出口路由器转发并完成 NAT 后，源 IP 会变为什么？若该路由器转发前 TTL=64，转发后 TTL 是多少？
3. 从**第一个 HTTP 请求发出**开始，到 4 个对象全部接收，共需多少 RTT？
4. 若改为从 TCP 建连之前开始计时、且 DNS 已完成，还需多少 RTT？
<ExamSolution>
<ExamAnswer>

1. 目的 IP `203.0.113.80`，目的 MAC `02-AA-00-00-00-01`。
2. 源 IP 转换为 `198.51.100.9`，TTL 为 63，IPv4 首部校验和需要更新。
3. $1+3=4RTT$。
4. 建连再加 $1RTT$，共 $5RTT$。

</ExamAnswer>
<ExamExplanation>

1. IP 标识端到端目标，MAC 只标识当前链路的下一跳。服务器在异网段，所以发给默认网关，而不是通过 ARP 去问远端服务器的 MAC。
2. 地址转换改的是本题客户端的**源 IP**；目的 IP 仍指向远端 Web 服务器。IPv4 TTL 随路由转发减 1，IP 首部因被更改需重新校验。
3. HTTP 非流水线要求前一对象响应完才发下一对象请求，持续连接避免每个对象都重复三次握手，但不能使 3 张图片与 HTML 全部用一个 RTT 依次完成。
4. 时延题第一步总要圈出计时起点：从 HTTP 请求开始和从 TCP 建连请求开始不是同一个答案。

</ExamExplanation>
</ExamSolution>

<ExamQuestion>
某浏览器已经和服务器建立 TCP 持续连接，DNS 已解析。首页 HTML 引用 4 张小图片，服务器处理时间、传输时间均忽略，且 HTML 内容必须收到后才能获知图片 URL。假定请求与响应 RTT 均为常量。

1. HTTP/1.1 持续、非流水线方式，从发出首页 GET 到全部对象收到，需要几个 RTT？
2. 如果允许 HTTP/1.1 流水线，并在首页到达后连续发出 4 个图片请求，从发出首页 GET 起至少需几个 RTT？
3. 如果两种方式都改为从 TCP 三次握手开始前计时，且无需 DNS，应各增加多少 RTT？
4. 为什么不能把题目中的“持续连接”直接理解为所有对象只需一个 RTT？
<ExamSolution>
<ExamAnswer>

1. $1+4=5RTT$。
2. $1+1=2RTT$。
3. 均增加 $1RTT$，因此分别为 6 RTT 和 3 RTT。
4. 持续连接只意味着 TCP 连接复用；是否允许多个未完成请求并发、能否提前得知图片 URL 属于另外的条件。

</ExamAnswer>
<ExamExplanation>

1. 获取 HTML 需要一个 RTT，此后 4 张图片若逐一发起请求和等响应，每张各消耗一个 RTT。
2. HTML 到达前无法请求尚未知晓的图片；到达后可把图片请求连续放在同一条 TCP 连接中，理想流水线最短再用 1 RTT 返回全部小图片。这里假设响应无显著传输/排队时间。
3. TCP 初次建连一般还占一个 RTT，注意该 RTT 对所有对象只收取一次，而不是每张图都重新加一次。
4. HTTP/2 多路复用、HTTP/1.1 流水线和 HTTP/1.1 非流水线属于不同请求调度模型，做题须严格使用题设。

</ExamExplanation>
</ExamSolution>

## 2021 年第 47 题

<ExamQuestion>

**121. 2021 年第 47 题**

某网络拓扑如下图所示。以太网交换机 S 通过路由器 R 与 Internet 互联。路由器部分接口、本地域名服务器、H1、H2 的 IP 地址和 MAC 地址如图所示。

在 $t_0$ 时刻，H1 的 ARP 表和 S 的交换表均为空。H1 从 $t_0$ 时刻开始使用浏览器通过域名 `www.abc.com` 请求访问 Web 服务器；在 $t_1$ 时刻（$t_1>t_0$），S 第一次收到封装 HTTP 请求报文的以太网帧。假设从 $t_0$ 到 $t_1$ 期间，网络中没有发生任何与此次 Web 访问无关的通信。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2021-47-figure-001.svg" alt="2021 年第 47 题网络拓扑" />

1. 从 $t_0$ 到 $t_1$ 期间，H1 除了 HTTP 之外还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文依次通过哪些协议进行封装？
2. 若 S 的交换表表项结构为 `<MAC 地址, 端口>`，则在 $t_1$ 时刻，S 的交换表中有哪些表项？
3. 从 $t_0$ 到 $t_1$ 期间，H2 至少会接收到几个与此次 Web 访问相关的帧？这些帧是什么帧？其目的 MAC 地址是什么？

<ExamSolution>

<ExamAnswer>

1. 还运行 DNS。封装关系为：DNS 报文 $\rightarrow$ UDP 数据报 $\rightarrow$ IP 数据报 $\rightarrow$ 以太网帧。
2. $t_1$ 时刻交换表至少包含：`<00-11-22-33-44-cc, 4>`、`<00-11-22-33-44-bb, 1>`、`<00-11-22-33-44-aa, 2>`。
3. 至少接收到 $2$ 个帧，均为封装 ARP 请求报文的广播以太网帧，目的 MAC 地址均为 `FF-FF-FF-FF-FF-FF`。

</ExamAnswer>

<ExamExplanation>

### （1）DNS 及逐层封装

H1 使用的是域名 `www.abc.com`，在发送 HTTP 请求之前必须先获得该域名对应的 IP 地址，因此还需要运行 **DNS**。

DNS 通常使用 UDP 作为运输层协议，因此从应用层向下的封装关系为

$$
\text{DNS 报文}
\rightarrow
\text{UDP 数据报}
\rightarrow
\text{IP 数据报}
\rightarrow
\text{以太网帧}.
$$

原材料中将最后一层表述为“CSMA/CD 帧”，这里按题图中的以太网交换网络统一表述为“以太网帧”。

### （2）交换表的学习过程

交换机根据**收到帧的源 MAC 地址和入端口**学习表项。

在 $t_0$ 时刻，H1 的 ARP 表为空。H1 首先需要访问本地域名服务器 `192.168.1.126/25`，因此先发送 ARP 请求。S 从端口 4 收到该帧后，学习到

`<00-11-22-33-44-cc, 4>`。

本地域名服务器发送 ARP 应答时，S 从端口 1 收到该帧，于是学习到

`<00-11-22-33-44-bb, 1>`。

DNS 解析完成后，H1 发现 Web 服务器位于 Internet，需要把分组交给默认网关 R。由于 H1 尚不知道 R 的 MAC 地址，因此还会广播 ARP 请求。R 返回 ARP 应答时，S 从端口 2 收到该帧，于是学习到

`<00-11-22-33-44-aa, 2>`。

H2 在此期间没有主动发送帧，因此交换机不会仅因为向 H2 所在端口转发广播帧而学习 H2 的 MAC 地址。

所以在 $t_1$ 时刻，交换表为：

| MAC 地址 | 端口 |
| --- | ---: |
| `00-11-22-33-44-cc` | 4 |
| `00-11-22-33-44-bb` | 1 |
| `00-11-22-33-44-aa` | 2 |

### （3）H2 接收到的广播帧

从 $t_0$ 到 $t_1$，至少出现两次 ARP 广播：

- H1 查询本地域名服务器的 MAC 地址；
- H1 查询默认网关 R 的 MAC 地址。

ARP 请求封装在广播以太网帧中，S 会向除入端口外的其他相关端口转发，因此 H2 至少会收到这两个帧。

二者的目的 MAC 地址均为

$$
\boxed{\texttt{FF-FF-FF-FF-FF-FF}}.
$$



### DNS、ARP 与交换机自学习逐帧梳理

1. **DNS 是应用层，ARP 不是应用层。** H1 为域名访问须进行 DNS 查询；经典 DNS 查询经 UDP 53 端口承载，DNS 数据→UDP→IPv4→Ethernet。大型响应、区域传送或有特殊配置时 DNS 也能用 TCP，故“DNS 永远只能用 UDP”是错误扩展。
2. **H1 ARP 表为空并不意味着每发一个 IP 分组都要广播一次 ARP。** 本地域名服务器就在 H1 的同一子网 `/25`，先 ARP 解析 DNS 服务器 MAC；目标 Web 服务器在网外，H1 再 ARP 解析本地默认网关 MAC；中间已解析成功的表项可以重复使用，HTTP 后续 TCP 段不必每段 ARP。
3. **交换机只靠收到帧的源 MAC 学习。** H1 广播 ARP 请求，S 在入端口 4 学到 H1；DNS 服务器的应答从端口 1 进入，学到 DNS；路由器的 ARP 应答从端口 2 进入，学到网关。S 把广播帧复制到 H2 所在端口，但**向一个端口转发**不等于**学习那个端口上的设备 MAC**，所以表中没有静默 H2。
4. **题目问“至少”，应统计必然发生的广播。** H2 至少看见 H1 对 DNS 服务器、对默认网关各一次 ARP 请求，目的 MAC 均为广播 `FF-FF-FF-FF-FF-FF`。如果 DNS 服务器等其他设备恰好没有 ARP 缓存，它们也可能发额外 ARP 广播，但题目未必给出这些设备缓存，不能据此把最小值改大。
5. **未知单播洪泛与广播洪泛不是一回事。** 如果交换机尚不知道某单播目的 MAC，可能向其他端口洪泛；本题两次 ARP 应答返回前，交换机已经从请求学到 H1 MAC，因此返回给 H1 的已知单播通常不会经过 H2 端口。跨子网 HTTP 帧的链路目的 MAC 是本地网关，而不是远端 Web 主机或 H2。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>
交换机 S 连接四个端口：端口 1 是 H1，端口 2 是本地 DNS 服务器 D，端口 3 是默认网关 G，端口 4 是始终不发送帧的 H2。H1 与 D、G 位于同一 IPv4 子网；目标 Web 服务器在远端。起始时 H1 的 ARP 表和 S 的交换表为空，H1 已配置 DNS 服务器地址。为解析域名并访问 Web，H1 依次 ARP 请求 D、进行 DNS 查询、ARP 请求 G，并完成 TCP 建连。假定 D、G 均单播回复 ARP，网络中没有其他通信。

1. H1 从解析域名到请求网页，涉及哪些典型的应用层协议？DNS 查询通常被如何逐层封装？
2. H1 至少发出几个 ARP 广播请求？每个广播帧的目的 MAC 是什么？
3. 在发出首次 HTTP 请求时，S 至少能从哪些设备学到 MAC 与端口对应关系？
4. H2 至少收到几个与此次通信有关的广播帧？为什么不会仅因这些广播使自己的 MAC 出现在 S 的表中？
<ExamSolution>
<ExamAnswer>

1. DNS、HTTP；DNS→UDP→IPv4→以太网（经典查询场景）。
2. 两次；目的 MAC 均为 `FF-FF-FF-FF-FF-FF`。
3. H1→端口 1，D→端口 2，G→端口 3。
4. 至少两帧；交换机仅通过**入站帧的源 MAC**学习，H2 未发送帧，不能学出它的 MAC。

</ExamAnswer>
<ExamExplanation>

1. 域名首先要解析成 Web 服务器 IP，通常使用 UDP 53 查询；随后 HTTP 走 TCP 连接，两种应用层协议的运输层承载并不相同。
2. 主机想把帧交给同子网 D，先知道 D 的 MAC；远端 Web 服务器则需要交给 G，于是再知道 G 的 MAC。两次 ARP 请求皆为二层广播。
3. 第一次 H1 的广播使交换机学到 H1；D 返回 ARP 响应使交换机学到 D；G 返回 ARP 响应使交换机学到 G。
4. 交换机广播洪泛到同 VLAN 的其他端口，H2 因此会收到请求；然而 H2 没发送任何源 MAC 为自己的入站帧，不会被自动记录。若其他主机也恰好没有 ARP 缓存，广播数可能更多，所以问题问“至少”。

</ExamExplanation>

<ExamQuestion>
H1=`192.168.10.10/24`，默认网关 G=`192.168.10.1`，远端 DNS 服务器 D=`192.168.20.53`，远端 Web 服务器 W=`203.0.113.20`。H1 的 ARP 缓存初始为空；本地交换机还连接静默主机 H2。H1 已知 D 的 IP，只需向 D 查询 W 的地址；假设网关 MAC 经首次 ARP 后始终有效，DNS 通过 UDP 53 查询，且没有其他无关通信。

1. H1 在发送 DNS 查询前，应 ARP 解析 D 的 MAC 还是 G 的 MAC？为什么？
2. DNS 回复后 H1 首次访问 W 时，还需为 W 再发一次 ARP 广播吗？
3. 从发起 DNS 查询准备工作到向 W 发送 HTTP 请求之前，H2 至少收到多少次由 H1 发出的 ARP 广播？
4. 列出发往 D 的 IP 分组在 H1 本地以太网链路上的目的 IP 与目的 MAC 所属设备。
<ExamSolution>
<ExamAnswer>

1. ARP 解析 G 的 MAC；D 不在 H1 的 `192.168.10.0/24` 子网内。
2. 不需要；本地下一跳仍是 G，已缓存 G 的 MAC。
3. 至少一次，即最初解析 G 的 ARP 请求。
4. IP 目的地址为 `192.168.20.53`（D），以太网目的 MAC 为默认网关 G 的 MAC。

</ExamAnswer>
<ExamExplanation>

1. 是否需要对 DNS 服务器本身 ARP，取决于 DNS 的 IP 是否处在本地链路。远端 DNS 只能经过路由器，主机首先 ARP **下一跳网关**。
2. DNS 解析出 W 的公网地址后，H1 仍使用同一个默认网关转发到异网段，不会再对 W 的公网 IP 发本地广播 ARP 请求。
3. DNS 与 HTTP 虽属于两个应用层协议，但本地链路目的都为 G；第一次得到 G 的 ARP 缓存表项后可复用，所以本题的必要广播只有一次。若 G 或别的设备主动发送 ARP，请另据题意统计，不属于 H1 必要发出的广播。
4. 区分“IP 目的地址是最终服务器”与“链路层目的 MAC 是下一跳路由器”；这是 ARP/交换机与 IP 路由层叠分析题的关键。

</ExamExplanation>
</ExamSolution>
