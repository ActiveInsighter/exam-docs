## 2012 年第 47 题

<ExamQuestion>

**112. 2012 年第 47 题**

主机 H 通过快速以太网连接 Internet，IP 地址为 `192.168.0.8`；服务器 S 的 IP 地址为 `211.68.71.80`。H 与 S 使用 TCP 通信时，在 H 上捕获到 5 个 IP 分组，其前 40B 如图所示。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2012-47-figure-001.svg" alt="2012 年第 47 题捕获的 5 个 IP 分组" />

1. 哪几个 IP 分组由 H 发送？哪几个分组完成了 TCP 连接建立过程？哪几个分组通过快速以太网传输时需要填充？
2. 根据这些分组，S 已经收到多少字节应用层数据？
3. 若其中某个由 S 发出的 IP 分组在发送时前 40B 如下图所示，则该分组到达 H 时经过了多少个路由器？

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2012-47-figure-002.svg" alt="2012 年第 47 题服务器发出时的 IP 分组内容" />

<ExamSolution>

<ExamAnswer>

1. H 发送的是 1、3、4 号分组；1、2、3 号分组完成 TCP 三次握手；3、5 号分组在以太网上传输时需要填充。
2. S 已收到 $16\text{ B}$ 应用层数据。
3. 共经过 $15$ 个路由器。

</ExamAnswer>

<ExamExplanation>

### （1）判断方向、握手与以太网填充

IPv4 首部的源 IP 地址位于第 13～16 字节。1、3、4 号分组中的源地址均为

$$
\texttt{C0 A8 00 08}=192.168.0.8,
$$

因此它们由 H 发出。

TCP 三次握手可由 SYN、ACK 标志和序号关系判断：

- 1 号：`SYN=1, ACK=0`；
- 2 号：`SYN=1, ACK=1`，确认 1 号；
- 3 号：`ACK=1`，确认 2 号。

所以 1、2、3 号构成连接建立过程。

以太网帧的数据字段最小为 46B。3、5 号 IP 分组总长度字段为 `0028H`，即

$$
40\text{ B}<46\text{ B},
$$

因此封装成以太网帧时需要补齐 6B；其余分组无需填充。

### （2）应用层数据量

连接建立后 H 发送数据的起始序号为

$$
\texttt{846B41C6H}.
$$

5 号分组中 S 返回的确认号为

$$
\texttt{846B41D6H}.
$$

TCP 确认号表示“下一字节序号”，因此 S 已正确收到的数据量为

$$
\texttt{846B41D6H}-\texttt{846B41C6H}
=\texttt{10H}
=\boxed{16\text{ B}}.
$$

### （3）根据 TTL 判断经过的路由器数

先用 IP 首部标识字段判断图中服务器发送的分组与捕获的 5 号分组对应。发送时 TTL 为

$$
\texttt{40H}=64,
$$

H 捕获时 TTL 为

$$
\texttt{31H}=49.
$$

每经过一个路由器 TTL 减 1，因此路由器数为

$$
64-49=\boxed{15}.
$$



### 解题路线、首部定位与易错点

1. **先分层，后取字节。** 题图直接给出的是 IP 分组前 40B，而不是包含以太网首部的原始帧；IPv4 首部固定字段中的源地址从 IP 首部第 13B 开始，目的地址从第 17B 开始，TTL 位于第 9B。只有在题目给出完整以太网帧时，才把前 14B 的链路首部计入偏移。IPv4 的 IHL 与 TCP 的 Data Offset 分别决定两层首部实际长度，不能一律认为含选项时仍是 20B。
2. **三次握手的“次数”指 TCP 报文段，不是应用数据段。** 客户端 `SYN(seq=x)`、服务器 `SYN+ACK(seq=y,ack=x+1)`、客户端 `ACK(ack=y+1)` 形成三段握手；SYN 占一个序号，纯 ACK 不占序号。建立连接的第三个 ACK 可以与数据合并，但本题按图中各段判断。
3. **填充检查要对照 IP 总长度。** 普通 Ethernet II 帧有效载荷（IP 分组）最少 46B，若 IP 总长度 40B，需在**以太网数据字段外补 6B**。填充不算进 IP 的 Total Length、TCP 的数据长度，也不算作接收方应用数据；最小 64B 以太网帧通常还包含 14B 首部和 4B FCS。不要因为抓包工具可能省略 FCS/填充而混淆两种长度。
4. **TCP ACK 是“累计确认的下一个字节”，不是已经收到的最后一个字节。** 第一次数据序号到 ACK 的差得到 16B，前提是同一方向连续数据均已确认且没有 SYN/FIN 落入所求区间。如果发生重传，不能简单把每个发送段的长度累加成“新收到的字节数”；序号计算按模 $2^{32}$ 理解回绕。
5. **TTL 差值得先确认是同一个 IP 数据报。** 对照 IP 标识、源目的地址及题设分组，确定出发时 64、到达时 49，才有 $64-49=15$ 个三层转发路由器。二层交换机不会递减 TTL；端主机接收时不会再按一次转发计数。若经过 NAT，地址可能变化，此时尤其需要其他标识和题意确保两图确实对应。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>
某客户端 A（地址 `10.0.0.3`）与服务器 B 建立 TCP 连接。抓包显示：A 的 `SYN(seq=5000)`、B 的 `SYN+ACK(seq=9000,ack=5001)`、A 的 `ACK(ack=9001)`，随后 A 发送 28B TCP 负载，B 回累计 `ACK=5029`。假设 IPv4/TCP 均无选项，IPv4 首部 20B、TCP 首部 20B；发送端 IP TTL=58，同一分组到达目的主机时 TTL=52。以太网数据字段最小长度 46B。

1. 写出三个握手段的含义，说明 A 的第一个数据字节序号。
2. 28B 数据段封装后的 IPv4 总长度是多少？需要以太网填充吗？若有，仅含首部的纯 ACK 又如何？
3. B 的 `ACK=5029` 说明哪些数据已被累计确认？
4. 该数据报到达目的地之前经过多少个路由器？
<ExamSolution>
<ExamAnswer>

1. 依次是请求连接、服务器确认且同步自身序号、客户端确认服务器 SYN；A 第一个数据字节序号为 $5001$。
2. 数据段 IP 总长 $20+20+28=68\text{B}$，不填充；纯 ACK IP 总长 40B，需填充 6B。
3. 已累计确认序号 $5001$～$5028$ 共 28B；下一期待字节为 5029。
4. $58-52=6$ 个路由器。

</ExamAnswer>
<ExamExplanation>

1. SYN 即使不携带数据也占用一个序号；服务器 SYN 序号 9000，客户确认号因此是 9001，不能把第二次握手的序号加到客户端数据序号上。
2. 以太网要保证的是它的数据字段至少 46B，不是 TCP 负载至少 46B；填充位不会交给应用，也不会改变 IP Total Length。
3. `ACK=5029` 对连续 TCP 字节流做累计确认，表示此前的 $5029-5001=28$ 个字节已到达，而不是“服务器已经收到 5029B”。
4. TTL 在每一台转发路由器处至少减 1，链路层交换机不递减。这里假设给出的两个 TTL 属于同一个数据报。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

<ExamQuestion>
某 TCP 连接客户端初始序号为 1200。握手完成后，客户端发出一个 IPv4 数据报：IPv4 首部为 20B，带 TCP 选项的 TCP 首部为 32B，IPv4 总长度 64B。紧接着客户端发送 FIN，无其他数据。链路是普通以太网，数据字段至少 46B。

1. 求该数据报的应用数据长度，以及第一个和最后一个数据字节的序号。
2. 求 FIN 的序号、服务器完整接收 FIN 后确认号。
3. 上述携带数据的 IP 分组是否需要以太网填充？若一个只有 20B IPv4 首部和 20B TCP 首部的纯 ACK 被单独发送，需填充几字节？
4. 为何不能把 TCP 选项长度也计入应用数据？
<ExamSolution>
<ExamAnswer>

1. 应用数据 $64-20-32=12\text{B}$；序号 $1201$～$1212$。
2. FIN 序号 $1213$；服务器确认号 $1214$。
3. 64B IP 分组不需要；40B 纯 ACK 需要填充 6B。
4. TCP 选项属于 TCP 首部，数据长度必须使用 TCP 实际首部长度扣减。

</ExamAnswer>
<ExamExplanation>

1. 客户端 SYN 使用序号 1200，所以数据从 1201 开始。带选项的 TCP 首部长度由 Data Offset 字段确定，本题 32B 而非 20B。
2. 数据 12B 使用 1201～1212，FIN 紧接着消耗 1213，一个新的累计 ACK 因此为 1214。
3. 以太网帧长度判定只对 IP 总长与 46B 下限比较，不能把 TCP 控制标志视作额外“1 字节有效载荷”。
4. 若混淆 IP 总长和 TCP 负载长度，会同时算错 TCP 确认号及帧填充长度，这是抓包综合题常见连环失分点。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

## 2016 年第 41 题

<ExamQuestion>

**116. 2016 年第 41 题**

题图网络中，H3 访问 Web 服务器 S。S 为新 TCP 连接分配 20KB（$K=1024$）接收缓存，最大报文段长度 $MSS=1\text{ KB}$，平均往返时间 $RTT=200\text{ ms}$。H3 建立连接时初始序号为 100，并持续以 MSS 大小发送数据；拥塞窗口初始阈值为 32KB。S 对每个收到的段都立即确认并通告新的接收窗口。连接建立后，S 的接收缓存只有数据写入，没有数据被应用程序取走。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2016-41-figure-001.svg" alt="2016 年第 41 题网络拓扑" />

1. H3 收到的第二次握手 TCP 段中，SYN、ACK 标志位分别是多少？确认号是多少？
2. H3 收到第 8 个确认段时，S 通告的接收窗口是多少？此时 H3 的拥塞窗口和发送窗口分别是多少？
3. 当 H3 的发送窗口变为 0 时，下一个待发送数据段的序号是多少？从发送第 1 个数据段到发送窗口变为 0，平均数据传输速率是多少？忽略报文段发送时延。
4. 若通信已结束，在时刻 $t$ H3 请求断开连接，从 $t$ 起 S 最快经过多长时间释放连接？

<ExamSolution>

<ExamAnswer>

1. `SYN=1`，`ACK=1`，确认号为 `101`。
2. 接收窗口为 $12\text{ KB}$；拥塞窗口为 $9\text{ KB}$；发送窗口为 $9\text{ KB}$。
3. 下一个待发送数据段序号为 $20581$；平均数据传输速率为

$$
\boxed{163.84\text{ kbps}}.
$$

4. 最短为 $300\text{ ms}$。

</ExamAnswer>

<ExamExplanation>

### （1）第二次握手

H3 的初始序号为 100。第一次握手的 SYN 段虽然不携带应用数据，但会占用一个序号，因此 S 返回第二次握手时：

$$
SYN=1,\qquad ACK=1,\qquad ack=100+1=101.
$$

### （2）第 8 个 ACK 到达时的三个窗口

S 的接收缓存最初为 20KB，每收到 1 个 1KB 段就少 1KB 可用空间，且没有应用读取数据。收到 8 个段后：

$$
rwnd=20-8=12\text{ KB}.
$$

慢开始初始拥塞窗口为 1 MSS，即 1KB；每收到一个对新数据的 ACK，$cwnd$ 增加 1 MSS，所以收到 8 个 ACK 后：

$$
cwnd=1+8=9\text{ KB}.
$$

实际发送窗口为

$$
swnd=\min(cwnd,rwnd)=\min(9,12)=\boxed{9\text{ KB}}.
$$

### （3）序号与平均速率

S 最终缓存满 20KB，也就是已经接收

$$
20\times1024=20480\text{ B}
$$

数据。H3 第一个数据字节序号为 101，因此下一个待发送字节序号是

$$
101+20480=\boxed{20581}.
$$

慢开始发送轮次可按 $1,2,4,8,5$ KB 理解，共 5 个 RTT 后 20KB 数据均被确认、接收窗口降为 0，因此历时

$$
5\times200\text{ ms}=1\text{ s}.
$$

平均数据传输速率为

$$
\frac{20\times1024\times8}{1}
=163840\text{ bit/s}
=\boxed{163.84\text{ kbps}}.
$$

原整理中把 `20 KB/s` 错换算成了 `20.48 kbps`，这里已按字节与比特关系修正。

### （4）S 最快释放连接的时间

H3 的 FIN 到达 S 需要约半个 RTT；S 无待发送数据，可立即回复 ACK 并发送自己的 FIN；该 FIN 到达 H3 再用半个 RTT；H3 的最终 ACK 返回 S 又用半个 RTT。因此 S 收到最终 ACK 并释放连接的最短时间为

$$
\frac32 RTT
=1.5\times200\text{ ms}
=\boxed{300\text{ ms}}.
$$



### 窗口演化、吞吐量与连接释放的统一判断

1. **辨认三种窗口及其单位。** `rwnd` 是接收端可用缓存所允许的字节数，`cwnd` 是发送端拥塞控制额度，`swnd=min(rwnd,cwnd)` 是两者约束的窗口上界；真正还能新增发送的数据量还要扣除已发送而未确认的在途字节。题设的 $MSS=1\text{KB}=1024\text{B}$，因此前 8 个新数据确认令 $cwnd$ 从 1 增到 9 MSS；接收缓存因 8KB 进入而降至 12KB。
2. **不要把“收到第 8 个确认”误当第 8 轮 RTT。** 这里逐个 ACK 驱动拥塞窗口，8 个 ACK 可分布在多轮中。拥塞控制初始阈值 32KB 尚未触及，所以持续慢开始；若达到阈值，则后续按拥塞避免的约一 RTT 增加 1 MSS 规则处理（具体实现可以按字节计数）。
3. **最后的数据段不是第 5 轮满额发送。** 在题设的按轮次、立即确认和忽略发送时延模型中，发送量依次 $1,2,4,8,5$ MSS，总和 20 MSS。必须等第 5 轮数据的 ACK 返回，接收端才能通告零窗口、发送端才能确定窗口降为零。因此传输历时 $5RTT=1\text{s}$，平均应用数据速率 $20\times1024\times8/1=163840\text{bit/s}$。这里的 kbps 按 $1000\text{bit/s}$ 计。
4. **零窗口是流量控制事件，不等同于拥塞。** 即使拥塞窗口还很大，也不能越过接收端的零窗口发送常规新数据。TCP 可用持续计时器和零窗口探测处理窗口更新丢失问题；只有收到有效窗口更新且对方能接收后才能恢复正常发送。
5. **主动关闭方和被动关闭方行为不同。** 题目问的是服务器 S 何时能释放，故只需从 H3 的 FIN 到 S、S 的 FIN 到 H3、H3 最后 ACK 返回 S 共 $3RTT/2$；通常进入 TIME_WAIT 的是主动关闭方 H3，而不是本题被动关闭的 S。实际服务器能否立刻发 FIN 还依赖应用是否结束发送，题设求的是最快时间。

</ExamExplanation>

</ExamSolution>

4. `cwnd` 可能仍大于零，但 `rwnd=0` 必须停止普通数据；零窗口探测用于避免只因窗口更新报文丢失而永久停滞。

<ExamQuestion>
发送方连续发送 8 个 $MSS=1000\text{B}$ 的数据段，初始 $cwnd=1MSS$、阈值 $8MSS$；接收端应用同步读取，始终通告 $rwnd=3MSS$。$RTT=50\text{ms}$，无丢包、立即 ACK，按整轮发送且忽略发送时延。发送方 SYN 序号为 10。

1. 发送方最开始三个 RTT 轮次各最多可发多少数据段？累计发送多少段？
2. 全部 8 段可以按怎样的轮次发送？从首段发出到末段被确认至少需多长时间？
3. 最后一个数据段确认后的下一个数据字节序号是多少？平均应用数据速率是多少？
4. 是否能仅根据接收窗口 $3MSS$ 断言发送方拥塞窗口等于 3MSS？
<ExamSolution>
<ExamAnswer>

1. 第 1、2、3 轮最多发送 1、2、3 段，累计 6 段。
2. 轮次为 $1,2,3,2$ 段，共 4 RTT 即 $200\text{ms}$。
3. 下一个序号 $11+8000=8011$；平均速率 $8000\times8/0.2=320000\text{bit/s}=320\text{kbps}$。
4. 不能。$rwnd$ 与 $cwnd$ 独立；第三轮前 $cwnd=4MSS$，但被 $rwnd=3MSS$ 限制。

</ExamAnswer>
<ExamExplanation>

1. 最初 $cwnd=1$，第一轮 ACK 后增长为 2，第二轮 2 个 ACK 后增长为 4；第三轮实际发送上限是 $\min(4,3)=3$，不是 4。
2. 第三轮收完三个 ACK 后拥塞窗口可继续增长，但文件只剩 2 段，因此最后一轮发 2 段。接收端及时读取，使其通告接收窗口维持 3MSS，故不会出现零窗口。
3. SYN 使用序号 10，所以数据从 11 开始，共 8000 字节，下一个期望序号 8011。时长从首段发出开始，**不计 TCP 建连**。
4. 拥塞控制针对网络承载能力，流量控制针对接收端缓存；有效发送窗口通常不超过二者最小值，还需扣除在途数据。

1. FTP 的控制连接是持久连接还是非持久连接？数据连接是持久连接还是非持久连接？H 登录服务器时建立的是控制连接还是数据连接？
2. H 通过数据连接发送 F 时，F 的第一个字节序号是多少？释放该数据连接时，第二次挥手报文段中的确认序号是多少？
3. 传输 F 的过程中，当 H 收到确认序号为 $2101$ 的确认段时，拥塞窗口调整为多少？收到确认序号为 $7101$ 的确认段时，拥塞窗口调整为多少？

<ExamAnswer>

3. 分别为 $3\text{MSS}$ 和 $5\text{MSS}$。
4. 至少需要 $6\text{RTT}=60\ \text{ms}$；平均发送速率为 $0.3\ \text{MB/s}=2.4\ \text{Mb/s}$。

</ExamAnswer>

<ExamExplanation>

### （1）FTP 的两条连接

FTP 使用两条 TCP 连接：

- **控制连接**：用户登录后在整个会话期间保持，用于传送命令和响应，因此是持久连接；
- **数据连接**：传送一个文件或一次目录信息时建立，传输结束后释放，因此是非持久连接。

H 登录 FTP 服务器时首先建立的是控制连接。

### （2）序号

TCP 建立连接时，SYN 会消耗一个序号。H 的初始序号为 $100$，因此连接建立后第一个数据字节的序号为

$$
100+1=\boxed{101}.
$$

文件 F 共 $18000\ \text{B}$，因此最后一个数据字节的序号为

$$
101+18000-1=18100.
$$

随后 H 发出的 FIN 使用序号

$$
18101.
$$

FIN 同样消耗一个序号，所以服务器在第二次挥手中返回的确认号为

$$
18101+1=\boxed{18102}.
$$

### （3）拥塞窗口变化

初始阶段使用慢开始。

收到确认号 $2101$ 的 ACK 时，H 的拥塞窗口由 $2\text{MSS}$ 增长为

$$
\boxed{3\text{MSS}}.
$$

当拥塞窗口达到阈值 $4\text{MSS}$ 后进入拥塞避免阶段。继续传输并收到确认号 $7101$ 的 ACK 时，拥塞窗口调整为

$$
\boxed{5\text{MSS}}.
$$

### （4）最短传输时间与平均速率

文件大小为

$$
18000\ \text{B}=18\text{MSS}.
$$

从请求建立数据连接开始计时，先用 $1\text{RTT}$ 完成连接建立到可以发送数据的阶段。随后按拥塞窗口增长过程，连续各轮最多发送

$$
1,\ 2,\ 4,\ 5,\ 6\ \text{MSS},
$$

总计

$$
1+2+4+5+6=18\text{MSS}.
$$

因此确认全部文件被服务器接收至少还需 $5\text{RTT}$，总时间为

$$
(1+5)\text{RTT}
=6\times10\ \text{ms}
=\boxed{60\ \text{ms}}.
$$

应用层平均发送速率为

$$
\frac{18000\ \text{B}}{60\ \text{ms}}
=300000\ \text{B/s}
=0.3\ \text{MB/s}
=\boxed{2.4\ \text{Mb/s}}.
$$



### 拥塞窗口时序、TCP 字节流和 FTP 会话边界

1. **先建立序号账本。** 初始 SYN 用 100，首个文件字节用 101。文件占用 18000 个连续序号，因此文件最后一字节为 18100，接下来发送的 FIN 使用 18101，服务器回 ACK 为 18102。纯 ACK 不占序号；若主动关闭方没有额外数据，这条账本最直接。
2. **观察 ACK 的字节位置，而不是把确认号当“确认了几个段”。** `ack=2101` 意味着数据从 101 到 2100 共 2000B 已被累计确认，相当于 2 个完整 MSS；`ack=7101` 对应 7000B，共 7 个 MSS。题设无延迟确认、无丢包且按 MSS 分段，所以可以根据确认的新增段数推算 $cwnd$。
3. **慢开始跨越阈值之后才线性增长。** $ssthresh=4MSS$，起始 $cwnd=1MSS$；确认 1 个 MSS 后为 2，确认第 2 个为 3，确认第 3 个为 4，随后进入拥塞避免。到累计确认 7 个 MSS 时，经过拥塞避免一轮的近似增长，得到 $5MSS$。不要套用“从头到尾 ACK 一次就增长 1 MSS”，那会错误得到 8 MSS。
4. **平均速率的起止时刻严格按题意。** 题中“从请求建立数据连接”开始，包括 TCP 握手 $1RTT$；但终点是 H 收到完整文件已送达的累计 ACK，不包括挥手所需时间。5 轮窗口 $1+2+4+5+6=18MSS$，加握手一轮共 $6RTT$。如从**首段发送**才开始计时，结果变为 5 RTT，所求速率也会不同。
5. **FTP 双连接不是“FTP 必须使用两个端口同时传所有数据”的同义词。** 控制连接常在一次登录会话中保持；数据连接为一次文件传送或目录列表建立，在典型 FTP 模式下完成后关闭。主动/被动模式影响数据连接由谁主动发起及使用哪个端口，不改变两种连接的主要用途。现代 FTP 还可能受到网络防火墙、TLS 和实现差异影响，做题依题设采用经典模型。

</ExamExplanation>

<ExamQuestion>

**126. 2026 年第 47 题**

客户端 C 建立一条 TCP 连接，向服务器 $S_i$ 上传一个总长度为 $2000\ \text{B}$ 的计算任务描述文件。已知 C 的拥塞控制初始阈值为 $8\text{MSS}$，$\text{MSS}=500\ \text{B}$；$S_i$ 对收到的每个 TCP 数据段都进行确认，确认段不携带数据；接收窗口始终为 $1000\ \text{B}$；$\text{RTT}=5\ \text{ms}$。C 建立连接时选择的初始序号为 $1000$，$S_i$ 的初始序号为 $2000$。整个文件传输过程中没有重传、丢包或乱序。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2026-47-figure-001.svg" alt="2026 年第 47 题客户端与服务器场景" />

2. 当 C 收到 $S_i$ 发出的 `ACK=1, seq=2001, ack_seq=2001, rwnd=1000` 确认段后，C 的拥塞窗口增加到多少？发送窗口设置为多少？
3. C 与 $S_i$ 释放 TCP 连接需要几次挥手？C 收到的最后一个 TCP 报文段的 `seq`、`ack_seq` 和 `FIN` 分别是多少？
4. 忽略报文段发送时延，从 C 请求建立 TCP 连接的时刻开始计时，C 确定 $S_i$ 已成功收到整个文件的时间是多少？

<ExamSolution>

<ExamAnswer>

1. 三次握手；确认序号为 $1001$。
2. 拥塞窗口增加到 $3\text{MSS}=1500\ \text{B}$；发送窗口为 $1000\ \text{B}=2\text{MSS}$。
3. 四次挥手；C 收到的最后一个报文段中，`seq=2001`，`ack_seq=3002`，`FIN=1`。
4. $20\ \text{ms}$。

</ExamAnswer>

<ExamExplanation>

### （1）三次握手

TCP 连接建立使用三次握手。C 的初始序号为 $1000$，SYN 会消耗一个序号，所以 $S_i$ 在第二次握手中对 C 的 SYN 进行确认时：

$$
\text{ack\_seq}=1000+1=\boxed{1001}.
$$

### （2）拥塞窗口与发送窗口

文件传输开始时按慢开始增长拥塞窗口。

C 首轮发送 $1\text{MSS}=500\ \text{B}$，收到确认后拥塞窗口增至 $2\text{MSS}$，随后可再发送两个 MSS。

确认段

`ACK=1, seq=2001, ack_seq=2001, rwnd=1000`

说明 $S_i$ 已累计确认到字节序号 2000。该确认到达时，拥塞窗口按慢开始再增加 $1\text{MSS}$：

$$
\text{cwnd}=3\text{MSS}=1500\ \text{B}.
$$

实际发送窗口由拥塞窗口与接收窗口共同限制：

$$
\text{swnd}=\min(\text{cwnd},\text{rwnd})
=\min(1500,1000)
=\boxed{1000\ \text{B}}.
$$

也就是

$$
\boxed{2\text{MSS}}.
$$

### （3）四次挥手及最后一个收到的报文段

TCP 连接正常释放需要四次挥手。

C 的 SYN 使用序号 $1000$，因此数据从序号 $1001$ 开始。文件长度为 $2000\ \text{B}$，最后一个数据字节序号为

$$
1001+2000-1=3000.
$$

因此 C 的 FIN 使用序号

$$
3001,
$$

服务器确认该 FIN 时确认号为

$$
3001+1=\boxed{3002}.
$$

$S_i$ 没有发送应用层数据；它的 SYN 使用序号 $2000$，因此之后发送 FIN 时的序号为

$$
\boxed{2001}.
$$

所以 C 收到的最后一个来自 $S_i$ 的 TCP 报文段中：

$$
\boxed{\text{seq}=2001,\quad \text{ack\_seq}=3002,\quad \text{FIN}=1}.
$$

### （4）从建连请求到确认文件全部收到

忽略报文段发送时延，只考虑 RTT。

- $t=0$：C 发送 SYN；
- $t=5\ \text{ms}$：C 收到 SYN+ACK，完成一个 RTT，并可发出第三次握手确认，同时开始发送首个 $1\text{MSS}$ 数据；
- $t=10\ \text{ms}$：收到首个数据段 ACK，`cwnd` 变为 $2\text{MSS}$，发送两个 MSS；
- $t=15\ \text{ms}$：收到这两个数据段的确认，`cwnd` 可继续增长，但 `rwnd=1000\ \text{B}=2\text{MSS}$；此时文件只剩最后 $1\text{MSS}$，于是发送最后一个数据段；
- $t=20\ \text{ms}$：收到最后一个数据段的确认，C 确定整个 $2000\ \text{B}$ 文件均已被 $S_i$ 接收。

因此所需时间为

$$
\boxed{20\ \text{ms}}.
$$



### 细化 ACK、拥塞控制和零窗口之外的发送约束

1. **序号计算以字节为单位。** C 的 SYN 使用序号 1000，首字节序号 1001；2KB 文件用的是题设十进制 $2000\text{B}$，不是 $2\times1024\text{B}$。数据占 1001～3000，FIN 的序号为 3001，服务器确认 FIN 时的 `ack_seq=3002`。S 的 SYN 使用 2000，若无任何应用数据，S 的 FIN 使用 2001。
2. **确认序号 2001 为什么对应 1000B 数据？** 服务器对第一个 500B 段确认 `ack=1501`、对第二个确认 `ack=2001`；在典型逐段 ACK 的慢开始中，两个新确认令拥塞窗口从 1 MSS 依次变为 2、3 MSS。题设通告的 `rwnd=1000B` 不是拥塞窗口：实际窗口限额仍是 2 MSS。
3. **细分传输阶段。** 第一次握手用 1 RTT；第 1 个数据轮次发 1 段；下一轮最多发 2 段；最后一轮仅剩 1 段。收到末段累计 ACK 用 $1+3=4RTT=20\text{ms}$。若按所有子段的 ACK 立即触发流水发送，具体链路级调度可能更细；真题的 RTT 分轮分析假设段发送时延忽略、RTT 稳定且接收方按题意逐段确认。
4. **发送窗口大小不是“当前能立刻发出去的数据量”。** 若 $swnd=1000B$，但其中已有 500B 在途，则发送端剩余可使用额度仅 500B。在零窗口场景要分清 `rwnd=0` 导致停发和超时重传、拥塞窗口收缩导致停发属于不同控制机制。
5. **四次挥手中的“最后一个段”有视角。** C **收到**的最后一个 TCP 段是服务器 FIN（带 ACK，题设无额外应用数据）；C **发送**的最后一个段是对该 FIN 的纯 ACK。若应用协议允许服务器先主动关闭，或 ACK 与 FIN 合并、出现重传，则实际段数可能和理想四次挥手不同。本题严格按题设正常四次挥手求解。

</ExamExplanation>

1. 握手阶段每方 SYN 占一个序号，数据从客户 900+1=901 开始；服务器是否已发送文件不影响它对客户端 SYN 的确认值。
2. 第 1 轮发 1 个，第 2 轮受 $cwnd=2MSS$ 限制发 2 个，第 3 轮尽管 $cwnd$ 可增至 4MSS，仍受接收窗口 2MSS 约束，恰好发送最后两个。计时起点包含三次握手的 1 RTT。
3. 客户端文件占序号 901～2900；FIN 占 2901，确认到 2902。服务器只有 SYN 占用了 5000，因此 FIN 用 5001。
4. `rwnd` 是对发送端必须遵守的独立流控上限，不会因为网络未拥塞而自动扩大。

</ExamExplanation>

<ExamQuestion>
一条 TCP 连接的 MSS 为 500B，客户端 SYN 序号为 5000。服务端初始通告 $rwnd=500\text{B}$，客户端成功发出并收到其首个 500B 数据段的确认。此时服务端缓存已满且通告零窗口；发送方仍有数据待发，拥塞窗口为 $4MSS$。随后服务端应用取走 1000B，发出窗口更新，通告 $rwnd=1000\text{B}$。

1. 首个数据段的字节序号范围及服务器的确认号分别是多少？
2. 收到零窗口通知后，客户端还能直接再发送一个普通的 500B 新数据段吗？原因是什么？
3. 收到 1000B 的有效窗口更新且没有未确认在途数据后，理论上最多可立即发送多少新数据？
4. 如果窗口更新报文丢失，哪一种 TCP 机制可以避免双方永远等待？它与超时重传丢包有何区别？
<ExamSolution>
<ExamAnswer>

1. 范围 $5001$～$5500$；累计 ACK 为 $5501$。
2. 不能。$swnd=\min(2000,0)=0$。
3. $\min(2000,1000)=1000\text{B}=2MSS$。
4. 持续计时器与零窗口探测；这是探测接收能力变化，而非说明网络已丢失数据、必须缩小拥塞窗口。

</ExamAnswer>
<ExamExplanation>

1. SYN 消耗 5000，随后的 500B 有效数据占 5001～5500。接收端接到全部数据后确认 5501。
2. 拥塞窗口虽然允许 2000B，但接收端当前可用缓存为 0，流量控制优先阻止常规新数据传输。
3. 应用消费使服务端重新通告 1000B 额度。在没有在途未确认数据的条件下，可用额度正好是窗口最小值 1000B；若有在途数据，应另作扣减。
4. 零窗口探测用于请求接收方报告窗口，避免窗口打开报文丢失造成“发送方等窗口更新，接收方以为已通知”的互等。不能看到“停发”就机械地说拥塞控制的 `cwnd` 发生减半。

</ExamExplanation>
