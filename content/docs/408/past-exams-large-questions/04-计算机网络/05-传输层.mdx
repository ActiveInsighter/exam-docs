## 2012 年第 47 题

<ExamQuestion>

**112. 2012 年第 47 题**

主机 H 通过快速以太网连接 Internet，IP 地址为 `192.168.0.8`；服务器 S 的 IP 地址为 `211.68.71.80`。H 与 S 使用 TCP 通信时，在 H 上捕获到 5 个 IP 分组，其前 40B 如图所示。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2012-47-figure-001.svg" alt="2012 年第 47 题捕获的 5 个 IP 分组" />

1. 哪几个 IP 分组由 H 发送？哪几个分组完成了 TCP 连接建立过程？哪几个分组通过快速以太网传输时需要填充？
2. 根据这些分组，S 已经收到多少字节应用层数据？
3. 若其中某个由 S 发出的 IP 分组在发送时前 40B 如下图所示，则该分组到达 H 时经过了多少个路由器？

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2012-47-figure-002.svg" alt="2012 年第 47 题服务器发出时的 IP 分组内容" />

<ExamSolution>

<ExamAnswer>

1. 由 H 发出的是 **1、3、4 号**；**1、2、3 号**完成 TCP 三次握手；需要以太网填充的是 **3、5 号**，各填 **6 B**。
2. S 已按累计确认号确认收到 **16 B** 数据。
3. 该服务器分组从发出到 H 捕获，TTL 共减少 15，故经过 **15 台路由器**（题设无额外 TTL 改动）。

</ExamAnswer>

<ExamExplanation>

### 一、从前 40B 原始抓包中逐字段定位

**先明确定位规则**：正常无选项的 IPv4 首部长 20 B，紧随其后是至少 20 B TCP 首部。网络字节序是高位字节在前，十六进制多字节字段不能颠倒。以下位置都从 **IP 分组的第 1 字节**开始数，而不是从以太网帧开始数。

| 所需字段 | IPv4 分组位置 | 图中示例 | 得出的信息 |
| --- | --- | --- | --- |
| IPv4 总长度 | 第 3～4 B | 3 号 `00 28` | 40 B |
| TTL | 第 9 B | 捕获的 5 号 `31` | 十六进制 $0x31=49$ |
| 协议号 | 第 10 B | `06` | 上层是 TCP |
| 源 IPv4 | 第 13～16 B | `C0 A8 00 08` | `192.168.0.8`（H） |
| 目的 IPv4 | 第 17～20 B | `D3 44 47 50` | `211.68.71.80`（S） |
| TCP 序号 | TCP 第 5～8 B | 1 号 `84 6B 41 C5` | SYN 使用的初始序号 |
| TCP 确认号 | TCP 第 9～12 B | 5 号 `84 6B 41 D6` | 下一个期望收到的字节 |
| TCP 数据偏移 / 标志 | TCP 第 13～14 B | 1 号 `70 02` | TCP 首部 28 B；`SYN=1` |

由源地址逐行判断：1、3、4 号源 IP 是 `C0 A8 00 08`，所以来自 H；2、5 号源 IP 是 `D3 44 47 50`，来自 S。**源 IP 决定报文发送方向；以太网目的 MAC 只代表某一跳，不应用来判断端到端发送方。**

### 二、逐个读 TCP 控制位：为什么只有 1、2、3 是握手

TCP 的 SYN、ACK、PSH、FIN 等在首部控制位中编码；TCP **数据偏移字段以 4 字节为单位**，如 `70` 的高半字节是 7，对应 $7\times4=28$ B TCP 首部，并不是数据长度 7 B。

| 分组 | TCP 标志/方向 | 序号与确认逻辑 | 角色 |
| --- | --- | --- | --- |
| 1 | H→S，`SYN=1, ACK=0` | 初始序号 `846B41C5H` | 第一次握手 |
| 2 | S→H，`SYN=1, ACK=1` | 确认 `846B41C6H` | 第二次握手 |
| 3 | H→S，`ACK=1` | 确认服务器 SYN，TCP 负载为 0 | 第三次握手 |
| 4 | H→S，`PSH=1, ACK=1` | 从 `846B41C6H` 起发送数据 | 携带应用数据 |
| 5 | S→H，`ACK=1` | 确认 `846B41D6H` | 累计确认 |

**SYN、FIN 各消耗 1 个 TCP 序号，但纯 ACK 不消耗序号**。抓包中 1 号 SYN 的序号为 `846B41C5H`，因此 H 的首个应用数据字节序号是 `846B41C6H`。图中 4 号的 IP 总长度是 `0038H=56` B，IP/TCP 首部各 20 B，所以其 TCP 有效负载 $56-20-20=16$ B，这与 5 号累计确认吻合。

**校验性勘误**：原始配图里 **2 号 IP 首字节绘为 `43`**，其 IPv4 IHL=3（首部 12 B）在标准 IPv4 中不合法，真实抓包应至少为 5。此处应视为题图转录异常；按已给源/目的地址、协议号及 TCP 标志分析握手结论，不应机械宣称 `43` 也是有效的 IPv4 首部。

### 三、最小以太网帧：不要拿 64B 直接和 IP 总长度比较

传统以太网 MAC 帧的**最小总长为 64 B**，但其中包括目的/源 MAC 共 12 B、类型 2 B，以及末尾 FCS 4 B。因此最小**数据字段为**

$$
64-(6+6+2+4)=46\ \mathrm B.
$$

比较对象是 **IP 总长度**（以太网载荷），不是 TCP 有效负载。3、5 号均为 `0028H=40` B，所以每个补零 $46-40=\boxed{6\ \mathrm B}$。1、2 号 `0030H=48` B；4 号 `0038H=56` B，均无需填充。以太网填充字节**不算入 IPv4 总长度、TCP 序号或 TCP 应用数据**。

### 四、累计确认号推导 16B：确认号不是“本次收到的字节数”

首个数据字节为 `846B41C6H`，5 号 ACK 的确认号为 `846B41D6H`。由于 TCP 的确认号是“**到该序号之前为止连续完整收到**”，并非最近一个分组长度，因此

$$
\text{连续确认数据量}
=\mathtt{0x846B41D6}-\mathtt{0x846B41C6}
=\mathtt{0x10}=\boxed{16\ \mathrm B}.
$$

和 4 号 IP/TCP 首部扣除法相互校验。注意：这里表明 S 按 TCP **累计确认**了 16B；一般情况下 ACK 不能严格证明远端应用已经消费或持久化这些数据，属于“传输层已收到”的口径。

### 五、TTL 与跳数：对比“同一个分组”的发送与到达

题目给出 S **发送时**图中分组 TTL=`40H=64`；H 捕获到 5 号分组 TTL=`31H=49`。应先利用 IP 标识等字段核对是同一个分组，再相减：

$$
N_{\mathrm{routers}}=TTL_{\mathrm{send}}-TTL_{\mathrm{recv}}=64-49=\boxed{15}.
$$

通常每台执行 IPv4 转发的路由器会将 TTL 减 1 并更新 IPv4 首部校验和；**交换机在二层转发不减 TTL**，主机接收后也不再按经过一台路由器减 1。不能直接把捕获 TTL=49 当作经过 49 跳，也不能未经核对就假设原始 TTL 固定是 64。

### 六、考场方法与迁移

- 先分层：以太网最小帧 64B → 有效载荷最小 46B；IPv4 总长度包含 IP 首部；TCP 序号只跟 TCP 有效负载和 SYN/FIN 有关。
- 抓包定位：IPv4 源 IP 偏移 12、目的 IP 偏移 16；标准 20B IP 首部后才是 TCP 端口、序号和确认号。
- 求“已经收到多少”：**ACK 减数据起始 seq**；若含 SYN/FIN，须先扣除其占用的 1 个序号。
- 求路由器数：确认同一包的发送/到达 TTL，再做差；有隧道、TTL 初始化或其它改写时需另作说明。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

主机 A（`10.1.2.10`）通过以太网及若干路由器与主机 B（`203.0.113.7`）通信。捕获到 A→B 的三个 TCP 分组：①仅 SYN，`seq=4000`，IPv4 总长 44 B，TCP 首部长 24 B（含选项）；②仅 ACK，`seq=4001`，IPv4 总长 40 B，IP/TCP 首部各 20 B；③`PSH+ACK`，`seq=4001`，IPv4 总长 44 B，IP/TCP 首部各 20 B。B 随后发出的 ACK 是 `ack=4005`。已知三包均不带 VLAN 标签、IPv4 首部均为 20 B；B 发送该 ACK 时 TTL=64，A 捕获时 TTL=57。假设所有报文在标准以太网 II 上传输，最短数据字段为 46 B。

1. ①、②、③各自是否携带应用层数据？三个 IP 分组封装成以太网帧各至少补充多少字节？
2. B 的 `ack=4005` 表示累计确认了多少个 A 发出的应用层字节？为何不能从 `4005-4000` 得出 5B？
3. 从发送 TTL 64 到接收 TTL 57，途中至少经过多少个按标准执行 IPv4 转发的路由器？
4. 如果新增一个封装 802.1Q 标签的以太网帧、且其数据字段恰好 44 B，是否必然按原始“IP 小于 46B”补 2B？请写出比较依据。

<ExamSolution>

<ExamAnswer>

1. ① SYN 无应用数据，②纯 ACK 无应用数据，③携带 **4 B** 应用数据；各帧 IP 载荷分别 44、40、44B，应填充 **2、6、2 B**。
2. **4B**。因为 SYN 消耗一个序号，首个数据字节从 4001 开始；$4005-4001=4$。
3. **7 台**。标准转发一跳 TTL 减 1，$64-57=7$。
4. **不能不加区分地照搬**。题目若采用带 802.1Q 标签的 64B 最短 MAC 帧定义，VLAN 标签占 4B，数据最小可以降为 **42B**（总体最小帧长度仍 64B），44B IP 数据此时无需填充；须先确定题目对 VLAN 帧最小长度/标签口径的规定。

</ExamAnswer>

<ExamExplanation>

### （1）数据长度：用 IP 总长度扣 IP 与 TCP 首部

$$
D_{TCP}=L_{IP}-H_{IP}-H_{TCP}.
$$

①为 $44-20-24=0$B，其 24B TCP 首部比通常的 20B 多 4B 选项，但 SYN 本身不算应用数据。②为 $40-20-20=0$B。③为 $44-20-20=\boxed{4\mathrm B}$。IP 有选项、TCP 有选项都会占总长度空间，**不能假设所有 TCP 头一律 20B**。

标准无 VLAN 的以太网 II 帧头 14B，FCS 4B，最小帧 64B，故最低载荷 46B。三包分别需 $46-44=2$B、$46-40=6$B、$46-44=2$B；填充在以太网层，不属于 TCP 数据，也不改变 IP 总长度字段。

### （2）ACK 是“下一期望序号”，不直接等于数据字节数

A 初始 SYN 使用 4000，SYN 占用 1 个序号，首个数据段数据从 4001 开始。③带 4B，其字节序号覆盖 `4001～4004`；B 返回的 ACK=4005，正好累积确认到 4004：

$$
L_{app}=4005-(4000+1)=\boxed{4\mathrm B}.
$$

如果改成由 B 发送 FIN，则 FIN 也占 1 个序号；普通 ACK 不占序号。不能把 Ethernet 填充、IP 首部、TCP 首部或数据帧头计入 ACK 的增量。

### （3）TTL 校验与 VLAN 边界

TTL 从 64 到 57，说明按标准三层转发减了 7 次，二层交换机不消耗 TTL。若遇隧道端点重新封装或非标准 TTL 操作，不能再仅凭 64 与 57 确认物理设备总数。

VLAN 的 802.1Q 标签插在 MAC 地址与 EtherType 之间，总 MAC 开销比普通帧多 4B。必须明确题目的最小帧总体字节数及是否把标签计入，以避免直接把所有场景都写成“IP 最短一定要 46B”。**考试默认未说明 VLAN 则用 46B 规则**。

### （4）速解检查

| 提问对象 | 先看哪里 |
| --- | --- |
| 源宿主机 | IP 首部第 13～16B 源地址 |
| TCP 负载大小 | IP 总长度、IP IHL、TCP 数据偏移 |
| 累计确认数据量 | ACK − 首个数据字节 seq |
| 路由器跳数 | 同一个 IP 包发送/到达 TTL 差 |
| 以太网填充 | IP 整包大小与链路层最低数据字段 |

</ExamExplanation>

## 2016 年第 41 题

<ExamQuestion>

**116. 2016 年第 41 题**

题图网络中，H3 访问 Web 服务器 S。S 为新 TCP 连接分配 20KB（$K=1024$）接收缓存，最大报文段长度 $MSS=1\text{ KB}$，平均往返时间 $RTT=200\text{ ms}$。H3 建立连接时初始序号为 100，并持续以 MSS 大小发送数据；拥塞窗口初始阈值为 32KB。S 对每个收到的段都立即确认并通告新的接收窗口。连接建立后，S 的接收缓存只有数据写入，没有数据被应用程序取走。

<img src="/img/408/past-exams-large-questions/04-计算机网络/assets/2016-41-figure-001.svg" alt="2016 年第 41 题网络拓扑" />

1. H3 收到的第二次握手 TCP 段中，SYN、ACK 标志位分别是多少？确认号是多少？
2. H3 收到第 8 个确认段时，S 通告的接收窗口是多少？此时 H3 的拥塞窗口和发送窗口分别是多少？
3. 当 H3 的发送窗口变为 0 时，下一个待发送数据段的序号是多少？从发送第 1 个数据段到发送窗口变为 0，平均数据传输速率是多少？忽略报文段发送时延。
4. 若通信已结束，在时刻 $t$ H3 请求断开连接，从 $t$ 起 S 最快经过多长时间释放连接？

<ExamSolution>

<ExamAnswer>

1. 第二次握手：`SYN=1`、`ACK=1`、`ack=101`。
2. 第 8 个新的数据 ACK 到达时：`rwnd=12 KB`，`cwnd=9 KB`，可用作上限的发送窗口 $\min(cwnd,rwnd)=9\ \mathrm{KB}$。
3. 下一个待发送字节序号 **20581**；按题设理想逐 RTT 批量模型，平均 **$163.84\ \mathrm{kb/s}$**。
4. 若 S 在收到 FIN 时可立即回 ACK 并主动发送 FIN，且无发送延迟，S 最快在 $\frac32 RTT=\boxed{300\ \mathrm{ms}}$ 后收到最终 ACK，完成连接释放。

</ExamAnswer>

<ExamExplanation>

### 一、先画 TCP 事件线，注意 SYN 也占用序号

H3 第一次握手用 `seq=100,SYN=1`，S 回 `SYN=1,ACK=1,ack=101`，H3 再确认 S 的 SYN；真正第一个数据字节是 **101**。TCP 中 SYN 和 FIN **各占 1 个序号**，而 ACK-only 不占数据序号。`ack=101` 是**下一个期望字节**，不等于“确认收到 101B”。

### 二、四个窗口不是同一回事

- `rwnd`：接收端通告的接收窗口，取决于接收缓存尚能容纳的字节数，负责**流量控制**。
- `cwnd`：发送端拥塞窗口，取决于拥塞控制算法和 ACK 的反馈，负责**拥塞控制**。
- `ssthresh`：慢开始与拥塞避免转折阈值，本题初始 32KB，不是接收窗口。
- 发送量上限：$W=\min(cwnd,rwnd)$；若问**此刻还能额外发送多少新数据**，还应从窗口中减去已发送但未确认的在途字节，不能直接都叫“可用剩余额度”。

S 起始缓存 20KB、没有应用读取；每收到 1 个 1KB 的数据段，缓存空闲量下降 1KB。因此累计收到第 8 个数据段时

$$
rwnd=20-8=\boxed{12\ \mathrm{KB}}.
$$

题设采用**传统教材的慢开始模型**：初始 `cwnd=1MSS`，每收到一个确认新数据的 ACK，增加 1MSS。前 8 个 ACK 均无丢包也未达到阈值，故

$$
cwnd=(1+8)\mathrm{MSS}=\boxed{9\ \mathrm{KB}},
\quad W=\min(9,12)=\boxed{9\ \mathrm{KB}}.
$$

实际 TCP 实现可能带初始 10MSS、延迟确认、应用限速、窗口缩放等机制；这是按题设建模，不要把默认实现细节擅自代入。

### 三、逐 RTT 列状态比死背“指数增长”可靠

为便于求**理想最短平均时间**，把每 RTT 内能够发送且及时收到确认的数据视作同一发送轮，忽略传播之外的开销，并按题目“每段立即确认”处理：

| 发送轮 | 本轮发出的数据量 | 累计确认数据量 | 接收端剩余缓存 | 解释 |
| --- | ---: | ---: | ---: | --- |
| 1 | 1 KB | 1 KB | 19 KB | 初始 `cwnd=1MSS` |
| 2 | 2 KB | 3 KB | 17 KB | 慢开始倍增 |
| 3 | 4 KB | 7 KB | 13 KB | 慢开始倍增 |
| 4 | 8 KB | 15 KB | 5 KB | 尚有 5KB 缓存可用 |
| 5 | 5 KB | 20 KB | 0 KB | 受到 `rwnd` 限制，非发 16KB |

第 5 轮后的最新 ACK 通告 `rwnd=0`，没有新数据可发送。共经历 5 个 RTT，即 $5\times200\mathrm{ms}=1\mathrm s$。H3 已发送且 S 累计确认 20KB，故

$$
seq_{\mathrm{next}}=100+1+20\times1024=\boxed{20581}.
$$

应用数据平均速率

$$
\bar v=\frac{20\times1024\times8\ \mathrm{bit}}{5\times 0.2\ \mathrm s}
=\boxed{163840\ \mathrm{bit/s}}
=\boxed{163.84\ \mathrm{kb/s}}.
$$

**单位必须一致**：1KB=$1024$B，而链路速率的 `kb/s` 通常取 $10^3$ bit/s；`kB/s` 与 `kb/s` 相差 8 倍。并且零窗口表示**接收缓存已满**，不代表网络拥塞或 TCP 连接已经释放；真实 TCP 可用持续计时器探测窗口是否重新打开。

### 四、连接释放时间线为何是 1.5 RTT

按照标准四次挥手、单程传播时延 $RTT/2=100$ms，假定通信数据已传完、S 无待发送数据并立即处理：

| 时刻（从 $t$ 起） | 事件 |
| --- | --- |
| 0 | H3 发送 FIN |
| 100ms | S 收到 FIN，回复 ACK 并立即发送自己的 FIN |
| 200ms | H3 收到 S 的 FIN，立即回复最终 ACK |
| 300ms | S 收到最终 ACK，离开 `LAST_ACK`，完成释放 |

因此 S 最短释放时间为 $100+100+100=\boxed{300\mathrm{ms}}$。**不是 H3 释放的时间**：主动关闭方 H3 在发最终 ACK 后一般还会处于 `TIME_WAIT` 状态（典型为 $2MSL$）；S 的被动关闭路径不额外等待 2MSL。S 的 ACK 与 FIN 可连发甚至合并，但不改变本题传播时间下限。

### 五、相关考法：快速定位窗口瓶颈

1. 先算总待接收量，再算 `rwnd` 随 ACK 的变化；**接收方应用是否读取**是决定零窗口出现时间的关键。
2. `cwnd` 的轮次增长受 `ssthresh`、ACK 策略、是否重传影响；若题干限定传统慢开始，就按 1、2、4、8…发送轮统计。

<ExamSolution>

<ExamAnswer>

1. FTP **控制连接持久、数据连接通常每次文件传输单独建立（本题按非持久）**；登录时建立控制连接。
2. F 的首字节序号为 **101**；S 确认 H 发出的 FIN 时，确认序号为 **18102**。
3. 按题目教材式慢开始 / 拥塞避免模型，收到 `ack=2101` 后 `cwnd=3MSS`，收到 `ack=7101` 后 `cwnd=5MSS`。

<ExamExplanation>

### 一、FTP 双连接：为什么“登录”不是“传文件”

FTP 的**控制连接**用于账号口令、命令和响应，一般贯穿整个 FTP 会话；**数据连接**用于文件或目录列表的传输，在本题传统 FTP 模型中一次任务建立并关闭一条连接。这里“持久/非持久”描述的是 FTP 控制与数据连接，不等价于 HTTP 的“持久连接”选项。

FTP 常识还包括：控制连接通常通过服务端 TCP 21 端口建立；**主动模式**服务端会连接客户端提供的数据端口，**被动模式**则由客户端连接服务器指定的数据端口。不能无条件把 FTP 所有数据连接的服务器端口写成 20。两条连接可以各有独立 TCP 序号空间、拥塞窗口和关闭流程。

### 二、三次握手与四次挥手共用一个序号空间

H 为数据连接选初始序号 `ISN=100`，它的 SYN 使用 100，因此文件首个字节序号

$$
seq_1=ISN+1=\boxed{101}.
$$

F 共 $18000$B，其字节序号为 101～18100，TCP 连续确认收到全部文件时 ACK=18101。随后 H 发送 FIN，使用**尚未占用的下一个序号**18101；FIN 再消耗 1，故服务端收到该 FIN 后的第二次挥手

$$
ack_{FIN}=101+18000+1=\boxed{18102}.
$$

通用公式：若最早数据序号为 $s$、数据字节数为 $L$，那么数据末字节 $s+L-1$，FIN 的 `seq=s+L`，确认 FIN 的 `ack=s+L+1`。**TCP ACK 本身不额外增加数据序号**，不能再多加 1。

### 三、把确认号变成“已确认 MSS 数”

一段大小 MSS=1000B，因此 H 的文件发送序号与确认号按 1000B 递增：

| 累计完整确认数据段 | 对应 ACK | 教材拥塞窗口阶段 |
| ---: | ---: | --- |
| 0 | 101 | `cwnd=1MSS` 初始化 |
| 1 | 1101 | 慢开始增大到 2MSS |
| 2 | 2101 | 增大到 **3MSS** |
| 3 | 3101 | 达到阈值 4MSS |
| 7 | 7101 | 一个拥塞避免轮次结束，达到 **5MSS** |

注意确认号 `2101` 不表示“收到了 2101B”，而是 $2101-101=2000$B、恰好 2 个 MSS。题目采用**离散发送轮次的教材算法**：慢开始跨一个 RTT 大致翻倍，达到 $ssthresh=4MSS$ 后每个完整 RTT 约增加 1MSS。标准实现按每个 ACK 以合适比例调节 `cwnd`，因此中间瞬时值未必恰为整数 MSS；此处答案是题设教学模型的取整轮次，不宜当作所有实现的精确逐 ACK 公式。

### 四、18 MSS 最快如何在 5 个数据 RTT 内发完

忽略发送时延、无丢包、对端窗口不构成额外限制，并采用上一问的发送轮次模型：

| 数据轮次 | 本轮上限/MSS | 本轮实际发出/MSS | 文件累计发出/MSS | 这一轮的 ACK 到达后 |
| --- | ---: | ---: | ---: | --- |
| 1 | 1 | 1 | 1 | `cwnd` 增至 2 |
| 2 | 2 | 2 | 3 | `cwnd` 达 4 阈值 |
| 3 | 4 | 4 | 7 | `cwnd` 增至 5 |
| 4 | 5 | 5 | 12 | `cwnd` 增至 6 |
| 5 | 6 | 6 | 18 | 最后字节被累计确认 |

数据连接建立阶段需要一个 RTT（简化认为完成第三次握手后可立即发送文件首段）；从首段发出到最后 ACK 回来还需 5 RTT，故

$$
T=(1+5)RTT=6\times10\ \mathrm{ms}=\boxed{60\ \mathrm{ms}}.
$$

若问题改为“**最后一个数据段何时发出**”，时间会比“收到确认、确定服务端已完整收到”早 1 RTT；若传输结束后还需等待关闭确认，又应计入额外挥手传播。本题只问到完整接收已确认时为止。

$$
R=\frac{18000\times8\ \mathrm{bit}}{0.060\ \mathrm s}
=\boxed{2.4\times10^6\ \mathrm{bit/s}}
=\boxed{2.4\ \mathrm{Mb/s}}.
$$

`MSS` 是 TCP 有效数据最大长度，与以太网 MTU/IP 总长度不是同一概念；计算文件吞吐量只把 18000B 应用文件计入分子，不把 TCP/IP 头部当成文件数据。

### 五、易错模型迁移

- TCP 每条新连接都有各自 `ISN`；FTP 控制连接已建立，不代表新数据连接能省掉建连 RTT。
- 记 $s+L$ 是 **ACK 数据的确认号/本端 FIN 的序号**，$s+L+1$ 是 **ACK FIN 的确认号**。
- “拥塞窗口增大到 5MSS”依赖**教材每 RTT 近似增加一个 MSS**；题目若给出精确逐 ACK 公式，应按新规则重算，不能硬套整数阶梯。
- “最短耗时”画时间线：建连 RTT + 数据发送轮数 RTT；说明接收窗口、ACK 策略、发送延迟的理想化前提。

4. 忽略报文段发送时延，从 C 请求建立 TCP 连接的时刻开始计时，C 确定 $S_i$ 已成功收到整个文件的时间是多少？

<ExamSolution>

1. TCP **三次握手**；S 的第二次握手确认号为 **1001**。
2. 该 `ack_seq=2001` ACK 确认累计 1000 B 文件数据；按传统慢开始逐段增长规则，`cwnd=3MSS=1500B`，对端 `rwnd=1000B`，所以有效发送窗口上限为 **1000B**。

<ExamExplanation>

### 一、用同一条“序号轴”贯通建连、传输和断开

客户端 C 的初始序号为 1000，服务端 S 的初始序号为 2000。**SYN 和 FIN 各消耗一个序号，纯 ACK 不消耗**：

| 发报文的一端 | 动作 | seq | 对方期望的 ack |
| --- | --- | ---: | ---: |
| C | 第一次握手 SYN | 1000 | S 应答 1001 |
| S | 第二次握手 SYN+ACK | 2000 | C 应答 2001 |
| C | 发送第 1 个 500B 数据 | 1001 | S 确认 1501 |
| C | 全部 2000B 文件发完 | 最后一个数据字节 3000 | S 确认 3001 |
| C | 发送 FIN | 3001 | S 确认 3002 |
| S | 自己没有应用数据时发送 FIN | 2001 | C 确认 2002 |

所以第二次握手 S 的 `ack=1001`。S 未发送应用数据，只消耗 SYN 的那一个序号，FIN 的 `seq` 就是 2001；由于 C 的 FIN 使用 3001，S 的 FIN 里可附带 `ack=3002`。

**“C 最后收到的报文段”**指 S 的 FIN（第四次挥手是 C 发送给 S 的 ACK）；不能把 C 自己发出的最终 ACK 当成 C 收到的最后报文。

### 二、`ack_seq=2001` 究竟确认了什么

C 连接建好后第一个数据字节为 1001。某 ACK 累计确认至下一个期望字节 2001，则已连续正确接收

$$
2001-1001=1000\ \mathrm B=2MSS,
$$

这意味着前两个 MSS 数据段已被累计确认。初始拥塞窗口 1MSS，首个 500B 被确认后增长到 2MSS；随后第二个 500B 被确认时变成 3MSS。因为题设的慢开始阈值 $8MSS$ 尚未达到：

$$
cwnd=3\times500=\boxed{1500\ \mathrm B}.
$$

S 始终通告接收窗口 1000B，所以

$$
W=\min(cwnd,rwnd)=\min(1500,1000)=\boxed{1000\ \mathrm B}.
$$

**区分**：“拥塞窗口”仍是 1500B，没有被接收端改小；真正控制允许在途、未确认字节总量的是二者的最小值。ACK 到达瞬间若尚有其他未确认数据，还要扣除在途字节才能求立即可发送的额外字节数。

### 三、完整时间轴：为什么最终是 20ms 而不是 15ms

题设 $RTT=5$ms，忽略段发送时延、无丢包乱序，并让 C 在收到 ACK 后立即补发。

| 时刻 | C / S 的动作 | 累计已经被 C 确认交付的数据 |
| --- | --- | ---: |
| $t=0$ | C 发送 SYN | 0 |
| $t=5$ms | C 收到 SYN+ACK，发第三次握手 ACK + 第 1 段 500B | 0 |
| $t=10$ms | 收到首段 ACK；`cwnd=2MSS`，在 `rwnd=2MSS` 下发两段共 1000B | 500B |
| $t=15$ms | 收到接下来两段的 ACK；还剩最后一段 500B 待发 | 1500B |
| $t=20$ms | 最后一段 ACK 返回 | **2000B** |

因此 **“文件发送完”的时刻**（15ms）和 **“C 确定服务器完整收到”的时刻**（20ms）不同，题目问后者：

$$
T=4\times RTT=4\times5=\boxed{20\ \mathrm{ms}}.
$$

如果将第 2 个确认 `ack=2001` 看成确认了 1000 B，则需注意它只是累计 ACK，不代表一开始就能同时发送 1000 B；第 1 RTT 的初始拥塞窗口限制仍必须遵守。

### 四、结合现实 TCP 协议的边界

- 若**服务器应用从不读取数据**，`rwnd` 通常随缓冲被填满而缩小；本题明确 `rwnd` 始终 1000B，相当于应用或接收侧机制及时腾出空间，因此不能把它改写成“越收越小”的 2016 年模型。
- 真实 TCP 可能使用更大的初始 `cwnd`、延迟 ACK、捎带 ACK、快速打开等选项；原题明确的阈值、ACK 和模型优先于默认实现。
- 服务器回复 FIN 的具体时刻依赖应用何时决定关闭；本问第（3）小问只问字段，按**无服务端应用数据、顺序关闭**计算，与第（4）小问无关。
- RST 是异常复位，不属于题设四次正常挥手；不能把 TIME_WAIT 一概加到“C 收到服务器 FIN”的时间上。

### 五、答题公式汇总

$$
\begin{aligned}
seq_{\mathrm{first\ data}}&=ISN+1,\\
ack_{\mathrm{all\ data}}&=ISN+1+L,\\
seq_{\mathrm{FIN}}&=ISN+1+L,\\
ack_{\mathrm{FIN}}&=ISN+2+L,\\
W&=\min(cwnd,rwnd).
\end{aligned}
$$

这组关系同样适用于“换 MSS”“双向都发数据”“先停再关闭”等变式，只要分别跟踪双方独立的序号空间即可。

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

C 与 S 新建一条 TCP 连接，C 的初始序号为 200，S 的初始序号为 800。完成三次握手后，C 连续发送 1500B 任务数据，S 连续返回 600B 结果数据；均按序、无丢包，所有数据已被对方累计确认且双方都不再发送应用层数据。随后由 C 主动关闭，S 收到 C 的 FIN 后**立即**回 ACK，再发送自己的 FIN；双方不会同时关闭。

1. 三次握手中 S 回复的确认号、C 第一次确认 S 的 SYN 时的确认号各是多少？
2. C 与 S 各自首个应用数据字节的 seq 是多少？收到对端全部数据时，C、S 分别应回的累计 ACK 值是多少？
3. C 的 FIN 用什么 seq？S 的 FIN 用什么 seq、ack？C 发送第四次挥手时的 `seq`、`ack` 各是多少？
4. 指出“TCP 数据双向独立编号”和“一个连接有两条半关闭方向”的关系，并说明谁一般经历 TIME_WAIT。

<ExamSolution>

<ExamAnswer>

1. S 对 C 的 SYN 回 ACK **201**；C 对 S 的 SYN 回 ACK **801**。
2. 首数据字节 C **201**、S **801**；S 确认 C 全部数据 ACK **1701**，C 确认 S 全部数据 ACK **1401**。
3. C FIN `seq=1701`；S FIN `seq=1401,ack=1702`；C 最终 ACK `seq=1702,ack=1402`。
4. 双方的序号各沿自己的方向独立增长；C 主动关闭，其发送方向先结束，S 仍可在自身方向传输数据；**C 一般进入 TIME_WAIT**，S 正常收到最终 ACK 后从 LAST_ACK 关闭。

</ExamAnswer>

<ExamExplanation>

### （1）两个方向同时开两条序号轴

| 方向 | SYN 序号 | 第一个数据序号 | 发送数据量 | 下一个未占用序号 |
| --- | ---: | ---: | ---: | ---: |
| C→S | 200 | 201 | 1500B | $201+1500=1701$ |
| S→C | 800 | 801 | 600B | $801+600=1401$ |

TCP 的 ACK 字段确认**对端**字节，`seq` 指的是**自己方向**的字节位置。S 在第二次握手回 `ack=201`，C 在第三次握手回 `ack=801`；完全接收 C 数据后 S 对其累计确认到 1701；C 收到 S 全部数据后累计确认到 1401。

### （2）先关哪边就消耗哪边的 FIN 序号

C 的 FIN 使用 C 方向下一个未使用的 1701。S 对 C 的 FIN 回 ACK=1702；S 自己发送 FIN 则要用**S 自己**的 seq=1401，而其捎带确认号仍是 1702：

$$
\begin{aligned}
FIN_C:&\quad seq=1701,\\
FIN_S:&\quad seq=1401,\ ack=1702,\\
ACK_C^{last}:&\quad seq=1702,\ ack=1402.
\end{aligned}
$$

第四次挥手的 C→S ACK 一般不带数据，序号 1702 不会再向前推进；若后续出现重传，其序号也不能无故加 1。

### （3）谁进入 TIME_WAIT 与“半关闭”

C 已发送 FIN 就表示 C→S 的应用数据流结束，但 S→C 仍可继续传递尚未发完的结果，直到 S 也发 FIN。主动关闭方 C 收到 S 的 FIN 后需要保证最后 ACK 可重传，并防止旧连接报文干扰同一四元组的新连接，因此通常进入 TIME_WAIT。**不能把 S 的 `seq=1401` 写成 1702**：这等于把两个相互独立的序号轴混在一起。

</ExamExplanation>
