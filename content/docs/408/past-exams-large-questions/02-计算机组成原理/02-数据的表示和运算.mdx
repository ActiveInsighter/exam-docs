## 2011 年第 43 题

<ExamQuestion>

**41. 2011 年第 43 题**

假定在一个 **8 位字长**的计算机中运行如下 C 程序段：

```c
unsigned int x = 134;
unsigned int y = 246;
int m = x;
int n = y;
unsigned int z1 = x - y;
unsigned int z2 = x + y;
int k1 = m - n;
int k2 = m + n;
```

若编译器将 8 个 8 位寄存器 R1～R8 分别分配给变量 `x、y、m、n、z1、z2、k1、k2`。带符号整数采用补码表示。请回答：

1. 执行上述程序段后，寄存器 R1、R5 和 R6 的内容分别是什么？用十六进制表示。
2. 执行上述程序段后，变量 `m` 和 `k1` 的值分别是多少？用十进制表示。
3. 上述程序段涉及带符号整数加/减和无符号整数加/减。这四类运算能否使用同一个加法器及辅助电路实现？简述理由。
4. 计算机内部如何判断带符号整数加/减是否溢出？上述程序段中，哪些带符号整数运算会溢出？

<ExamSolution>

<ExamAnswer>

1. R1=`86H`、R5=`90H`、R6=`7CH`。
2. $m=-122$，$n=-10$，$k1=-112$；`k2` 对应的 8 位运算位模式为 `7CH`，它发生**有符号溢出**，不能把截断结果 124 当成数学正确结果。
3. 四类加减法可共用同一个 8 位加法器，通过对减数按位取反和设置初始进位实现减法，区别在于如何**解释结果**以及 **CF/OF 标志**。
4. `k1=m-n` 无溢出，`k2=m+n` 溢出。一般加/减法的带符号溢出可用 $V=C_{in,sign}\oplus C_{out,sign}$ 判定。

</ExamAnswer>

<ExamExplanation>

### 一、统一思路：所有寄存器先求 8 位模式，再选择解读方式

8 位系统的位模式在 $0$ 到 $255$ 之间循环。在题目给定的**8 位带符号/无符号机器数模型**下，`unsigned int` 表示 $0$～$255$，`int` 的补码真值范围是 $-128$～$127$。相同的位串不因变量声明而发生变化；转换的是它的数学解释：

$$
\operatorname{signed8}(u)=\begin{cases}u,&0\le u\le127,\\u-256,&128\le u\le255.\end{cases}
$$

计算逐项列成表，检查比只看结果更稳妥：

| 对象 | 数学计算 / 解释 | 寄存器低 8 位 | 按变量类型解释 |
| --- | --- | --- | --- |
| `x`，R1 | 134 | `86H` | 134（无符号） |
| `y`，R2 | 246 | `F6H` | 246（无符号） |
| `m`，R3 | `86H` 按补码解释 | `86H` | $134-256=-122$ |
| `n`，R4 | `F6H` 按补码解释 | `F6H` | $246-256=-10$ |
| `z1=x-y`，R5 | $134-246=-112$，模 256 | `90H` | 144（无符号） |
| `z2=x+y`，R6 | $134+246=380$，模 256 | `7CH` | 124（无符号） |
| `k1=m-n`，R7 | $-122-(-10)=-112$ | `90H` | -112（补码） |
| `k2=m+n`，R8 | $-122+(-10)=-132$ | `7CH` | 位串解读为 124，数学上发生溢出 |

例如 $\texttt{86H}=1000\,0110_2$，最高位为 1，其补码真值为 $134-256=-122$；而 $\texttt{F6H}$ 真值为 $246-256=-10$。无符号减法的 $-112\pmod {256}=144=\texttt{90H}$，无符号加法的 $380\pmod {256}=124=\texttt{7CH}$。

### 二、一套加法器实现带/无符号的加与减

对任意 8 位 A、B，减法通过补码恒等式完成：

$$
A-B\equiv A+\overline B+1\pmod {2^8}.
$$

因此可用一个“加/减”控制位 `SUB` 设置 `B' = B XOR SUB`，并把加法器初始进位设为 `SUB`：

$$
S=A+(B\oplus\text{mask}(SUB))+SUB\pmod {256},
$$

其中 $	ext{mask}(0)=	exttt{00H}$、$	ext{mask}(1)=	exttt{FFH}$。当 `SUB=0` 时就是 $A+B$，当 `SUB=1` 时就是 $A+\bar B+1$。无符号加减与补码加减的**8 位结果完全相同**，只是不同的上层计算语义需要不同的标志位判断。这正是考研组成原理“位级运算与数值解释分离”的核心。

### 三、三种标志别混：进位、借位、符号溢出

- **无符号加法**：最高位向外产生进位 $C_{out}=1$ 表示 8 位结果装不下，例如 $134+246=380$，有无符号溢出。
- **无符号减法**：通常以 $A+\bar B+1$ 的进位理解借位，若 $C_{out}=0$ 则发生无符号借位（有些体系结构的 CF 定义与“借位”相反，须按 ISA 明确约定）。例如 $134-246$ 借位。
- **补码带符号加/减**：要检测的是真值是否超出 $[-128,127]$，可用“进入符号位的进位 $C_{in,sign}$”与“离开符号位的进位 $C_{out,sign}$”异或：

$$
\boxed{V=C_{in,sign}\oplus C_{out,sign}}.
$$

等价符号口诀：加法**同号相加得异号**才溢出；减法**异号相减且结果符号与被减数不同**才溢出。公式和口诀均需要按**操作实际是加法还是减法**使用，不可混用。

### 四、本题带符号运算逐项判断

$$
k1=m-n=-122-(-10)=-112\in[-128,127],
$$

所以 `k1` 无溢出，结果 `90H` 按补码恰好解释为 -112。

$$
k2=m+n=-122+(-10)=-132<-128,
$$

所以 `k2` 溢出；加法器保留低 8 位后得到 `7CH`，即数学和的模 256 代表值 124。**两负数相加变正数**正是溢出的直观证据。注意 `z2` 和 `k2` 得到同样的位串 `7CH`，但一个作为无符号数得到有效的模运算结果，另一个不能正确代表真值 -132。

### 五、必须知道的 C 标准与考试简化模型的边界

标准 C 要求 `int` 至少 16 位，因此题目中的“8 位 `int`”是为机器数运算设计的**抽象模型**；对现实 C 实现而言，将超出带符号范围的无符号值转换成有符号值具有实现规定的行为，而带符号整数运算溢出并**不保证**自动回绕（通常属于未定义行为）。解真题请按题干“8 位补码机器”求寄存器低位及硬件 OF，工程代码中应避免依赖这些越界运算的返回值。高频考点见本章[原创题](#question-original-163)。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

某 8 位 ALU 执行 $S=A-B\pmod {256}$，通过 $A+\bar B+1$ 实现，最高位输出进位记为 $C_{out}$，**无符号借位**发生当且仅当 $C_{out}=0$。

1. 对 $A=\texttt{80H}$、$B=\texttt{01H}$ 求结果、无符号借位标志、带符号溢出标志；
2. 对 $A=\texttt{01H}$、$B=\texttt{80H}$ 再计算一次；
3. 给出一般减法 $A-B$ 的符号位判溢出公式并说明两个标志为什么不能相互代替。

<ExamSolution>

<ExamAnswer>

第一组结果 `7FH`，**无借位**（$C_{out}=1$），**有符号溢出**（$V=1$）；第二组结果 `81H`，**有借位**（$C_{out}=0$），**有符号溢出**（$V=1$）。公式为 $V=(a_s\oplus b_s)\land(s_s\oplus a_s)$，其中下标 $s$ 表示符号位。

</ExamAnswer>

<ExamExplanation>

1. $\texttt{80H}-\texttt{01H}=\texttt{7FH}$，按无符号解释为 $128-1=127$，完全可表示，不借位；按有符号补码解释则为 $-128-1=-129$，小于下界 -128，因此溢出。按 ALU 进位验证：`80H + FEH + 1 = 17FH`，最高位进位是 1。
2. $\texttt{01H}-\texttt{80H}=\texttt{81H}$，无符号意义上 $1-128=-127$ 需借位；补码意义上 $1-(-128)=129$，大于 127，故同样有溢出。通过 `01H + 7FH + 1 = 81H`，没有最高位进位。
3. 对减法，**两个操作数符号不同**才有可能溢出，且结果符号不同于被减数符号则确实溢出，所以 $V=(a_s\oplus b_s)(s_s\oplus a_s)$。而借位判断考察的是**无符号数值大小关系 $A<B$**。一个处理真值范围，一个处理 unsigned 的借位，不能用 `CF==OF` 或“结果最高位为 1”代替。

做题建议把“位模式运算、unsigned 判断、signed 判断”分三列，先算 8 位结果，再分别按相应的语义求标志。若 ISA 直接把 CF 定义为借位，则记忆“减法进位 $C_{out}$ 与借位互补”的关系即可。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2017 年第 43 题

<ExamQuestion>

**53. 2017 年第 43 题**

已知

$$
f(n)=\sum_{i=0}^{n}2^i=2^{n+1}-1,
$$

计算 $f(n)$ 的 C 语言函数 `f1` 如下：

```c
int f1(unsigned n) {
    int sum = 1, power = 1;
    for (unsigned i = 0; i <= n - 1; i++) {
        power *= 2;
        sum += power;
    }
    return sum;
}
```

将 `f1` 中的 `int` 都改为 `float`，可得到计算 $f(n)$ 的另一个函数 `f2`。假设 `unsigned` 和 `int` 型数据都占 32 位，`float` 采用 IEEE 754 单精度格式。请回答：

1. 当 $n=0$ 时，`f1` 会出现死循环，为什么？若将 `f1` 中变量 `i` 和 `n` 都定义为 `int` 型，是否还会出现死循环？为什么？
2. `f1(23)` 和 `f2(23)` 的返回值是否相等？机器数各是什么（十六进制）？
3. `f1(24)` 和 `f2(24)` 的返回值分别为 $33554431$ 和 $33554432.0$，为什么不相等？
4. $f(31)=2^{32}-1$，而 `f1(31)` 的返回值却为 $-1$，为什么？若使 `f1(n)` 的返回值与 $f(n)$ 相等，则最大的 $n$ 是多少？
5. `f2(127)` 的机器数为 `7F800000H`，对应什么值？若使 `f2(n)` 的结果不溢出，最大的 $n$ 是多少？若要求结果精确、无舍入，最大的 $n$ 是多少？

<ExamSolution>

<ExamAnswer>

1. `n=0` 时，32 位 `unsigned` 的 `n-1` 得到 $2^{32}-1$；`i` 循环增大后又按模 $2^{32}$ 回到 0，循环条件无法使其正常结束。若 `i,n` 均改为 `int`，`0<=-1` 初次即假，返回 1。
2. `f1(23)=f2(23)=16777215`；机器数分别为 `00FFFFFFH`、`4B7FFFFFH`。
3. `f1(24)=33554431`，`f2(24)=33554432.0`，原因是 24 位有效精度与“最近偶数”舍入。
4. 按题目补码回绕机器模型，`f1(31)` 的位模式是 `FFFFFFFFH`，解释为 -1；得到数学正确整数值的最大参数是 $n=30$。
5. `7F800000H` 为 IEEE 754 单精度 $+\infty$；`f2` 返回有限值的最大 $n=126$，精确值的最大 $n=23$。

</ExamAnswer>

<ExamExplanation>

### 一、无符号下溢是控制流错误，不是浮点舍入

原循环为 `for (unsigned i=0; i<=n-1; i++)`。当 $n=0$，**表达式 `n-1` 在 unsigned 类型内执行**，不是数学整数的 -1，而是

$$
0-1\equiv 2^{32}-1\pmod{2^{32}}=\texttt{FFFFFFFFH}.
$$

初始 $i=0$ 满足条件，后续 $i$ 不可能大于 `UINT_MAX`；在纯无符号控制变量模型中，`i++` 从最大值回绕成 0，仍满足条件，构成死循环。若把 `i`、`n` 都改成有符号 `int`，`n-1=-1`，开始时 $0\le-1$ 不成立，所以 $f(0)=1$ 可以返回。

**程序工程层面的额外提醒**：原函数还包含 `int power *= 2`、`int sum += power`，当迭代足够多时会发生**有符号溢出（ISO C 未定义行为）**；所以严格的 C 语言标准不能承诺实际程序必然永远循环。考题讨论的是循环边界与 32 位硬件回绕的典型现象。更可靠的循环写法是 `for (unsigned i=1; i<=n; ++i)` 并对 `i` 的上界和算术溢出另行处理，或用带上界检查的 `while`。

### 二、精确整数编码与 IEEE 754 单精度拆位

数学恒等式为

$$
f(n)=1+2+\cdots+2^n=2^{n+1}-1.
$$

对 $n=23$，$f(23)=2^{24}-1=16777215$，是 24 个 1 的二进制整数；32 位有符号整数能精确容纳，机器数是 `00FFFFFFH`。

单精度格式分为 1 位符号、8 位偏置阶码（偏置 $127$）、23 位尾数，规格化数有隐含最高有效位 $1$，总有效精度 **$p=24$ 位**。$2^{24}-1$ 的规格化形式为

$$
1.\underbrace{11\cdots11}_{23\text{ 个}}\times2^{23},\qquad E=23+127=150=\texttt{96H},
$$

符号位为 0，尾数域为 23 个 1，拼装成 `4B7FFFFFH`。它被**精确表示**，因此两个函数返回值在数值上相等，但位模式不相等（类型不同）。

### 三、$n=24$ 的关键不是溢出，而是精度损失

$$
f(24)=2^{25}-1=33554431.
$$

在 $2^{25}$ **下方紧邻的单精度浮点数**是 $2^{25}-2$，两者相差 2；$2^{25}-1$ 恰好位于两者中点。IEEE 754 默认舍入模式“就近，遇中间值取偶”（ties-to-even）选取尾数最低有效位为偶数的 $2^{25}$，从而得到 `33554432.0`。

不能简单说“所有大于 $2^{24}$ 的整数都被向上舍入”：例如 $2^{24}+2$ 是可以精确表示的，$2^{24}+1$ 才是中间值。舍入方向还受当前舍入模式影响；题目默认通常是就近偶数。

### 四、`f1` 的数学范围与 C 有符号溢出

为了使 $f(n)$ 作为 32 位 `int` 精确返回，需要

$$
2^{n+1}-1\le2^{31}-1\iff n\le30.
$$

当 $n=31$，$f(31)=2^{32}-1$，其低 32 位全为 1，按补码位模式被解释为 -1。**这是题设机器模型的答案，不代表标准 C 对 `int` 算术溢出作了回绕保证**：实际循环在计算 `power=2^{31}` 时就已经发生有符号溢出，标准 C 对结果不再保证。面向真实程序，应用足够宽的无符号整数类型，且先检查目标范围。

### 五、`f2` 的有限值边界与精确性边界不是一回事

单精度最大有限数是

$$
F_{\max}=(2-2^{-23})2^{127}=2^{128}-2^{104}.
$$

`f2` 逐次累加 $2^i$：$n=126$ 时最大幂次为 $2^{126}$，总和舍入为有限的 $2^{127}$；$n=127$ 时累加到 $2^{127}$，真实总和 $2^{128}-1$ 在就近舍入下溢出为 `7F800000H`，即 $+\infty$（不同舍入模式或浮点环境下需另行确认）。

**完全精确**要求二进制全 1 的 $n+1$ 位都能容纳于单精度的 24 位有效精度：

$$
n+1\le24\iff\boxed{n\le23}.
$$

考试中务必把四种界限分开记：**循环边界问题**、**带符号整数范围**、**浮点有限范围**、**浮点可精确表达范围**。并区分 `int` 机器数十六进制与 `float` 的 IEEE 754 位模式。见[原创题](#question-original-164)。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

假设采用 IEEE 754 的默认“就近，遇中间取偶”舍入。

1. 把 $2^{24}+1$、$2^{24}+3$ 分别存入单精度 `float`，结果是多少？解释为何结果方向不同。
2. 将 2017 年大题的 `f2` 改成 IEEE 754 **双精度（binary64）** 累加函数 `f3`，`sum`、`power` 均为 `double`；问 $f3(n)$ 的结果可**精确**等于 $2^{n+1}-1$ 的最大 $n$，以及结果保持**有限值**的最大 $n$，并写出推导前提。

<ExamSolution>

<ExamAnswer>

单精度舍入：$2^{24}+1\mapsto2^{24}$，$2^{24}+3\mapsto2^{24}+4$；双精度 $p=53$ 位、最大正常数指数 $1023$，故完全精确的最大 $n=52$，默认舍入下保持有限的最大 $n=1022$。

</ExamAnswer>

<ExamExplanation>

**第一问**：在 $[2^{24},2^{25})$ 区间相邻单精度浮点数相距 $2$。$2^{24}+1$ 位于 $2^{24}$ 和 $2^{24}+2$ 的中点；前者的有效尾数最低位为偶，于是选择 $2^{24}$。$2^{24}+3$ 位于 $2^{24}+2$ 和 $2^{24}+4$ 中点；选择尾数最低位为偶的 $2^{24}+4$。这说明 ties-to-even **不是固定向下或者向上**。

**第二问**：binary64 有 52 位显式尾数加 1 位隐含位，共 53 位有效精度。$f(n)=2^{n+1}-1$ 是 $n+1$ 个二进制 1，精确性需要 $n+1\le53$，得最大 $n=52$。binary64 最大有限数为 $(2-2^{-52})2^{1023}$，当 $n=1022$，$f(n)=2^{1023}-1$ 在累加过程中舍入到有限的 $2^{1023}$；当 $n=1023$，数学值 $2^{1024}-1$ 在默认就近舍入下超出有限范围，得到 $+\infty$。故最大 $n=1022$。

本结论限定：使用 binary64、默认舍入、各轮中间运算按 binary64 计算、不使用编译器会改变逐步舍入语义的“快速数学”优化；同时应修复原始 `unsigned` 循环的 $n=0$ 边界问题。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

## 2020 年第 43 题

<ExamQuestion>

**59. 2020 年第 43 题**

有两个实现 $x\times y$ 的 C 语言函数：

```c
unsigned umul(unsigned x, unsigned y) { return x * y; }
int imul(int x, int y) { return x * y; }
```

假定计算机 M 中 ALU 只能进行加减运算和逻辑运算。请回答：

1. 若指令系统没有乘法指令，但有加、减和移位等指令，为什么仍可实现上述乘法？
2. 若指令系统有乘法指令，并基于 ALU、移位器、寄存器和相应控制逻辑实现，控制逻辑的作用是什么？
3. 对以下三种情况：①无乘法指令；②用 ALU 和移位器实现乘法指令；③用阵列乘法器实现乘法指令，`umul()` 在哪种情况下执行时间最长？哪种最短？说明理由。
4. $n$ 位整数乘法可得到 $2n$ 位完整乘积。当 $n=32$、$x=2^{31}-1$、$y=2$ 时，带符号与无符号乘法得到的 64 位完整乘积分别是什么（十六进制）？此时 `umul()` 和 `imul()` 的返回结果是否溢出？对无符号乘法，若只取低 32 位，如何根据 64 位完整乘积判断是否溢出？

<ExamSolution>

<ExamAnswer>

1. 即使没有乘法指令，也可用移位、加法、条件判断等普通指令完成二进制“部分积累加”。
2. 微操作控制逻辑负责取乘数位、决定加法、控制移位、寄存器使能、循环次数和完成信号。
3. 在题设的典型实现模型下：①软件循环最慢，③阵列乘法器最快，②迭代硬件乘法居中；这是**通常的结构级比较**，非对所有具体 CPU 的绝对性能保证。
4. 两种解释下的 64 位真值乘积都是 `00000000FFFFFFFEH`。`umul` 无符号 32 位结果可容纳，不溢出；`imul` 的 32 位有符号结果溢出。无符号完整乘积高 32 位全 0，当且仅当缩为低 32 位无溢出。

</ExamAnswer>

<ExamExplanation>

### 一、从二进制展开理解乘法为什么能“用加法代替”

设无符号乘数 $y=\sum_{i=0}^{n-1} y_i2^i$，其中 $y_i\in\{0,1\}$，则

$$
xy=\sum_{i=0}^{n-1}y_i\,(x\ll i).
$$

这等价于每次查看乘数最低位：若为 1，则累加当前被乘数；随后被乘数左移、乘数右移，重复 $n$ 次。例如 $13\times 11=13\times(8+2+1)=104+26+13=143$。执行它只需要按位与、移位和加法，所以没有乘法指令时软件循环仍能实现乘法。

下面展示一个**完整 64 位积**的固定次数算法（按题设操作数为 32 位无符号数）：

```c
#include <stdint.h>

uint64_t umul64_shift(uint32_t x, uint32_t y) {
    uint64_t a = x, p = 0;            // a 先扩宽再左移
    for (int i = 0; i < 32; ++i) {
        if (y & 1U) p += a;
        a <<= 1;
        y >>= 1;
    }
    return p;
}
```

`a` 的 64 位扩宽很重要：若先以 32 位执行 `x << i`，高位可能在加到部分积之前就丢失，无法计算完整 64 位乘积。

### 二、控制逻辑与数据通路分工

- **ALU**：对部分积与被乘数作加法，或执行必要的减法；
- **移位器**：按算法对乘数、被乘数或组合寄存器进行移位；
- **寄存器**：暂存部分积、乘数、被乘数及当前结果；
- **控制器/计数器**：根据最低位、符号位、计数等条件，发出 ALU 操作、移位方向、寄存器装载使能和结束信号。

软实现①需要执行若干条机器指令，每条指令又有取指、译码开销；迭代硬件②一条乘法指令内部多周期执行；并行阵列③一次性生成/归约多个部分积，典型延迟更低而面积、功耗通常更大。题目规定的一般比较是 **①最长，③最短**；真实运行性能还受流水线、微体系结构、时钟和编译优化等影响。

### 三、完整乘积、截断积、带符号与无符号溢出

本题 $x=\texttt{7FFFFFFFH}=2^{31}-1$，$y=\texttt{00000002H}=2$；两者最高位为 0，所以正数的带符号/无符号**真值相同**：

$$
xy=2(2^{31}-1)=2^{32}-2=\boxed{\texttt{00000000FFFFFFFEH}}.
$$

无符号 32 位范围为 $[0,2^{32}-1]$，所以 `umul` 返回低位 `FFFFFFFEH`，作为无符号值是 4294967294，**未溢出**。有符号 32 位范围为 $[-2^{31},2^{31}-1]$，4294967294 超限，所以 `imul` **发生有符号溢出**，若硬件仅保留低位，其位模式 `FFFFFFFEH` 会被补码解释为 -2；这不是数学乘积。

对**无符号** $32\times32$ 乘法，完整 64 位积 $P=P_H\cdot2^{32}+P_L$，截断到 32 位不丢数值当且仅当 $P_H=0$：

$$
\boxed{\text{unsigned 无溢出}\iff P_H=\texttt{00000000H}}.
$$

对**带符号**乘法，不能套用“高 32 位为 0”的规则：其正确条件是整个 64 位积恰好为低 32 位的**符号扩展**，即

$$
\boxed{\text{signed 无溢出}\iff P_H=\begin{cases}0,&P_L\text{ 的最高位为 }0,\\2^{32}-1,&P_L\text{ 的最高位为 }1.\end{cases}}
$$

本题 $P_H=0$ 但 $P_L$ 符号位为 1，故 signed 溢出、unsigned 不溢出，构成**同一串结果位在不同类型下溢出判定不同**的标准案例。

### 四、考试与实战易错点

1. “两种完整乘积相同”不是任意有符号/无符号数都成立；它在本题中成立，是因为两操作数的最高位都为 0。若操作数最高位为 1，两种数学解释与 64 位全积可能不同。
2. 标准 C 的无符号乘法按模 $2^{32}$ 定义，溢出检测是要判断是否丢失真实数学乘积的高位；`imul` 对超范围的有符号乘法，ISO C 属于**未定义行为**，不能依赖编译器一定返回 -2。
3. 比较实现时应说明操作数位数和硬件结构，**单条乘法指令**未必严格等于**单周期执行**。
4. 如果题目变为“低 32 位是否相等”，对同样的两个**位模式**，模 $2^{32}$ 的乘法低 32 位是相同的，不管把它们按 signed 还是 unsigned 解释；但 64 位全积一般不同，见[原创题](#question-original-165)。

</ExamExplanation>

取相同的 32 位位模式 $x=\texttt{FFFFFFFEH}$、$y=\texttt{00000003H}$，分别作为 `uint32_t` 与 `int32_t` 两种类型进行乘法。假设均先在 64 位精度得到真实数学乘积。

1. 给出 unsigned 与 signed 两种解释的操作数及完整 64 位积；
2. 比较两种情形的乘积低 32 位，并判断把结果截断到 32 位是否会丢失数学真值；
3. 给出检查带符号 32 位乘积是否可容纳于 32 位的高低位规则。

<ExamSolution>

<ExamAnswer>

Unsigned：$4294967294\times3=12884901882=\texttt{00000002FFFFFFFAH}$，截断到 `FFFFFFFAH` **丢失真值**；signed：$(-2)\times3=-6=\texttt{FFFFFFFFFFFFFFFAH}$，截断到 `FFFFFFFAH` **不丢失真值**。两种低 32 位**相同**，高 32 位不同。

</ExamAnswer>

<ExamExplanation>

`FFFFFFFEH` 的无符号值为 $2^{32}-2$，带符号补码值为 $-2$。因此 unsigned 真积是 $3(2^{32}-2)=3\cdot2^{32}-6=2\cdot2^{32}+(2^{32}-6)$，即 `00000002FFFFFFFAH`；signed 真积是 -6，64 位补码符号扩展为 `FFFFFFFFFFFFFFFAH`。

**为何低位一致？** 对任何同一位模式，signed 与 unsigned 解释只差 $2^{32}$ 的整数倍。乘以另一操作数后，差仍是 $2^{32}$ 的整数倍，所以**模 $2^{32}$** 的结果相同。但是完整积并非总相同。

无符号结果能放入 32 位当且仅当高 32 位为 0；带符号结果能放入 32 位当且仅当高 32 位等于低 32 位符号位扩展的 32 位全 0 或全 1。此例的 signed 高位全 1，低位符号位为 1，所以 signed 不溢出；unsigned 高位为 2，所以 unsigned 真积超出了 32 位无符号范围。

真实 C 程序可先显式提升到 `int64_t` / `uint64_t` 再做乘法与检测，不应先做可能溢出的 `int32_t * int32_t` 再转成 64 位——**提升发生得太晚**。

</ExamExplanation>

## 2025 年第 44 题

<ExamQuestion>

**70. 2025 年第 44 题**

对于上题中的计算机 M 和程序 P，假定 P 的部分机器级代码如下，其中 R0～R4 为通用寄存器，SEXT 表示按符号扩展；M 中补码除法器的逻辑结构如下图所示。

```text
// x 在 R2 中，i 在 R4 中
// 数组 d 的首地址在 R3 中
mov  R1, (R3+R4*4) // R1 <- d[i]
scov R1             // {R0,R1} <- SEXT(R1)
idiv R1, R2         // R1 <- {R0,R1} / R2
```

<img src="/img/408/past-exams-large-questions/02-计算机组成原理/assets/2025-44-figure-001.svg" alt="2025 年第 44 题补码除法器逻辑结构" />

1. 若执行 `idiv` 指令的除运算时，`d[i]=0x87654321`、`x=0xff`，则补码除法器中寄存器 R、Q 和 Y 的初始内容分别是什么（用十六进制表示）？图中哪个部件包含计数器？在补码除法器执行过程中，由 `ALUop` 所控制的 ALU 运算有哪几种？
2. 假设 `idiv` 指令执行过程中会检测并触发除法异常，则执行 `idiv` 时，哪些情况下会发生除法异常？要求给出此时 `d[i]` 和 `x` 的十六进制机器数。发生除法异常时，在异常响应过程中 CPU 需要完成哪些操作？

<ExamSolution>

<ExamAnswer>

1. $\boxed{R=\texttt{FFFFFFFFH}}$、$\boxed{Q=\texttt{87654321H}}$、$\boxed{Y=\texttt{000000FFH}}$。计数器在控制逻辑 $C_n$ 中。`ALUop` 至少选择 ALU 的**加法、减法**。
2. 除数为 0：`x=00000000H`，`d[i]` 任意；商超出 32 位补码范围：`d[i]=80000000H` 且 `x=FFFFFFFFH`。异常响应时保存断点/程序状态、确定异常类型并进入内核态、取异常处理入口更新 PC；一般寄存器现场通常由处理程序继续保存。

<ExamExplanation>

### 一、先从机器指令恢复“被除数究竟是多少位”

程序先执行

```text
mov  R1, (R3+R4*4)   // 按 int 数组元素宽度寻址 d[i]
scov R1               // 对 R1 的 32 位值做符号扩展
idiv R1, R2           // 64 位{R0,R1} 被除数 / 32 位 R2 除数
```

其中有效地址 $R3+R4\times4$ 由数组首地址、下标及每个 32 位整型元素占 4 字节得出。`mov` 加载 `d[i]=\texttt{87654321H}`。这个 32 位补码最高位是 1，所以是负数，其向 64 位的**符号扩展**必须在高 32 位填满 1：

$$
\underbrace{\texttt{FFFFFFFF}}_{R0}\underbrace{\texttt{87654321}}_{R1}\mathrm H.
$$

从图中除法器的数据通路看，R、Q 分别接收被除数的高、低 32 位，而 Y 装除数。`x=0xff` 是十六进制的正数 $255$，在 32 位 `int` 中为 `000000FFH`，不是把单个字节 `FFH` 强行符号扩展成 `FFFFFFFFH`（后者是 -1）。因此

$$
\boxed{(R,Q,Y)=(\texttt{FFFFFFFFH},\texttt{87654321H},\texttt{000000FFH})}.
$$

这类问题的速解顺序是**数据宽度→原数符号→SEXT/ZEXT→部件装载**，不要反过来猜 R 与 Q。

### 二、计数器、ALU、移位器如何协同工作

图中的 $C_n$ 是迭代的**控制逻辑**，记录已执行的位数/剩余轮次，故含计数器；R、Q、Y 是保存操作数据的寄存器，不能把其中一个直接说成控制计数器。

补码恢复余数法或不恢复余数法的细节可能不同，但图中 `ALUop` 必须能让 ALU 进行**加法和减法**，例如以 $R-Y$ 试探商位、按条件通过 $R+Y$ 恢复余数或参与下一轮修正；同时通过移位控制将 R/Q 的位传递至下一步。题目问 `ALUop` 控制的运算种类时，不能把单独移位部件执行的“左移”混写成 ALU 加、减运算的一种。

### 三、两个除法异常的确切机器数

1. **除数为 0**：对任意被除数 $d[i]$，当 $x=\texttt{00000000H}$ 时都不能完成除法；注意即使 $d[i]=0$，$0/0$ 仍非法。
2. **商溢出**：被除数是 32 位 `int` 经符号扩展的原值，除数也是 32 位 `int`。对非零除数，商超出范围 $[-2^{31},2^{31}-1]$ 只可能是

$$
(-2^{31})/(-1)=+2^{31}>2^{31}-1.
$$

对应

$$
\boxed{d[i]=\texttt{80000000H},\quad x=\texttt{FFFFFFFFH}}.
$$

别把 `80000000H` 当正数 $2^{31}$，也别把 `000000FFH` 误读成 -1。题设说硬件检测并触发除法异常，因此需要给出**数学上越界的组合**；具体体系结构可能以同步异常方式报告。

### 四、异常响应过程：硬件做什么，软件做什么

同步除法异常通常在当前指令执行中检测到，其异常处理要保护能够确定出错指令的位置及恢复所需的状态，典型流程为：

1. 记录异常原因、保存适当的程序计数器（故障指令地址或按架构约定的返回断点）和处理器状态字；
2. 切换到相应特权态，按体系结构要求设置异常屏蔽与处理状态；
3. 通过异常向量或异常入口寄存器得到处理程序地址，更新 PC，开始执行异常处理程序；
4. 处理程序按需保护通用寄存器、报告/终止出错程序，或在可恢复场景下修正状态后返回。

这里的第 1～3 步是**硬件异常响应的核心**，第 4 步属于异常处理软件的工作。异常不等于异步外部中断：除法异常由**当前执行的指令**导致；对能否重执行该指令、保存 PC 的具体值应遵从体系结构的规定。

### 五、考点迁移：直接计算商与余数

若不发生异常，本题数据的真值为

$$
d[i]=\texttt{87654321H}=2271560481-2^{32}=-2023406815,
\qquad x=255.
$$

C 的有符号整数除法向 0 截断，故

$$
q=\operatorname{trunc}(-2023406815/255)=-7934928,
$$

$$
r=d[i]-qx=-175,
\qquad |r|<|x|.
$$

商的低 32 位是 `FF86EC30H`，余数的补码位模式是 `FFFFFF51H`。这组计算可检验：除数 $255$ 是正数，非零余数与被除数同号；**数学负数的向下取整**与 **C 的向零截断**不同（不能把商直接写成 $-7934929$）。

1. 对两个非零、非异常的 $x=\pm255$，求十进制商和余数，检查 $d[i]=qx+r$；
2. 当 $x=0$ 和 $x=-1$ 时分别是否触发异常？给出判定理由；
3. 将被除数改为 `80000000H`，问 $x=-1$ 会发生什么异常，并说明“负数除以 -1”是否总会溢出。

<ExamSolution>

<ExamAnswer>

$\texttt{87654321H}=-2023406815$。$x=255$ 时商 $q=-7934928$、余数 $r=-175$；$x=-255$ 时商 $q=7934928$、余数仍为 $-175$。$x=0$ 一定除零异常；$x=-1$ 对本例不会溢出，得到商 $2023406815$、余数 0；若被除数改为 `80000000H`（$-2^{31}$），则除以 -1 得 $+2^{31}$，触发商溢出。

</ExamAnswer>

<ExamExplanation>

32 位补码转十进制：$0x87654321=2271560481$（无符号），减去 $2^{32}=4294967296$ 得 $-2023406815$。C 整数除法定义（除以 0 与商不可表示除外）为 $q=\operatorname{trunc}(a/b)$，且 $a=qb+r$，满足 $|r|<|b|$，非零余数同被除数符号。

当 $b=255$ 时，$2023406815=7934928\times255+175$，所以 $q=-7934928$、$r=-175$。当 $b=-255$ 时，商取正 $7934928$，余数依然是 $-175$，因为余数的符号由**被除数**决定，而非由除数决定。两次都能代回 $a=qb+r$ 校验。

当 $b=0$ 时数学除法未定义，必为除零异常；当 $b=-1$ 时，本例商为 $2023406815$，没有超过 $2^{31}-1=2147483647$，故安全。但 $a=-2147483648$ 时，$(-2147483648)/(-1)=+2147483648$，超出带符号 32 位上限，这是唯一的两非零操作数商溢出情况。不能把“被除数为负，除数 -1”整体判作异常。

考试检查顺序：**除数是否为 0→是否是 `INT_MIN / -1`→按向零截断求商→用恒等式求余数→检查余数符号/界限**。面对指令级题目，先确认被除数宽度与符号扩展规则，再进行上述步骤。
