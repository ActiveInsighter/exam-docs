## 2011 年第 43 题

<ExamQuestion>

**41. 2011 年第 43 题**

假定在一个 **8 位字长**的计算机中运行如下 C 程序段：

```c
unsigned int x = 134;
unsigned int y = 246;
int m = x;
int n = y;
unsigned int z1 = x - y;
unsigned int z2 = x + y;
int k1 = m - n;
int k2 = m + n;
```

若编译器将 8 个 8 位寄存器 R1～R8 分别分配给变量 `x、y、m、n、z1、z2、k1、k2`。带符号整数采用补码表示。请回答：

1. 执行上述程序段后，寄存器 R1、R5 和 R6 的内容分别是什么？用十六进制表示。
2. 执行上述程序段后，变量 `m` 和 `k1` 的值分别是多少？用十进制表示。
3. 上述程序段涉及带符号整数加/减和无符号整数加/减。这四类运算能否使用同一个加法器及辅助电路实现？简述理由。
4. 计算机内部如何判断带符号整数加/减是否溢出？上述程序段中，哪些带符号整数运算会溢出？

<ExamSolution>
<ExamAnswer>

1. `R1 = 86H`、`R5 = 90H`、`R6 = 7CH`。
2. `m = -122`、`k1 = -112`。
3. 可以共用一个 8 位加法器及取反、进位和溢出检测电路；位运算相同，区别在结果解释与标志判断。
4. 补码加法：同号相加而结果异号，或符号位进位 $C_7\oplus C_8=1$ 时溢出；减法：被减数和减数异号而结果与被减数异号时溢出。本题仅 `k2=m+n` 溢出。

</ExamAnswer>
<ExamExplanation>

1. **先确定位宽和运算语义，再求十六进制位模式。** 在题设的 8 位整数机器模型下，无符号数以模 $2^8=256$ 保存：

   $$x=134=\texttt{86H},\qquad y=246=\texttt{F6H}.$$

   无符号减法 $134-246=-112\equiv144\pmod{256}$，故 `R5 = 90H`；无符号加法 $134+246=380\equiv124\pmod{256}$，故 `R6 = 7CH`。8 位舍弃的是最高进位，并非按十进制把结果截断。

2. **补码的“位模式”与“真值”要分开。** `m=x` 后寄存器仍存 `86H`，但当作补码解释：$m=134-256=-122$。同理 `n=\texttt{F6H}=246-256=-10$，所以 $k1=m-n=-122-(-10)=-112$，恰在范围 $[-128,127]$ 内，其位模式是 `90H`。记忆捷径：$w$ 位补码的最高位为 1 时，有符号真值等于无符号数值减 $2^w$。

3. **同一加法器为何兼容四类运算？** $w$ 位数据通路只计算 $S=(A+B+C_{in})\bmod 2^w$。做减法时令 $B'=\overline B$、$C_{in}=1$，实现 $A-B=A+\overline B+1$；做加法时 $B'=B,C_{in}=0$。无符号加法看最高位进位判断是否超出 $2^w-1$；有符号加法看溢出标志，不能混用这两个判据。无符号减法若允许借位，也仍能输出模 $2^w$ 的低位结果。

4. **两种溢出判据及本题逐式检查。** 对补码加法，若 $A,B$ 同号而结果异号则溢出；在硬件上等价于最高数值位进入符号位的进位与符号位输出进位异或为 1。对减法 $A-B$，只有 $A,B$ 异号且结果符号与 $A$ 相反才溢出。`k1=-112` 不溢出；`k2=-122+(-10)=-132` 小于 $-128$，8 位计算保留 `7CH`，将两个负数算成了正数，发生溢出。`x+y` 的进位不能据此推断 `m+n` 是否溢出，因为同一位模式的解释不同。

5. **答题模板与易错点。** 先列 $2^w$ 与有符号范围，再按模数写位模式，随后转补码真值，最后分别检查 *CF（无符号进位/借位）* 与 *OF（有符号溢出）*。在标准 C 语言抽象语义中，普通平台 `int` 不必为 8 位；并且带符号算术溢出属未定义行为。本题明确限定 8 位寄存器及补码机器模型，答案是在该模型下得到的运算结果，不能直接推广为所有 C 编译器的行为。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

<ExamQuestion>

在一台 8 位补码计算机上，寄存器的原始位模式为 `A=7DH`、`B=05H`，分别执行 $A+B$ 和 $A-B$，结果均只保留 8 位。

1. 两条运算的结果位模式和补码真值分别是多少？
2. 分别判断有符号溢出与无符号加法进位、无符号减法借位。
3. 若把 A、B 视为无符号数，运算结果的数学值与保存值分别是多少？

<ExamSolution>
<ExamAnswer>

1. 加法保存 `82H`（补码 $-126$）；减法保存 `78H`（补码 $120$）。
2. 加法有符号溢出，且无符号加法无最高位进位；减法无有符号溢出，也无无符号借位。
3. 无符号加法 $125+5=130$，保存 $130$；无符号减法 $125-5=120$，保存 $120$。

</ExamAnswer>
<ExamExplanation>

1. `7DH=125`、`05H=5`，加法数学结果 $130>127$，低 8 位为 `82H`，补码真值为 $130-256=-126$；减法结果 $120=\texttt{78H}$。
2. **同号相加符号突变**：$125$ 与 $5$ 都为正，但加法保存结果被解读成负数，故 OF=1；$130<256$，故加法无最高位进位（CF=0）。减法 $125-5\ge0$，无需借位；两个同号正数相减不存在本例的补码溢出。
3. 注意 OF 与 CF 是独立概念，不要因为“结果有负号”就推断无符号加法进位，更不能因为无进位就断言有符号计算正确。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

<ExamQuestion>

某 8 位处理器使用同一 ALU 执行 `A - B`，输入 `A=80H`、`B=01H`。

1. 求 8 位结果，并给出有符号和无符号两种解释下输入的真值。
2. 两种解释下的运算是否分别出现超范围？为什么？
3. 写出减法复用加法器时第二操作数和初始进位的取值。

<ExamSolution>
<ExamAnswer>

1. 保存结果 `7FH`；有符号输入分别为 $-128,1$；无符号输入分别为 $128,1$。
2. 有符号运算 $-128-1=-129$ 溢出；无符号运算 $128-1=127$ 无借位，不超范围。
3. 把 `01H` 按位取反为 `FEH`，初始进位 $C_{in}=1$，相加得到 `7FH`（舍弃高位进位）。

</ExamAnswer>
<ExamExplanation>

1. 算式 `80H + FEH + 01H = 17FH`，8 位 ALU 保存低 8 位 `7FH`；同一结果位串既可解释为有符号 $127$，也可解释为无符号 $127$。
2. 补码的最小负数 $-128$ 没有正数对称值 $128$；再减 1 必须溢出。若输入是无符号数，则 $128-1=127$，运算完全合法。
3. 硬件减法通常采用 $A+\overline B+1$，无需另设完整的减法器。解题时必须先选解释规则，**结果的机器数本身不反映运算是否“算对”**。

</ExamExplanation>
</ExamSolution>

## 2017 年第 43 题

<ExamQuestion>

**53. 2017 年第 43 题**

已知

$$
f(n)=\sum_{i=0}^{n}2^i=2^{n+1}-1,
$$

计算 $f(n)$ 的 C 语言函数 `f1` 如下：

```c
int f1(unsigned n) {
    int sum = 1, power = 1;
    for (unsigned i = 0; i <= n - 1; i++) {
        power *= 2;
        sum += power;
    }
    return sum;
}
```

将 `f1` 中的 `int` 都改为 `float`，可得到计算 $f(n)$ 的另一个函数 `f2`。假设 `unsigned` 和 `int` 型数据都占 32 位，`float` 采用 IEEE 754 单精度格式。请回答：

1. 当 $n=0$ 时，`f1` 会出现死循环，为什么？若将 `f1` 中变量 `i` 和 `n` 都定义为 `int` 型，是否还会出现死循环？为什么？
2. `f1(23)` 和 `f2(23)` 的返回值是否相等？机器数各是什么（十六进制）？
3. `f1(24)` 和 `f2(24)` 的返回值分别为 $33554431$ 和 $33554432.0$，为什么不相等？
4. $f(31)=2^{32}-1$，而 `f1(31)` 的返回值却为 $-1$，为什么？若使 `f1(n)` 的返回值与 $f(n)$ 相等，则最大的 $n$ 是多少？
5. `f2(127)` 的机器数为 `7F800000H`，对应什么值？若使 `f2(n)` 的结果不溢出，最大的 $n$ 是多少？若要求结果精确、无舍入，最大的 $n$ 是多少？

<ExamSolution>
<ExamAnswer>

1. `n=0` 时无符号表达式 `n-1` 变成 $2^{32}-1$；无符号 `i` 循环加一后回绕，条件一直成立。若 `i` 和 `n` 均改为 `int`，初次判断 $0\le-1$ 为假，不死循环。
2. `f1(23)=f2(23)=16777215`；机器数分别是 `00FFFFFFH`（32 位整数）与 `4B7FFFFFH`（单精度浮点数）。
3. `f1(24)=33554431`；`f2(24)=33554432.0`。原因是单精度 24 位有效数字不足以精确容纳 $2^{25}-1$。
4. 按题设 32 位补码截断模型，`f1(31)` 的位模式为 `FFFFFFFFH`，解释为 $-1$；正整数结果准确时最大的 $n=30$。
5. `7F800000H` 为正无穷 $+\infty$；`f2` 有限且不溢出的最大 $n=126$；不发生舍入的最大 $n=23$。

</ExamAnswer>
<ExamExplanation>

1. **先分析边界表达式，后看循环是否终止。** 对 32 位 `unsigned` 而言，$0-1\equiv2^{32}-1\pmod{2^{32}}$，循环条件变为 `i <= UINT_MAX`，而 `i` 无论是多少总满足它。`i` 到最大值后 `i++` 按模 $2^{32}$ 回到 0，因此不是“只执行约 $2^{32}$ 次”，而是持续循环。将 `n`、`i` 同时改成有符号 `int`，`n=0` 时上界为 $-1$，初始判断直接失败，返回 $f(0)=1$。**工程改进**：用 `for (unsigned i=1; i<=n; ++i)` 消除 `n-1` 在零处的无符号下溢，但仍需按目标范围检查算术溢出和循环计数上界。

2. **整数位模式与 IEEE 754 编码逐项确定。** $f(23)=2^{24}-1=16777215=\texttt{00FFFFFFH}$。浮点规格化写作 $1.111\ldots111_2\times2^{23}$：符号位 $0$，阶码 $23+127=150=\texttt{96H}$，尾数字段全为 1（23 位），得到 `4B7FFFFFH`。$2^{24}-1$ 恰有 24 个有效二进制位，单精度能精确表示。

3. **浮点精度是“有效位”，而不是“可表示数值的最大绝对值”。** 单精度含 23 位显式小数和一位隐藏前导 1，共 24 位有效数字。$f(24)=2^{25}-1$ 有 25 个连续 1。靠近 $2^{25}$ 时浮点数间距为 $2^{25-23}=4$（下侧邻数间距为 2），精确值 $2^{25}-1$ 与 $2^{25}$ 差 1，因此在默认最近偶数舍入规则下舍入为 $2^{25}$。`f2` 在循环中逐次舍入，也得到 $33554432$，不能只看表达式的数学值而忽略中间计算。

4. **理解补码模截断与 C 语言溢出规则的区别。** 数学结果 $f(31)=2^{32}-1$，其低 32 位均为 1，补码解释为 $-1$。能够作为非负 `int` 精确表示的最大结果满足 $2^{n+1}-1\le2^{31}-1$，即 $n\le30$。但严格 ISO C 中有符号 `int` 乘法/加法溢出属于**未定义行为**，所以 `f1(31)=-1` 是题目所假定的补码机器运算现象，不是每个编译器必须保证的标准 C 结论。

5. **区分有限范围与无舍入精度。** 单精度指数域全 1、尾数为 0 的 `7F800000H` 表示 $+\infty$。`f2(126)` 的逐次计算结果可舍入为有限的 $2^{127}$；再累加 $2^{127}$ 会到约 $2^{128}$，超出正常浮点最大有限数，`f2(127)` 为 $+\infty$，故非溢出最大 $n=126$。若必须得到精确整数 $2^{n+1}-1$，连续 $n+1$ 个 1 均须落入 24 位有效数字，故 $n\le23$。

6. **通用解题法。** 遇到整数和浮点混合题，按“类型提升/无符号模运算 → 中间结果位宽 → 规格化指数 → 有效精度及舍入 → 特殊数编码”五步处理。不能混淆 `overflow`（指数超限）和 `inexact`（有限但舍入）；浮点运算的一次舍入也可能影响后续所有循环结果。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

某程序使用 32 位 `unsigned` 和 IEEE 754 单精度 `float`，依次计算 $g(n)=2^n+1$，采用默认“舍入到最近，遇中点取偶”。

1. $g(23)$、$g(24)$ 能否被 `float` 精确表示？分别给出浮点值。
2. 把 `float` 的有效精度提高到 53 位（如常见 IEEE 754 双精度）后，最大的非负整数 $n$ 为多少，才能保证 $g(n)$ 精确？

unsigned count(unsigned n) {

## 2020 年第 43 题

<ExamQuestion>

**59. 2020 年第 43 题**

有两个实现 $x\times y$ 的 C 语言函数：

```c
unsigned umul(unsigned x, unsigned y) { return x * y; }
int imul(int x, int y) { return x * y; }
```

假定计算机 M 中 ALU 只能进行加减运算和逻辑运算。请回答：

1. 若指令系统没有乘法指令，但有加、减和移位等指令，为什么仍可实现上述乘法？
2. 若指令系统有乘法指令，并基于 ALU、移位器、寄存器和相应控制逻辑实现，控制逻辑的作用是什么？
3. 对以下三种情况：①无乘法指令；②用 ALU 和移位器实现乘法指令；③用阵列乘法器实现乘法指令，`umul()` 在哪种情况下执行时间最长？哪种最短？说明理由。
4. $n$ 位整数乘法可得到 $2n$ 位完整乘积。当 $n=32$、$x=2^{31}-1$、$y=2$ 时，带符号与无符号乘法得到的 64 位完整乘积分别是什么（十六进制）？此时 `umul()` 和 `imul()` 的返回结果是否溢出？对无符号乘法，若只取低 32 位，如何根据 64 位完整乘积判断是否溢出？

<ExamSolution>
<ExamAnswer>

1. 能。二进制乘法可拆为若干次按位测试、条件加法与移位，不需要专门的乘法指令。
2. 控制逻辑负责初始化部分积、测试乘数位、选择加/不加、控制移位和寄存器写入，并循环预定次数。
3. 按题意的典型硬件实现：①软件模拟通常最慢，③阵列乘法器通常最快，②移位加法迭代电路居中。
4. 完整 64 位乘积均是 `00000000FFFFFFFEH`。`umul()` 的 32 位结果未溢出，`imul()` 的数学结果超过 `INT_MAX`。无符号乘法完整积的高 32 位全为零，才表示低 32 位足以保存真实乘积。

</ExamAnswer>
<ExamExplanation>

1. **软件乘法的数学依据。** 若 $y=\sum_{i=0}^{31}b_i2^i$，$b_i\in\{0,1\}$，则 $xy=\sum_{i=0}^{31}b_i(x\ll i)$。程序可以逐位检查乘数：若最低位为 1，累加当前被乘数；随后被乘数左移、乘数逻辑右移。为得到真正的 64 位积，必须使用宽度足够的部分积及乘积寄存器，不能只用 32 位结果后再试图恢复丢失的高位。

2. **数据通路与控制器的分工。** ALU 完成加减，移位器改变操作数相对权重，寄存器保存部分积、乘数和被乘数；控制器发出多拍控制信号，选择数据源、决定是否相加、更新计数器并结束运算。考试常问“控制逻辑的作用”，应回答**微操作的时序和条件选择**，而不是笼统写“控制乘法”。

3. **性能比较的适用前提。** 软件乘法需执行多条机器指令及其取指译码过程；迭代乘法器完成一条但一般要约 $n$ 次移位、加法控制；阵列乘法器并行产生和压缩部分积，组合逻辑延迟较低、硬件成本较高。因此通常速度顺序为③快于②快于①。该结论依赖原题假设的典型设计，实际性能还取决于流水线、时钟频率、优化和乘法器结构，不能机械认为“所有阵列电路必是单周期”。

4. **完整积、截断积与类型解释。** $x=2^{31}-1=\texttt{7FFFFFFFH}$、$y=2$，精确乘积为 $2^{32}-2=4294967294$，64 位为 `00000000FFFFFFFEH`。它在 32 位无符号范围 $[0,2^{32}-1]$ 中，却在有符号范围 $[-2^{31},2^{31}-1]$ 之外。取低 32 位是 `FFFFFFFEH`；视为 `unsigned` 得 $4294967294$ 正确，视为 `int` 得 $-2$，与真实乘积不同。标准 C 的有符号乘法溢出属于未定义行为，本题讨论的是硬件截断位模式，不应把 `imul()` 在所有编译器上的返回值断言为 $-2$。

5. **两类溢出的通用判据。** 设 32×32 得到 64 位完整积 $P=P_H\,|\,P_L$。无符号时，$P_H=0$ 才不会丢失有效数值位；有符号时，$P_H$ 必须与 $P_L$ 的符号位作相同的全位扩展（$P_L$ 非负则 $P_H=\texttt{00000000H}$，$P_L$ 为负则 $P_H=\texttt{FFFFFFFFH}$）。这比只看低位符号更可靠。考场可用 $-1\times2$ 等反例记忆：其 64 位高半部全为 1，却没有有符号溢出。

6. **常见陷阱。** 乘法“产生 $2n$ 位完整积”与 C 函数“返回 $n$ 位结果”是两件事；移位加法并不意味着可以忽略部分积位宽；无符号回绕是定义明确的模运算，而有符号超范围在 C 语言中不是普遍规定的“直接截断”。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>

对两个 32 位机器数 `FFFFFFFFH` 和 `00000002H` 做乘法，结果保留低 32 位，亦能取得高 32 位完整积。

1. 视为无符号操作数时，给出 64 位积、高 32 位、低 32 位及溢出结论。
2. 视为有符号补码操作数时，重复上述计算。
3. 解释为什么不能简单地以“高 32 位不为 0”判定有符号乘法溢出。

<ExamSolution>
<ExamAnswer>

1. 无符号：积 `00000001FFFFFFFEH`，高部 `00000001H`，低部 `FFFFFFFEH`；溢出。
2. 有符号：$-1\times2=-2$，完整积 `FFFFFFFFFFFFFFFEH`，高部 `FFFFFFFFH`，低部 `FFFFFFFEH`；不溢出。

3. 整数乘法结果位模式可相同但溢出标志不同，关键在**如何解释输入**和**完整积能否符号扩展/零扩展**。

## 2025 年第 44 题

<ExamQuestion>

**70. 2025 年第 44 题**

对于上题中的计算机 M 和程序 P，假定 P 的部分机器级代码如下，其中 R0～R4 为通用寄存器，SEXT 表示按符号扩展；M 中补码除法器的逻辑结构如下图所示。

```text
// x 在 R2 中，i 在 R4 中
// 数组 d 的首地址在 R3 中
mov  R1, (R3+R4*4) // R1 <- d[i]
scov R1             // {R0,R1} <- SEXT(R1)
idiv R1, R2         // R1 <- {R0,R1} / R2
```

<img src="/img/408/past-exams-large-questions/02-计算机组成原理/assets/2025-44-figure-001.svg" alt="2025 年第 44 题补码除法器逻辑结构" />

1. 若执行 `idiv` 指令的除运算时，`d[i]=0x87654321`、`x=0xff`，则补码除法器中寄存器 R、Q 和 Y 的初始内容分别是什么（用十六进制表示）？图中哪个部件包含计数器？在补码除法器执行过程中，由 `ALUop` 所控制的 ALU 运算有哪几种？
2. 假设 `idiv` 指令执行过程中会检测并触发除法异常，则执行 `idiv` 时，哪些情况下会发生除法异常？要求给出此时 `d[i]` 和 `x` 的十六进制机器数。发生除法异常时，在异常响应过程中 CPU 需要完成哪些操作？

<ExamSolution>
<ExamAnswer>

1. 初值 $R=\texttt{FFFFFFFFH}$、$Q=\texttt{87654321H}$、$Y=\texttt{000000FFH}$；计数器位于控制逻辑 $C_n$，`ALUop` 控制 ALU 的加与减。
2. 两种异常：①除零，`x=00000000H`，`d[i]` 为任意 32 位值；②商溢出，`d[i]=80000000H` 且 `x=FFFFFFFFH`。CPU 保存断点及处理器状态、进入异常处理状态，按异常向量跳转至异常处理程序。

</ExamAnswer>
<ExamExplanation>

1. **识别指令中各寄存器含义。** `mov R1,(R3+R4*4)` 从数组读取 32 位元素；`scov R1` 将 `R1` 作为有符号补码进行**符号扩展**，得到 64 位 `{R0,R1}`。由于 `87654321H` 的最高位为 1，被除数为负，其高 32 位填满 1：`FFFFFFFF87654321H`，因此除法器高半余数/被除数寄存器 $R=\texttt{FFFFFFFFH}$、低半寄存器 $Q=\texttt{87654321H}$。除数来自 `R2`，$x=\texttt{FFH}$ 按题意是 32 位整数值 $255$，写成 8 位 `FFH` 只是省略高位的十六进制零，故 $Y=\texttt{000000FFH}$，**不是**补码 $-1$。

2. **理解恢复余数/不恢复余数类迭代除法的数据通路。** 迭代除法需要根据当前余数符号执行试减 $R-Y$ 或加回 $R+Y$，因此 `ALUop` 至少选择加法与减法；余数和商寄存器的移位属于另一组控制信号。计数器记录已经完成的迭代位数，归控制逻辑 $C_n$ 管理，而非放入加法器内部。具体时序随教材采用的补码除法算法可能不同，答本题时只需识别图示控制信号的作用。

3. **异常①：除数为零。** 如果 `x=00000000H`，商在数学上无定义，$d[i]$ 不受限制；不应只写“被除数也为零”或认为 $0/0$ 可以得到商 0。

4. **异常②：商超出 32 位补码范围。** 有符号 32 位范围 $[-2^{31},2^{31}-1]$。只有 $(-2^{31})/(-1)=2^{31}$ 超出上界，其余非零整数除数组合的商都能容纳。因此两机器数分别为 `80000000H` 和 `FFFFFFFFH`。不要将 `FFFFFFFFH` 与题目第（1）问的 `000000FFH` 混淆。

5. **异常响应的硬件与软件责任。** CPU 检测异常后，按体系结构保存必要的断点 PC 与程序状态（有的 CPU 还记录异常原因/故障地址），切换到特权处理状态，并按异常号/向量取得入口地址而跳转。异常处理程序通常进一步保存需要保护的通用寄存器现场，处理或终止故障指令，随后按异常可恢复性决定重新执行、跳过或结束进程。不能把“所有通用寄存器必由硬件自动入栈”当作通用规律。

6. **举一反三：三种“扩展”要区分。** 零扩展把高位填 0；符号扩展复制源操作数符号位；把十六进制 `FFH` 写成 32 位 `000000FFH` 是对数值 255 的正常编码。本题同时涉及符号扩展的被除数和普通正除数，最易在此失分。

</ExamExplanation>
</ExamSolution>
</ExamQuestion>
