## 2011 年第 43 题

<Question
  id="408-co-large-2011-43"
  type="essay"
  tags="来源:2011考研408, 科目:计算机组成原理, 章节:数据表示与运算, 考点:补码加减, 考点:溢出标志, 难度:综合"
>

假定在一个 **8 位字长**的计算机中运行如下 C 程序段：

```c
unsigned int x = 134;
unsigned int y = 246;
int m = x;
int n = y;
unsigned int z1 = x - y;
unsigned int z2 = x + y;
int k1 = m - n;
int k2 = m + n;
```

编译器将 8 个 8 位寄存器 R1～R8 分别分配给 `x、y、m、n、z1、z2、k1、k2`；带符号数采用补码表示。回答：

1. 执行后 R1、R5、R6 的内容各是什么？用十六进制表示。
2. `m`、`k1` 的十进制值是什么？
3. 带符号与无符号整数的加法、减法能否共用同一个加法器及辅助电路？为什么？
4. 硬件如何判断补码加减溢出？本程序哪些**带符号运算**溢出？

<Solution>

### 参考答案

| 问题 | 结论 |
| --- | --- |
| 寄存器内容 | **R1=`86H`，R5=`90H`，R6=`7CH`** |
| 补码变量真值 | **`m=-122`，`k1=-112`** |
| 硬件实现 | **可以共用加法器**；减法由对第二操作数逐位取反并令输入进位为 1 实现 |
| 补码溢出 | 仅 **`k2=m+n`** 溢出；`k1=m-n` 不溢出 |

本题须严格区分“**寄存器位串**”“**该位串的带符号解释**”与“**数学计算有无超出表示范围**”。`k2` 数学值是 $-132$，8 位截断为 `7CH`，作为 8 位补码却解释成 $+124$，因此发生溢出。

### 逐步解答

<Steps>
  <Step>

  ### 第一步：先固定表示范围

  8 位无符号数取值范围为 $[0,255]$，8 位补码有符号数取值范围为 $[-128,127]$。同一字节值 $u$ 的补码解释为

  $$
  \operatorname{signed}(u)=\begin{cases}u,&0\le u<128,\\u-256,&128\le u\le255.\end{cases}
  $$


  $134=128+6=\texttt{86H}$，$246=240+6=\texttt{F6H}$，故 R1 为 `86H`，R2 为 `F6H`。赋给有符号变量后，题设机器仍存相同的 8 位串，得到

  $$
  m=134-256=-122,\qquad n=246-256=-10.
  $$


  </Step>
  <Step>

  ### 第二步：无符号计算按模 $256$ 保存

  $$
  \begin{aligned}
  z1&=134-246=-112\equiv144\pmod{256}=\texttt{90H},\\
  z2&=134+246=380\equiv124\pmod{256}=\texttt{7CH}.
  \end{aligned}
  $$


  因此 R5 为 `90H`，R6 为 `7CH`。**无符号减法发生借位**或**无符号加法产生进位**，不影响低 8 位仍能通过加法器算出的事实。

  </Step>
  <Step>

  ### 第三步：有符号计算先求真值，再查是否越界

  $$
  k1=-122-(-10)=-112\in[-128,127],
  $$


  故 `k1` 不溢出，8 位补码是 `90H`。

  $$
  k2=-122+(-10)=-132<-128.
  $$


  保存低 8 位为 $-132\bmod256=124=\texttt{7CH}$，但把此位串当补码读取却是 $+124$：**两个负数相加得到正号**，这是典型的补码加法溢出。

  </Step>
  <Step>

  ### 第四步：解释加、减共用硬件的原因

  数字电路执行的是二进制位运算：

  $$
  A-B\equiv A+(\overline B)+1\pmod{2^8}.
  $$


  使用一个加法器即可。控制信号令加法时第二操作数原样进入加法器、输入进位 $C_{in}=0$；减法时将第二操作数逐位异或控制位、取反后进入加法器，$C_{in}=1$。差别在于**溢出标志的判定与结果的数值解释**，不在于另造一套带符号加法电路。

  </Step>
</Steps>

### 两套溢出标志不能混用

设输入符号位为 $s_A,s_B$，结果符号位为 $s_R$。以补码解释时：

| 运算 | 有符号溢出的等价判据 |
| --- | --- |
| $A+B$ | $s_A=s_B$ 且 $s_R\ne s_A$ |
| $A-B$ | $s_A\ne s_B$ 且 $s_R\ne s_A$ |

对统一的加法器，无论其用于加法还是补码减法，溢出标志均可由**符号位输入进位与输出进位异或**求得：$OF=C_{7}\oplus C_{8}$（从第 0 位开始编号）。无符号加法则关注最高进位；无符号减法关注借位（有些处理器以进位标志取反表达借位），**并不等同于** $OF$。

<Callout type="warn" title="C 语言标准与题目抽象机器的差异">

标准 C 并不要求 `int` 只有 8 位；把大于 `INT_MAX` 的无符号值转为有符号类型，其结果还涉及具体实现。标准 C 中有符号算术溢出也不是“必然按补码回绕”，而属于未定义行为。本题给定的是**8 位寄存器、补码与截断运算的考试机器模型**，上述 `k2=7CH` 指硬件截断结果，不可当作普适的 C 语言行为保证。

</Callout>

### 考场得分要点

先写出 $2^8=256$ 及表示范围，再分别完成**模运算**和**补码解释**；最后用“同号相加结果异号”检查 `k2`，不要只看十六进制值是否相同。

</Solution>
</Question>

### 原创强化题 1：同一位串、不同的进位与溢出

<Question
  id="408-co-practice-2011-43-a"
  type="essay"
  tags="来源:原创强化, 科目:计算机组成原理, 章节:数据表示与运算, 考点:加减标志, 考点:边界值"
>

某处理器的数据通路为 **16 位**，采用补码，并统一把运算结果截为 16 位。寄存器 `A=8000H`、`B=FFFFH`。分别计算 `A+B` 与 `A-B`。

1. 给出两条指令的 16 位结果位串。
2. 分别把输入视为**无符号数**与**有符号数**，判断加法的最高进位（CF）、减法的借位，以及有符号溢出（OF）。
3. 解释为什么一种运算可以出现 `CF=1, OF=1`，而另一种却可能出现“有借位但无有符号溢出”。

<Solution>

### 参考答案

| 运算 | 低 16 位 | 无符号运算 | 有符号运算 | 标志 |
| --- | --- | --- | --- | --- |
| `A+B` | `7FFFH` | $32768+65535=98303$，超出 $65535$ | $-32768+(-1)=-32769$，小于最小补码值 | **CF=1，OF=1** |
| `A-B` | `8001H` | $32768-65535=-32767$，需借位 | $-32768-(-1)=-32767$，在范围内 | **有借位，OF=0** |

### 解题过程

1. 加法中 $\texttt{8000H}+\texttt{FFFFH}=\texttt{17FFFH}$，丢弃第 17 位进位，保存 `7FFFH`；两个补码负数相加却出现正号，OF 置位。
2. 减法中 $\texttt{8000H}-\texttt{FFFFH}\equiv\texttt{8001H}\pmod{2^{16}}$。无符号计算需要借位，而补码计算 $-32767$ 能够表示，所以不置 OF。
3. CF / 借位考察**无符号范围**；OF 考察**补码有符号范围**。二者完全可以同时发生、分别发生或同时不发生。

**校验技巧：** 遇到十六进制最高位为 1，先写出两种可能的解释，例如 `FFFFH` 可是 $65535$，也可是 $-1$；不能直接凭结果最高位是否为 1 推断溢出。

</Solution>
</Question>

### 原创强化题 2：为 ALU 写一个不依赖带符号溢出的模拟器

<Question
  id="408-co-practice-2011-43-b"
  type="essay"
  tags="来源:原创预测, 科目:计算机组成原理, 章节:数据表示与运算, 考点:补码溢出, 考点:ALU实现"
>

实现函数 `void add8(unsigned a, unsigned b, unsigned *low, int *carry, int *overflow)`：题设 $a,b\in[0,255]$，分别代表两个 **8 位位模式**。函数应计算低 8 位结果、无符号加法进位标志和 8 位补码加法溢出标志。

要求不依赖 C 的带符号溢出行为；给出完整 C 代码，并解释输入 `a=0x7F,b=0x01` 和 `a=0xFF,b=0x01` 的输出。

<Solution>

### 参考答案

`7FH+01H` 得低位 `80H`、无进位、**有符号溢出**；`FFH+01H` 得低位 `00H`、有无符号进位、**无有符号溢出**。

```c
#include <stddef.h>

void add8(unsigned a, unsigned b,
          unsigned *low, int *carry, int *overflow) {
    /* 前提：0 <= a,b <= 255；输出指针均有效 */
    unsigned full = a + b;        /* 最大 510，不会使 unsigned 溢出 */
    unsigned r = full & 0xFFu;
    unsigned sa = (a >> 7) & 1u;
    unsigned sb = (b >> 7) & 1u;
    unsigned sr = (r >> 7) & 1u;

    *low = r;
    *carry = (full >= 256u);
    *overflow = (sa == sb && sr != sa);
}
```

### 为什么代码可靠？

全部算术都在足够宽的 `unsigned` 中进行；先求 `full` 再截断，能区分“保留的位模式”与“被丢弃的高位”。补码 OF 仅由三个符号位计算，而不把已经超范围的补码数学值强行放进 C 的 `signed char`。

| 输入 | `full` | `low` | `carry` | `overflow` |
| --- | ---: | --- | ---: | ---: |
| `7FH + 01H` | $128$ | `80H` | 0 | 1 |
| `FFH + 01H` | $256$ | `00H` | 1 | 0 |

<Callout type="info" title="预测变式：将加法推广为减法">

可先构造 $b'=b\oplus\texttt{FFH}$，再用加法器求 $a+b'+1$ 的低 8 位。注意该加法器的**最高进位等于“无借位”**这一常见硬件约定，而不能直接把它称为借位。OF 则改用减法符号规则：$s_A\ne s_B$ 且 $s_R\ne s_A$。

</Callout>

</Solution>
</Question>

## 2017 年第 43 题

<Question
  id="408-co-large-2017-43"
  type="essay"
  tags="来源:2017考研408, 科目:计算机组成原理, 章节:数据表示与运算, 考点:IEEE754, 考点:无符号回绕, 难度:综合"
>

已知

$$
f(n)=\sum_{i=0}^{n}2^i=2^{n+1}-1.
$$


用 C 函数计算 $f(n)$：

```c
int f1(unsigned n) {
    int sum = 1, power = 1;
    for (unsigned i = 0; i <= n - 1; i++) {
        power *= 2;
        sum += power;
    }
    return sum;
}
```

把 `f1` 中的 `int` 类型均改成 `float` 类型，得到函数 `f2`。设 `unsigned`、`int` 均为 **32 位**，`float` 采用 **IEEE 754 单精度**。回答：

1. 为什么 `n=0` 时 `f1` 死循环？若 `i`、`n` 都改成 `int` 是否仍死循环？
2. `f1(23)` 和 `f2(23)` 返回值是否相等？各自的 32 位机器数是什么（十六进制）？
3. 为什么 `f1(24)=33554431`，`f2(24)=33554432.0`？
4. 为什么题设机器上 `f1(31)=-1`？使 `f1(n)` 与数学定义精确相等时，最大的 $n$ 是多少？
5. `f2(127)` 的机器数为 `7F800000H`，表示什么？为保证 `f2` 结果**有限**，最大的 $n$ 是多少？为保证结果**精确且无舍入**，最大的 $n$ 是多少？

<Solution>

### 参考答案

| 小问 | 答案 |
| --- | --- |
| 1 | `n-1` 发生 **32 位无符号下溢**，成为 `UINT_MAX`，`i <= UINT_MAX` 永为真；`i,n` 同改有符号 `int` 后，初次检查 $0\le -1$ 为假，不执行循环 |
| 2 | 数值相同，均为 **16777215**；`f1(23)` 位模式 **`00FFFFFFH`**，`f2(23)` 位模式 **`4B7FFFFFH`** |
| 3 | 真值 $2^{25}-1$ 超出单精度的连续整数精确区间，按默认最近偶数舍入得 **$2^{25}=33554432$** |
| 4 | 补码机器低 32 位为 `FFFFFFFFH`，解释为 $-1$；精确无溢出最大 **$n=30$** |
| 5 | `7F800000H` 表示 **$+\infty$**；结果保持有限的最大 **$n=126$**，完全精确的最大 **$n=23$** |

### 逐问推导

<Steps>
  <Step>

  ### 第一问：无符号下溢为何造成无限循环

  当 `n=0`，`n-1` 的运算采用无符号语义：

  $$
  0-1\equiv2^{32}-1=4294967295\pmod{2^{32}}.
  $$


  因而条件等价于 `i <= UINT_MAX`，对任何 32 位无符号 `i` 均成立。即便 `i` 已增至 `UINT_MAX`，再执行 `i++` 也会回绕至 0，使条件依旧成立。

  将 `i,n` 一起改为有符号 `int` 后，`n-1=-1`，第一轮的 $0\le-1$ 不成立，返回初值 `sum=1`。注意这里分析的是**循环控制语义**；原函数实际反复做有符号整数乘加，发生带符号溢出后，严格 C 语言行为不再有保证。

  </Step>
  <Step>

  ### 第二问：区分整数表示与浮点编码

  $$
  f(23)=2^{24}-1=16777215=\texttt{00FFFFFFH}.
  $$


  单精度有效数字共 24 位（1 个隐藏位、23 个小数位），恰好能无误地表示连续 24 个二进制 1：

  $$
  2^{24}-1=(1.\underbrace{11\cdots11}_{23\text{ 位}})_2\times2^{23}.
  $$


  IEEE 754 单精度的符号位为 0；阶码为 $23+127=150=\texttt{96H}$；尾数字段的 23 位全为 1。拼接后为

  $$
  0\ \vert\ 10010110\ \vert\ 111\cdots111
   =\boxed{\texttt{4B7FFFFFH}}.
   $$


  两个返回值**数值相等但位模式不同**：`00FFFFFFH` 是整数编码，`4B7FFFFFH` 是浮点编码。

  </Step>
  <Step>

  ### 第三问：为何第 24 次继续累加时开始舍入

  $$
  f(24)=2^{25}-1=33554431.
  $$


  单精度在 $[2^{24},2^{25})$ 区间的相邻可表示数间距为 2，在 $[2^{25},2^{26})$ 区间的间距为 4；真实值 $2^{25}-1$ 距离 $2^{25}$ 仅为 1，因此四舍六入、遇中点取偶的舍入方式将它变成 $2^{25}=33554432$。

  计算过程也符合这一现象：前面累积结果 $2^{24}-1$ 可精确表示；再加上 `power=2^24`，数学值为 $2^{25}-1$，最终舍入一次。

  </Step>
  <Step>

  ### 第四问：32 位补码的上界

  32 位 `int` 的最大正数为 $2^{31}-1$。需要

  $$
  2^{n+1}-1\le2^{31}-1\iff n\le30.
  $$


  $n=31$ 时真值为 $2^{32}-1$，若按题设机器的低 32 位截断运算，保存 `FFFFFFFFH`，补码解释为 $-1$；真实数学结果与截断后的机器解释已经不同。

  </Step>
  <Step>

  ### 第五问：浮点范围和有效精度分别给出两个上界

  `7F800000H` 的指数域全为 1、尾数字段全为 0、符号位为 0，故表示 $+\infty$。

  对于 IEEE 754 单精度，$2^{127}$ 有限且能精确编码，$2^{128}$ 超出有限表示范围。按逐次舍入的求和过程，`f2(126)` 返回有限值 $2^{127}$；`f2(127)` 尝试形成约 $2^{128}$，得到正无穷。因此**不溢出最大 $n=126$**。

  若要求数学整数 $f(n)=2^{n+1}-1$ 完全精确，它有 $n+1$ 个连续有效二进制 1；单精度仅有 24 个有效位，所以**无舍入最大 $n=23$**。

  </Step>
</Steps>

### 一张表区分三个关键临界点

| $n$ | 数学值 / 运算现象 | 32 位 `int` | IEEE 754 `float` |
| ---: | --- | --- | --- |
| 23 | $2^{24}-1$ | 精确 | **精确** |
| 24 | $2^{25}-1$ | 精确 | **发生舍入**（到 $2^{25}$） |
| 30 | $2^{31}-1$ | **精确上界** | 有限，但不精确 |
| 31 | $2^{32}-1$ | **有符号超范围** | 有限，但不精确 |
| 126 | 结果近似 $2^{127}$ | 早已超范围 | **仍有限** |
| 127 | 结果近似 $2^{128}$ | 早已超范围 | **正无穷** |

<Callout type="warn" title="两处容易遗漏的编程语义">

1. `for (unsigned i=0; i<=n-1; i++)` 的 `n=0` 故障源于**循环边界本身**，不是 `power *= 2` 导致的；改成半开区间或提前处理零可以修复此边界。
2. 标准 C **不承诺带符号溢出后补码回绕**。`f1(31)=-1` 应理解为题干指定的特定机器行为，不能据此写出通用可移植代码。求精确 $f(n)$ 时还须避免幂运算产生超范围中间值。

</Callout>

### 核心方法

读题时分别问：**循环是否正确终止？整数真值能否装进结果类型？浮点的有效位够不够？浮点指数能否覆盖该数量级？** 四个问题的边界并不相同。

</Solution>
</Question>

### 原创强化题 1：舍入中点与非结合性

<Question
  id="408-co-practice-2017-43-a"
  type="essay"
  tags="来源:原创强化, 科目:计算机组成原理, 章节:数据表示与运算, 考点:就近偶数舍入, 考点:ULP"
>

假定 `float` 为 IEEE 754 单精度，采用默认的**就近舍入、遇中点取偶**。有如下三段代码（分别执行）：

```c
float a = 16777216.0f;
float b = (float)16777217;
float c = (float)16777219;

float s = 16777216.0f;
for (int i = 0; i < 4; ++i) s += 1.0f;
```

1. 求 `a`、`b`、`c` 的实际浮点值，并给出三者的十六进制编码。
2. 循环执行后 `s` 等于多少？为什么数学上加了 4，结果却没有增加？
3. 若只执行 `s += 4.0f` 一次，结果是多少？说明两种求和次序表现不同的根本原因。

<Solution>

### 参考答案

| 变量 | 实际值 | IEEE 754 单精度编码 |
| --- | ---: | --- |
| `a` | $16777216$ | `4B800000H` |
| `b` | $16777216$ | `4B800000H` |
| `c` | $16777220$ | `4B800002H` |

循环逐次加 `1.0f` 后 **`s` 仍是 $16777216$**；一次加 `4.0f` 后则为 **$16777220$**。

### 推导与示意

1. 在 $[2^{24},2^{25})$，浮点间距 ULP 为 $2^{24-23}=2$，所以可表示值依次为 $2^{24},2^{24}+2,2^{24}+4,\ldots$。
2. 整数 $2^{24}+1$ 恰在 $2^{24}$ 和 $2^{24}+2$ 中间；就近偶数把它舍到尾数最低位为偶的 $2^{24}$。
3. 整数 $2^{24}+3$ 恰在 $2^{24}+2$ 和 $2^{24}+4$ 中间；后者尾数最低位为偶，故舍到 $2^{24}+4$。
4. 每次单独计算 `s + 1.0f`，都得到**同一个中点** $2^{24}+1$，每次又舍回 $2^{24}$，所以做四次结果仍不变；但直接加 $4$ 不需要舍掉低位。

**核心考点：** 浮点加法的每一步都有独立的舍入，因而“先算和再舍入”和“每次加后立即舍入”可能不同。不能仅用实数代数的结合律推断有限精度计算结果。

</Solution>

### 原创强化题 2：修复 $f(n)$ 的边界和类型陷阱

<Question
  id="408-co-practice-2017-43-b"
  type="essay"
  tags="来源:原创预测, 科目:计算机组成原理, 章节:数据表示与运算, 考点:定宽整数, 考点:移位边界"
>

设计 C 函数 `int calcF(unsigned n, uint64_t *out)`，按数学定义计算

$$
f(n)=2^{n+1}-1.
$$


规定 `out` 非空。要求：

1. 当 $0\le n\le63$ 时返回 `1` 并把**精确值**写入 `*out`；$n\ge64$ 时返回 `0`，且不修改 `*out`。
2. 不准调用 `pow`，不能执行 `1ULL << 64` 一类移位位数越界的操作。
3. 说明 `n=0,62,63,64` 时的返回行为和原因。

<Solution>

### 参考答案

```c
#include <stdint.h>

int calcF(unsigned n, uint64_t *out) {
    if (out == NULL || n >= 64u) return 0;
    uint64_t s = UINT64_C(0);
    for (unsigned i = 0; i <= n; ++i)
        s = (s << 1) | UINT64_C(1);
    *out = s;
    return 1;
}
```

结果：$n=0$ 写入 $1$；$n=62$ 写入 $2^{63}-1$；$n=63$ 写入 `UINT64_MAX`，即 $2^{64}-1$；$n=64$ 返回失败并保持输出不变。

### 为何这种写法安全

循环在执行第 $t$ 次后，`s` 恰好由 $t$ 个二进制 1 组成，即 $s=2^t-1$。从 $t=0$ 的全 0 开始，归纳有

$$
2(2^t-1)+1=2^{t+1}-1.
$$


若 $n\le63$，只需至多 64 次迭代，最终恰有 64 个二进制 1，完整适配 `uint64_t`。与 `1ULL << (n+1)` 不同，上面代码不会在 `n=63` 时移位 64 位：每一次只左移 **1 位**，所有移位均在 64 位无符号类型中有效。输入边界检查位于循环之前，确保不会把 `unsigned` 循环变量推到回绕。

<Callout type="info" title="两种上界不要记混">

- 对 32 位 `int`，$f(n)$ 的无溢出上界是 $n=30$。
- 对 64 位 `uint64_t`，允许把最高位作为数值位使用，故上界是 $n=63$。

</Callout>

</Solution>
</Question>

## 2020 年第 43 题

<Question
  id="408-co-large-2020-43"
  type="essay"
  tags="来源:2020考研408, 科目:计算机组成原理, 章节:数据表示与运算, 考点:乘法器, 考点:乘积溢出, 难度:综合"
>

有两个实现 $x\times y$ 的 C 语言函数：

```c
unsigned umul(unsigned x, unsigned y) { return x * y; }
int imul(int x, int y) { return x * y; }
```

假设计算机 M 的 ALU 只能完成加减法与逻辑运算。回答：

1. 若指令系统**没有乘法指令**，但有加、减和移位指令，为什么仍能实现乘法？
2. 若有乘法指令并采用 ALU、移位器、寄存器及控制逻辑实现，控制逻辑具体负责什么？
3. 比较三种情形下 `umul()` 的执行速度：①无乘法指令；②用 ALU、移位器实现乘法指令；③用阵列乘法器实现乘法指令。通常哪种最慢、哪种最快？
4. 对于 $n=32$、$x=2^{31}-1$、$y=2$，求**带符号与无符号**乘法的完整 64 位乘积（十六进制），判断 `umul()`、`imul()` 是否出现 32 位结果溢出，并给出从完整乘积判断无符号乘法溢出的方法。

<Solution>

### 参考答案

1. **可实现。** 通过乘数逐位检测、条件加法和移位，将乘法拆成有限次 ALU 能完成的运算。
2. **控制逻辑**负责组织微操作：初始化寄存器、逐位测试乘数、选择是否加上部分积、控制移位和寄存器写回、判断是否结束。
3. 按题目的典型硬件实现模型，**①通常最慢，③通常最快，②居中**。软件模拟有多条指令的取指译码开销；迭代乘法器需多拍；阵列乘法器并行形成、归并部分积。
4. 数学积为

   $$
   \boxed{(2^{31}-1)\times2=2^{32}-2=4294967294
   =\texttt{00000000FFFFFFFEH}\ (64\text{ 位})}.
   $$


   两种解释下，因本题输入均为正且数值相同，**完整 64 位积相同**。`umul()` 的数学结果在 32 位 `unsigned` 范围内，**不溢出**；`imul()` 的数学结果超过 `INT_MAX`，**发生有符号超范围**。若以硬件低 32 位截断，二者低位都是 `FFFFFFFEH`，但 `int` 解读为 $-2$。对于无符号完整积，**高 32 位全为 0 才没有截断溢出**。

### 解题过程

<Steps>
  <Step>

  ### 第一步：将乘法还原为移位和加法

  任何 $w$ 位无符号乘数都可表示为

  $$
  y=\sum_{i=0}^{w-1}b_i2^i,\quad b_i\in\{0,1\}.
  $$


  因而

  $$
  xy=\sum_{i=0}^{w-1}b_i(x\ll i).
  $$


  每轮查看当前乘数的最低位：为 1 则把当前被乘数加进部分积；为 0 则不加；随后被乘数左移一位，乘数右移一位。这仅需要测试位、加法、移位、循环控制。**计算完整 $2w$ 位乘积时，部分积寄存器必须足够宽**，不能先在 $w$ 位里丢掉高位再试图恢复。

  </Step>
  <Step>

  ### 第二步：区分数据通路与控制单元

  | 部件 | 负责的工作 |
  | --- | --- |
  | ALU | 对部分积与被乘数进行加法，必要时用于计数等运算 |
  | 移位器 | 移动被乘数或乘数，使下一位对应更高的权值 |
  | 寄存器 | 保存乘数、被乘数、部分积和轮数 |
  | 控制逻辑 | 根据乘数位和状态，产生多拍的写使能、选择、移位和结束信号 |

  控制器并不是另一种“计算乘积的运算器”，它负责确保正确的运算在正确的时刻发生。

  </Step>
  <Step>

  ### 第三步：比较三种实现的开销

  - **① 无乘法指令：** 编译器生成若干条移位、测试、加法和分支指令，并承担取指、译码等额外开销。
  - **② 迭代硬件乘法器：** 一条机器乘法指令在内部经历多个时钟节拍，循环调用 ALU 和移位器。
  - **③ 阵列乘法器：** 硬件同时产生多个部分积，经专用组合逻辑并行压缩，典型延迟更低，但面积、布线和功耗代价较高。

  这一速度排序属于**原题典型设计假设**。实际处理器是否流水化、单周期、多周期及其时钟频率会影响真实延迟，不能仅由“阵列”二字绝对判定。

  </Step>
  <Step>

  ### 第四步：分别检验两种整数语义

  $$
  x=2^{31}-1=\texttt{7FFFFFFFH},\qquad y=2=\texttt{00000002H}.
  $$


  64 位积为

  $$
  P=\texttt{00000000}\ \vert\ \texttt{FFFFFFFE}.
  $$


  对 32 位无符号整数，最大值是 $2^{32}-1$，而 $P=2^{32}-2$，故仍可正确返回 `FFFFFFFEH`，无需丢失有效高位。

  对 32 位有符号整数，最大值是 $2^{31}-1$，$P$ 远超该值，因此不能用 32 位 `int` 表达。截取低半部会形成最高位为 1 的 `FFFFFFFEH`，其补码解释为 $-2$，**并不等于真正的乘积**。

  </Step>
</Steps>

### 判断完整积是否能收缩到 32 位

设 64 位完整乘积 $P=P_H\Vert P_L$，$P_H$、$P_L$ 各为 32 位。

| 解释方式 | 不溢出的充要条件 | 本题 |
| --- | --- | --- |
| 无符号 32 位 | $P_H=\texttt{00000000H}$ | 满足，无溢出 |
| 有符号 32 位补码 | $P_H$ 必须是 $P_L$ 符号位的完整符号扩展 | 不满足：$P_L$ 最高位为 1，但 $P_H$ 是全 0 |

例如，完整积 $-2$ 的 64 位补码为 `FFFFFFFFFFFFFFFEH`，虽然其高 32 位全为 1，却能正确表示为 32 位补码 `FFFFFFFEH`；因此**“高半部非零”不是有符号乘法的溢出判据**。

<Callout type="warn" title="C 语言有符号乘法与硬件截断要分开">

在 ISO C 中，`int` 乘法结果超出表示范围属于未定义行为。题目中 `imul()` 的结论应表述为“**真实乘积无法用 32 位有符号数表示，故发生有符号溢出**”；`-2` 仅是某些补码机器直接保留乘积低 32 位时的位模式解释，不是 C 语言保证返回的值。无符号 `unsigned` 运算则按模 $2^{32}$ 定义。

</Callout>

### 易错定位

别把“完成一条乘法指令”和“通过多少个内部时钟节拍”混为一谈；更不要把 64 位**完整乘积**误写成 32 位的有符号解释。先写完整积，再比较对应类型的可表示范围，是最稳定的得分路径。

</Solution>
</Question>

两组 32 位原始位模式分别是：

3. 为什么仅查看低 32 位，无法区分两种溢出情况？

<Solution>

### 参考答案

| 组别与解释 | 64 位完整积 | 低 32 位 | 32 位溢出？ |
| --- | --- | --- | --- |
| ① 无符号：$(2^{32}-1)\times2$ | `00000001FFFFFFFEH` | `FFFFFFFEH` | **是**：高半部为 `00000001H` |

| ② 无符号：$(2^{31}-1)\times2$ | `00000000FFFFFFFEH` | `FFFFFFFEH` | **否**：高半部为 0 |

### 原创强化题 2：不用乘法指令实现 32×32→64 位乘法

<Question
  id="408-co-practice-2020-43-b"
  type="essay"
  tags="来源:原创预测, 科目:计算机组成原理, 章节:数据表示与运算, 考点:移位加法, 考点:宽位乘积"
>

处理器有 64 位寄存器和加法、位移指令，却没有乘法指令。设计函数

```c
uint64_t mul32(uint32_t x, uint32_t y);
```

求两个 32 位**无符号数**的准确 64 位乘积。

1. 实现时不得使用 `*` 运算符，且不得丢失高 32 位。
2. 给出输入 `x=FFFFFFFFH`、`y=00000002H` 时的最终积、高低 32 位及 32 位无符号溢出标志。
3. 用位数 $w$ 表述迭代移位加法的轮数、复杂度，并解释为什么必须先把被乘数提升到更宽位数再移位。

<Solution>

### 参考答案

```c
#include <stdint.h>

uint64_t mul32(uint32_t x, uint32_t y) {
    uint64_t cur = (uint64_t)x;   /* 在移位前扩展至 64 位 */
    uint64_t result = UINT64_C(0);
    uint32_t bits = y;

    while (bits != 0u) {
        if ((bits & 1u) != 0u)
            result += cur;
        bits >>= 1;
        if (bits != 0u)
            cur <<= 1;
    }
    return result;
}

/* 调用方可这样判断 32 位无符号结果是否超范围：
   uint64_t full = mul32(x, y);
   uint32_t low = (uint32_t)full;
   int overflow = (full >> 32) != 0u;
*/
```

对 `FFFFFFFFH × 2`：

$$
P=\texttt{00000001FFFFFFFEH},
$$


所以高 32 位为 `00000001H`、低 32 位为 `FFFFFFFEH`，`overflow=1`。

### 为什么算法能在 64 位中保持精确？

写出 $y=\sum b_i2^i$。处理乘数的第 $i$ 个二进制位之前：

- `cur` 等于原始 $x\cdot2^i$；
- `result` 已累加所有先前满足 $b_j=1$ 的部分积；
- `bits` 的最低位就是当前待判定的 $b_i$。

若该位为 1，累加本轮 `cur`；否则忽略。随后乘数右移一位，被乘数必要时左移一位，归纳不变量始终成立。乘数处理完毕，`result` 就是完整的 $xy$。

由于

$$
0\le xy\le(2^{32}-1)^2<2^{64},
$$


64 位无符号数足够保存全部精确积。代码在移位之前已经将 `x` 转换成 `uint64_t`；若先执行 `x << i` 再转换，则移位发生在**32 位表达式**里，丢掉的高位无法挽救。

### 复杂度分析

最多检查 $w=32$ 位乘数，每位执行常数次**固定宽度机器字操作**，因此以 $w$ 为变量的机器字操作次数是 $O(w)$、辅助机器字数是 $O(1)$；如果按逐位门级加法成本计算，一次最高 $2w$ 位加法有 $O(w)$ 位操作，整体位复杂度可记为 $O(w^2)$。对题给的 32 位输入，循环最多 32 轮。

**推广边界：** 这份实现处理无符号数。直接把负的 `int32_t` 强转为 `uint32_t` 再按无符号规则相乘，得到的是另一种数学运算；若题目要求带符号完整积，应先明确二补码有符号扩展或使用足够宽的有符号数求积。

</Solution>
</Question>

### 解题过程

<Steps>
  <Step>

  **步骤一：按指令执行顺序还原寄存器，而不是直接把字面数填到除法器。**

  `mov` 从 `d[i]` 读取一个 32 位整数到 R1，位模式为 `87654321H`。该数最高位为 1，按补码解释为负数。因此 `scov` 是**符号扩展**：

  $$
  \{R0,R1\}=\operatorname{SEXT}_{64}(\texttt{87654321H})=\texttt{FFFFFFFF87654321H}.

  图中 R 保存扩展结果的高 32 位，Q 保存低 32 位。R2 中的 $x=\texttt{0xFF}$ 是 $255$；以 32 位补码正数写出就是 `000000FFH`。所以初始化表为：

  | 硬件寄存器 | 功能 | 32 位初值 |
  | --- | --- | --- |
  | R | 被除数高半部、迭代余数相关寄存器 | `FFFFFFFFH` |
  | Q | 被除数低半部、迭代商相关寄存器 | `87654321H` |
  | Y | 除数 | `000000FFH` |

  **辨错：**若错误地把 `FFH` 当成“8 位有符号数 $-1$”，会把 Y 错写为 `FFFFFFFFH`。本题以 32 位机器数保存 `x`，必须检查**第 31 位**而不是十六进制简写的最高位。

  </Step>
  <Step>

  **步骤二：分清运算器、移位单元与微操作控制。**

  补码除法通常按位形成商并更新部分余数。试减除数可通过 `R - Y` 完成；需要恢复或按算法规则调整部分余数时可通过 `R + Y` 完成。因此 ALU 的控制选择为加/减，而非要求 ALU 单独具备一个“除法”运算功能。

  计数器负责记录迭代位数或剩余轮次，其读写、移位、写使能及结束判断由控制逻辑 $C_n$ 协调。图中的计数器**不应误认为 R、Q、Y 或 ALU 内部的算术结果寄存器**。

  </Step>
  <Step>

  **步骤三：从数学商的可表示范围确定所有异常边界。**

  32 位补码能表示的整数范围为

  $$
  -2^{31}\le q\le2^{31}-1.
  $$


  当 `x==0` 时除法无定义，直接异常。若 `x!=0`，考察商按**向零截断**得到的整数是否在此范围内。极值不对称：最小负数为 $-2^{31}$，其相反数 $2^{31}$ 无法表示。于是

  $$
  \frac{-2^{31}}{-1}=2^{31}>2^{31}-1
  $$


  是唯一的非零除数商溢出情况：

  | 类型 | `d[i]` | `x` | 原因 |
  | --- | --- | --- | --- |
  | 除零 | 任意 | `00000000H` | 除数为零 |
  | 商溢出 | `80000000H` | `FFFFFFFFH` | $(-2^{31})/(-1)=2^{31}$ |

  对照：`80000000H / 00000001H` 的商为 $-2^{31}$，正好是下界，**不溢出**；`80000000H / FFFFFFFFH` 的商为 $+2^{31}$，超出上界，**必须报异常**。

  </Step>
  <Step>

  **步骤四：沿异常控制流说明 CPU 与处理程序的分工。**

  异常属于执行指令时检测到的**同步事件**。处理器通常需要：

  1. 阻止错误商作为正常结果提交；保存或提供能定位故障 `idiv` 的 PC、必要程序状态及异常原因。
  2. 按体系结构规定切换特权级或异常模式，并从异常向量表/专用异常入口获得处理程序地址。
  3. 跳转到异常处理程序。处理程序视需要再保存通用寄存器现场，报告除零/溢出、终止任务，或在可支持的情况下修复与重试。

  对**精确异常**，故障指令之前的指令效果可见，而之后的指令不应产生不该有的体系结构副作用。具体 PC 保存的是故障指令地址还是规定的异常返回地址，依赖 ISA，不能自行规定“一律是下一条指令”。

  </Step>
</Steps>

<Callout type="warn" title="三个经常混在一起的概念">

- `87654321H` 是 32 位**负数**，要做符号扩展；`000000FFH` 是 32 位**正数**，不可因简写为 `FFH` 而当作 $-1$。
- **符号扩展**是复制符号位，**取反加一**才是求补码负值；两者不是同一操作。
- 补码除法的商可能超范围，但余数有正负并不意味着溢出；应判断除零与**商的范围**。

</Callout>

### 原创强化题 1｜符号扩展、向零截断与余数符号

<Question
  id="408-co-large-2025-44-ext1"
  type="essay"
  tags="来源:原创强化训练, 科目:计算机组成原理, 章节:数据表示与运算, 考点:补码除法, 考点:余数规则, 难度:拔高"
>

仍采用原题的 32 位有符号补码除法器：`scov` 把 32 位 `d[i]` 符号扩展到 `{R0,R1}`，`idiv` 对商**向零截断**，余数满足 $a=bq+r$。

现有 `d[i]=80000001H`、`x=00000002H`。

1. 写出 64 位 `{R0,R1}` 及 R、Q、Y 三个初值。
2. 计算**数学商、数学余数**，写出商与余数的 32 位补码机器数；检验恒等式 $a=bq+r$。
3. 是否发生商溢出？若错误地使用数学上的**向下取整**代替 C 整数除法的向零截断，会得到什么商和余数？

<Solution>

### 参考答案

1. `{R0,R1}=FFFFFFFF80000001H`；`R=FFFFFFFFH`、`Q=80000001H`、`Y=00000002H`。
2. 被除数 $a=-2147483647$，除数 $b=2$；商 $q=-1073741823=\texttt{C0000001H}$，余数 $r=-1=\texttt{FFFFFFFFH}$。
3. **无异常。** 向下取整会错得商 $-1073741824$（`C0000000H`）及余数 $+1$，不符合 C 的有符号整数除法约定（余数非零时与被除数同号）。

### 详细推导

<Steps>
  <Step>

  32 位 `80000001H` 的最高位为 1，真值是

  $$
  2^{31}+1-2^{32}=-2^{31}+1=-2147483647.
  $$


  所以符号扩展后高半部填满 1；除数 `00000002H` 是正数 $+2$。

  </Step>
  <Step>

  先求绝对值：$2147483647=2\times1073741823+1$。商向零截断：

  $$
  q=-1073741823,\qquad r=a-bq=-2147483647-2(-1073741823)=-1.
  $$


  检查 $2(-1073741823)+(-1)=-2147483647$；且 $|r|<|b|$。补码机器数由模 $2^{32}$ 编码得到：

  $$
  2^{32}-1073741823=\texttt{C0000001H},\qquad
  2^{32}-1=\texttt{FFFFFFFFH}.
  $$


  </Step>
  <Step>

  如果误用向下取整，$-2147483647/2$ 会取 $-1073741824$，以 $a=bq+r$ 反算余数得 $+1$。这一对在数学上仍满足恒等式，但**不满足题设向零截断的指令语义**。

  </Step>
</Steps>

**考试易错点：**初始寄存器 R 保存符号扩展所得的高半字，并不保证数值等于最终余数。本组初值 `FFFFFFFFH` 与最终余数 `FFFFFFFFH` 只是恰好相同，不能用来替代计算。

</Solution>

### 原创强化题 2｜精确异常与边界值测试矩阵

<Question
  id="408-co-large-2025-44-ext2"
  type="essay"
  tags="来源:原创预测题, 科目:计算机组成原理, 章节:数据表示与运算, 考点:除法异常, 考点:精确异常, 难度:综合"
>

某 32 位处理器的 `IDIV32` 以两个有符号补码整数相除，商向零截断；除零和商溢出均产生**可精确定位故障指令**的同步异常。

逐组判定是否异常；非异常时写出商（十六进制），并填写异常类型：

| 组别 | 被除数 `a` | 除数 `b` |
| --- | --- | --- |
| A | `80000000H` | `FFFFFFFFH` |
| B | `80000000H` | `00000001H` |
| C | `00000000H` | `00000000H` |
| D | `7FFFFFFFH` | `FFFFFFFFH` |

进一步回答：若执行顺序为 `I1; IDIV32; I3`，当 `IDIV32` 触发精确异常时，三条指令的可见状态应满足什么要求？恢复执行时为什么不能无条件把保存的 PC 加一？

<Solution>

### 参考答案

| 组别 | 数学结果 | 结论 | 32 位商 |
| --- | --- | --- | --- |
| A | $(-2^{31})/(-1)=2^{31}$ | 商溢出异常 | 无合法商 |
| B | $(-2^{31})/1=-2^{31}$ | 正常 | `80000000H` |
| C | $0/0$ 无定义 | 除零异常 | 无合法商 |
| D | $(2^{31}-1)/(-1)=-(2^{31}-1)$ | 正常 | `80000001H` |

精确异常下 `I1` 的已完成效果可见，故障 `IDIV32` 的错误商**不得当作成功执行结果提交**，`I3` 不能产生越过故障点的体系结构副作用。处理器必须按架构约定报告故障指令位置或可恢复位置；是否重试、跳过或终止由异常类型与处理程序决定，不能无条件执行 `PC++`。

### 判断步骤

- **先判除数零：**C 组直接异常；“零除零”不是可返回零的特例。
- **再判唯一的商溢出边界：**二补码的负数端多一个绝对值 $2^{31}$，只有 `INT_MIN / -1` 溢出，即 A 组。
- **再写正常商：**B 组等于二补码最小值；D 组为 $-2147483647$，机器数为 `80000001H`。

### 为什么 PC 需要结合异常语义？

除法错误通常不能靠“重做相同操作”自动解决；操作系统可能向用户进程报告算术错误或终止进程。即便一种 ISA 支持重试故障指令，**指令长度也不一定为一个固定地址单位**，而且不同异常保存的可能是故障 PC 或约定的恢复 PC。处理程序必须按体系结构定义解释保存的地址，不能把一般同步异常简单处理为“PC 加一再执行”。

<Callout type="info" title="考点串联：精确异常 ≠ 普通函数调用">

普通函数调用按程序指定的目标跳转；同步异常由硬件发现执行故障并依据特权机制进入处理程序。保存的处理器状态和异常原因用于保证能解释故障、决定是否可恢复。

</Callout>

</Solution>
