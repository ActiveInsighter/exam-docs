## 先把 408 大题看成四条主线

很多大题看似每年换一种问法，实际上只是把**同一套对象与规则**换了参数。做题时先找到主线，再代入数字或写代码。

| 科目 | 题目中的主角 | 真正要做的事 | 一眼识别的线索 |
| --- | --- | --- | --- |
| 数据结构 | 结点、指针、集合、图 | 找到并维护一个**不变量**，保证算法始终正确 | 链表、树、查找、最短路、排序、复杂度 |
| 计算机组成原理 | 地址、位模式、寄存器、数据通路、时钟 | 追踪**数据在哪里，经过哪个硬件，何时可用** | Cache、TLB、指令、ALU、流水线、访存 |
| 操作系统 | 进程状态、内存页、共享资源、磁盘块 | 推演**谁拥有资源、谁等待、哪个事件改变状态** | PV、死锁、调度、缺页、文件索引、磁盘调度 |
| 计算机网络 | 比特、帧、分组、TCP 字节流、路由表 | 按协议层追踪**谁把什么发给谁、经历多少时间** | IP、子网、路由聚合、TCP、DNS、HTTP、RTT |

## 组成原理和操作系统为什么总像混在一起？

把一次 CPU 读内存的过程串起来，就能理解很多分散考点并不是新的知识：

```text
CPU 执行 load 指令
  ↓ 指令要求读取某个虚拟地址
拆分虚拟页号与页内偏移
  ↓
TLB 命中？ ── 否 → 查页表
  ↓                  ↓
获取页框号       页面在内存？ ── 否 → 缺页异常 → OS 调页 → 重启指令
  ↓                  ↓ 是
拼出物理地址 ←────────┘
  ↓
Cache 命中？ ── 否 → 从主存装入对应 Cache 块
  ↓
把数据送回 CPU 寄存器 / ALU
  ↓
有数据依赖？流水线能否转发？是否必须暂停？
```

其中有三个必须分别理解的失败事件：

| 事件 | 哪一层没找到 | 接下来做什么 |
| --- | --- | --- |
| TLB miss | 快速地址转换缓存里没找到页表项 | 查页表，**不一定**缺页 |
| Page fault（缺页） | 页表指示所需虚拟页不在主存 | 进入操作系统异常处理，必要时磁盘换入页面 |
| Cache miss | 处理器缓存里没有对应主存块 | 从更低一级缓存或主存获取数据，**不代表**缺页 |

**带数字走一遍：** 假设页大小 4 KiB，虚拟地址为 `0x1234`，查页表后得到物理页框号 `0xA`。虚拟页号是 `0x1`，页内偏移是 `0x234`，因此物理地址是 `0xA234`。若 Cache 块长 64 B，块内偏移就是 `0x34`；若直接映射 Cache 有 8 行，则主存块号为 `0x288`、Cache 行号为 `0`、Tag 为 `0x51`。这一连串结果都来自同一次地址拆分与映射，不需要背五套互不相干的口诀。

## 写综合大题时，先列四个检查项

- **对象和单位**：这是虚拟地址还是物理地址？字还是字节？bit 还是 B？时间是一个周期还是一次访存？
- **前置条件**：需要先得到什么才能进入下一步？例如先申请空位再写缓冲区、先翻译地址再查询物理 Cache。
- **状态与顺序**：访存、TLB、Cache、页框、寄存器、TCP 窗口等状态会随着每次操作改变，不能把每一步当作独立小题。
- **结果的验证**：用反例、边界值、容量约束、守恒量或第二种公式检查结果，而不仅是计算出一个数。
