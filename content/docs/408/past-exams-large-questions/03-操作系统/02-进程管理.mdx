# 第 2 章 进程管理

## 2.2 CPU 调度与上下文切换

<Question id="408-591a95-036" type="essay" tags="来源:2016考研408">

某进程调度程序采用基于优先数 (priority) 的调度策略, 即选择优先数最小的进程运行, 进程创建时由用户指定一个 nice 作为静态优先数。为了动态调整优先数,引入运行时间 cpuTime 和等待时间 waitTime,初值均为 0。进程处于执行态时, cpuTime 定时加 1,且 waitTime 置 0; 进程处于就绪态时, cpuTime 置 0, waitTime 定时加 1。请回答下列问题:
   (1) 若调度程序只将 nice 的值作为进程的优先数, 即 priority = nice, 则可能会出现饥饿现象, 为什么?
   (2) 使用 nice、 cpuTime 和 waitTime 设计一种动态优先数计算方法, 以避免产生饥饿现象, 并说明 waitTime 的作用。

<Solution>

**【解析】**

(1) 根据第一问的描述，如果调度程序只将 nice 值作为进程的优先数，则本调度算法为静态优先级调度算法。如果有进程的优先级过低，而就绪队列中不断有高优先级进程进入，则该低优先级进程会一直无法使用处理机，从而发生饥饿现象。

(2) 解决饥饿现象的手段之一，就是引入动态优先数，通过动态调整进程的优先数来使得每个进程都可以在有限时间内使用处理机。当设计动态优先数时，不难想到可以类比高响应比优先调度算法，需保证设计出来的动态优先数有三个特点：两个进程如果其他指标均相同，由 nice 决定优先数；低优先数进程通过长时间等待优先数会减小；进程使用处理机运行后优先数会变大。最终设计出的计算公式为：

$$
\mathrm{priority}=(\beta\times\mathrm{cpuTime})\div (1+\mathrm{nice}+\alpha\times\mathrm{waitTime})
$$

其中，常数 $\beta>0$，常数 $\alpha>0$。公式中的除数需要加 1，从而避免除数为 0。$\alpha$ 和 $\beta$ 用于调整 waitTime 和 cpuTime 的影响程度。waitTime 用来提高那些长时间等待处理器资源的进程的优先级，防止其饥饿。

{/* 原书公式按原样保留。由于就绪态 cpuTime=0，此式在分母非零时使所有就绪进程的优先数均为 0，不能体现 nice、waitTime 的作用，且原题未限定 nice 非负；不应直接视为可靠的防饥饿公式。 */}

**【提示】** 答案不唯一，体现“cpuTime 使优先数上升、waitTime 使优先数下降”即可。但注意需要设计为优先数越小进程越容易被调度。

> **【点评】** 创新题。考查优先级调度中的饥饿问题。第（2）问答案不唯一。其实，本题考点，只是基于进程调度的背景，即使没学过操作系统这门课，根据题意也能解题。

</Solution>

</Question>

<Question id="408-591a95-037" type="essay" tags="来源:2023考研408">

(8 分) 进程 P 通过执行系统调用从键盘接收一个字符的输入。已知此过程中与进程 P 相关的操作包括: ①将进程 P 插入就绪队列；②将进程 P 插入阻塞队列；③将字符从键盘控制器读入系统缓冲区；④启动键盘中断处理程序；⑤进程 P 从系统调用返回；⑥用户在键盘上输入字符。 以上编号① ∼ ⑥仅用于标记操作, 与操作的先后顺序无关。请回答下列问题。
   (1) 按照正确的操作顺序, 操作①的前一个和后一个操作分别是上述操作中的哪一个？操作⑥的后一个操作是上述操作中的哪一个?
   (2) 在上述哪个操作之后, CPU 一定从进程 P 切换到其他进程？在上述哪个操作之后 CPU 调度程序才能选中进程 P 执行？
   (3) 完成上述哪个操作的代码属于键盘驱动程序？
   (4) 键盘中断处理程序执行时, 进程 P 处于什么状态？ CPU 处于内核态还是用户态？

<Solution>

**【解析】**

（1）正确的步骤为②，⑥，④，③，①，⑤。当进程 P 通过系统调用请求从键盘读入一个字符，进程 P 首先会被阻塞，等待用户输入字符，用户输入字符后，键盘会发送中断请求给 CPU，CPU 调用相应的中断处理程序，把字符从键盘控制器读入系统缓冲区，字符读到系统缓冲区后，进程 P 因为 IO 请求完成了，会被调入就绪队列，之后系统调用完成，进行返回。所以①的前一个步骤为③，①的后一个步骤为⑤，⑥的后面是步骤④。

（2）步骤 2 一定会使 CPU 从 P 进程切换到其他进程，因为 P 进程阻塞了，这时候 CPU 会去执行就绪队列中的任务。步骤 1 之后可以调度进程 P，因为 P 在就绪队列中，可以进行调度了。

（3）磁盘驱动程序是由 CPU 执行的，负责把字符从键盘控制器读入系统缓冲区，所以步骤 3 是由键盘驱动程序完成的。

{/* 原书将“键盘驱动程序”误写为“磁盘驱动程序”，按原文保留。 */}

（4）中断处理时候，进程 P 是阻塞状态，CPU 因为需要访问内存和硬件，所以处于内核态。

**【点评】** 常规题。考查常见的基本概念，平平无奇，考查不应该在此题上丢分。

</Solution>

</Question>

## 2.3 进程同步

<Question id="408-591a95-048" number={3} type="essay" tags="来源:2009考研408">

三个进程 P1、 P2、 P3 互斥使用一个包含 N ($N>0$) 个单元的缓冲区。 P1 每次用 produce（ ） 生成一个正整数并用 put（ ） 送入缓冲区某一空单元中;P2 每次用 getodd（ ） 从该缓冲区中取出一个奇数并用 countodd（ ） 统计奇数个数; P3 每次用 geteven（ ） 从该缓冲区中取出一个偶数并用 counteven（ ） 统计偶数个数。请用信号量机制实现这三个进程的同步与互斥活动, 并说明所定义信号量的含义 (要求用伪代码描述)。

<Solution>

**【解析】** 定义同步信号量 odd，控制 $P_1$ 与 $P_2$ 之间奇数取用的同步；定义同步信号量 even，控制 $P_1$ 与 $P_3$ 之间偶数取用的同步；定义同步信号量 num_empty，表示空余位置数，有空余位置才可放入正整数；定义互斥信号量 num_mutex，实现对临界区的互斥访问，程序具体实现如下：

```c
semaphore odd = 0;//定义奇数取用的同步信号量
semaphore even = 0;//定义偶数取用的同步信号量
semaphore num_empty = N;//定义同步信号量，表示空余位置数
semaphore num_mutex = 1;//定义对临界区访问的互斥信号量
CoBegin{
    P1(){
        while(1){
            x = produce(); //生成一个正整数
            P(num_empty); //（同步）申请一个空余位置，empty自减
            P(num_mutex); //（互斥）对临界区执行P操作，防止他人进入
            Put(); //将生成的正整数放入缓冲区空单元
            V(num_mutex); //（互斥）对临界区执行V操作，允许他人进入
            if(x % 2 == 0)
                V(even); //（同步）如果是偶数，even自增，以便等待中的P3使用
            else
                V(odd); //（同步）如果是奇数，odd自增，以便等待中的P2使用
        }
    }
    P2( ){
        while(1){
            P(odd);//（同步）P1产生奇数后，P2才可取用
            P(num_mutex); //（互斥）对临界区执行P操作，防止他人进入
            getodd(); //取出一个奇数
            V(num_mutex); //（互斥）对临界区执行V操作，允许他人进入
            V(num_empty); //（同步）新增一个空余位置，以便等待中的P1使用
            countodd(); //统计奇数个数
        }
    }
    P3(){
        while(1){
            P(even); //（同步）P1产生偶数后，P3才可取用
            P(num_mutex); //（互斥）对临界区执行P操作，防止他人进入
            geteven(); //取出一个偶数
            V(num_mutex); //（互斥）对临界区执行V操作，允许他人进入
            V(num_empty); //（同步）新增一个空余位置，以便等待中的P1使用
            counteven(); //统计偶数个数
        }
    }
}CoEnd
```

**【点评】** 常规题。本题是一道典型的“生产者—消费者”的 PV 操作题。在经典例题基础上，经过了改编，考查灵活运用。

</Solution>

</Question>

<Question id="408-591a95-049" type="essay" tags="来源:2011考研408">

某银行提供 1 个服务窗口和 10 个供顾客等待的座位。顾客到达银行时,若有空座位,则到取号机上领取一个号, 等待叫号。取号机每次仅允许一位顾客使用。当营业员空闲时, 通过叫号选取一位顾客, 并为其服务。顾客和营业员的活动过程描述如下:

```text
Cobegin {
    process 顾客 {
        从取号机获取一个号码;
        等待叫号;
        获取服务;
    }

    process 营业员 {
        while (TRUE) {
            叫号;
            为客户服务;
        }
    }
} Coend
```

请添加必要的信号量和 P/V (或 wait（ ）、 signal（ ）) 操作, 实现上述过程中的互斥与同步。要求写出完整的过程, 说明信号量的含义并赋初值。

<Solution>

**【解析】** ① 定义同步信号量 call_custom，初始为 0，实现顾客与营业员之间叫号的同步；② 定义互斥信号量 mutex，初始为 1，实现对取号机这一互斥资源的互斥访问；③ 定义一对信号量 seats_empty = 10 和 seats_full = 0，分别表示空余座位数和已用座位数，有空余座位才可落座。具体实现如下：

```text
semaphore seats_empty = 10; //空座位数量，初始为10
semaphore seats_full = 0; //座位的已用数量
semaphore mutex = 1; //实现对取号机这一互斥资源的互斥访问
semaphore call_custom = 0; //实现顾客与营业员之间叫号的同步
CoBegin {
process 顾客i {
    P(seats_empty); // 申请空座位
    P(mutex); //（互斥）防止他人使用取号机
    从取号机获取一个号码;
    V(mutex); //（互斥）允许他人使用取号机
    V(seats_full); //（同步）通知营业员，有顾客在等待被服务
    P(call_custom); //（同步）等待营业员叫号
    获取服务;
}
process 营业员 {
    while(TRUE) {
        P(seats_full); //（同步）若没有顾客在等待被服务，则营业员休息
        叫号;
        V(call_custom); //（同步）通知顾客，已被叫号
        V(seats_empty); // 顾客去服务窗口，释放一个座位，空座位数量加1
        为顾客服务;
    }
}
} CoEnd
```

**【提示】** ① P/V 题有一个基本思路是：先找出同步或互斥关系，同步关系信号量初值为 0；互斥关系，信号量初值为 1。② 此题是较难的一类 P/V 题，是经典 P/V 场景的变式，考生如果感觉无从下手，在竞成《操作系统考研复习全书》进程同步小节中、有大量的各类 P/V 题，考生可强化练习。

**【点评】** 常规题。本题是经典的 P/V 操作题，不同于哲学家进餐、读写者等套路强的题，此类经典 P/V 做题套路性不强、灵活性高，这也是它的难点所在。操作系统的 P/V 操作题类似数据结构的算法题，需要考生多加练习，保持手感。

</Solution>

</Question>

<Question id="408-591a95-051" type="essay" tags="来源:2014考研408">

系统中有多个生产者进程和多个消费者进程,共享一个能存放 1000 件产品的环形缓冲区 (初始为空)。当缓冲区未满时, 生产者进程可以放入其生产的一件产品, 否则等待；当缓冲区未空时,消费者进程可以从缓冲区取走一件产品,否则等待。要求一个消费者进程从缓冲区连续取出 10 件产品后,其他消费者进程才可以取产品。请使用信号量 P/V (wait（ ）、 signal（ ）) 操作实现进程间的互斥与同步, 要求写出完整的过程, 并说明所用信号量的含义和初值。

<Solution>

**【解析】** 本题改编自经典的生产者－消费者问题。① 定义互斥信号量 mutex_consumer，用于实现在一个消费者进程进入缓冲区，且尚未取出 10 件产品之前，其他消费者进程不可以进入缓冲区取产品；② 定义互斥信号量 mutex_buffer，用于实现对缓冲区的互斥访问；③ 定义信号量 empty 和 full，分别表示缓冲区的空位数和已存放的产品数量。伪代码描述如下：

```c
semaphore mutex_consumer = 1; //实现消费者进程之间的互斥操作
semaphore mutex_buffer = 1; //实现对缓冲区的互斥访问
semaphore empty = 1000; //缓冲区可用空位数量
semaphore full = 0; //缓冲区已存放的产品数量

生产者进程
while(1){
    生产一件产品;
    P(empty); //占用一个缓冲区，如剩余容量不足则等待
    P(mutex_buffer); //（互斥）阻止他人访问缓冲区
    把产品放入缓冲区;
    V(mutex_buffer); //（互斥）允许他人访问缓冲区
    V(full); //（同步）缓冲区的已用容量加1
}

消费者进程
while(1){
    P(mutex_consumer); //申请进入缓冲区取走10件产品
    for(int i = 0; i < 10; i++){ //用这个循环描述连续取走10件
        P(full); // 申请从缓冲区取走一件产品，若缓冲区为空则等待
        P(mutex_buffer); //（互斥）阻止他人访问缓冲区
        从缓冲区取走一件产品;
        V(mutex_buffer); //（互斥）允许他人访问缓冲区
        V(empty); //缓冲区空位+1
    }
    V(mutex_consumer); //从缓冲区连续取走10件产品后，其他消费者可取产品
}
```

**【提示】** ★ ① 上述伪代码实现中，默认生产者和消费者不能同时访问缓冲区（经典的“生产者－消费者”问题也是这样要求的）。但本题官方给出的参考答案中，默认生产者和消费者可以同时访问缓冲区。而且，本题也未明确说明：“生产者和消费者是否可以同时访问缓冲区”，所以，两种写法都可以。而且，更推荐考生我们这里的这种写法。

② 教育部每年都会公布统考科目真题的标准答案，竞成将历年官方公布的 408 评分标准答案（2009～至今），整理在竞成《408 评分标准与官方答案》这本书中，建议考生去看看。

**【点评】** 常规题。本题根据教材上常见的“生产者－消费者”问题改编，主要改编点在于加了约束条件“一个消费者进程从缓冲区连续取走 10 件产品”，考查灵活运用。根据经典例题改编，此类考查方向多、变种很多，且“死记硬背”没有用，需要考生平时多练习（提高熟练度），多见一些题型（开拓视野），多积累总结，增进理解。

</Solution>

<Question id="408-591a95-052" type="essay" tags="来源:2015考研408">

(9 分) 有 A、 B 两人通过信箱进行辩论, 每个人都从自己的信箱中取得对方的问题。 将答案和向对方提出的新问题组成一个邮件放入对方的邮箱中。假设 A 的信箱最多放 M 个邮件, B 的信箱最多放 N 个邮件。初始时 A 的信箱中有 x 个邮件 ($0<x<M$),B 的信箱中有 y 个 ($0<y<N$)。 辩论者每取出一个邮件, 邮件数减 1。 A 和 B 两人的操作过程描述如下所示。

```text
Cobegin
A {
    while (TRUE) {
        从 A 的信箱中取出一个邮件;
        回答问题并提出一个新问题;
        将新邮件放入 B 的信箱;
    }
}

B {
    while (TRUE) {
        从 B 的信箱中取出一个邮件;
        回答问题并提出一个新问题;
        将新邮件放入 A 的信箱;
    }
}
CoEnd
```

当信箱不为空时,辩论者才能从信箱中取邮件,否则需要等待。当信箱不满时,辩论者才能将新邮件放入信箱, 否则需要等待。请添加必要的信号量和 P/V (或 wait、 signal) 操作, 以实现上述过程的同步。要求写出完整过程, 并说明信号量的含义和初值。

```c

semaphore chopsticks[n];//实现对筷子这一互斥资源的互斥访问
for(int i = 0; i<=amount_chop; i++){
    chopsticks[i] = 1;//每两个哲学家之间的筷子数量是一只
}
CoBegin{
    while(TRUE){//第i个哲学家
        进行思考;
        P(bowl);//（互斥）拿起一个碗
        P(chopsticks[(i+1) MOD n]);//（互斥）拿起右侧筷子
        P(chopsticks[i]);//（互斥）拿起左侧筷子
        开始就餐;
        V(chopsticks[(i+1) MOD n]);//（互斥）放下右侧筷子
        V(chopsticks[i]);//（互斥）放下左侧筷子
        V(bowl);//（互斥）放下一个碗
    }
}CoEnd
```

```c
if (key == TRUE)
    swap key, lock;  // 交换 key 和 lock 的值
临界区;
lock = TRUE;
...
```

**图 (b)：newSwap（ ） 的代码**

```c
void newSwap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}
```

请回答下列问题。
   (1) 图 (a) 的伪代码中哪些语句存在错误？将其改为正确的语句 (不增加语句条数)。
   (2) 图 (b) 给出了交换两个变量值的函数 newSwap（ ） 的代码, 是否可以用函数调用语句 “newSwap(&key,&lock)” 代替指令 “swap key, lock” 以实现临界区互斥? 为什么?

<Solution>

**【解析】**

（1）① 进入区中的语句“`if(key == TRUE) swap key, lock;`”存在错误，修改为“`while(key == TRUE) swap key,lock;`”。因为 if 语句无论判断结果如何，都会继续向下执行。因为对于实现临界区互斥访问，应该使用循环来等待 lock 变量为 FALSE 的时候再进入临界区，以确保在 lock 为 TRUE 时一直等待，直到 lock 为 FALSE 才能进入临界区。② 退出区中语句“`lock = TRUE`”存在错误，修改为“`lock = FALSE`”。因为 lock 为 TRUE 代表上锁了，退出区需要将 lock 解锁，让其他的线程可以访问临界区。

（2）否。不能使用函数“`newSwap(&key, &lock)`”替代指令“`swap key, lock`”。因为 newSwap 为函数调用，其执行不具备原子性（swap 是硬件指令，由硬件保证原子性），在调用函数 newSwap 执行时，传递给形参 b 的是引用 lock，而在执行 newSwap 的过程中，会修改 lock 的值。多个线程可以并发执行函数 newSwap，导致 lock 的值受到多个线程的影响，可能导致多个并发执行的线程同时进入临界区，无法正确实现临界区的互斥。

**【点评】** 冷门考点。此题考查通过硬件同步机制实现临界区互斥。从知识点的角度来说，如果学过这个考点，其实很简单。如果考前忽略了这个考点的学习，则容易出错。由于信号量实现进程同步互斥考查较多，另外两种通过软件和硬件机制实现临界区互斥的方法，可能容易被考生忽略。这里再次提醒各位考生，只要是 408 考试大纲中的内容，408 都有可能考到，不能放弃某个考点不学。

</Solution>

(8 分) 计算机系统中的进程之间往往需要相互协作以完成一个任务。在某网络系统中, 缓冲区 B 用于存放一个数据分组, 对 B 的操作有 C1、 C2 和 C3。 C1 将一个数据分组写入 B 中, C2 从 B 中读出一个数据分组, C3 对 B 中的数据分组进行修改。要求 B 为空时才能执行 C1,B 非空时才能执行 C2 和 C3。请回答下列问题。
   (1) 假设进程 P1 和 P2 都需要执行 C1, 实现 C1 的代码是否为临界区？为什么？
   (2) 假设 B 初始为空, 进程 P1 执行 C1 一次, 进程 P2 执行 C2 一次。请定义尽可能少的信号量,并用 wait（ ）, signal（ ） 操作描述进程 P1 和 P2 之间的同步或互斥关系,说明所用信号量的作用及其初值。
   (3) 若 B 初始不为空, 进程 P1 和 P2 各执行 C3 一次, 请定义尽可能少的信号量, 用 wait（ ）, signal（ ） 操作描述进程 P1 和 P2 之间的同步或互斥关系,说明所用信号量的作用及其初值。

<Solution>

**【解析】**

（1）两个进程 P1 和 P2 都需要执行 C1，而 C1 对 B 执行写操作。同一时刻只有一个进程能对 B 执行写操作，所以 B 是临界资源，实现访问临界资源 B 的代码 C1 是临界区。

（2）由于缓冲区初始为空，所以只有进程 P1 写了之后，进程 P2 才能读，P2 的操作应该在 P1 之后。所以，进程 P1 和 P2 为同步关系，实现同步关系的信号量 S 的初值为 0。进程 P1 和 P2 之间的同步关系描述如下：

```c
Semaphore S = 0; //实现进程 P1 与 P2 的同步
```

| P1 | P2 |
| --- | --- |
| `...` | `...` |
| `C1;` | `wait(S);` |
| `signal(S);` | `C2;` |
| `...` | `...` |

**【提示】** 这题看似简单，其实还是有坑的。坑点在于题目要求“定义尽可能少的信号量”，主要有以下 2 个“坑点”：

① 题目说“进程 P1 执行 C1 一次，进程 P2 执行 C2 一次”，因为只执行一次，就不用设置信号量考虑进程 P1 和进程 P2 执行多次的情况；

② 题目说“缓冲区 B 只存放一个数据分组”，就不用设置专门信号量考虑进程 P1 和进程 P2 互斥访问缓冲区 B。

考场时间紧张，很有可能考虑不周，写出如下答案。

```c
Semaphore S = 0, mutex = 1;
```

| P1 | P2 |
| --- | --- |
| `...` | `...` |
| `wait(mutex);` | `wait(S);` |
| `C1;` | `C2;` |
| `signal(S);` | `signal(mutex);` |
| `...` | `...` |

上面的做法功能上没问题，只是不符合题目要求“定义尽可能少的信号量”。因为进程 P1 和 P2 只执行一次，所以无需设置信号量 mutex 用于互斥访问 B。

（3）题目已说明 “B 初始不为空”，说明 B 已经有数据了，不用考虑将数据写入 B 的情况，进程 P1 和 P2 均对缓冲区 B 执行修改操作，因此要互斥访问 B。所以，进程 P1 和 P2 为互斥关系，实现互斥关系的信号量 mutex 的初值为 1。进程 P1 和 P2 之间的互斥关系描述如下：

```c
Semaphore mutex = 1; //实现 P1 与 P2 互斥执行 C3
```

| P1 | P2 |
| --- | --- |
| `...` | `...` |
| `wait(mutex);` | `wait(mutex);` |
| `C3;` | `C3;` |
| `signal(mutex);` | `signal(mutex);` |
| `...` | `...` |

**【提示】** 这一问 3 分很简单，命题人也没在这问上设置坑点，基本是送分题。但这题是这套试卷的倒数第 2 题的最后一问，考生可能在送分题上也没时间拿分。

**【点评】** 常规题。简单的 P/V 操作题目，除了解析中的第（2）问已指出的一些坑点，其他的很简单。大部分考生应该至少能得 5 分。
