# 408 历年大题整理 · 操作系统（第 101–108 题）

<ExamQuestion>

**101. 2023 年第 45 题**

现要求学生使用 `swap` 指令和布尔型共享变量 `lock` 实现临界区互斥。`lock=TRUE` 时线程不能进入临界区，`lock=FALSE` 时线程能够进入临界区。某同学编写的伪代码如下图所示。

<img src="/img/408/past-exams-large-questions/03-操作系统/assets/2023-45-figure-001.svg" alt="2023 年第 45 题伪代码" />

1. 图 (a) 中哪些语句存在错误？将其改为正确语句，不增加语句条数。
2. 图 (b) 给出了交换两个变量值的函数 `newSwap()`。能否用函数调用 `newSwap(&key, &lock)` 代替指令 `swap key, lock` 来实现临界区互斥？为什么？

<ExamSolution>

<ExamAnswer>

1. 进入区中的

```c
if (key == TRUE)
    swap key, lock;
```

应改为

```c
while (key == TRUE)
    swap key, lock;
```

退出区中的

```c
lock = TRUE;
```

应改为

```c
lock = FALSE;
```

2. 不能。普通函数 `newSwap()` 的“读两个变量—写回两个变量”不是一条不可分割的原子操作，多个线程并发执行时可能交叉访问共享变量 `lock`，因而不能保证互斥。

</ExamAnswer>

<ExamExplanation>

### （1）进入区为什么必须循环执行 `swap`

线程进入临界区前令 `key=TRUE`。

- 若 `lock=FALSE`，执行原子的 `swap key, lock` 后得到 `key=FALSE`、`lock=TRUE`。此时该线程取得锁，可以退出循环并进入临界区。
- 若 `lock=TRUE`，交换后 `key` 仍为 `TRUE`，说明锁仍被其他线程占用，应继续等待并再次执行 `swap`。

因此不能只判断一次，必须写成 `while (key == TRUE)`。

线程离开临界区时应释放锁，所以应执行 `lock=FALSE`，而不是再次置为 `TRUE`。

### （2）为什么普通函数不能替代 `swap` 指令

硬件 `swap` 指令的关键不是“最终交换了两个值”，而是**整个交换过程具有原子性**。图中的 `newSwap()` 实际上包含多次普通读、写操作：

```c
bool temp = *a;
*a = *b;
*b = temp;
```

若两个线程同时进入该函数，执行次序可以交叉，两个线程都有可能观察到不一致的中间状态，从而同时认为自己取得了锁。因此普通函数调用不能直接替代原子 `swap` 指令。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**102. 2023 年第 46 题**

进程 P 通过执行系统调用从键盘接收一个字符。已知此过程中与进程 P 相关的操作包括：

① 将进程 P 插入就绪队列；  
② 将进程 P 插入阻塞队列；  
③ 将字符从键盘控制器读入系统缓冲区；  
④ 启动键盘中断处理程序；  
⑤ 进程 P 从系统调用返回；  
⑥ 用户在键盘上输入字符。

以上编号仅用于标记操作，与先后顺序无关。请回答：

1. 操作①的前一个和后一个操作分别是哪一个？操作⑥的后一个操作是哪一个？
2. 在哪个操作之后 CPU 一定从进程 P 切换到其他进程？在哪个操作之后 CPU 调度程序才可以选择进程 P 执行？
3. 完成哪个操作的代码属于键盘驱动程序？
4. 键盘中断处理程序执行时，进程 P 处于什么状态？CPU 处于内核态还是用户态？

<ExamSolution>

<ExamAnswer>

1. 操作①之前是③，之后是⑤；操作⑥之后是④。
2. 操作②之后 CPU 一定从进程 P 切换到其他进程；操作①之后，P 才重新具备被调度执行的条件。
3. 操作③属于键盘驱动程序完成的工作。
4. 此时进程 P 处于阻塞态，CPU 处于内核态。

</ExamAnswer>

<ExamExplanation>

进程 P 发起读键盘的系统调用后，如果字符尚未到达，P 无法继续执行，于是被加入阻塞队列，即先发生②。P 阻塞后 CPU 必须调度其他可运行进程。

之后用户输入字符⑥，键盘产生中断并启动中断处理程序④。中断处理过程中，驱动程序把字符从键盘控制器读入系统缓冲区③。等待该输入的进程 P 随后被唤醒并插入就绪队列①。

P 进入就绪队列并不意味着立即运行，而是从此具备再次被调度的资格。等 P 真正获得 CPU 后，先前的系统调用继续执行并返回用户程序⑤。

因此核心先后关系为

$$
②\rightarrow⑥\rightarrow④\rightarrow③\rightarrow①\rightarrow⑤,
$$

其中①与⑤之间还可能夹有“等待调度、获得 CPU”等未在题目编号中列出的过程。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**103. 2024 年第 45 题**

某计算机按字节编址，采用页式虚拟存储管理方式，虚拟地址和物理地址长度均为 32 位，页表项大小为 4B，页大小为 4MB，虚拟地址结构如下。

<img src="/img/408/past-exams-large-questions/03-操作系统/assets/2024-45-figure-001.svg" alt="2024 年第 45 题虚拟地址结构" />

进程 P 的页表起始虚拟地址为 `B8C00000H`，该页表被装载到从物理地址 `65400000H` 开始的连续主存空间中。

1. CPU 访问虚拟地址 `12345678H` 时发生缺页异常。缺页处理后，该地址经 MMU 转换得到物理地址 `BAB45678H`。需要为新缺页分配页框并更新相应页表项。求该页表项的虚拟地址、物理地址，以及更新后的页框号。
2. 进程 P 的页表所在页的页号是多少？该页对应的页表项的虚拟地址是多少？该页表项中的页框号是多少？

<ExamSolution>

<ExamAnswer>

1. 对虚拟地址 `12345678H`：
   - 页号为 `048H`；
   - 页表项虚拟地址为 `B8C00120H`；
   - 页表项物理地址为 `65400120H`；
   - 更新后的页框号为 `2EAH`。
2. 页表起始虚拟地址所在页的页号为 `2E3H`；对应页表项虚拟地址为 `B8C00B8CH`；该页表项中的页框号为 `195H`。

</ExamAnswer>

<ExamExplanation>

页大小为

$$
4\text{MB}=2^{22}\text{B},
$$

所以页内偏移量占 22 位，页号占 10 位。

### （1）虚拟地址 `12345678H`

页号为

$$
\text{VPN}=\left\lfloor\frac{\texttt{12345678H}}{2^{22}}\right\rfloor
=\texttt{048H},
$$

页内偏移为

$$
\texttt{345678H}.
$$

每个页表项占 4B，因此第 `048H` 个页表项相对于页表起始地址的偏移为

$$
\texttt{048H}\times 4=\texttt{120H}.
$$

故页表项的虚拟地址为

$$
\texttt{B8C00000H}+\texttt{120H}
=\boxed{\texttt{B8C00120H}},
$$

物理地址为

$$
\texttt{65400000H}+\texttt{120H}
=\boxed{\texttt{65400120H}}.
$$

缺页处理后得到物理地址 `BAB45678H`。物理页框号取高 10 位：

$$
\text{PFN}=\texttt{BAB45678H}\gg22
=\boxed{\texttt{2EAH}}.
$$

### （2）页表自身所在虚拟页

页表起始虚拟地址为 `B8C00000H`，因此其页号为

$$
\texttt{B8C00000H}\gg22
=\boxed{\texttt{2E3H}}.
$$

该虚拟页对应的页表项位于

$$
\texttt{B8C00000H}+\texttt{2E3H}\times4
=\boxed{\texttt{B8C00B8CH}}.
$$

页表自身从物理地址 `65400000H` 开始装入，因此该页的页框号为

$$
\texttt{65400000H}\gg22
=\boxed{\texttt{195H}}.
$$

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**104. 2024 年第 46 题**

某网络系统使用缓冲区 B 存放一个数据分组，对 B 有三种操作：

- C1：将一个数据分组写入 B；
- C2：从 B 中读出一个数据分组；
- C3：修改 B 中的数据分组。

要求：B 为空时才能执行 C1，B 非空时才能执行 C2 和 C3。

1. 若进程 P1、P2 均需执行 C1，实现 C1 的代码是否为临界区？为什么？
2. 若 B 初始为空，P1 执行 C1 一次，P2 执行 C2 一次。请定义尽可能少的信号量，并用 `wait()`、`signal()` 描述 P1、P2 的同步或互斥关系，说明信号量的作用和初值。
3. 若 B 初始非空，P1、P2 各执行 C3 一次。请定义尽可能少的信号量，并描述同步或互斥关系。

<ExamSolution>

<ExamAnswer>

1. 是。P1、P2 都可能修改同一共享缓冲区 B，C1 必须互斥执行。
2. 只需一个同步信号量，例如 `full=0`：

```c
semaphore full = 0;

P1() {
    C1;
    signal(full);
}

P2() {
    wait(full);
    C2;
}
```

3. 只需一个互斥信号量 `mutex=1`：

```c
semaphore mutex = 1;

P1() {
    wait(mutex);
    C3;
    signal(mutex);
}

P2() {
    wait(mutex);
    C3;
    signal(mutex);
}
```

</ExamAnswer>

<ExamExplanation>

### （1）C1 是否属于临界区

B 是共享数据。若两个进程同时判断“B 为空”并同时写入 B，就可能造成覆盖或数据不一致。因此多个进程执行 C1 时，对 B 的访问必须互斥，C1 对应代码属于临界区。

### （2）一次 C1 与一次 C2

题目限定 P1 只执行一次 C1、P2 只执行一次 C2，且 B 初始为空。只要保证 **C2 一定在 C1 完成之后执行**，两者就不会同时访问 B，因此不需要再额外设置互斥信号量。

`full` 初值为 0，表示 B 中尚无可读数据。P1 完成 C1 后执行 `signal(full)`，P2 才能通过 `wait(full)` 并执行 C2。

因此在“尽可能少”的要求下，一个信号量即可。

### （3）两个 C3

B 初始非空，两个进程都要修改同一个数据分组，因此无需解决“空/非空”的先后关系，只需保证两个 C3 互斥执行。设置初值为 1 的二元信号量 `mutex` 即可。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**105. 2025 年第 45 题**

甲、乙、丙三人一起植树。甲负责挖坑；乙负责放树苗并填土；丙负责给新种的树苗浇水。步骤依次为：挖树坑 → 放树苗、填土 → 浇水。

现有铁锹和水桶各一个，铁锹用于挖树坑和填土，水桶用于浇水。当尚未被乙处理的树坑数量小于 3 时，甲才可以继续挖坑。初始时树坑数为 0，铁锹和水桶均可用。请定义尽可能少的信号量，用 `wait()`、`signal()` 描述三人的同步、互斥关系，并说明各信号量作用及初值。

<ExamSolution>

<ExamAnswer>

可定义 4 个信号量：

```c
semaphore shovel = 1;   // 铁锹互斥使用
semaphore slots  = 3;   // 还允许新增的未处理树坑数
semaphore pits   = 0;   // 已挖好、等待乙处理的树坑数
semaphore water  = 0;   // 已填土、等待丙浇水的树苗数
```

伪代码为：

```c
甲() {
    while (1) {
        wait(slots);
        wait(shovel);
        挖树坑;
        signal(shovel);
        signal(pits);
    }
}

乙() {
    while (1) {
        wait(pits);
        wait(shovel);
        放树苗并填土;
        signal(shovel);
        signal(slots);
        signal(water);
    }
}

丙() {
    while (1) {
        wait(water);
        浇水;
    }
}
```

</ExamAnswer>

<ExamExplanation>

这是两个相邻生产—消费关系叠加而成的流水线：

$$
\text{甲挖坑}\rightarrow\text{乙放苗并填土}\rightarrow\text{丙浇水}.
$$

`slots` 初值为 3，用来限制“已经挖好但尚未被乙处理”的树坑最多为 3 个；甲每挖一个坑先消耗一个 `slots`，乙填完一个坑后再归还一个。

`pits` 初值为 0，记录已经挖好、可供乙处理的坑数。乙必须先 `wait(pits)`，因此不会在没有树坑时执行放苗、填土。

`water` 初值为 0，记录已经完成放苗和填土、可以浇水的树苗数，保证丙不会提前浇水。

铁锹同时被甲的“挖坑”和乙的“填土”使用，所以还需二元信号量 `shovel=1` 保证互斥。水桶只有丙使用，不需要再为水桶设置互斥信号量。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

**106. 2025 年第 46 题**

某进程的虚拟地址空间如下图，阴影部分表示未占用区域。现有 C 程序：

<img src="/img/408/past-exams-large-questions/03-操作系统/assets/2025-46-figure-001.svg" alt="2025 年第 46 题进程虚拟地址空间" />

```c
char *ptr;

void main() {
    int length;
    ptr = (char *)malloc(100);
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```

1. 程序执行时，PCB 位于哪个区域？执行 `scanf()` 等待键盘输入时，该进程处于什么状态？
2. `main()` 函数的代码位于哪个区域？其直接调用的哪些函数的功能需要通过执行设备驱动程序实现？
3. 变量 `ptr` 被分配在哪个区域？若 `length` 没有被分配到寄存器中，它被分配在哪个区域？`ptr` 指向的字符串位于哪个区域？

<ExamSolution>

<ExamAnswer>

1. PCB 位于操作系统内核区；执行 `scanf()` 等待键盘输入时，进程处于阻塞态。
2. `main()` 的机器代码位于只读代码段；其直接调用的函数中，`scanf()` 和 `printf()` 涉及设备 I/O，需要相应设备驱动程序参与实现。
3. `ptr` 是全局变量，位于读/写数据段；局部变量 `length` 若不在寄存器中，则位于用户栈；`malloc()` 动态分配的、由 `ptr` 指向的字符串存储空间位于堆。

</ExamAnswer>

<ExamExplanation>

PCB 属于操作系统维护的进程管理数据结构，存放在内核空间，而不是用户进程自己的普通用户地址区。

`scanf()` 等待键盘输入时，进程因等待 I/O 事件而不能继续执行，所以进入阻塞态。键盘输入以及终端/显示输出最终需要相应设备驱动程序配合，因此题中直接调用的 `scanf()`、`printf()` 涉及驱动程序；`malloc()`、`strlen()`、`free()` 本身不是设备 I/O 操作。

在图示地址空间中：

- `main()` 的指令属于只读代码段；
- `char *ptr;` 是具有静态存储期的全局变量，题图把此类可读写静态数据统一归入“读/写数据段”；
- `length` 是 `main()` 的局部自动变量，若编译器没有把它分配在寄存器中，则通常位于用户栈；
- `malloc(100)` 获得的动态存储区位于堆，因此输入字符串也位于堆中。

</ExamExplanation>

</ExamSolution>

**107. 2026 年第 45 题**

系统采用“优先级 + 时间片轮转”调度算法，优先级值越大表示优先级越高。仅当发生时钟中断时才触发抢占 CPU，时钟中断间隔为 10ms。进程首次进入就绪队列时，时间片为 50ms。

若进程因时间片用完而返回就绪队列，其优先级减 1；若进程被更高优先级进程抢占而返回就绪队列，其优先级不变。多个进程优先级相同时，先进入就绪队列者优先。

| 进程 | 到达就绪队列时间（ms） | 初始优先级 | CPU 运行时间（ms） |
| --- | ---: | ---: | ---: |
| P1 | 10 | 3 | 95 |
| P2 | 10 | 4 | 20 |
| P3 | 12 | 2 | 40 |
| P4 | 14 | 5 | 60 |

1. 从 10ms 开始进程调度，直到所有进程结束。此过程中时钟中断次数和 CPU 调度次数分别是多少？P1、P2、P3、P4 的首次调度时刻分别是什么？
2. 若时间片从 50ms 改为 100ms，CPU 调度次数将增大、不变还是减少？若时钟中断间隔从 10ms 改为 1ms，系统开销将增大、不变还是减少？

<ExamSolution>

<ExamAnswer>

1. 调度过程中的关键切换时刻为 `10、20、70、80、90、140、180 ms`：
   - 时钟中断共 22 次；
   - CPU 调度共 7 次；
   - P1、P2、P3、P4 的首次调度时刻分别为 `90ms、10ms、140ms、20ms`。
2. 时间片增大到 100ms 后，CPU 调度次数减少；时钟中断间隔缩短到 1ms 后，系统开销增大。

</ExamAnswer>

<ExamExplanation>

### （1）调度过程

从 10ms 开始：

| 时间段 | 运行进程 | 原因 / 结果 |
| --- | --- | --- |
| 10–20ms | P2 | 10ms 时 P1、P2 已就绪，P2 优先级更高；14ms 到达的 P4 要到 20ms 时钟中断时才能触发抢占 |
| 20–70ms | P4 | 20ms 时 P4 以优先级 5 抢占 P2；运行满 50ms 后时间片耗尽，优先级降为 4 |
| 70–80ms | P2 | 此时 P2 与 P4 均为优先级 4，P2 更早进入就绪队列；P2 再运行 10ms 后完成 |
| 80–90ms | P4 | P4 剩余 10ms，运行后完成 |
| 90–140ms | P1 | P1 优先级 3，高于 P3；运行满 50ms 后时间片耗尽，优先级降为 2 |
| 140–180ms | P3 | P3 与 P1 均为优先级 2，但 P3 更早进入就绪队列；P3 运行 40ms 后完成 |
| 180–225ms | P1 | P1 运行剩余 45ms 后完成 |

所以 CPU 实际选择新运行进程的时刻共有 7 个：

$$
10,20,70,80,90,140,180\text{ ms}.
$$

按题目给出的 10ms 时钟节拍并从 10ms 开始计入，到全部进程在 225ms 完成之前，时钟中断时刻为

$$
10,20,30,\ldots,220\text{ ms},
$$

共

$$
\frac{220-10}{10}+1=22
$$

次。

各进程首次获得 CPU 的时刻因此为：

$$
P2:10\text{ ms},\quad P4:20\text{ ms},\quad
P1:90\text{ ms},\quad P3:140\text{ ms}.
$$

### （2）参数变化

时间片由 50ms 增大到 100ms 后，因“时间片耗尽”导致的重新排队和切换次数减少，因此 CPU 调度次数减少。

时钟中断间隔由 10ms 缩短到 1ms 后，中断发生更频繁，中断现场保护、恢复以及调度条件检查等工作更频繁，所以系统开销增大。

### （1）索引节点位置、访问盘块数和文件数上限

每盘块可容纳的索引节点数为

$$
\frac{4096}{128}=32.
$$

`file` 的索引节点号为 1000，因此它位于索引节点表中的第

$$
\left\lfloor\frac{1000}{32}\right\rfloor=31
$$

号盘块偏移处。索引节点表从盘块 100 开始，所以实际盘块号为

$$
100+31=\boxed{131}.
$$

访问文件偏移 21460 时，其逻辑块号为

$$
\left\lfloor\frac{21460}{4096}\right\rfloor=5,
$$

块内偏移为

$$
21460\bmod4096=980.
$$

5 个直接地址项对应逻辑块号 0～4，因此逻辑块号 5 是一级间接地址项能够访问到的第一个数据块。题目已说明索引节点在内存中，所以最坏情况下还需：

1. 读一级间接索引块；
2. 再读目标数据块。

共

$$
\boxed{2\text{ 个盘块}}.
$$

索引节点表共有 4096 个盘块，每块 32 个索引节点，因此总索引节点数为

$$
4096\times32=\boxed{131072}.
$$

每个文件或目录都需要一个索引节点，所以在磁盘空间足够时，文件数量上限由索引节点数决定。

### （2）删除 `dir1` 时的元数据修改
