## 2009 年第 46 题

<ExamQuestion>

**74. 2009 年第 46 题**

请求分页管理系统中，某进程的页表如下。

| 页号 | 页框号 | 有效位 |
| --- | --- | --- |
| 0 | `101H` | 1 |
| 1 | — | 0 |
| 2 | `254H` | 1 |

页面大小为 $4\text{ KB}$，一次内存访问时间为 $100\text{ ns}$，一次 TLB 访问时间为 $10\text{ ns}$，处理一次缺页的平均时间为 $10^8\text{ ns}$（已含更新 TLB 和页表的时间）。进程的驻留集大小固定为 2，采用 LRU 页面置换算法和局部淘汰策略。

假设：

1. TLB 初始为空；
2. 地址转换时先访问 TLB，若 TLB 未命中，再访问页表；忽略访问页表后的 TLB 更新时间；
3. 有效位为 0 表示页面不在内存，产生缺页中断；缺页中断处理完成后，返回产生缺页中断的指令处重新执行。

虚地址访问序列为 `2362H`、`1565H`、`25A5H`。请回答：

1. 依次访问上述三个虚地址，各需多少时间？给出计算过程。
2. 基于上述访问序列，虚地址 `1565H` 的物理地址是多少？说明理由。

<ExamSolution>

<ExamAnswer>

- 访问 `2362H`：$10+100+100=\boxed{210\text{ ns}}$。
- 访问 `1565H`：$10+100+10^8+10+100=\boxed{100000220\text{ ns}}$。
- 访问 `25A5H`：$10+100=\boxed{110\text{ ns}}$。
- 页 1 被装入被淘汰页 0 所占用的页框 `101H`，所以 `1565H` 的物理地址为 **`101565H`**。

</ExamAnswer>

<ExamExplanation>

### 一、地址划分：页号变，页内偏移永远不变

页面大小为 $4\text{ KiB}=2^{12}$ 字节，故后 12 位（3 个十六进制数）为页内偏移：

| 虚地址 | 页号 | 页内偏移 | 初始驻留情况 |
| --- | ---: | --- | --- |
| `2362H` | 2 | `362H` | 页 2 在页框 `254H` |
| `1565H` | 1 | `565H` | 页 1 不驻留 |
| `25A5H` | 2 | `5A5H` | 页 2 起初驻留，随后仍驻留 |

分页地址转换的拼接式为

$$
\mathrm{PA}=(\text{页框号}\ll12)\;|\;\text{页内偏移}.
$$

这里十六进制页框号 `101H` 直接左移 3 个十六进制数字后再拼接偏移 `565H`，得到 `101565H`；**不能把页框号直接当作物理地址**。

### 二、逐次跟踪 TLB、页表、缺页与 LRU

假设题设页表驻留内存、一次主存访问 100 ns、TLB 查找 10 ns；缺页处理费 $10^8$ ns，并含页表/TLB 更新，但**缺页指令重新执行后的地址访问还须计时**。

| 步骤 | 事件 | TLB 结果 | 页表/置换 | 耗时 |
| --- | --- | --- | --- | ---: |
| 1：`2362H` | 访问页 2 | miss | 有效位 1，装入 TLB | $10+100+100=210$ ns |
| 2：`1565H` | 访问页 1 | miss | 页表有效位 0，触发缺页 | 首次查找 $10+100$ ns |
| 2：缺页处理 | 需要空页框 | — | 驻留页 0、2 中按 LRU 淘汰页 0，页 1 使用 `101H` 页框 | $10^8$ ns |
| 2：重启指令 | 再访问页 1 | hit | TLB 已随缺页处理更新 | $10+100=110$ ns |
| 3：`25A5H` | 再访问页 2 | hit | 页 2 未被淘汰 | $10+100=110$ ns |

所以第二次访存总耗时

$$
T_2=(10+100)+10^8+(10+100)=100000220\text{ ns}.
$$

**为什么淘汰页 0？** 驻留集最多 2 页，最初为页 0 和页 2。首个地址先访问页 2，因此页 2 比页 0 最近使用；当页 1 缺页时，LRU 淘汰最久未用的页 0。更换页时需使被淘汰页原来可能存在的 TLB 表项失效；本题 TLB 初始空，所以不存在页 0 的旧 TLB 项要清理。

### 三、常见的三种耗时公式

在题设**TLB 和页表均按顺序查询**、且每次访问主存 100 ns 的模型下：

$$
\begin{aligned}
T_{\mathrm{TLB\ hit}}&=10+100=110\text{ ns},\\
T_{\mathrm{TLB\ miss,\ resident}}&=10+100+100=210\text{ ns},\\
T_{\mathrm{page\ fault}}&=10+100+10^8+10+100=10^8+220\text{ ns}.
\end{aligned}
$$

缺页并不是“TLB miss 一定触发”；**页表无有效映射才是缺页**。重启时是否再次查 TLB、是否需计入一次页表查询，取决于题设是否说“缺页服务已经更新 TLB”和“是否重启指令”。这是本题容易少算/多算 110 ns 的根源。

### 四、物理地址与正确性自检

页 1 的新页框为 `101H`，偏移为 `565H`，故

$$
\mathrm{PA}=\texttt{101H}\times\texttt{1000H}+\texttt{565H}
=\boxed{\texttt{101565H}}.
$$

验证：页 1 装入后当前驻留集为 $\{1,2\}$；页 2 仍在内存且上次刚装入 TLB，因此第三次访问 TLB 命中。该轨迹同时符合固定驻留集、局部淘汰和 LRU 三个条件。

**考场口诀**：先划页号/偏移 → 标记 TLB miss 与 page fault 是两回事 → 缺页前检查 LRU → 换页后更新映射 → 按重启规则单独算访存开销。

</ExamExplanation>

</ExamSolution>

</ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

某进程页面大小为 $4\text{ KiB}$、驻留集固定为两页且按 LRU 局部替换。起初页 0 在页框 `8H`、页 1 在页框 `9H`，页 2 不在内存；TLB 初始为空且容量足以缓存所有当前驻留页，页面被逐出时其 TLB 项立即失效。访问时间：TLB 10 ns、主存 100 ns、一次缺页处理 $10^6$ ns（含页表/TLB 更新）。TLB miss 时先查询一次内存页表；缺页处理后指令重新执行。访问序列为：

`0123H → 2456H → 1789H → 2ABCH → 0DEFH`。

1. 对每次访问分别判定 TLB hit/miss、是否缺页、谁被淘汰；
2. 计算每次访问所需时间及总时间；
3. 求最后一次虚地址 `0DEFH` 所对应的物理地址，并解释为何“TLB miss”不必然是“缺页”。

<ExamSolution>

<ExamAnswer>

| 访问页 | TLB | 缺页 | 被替换页 | 耗时 (ns) |
| --- | --- | --- | --- | ---: |
| 0 | miss | 否 | — | 210 |
| 2 | miss | 是 | 页 1 | 1,000,220 |
| 1 | miss | 是 | 页 0 | 1,000,220 |
| 2 | hit | 否 | — | 110 |
| 0 | miss | 是 | 页 1 | 1,000,220 |

共 **3 次缺页、1 次 TLB 命中、4 次 TLB 未命中**；总时间为

$$
210+3(10^6+220)+110=\boxed{3{,}000{,}980\text{ ns}}.
$$

最后页 0 被装入页框 `8H`，故 `0DEFH` 的物理地址为 **`08DEFH`**。

</ExamAnswer>

<ExamExplanation>

**一、把页号/偏移和驻留集跟踪分开。** 页大小 4 KiB，故每个虚地址的十六进制首位是页号，后三位是偏移。首个访问页 0 时，页 0 本来就驻留，仅 TLB 尚未建立映射；应查页表并正常访存，不能算缺页。

**二、LRU 时间线逐项维护**（左旧右新）：

| 访问后 | 驻留页从最久未用到最近使用 | 变化 |
| --- | --- | --- |
| 初始 | 取决于历史；首次页 0 访问后可确定其更近 | 初始页 0、1 |
| 访问页 0 | $1,0$ | 页 0 更新为最近使用 |
| 访问页 2 | $0,2$ | 淘汰页 1（框 9），页 2 入框 9 |
| 访问页 1 | $2,1$ | 淘汰页 0（框 8），页 1 入框 8 |
| 再访问页 2 | $1,2$ | 页 2 TLB 命中、成为最近使用 |
| 再访问页 0 | $2,0$ | 淘汰页 1（框 8），页 0 入框 8 |

**三、重启指令的开销不漏算**。驻留且 TLB miss：$10+100+100=210$ ns；TLB hit：$10+100=110$ ns；缺页时先 TLB 查询 10 ns、页表查找 100 ns，缺页处理 $10^6$ ns，重启后命中 TLB 10 ns、访问内存 100 ns，因此 $10^6+220$ ns。合计 3,000,980 ns。

**四、TLB 项与页框不是“一次创建、永久有效”。** 页 1、页 0 被替换时，其旧映射必须作废。若保留它们的 TLB 旧表项，系统可能在不应驻留的时刻错误地命中旧映射，产生严重的物理地址错译。这是为何本题最后页 0 虽早先访问过，仍是 **TLB miss + 缺页**。

**五、物理地址**：最终页 0 在框 8、偏移 `DEFH`，

$$
\mathrm{PA}=\texttt{8H}\times\texttt{1000H}+\texttt{DEFH}=\boxed{\texttt{08DEFH}}.
$$

答题时务必区分：**TLB miss** 表示快速地址转换缓存未命中；**page fault** 表示所需页不在当前有效内存映射，两者不是同义词。

</ExamExplanation>

</ExamSolution>

## 2010 年第 46 题

<ExamQuestion>

**76. 2010 年第 46 题**

某计算机的逻辑地址空间和物理地址空间均为 $64\text{ KB}$，按字节编址。某进程最多需要 6 页数据存储空间，页大小为 $1\text{ KB}$。操作系统采用固定分配、局部置换策略，为该进程分配 4 个页框。

在时刻 260 前，该进程的页面情况如下。

| 页号 | 页框号 | 装入时刻 | 访问位 |
| --- | ---: | ---: | ---: |
| 0 | 7 | 130 | 1 |
| 1 | 4 | 230 | 1 |
| 2 | 2 | 200 | 1 |
| 3 | 9 | 260 | 1 |

当进程执行到时刻 260 时，要访问逻辑地址 `17CAH`。请回答：

1. 该逻辑地址对应的页号是多少？
2. 若采用 FIFO 页面置换算法，该逻辑地址对应的物理地址是多少？给出计算过程。
3. 若采用 CLOCK 页面置换算法，该逻辑地址对应的物理地址是多少？设搜索下一页的指针按顺时针方向移动，且当前指向 2 号页框，如下图所示。

<img src="/img/408/past-exams-large-questions/03-操作系统/assets/2010-46-figure-001.svg" alt="2010 年第 46 题 CLOCK 页框示意图" />

<ExamSolution>

<ExamAnswer>

1. 虚地址 `17CAH` 的页号为 **5**，页内偏移为 **`3CAH`**。
2. FIFO 选最早装入的页 0（页框 7），物理地址：**`1FCAH`**。
3. CLOCK 从所指页框 2 开始扫描，四个访问位均为 1，第一圈清 0，第二圈在页框 2 命中第一个 0，故替换页 2（页框 2），物理地址：**`0BCAH`**。

</ExamAnswer>

<ExamExplanation>

### 一、先算页号与偏移，不要直接按十六进制位数切

页大小是 $1\text{ KiB}=2^{10}$ 字节，一页包含 `400H` 字节。

$$
\begin{aligned}
\mathrm{VPN}&=\left\lfloor\frac{\texttt{17CAH}}{\texttt{400H}}\right\rfloor=5,\\
\mathrm{offset}&=\texttt{17CAH}\bmod\texttt{400H}=\texttt{3CAH}.
\end{aligned}
$$

页内偏移占**10 位**，不对应完整的十六进制整数位数。页号为 5，原驻留集只有 0、1、2、3，故访问页 5 时必然缺页。

物理地址统一按下式计算：

$$
\mathrm{PA}=\text{页框号}\times 2^{10}+\text{页内偏移}.
$$

### 二、FIFO：比较“装入时刻”，不要比较“最后一次访问”

现有页的装入时刻为页 0 的 130、页 1 的 230、页 2 的 200、页 3 的 260，因此最早进入内存的是页 0（页框 7）。FIFO 淘汰它；页 5 占用页框 7，得到

$$
\mathrm{PA}=7\times\texttt{400H}+\texttt{3CAH}
=\texttt{1C00H}+\texttt{3CAH}=\boxed{\texttt{1FCAH}}.
$$

注意 FIFO **不管访问位是否为 1**；只要不是重新调入，就不会因普通访问而改变先后次序。`装入时刻=260` 的页 3 是最新进入的，不会首先被替换。

### 三、CLOCK：按“指针当前位置 + 箭头方向”逐框扫描

本题图给出的扫描顺序从 **页框 2** 开始、沿顺时针遍历为

$$
2\rightarrow4\rightarrow7\rightarrow9\rightarrow2.
$$

四个访问位开始都是 1，基本 CLOCK 的检查规则是：若访问位 $R=1$，置 $R\leftarrow0$ 并移向下一页框；若 $R=0$，选择该页框作为牺牲者。故：

| 检查次数 | 页框 | 原访问位 | 操作 |
| --- | ---: | ---: | --- |
| 1 | 2 | 1 | 清为 0，继续 |
| 2 | 4 | 1 | 清为 0，继续 |
| 3 | 7 | 1 | 清为 0，继续 |
| 4 | 9 | 1 | 清为 0，继续 |
| 5 | 2 | 0 | **选为牺牲页框** |

页框 2 中原来是页 2，装入新页 5 后物理地址

$$
\mathrm{PA}=2\times\texttt{400H}+\texttt{3CAH}
=\texttt{0800H}+\texttt{3CAH}=\boxed{\texttt{0BCAH}}.
$$

新页通常设访问位为 1；替换后时钟指针按实现规则指向**被替换页框的下一个页框**（本题当前访问只关心牺牲框，因此该后续指针状态不影响本问数值）。

### 四、考点拓展：FIFO、LRU、CLOCK 的联系与区别

| 算法 | 主要判据 | 是否需要逐访存维护次序 | 典型陷阱 |
| --- | --- | --- | --- |
| FIFO | 最先调入内存 | 不需要（记装入顺序） | 发生 Belady 异常；“老页最近使用”也可能被淘汰 |
| LRU | 最长时间未访问 | 精确实现需维护时间戳/栈 | 不能以装入时刻代替使用时刻 |
| 基本 CLOCK | 按环形扫描 R 位，给 $R=1$ 者第二次机会 | 访存时置 R=1 | 指针位置、方向、清位过程可能改变牺牲页 |

**最后检查**：地址划分正确（$\texttt{17CAH}=5\times\texttt{400H}+\texttt{3CAH}$），置换目标在 4 个本地页框内，拼接后的物理地址均保留 `3CAH` 的页内偏移。

</ExamExplanation>

</ExamSolution>

<ExamQuestion>

<span className="inline-block rounded border px-2 py-0.5 text-xs text-fd-muted-foreground">原创</span>

页大小为 $1\text{ KiB}$，固定分配 4 个页框。当前状态：

| 页框号 | 驻留页 | 访问位 $R$ | 装入先后（越小越早） |
| ---: | ---: | ---: | ---: |
| 2 | 0 | 1 | 1 |
| 4 | 1 | 0 | 2 |
| 7 | 2 | 1 | 3 |
| 9 | 3 | 0 | 4 |

页框 CLOCK 环形顺序为 $2\to4\to7\to9\to2$，当前指针指向页框 **7**。先后访问两个不存在的虚页：页 4（虚地址 `1300H`），接着页 5（虚地址 `17CAH`）。每次访问新装入页都将访问位置为 1；每次替换后指针移动到**被换页框的下一个页框**。两个页面在置换之间没有其他访存。

1. 若采用 FIFO，各次淘汰哪一页、装入哪个页框？给出两次访问的物理地址；
2. 若采用基本 CLOCK，各次扫描哪些页框、淘汰哪一页、装入哪个页框？给出两个物理地址及最后指针位置；
3. 解释“R 位等于 1”和“页装入得早”之间有无等价关系。

<ExamSolution>

<ExamAnswer>

- FIFO：第一次淘汰最早装入的**页 0**（框 2），`1300H` 对应 `0B00H`；第二次淘汰**页 1**（框 4），`17CAH` 对应 `13CAH`。
- CLOCK：从框 7 开始，先遇 $R_7=1$，清为 0；到框 9 遇 $R_9=0$，淘汰页 3，在框 9 装页 4，故首次物理地址 `2700H`，指针转向框 2。第二次从框 2 开始，先清 $R_2=1$，到框 4 遇 $R_4=0$，淘汰页 1，在框 4 装页 5，故物理地址 `13CAH`；最终指针指向框 **7**。

</ExamAnswer>

<ExamExplanation>

**一、地址分解**：页大小 `400H` 字节。

$$
\begin{aligned}
\texttt{1300H}&=4\times\texttt{400H}+\texttt{300H},\\
\texttt{17CAH}&=5\times\texttt{400H}+\texttt{3CAH}.
\end{aligned}
$$

因而无论用哪个替换算法，页内偏移都分别保持 `300H` 和 `3CAH`；变化的只有页框号。

**二、FIFO 只用装入队列**。原装入次序为页 0、1、2、3。第一次让页 4 复用页 0 的框 2，成为队尾；第二次让页 5 复用页 1 的框 4。所以

$$
\begin{aligned}
\mathrm{PA}_4 &= 2\times\texttt{400H}+\texttt{300H}=\texttt{0B00H},\\
\mathrm{PA}_5 &= 4\times\texttt{400H}+\texttt{3CAH}=\texttt{13CAH}.
\end{aligned}
$$

**三、CLOCK 的逐步走表**：

| 缺页 | 检查顺序 | 置换结果 | 置换后指针 |
| --- | --- | --- | --- |
| 访问页 4 | 框 7（$R=1\to0$）→框 9（$R=0$） | 页 3 被换出，页 4 入框 9 且 $R=1$ | 框 2 |
| 访问页 5 | 框 2（$R=1\to0$）→框 4（$R=0$） | 页 1 被换出，页 5 入框 4 且 $R=1$ | 框 7 |

所以 CLOCK 第一次物理地址

$$
9\times\texttt{400H}+\texttt{300H}=\texttt{2700H},
$$

第二次物理地址

$$
4\times\texttt{400H}+\texttt{3CAH}=\texttt{13CAH}.
$$

**四、核心差别**：FIFO 以“页装入内存的先后”淘汰，普通访存不会改变排序；CLOCK 使用访问位给近期用过的页面第二次机会，且访问位为 0 不一定表示最久未访问，只说明自上次清零起（或初始设为 0 后）未被记录到访问。于是**R=1 不等于最新装入**，**R=0 也不等于最早装入**；两个算法的选择可能不同，正如此例首次选框 2 和框 9。

</ExamExplanation>

</ExamSolution>

## 2012 年第 45 题

<ExamQuestion>

**79. 2012 年第 45 题**

某请求分页系统采用如下局部页面置换策略：系统从 0 时刻开始扫描，每隔 5 个时间单位扫描一轮驻留集（扫描时间忽略不计）。本轮没有被访问过的页框将被系统回收，并放到空闲页框链尾；其中的内容在下一次被重新分配之前不清空。当发生缺页时，如果该页曾被使用过且仍在空闲页框链表中，则将其重新放回该进程的驻留集中；否则，从空闲页框链表头部取出一个页框。

不考虑其他进程的影响和系统开销。初始时进程驻留集为空，系统空闲页框链表中的页框号依次为

$$
32,\ 15,\ 21,\ 41.
$$

进程 P 依次访问的 $\langle\text{虚拟页号},\text{访问时刻}\rangle$ 为

$$
\langle1,1\rangle,
\langle3,2\rangle,
\langle0,4\rangle,
\langle0,6\rangle,
\langle1,11\rangle,
\langle0,13\rangle,
\langle2,14\rangle.
$$

请回答：

1. 访问 $\langle0,4\rangle$ 时，对应的页框号是多少？
2. 访问 $\langle1,11\rangle$ 时，对应的页框号是多少？说明理由。
3. 访问 $\langle2,14\rangle$ 时，对应的页框号是多少？说明理由。
4. 该策略是否适合时间局部性好的程序？说明理由。

<ExamSolution>

<ExamAnswer>

1. 访问页 0（$t=4$）时使用 **21 号页框**。
2. 访问页 1（$t=11$）时重新取回 **32 号页框**，其内容尚未被其他页覆盖。
3. 访问页 2（$t=14$）时从空闲链表头取得 **41 号页框**。
4. **适合时间局部性较好的程序**：短时间内重新访问的旧页可能仍在空闲链中保留原内容，从而避免外存读页；但是否实际避免磁盘读取，取决于该页框是否尚未被复用。

</ExamAnswer>

<ExamExplanation>

### 一、辨别这道题和普通 FIFO、LRU 置换的区别

题目的算法是**周期扫描 + 先回收后复用的页框链表**，并非按访问顺序直接从驻留集中选择 FIFO/LRU 牺牲页。关键是：

- 每 $5$ 个时间单位发生一次扫描，即 $t=5,10,15,\ldots$；扫描时间忽略。
- 若某页在上一扫描区间**一次都未访问**，本次扫描将其从进程驻留集移出，并把原页框**追加到空闲链尾**。
- 被回收不意味着立即擦除原数据：只要尚未重新分配，该页仍可从空闲链中**按原页框回收**，无需从外存重新装入。
- 从未访问或原页框已复用的页需要从**空闲链首**分配页框。

容易混淆的地方在于：“已经不属于驻留集”和“内容必须从磁盘重新读取”不是同一回事。这类保留旧内容的空闲页框可视作一个短期缓冲区。

### 二、完整事件表：每一步写出驻留页、空闲链

记 $p\mapsto f$ 为虚拟页 $p$ 占用页框 $f$。$t=5$ 扫描后访问标记清零，以统计下一轮是否被引用。

| 时刻 | 事件 | 扫描或访存后的进程驻留页 | 空闲页框链（队首 $\to$ 队尾） |
| --- | --- | --- | --- |
| 初始 | 尚未访问 | $\varnothing$ | $32\to15\to21\to41$ |
| $1$ | 访问页 1，首次调入 | $1\mapsto32$ | $15\to21\to41$ |
| $2$ | 访问页 3，首次调入 | $1\mapsto32,3\mapsto15$ | $21\to41$ |
| $4$ | 访问页 0，首次调入 | 增加 $0\mapsto21$ | $41$ |
| $5$ | 扫描：页 1、3、0 在本轮均曾访问，无回收 | $1,3,0$ 均驻留；清除本轮引用记录 | $41$ |
| $6$ | 再访问页 0 | $1,3,0$ 均驻留；页 0 记录本轮访问 | $41$ |
| $10$ | 扫描：页 1、3 本轮未使用 | 仅保留 $0\mapsto21$ | $41\to32\to15$ |
| $11$ | 再访问页 1 | 恢复 $1\mapsto32$，不需占用队首页框 | $41\to15$ |
| $13$ | 再访问页 0 | 仍为 $0\mapsto21$ | $41\to15$ |
| $14$ | 首次访问页 2 | 增加 $2\mapsto41$ | $15$ |

**注意**：$t=10$ 的回收顺序即使采用题意给定的驻留集扫描顺序，所求 $t=14$ 的队首仍为原先未用过的 $41$；不能误把“页 1 对应框 32”理解成此时队首是 32。

### 三、每一问为何得到这些页框号

**第（1）问。** $t=1$、$2$ 已从链首分别取走 32 和 15；$t=4$ 下一空闲队首自然是 $21$。

**第（2）问。** 在 $(5,10]$ 这一轮没有访问页 1，故 $t=10$ 时它被回收并带着旧内容排队。$t=11$ 时并非机械地弹出队首 $41$，而是**优先从链中找到页 1 的原页框 32**，因此得到 32，并从空闲链中删除该节点。

**第（3）问。** 页 2 从未访问，在空闲链也没有它的旧副本，因而必须取队首 $41$，与上问“复活旧页”机制不同。

### 四、时间局部性和真正缺页的微妙区别

时间局部性说的是：刚被访问的数据在较短时间内很可能再次访问；题目策略通过**延迟覆盖空闲页框内容**保存了这种“近期旧页”的重用机会。如果页框在被复用前再次命中旧内容，所需操作可以省去磁盘读取，但仍可能需要更新驻留集与页表、撤销空闲链项。因此“无磁盘 I/O”不表示“无需任何软件或地址变换开销”。

若访问间隔很长、空闲链中的原页框已被其他页面占用，则必须重新从外存装入。不能武断地说“回收后再次访问永远无缺页开销”。

### 五、这类综合题的解题技巧

按时间升序建立**事件驱动表**，把周期扫描单独插入时间轴；分别维护“驻留集”“最近一次扫描以来的访问位”和“空闲链”；回收时**追加链尾**；再次访问已回收的旧页时先判断旧内容是否仍在**未被复用的空闲框**中。**禁止将空闲链自动看成 LRU 队列。**

3. 虚拟页号 8、9 的页表项物理地址分别为 `00200020H`、`00200024H`；页框号为 `00900H`、`00901H`；代码第 2 页物理起始地址为 **`00901000H`**。

<ExamExplanation>

### 一、先画地址切分图，而不要直接背页表大小

32 位字节编址、每页偏移占 12 位：

```text
线性地址（一级页表）    [ 虚拟页号 20 位 | 页内偏移 12 位 ]
线性地址（二级页表）    [ 目录号 10 位 | 表内索引 10 位 | 页内偏移 12 位 ]
```

因此页大小 $2^{12}=4096\text{ B}$，页内偏移范围为 `000H` 至 `FFFH`。一级页表的表项数是 $2^{20}$，每项 4 字节，则

$$
S_{\mathrm{single}}=2^{20}\times4=2^{22}\text{ B}=4\text{ MiB}.
$$

**这是最大（完整）一级页表规模**，不是某个程序已实际占用的代码页数；若题目改问“二级页表实际占用”，则按已经分配的二级页表页数计算，不能沿用固定 4 MiB。

### 二、10-10-12 的按位运算模板

虚拟地址 `LA` 转换为无符号 32 位数后：

```c
uint32_t dir    = ((uint32_t)LA >> 22) & 0x3FFu;
uint32_t index  = ((uint32_t)LA >> 12) & 0x3FFu;
uint32_t offset =  (uint32_t)LA        & 0xFFFu;
```

由于 `LA` 本身最多 32 位，取最高 10 位的 `dir` 可省略 `& 0x3FF`，但提取中间 10 位 `index` **必须掩码**，否则移出的高位页目录号也留在结果里。

地址转换的硬件过程通常是：页目录基址寄存器定位页目录（PDE）→ 按目录号读出二级页表物理基址 → 按表内索引读出 PTE → 由页框号和原偏移拼接物理地址。TLB 命中可以跳过内存中的页表行走，题目此处只考字段切分。

### 三、代码段对应的页号与页表项物理地址

给出的代码段起始虚址为 `00008000H`，长度 $8\text{ KiB}=2\times4096$ 字节，恰在页边界开始：

| 代码页次序 | 虚拟页号（VPN） | 对应虚址范围 | PTE 物理地址 |
| --- | ---: | --- | --- |
| 第 1 页 | 8 | `00008000H`—`00008FFFH` | `00200020H` |
| 第 2 页 | 9 | `00009000H`—`00009FFFH` | `00200024H` |

一级页表在物理地址 `00200000H` 开始，每条表项 4 B，因而

$$
\begin{aligned}
\mathrm{PTEaddr}(8)&=\texttt{00200000H}+8\times4=\texttt{00200020H},\\
\mathrm{PTEaddr}(9)&=\texttt{00200000H}+9\times4=\texttt{00200024H}.
\end{aligned}
$$

**切忌混淆**：VPN 8、9 是页表项下标；`00200020H` 等是**页表项存放位置**，它们并不是程序指令的物理地址。

### 四、页框号与代码页的物理地址

题目特别指出代码段被放在**连续**物理空间，起始物理地址 `00900000H`，于是

$$
\begin{aligned}
\mathrm{PFN}_1&=\texttt{00900000H}\,/\,\texttt{1000H}=\texttt{00900H},\\
\mathrm{PFN}_2&=\mathrm{PFN}_1+1=\texttt{00901H}.
\end{aligned}
$$

由页框号和零偏移拼成代码第 2 页的物理起始地址：

$$
\mathrm{PA}_2=\texttt{00901H}\times\texttt{1000H}=\boxed{\texttt{00901000H}}.
$$

**重要前提**：一般分页存储并**不要求相邻虚拟页在物理内存连续**，本题之所以可以 `PFN+1`，只因为显式给了“连续装载”条件。

### 五、拓展边界判断

若代码从 `00008FF0H` 开始且长度仍为 8 KiB，其结束位置跨越虚拟页 8、9、10，总共占 **3 页**。通用计算式：

$$
N=\left\lfloor\frac{a+L-1}{P}\right\rfloor-\left\lfloor\frac{a}{P}\right\rfloor+1,
$$

其中 $a$ 为首地址，$L>0$ 为字节数，$P$ 为页大小。这比单纯计算 $\lceil L/P\rceil$ 更适合处理非对齐段。

某计算机系统按字节编址，采用二级页表的分页存储管理方式，虚拟地址格式如下：

<ExamSolution>

<ExamAnswer>

1. 页和页框均为 $2^{12}=4096\text{ B}$；共有 $2^{20}$ 个虚拟页。
2. 页目录占 $1$ 页，最多 $2^{10}=1024$ 张二级页表，每张占 $1$ 页；共 **1025 页**。
3. 只需同一个二级页表：两地址的页目录号均为 **4**。其表内索引分别为 **0** 和 **274**（十六进制 `112H`）。

</ExamAnswer>

<ExamExplanation>

### 一、二级分页的三个单位

给定地址分段 `10 位目录号 / 10 位表索引 / 12 位偏移`：

$$
\begin{aligned}
P&=2^{12}=4096\text{ B},\\
\#\mathrm{VPN}&=2^{10+10}=2^{20},\\
\#\mathrm{PDE}&=2^{10}=1024,\\
\#\mathrm{PTE/table}&=2^{10}=1024.
\end{aligned}
$$

页、页框的**容量一样**，前者属于虚拟地址空间，后者属于物理内存。虚拟页号是目录号和表内索引的组合，不要把“表内索引 10 位”误当成整个进程只有 $2^{10}$ 个虚拟页。

### 二、1025 是最大占用，不是程序启动必然分配的大小

表项占 4 B，故页目录和一张二级页表均为

$$
1024\times4\text{ B}=4096\text{ B}=1\text{ 页}.
$$

完整覆盖整个 32 位虚拟地址空间时需要 $1024$ 张二级表，再加一个页目录：

$$
N_{\mathrm{table}}=1+1024=\boxed{1025\text{ 页}},
\qquad S_{\max}=1025\times4096\text{ B}.
$$

核心节省点是**按需分配二级页表**：如果进程仅用到一个页目录项覆盖的虚拟区间，在不考虑额外系统结构的条件下，只需 $1+1=2$ 页，而非 1025 页。题设“最多”与“最少/实际”不可混用。

### 三、两个虚拟地址的目录号和索引都算出来

$$
\mathrm{dir}(VA)=VA\gg22,\quad
\mathrm{index}(VA)=(VA\gg12)\mathbin{\&}\texttt{0x3FF}.
$$

| 虚拟地址 | 目录号 | 二级表索引 | 页内偏移 |
| --- | ---: | ---: | ---: |
| `01000000H` | $4$ | $0$ | `000H` |
| `01112048H` | $4$ | $274=\texttt{112H}$ | `048H` |

$$
1024\times4096\text{ B}=4\text{ MiB}
$$

的连续虚拟地址区间；目录号为 4 的区间是 `01000000H`—`013FFFFFH`，题目两个地址都在该区间内。

**关键区别**：“涉及 1 张二级页表”不代表“访问 1 个页表项”——实际需要查询两个不同的 PTE（索引 0 和 274），也不代表这两个页面在物理内存连续。

### 四、同类考法迁移

遇到若干虚拟地址，优先按 $4\text{ MiB}$ 为块求目录号，或直接右移 22 位；随后按 4 KiB 求页内偏移。若加入 TLB，只有在明确给出命中信息后才能计算实际页表行走次数；题目问“涉及多少张二级页表”不等于问访存次数、页故障次数。

**89. 2017 年第 45 题**

假定计算机 M 采用二级分页虚拟存储管理方式，虚拟地址格式如下：

00401020  55  push ebp

最后一条 `ret` 指令位于 `0040107FH`。

请回答：

1. 函数 `f1` 的机器指令代码占多少页？
2. 取第 1 条指令 `push ebp` 时，若地址变换过程中需要访问内存中的页目录和页表，则分别访问页目录和对应页表的第几个表项（编号从 0 开始）？

<ExamSolution>

<ExamAnswer>

1. `f1` 的指令代码全部落在 `00401000H`—`00401FFFH`，只占 **1 页**。
2. 取地址 `00401020H` 上的 `push ebp` 时，使用页目录**第 1 项**，以及该目录所指二级页表的**第 1 项**，索引均从 0 开始。
3. 如果 `scanf()` 需要等待尚未到达的键盘输入，则 P 依次经历 **运行态 $\to$ 阻塞态 $\to$ 就绪态 $\to$ 运行态**。CPU 执行 I/O 系统调用、处理中断时会进入**内核态**；若输入早已在系统缓冲区，可能不经历阻塞。

</ExamAnswer>

<ExamExplanation>

### 一、代码长度与跨页判断不要混为一谈

`f1` 的第一条机器指令位于 `00401020H`，最后一条 `ret` 位于 `0040107FH`。在已给出的机器码表中最后的 `ret` 是 1 字节，故总机器代码占用地址数为

$$
\texttt{0040107FH}-\texttt{00401020H}+1=\texttt{60H}=96\text{ B}.
$$

即使不知道具体长度，单看两端的虚拟页号即可判断：

$$
\begin{aligned}
\mathrm{VPN}_{\text{start}}&=\texttt{00401020H}\gg12=\texttt{401H},\\
\mathrm{VPN}_{\text{end}}&=\texttt{0040107FH}\gg12=\texttt{401H}.
\end{aligned}
$$

均在 `00401000H`—`00401FFFH`，所以只占 **1 个虚拟页**。指令数、机器码字节数和代码页数不是同一量；特别是**变长指令可能跨页**，不能只按指令条数乘以固定指令长度。

### 二、完整地址分解：目录 1、表索引 1、偏移 020H

对第 1 条指令地址 `00401020H`：

$$
\begin{aligned}
\mathrm{PDI}&=(\texttt{00401020H}\gg22)=1,\\
\mathrm{PTI}&=(\texttt{00401020H}\gg12)\mathbin{\&}\texttt{3FFH}=1,\\
\mathrm{OFF}&=\texttt{00401020H}\mathbin{\&}\texttt{FFFH}=\texttt{020H}.
\end{aligned}
$$

硬件先由页目录基址定位页目录的第 1 项，取得该二级页表的**物理基址**，再访问该页表第 1 项，最后由页框号和 `020H` 拼装物理地址。若 TLB 命中，通常无需真正从内存读 PDE/PTE；原题加了“若地址变换过程中需要访问内存页目录和页表”的前提。

### 三、`scanf()` 的同步输入为何可能使进程阻塞

按题设键盘中断驱动 I/O、且输入数据尚未就绪的常见过程：

1. P 在用户态执行到 `scanf()`，经库函数最终请求内核 I/O 服务，发生**系统调用/陷入**，CPU 切为内核态。
2. 内核发现所需输入尚未准备好，将 P 放到相应事件等待队列：$\text{运行}\to\text{阻塞}$；调度其他进程。
3. 键盘事件到达，CPU 响应**硬件中断**并在内核态执行驱动/中断处理，接收字符并满足等待条件。
4. 内核把 P 唤醒：$\text{阻塞}\to\text{就绪}$；这一步**不是**立刻必然运行。
5. 调度器选中 P 后：$\text{就绪}\to\text{运行}$，系统调用返回，继续执行 `f1`。

**容易丢分的对比**：系统调用是进程主动进入内核的同步陷入；输入完成中断由外设异步产生。进程阻塞、CPU 内核态、进程再被调度是三个不同层面的概念，不能把“CPU 内核态”说成 P 变为内核态进程。

### 四、边界考法与反例

若输入已在缓冲区、`scanf()` 立即返回，则没有必要阻塞。若函数代码从 `00401FFEH` 开始，后面还有长度为 4 字节的指令，其字节地址跨 `00401FFFH`/`00402000H` 两页，即使只是一条指令也可能触及两页。对跨页取指需分别检查相关页的地址映射和权限；有一个目标页缺失时可产生缺页异常并在故障处理后重新执行。

$$
\begin{aligned}
VA&=6\times2^{22}+6\times2^{12}+8\\
&=\texttt{01800000H}+\texttt{00006000H}+\texttt{00000008H}\\
&=\boxed{\texttt{01806008H}}.
\end{aligned}
$$

逆向验算：`01806008H >> 22 = 6`；`(01806008H >> 12) & 3FFH = 6`；低 12 位为 `008H`。**目录号为 6 并不是虚拟页号为 6**，真实虚拟页号是 $(6\ll10)+6=6150$。

### 二、为何页目录基址必须是物理地址

页目录本身是地址转换的数据结构。如果 PDBR 保存一个还需要分页转换的虚拟地址，而地址转换又依赖 PDBR，便会产生“先转换页目录基址才能找到页目录”的递归依赖。因此传统分页硬件中的 PDBR/页表基址寄存器指明的是**物理地址**（实际架构可能在低位附带控制标志，题目只考基址语义）。

进程 A 与 B 在通常情况下有不同的页目录，执行进程地址空间切换需装入相应 PDBR；同一进程的线程共享代码段、堆和虚拟地址空间，所以仅切线程通常不改变 PDBR。**例外与条件**：不同进程可以特意共享页表/地址空间，内核线程等实现细节也可能变化；本题按典型独立进程地址空间模型回答。

### 三、PDBR 更新与 TLB 失效是两个问题

从 A 切到 B 后，虚拟页号相同也可能映射到不同物理页框。若 TLB 项不区分进程地址空间，切换后需要失效旧项；若支持 ASID/PCID 等地址空间标识，则可保留不同地址空间的 TLB 项并按标识查找。**不能据“PDBR 变化”推导“TLB 一定全部清空”**。反过来，同一进程内线程切换通常既不改变页目录，也无需因地址空间更换而整体清空 TLB。

### 四、改进型 CLOCK 为什么需要 R、M 两位

四类候选页：

| $(R,M)$ | 含义 | 典型淘汰优先级 |
| --- | --- | --- |
| $(0,0)$ | 最近未用、未修改 | 优先：无需回写 |
| $(0,1)$ | 最近未用、已修改 | 次选：可能需回写 |
| $(1,0)$ | 最近用过、未修改 | 通常暂不给换出 |
| $(1,1)$ | 最近用过、已修改 | 通常暂不给换出 |

某些实现会多轮扫描并清访问位，使 $(1,0)$、$(1,1)$ 逐步变成可选候选页；题目问的是**至少要提供的页表状态字段**，具体扫描次序依选定的改进 CLOCK 实现而定，不应把不同教材伪代码混用。普通 CLOCK 主要靠 $R$ 位给第二次机会，改进型 CLOCK 再考虑 $M$ 位以降低回写代价。

### 五、典型错因

- 把“逻辑地址字段”直接当作物理页框号，忽略两级页表转换；
- 把不同线程视作不同进程，以为切换同进程线程就必须换 PDBR；
- 把 $R=0$ 等同于“已经很久没用”、$M=1$ 等同于“不能换出”：二者都不成立；
- 误认修改位只有软件访问文件时才置位——CPU 向页面写入也会使页变脏。

| --- | ---: | ---: | ---: |
| A | 0 | 1 | 1 |
| B | 1 | 0 | 1 |
| C | 2 | 1 | 0 |
| D | 3 | 0 | 0 |

明确采用下列**改进型 CLOCK** 规则：第一轮自指针开始环扫，找第一个 $(R,M)=(0,0)$，此轮**不改位**；若不存在，则第二轮自指针开始找第一个 $(0,1)$，且在本轮**遇到 $R=1$ 的页框时将 $R$ 清零**；若仍不存在，再重复两轮。找到牺牲页后装入新页，新页访问位置 1、修改位置 0，指针移至被替换页框之后。

1. 两次缺页分别替换哪个原页、使用哪个页框？
2. 每次完整列出实际扫描到的页框顺序，并求第二次替换后指针位置；

<ExamAnswer>

- 第一次第一轮依次检查 **A、B、C、D**，在 D 找到 $(0,0)$，淘汰页 **3**，装页 4 至 D；指针改为 A，**不需要回写**。
- 第二次第一轮 A、B、C、D 均不满足 $(0,0)$；第二轮从 A 开始清 A 的访问位后，到 B 发现 $(0,1)$，淘汰页 **1**，装页 5 至 B；指针改为 C，**需要回写**。

<ExamExplanation>

**五、与普通 CLOCK 对照**：普通 CLOCK 从 A 检查 $R=1$ 就清零并向后，接着 B 的 $R=0$，立即换 B。改进型 CLOCK 在第一轮直接找到清洁的 D，避免了一次脏页回写。两者优化目标不同，解题时必须在答题纸上逐步写出“指针、R/M、是否清位、被替换框”，不能只凭“最近没访问”的直觉选页。

<ExamExplanation>

### 一、先列出题目隐藏的三个大小关系

该机器的地址字段为 `10 位页目录号 | 10 位页表索引 | 12 位页内偏移`，页大小

$$
P=2^{12}=4096\text{ B}=4\text{ KiB}.
$$

一个数组元素 4 B，一行 1024 个元素，所以

$$
\text{每行大小}=1024\times4=4096\text{ B}=P.
$$

整张数组共有 1024 行，故数组总字节数为 $1024\times4096=2^{22}\text{ B}=4\text{ MiB}$，在页对齐起始地址 `10800000H` 下恰好跨 **1024 个虚拟页**；但“1024 个页”与“1024 个页框连续”不是一回事。

### 二、按行优先计算虚拟地址，避免颠倒下标

C 语言二维数组 `a[i][j]` 的元素地址（从零开始）为

$$
VA(a[i][j])=VA(a[0][0])+(i\times N_{\rm col}+j)\times S,
$$

其中 $N_{\rm col}=1024$，元素大小 $S=4$ B。因此

$$
\begin{aligned}
\Delta &= (1\times1024+2)\times4=4104_{10}=\texttt{1008H},\\
VA &=\texttt{10800000H}+\texttt{1008H}
=\boxed{\texttt{10801008H}}.
\end{aligned}
$$

**不能**把 `a[1][2]` 的第一个下标当作列下标，也不能先把下标乘以页大小再乘以元素大小——只有一整行恰好为一页才使“行号加到虚页号”成为快捷办法。

### 三、虚拟页号、PDE 位置与 PTE 位置是三种不同概念

将 32 位虚拟地址按 10/10/12 切分：

```text
VA = 10801008H
目录号       (VA >> 22)                = 042H
二级表索引   ((VA >> 12) & 3FFH)       = 001H
页内偏移     (VA & FFFH)              = 008H
```

每个 PDE 和 PTE 都是 4B，因此

$$
\begin{aligned}
PA(\text{PDE})&=\texttt{00201000H}+\texttt{042H}\times4
=\boxed{\texttt{00201108H}},\\
\text{二级页表基址}&=\texttt{00301H}\times\texttt{1000H}
=\texttt{00301000H},\\
PA(\text{PTE})&=\texttt{00301000H}+\texttt{001H}\times4
=\boxed{\texttt{00301004H}}.
\end{aligned}
$$

| 量 | 本题结果 | 用来做什么 |
| --- | --- | --- |
| 目录号 `042H` | 选中页目录中的 PDE | 确定二级页表存放处 |
| PDE **物理地址** `00201108H` | 保存 PDE 的内存单元位置 | 读取页框号 `00301H` |
| 二级索引 `001H` | 选中目标 PTE | 找到数组元素所在虚拟页的页框号 |
| PTE **物理地址** `00301004H` | 保存 PTE 的内存单元位置 | **不是**数组元素的物理地址 |
| 页内偏移 `008H` | 保持不变 | 与实际数据页框号拼接 |

题目只给出了 **二级页表页** 的页框号，并未提供 `a[1][2]` 的数据页 PTE 所记录的页框号，因此**不能计算元素自身的最终物理地址**。这一点尤其容易在第（1）问中混淆。

### 四、虚拟连续、物理离散与局部性

同一 C 数组按行优先连续存储，元素的逻辑/虚拟地址从起点线性增长；操作系统可把虚页 `10800H`、`10801H`、……映射到完全不相邻的物理页框。页表建立的是**逐页映射**，而不是把每个二维数组的行强制放到相邻的物理页。

按行遍历：连续访问同一行的 1024 个元素，访问一个页后有强空间局部性；按列遍历：先访问第 0 行某一列，再访问第 1、2、……行同一列，相邻访问步长为 $1024\times4=4096$ B，恰好跨页。在物理可用页框数、TLB 容量不足时，按列可能形成严重的抖动；如果全部页都驻留并在 TLB 中有足够表项，**不能简单断言按列一定发生更多缺页**，题目只问一般的局部性优劣。

### 五、快速验算与迁移

1. 地址偏移 `1008H` 正好等于一页 `1000H` 加两元素 `8H`。
2. `10801008H` 的末三位为 `008H`，符合第 2 个元素的字节偏移。
3. `042H×4=108H`，`001H×4=4H`，两级表项地址计算均为“**相应表的物理基址 + 表索引×表项大小**”。
4. 若一行不是整页，判断跨页次数必须用 `$\lfloor(\text{起点偏移}+\text{长度}-1)/P\rfloor$`，不能再把“每行=每页”当成普遍规律。

<ExamAnswer>

1. `a[2][3]` 虚拟地址为 **`1080200CH`**；目录号 `042H`，表内索引 `002H`，PDE 地址 **`00201108H`**，PTE 地址 **`00301008H`**。

</ExamAnswer>

<ExamExplanation>

**一、定位一个二维数组元素。** $a[i][j]$ 的字节偏移为 $(i\times1024+j)\times4$。故

$$
VA(a[2][3])=\texttt{10800000H}+ (2\times1024+3)\times4=\boxed{\texttt{1080200CH}}.
$$

页大小 $2^{12}=4096$ B，故 `VA >> 22 = 042H`、`(VA >> 12) & 3FFH = 002H`、偏移 `00CH`。按表项大小 4B：

$$
\begin{aligned}
PA(\mathrm{PDE})&=\texttt{00201000H}+\texttt{042H}\times4=\boxed{\texttt{00201108H}},\\
PA(\mathrm{PTE})&=(\texttt{00301H}\ll12)+\texttt{002H}\times4=\boxed{\texttt{00301008H}}.
\end{aligned}
$$

PTE **存放的位置**不等于该元素的最终物理地址，后者还取决于 PTE 中的数据页框号。

**二、按行遍历：每页只需首次装入。** 行 0 的 1024 次访问均在同一页；行 1 同理。由于循环只向后走，不再返回上一行，即使驻留集容量仅 2 页，每行最多一次缺页：$4\times1=\boxed{4}$ 次。

**三、按列遍历：产生循环“完全淘汰”。** 每列访问次序为行 0、1、2、3；访问的页号顺序

```text
0,1,2,3,  0,1,2,3,  ... （共重复 1024 轮）
```

每次访问都与前一次访问的页不同，而在容量 2 的 LRU 驻留集中，每个页再次被访问前恰好已经经过 3 个其他不同页的访问；因此在再次访问它之前必被淘汰。每列 4 次缺页、共 1024 列：

$$
N_{\rm column}=4\times1024=\boxed{4096}.
$$

两次试验的驻留集必须**各自从空状态开始**，否则两种访问次序不能公平比较。

**四、局部性不等于缺页数恒定。** 按行通常利用空间局部性，按列步长为一整页，易增加 TLB miss、Cache miss 和工作集需求。但**缺页次数依赖驻留页数量及初始驻留状态**：若提供至少 4 个页框并在访问前全部装入数组页，则两种遍历都不会有数据页缺页。考题答“哪种局部性更好”与答“具体缺页几次”所需的条件并不相同。

</ExamAnswer>

<ExamExplanation>

### 一、为什么页大小 4 MiB 会改变整套地址拆分

$$
4\text{ MiB}=4\times2^{20}\text{ B}=2^{22}\text{ B}.
$$

因此对于 32 位虚拟地址，只有 $32-22=10$ 位虚拟页号；整个虚拟地址空间至多有 $2^{10}=1024$ 页。每个页表项 4B，单级页表共需 $1024\times4=4096$ B（仅 **4 KiB**）；这里**页表本身远小于一个 4 MiB 的数据页**。别把页表大小误认成页大小。

固定分解式：

$$
\mathrm{VPN}=VA\gg22,\qquad
\mathrm{OFF}=VA\mathbin{\&}\texttt{3FFFFFH},\qquad
VA=(\mathrm{VPN}\ll22)+\mathrm{OFF}.
$$

### 二、第（1）问：以数据页的 VPN 去定位 PTE

对 `12345678H`，

$$
\mathrm{VPN}=\texttt{048H},\qquad \mathrm{OFF}=\texttt{345678H}.
$$

页表开始的**虚拟地址**是 `B8C00000H`，PTE 为第 72 项（从 0 计数），所占字节偏移为

$$
\texttt{048H}\times4=\texttt{120H}.
$$

本题又明确**整张页表连续装载**于以 `65400000H` 为起始的物理区域，所以相同的字节偏移同时适用于表项的虚、实地址：

$$
\begin{aligned}
VA(\mathrm{PTE})&=\texttt{B8C00000H}+\texttt{120H}
=\boxed{\texttt{B8C00120H}},\\
PA(\mathrm{PTE})&=\texttt{65400000H}+\texttt{120H}
=\boxed{\texttt{65400120H}}.
\end{aligned}
$$

注意：**PTE 的物理地址**和**该 PTE 指向的数据页物理地址**不是同一个地址。题目问“新填入页表项中的页框号”，此时要利用缺页处理完成后的数据地址 `BAB45678H`，取高 10 位：

$$
\mathrm{PFN}=\texttt{BAB45678H}\gg22=\boxed{\texttt{2EAH}}.
$$

再逆向还原：`2EAH × 400000H + 345678H = BAB45678H`。这说明页内偏移在地址转换中保留，改变的是页号到页框号的映射。

### 三、第（2）问：页表页自身也有虚拟页号

页表从 `B8C00000H` 开始，它的页号为

$$
\mathrm{VPN}_{\mathrm{table}}=\texttt{B8C00000H}\gg22
=\boxed{\texttt{2E3H}}.
$$

页号 `2E3H` 自身在页表中对应第 `2E3H` 项，所以其页表项虚拟地址是

$$
VA(\mathrm{PTE}_{\mathrm{table}})
=\texttt{B8C00000H}+\texttt{2E3H}\times4
=\boxed{\texttt{B8C00B8CH}}.
$$

页表所在页已知从 `65400000H` 物理地址开始，物理页框号为

$$
\mathrm{PFN}_{\mathrm{table}}=\texttt{65400000H}\gg22
=\boxed{\texttt{195H}}.
$$

| 本题对象 | 虚拟页号 | 对应页框号 | 数据源 |
| --- | --- | --- | --- |
| 正在发生缺页的数据页 | `048H` | `2EAH` | 缺页后物理地址 `BAB45678H` |
| **存储页表的**虚拟页 | `2E3H` | `195H` | 页表物理基址 `65400000H` |

两组编号分别描述“被转换的页”和“用来存转换表的页”，切忌串用。

### 四、为什么没有无限的“页表的页表”递归

页表可被映射到某个虚拟页，**不代表硬件做地址转换时必须先用虚拟地址寻找这张页表**。传统页表基址寄存器保存的是硬件可直接定位的页表**物理基址**，硬件由此完成页表行走。页表的虚拟地址映射用于操作系统或进程在相应权限下访问、修改页表，而非替代硬件已经掌握的物理入口。

### 五、解题技巧及边界条件

- 先从页大小推出偏移位数，再算 `>> 22`，不要直接沿用常见 4 KiB 页的 `>> 12`。
- 用“PTE 在表中的下标 × 表项字节数”求 **PTE 存储地址**，用 “物理数据地址 >> 22” 求 **PFN**。
- 本题物理 PTE 地址之所以能用基址加偏移，是因为题目明确保证页表**连续装载**且开始地址对齐；若页表跨页并映射到不连续物理页框，这种简单线性相加就不再成立。

某 32 位机器以 4 MiB 为页大小，单级页表共有 1024 个 4B PTE（页表占 4096 B）。页表从**虚拟地址 `B8FFFF00H`** 开始，因此跨两个虚拟大页。已知页表所在的前一虚拟页 `B8C00000H`—`B8FFFFFFH` 映射到物理页框基址 `65400000H`；后一虚拟页 `B9000000H`—`B93FFFFFH` 映射到物理页框基址 `ABC00000H`。这两张物理大页均已驻留且可被访问。

1. 求页表第 63、64、72 项（下标从 0 开始）的**虚拟地址**和**物理地址**。
2. 对被转换的虚拟地址 `12345678H`，应读取页表中哪一项？其 PTE 的物理地址是多少？
3. 能否直接用“前一物理页基址 `65400000H` + 72×4”求第 72 项地址？说明根本原因。

<ExamSolution>

<ExamAnswer>

| PTE 下标 | PTE 虚拟地址 | PTE 物理地址 |
| ---: | --- | --- |
| 63 | `B8FFFFFCH` | `657FFFFCH` |
| 64 | `B9000000H` | `ABC00000H` |
| 72 | `B9000020H` | `ABC00020H` |

`12345678H` 的 VPN 为 `048H`，即第 **72 项**，PTE 的物理地址为 **`ABC00020H`**。不能把虚拟地址连续简单等同于物理地址连续。

<ExamExplanation>

**一、先求页表相对偏移，再加页表虚拟首址。** 第 $k$ 项相对偏移为 $4k$ B：

$$
\begin{aligned}
VA_{63}&=\texttt{B8FFFF00H}+\texttt{FCH}=\texttt{B8FFFFFCH},\\
VA_{64}&=\texttt{B8FFFF00H}+\texttt{100H}=\texttt{B9000000H},\\
VA_{72}&=\texttt{B8FFFF00H}+\texttt{120H}=\texttt{B9000020H}.
\end{aligned}
$$

注意 4 MiB 大页边界在 `B8FFFFFFH` 和 `B9000000H` 之间，第 63 项的最后 4 字节刚好收尾，第 64 项已经属于另一虚拟页。

**二、按虚拟页分别映射页内偏移。** 前一页的物理基址为 `65400000H`，后一页的物理基址为 `ABC00000H`；两张页不连续。

$$
\begin{aligned}
PA_{63}&=\texttt{65400000H}+\texttt{3FFFFCH}=\boxed{\texttt{657FFFFCH}},\\
PA_{64}&=\texttt{ABC00000H}+\texttt{000000H}=\boxed{\texttt{ABC00000H}},\\
PA_{72}&=\texttt{ABC00000H}+\texttt{000020H}=\boxed{\texttt{ABC00020H}}.
\end{aligned}
$$

**三、为什么访问 `12345678H` 要用第 72 项。** 页大小 $2^{22}$ B，其高 10 位为 VPN，

$$
\texttt{12345678H}\gg22=\texttt{048H}=72.
$$

VPN 在页表中选第 72 项；由于页表**虚拟**起始地址靠近大页边界，第 72 项物理上落入后一物理页。

**四、辨别题目提供的是“映射关系”还是“页表连续物理装载”。** 原 2024 真题明确给出整张页表被连续装到一个物理区域，故可以由物理基址加表项偏移；本变式只给出两段**分别映射**的虚拟页，不能越过边界直接沿用物理基址加全局偏移。概念上，“虚拟连续”“物理连续”“同一页框内连续”是三种不同保证。

## 2025 年第 46 题

<ExamQuestion>

**106. 2025 年第 46 题**

某进程的虚拟地址空间如下图，阴影部分表示未占用区域。现有 C 程序：

<img src="/img/408/past-exams-large-questions/03-操作系统/assets/2025-46-figure-001.svg" alt="2025 年第 46 题进程虚拟地址空间" />

```c
char *ptr;

void main() {
    int length;
    ptr = (char *)malloc(100);
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```

1. 程序执行时，PCB 位于哪个区域？执行 `scanf()` 等待键盘输入时，该进程处于什么状态？
2. `main()` 函数的代码位于哪个区域？其直接调用的哪些函数的功能需要通过执行设备驱动程序实现？
3. 变量 `ptr` 被分配在哪个区域？若 `length` 没有被分配到寄存器中，它被分配在哪个区域？`ptr` 指向的字符串位于哪个区域？

<ExamSolution>

<ExamAnswer>

1. PCB 由内核维护，位于**操作系统内核区**；当 `scanf()` 需要等待尚未就绪的键盘输入时，进程进入**阻塞态**。
2. `main()` 的机器指令位于**只读代码段**；它直接调用的函数中，`scanf()` 和 `printf()` 的输入/输出功能通常需要通过设备驱动和内核 I/O 路径实现。
3. 全局变量 `ptr` 位于**读/写数据段**（精确地说，未显式初始化的 `ptr` 通常位于 BSS）；若 `length` 未被寄存器优化，通常位于**用户栈**；`ptr` 所指向的 `malloc(100)` 存储块位于**堆**。

</ExamAnswer>

<ExamExplanation>

### 一、先按“存储期、对象性质、指针的值”判断位置

| 对象 | 寿命与用途 | 在题图中的区域 | 理解陷阱 |
| --- | --- | --- | --- |
| PCB | 内核管理的进程控制结构 | 内核区 | 不等同于用户栈上的变量 |
| `main()` 指令 | 可执行指令 | 只读代码段 | 函数栈帧不是函数机器指令 |
| 全局 `char *ptr` **变量本身** | 静态存储期，可保存地址 | 可读写静态数据区（常为 BSS） | `ptr` 本身不在堆里 |
| 局部 `int length` | 自动存储期 | 通常在用户栈（如果未放寄存器） | 标准 C 不保证每个局部变量都有独立栈槽 |
| `malloc(100)` 的 100B 对象 | 动态存储期 | 堆（典型进程布局） | 不是指针变量所处的地址 |
| `strlen`、`scanf` 等库函数的代码 | 可执行代码 | 代码段/共享库的可执行映射 | 调用函数也会额外使用栈帧 |

核心原则是**指针变量所处位置**与其**指向对象所处位置**互不决定：全局指针可以指向堆，也可以指向栈或静态数组。本题 `ptr` 未显式初始化，具有静态存储期且零初始化，典型 ELF 程序放在 `.bss`；教材图把它归入“读/写数据段”，按图作答即可。

### 二、`scanf()` 等待输入时发生了哪些状态转换

若输入尚未到达，典型过程：

1. 运行中的进程执行库函数 `scanf()`；经系统调用进入内核，请求读入输入数据。
2. 内核发现条件未满足，将该进程挂入等待队列：**运行 → 阻塞**。
3. 键盘或终端产生可供读取的数据后，外设经中断等机制通知内核；内核唤醒进程：**阻塞 → 就绪**。
4. 被调度器选中后，才发生**就绪 → 运行**；`scanf()` 获取输入并返回。

**阻塞与内核态不是一回事**：进程可因 I/O 阻塞，此时 CPU 可去执行其他进程；“进入内核态”描述 CPU/指令执行权限级别，不是进程调度状态。输入已缓冲且满足需求时，`scanf()` 可能直接返回而**没有阻塞阶段**，但按原题“等待键盘输入”的条件应答阻塞。

### 三、直接调用函数、用户态库函数与设备驱动的关系

- `scanf()` 为标准库格式化输入函数，通常最终经内核读取键盘/终端/标准输入；`printf()` 为格式化输出函数，缓冲区需要写出时经内核设备 I/O 路径完成。故原题选择二者。
- `strlen()` 只逐字节扫描以 `\0` 结尾的字符串，**一般无需设备驱动**。
- `malloc()`/`free()` 管理用户空间分配器的内存；需要时可能通过系统调用申请/归还虚拟内存映射，**不能因此把它们认定为设备驱动 I/O 函数**。
- `printf()` 可能先把内容存入用户态缓冲区，而非**每次调用立即执行设备驱动**；题目问的是实现其 I/O 功能最终涉及的路径，而非对每次函数调用作硬件执行承诺。

### 四、题中 C 程序的安全性和可移植性问题

原程序中的 `scanf("%s", ptr)` 没有限制字符数，输入超过 99 个非空白字符就可能覆盖堆缓冲区（还需要 1B 存放字符串终止符 `\0`）。正确的宽度限制应写为 `scanf("%99s", ptr)`，并且要检查 `malloc` 以及 `scanf` 是否成功。标准 C 中 `main` 宜声明为 `int main(void)`，正常结束返回 0；`strlen` 返回 `size_t`，也不宜笼统用 `int` 承载不受限的结果。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *ptr;
int main(void) {
    ptr = malloc(100);
    if (ptr == NULL) return 1;
    if (scanf("%99s", ptr) != 1) {
        free(ptr);
        ptr = NULL;
        return 1;
    }
    size_t length = strlen(ptr);
    printf("length=%zu\n", length);
    free(ptr);
    ptr = NULL;
    return 0;
}
```

以上改写是**延伸学习的安全版本**，并非修改考场题干；若输入可以含空格，还应改用 `fgets` 并处理换行符。

先列出 PCB、函数指令、指针变量、指向的内存、自动变量五个对象；再从“全局/局部/动态申请”判断生命周期，最后再联系图中的代码区、数据区、堆、栈、内核区。**不要仅凭变量类型 `char*` 判定堆，不要仅凭 `scanf` 就说进程一定会阻塞**（本题是明确“等待键盘输入”）。

假定某常见用户进程采用代码段、可读写静态数据区、堆、用户栈和内核区的典型布局，`malloc(32)` 成功且为小块堆分配。观察以下 C 程序（编译器不把局部对象完全优化掉）：

1. `g` 位于静态可写区（常为 BSS）；`p` 和 `local` 通常位于用户栈；`p` 指向的 32B 存储块在堆；`main()` 指令在代码段；PCB 在内核区。
2. 输入未就绪时可经历 **运行→阻塞→就绪→运行**；`printf()` 可因标准输出缓冲而延迟真正设备 I/O，并非每次调用瞬时写设备。

</ExamAnswer>

<ExamExplanation>

**一、判断存放在哪里，必须先分清“指针”和“指向空间”。** `g` 在函数外声明，属于**静态存储期**，未显式初始化通常进入 BSS；`p` 在 `main` 内声明，属于自动对象，通常进入用户栈。调用 `malloc(32)` 得到的对象具有**动态存储期**，在题设的典型实现中位于堆。执行 `g=p` 只是把**同一个堆块地址**再放入全局指针，并没有拷贝出第二块堆空间。

`local[16]` 是自动数组，通常在用户栈并包含字符 `'4','0','8','\0'`。`main` 的机器代码位于可执行映射，PCB 属于内核维护结构。局部变量“常在栈上”是课程中的典型实现，而不是 ISO C 对物理内存布局的规范承诺。

**二、阻塞唤醒过程。** 输入条件未满足时 `scanf` 的底层读取请求可能阻塞当前进程；设备到达/缓冲区可用使其**就绪**，再由调度器选中变成运行。若输入已经缓冲好，则可以直接返回，无须走阻塞路径。`printf` 先写入用户态 stdio 缓冲区的情况很常见，缓冲区刷新后才经内核驱动完成设备输出。因此“函数与设备 I/O 有关”不等于“每次调用都立刻执行物理 I/O”。

**三、安全改写。** 读入长度限制是 `31`，因为 32B 数组/堆块必须给字符串的 `\0` 留一个字节。使用宽度限制和错误判断：

```c
char *p = malloc(32);
if (p == NULL) return 1;
g = p;
if (scanf("%31s", p) != 1) {
    free(p);
    g = NULL;
    return 1;
}
printf("%s", local);
free(p);
g = NULL;  /* 防止全局别名继续指向已释放的区域 */
```

`free(p)` 后即使 `p` 本身不再使用，`g` 仍然指向失去有效生命周期的存储区域；若后来再用 `g` 解引用就有**使用释放后内存**问题。注意 `g=NULL` 只清除了这个特定别名，系统中若还有其他别名也需要管理。

**四、易混点总结。** “指针变量在栈，指向对象在堆”“PCB 在内核，进程代码在用户可执行区”“stdio 库缓冲与设备驱动不是同一层”，这三个区分在题目改写存储期、别名个数、缓冲策略时仍成立。
