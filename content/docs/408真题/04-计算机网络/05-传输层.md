# 第 5 章 传输层


## 5.1 UDP 协议

1. 【2014】下列关于 UDP 协议的叙述中, 正确的是（ ）。 I. 提供无连接服务 II. 提供复用 / 分用服务 III. 通过差错校验, 保障可靠数据传输

A. 仅 I  
B. 仅 I、 II  
C. 仅 II、 III  
D. I、 II、 III  


<details>
<summary>查看答案与解析</summary>

**答案：** B

**解析：**

UDP 是无连接的传输层协议，不需要在通信前建立连接，因此I正确。UDP 通过端口号把来自多个应用进程的数据复用到网络层，并在接收端依据目的端口号进行分用，因此II正确。UDP 校验和只能用于发现传输过程中可能出现的差错，不提供确认、重传和按序交付机制，不能保障可靠传输，因此III错误。故选 B。


</details>

2. 【2018】UDP 协议实现分用 (demultiplexing) 时所依据的头部字段是（ ）。

A. 源端口号  
B. 目的端口号  
C. 长度  
D. 校验和  


<details>
<summary>查看答案与解析</summary>

**答案：** B

**解析：**

UDP 接收端进行分用时，要把收到的数据报交付给与其**目的端口号**对应的套接字或应用进程。源端口号主要用于标识发送进程并供接收方回送数据，不是接收端分用的直接依据。故选 B。


</details>

3. 【2024】若 UDP 协议在计算校验和过程中, 计算得到中间结果为 1011100110110110 时,还需要加上最后一个 16 位数 0110010111000101, 则最终计算得到的校验和为（ ）。

A. 0001111101111011  
B. 0001111101111100  
C. 1110000010000011  
D. 1110000010000100  


<details>
<summary>查看答案与解析</summary>

**答案：** C

**解析：**

UDP 校验和采用 16 位反码加法。先将两个 16 位数相加：

$\displaystyle 1011100110110110+0110010111000101=1\,0001111101111011$。

最高位产生进位，需要进行回卷加法：

$\displaystyle 0001111101111011+1=0001111101111100$。

再对结果逐位取反，得到校验和：

$\displaystyle 1110000010000011$。

故选 C。


</details>

## 5.2 TCP 协议

1. 【2009】主机甲与主机乙之间已建立一个 TCP 连接, 主机甲向主机乙发送了两个连续的 TCP 段, 分别包含 300B 和 500B 的有效载荷, 第一个段的序列号为 200, 主机乙正确接收到两个段后, 发送给主机甲的确认序列号是（ ）。

A. 500  
B. 700  
C. 800  
D. 1000  


<details>
<summary>查看答案与解析</summary>

**答案：** D

**解析：**

TCP 的确认序号表示接收方下一次期望收到的字节序号。第一个 TCP 段从序号 $\displaystyle 200$ 开始，两个段共携带 $\displaystyle 300+500=800\,\mathrm{B}$ 数据，因此下一个期望字节序号为

$\displaystyle 200+800=1000$。

故选 D。


</details>

2. 【2009】一个 TCP 连接总是以 1KB 的最大段长发送 TCP 段, 发送方有足够多的数据要发送。当拥塞窗口为 16KB 时发生了超时, 如果接下来的 4 个 RTT (往返时间) 时间内的 TCP 段的传输都是成功的,那么当第 4 个 RTT 时间内发送的所有 TCP 段都得到肯定应答时,拥塞窗口大小:（ ）

A. 7KB  
B. 8KB  
C. 9KB  
D. 16KB  


<details>
<summary>查看答案与解析</summary>

**答案：** C

**解析：**

发生超时前拥塞窗口为 $\displaystyle 16\,\mathrm{KB}$，超时后慢开始门限变为原来的一半：

$\displaystyle \mathrm{ssthresh}=8\,\mathrm{KB}$，

拥塞窗口重置为 $\displaystyle 1\,\mathrm{KB}$。随后各 RTT 结束时的拥塞窗口依次为：

$\displaystyle 2\,\mathrm{KB},\ 4\,\mathrm{KB},\ 8\,\mathrm{KB},\ 9\,\mathrm{KB}$。

前三个 RTT 处于慢开始阶段；达到门限后进入拥塞避免阶段，每经过一个 RTT 约增加一个 MSS。因此第 4 个 RTT 内发送的所有段均被确认后，拥塞窗口为 $\displaystyle 9\,\mathrm{KB}$。故选 C。


</details>

3. 【2010】主机甲和主机乙之间已建立了一个 TCP 连接, TCP 最大段长度为 1000B。若主机甲的当前拥塞窗口为 4000B, 在主机甲向主机乙连续发送两个最大段后, 成功收到主机乙发送的第一个段的确认段, 确认段中通告的接收窗口大小为 2000B, 则此时主机甲还可以向主机乙发送的最大字节数是（ ）。

A. 1000  
B. 2000  
C. 3000  
D. 4000  


<details>
<summary>查看答案与解析</summary>

**答案：** A

**解析：**

发送方的实际发送窗口为拥塞窗口和接收窗口的较小者。收到第一个段的确认后，两个已发送段中还有一个 $\displaystyle 1000\,\mathrm{B}$ 的段尚未被确认。此时接收方通告的接收窗口为 $\displaystyle 2000\,\mathrm{B}$，故发送方允许的未确认数据总量最多为 $\displaystyle 2000\,\mathrm{B}$。已经有 $\displaystyle 1000\,\mathrm{B}$ 在途，因此还可发送

$\displaystyle 2000-1000=1000\,\mathrm{B}$。

故选 A。


</details>

4. 【2011】主机甲向主机乙发送一个 (SYN = 1, seq = 11220) 的 TCP 段, 期望与主机乙建立 TCP 连接,若主机乙接受该连接请求, 则主机乙向主机甲发送的正确的 TCP 段可能是（ ）。

A. `{SYN=0,ACK=0,seq=11221,ack=11221}`  
B. (SYN = 1,ACK = 1,seq = 11220,ack = 11220)  
C. (SYN = 1, ACK = 1, seq = 11221, ack = 11221)  
D. `{SYN=0,ACK=0,seq=11220,ack=11220}`  


<details>
<summary>查看答案与解析</summary>

**答案：** C

**解析：**

主机乙接受连接请求时，应发送第二次握手报文段，其中 $\displaystyle \mathrm{SYN}=1$、$\displaystyle \mathrm{ACK}=1$。主机甲的 SYN 段序号为 $\displaystyle 11220$，SYN 标志本身占用一个序号，因此乙应确认

$\displaystyle \mathrm{ack}=11220+1=11221$。

乙自己的初始序号可以独立选择，选项 C 中的 $\displaystyle \mathrm{seq}=11221$ 是可能的。故选 C。


</details>

5. 【2011】主机甲与主机乙之间已建立一个 TCP 连接,主机甲向主机乙发送了 3 个连续的 TCP 段, 分别包含 300B、 400B 和 500B 的有效载荷, 第 3 个段的序号为 900。若主机乙仅正确接收到第 1 和第 3 个段, 则主机乙发送给主机甲的确认序号是（ ）。

A. 300  
B. 500  
C. 1200  
D. 1400  


<details>
<summary>查看答案与解析</summary>

**答案：** B

**解析：**

设第 1 个段的序号为 $\displaystyle x$。第 3 个段之前已有 $\displaystyle 300+400=700\,\mathrm{B}$ 数据，因此

$\displaystyle x+700=900$，

得 $\displaystyle x=200$。第 1 个段覆盖序号 $\displaystyle 200\sim499$，第 2 个段应从序号 $\displaystyle 500$ 开始。由于第 2 个段丢失，即使第 3 个段已经到达，TCP 仍采用累计确认，确认序号只能是当前连续数据之后的第一个缺失字节序号 $\displaystyle 500$。故选 B。


</details>

6. 【2013】主机甲与主机乙之间已建立一个 TCP 连接, 双方持续有数据传输, 且数据无差错与丢失。若甲收到 1 个来自乙的 TCP 段,该段的序号为 1913、确认序号为 2046、有效载荷为 100 字节,则甲立即发送给乙的 TCP 段的序号和确认序号分别是（ ）。

A. 2046、 2012  
B. 2046、 2013  
C. 2047、 2012  
D. 2047、 2013  


<details>
<summary>查看答案与解析</summary>

**答案：** B

**解析：**

甲收到乙的 TCP 段，其序号为 $\displaystyle 1913$，有效载荷为 $\displaystyle 100\,\mathrm{B}$，所以甲下一次期望收到乙的数据序号为

$\displaystyle 1913+100=2013$。

该段中的确认序号为 $\displaystyle 2046$，表示乙下一次期望收到甲的字节序号是 $\displaystyle 2046$，因此甲立即发送的段可取序号 $\displaystyle 2046$、确认序号 $\displaystyle 2013$。故选 B。


</details>

7. 【2014】主机甲和主机乙已建立了 TCP 连接, 甲始终以 MSS = 1KB 大小的段发送数据, 并一直有数据发送；乙每收到一个数据段都会发出一个接收窗口为 10KB 的确认段。若甲在 t 时刻发生超时时拥塞窗口为 8KB, 则从 t 时刻起, 不再发生超时的情况下, 经过 10 个 RTT 后, 甲的发送窗口是（ ）。

A. 10KB  
B. 12KB  
C. 14KB  
D. 15KB  


<details>
<summary>查看答案与解析</summary>

**答案：** A

**解析：**

超时时拥塞窗口为 $\displaystyle 8\,\mathrm{KB}$，故超时后

$\displaystyle \mathrm{ssthresh}=4\,\mathrm{KB},\qquad \mathrm{cwnd}=1\,\mathrm{KB}$。

若以后不再超时，10 个 RTT 结束时拥塞窗口依次为

$\displaystyle 2,4,5,6,7,8,9,10,11,12\,\mathrm{KB}$。

但乙始终通告接收窗口为 $\displaystyle 10\,\mathrm{KB}$，所以甲的实际发送窗口为

$\displaystyle \min(12,10)=10\,\mathrm{KB}$。

故选 A。


</details>

8. 【2015】主机甲和主机乙新建一个 TCP 连接, 甲的拥塞控制初始阈值为 32KB, 甲向乙始终以 MSS = 1KB 大小的段发送数据, 并一直有数据发送; 乙为该连接分配 16KB 接收缓存, 并对每个数据段进行确认, 忽略段传输延迟。若乙收到的数据全部存入缓存, 不被取走, 则甲从连接建立成功时刻起, 未发生超时的情况下, 经过 4 个 RTT 后, 甲的发送窗口是（ ）。

A. 1KB  
B. 8KB  
C. 16KB  
D. 32KB  


<details>
<summary>查看答案与解析</summary>

**答案：** A

**解析：**

初始拥塞窗口按 $\displaystyle 1\,\mathrm{MSS}=1\,\mathrm{KB}$ 计算，且慢开始门限为 $\displaystyle 32\,\mathrm{KB}$。前 4 个 RTT 中，甲分别最多发送 $\displaystyle 1,2,4,8\,\mathrm{KB}$，乙缓存中累计存入

$\displaystyle 1+2+4+8=15\,\mathrm{KB}$。

因此乙最新通告的接收窗口为

$\displaystyle 16-15=1\,\mathrm{KB}$。

此时甲的拥塞窗口已增长到 $\displaystyle 16\,\mathrm{KB}$，但实际发送窗口为

$\displaystyle \min(16,1)=1\,\mathrm{KB}$。

故选 A。


</details>

9. 【2017】若甲向乙发起一个 TCP 连接, 最大段长 MSS = 1KB, RTT = 5ms, 乙开辟的接收缓存为 64KB, 则甲从连接建立成功至发送窗口达到 32KB, 需经过的时间至少是（ ）。

A. 25ms  
B. 30ms  
C. 160ms  
D. 165ms  


<details>
<summary>查看答案与解析</summary>

**答案：** A

**解析：**

连接建立成功后，初始拥塞窗口为 $\displaystyle 1\,\mathrm{KB}$。接收缓存为 $\displaystyle 64\,\mathrm{KB}$，在发送窗口达到 $\displaystyle 32\,\mathrm{KB}$ 前不会构成限制。慢开始阶段拥塞窗口每经过一个 RTT 加倍：

$\displaystyle 1\to2\to4\to8\to16\to32\,\mathrm{KB}$。

共需 $\displaystyle 5$ 个 RTT，因此最短时间为

$\displaystyle 5\times5\,\mathrm{ms}=25\,\mathrm{ms}$。

故选 A。


</details>

11. 【2019】若主机甲主动发起一个与主机乙的 TCP 连接,甲、乙选择的初始序列号分别为 2018 和 2046, 则第三次握手 TCP 段的确认序列号是（ ）。

A. 2018  
B. 2019  
C. 2046  
D. 2047  


<details>
<summary>查看答案与解析</summary>

**答案：** D

**解析：**

第三次握手由主机甲向主机乙发送 ACK。乙在第二次握手中使用的初始序列号为 $\displaystyle 2046$，SYN 标志占用一个序号，因此甲在第三次握手中应确认

$\displaystyle 2046+1=2047$。

故选 D。


</details>

12. 【2020】主机甲与主机乙已建立一条 TCP 连接, 最大段长 (MSS) 为 1KB, 往返时间 (RTT) 为 2ms, 在不出现拥塞的前提下, 拥塞窗口从 8KB 增长到 32KB 所需的最长时间是（ ）。

A. 4ms  
B. 8ms  
C. 24ms  
D. 48ms  


<details>
<summary>查看答案与解析</summary>

**答案：** D

**解析：**

在不发生拥塞的情况下，拥塞窗口从 $\displaystyle 8\,\mathrm{KB}$ 增长到 $\displaystyle 32\,\mathrm{KB}$，若处于慢开始阶段只需较少 RTT；题目问“最长时间”，应按拥塞避免阶段计算。拥塞避免阶段每经过一个 RTT 增加一个 MSS，即 $\displaystyle 1\,\mathrm{KB}$。需要增加

$\displaystyle 32-8=24\,\mathrm{KB}$，

故需 $\displaystyle 24$ 个 RTT，时间为

$\displaystyle 24\times2\,\mathrm{ms}=48\,\mathrm{ms}$。

故选 D。


</details>

13. 【2020】若主机甲与主机乙建立 TCP 连接时, 发送的 SYN 段中的序号为 1000, 在断开连接时,甲发送给乙的 FIN 段中的序号为 5001, 则在无任何重传的情况下, 甲向乙已经发送的应用层数据的字节数为（ ）。

A. 4002  
B. 4001

D. 3999

<summary>查看答案与解析</summary>

**答案：** C

建立连接时甲发送的 SYN 段序号为 $\displaystyle 1000$，SYN 占用一个序号，因此甲发送应用层数据时的第一个字节序号为 $\displaystyle 1001$。FIN 段序号为 $\displaystyle 5001$，说明应用层数据最后一个字节的序号为 $\displaystyle 5000$。因此应用层数据字节数为

$\displaystyle 5000-1001+1=4000\,\mathrm{B}$。

故选 C。


</details>

14. 【2021】若客户首先向服务器发送 FIN 段请求断开 TCP 连接,则当客户收到服务器发送的 FIN 段并向服务器发送了 ACK 段后, 客户的 TCP 状态转换为（ ）。

D. FIN _WAIT _2  


<details>

客户首先发送 FIN，说明客户是主动关闭方。客户收到服务器的 FIN 后，向服务器发送最后一个 ACK，并从 $\displaystyle \mathrm{FIN\_WAIT\_2}$ 转入 $\displaystyle \mathrm{TIME\_WAIT}$，等待 $\displaystyle 2\mathrm{MSL}$ 后才进入 CLOSED。故选 B。

15. 【2021】若大小为 12B 的应用层数据分别通过 1 个 UDP 数据报和 1 个 TCP 段传输,则该 UDP 数据报和 TCP 段实现的有效载荷 (应用层数据) 最大传输效率分别是（ ）。

17. 【2022】假设主机甲和主机乙已建立一个 TCP 连接,最大段长 MSS = 1KB,甲一直有数据向乙发送,当甲的拥塞窗口为 16KB 时,计时器发生了超时,则甲的拥塞窗口再次增长到 16KB 所需要的时间至少是（ ）。

A. 4RTT  
B. 5RTT  
C. 11RTT  
D. 16RTT  


<details>
<summary>查看答案与解析</summary>

**答案：** C

**解析：**

计时器超时时，原拥塞窗口为 $\displaystyle 16\,\mathrm{KB}$，故

$\displaystyle \mathrm{ssthresh}=8\,\mathrm{KB},\qquad \mathrm{cwnd}=1\,\mathrm{KB}$。

慢开始阶段经过 3 个 RTT，拥塞窗口按

$\displaystyle 1\to2\to4\to8\,\mathrm{KB}$

增长到门限。随后进入拥塞避免阶段，从 $\displaystyle 8\,\mathrm{KB}$ 增长到 $\displaystyle 16\,\mathrm{KB}$ 还需 8 个 RTT。因此至少需要

$\displaystyle 3+8=11\,\mathrm{RTT}$。

故选 C。


</details>

18. 【2022】假设客户 C 和服务器 S 已建立一个 TCP 连接, 通信往返时间 RTT = 50ms, 最长报文段寿命 MSL = 800ms, 数据传输结束后, C 主动请求断开连接。若从 C 主动向 S 发出 FIN 段时刻算起,则 C 和 S 进入 CLOSED 状态所需的时间至少分别是（ ）。

A. 850ms,50ms  
B. 1650ms,50ms  
C. 850ms,75ms  
D. 1650ms,75ms  


<details>
<summary>查看答案与解析</summary>

**答案：** D

**解析：**

客户 C 是主动关闭方。单向传播时延为

$\displaystyle \dfrac{\mathrm{RTT}}{2}=25\,\mathrm{ms}$。

从 C 发出 FIN 起，最短情况下：服务器在 $\displaystyle 25\,\mathrm{ms}$ 后收到 FIN，并立即发送 ACK 和自己的 FIN；C 在 $\displaystyle 50\,\mathrm{ms}$ 时收到服务器的 FIN，发送最后一个 ACK 并进入 TIME_WAIT。C 需等待

$\displaystyle 2\mathrm{MSL}=1600\,\mathrm{ms}$，

故 C 进入 CLOSED 的最短时间为

$\displaystyle 50+1600=1650\,\mathrm{ms}$。

服务器还需等待最后一个 ACK 传播回来，因此在

$\displaystyle 50+25=75\,\mathrm{ms}$

时进入 CLOSED。故选 D。


</details>

19. 【2024】假设主机 H 通过 TCP 向服务器发送长度为 3000B 的报文, 往返时间 RTT = 10ms, 最长报文段寿命 MSL = 30s, 最大报文段长度 MSS = 1000B, 忽略 TCP 段的传输时延, 报文传输结束后 H 首先请求断开连接, 则从 H 请求建立 TCP 连接时刻起, 到 H 进入 CLOSED 状态为止, 所需时间至少是（ ）。

A. 30.03s  
B. 30.04s  
C. 60.03s  
D. 60.04s  


<details>
<summary>查看答案与解析</summary>

**答案：** D

**解析：**

H 请求建立连接后，经过 1 个 RTT，即 $\displaystyle 10\,\mathrm{ms}$，收到服务器的 SYN+ACK，并可在第三次握手 ACK 中同时发送第一个数据段。初始拥塞窗口按 $\displaystyle 1\,\mathrm{MSS}$ 计算：

1. 第 1 个数据 RTT 发送 $\displaystyle 1$ 个段，至 $\displaystyle 20\,\mathrm{ms}$ 收到确认；
2. 第 2 个数据 RTT 发送余下 $\displaystyle 2$ 个段，至 $\displaystyle 30\,\mathrm{ms}$ 收到确认；
3. H 随即发送 FIN，最短情况下服务器收到后立即回送 ACK 和 FIN，H 在 $\displaystyle 40\,\mathrm{ms}$ 收到 FIN、发出最后一个 ACK并进入 TIME_WAIT。

H 在 TIME_WAIT 中还要等待

$\displaystyle 2\mathrm{MSL}=60\,\mathrm{s}$。

总时间至少为

$\displaystyle 0.04+60=60.04\,\mathrm{s}$。

故选 D。

21. 【2016】假设下图中的 H3 访问 Web 服务器 S 时, S 为新建的 TCP 连接分配了 20KB(K = 1024)

![第 5 章 传输层 5.2 第21题：图表，见原 PDF 第56页附近](/img/questions/408/computer-network-5-2-q21.png)

的接收缓存, 最大段长 MSS = 1KB, 平均往返时间 RTT = 200ms。 H3 建立连接时的初始序号为 100, 且持续以 MSS 大小的段向 S 发送数据, 拥塞窗口初始阈值为 32KB；S 对收到的每个段进行确认, 并通告新的接收窗口。假定 TCP 连接建立完成后, S 端的 TCP 接收缓存仅有数据存入而无数据取出。请回答下列问题:
   (1) 在 TCP 连接建立过程中, H3 收到的 S 发送过来的第二次握手 TCP 段的 SYN 和 ACK 标志位的值分别是多少？确认序号是多少？
   (2) H3 收到的第 8 个确认段所通告的接收窗口是多少？此时 H3 的拥塞窗口变为多少?H3 的发送窗口变为多少?
   (3) 当 H3 的发送窗口等于 0 时, 下一个待发送的数据段序号是多少？ H3 从发送第 1 个数据段到发送窗口等于 0 时刻为止,平均数据传输速率是多少 (忽略段的传输延时)?
   (4) 若 H3 与 S 之间通信已经结束, 在 t 时刻 H3 请求断开该连接, 则从 t 时刻起, S 释放该连接的最短时间是多少?


<details>
<summary>查看答案与解析</summary>

**答案：** （1）$\displaystyle \mathrm{SYN}=1$，$\displaystyle \mathrm{ACK}=1$，确认序号为 $\displaystyle 101$。

（2）第 8 个确认段通告的接收窗口为 $\displaystyle 12\,\mathrm{KB}$；拥塞窗口为 $\displaystyle 9\,\mathrm{KB}$；发送窗口为 $\displaystyle 9\,\mathrm{KB}$。

（3）下一个待发送数据段的序号为 $\displaystyle 20581$；平均数据传输速率为 $\displaystyle 20\,\mathrm{KB/s}=20480\,\mathrm{B/s}$。

（4）S 释放连接的最短时间为 $\displaystyle 300\,\mathrm{ms}$。

**解析：**

（1）第二次握手由服务器 S 发送 SYN+ACK 段，因此两个标志位都为 1。H3 的初始序号为 $\displaystyle 100$，SYN 占用一个序号，所以确认序号为

$\displaystyle 100+1=101$。

（2）S 的接收缓存为 $\displaystyle 20\,\mathrm{KB}$，每收到一个 $\displaystyle 1\,\mathrm{KB}$ 数据段就确认一次，且缓存中的数据不被取走。收到并确认第 8 个段后，缓存中已有 $\displaystyle 8\,\mathrm{KB}$，故通告的接收窗口为

$\displaystyle 20-8=12\,\mathrm{KB}$。

慢开始阶段中，每收到一个新数据段的确认，拥塞窗口增加一个 MSS。初始拥塞窗口为 $\displaystyle 1\,\mathrm{KB}$，收到第 8 个确认后为

$\displaystyle 1+8=9\,\mathrm{KB}$。

因此发送窗口为

$\displaystyle \min(9,12)=9\,\mathrm{KB}$。

（3）H3 的 SYN 使用序号 $\displaystyle 100$，故第一个数据字节序号为 $\displaystyle 101$。接收缓存被 $\displaystyle 20\,\mathrm{KB}=20480\,\mathrm{B}$ 数据填满后，下一个待发送字节序号为

$\displaystyle 101+20480=20581$。

按慢开始过程，H3 在连续 5 个 RTT 中分别使 S 累计接收的数据量达到 $\displaystyle 1,3,7,15,20\,\mathrm{KB}$，第 5 个 RTT 结束时收到零窗口通告。总时间为

$\displaystyle 5\times200\,\mathrm{ms}=1\,\mathrm{s}$，

故平均速率为

$\displaystyle \dfrac{20\,\mathrm{KB}}{1\,\mathrm{s}}=20\,\mathrm{KB/s}=20480\,\mathrm{B/s}$。

（4）H3 在 $\displaystyle t$ 时刻发出 FIN。经过半个 RTT，S 收到 FIN，并在最短情况下立即发送 ACK 和自己的 FIN；再经过半个 RTT，H3 收到 FIN 并发送最后一个 ACK；该 ACK 还需半个 RTT 才能到达 S。S 收到最终 ACK 后才能从 LAST_ACK 状态进入 CLOSED 并释放连接，因此最短时间为

$\displaystyle \dfrac{3}{2}\mathrm{RTT}=\dfrac{3}{2}\times200\,\mathrm{ms}=300\,\mathrm{ms}$。

22. 【2023】(9 分) 某网络拓扑如下图所示, 主机 H 登录到 FTP 服务器后, 向服务器上传一个大小为 18000B 的文件 F。假设 H 为传输 F 建立数据连接时, 选择的初始序号为 100, MSS = 1000B, 拥塞控制的初始阈值是 4MSS,RTT = 10ms, 忽略 TCP 的传输时延；在 F 的传输过程中, H 均以 MSS 段向服务器发送数据, 且未发生差错、丢包和乱序现象。

![第 5 章 传输层 5.2 第22题：网络拓扑图，见原 PDF 第57页附近](/img/questions/408/computer-network-5-2-q22.png)


请回答下列问题。
   (1)FTP 的控制连接是持久的还是非持久的？ FTP 的数据连接是持久的还是非持久的？ H 登录 FTP 服务器时, 建立的 TCP 连接是控制连接还是数据连接?
   (2) H 通过数据连接发送 F 时, F 的第一个字节序号是多少？在断开数据连接的过程中, FTP 服务器发送的第二次挥手 ACK 段的确认序号是多少?

<details>
<summary>查看答案与解析</summary>

**答案：** （1）FTP 控制连接是持久连接，数据连接是非持久连接；H 登录服务器时建立的是控制连接。

（2）F 的第一个字节序号为 $\displaystyle 101$；服务器第二次挥手 ACK 段的确认序号为 $\displaystyle 18102$。

（3）收到确认序号 $\displaystyle 2101$ 时，拥塞窗口为 $\displaystyle 3\,\mathrm{MSS}$；收到确认序号 $\displaystyle 7101$ 时，拥塞窗口为 $\displaystyle 5\,\mathrm{MSS}$。

（4）至少需要 $\displaystyle 60\,\mathrm{ms}$；应用层数据平均发送速率为 $\displaystyle 300000\,\mathrm{B/s}$，即 $\displaystyle 2.4\,\mathrm{Mb/s}$。

**解析：**

（1）FTP 使用两条 TCP 连接：控制连接在整个会话期间保持，用于传送命令和响应，因此是持久连接；每次传送文件或目录时单独建立数据连接，传输结束即关闭，因此是非持久连接。登录时先建立的是控制连接。

（2）H 建立数据连接时选择的初始序号为 $\displaystyle 100$，SYN 占用一个序号，所以文件第一个字节序号为

$\displaystyle 100+1=101$。

文件大小为 $\displaystyle 18000\,\mathrm{B}$，发送完后下一个序号为

$\displaystyle 101+18000=18101$。

H 随后发送的 FIN 使用序号 $\displaystyle 18101$，FIN 又占用一个序号，所以服务器在第二次挥手中确认

$\displaystyle 18101+1=18102$。

（3）初始拥塞窗口为 $\displaystyle 1\,\mathrm{MSS}$，慢开始门限为 $\displaystyle 4\,\mathrm{MSS}$。确认序号 $\displaystyle 2101$ 表明前两个数据段已被累计确认。第一个确认使拥塞窗口由 $\displaystyle 1$ 增至 $\displaystyle 2\,\mathrm{MSS}$，第二个确认使其增至 $\displaystyle 3\,\mathrm{MSS}$。

确认序号 $\displaystyle 7101$ 表明前 7 个数据段已确认。前 3 个段确认后拥塞窗口达到门限 $\displaystyle 4\,\mathrm{MSS}$；随后进入拥塞避免阶段，在确认第 4～7 个段的一个 RTT 内，拥塞窗口合计增加约一个 MSS，故调整为 $\displaystyle 5\,\mathrm{MSS}$。

（4）从请求建立数据连接起，先用 1 个 RTT 完成前两次握手并使 H 能发送第三次握手及第一个数据段。之后各轮可发送的数据段数依次为

$\displaystyle 1,2,4,5,6$，

共计 $\displaystyle 18$ 个数据段，恰好传完文件。确认全部数据还需 5 个数据 RTT。因此总时间至少为

$\displaystyle (1+5)\mathrm{RTT}=6\times10\,\mathrm{ms}=60\,\mathrm{ms}$。

应用层平均发送速率为

$\displaystyle \dfrac{18000\,\mathrm{B}}{0.06\,\mathrm{s}}=300000\,\mathrm{B/s}$，

换算为比特率为

$\displaystyle 300000\times8=2.4\times10^6\,\mathrm{b/s}=2.4\,\mathrm{Mb/s}$。


</details>
