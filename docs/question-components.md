# 题目与解答组件

题目文档使用四个组件：`Question`、`Option`、`Blank`、`Solution`。组件已全局注册，MDX 中无需导入。
答案只写一次，并且写在结构化属性里：`Option` 的 `correct`、`Blank` 的 `answer`、判断题的 `answer`。
选项字母、题号和做题交互都由组件生成。全部题型的可交互示例见 `content/docs/question-types.mdx`（`/docs/question-types`）。

## 五种题型

| `type`     | 交互                              | 答案写在                          |
| ---------- | --------------------------------- | --------------------------------- |
| `single`   | 点击选项立即判分                  | 恰好一个 `<Option correct>`       |
| `multiple` | 选择后点击「提交答案」            | 至少两个 `<Option correct>`       |
| `boolean`  | 点击「正确 / 错误」立即判分       | `<Question answer={true\|false}>` |
| `blank`    | 逐空输入后提交（回车跳到下一空）  | 每个 `<Blank answer="…" />`       |
| `essay`    | 对照参考解答自评：正确 / 部分正确 / 错误 | `<Solution>`                |

每道题渲染为一张圆角卡片：左上角是题号、题型和标签胶囊，右上角是收藏、标签、注释按钮，底部是判分结果与「查看解答」。

解答题不自动判分：底部给出「正确 / 部分正确 / 错误」三个自评按钮，「题目与解析」弹窗里先列参考解答、再给同样的自评按钮，可随时改。自评和其他题型的作答一样保存与同步（`selected` 中存字母 A / B / C，与判断题存字母的方式相同），右下角答题球也按自评结果统计。

选项未选中时只有一圈细边框、没有底色；点选后颜色从按下的位置扩散铺满整个选项（含边框），判分颜色同样如此。
作者在题目之间写的 `---` 分割线会被自动隐藏，不需要删除。

### 单选 / 多选

```mdx
<Question id="408-ds-001" type="single" tags="来源:408 统考 2019, 数据结构">

算法的基本特征不包括（ ）。

<Option>有穷性</Option>
<Option>确定性</Option>
<Option>可行性</Option>
<Option correct>可读性</Option>

<Solution>

可读性不是算法必须具备的基本特征。

</Solution>

</Question>
```

- 选项不要手写 `A.`、`B.`，顺序就是显示顺序；选项前必须空一行，选项之间连续放置。
- 选项字母用 Computer Modern 数学斜体（KaTeX 自带的 `KaTeX_Math` 字体，与公式变量同款）排在柔和的圆底上，
  判分后的「正确答案」等答案字母也用同一字体。
- 多选题把每个正确选项都标上 `correct`。
- 选项与判断按钮都是 [`TileButton`](button-component.md)：选中、判对、判错的底色从点击位置以圆形扩散铺满；
  没点到而被揭示的正确答案从字母处扩散，键盘操作从字母处扩散。
- 判分反馈：选对为绿色勾，选错为红色叉并轻微抖动；单选答错时正确项以绿色描边标出「正确答案」；
  多选题没选到的正确项以**黄色**标出「漏选」。结果胶囊：回答正确（绿）、少选（黄，只选了正确项的一部分）、回答错误（红，选了错误项）。

### 判断

```mdx
<Question id="os-014" type="boolean" answer={false} tags="操作系统">

用户态线程的切换必须经过内核。

<Solution>

用户态线程可以在用户空间完成切换。

</Solution>

</Question>
```

判断题显示「正确 / 错误」两个大按钮，点击即判分。作答记录沿用选择题的存储格式（`A` = 正确，`B` = 错误），旧记录保持有效。

### 填空

```mdx
<Question id="net-007" type="blank">

TCP 位于 OSI 的 <Blank answer="传输层" aliases={["运输层"]} />，建立连接需要 <Blank answer="3" /> 次握手。

</Question>
```

一题可以有多个空，判分逐空显示（正确绿色、错误红色），全部正确为「回答正确」，部分正确为黄色「部分正确 · 1/2 空」。

`Blank` 的属性：

| 属性          | 说明                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| `answer`      | 必填。标准答案。                                                                                       |
| `aliases`     | 其他可接受的写法，如 `aliases={["运输层"]}`。                                                          |
| `kind`        | `"text"` 或 `"math"`。省略时：纯数字与算式答案（`3`、`-1/2`、`2√3`、`π/4`、`50%`）为 `math`，其余为 `text`。 |
| `tolerance`   | 数值绝对误差，如 `tolerance={0.01}`。                                                                  |
| `placeholder` | 空白时的提示文字。                                                                                     |

**文字型（`text`）**：唤起系统键盘。比较前做归一化：全角转半角、忽略大小写与空白、去掉引号和句末标点。

**数学型（`math`）**：不唤起系统键盘（`inputmode="none"`），聚焦时从底部弹出屏幕数学键盘（桌面为悬浮面板），
硬件键盘仍可直接输入。键盘提供数字、四则运算、括号、分数线、乘方与平方、根号、π、e、变量 x/y/n/t/a、
三角与反三角函数、ln、lg、log(底数, 真数)、绝对值、阶乘、百分号，以及光标左右移动（长按连续）、删除（长按连续，
`sin(`、`√(` 等整体删除）和「下一空 / 提交」。键盘顶部实时排版预览当前表达式并提示语法错误。

数学型按**数值等价**判分，不使用 `eval`：`lib/math-expression` 把输入解析为语法树后在固定函数表上求值。

- 常数表达式比较数值：`1/2`、`0.5`、`50%` 等价；`√2/2` 与 `1/√2` 等价。默认相对误差 1e-9，设置 `tolerance` 后改用绝对误差。
- 含变量的表达式在固定的 14 个取样点（正负两侧）比较：`(x+1)^2` 与 `x^2+2x+1` 等价，`sin^2x+cos^2x` 与 `1` 等价。
  两边只在都有定义的点上比较；一边有定义另一边无定义视为不等价（如 `√(x^2)` 与 `x`）。
- 方程（一个 `=`）比较两边之差是否只差一个非零常数倍：`y=2x+1` 与 `2x-y+1=0` 等价。
- 支持：整数、小数、科学计数（`1e-3`）、π / pi、e、单字母变量、`+ − × · ÷ / ^`（右结合）、隐式乘法（`2x`、`3(x+1)`、`(a)(b)`）、
  `%`、`!`、`|x|`、`²` `³`、`√` `∛`，函数 sqrt cbrt abs sin cos tan cot sec csc arcsin arccos arctan sinh cosh tanh ln lg log exp、
  `log(底数, 真数)`，`sin^2 x` 表示 `(sin x)^2`。单参数 `log` 按以 10 为底处理。
- 不支持：区间、集合、不等式、矩阵、复数、极限/求导等符号运算。这类答案以及需要判断「化简形式」的题目请用 `kind="text"` 或解答题。
- 输入无法解析时该空判为错误，并提示「无法识别为数学表达式」。

`kind="math"` 的答案在编译时会被解析，写错（如 `answer="(1+"`）会让构建报错。

### 解答

```mdx
<Question id="os-021" type="essay" points={10}>

简述进程与线程的主要区别。

<Solution>

1. 进程是资源分配的基本单位。
2. 线程是 CPU 调度的基本单位。

</Solution>

</Question>
```

## Question 属性

| 属性       | 说明                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| `id`       | 必填。稳定的唯一标识（字母、数字、`.`、`_`、`-`），不要随题目顺序变化。    |
| `type`     | 必填。五种题型之一。                                                       |
| `answer`   | 仅判断题：`{true}` 或 `{false}`。                                          |
| `tags`     | 可选。题目内置标签，见下节。                                               |
| `points`   | 可选。题目分值，正数。                                                     |
| `number`   | 可选。覆盖自动题号：`{15}` 从 15 重新计数，`"例 1"` 使用文字，`{false}` 不显示。 |

题号按文档顺序自动生成，从 1 开始；设置 `number={n}` 后后续题目接着 `n` 计数。

## 内置标签

题目自带的标签（来源、分类、考点等）写在 `tags` 属性里，显示为卡片左上角的彩色小胶囊：

```mdx
<Question id="ds-101" type="single" tags="2023 统考, 数据结构, 易错">
<Question id="ds-102" type="single" tags="来源:2023 统考, 章节:栈与队列">
<Question id="ds-103" type="single" tags={["来源:模拟卷", "易错"]}>
```

- 用逗号（`,` `，` `、`）分隔，也可以写成字符串数组；最多 8 个，每个最多 32 字，重复的会去掉。
- `分类:值`（冒号可全角）把分类显示为较浅的前缀；**同一分类的标签颜色相同**，没有分类的标签按文字决定颜色，全站稳定。
- 修改 `tags` 不改变题目 revision，不会让读者已有的作答记录失效。

读者自己创建的标签（如「难题」）与内置标签分开存储，显示在内置标签之后（灰底带色点），见
[题目数据库 · 标签、收藏与注释](question-database.md#标签收藏与注释)。

## 结构规则

- `Option` 必须是 `Question` 的直接子元素，不能放进列表、引用或 `Solution`。
- `Solution` 放在最后，一道题至多一个；它不会直接显示在页面上，点击「查看解答」后在底部浮窗中展示。
- 题干可以自由使用 Markdown、公式、图片、表格和代码；`Question` 内的标题不会出现在目录中。

编译时会校验这些规则（`lib/remark-question.ts`）：id 缺失或重复、题型非法、单选没有恰好一个
`correct`、多选少于两个、选项不连续、`Solution` 不在最后、填空缺少 `answer`、`kind` 非法、数学答案无法解析、
`tags` 格式错误等都会让构建报错，并指出文件、行号和题目 id。`tests/question-content.test.ts` 会对 `content/docs`
下全部文档做同样的检查，并要求 id 全局唯一。

## 题目与解析浮窗

「查看解答」打开题目与解析弹窗，基于通用组件 [`Modal`](modal-component.md)：

- 顶栏：题号（或「题目与解析」）、题型、内置标签与读者标签；工具栏为收藏 / 标签 / 注释与「收藏与标签」，最后是关闭。
  内容滚到顶栏下方时，顶栏取其下方表面的半透明底色。
- 桌面：底部抽屉（最大宽 76rem），左右分栏（`ModalSplit`）。左栏为题目（揭示答案）与「我的注释」，右栏为答案对照（正确答案与你的答案，填空逐空对照）和解析，两栏各自滚动。
- 手机：底部抽屉，单列滚动，较长的题目先折叠为几行（可展开），答案与解析紧随其后，注释在最后。
- 「收藏与标签」作为第二层弹窗叠在解答之上：返回按钮或 Esc 回到解答，「全部关闭」一起关闭，点击条目跳转到对应题目。
- 关闭方式：Esc、关闭按钮、点击遮罩，或向下拖动顶栏。打开时焦点在标题上，关闭后回到「查看解答」按钮。
- 浮窗中的题目是页面上该题渲染结果的只读副本（不再在页面数据里重复序列化题干），所以公式、图片和选项布局与页面一致。

## 性能约定

长页面可能有上百道题、数千个公式节点，题目组件按以下约定控制每题开销：

- 卡片使用 `content-visibility: auto`，屏幕外的题目跳过布局与绘制。
- 每题的「查看解答」浮窗和标签弹层都是普通按钮，第一次打开时才挂载对应的 Modal / Popover。
- 选项的点击填充是 CSS 伪元素，按下位置直接写入元素的 CSS 变量，不触发重新渲染。
- 选项的判分图标、多选勾选角标和卡片右上角的收藏 / 标签 / 注释图标都是 CSS mask 伪元素或单个元素，不为每个选项生成 SVG。
- 选项分栏只测量视口附近的题目，其余进入视口前再测量；数学键盘与「收藏与标签」对话框按需加载。
- 生命周期与页面相同的观察器和全局监听器（如 `use-choice-columns.ts` 中的 `IntersectionObserver`、`ResizeObserver`、`document.fonts` 监听）在模块加载时创建，不要在 effect 里懒创建：
  压缩器会把只用一次的辅助函数内联进 effect，回调因此与 effect 共享作用域，持有某个题目元素，客户端切换页面后整个旧页面无法回收
  （2026-10-22 线上实测：离开 136 题页面后残留约 2.7 万个节点）。检查方法：切换页面并强制 GC 后，CDP `Performance.getMetrics` 的 `Nodes` 应接近当前 DOM 元素数。

## 版本哈希

编译时会为每道题写入 `data-question-revision`（题型、答案与题目正文的 SHA-1 前 8 位）。
保存做题记录时同时保存 `question_id` 与 `revision`，修改答案或解析之后，历史记录仍能对应到当时的题目内容。
选项按位置连同 `revision` 保存，不要把显示的字母当作永久选项 id。收藏、标签和注释只按 `question_id` 保存，不随 revision 变化。

## 答题记录

选择、判断与填空题会把草稿、提交和重做后的状态保存到浏览器 IndexedDB，刷新后恢复。
登录由右上角的[账号菜单](account.md)负责；配置 Supabase 后，登录账号的答案、标签、收藏与注释会自动同步。
题目正文和标准答案继续由本文档管理。

账号隔离、数据库结构、冲突策略和部署步骤见 [题目数据库与本地优先同步](question-database.md)。
